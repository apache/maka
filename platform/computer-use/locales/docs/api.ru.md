Computer Use — это независимый постоянный JavaScript REPL. Используйте cua_repl напрямую;
Code Mode не требуется. Переменные и привязанные объекты сохраняются между вызовами и ходами (Turn) в рамках
текущего процесса хоста. У нового REPL после перезапуска нет переменных из истории;
ориентируйтесь на текущее состояние Computer Use, переданное с запросом модели.
Для работы с веб-сайтами начинайте с `await cua.listBrowsers()` и используйте вкладку браузера до
нативного ввода в окно браузера. Установленные подключения ChatGPT можно перехватывать по
требованию без настройки shell и без запуска десктопного приложения ChatGPT.
Используйте `await` верхнего уровня, но не `return` верхнего уровня. Этот REPL сохраняет объявления;
повторно используйте привязки или выбирайте новые имена. В нём нет API Node и `setTimeout`.

`cua.computer.target` указывает выбранную платформу рабочего стола (`mac`, `linux`, `windows`).
В WSL по умолчанию выбирается хост Windows; команды shell при этом всё ещё могут выполняться в Linux.

`cua.computer` также предоставляет нативные для платформы методы в стиле snake_case. Они принимают объект параметров, а не позиционные аргументы App/Tab, описанные ниже; `list_apps()`, `list_windows()` и `get_screenshot()` в Linux не принимают параметров. Сначала изучите выбранный интерфейс и прочитайте его перечень:
```js
const native = cua.computer;
nodeRepl.write({target: native.target, methods: Object.keys(native).filter(k => typeof native[k] === 'function')});
nodeRepl.write(await (native.list_windows ? native.list_windows() : native.list_apps()));
```
| target | Нативные методы (аудио описано отдельно) |
| --- | --- |
| `linux` | `perform_secondary_action`, `click`, `drag`, `drag_handle`, `activate_window`, `get_screenshot`, `list_apps`, `list_windows`, `move`, `move_relative`, `press_key`, `scroll`, `type_text`, `launch_app`, `get_window_state` |
| `mac` | `list_apps`, `get_app_state`, `click`, `drag`, `paste`, `perform_secondary_action`, `press_key`, `scroll`, `select_text`, `set_value`, `type_text` |
| `windows` | `activate_window`, `get_window_state`, `click`, `scroll`, `drag`, `press_key`, `type_text`, `launch_app`, `list_apps`, `list_windows`, `get_window`, `perform_secondary_action`, `set_value` |

- Linux X11: передавайте возвращённый объект `window` в `get_window_state({window, query?, include_screenshot?})`. Передайте наблюдаемый `element_id` **или** целые `x,y` в `click({window, element_id})` / `click({window, x, y, mouse_button?, click_count?, duration?, key?})`; координаты окна локальны, а при отсутствии `window` используется рабочий стол. Другие методы ввода включают `type_text({window?, text, element_id?})`, `press_key({window?, key, duration?})`, `scroll({window?, direction, pixels?, x?, y?, element_id?, key?})`, `drag({window?, path:[{x,y},…], key?})`, `move({window?, x,y,key?})`, `move_relative({dx,dy,key?})`, `activate_window({window})`, `perform_secondary_action({window,element_id,action})` и `launch_app({app})`. `duration` задаётся в миллисекундах. `drag_handle()` создаёт дескриптор перетаскивания рабочего стола с методами `start({x,y})`, `move_to({x,y})`, `end()`; обязательно завершите его явно в пределах текущего хода.
- Windows: используйте возвращённый дескриптор окна `{app,id,...}`. Прочитайте `get_window_state({window, include_text?, include_screenshot?})` перед индексированным вводом или вводом по снимку экрана; снимки экрана включены по умолчанию, текст отключён. Используйте `click({window,element_index})` или `click({window,x,y,screenshotId?})`, `scroll({window,x,y,scrollX,scrollY,screenshotId?})`, `drag({window,from_x,from_y,to_x,to_y,screenshotId?})`, `press_key({window,key})`, `type_text({window,text})`, `set_value({window,element_index,value})`, `perform_secondary_action({window,element_index,action})`, `activate_window({window})`, `get_window({id})` и `launch_app({app})`. Укажите в `screenshotId` возвращённый `id` снимка экрана, чтобы использовать координаты изображения. Без него используются целочисленные локальные координаты окна в размерах последнего наблюдаемого снимка экрана либо в размерах окна до получения снимка экрана. Прокрутка принимает одновременно `scrollX` и `scrollY` в одном вызове. Вторичные действия в настоящее время поддерживают Expand/Collapse; другие метки отклоняются.
- macOS: используйте возвращённый `id` приложения в качестве `app`. Прочитайте `get_app_state({app})`, затем вызовите `click({app,element_index,mouse_button?,click_count?})` или `click({app,x,y,mouse_button?,click_count?})`, `drag({app,from_x,from_y,to_x,to_y})`, `scroll({app,element_index,direction,pages?})` (или `x,y`), `press_key({app,key})`, `type_text({app,text})`, `paste({app,text,format:'text'})`, `set_value({app,element_index,value})`, `select_text({app,element_index,text,prefix?,suffix?,selection_type?})` или `perform_secondary_action({app,element_index,action})`.

Нативные перечни и структуры состояния различаются в зависимости от платформы; повторно используйте возвращённые ID и селекторы, а не дескрипторы обёртки App. Состояние Linux возвращает `ax_tree` и `screenshots`; записи снимков экрана содержат `filepath`, `bytes`, `data_url`. Состояние Windows выводит свои изображения снимков экрана. Остальные нативные результаты возвращаются для вывода через `nodeRepl.write`/`emitImage`; изменяющие методы возвращают undefined. Текущие разрешения хоста и приложений продолжают действовать, и присутствующий метод может отклонить вызов при недоступном бэкенде или неподдерживаемой операции. Обновите состояние после ошибки устаревшей цели (stale-target); не повторяйте ввод с неизвестным результатом. Не переносите активное перетаскивание между ходами; обновляйте наблюдения после сброса.


У нового REPL нет привязанных целей. Приведённые ниже точки входа выводят документацию API
и перечень объектов или начальное состояние цели. Идентификаторы браузеров поступают от настроенных CDP-провайдеров и подключённых провайдеров браузерных
расширений. Точные ID имеют приоритет; только при отсутствии точного совпадения `maka` и `chatgpt` выбирают единственную текущую конечную точку расширения. Если ни один из них недоступен, используйте нативные окна браузера через getApp. API не предоставляет функции администрирования драйвера, такие как start_session.

Установленное расширение ChatGPT с оригинальным нативным хостом обнаруживается автоматически в Chrome или Chromium. `listBrowsers()` отмечает его как `on_demand`; выбор этого браузера перехватывает управление до тех пор, пока `browser.release()` или очистка хода не восстановит исходный хост. Команда настройки, порт отладки или запуск десктопного приложения ChatGPT не требуются. Для работы с сайтами предпочитайте это подключение браузера нативному вводу в окно браузера.

Совместимость с ChatGPT обеспечивается по принципу «насколько возможно» (best effort). Точные ID и существующие дескрипторы никогда не переключают провайдеров.

Точки входа (выбор выводит начальное состояние):
- `await cua.getState({emit?})`: перечень приложений и доступных браузеров, включая ошибки формирования перечня.
- `await cua.listApps({emit?})`, `await cua.listWindows({pid?, emit?})`.
  Передайте наблюдаемый PID приложения, чтобы включить его плавающие панели в macOS.
  Записи окон содержат `pid` и `bindable`. Выбирайте окно с `bindable: true`.
  Недоступная привязка содержит `bindingError`. Привязываемые записи macOS также содержат
  `applicationId` и `appPath`. При привязке проверяются согласие для приложения и его актуальная идентичность.
- `const app = await cua.getApp("Name / bundle ID / app path")` или `getApp({windowId})`.
  macOS запускает отсутствующее приложение. В Windows getApp выбирает уже открытое окно;
  используйте `await cua.computer.launch_app({app: appId})` с ID из cua.listApps(),
  затем обновите перечень и выберите нужное окно.
  При неоднозначности имён выберите конкретное окно. Linux требует, чтобы приложение уже было открыто.
- `await cua.listBrowsers({emit?})`, `await cua.listTabs({browser?, emit?})`.
- `const browser = await cua.getBrowser({id? , url?})`: выбор без открытия вкладки.
  Предполагаемый URL не обязан уже быть открыт. Выберите конкретный ID, если доступно несколько провайдеров.
- `const tab = await cua.getTab("tab ID", {browser?})` или `getTab({url}, {browser?})`.
- `await cua.createBrowserTab(browserId, url?)`: открывает вкладку в профиле выбранного провайдера.
  Здесь и в getBrowser для URL без схемы используется HTTPS.
  Создание начинается с собственной пустой вкладки; явный URL затем запрашивает навигацию.
  При отказе в навигации эта пустая вкладка остаётся до очистки хода.
  Недоступные провайдеры, упоминания вкладок и неподдерживаемые параметры создания вызывают исключение.
- `await browser.tabs.list()`, `await browser.tabs.get(id)`, `await browser.tabs.new()`:
  получить список вкладок, привязать конкретную вкладку или создать пустую временную вкладку в этом браузере. Эти методы
  возвращают данные без их вывода; get/new возвращают объекты Tab без начального наблюдения AX.
  Вызовите getAXState перед использованием наблюдаемых целей. `await tab.title()` и `await tab.url()`
  возвращают текущие метаданные, не изменяя наблюдение доступности.

- Подключённые адаптеры браузеров также предоставляют `await browser.user.openTabs()` и
  `await browser.user.claimTab(tabOrId)`. Список возвращает текущие метаданные пользовательских вкладок;
  перехват возвращает обычный объект Tab после проверки текущих разрешений и подготовки подключения.
  Используйте строковый ID из списка или объект из списка. Очистка хода освобождает пользовательские вкладки,
  не закрывая их; вкладки, созданные этой сессией, остаются временными. `browser.tabs.get(id)` остаётся ленивой
  привязкой и не выполняет начального перехвата или наблюдения AX. Эти методы не
  сохраняют выданные разрешения. Для провайдеров расширений `browser.tabs.list()` перечисляет управляемые вкладки
  этой сессии. Настроенные CDP-провайдеры не имеют `browser.user`; используйте вместо этого их методы `browser.tabs`.

Maka предоставляет браузерный профиль AX: `tab.ax` содержит `get`, `write`, `click`,
`drag`, `paste`, `performSecondaryAction`, `pressKey`, `scroll`, `selectText`,
`setValue` и `typeText`. Сигнатуры действий совпадают с описанными ниже методами Tab.
`await tab.ax.get(mode = 'state', {disableDiffing?})` возвращает текст, байты изображения или
`{state, screenshot?}` для режимов `state`, `screenshot` или `both`, без вывода.
`await tab.ax.write(mode = 'state', options?)` выводит доступные результаты и
возвращает undefined. Существующие плоские методы Tab остаются доступными.
Фасад AX и плоские методы работают с одной и той же привязанной вкладкой Tab.

Наблюдения App и Tab:
- `getAXState({emit?, disableDiffing?})` возвращает текст. Вкладки и приложения macOS по умолчанию используют diff;
  приложения Windows и Linux возвращают полное состояние.
- `getScreenshot({emit?})` возвращает Uint8Array и выводит изображение.
- `getAXStateAndScreenshot(options?)` возвращает `{state, screenshot?}` и выводит доступные результаты.
Обнаружение, выбор и наблюдения выводят результат автоматически. Вызывайте их напрямую;
оборачивать `getScreenshot()` в `nodeRepl.emitImage()` или `getAXState()` в
`nodeRepl.write()` избыточно. Используйте `{emit:false}`, если обрабатываете результат
самостоятельно; ошибки перечня при этом всё равно отображаются. Нативные методы снимков экрана в Windows отклоняют
`{emit:false}` ещё до захвата. Одинаковые изображения, выведенные в рамках одного вызова,
доставляются один раз. Последующий вызов может вывести то же изображение снова.
Наблюдения включают ограниченное окно стабилизации для кратких обновлений UI (200 мс для
вкладок, 400 мс для приложений). Это не ожидание произвольной асинхронной работы;
непрерывная анимация не продлевает это окно. Для наблюдения более поздних изменений выполните обновление.
Успешный снимок экрана того же неизменившегося документа браузера сохраняет существующие
AX-ссылки. После навигации, замены документа или аннулирования цели
обновите `getAXState()` перед повторным использованием индексов; также обновляйте для вновь появившихся элементов. Нативные Linux/Windows сохраняют ранее наблюдаемые идентификаторы элементов,
пока именно эти элементы остаются действительными.
Если нативное наблюдение AX завершилось ошибкой, пока приложение было занято, обновите тот же привязанный объект,
когда приложение снова начнёт отвечать. Неудачные наблюдения делают старые индексы и координаты недействительными.

Действия App и Tab:
- `await app.bringToFront()` постоянно активирует именно привязанное нативное окно. Метод не отправляет ввод с клавиатуры или указателя и сообщает о неизвестном результате, если рабочий стол не может подтвердить активацию.
- `click(index | [x,y], {mouseButton?, clickCount?})`, `drag([x,y], [x,y])`.
- `scroll(index | [x,y], "up" | "down" | "left" | "right", distance?)`.
- Нативные приложения также принимают кнопки мыши `l/r/m` и направления `u/d/l/r`.
  macOS обрезает пробелы и игнорирует регистр для этих имён, а также принимает кнопки `0/1/2`
  для левой/правой/средней.
- `setValue(index, string)`; недоступно для нативных приложений Linux.
- `selectText(index, text, {prefix?, suffix?, selectionType?})`, где selectionType — это
  `text`, `cursor_before` или `cursor_after`. Нативное выделение доступно только в macOS.
  `text_not_found` означает, что текст или указанный контекст отсутствует; прочитайте текущее
  состояние снова. `ambiguous_text` требует более конкретного prefix/suffix.
- `performSecondaryAction(index, action)`: используйте точное действие, указанное в нативном
  наблюдении AX. CDP не предоставляет вторичных действий и отклоняет этот метод.

Ввод App: `typeText(text)`, `paste(text, {format?})`, `pressKey(key)`.
Ввод Tab: `typeText(index|null, text)`, `paste(index|null, text, {format?})`,
`pressKey(index|null, key)`. Указанный индекс сначала переводит фокус на наблюдаемое поле.
Используйте `null` для текущего фокуса. Примеры клавиш: `Return`, `Tab`, `super+a`, `shift+Left`.
Форматы вставки: `text` (по умолчанию), `md` (исходный код Markdown как обычный текст) и `html`.
Нативные приложения Linux и Windows поддерживают только `text`.
Нативная вставка HTML доступна только в macOS и требует читаемого редактируемого значения и выделения. Она временно
активирует нужное окно, сохраняет его выделение и восстанавливает прежний буфер обмена,
если пользователь не скопировал что-то более новое. Неизменившееся значение считается неопределённым результатом.
Вставка HTML в браузере требует наблюдаемого элемента contenteditable.

Навигация Tab: `goto(url)`, `back()`, `forward()`, `reload()`, `close()`.
`await tab.screenshot({ fullPage: false, clip: { x, y, width, height } })` возвращает байты JPEG без вывода изображения. Опустите `clip` для области просмотра; `fullPage: true` захватывает весь документ. Ширина и высота `clip` должны быть положительными. Координаты и размеры задаются в CSS-пикселях. Захват области просмотра сначала пытается получить свежий кадр скринкаста, а затем выполняет команду снимка экрана той же вкладки после подтверждённой очистки; неопределённые операции не повторяются.

У провайдеров расширений `await tab.markDeliverable()` оставляет вкладку открытой при нормальном завершении хода и передаёт её пользователю. `await tab.markHandoff()` сохраняет вкладку для этой же сессии; следующий фактический ход возобновит её уже без метки. Исходное происхождение (агент/пользователь) сохраняется, поэтому вкладка, созданная агентом, закроется при завершении последующего хода без метки. Более поздняя явная метка заменяет предыдущую. Оба метода возвращают undefined после соответствующего подтверждения (ACK) намерения, что не гарантирует физическую доставку или очистку. Метки не сохраняют разрешения сайтов; вызов с неопределённым результатом не повторяется. Прямой CDP не поддерживает эти метки.

`tab.clipboard` предоставляет `read()`, `readText()`, `write(items)` и `writeText(text)`.
Эти методы возвращают значения без их вывода. Расширенный элемент содержит непустой массив `entries`;
каждая запись имеет `mimeType` и ровно одно строковое поле: `text` или `base64`. Необязательное поле
`presentationStyle` принимает значения `unspecified`, `inline` или `attachment`. Например:
`await tab.clipboard.write([{entries:[{mimeType:'text/plain',text:'Hello'}]}])`.
Виртуальные данные разделяются между вкладками, использующими один и тот же настроенный контекст бэкенда;
они не читают и не изменяют системный буфер обмена ОС. Авторизованные страницы после установки
используют те же данные через свой Clipboard API. Агентский `readText()` возвращает текст
первой точной записи `text/plain` либо пустую строку для записи только с base64;
метод `readText()` на странице декодирует такую запись через Blob. Очистка хода удаляет
мосты страницы и сохраняет накопленные данные. Сброс создаёт новый пустой контекст.

Методы ожидания возвращают undefined. `locator.waitFor({state, timeoutMs?})` требует
`state: 'attached'|'detached'|'visible'|'hidden'` и проверяет первое совпадение;
отсутствие совпадений удовлетворяет состояниям `detached` и `hidden`.
`tab.playwright.waitForURL(pattern, {waitUntil?, timeoutMs?})` сопоставляется с полным URL:
`*` остаётся внутри сегмента между слешами, `**` может пересекать слеши, а остальные
символы трактуются буквально. Значение `waitUntil` по умолчанию — `commit`; `load`,
`domcontentloaded` и `networkidle` ожидают соответствующего состояния после совпадения.
`tab.playwright.waitForLoadState({state?, timeoutMs?})` по умолчанию использует `load`, а также
принимает `domcontentloaded` и `networkidle`. Эти условные ожидания по умолчанию ограничены
3000 мс и учитывают более длительные явные тайм-ауты. Ноль не оставляет бюджета ожидания событий:
локатор всё же делает первую проверку, текущий URL или состояние загрузки уже могут совпадать,
а networkidle завершается по тайм-ауту. `tab.playwright.waitForTimeout(ms)` принимает неотрицательное
целое число и ждёт фиксированную длительность. Для ожидания, запускаемого действием, сначала начните
ожидание до действия, а затем дождитесь обоих промисов. Остановка отменяет исходное ожидание.

`tab.playwright` разрешает DOM-локаторы без предварительного наблюдения AX.
Используйте `locator(selector)`, `getByRole`, `getByText`, `getByLabel`, `getByPlaceholder`
или `getByTestId`; `frameLocator(selector)` переходит внутрь фрейма. Локаторы поддерживают
`first/last/nth`, `filter`, `and/or`, `count`, `all`, `allTextContents`,
`textContent`, `innerText`, `getAttribute`, `isEnabled` и `isVisible`.
`domSnapshot()` возвращает текст DOM-доступности страницы.

Методы ввода для локаторов возвращают undefined: `click(options?)`, `dblclick(options?)`,
`fill(text, options?)`, `type(text, options?)`, `press(key, options?)`,
`pressSequentially(text, options?)`, `selectOption(valueOrValues, options?)`,
`setChecked(boolean, options?)`, `check(options?)` и `uncheck(options?)`.
Параметры клика принимают `button: 'left'|'right'|'middle'`, `modifiers`, `force` и
`timeoutMs`; параметры установки флажка принимают `force` и `timeoutMs`. Модификаторы: `Alt`,
`Control`, `ControlOrMeta`, `Meta` и `Shift`; `ControlOrMeta` соответствует платформе выбранного
браузера. Остальные параметры ввода принимают `timeoutMs`. Тайм-ауты — положительные целые числа;
подготовка по умолчанию занимает 3000 мс и учитывает более длительные явные тайм-ауты. Выбор опции принимает строковое значение или дескриптор с
`value`, `label` или неотрицательным целым `index`; массивы выбирают несколько опций.

Изменяющие операции локатора используют единственное совпадение или единственное видимое совпадение. Неоднозначные совпадения
вызывают исключение. Обычные fill/type текста используют событие виртуальной вставки, уважают отмену
обработчиком страницы и сохраняют содержимое буфера обмена. Пустая вставка по умолчанию не стирает
значение. Горячие клавиши буфера обмена используют тот же виртуальный буфер обмена;
неподдерживаемые комбинации вызывают исключение до отправки нативных клавиш. Успешные записи очищают
кэш чтения только у вызывающей коллекции локаторов. Результаты ввода всё равно необходимо
проверять на странице; неопределённый результат автоматически не повторяется.

Загрузки требуют подключённого провайдера расширения с уведомлениями о загрузках и текущего
разрешения хоста на скачивание. Подготовьте ожидание до запуска действия в той же вкладке Tab:
`const pending = tab.playwright.waitForEvent('download', {timeoutMs:3000});`
затем выполните клик или навигацию и `const download = await pending`.
`await download.path({timeoutMs?})` возвращает имя файла, сообщённое браузером, или null.
Метод не передаёт файл и не доказывает, что путь относится к этой задаче; это может быть
путь на другом хосте, пустое значение или недоступный путь. Операции saveAs нет.
`await tab.playwright.locator(selector).downloadMedia({timeoutMs?})` запрашивает скачивание медиа
для единственного совпадающего локатора. Ожидания загрузки возвращают данные без их вывода;
запуск скачивания медиа возвращает undefined. Нативный срок начала истекает на первом
подходящем событии Started; отмена и очистка хоста продолжают действовать после этого.
Разрешение на чтение и разрешение на загрузку независимы, в том числе при другом
источнике или целевом origin. Само по себе настроенное подключение CDP не предоставляет
нативных уведомлений о загрузке.
Maka также предоставляет `tab.cua.downloadMedia({x,y,timeoutMs?})` и
`tab.dom_cua.downloadMedia({node_id,timeoutMs?})` как узкие расширения. Выбранные
провайдеры расширений в настоящее время отклоняют эти команды скачивания медиа по координатам/узлу; используйте
реализованный маршрут через локатор. Неопределённый результат загрузки никогда не повторяется автоматически.
Возвращённый дескриптор сохраняет исходную привязку к Tab, но не разрешение. Держите эту вкладку
доступной: `path()` повторно проверяет текущие метаданные вкладки и разрешения хоста до
обращения к кэшу. Устаревший дескриптор не может удерживать закрытую вкладку открытой. В последующих ходах
по-прежнему требуется актуальный доступ к вкладке; может потребоваться перехватить вкладку заново.

`await tab.getJsDialog()` возвращает undefined или объект текущего диалога с полями
`type` и `dismiss()`. У диалогов подтверждения также есть `accept()`; у диалогов prompt есть
`accept(text)`, включая пустую строку. Старые объекты диалогов не могут взаимодействовать с
новым диалогом, пришедшим на смену. Обрабатывайте активный диалог до обычных чтений страницы или ввода.
`getAXState()` показывает его сообщение и индексированные элементы управления; элементы управления prompt поддерживают
`setValue`, `typeText` и Return/Escape. У элементов управления диалога нет координат на странице.
Снимки экрана недоступны, пока открыт диалог: вызовы только снимка экрана выбрасывают исключение,
а комбинированные наблюдения возвращают состояние диалога без свойства screenshot.
Подключённый хост браузера автоматически принимает диалоги beforeunload, пока удерживает
текущее управление. Очистка хода отсоединяет управление, не закрывая пользовательские вкладки.

Навигация поддерживает HTTP(S) и about:blank и ожидает наблюдаемого документа.
Охвачена основная цель CDP; доступность межпроцессных iframe неполная.
Расстояния прокрутки в страницах для CDP принимают конечные числа, включая дробные, ноль и отрицательные
значения. Одна страница равна ширине или высоте содержимого цели, минимум
100 CSS-пикселей; координатные цели используют область просмотра. Расширение CDP `{pixels:n}`
принимает положительные конечные смещения в пикселях.
Linux отклоняет числовые значения в страницах. Linux X11 по умолчанию использует `{pixels:800}` и принимает целые расстояния в пикселях от 1 до
65535. Он отправляет `max(round(pixels/100),1)` шагов колёсика; итоговое смещение содержимого
определяет приложение. Linux Wayland в настоящее время отклоняет ввод в пикселях.
Прокрутка в macOS принимает положительные конечные числа страниц (по умолчанию 1) и отклоняет
`{pixels}`. Дробное количество страниц поддерживается.
Windows требует точку координат и положительное конечное расстояние `{pixels:500}`;
отсутствующее расстояние и числовые значения в страницах отклоняются. Координаты и направленные расстояния используют
JavaScript `Math.round`; округлённые значения должны помещаться в знаковое 32-битное целое. Нативные смещения колёсика
ограничены по каждой оси диапазоном [-32768,32767], а указатель остаётся на цели.
Смещение содержимого определяет приложение. Нативная индексированная прокрутка сохраняет выбранную цель
доступности. Нативные индексированные клики через обёртку App поддерживают один семантический клик; для
множественных кликов используйте координаты снимка экрана. Низкоуровневый `cua.computer.click` в macOS также
поддерживает множественные индексированные клики через имитацию событий мыши.

Успешная отправка ввода не гарантирует итоговое состояние приложения.
Координатные действия в браузере используют CSS-координаты области просмотра и не требуют снимка экрана.
Снимки экрана не масштабируют эти координаты.
Локальные координаты окна в Linux можно использовать без снятия снимка экрана. Нативные
сопоставления снимков экрана в Linux/Windows сохраняются после действий ввода до тех пор, пока другое наблюдение
не заменит их; наблюдение только AX сбрасывает сопоставление изображения. После этого координатный ввод в Windows
требует нового снимка экрана. Изменение геометрии окна делает сохранённое сопоставление недействительным.
Координатный ввод в macOS в настоящее время требует нового снимка экрана после действия.
Нативные семантические действия используют сохранённые элементы доступности. Меню приложений
ограничены своим процессом-владельцем и именно привязанным окном; содержимое закрытого меню
опускается, пока меню не будет открыто. Взаимодействие с меню может активировать
привязанное окно и удерживает его активным, пока меню открыто.
Нативный координатный и клавиатурный ввод по умолчанию доставляется в фоне именно в
привязанное окно. Если фоновая доставка не поддерживается, сообщается об ошибке; ввод автоматически
не повторяется на переднем плане. Неподтверждённые эффекты уже могли быть доставлены.
Для сайтов предпочитайте операции через вкладки браузера (Tab): они не затрагивают фокус рабочего стола и
указатель. Для нативного ввода текста предпочитайте `typeText` или `setValue`; `paste` в macOS использует
системный буфер обмена и ввод с клавиатуры на переднем плане. Нативные меню могут активировать своё
окно. Некоторые координатные маршруты могут перемещать системный указатель; метаданные доставки
сообщают фактический маршрут. Нативные вызовы `app.pressKey(key, {deliveryMode:"foreground"})`
и `app.typeText(text, {deliveryMode:"foreground"})` явно запрашивают маршрут переднего плана,
когда это необходимо; по умолчанию используется `"background"`. Не повторяйте неподтверждённый ввод
автоматически и не переключайте режимы молча.

`nodeRepl.write(value)` выводит текст/JSON. `await nodeRepl.emitImage(bytes | dataUrl |
{bytes, mimeType})` выводит изображение. URL изображений File/HTTP, Node, произвольный доступ к файловой системе
и сетевые API недоступны. `cua.rewriteDocumentation()` повторно выводит эту справку.

Когда хост включает запись выходного аудио, `await cua.computer.start_audio_recording({max_duration_ms?})`
начинает запись и возвращает undefined, позволяя продолжать другие вызовы. Длительность по умолчанию
составляет 60000 мс и принимает целые числа от 100 до 300000. `await cua.computer.stop_audio_recording()`
возвращает `{filepath, bytes, data_url}` для завершённого стерео WAV PCM16 24 кГц. Достижение
предельной длительности останавливает запись; вызовите stop, чтобы получить результат. `await nodeRepl.emitAudio(bytes | dataUrl |
{bytes, mimeType})` явно выводит аудио. Эти методы отсутствуют, когда аудио отключено.
Сброс и очистка сессии удаляют записи и их локальные пути.

Каждая операция использует текущие разрешения хоста; JS-объекты не сохраняют выданных разрешений.
При выключенной песочнице сессии Computer Use, приложения, сайты в браузере, история,
передача файлов и аудио не требуют дополнительного подтверждения Maka. Изменение разрешений
или остановка текущей операции по-прежнему вступают в силу.
В режиме Ask подтверждение Computer Use происходит до запуска тайм-аута выполнения REPL.
Ожидания согласия для приложения, сайта в браузере и аудио ставят оставшийся бюджет на паузу. Нативные
ожидания macOS/Windows также ставят его на паузу; обычные асинхронные ожидания и нативные операции Linux
расходуют бюджет. Пауза никогда не восполняет бюджет и не отключает отмену.
Нативные операции macOS возвращают `desktop_locked`, пока экран заблокирован; подключённые
CDP-провайдеры и чистые вычисления в REPL остаются доступными независимо.
У каждой сессии свой курсор Maka. Действия ввода показывают его автоматически.
`cua.cursor.configure({label?, color?,
enabled?, reducedMotion?})` изменяет отображение для этой сессии. Доступные цвета: `blue`, `mint`,
`violet`, `amber`, `rose`, `cyan`; длина метки — до 48 символов. `cua.cursor.getState()`
возвращает настройки и нативную/браузерную видимость. Нативный рендерер в состоянии `idle` запускается
при первой нативной индикации; `unavailable` указывает на отсутствующий или сбойный хост отображения.
Вызовите configure повторно, чтобы перезапустить сбойный рендерер. Курсор принадлежит сессии, но не остаётся на экране после хода: он отображается во время хода, скрывается по окончании хода и появляется снова при следующем действии ввода.
Курсоры не разделяют полномочий ввода и не перемещают системный указатель. Несколько курсоров
не изолируют физическую клавиатуру, фокус приложений или метод ввода.
Отменённые, превысившие тайм-аут или исчерпавшие кучу REPL требуют вызова `cua_reset` с последующей повторной привязкой целей. Принятая
нативная работа завершается до возврата управления; сброс не отменяет уже отправленный ввод.
При нормальном завершении хода эта сессия закрывает созданные ею временные вкладки без меток и освобождает наблюдения страниц.
Ранее существовавшие пользовательские вкладки и помеченные сохраняемые вкладки остаются открытыми по описанным выше правилам. Сброс очищает REPL
и привязки этой сессии; он не выдаёт новых прав доступа и не снимает обязательств по сохранённым ресурсам и очистке этой сессии.
Неподтверждённая метка или закрытие сохраняют владение и не повторяются.

Та же коллекция браузеров доступна как `agent.browsers` и `cua.browsers`.
Её методы `list`, `get(id)`, `getDefault` и `getForUrl(url)` возвращают метаданные
или ленивые объекты Browser без вывода наблюдения. `cua.getBrowser` — это
удобная точка входа, выводящая документацию. Browser предоставляет `tabs.selected()`
для активной вкладки его логической сессии; это не выбирает вкладку, находящуюся в фокусе ОС.
У текущего прямого CDP-провайдера нет службы активной вкладки логической сессии, поэтому
`selected()` возвращает `undefined`.

`await browser.release()` возвращает аренду браузера ChatGPT по требованию этой сессии. Метод завершает временные вкладки текущего хода и физические ресурсы управления перед освобождением хоста; сохранённые страницы остаются открытыми. Другие сессии сохраняют собственные аренды. Последнее освобождение восстанавливает исходный нативный хост. Перед дальнейшим использованием получите аренду снова через `cua.getBrowser({id: "chatgpt"})`; дескрипторы от выведенного из работы поколения хоста требуют нового подключения. Обычная очистка хода также освобождает аренду. Долгоживущим агентам следует освобождать аренду перед переходом в режим ожидания. Другие провайдеры браузеров эту операцию не поддерживают.

`await browser.nameSession(name)` обрезает пробелы и сохраняет заголовок управляемой группы
сессии. Существующее управляемое представление обновляется через принадлежащие ему квитанции;
вновь создаваемые вкладки используют сохранённый заголовок. `cua.createBrowserTab(id, url,
{sessionName})` определяет браузер и дожидается назначения имени до создания вкладки.
Текущий профиль браузера не предоставляет возможность управления видимостью.

`await browser.history({queries, limit, from, to})` читает историю всего профиля
через расширение, которое объявляет отдельный транспорт истории. При включённой песочнице требуется
независимое согласие `browser_history` для фактического ID и поколения браузера
в рамках текущей границы разрешений сессии. Разрешения на страницы и загрузки его не авторизуют.
Ни один запрос истории не одобряется автоматически политикой origin страницы.
По умолчанию выполняется запрос по всей истории с ограничением в 100 записей; результаты переданных запросов
объединяются по убыванию времени посещения, дедуплицируются по URL и затем ограничиваются.
Встроенное расширение Maka объявляет разрешение history в Chrome; более старое установленное
расширение без этого разрешения не объявляет поддержку истории.
ChatGPT и другие сторонние адаптеры поддерживаются по принципу best effort.

- `await browser.user.getTabContext(tabOrId)` читает контекст видимой в данный момент
  пользовательской вкладки без её перехвата и перевода фокуса. Текущий URL вкладки авторизуется
  хостом; вызывающая сторона не может подставить другой URL. Приватные вкладки и URL, который
  изменился во время отдельного чтения, отклоняются. Результат имеет вид
  `{kind:'text',text,title,url,truncated}` или
  `{kind:'document',data,fileName,mimeType,title,url}`, где `data` — это
  `Uint8Array`, содержащий фактический экспортированный файл. Когда хост обеспечивает публикацию
  файлов, документы также содержат реальный `path`, принадлежащий сессии. Документы Google
  Workspace могут предоставлять контекст в Markdown, PDF или XLSX; обычные страницы
  могут включать текущее выделение, а страницы просмотра YouTube — транскрипт.
  Провайдер `maka` реализует фиксированные операции чтения; `chatgpt` повторно использует свой
  штатный протокол чтения, когда он поддерживается. Поддержка сторонних адаптеров остаётся best effort.

- `await tab.playwright.evaluate(pageFunction, arg?, {timeoutMs}?)` выполняет
  автономную функцию в контексте текущей страницы. Строка трактуется как
  выражение. Варианты для локатора передают `(element, arg)` в `locator.evaluate` или
  `(elements, arg)` в `locator.evaluateAll`; форма для одного элемента требует
  однозначной цели, а форма для всех элементов допускает пустое совпадение.
  Аргументы должны быть сериализуемы в JSON. Результаты представляют собой простые данные; функции и
  символы опускаются, большие целые числа преобразуются в строки, а неконечные числа —
  в `null`. Этот API ограничивает глубину результата значением 8, массивы — 2000 элементами,
  объекты — 200 ключами, а строки — 200000 единицами UTF-16, с маркерами `[MaxDepth]`,
  `[Circular]` и `[Truncated]` там, где это применимо.
- Выполнение предоставляет доступ только для чтения к DOM, CSS, геометрии, диапазонам (range) и выделению.
  Оно не предоставляет доступ к сети, cookie, загрузке модулей или редактированию DOM. Прокрутка,
  локальные границы диапазонов и таймеры только с функциями остаются поддерживаемыми операциями.
  Тайм-аут по умолчанию составляет 3000 мс; явные значения задают запрошенную длительность.
  Остановленный или прерванный скрипт уже мог выполниться; он не запускается повторно
  автоматически. Существующие разрешения сайтов и владение вкладкой продолжают действовать.

Ввод указателем в браузере доступен через `tab.cua.move({x,y,keys?})`,
`click({x,y,button?,keypress?})`, `double_click({x,y,keypress?})`,
`drag({path:[{x,y},...],keys?})` и
`scroll({x,y,scrollX,scrollY,keypress?})`. Координаты и расстояния — это числа CSS
области просмотра, сохраняющие дробные и отрицательные значения; кнопки: 1 (левая),
2 (средняя) или 3 (правая). Имена модификаторов указателя: Alt, Control, Meta, Shift и
ControlOrMeta. `tab.cua.keypress({keys:[...]})` отправляет комбинацию клавиш в текущий фокус;
`tab.cua.type({text})` вставляет текст в текущий фокус через виртуальный буфер обмена браузера,
сохраняя данные, находящиеся в буфере обмена. Текст может содержать Markdown;
Google Sheets получает обычный текст. Эти методы ввода возвращают undefined и не
повторяют ввод с неопределённым результатом.

`await tab.dom_cua.get_visible_dom()` возвращает видимый интерактивный HTML со
строковыми значениями `node_id`. Используйте именно эти строки с `click({node_id})` или
`double_click({node_id})`; `scroll({node_id?,x,y})` принимает расстояния прокрутки и
использует центр области просмотра, если node_id опущен. `keypress({keys:[...]})` и
`type({text})` используют текущий фокус, а не ID узла. Методы DOM возвращают undefined,
кроме снимка. Новый снимок выводит из обращения отсутствующие DOM-узлы; навигация или
замена фрейма могут сделать узел устаревшим. Выполните наблюдение заново вместо угадывания
ID или повторения ввода с неизвестным результатом.

### Диалоги выбора файлов и загрузка

```js
const pending = tab.playwright.waitForEvent('filechooser', { timeoutMs: 3000 });
await tab.playwright.getByRole('button', { name: 'Upload' }).click();
const chooser = await pending;
chooser.isMultiple();
await chooser.setFiles(['workspace-file.bin']);
```

Начните ожидание до действия, открывающего диалог выбора файлов. Ожидание события выбора файлов по умолчанию составляет 3000 мс; явный тайм-аут должен быть положительным целым числом. `isMultiple()` выполняется синхронно. `setFiles(pathOrPaths, {timeoutMs})` принимает один путь или непустой массив; диалог выбора одного файла отклоняет несколько путей. Его необязательный тайм-аут проверяется без отбрасывания уже запущенного выбора.

Пути относятся к файловой системе хоста агента (Agent Host) и подчиняются файловой политике рабочей области вызывающей стороны. Доступ к странице, согласие на загрузку для текущего HTTP(S)-origin и разрешение на чтение файлов независимы. Поддерживаемый снимок ввода — обычный файл. Файлы передаются как неизменяемые байты и материализуются выбранным хостом браузера Maka; не преобразуйте пути между операционными системами самостоятельно.

Дескрипторы выбора принадлежат вкладке, документу и ходу, в которых они были выданы. Выборщики из дочерних целей не поддерживаются. Выборщики расширений требуют полной информации о происхождении исходного события; для загрузок дополнительно требуется подтверждённое размещение файлов на хосте браузера. Chatgpt работает по принципу best effort, а настроенный CDP без такого размещения отклоняет загрузку до отправки файлов. Существующая привязанная вкладка никогда не заменяется другим браузером ради выполнения операции. Успешный выбор расходует дескриптор. Неизвестный результат необходимо сверить, а не повторять операцию.

Если очистка сообщает о неподтверждённом результате, не предполагайте, что скопированные данные загрузки удалены. Автоматическое освобождение после завершения хоста браузера, пока файлы остаются выбранными, пока недоступно.
