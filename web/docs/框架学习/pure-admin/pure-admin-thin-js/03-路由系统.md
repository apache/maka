# 03 - 路由系统

本章结论：路由分静态和动态两套。静态路由从 `src/router/modules/` 自动扫描注册，强制拍平成两级；动态路由登录后从 `/get-async-routes` 接口拉取，按角色过滤后手动 `addRoute`。所有动态行为的核心都在 `src/router/utils.js`，守卫逻辑在 `src/router/index.js` 的 `router.beforeEach`。

## 先建立心智模型

把路由表想象成一家公司的组织架构。静态路由是公司的常设部门（首页、错误页、登录页），开业前就定好；动态路由是项目组（权限管理这类业务菜单），由"总部"（后端接口）按你的职级（roles）临时任命。守卫（beforeEach）是门口的保安，核对工牌后才放行，工牌不对的送进 403 房间。

## 静态路由：自动扫描与两级拍平

`src/router/index.js` 顶部用 Vite 的 glob 导入自动收集路由模块：

```js
const modules = import.meta.glob(
  ["./modules/**/*.js", "!./modules/**/remaining.js"],
  { eager: true }
);
```

在 `src/router/modules/` 下新建 `.js` 文件并导出默认路由对象，重启后自动生效，无需手动 import（`remaining.js` 被排除，单独处理）。目前该目录有三个文件：

- `home.js`：根路由 `/`，指向 Layout，redirect 到 `/welcome`。
- `error.js`：`/error/403`、`/error/404`、`/error/500`。
- `remaining.js`：登录页、全屏 403/500、redirect 中转页，这些页面不进侧边栏菜单。

收集到的原始路由要经过一条加工链才能注册，加工链本身值得逐个认识：

```
routes.flat(Infinity)          # 摊平嵌套数组
  → ascending()                # 按 meta.rank 升序，首页永远第一
  → buildHierarchyTree()       # 修复父子关系（utils/tree.js）
  → formatFlatteningRoutes()   # 多级嵌套摊成一维
  → formatTwoStageRoutes()     # 一维重新拼成两级
```

为什么要强制拍平成两级？`src/router/utils.js` 的 `formatTwoStageRoutes` 注释给了原因：**vue-router 的 keep-alive 只支持两级缓存**，三级以上路由会导致页面缓存失效。所以无论业务路由嵌套多深，最终注册的都是"Layout 一层 + 页面一层"。侧边栏显示的层级来自 `constantMenus`（保持原始层级的那份数据），和实际注册的路由层级是两回事，这个分离是理解本模板路由的关键。

`ascending` 还有一个细节：没写 `meta.rank` 的路由会按出现顺序自动补 `index + 2`，`rank: 0` 只留给首页。想让菜单排前面，给路由的 `meta.rank` 一个小数字即可。

## 动态路由：从接口到注册

核心函数是 `src/router/utils.js` 的 `initRouter()`，三个场景会调它：登录成功后（`src/views/login/index.vue` 的 `onLogin`）、刷新页面时守卫发现菜单为空、退出登录后的重置。

流程分四步：

**第一步，拉取。** 调 `src/api/routes.js` 的 `getAsyncRoutes()`，请求 `/get-async-routes`。mock 返回一个权限管理菜单（`mock/asyncRoutes.js`）。

**第二步，可选缓存。** 如果 `platform-config.json` 里 `CachingAsyncRoutes: true`，路由数据会缓存进 localStorage 的 `async-routes` 键，下次刷新不再发请求。默认是 `false`，每次刷新都拉。

**第三步，补全规范。** `addAsyncRoutes()` 对后端返回的数据做兼容处理，规则有四条，写后端路由接口时必须知道：

| 规则 | 说明 |
| --- | --- |
| 标记来源 | 自动给 `meta` 加 `backstage: true`，标识后端返回的路由 |
| 父级 redirect | 父级没写 redirect 时，自动取第一个子级的 path |
| 父级 name | 父级没写 name 时，自动取"第一个子级的 name + Parent"后缀，避免与子级重名导致重定向跳 404 |
| 组件解析 | `meta.frameSrc` 存在则用 IFrame 组件（`src/layout/frame.vue`）；否则拿 `component` 字段（不传就用 path）去匹配 `import.meta.glob("/src/views/**/*.{vue,jsx}")` 的结果 |

组件解析这条最实用：后端传 `"component": "permission/button/index"`，前端就在 views 目录里找路径包含这段字符串的文件。所以**后端返回的 component 字符串必须能与 `src/views` 下的实际文件路径对上**，对不上渲染出来就是空白。

**第四步，注册。** `handleAsyncRoutes()` 把路由逐条 push 进根路由的 children 并调用 `router.addRoute()`，同时保持 `router.options.routes[0].children` 与 path 为 `/` 的路由的 children 一致（不一致会出诡异 bug，源码注释特别强调过）。注册完才组装菜单（`handleWholeMenus`）并添加全屏 404 兜底。

404 兜底的添加时机是个精妙细节：`addPathMatch()` 在动态路由注册**之后**才把 `/:pathMatch(.*)` 加进路由表。如果反过来先加 404，刷新一个动态路由页面时，首次导航会先命中 404，造成"刷新就 404"的假 bug。

## 路由守卫：保安的工作流程

`src/router/index.js` 的 `router.beforeEach` 是全站访问控制的总闸，逻辑按登录状态分岔：

**已登录**（cookie 里有 `multiple-tabs` 且 localStorage 里有 `user-info`）：

1. 目标路由配了 `meta.roles` 且与用户角色无交集，跳 `/error/403`。
2. 开了 `VITE_HIDE_HOME` 时手动访问 `/welcome` 会被送进 404。
3. `_from.name` 不存在说明是刷新场景：此时如果菜单为空就调 `initRouter()` 重建路由，恢复标签页后重新 `router.push` 一次。源码注释提醒：刷新时守卫可能触发两次，依赖守卫做副作用的代码要在 `to.name` 存在的条件下写，避免执行两遍。
4. 目标路由的 name 是个 URL，说明是外链菜单，调 `openLink` 新窗口打开。

**未登录**：访问白名单（只有 `/login`）放行，其余一律 `removeToken()` 后送回登录页。

守卫还顺带做了两件小事：给页面标题拼上站点名（`document.title`），以及用 NProgress 显示顶部进度条（已加载过的页面不再重复显示，靠 `loadedPaths` 这个 Set 记录）。

## 常见误解纠偏

**误解一：菜单就是路由。** 侧边栏菜单来自 `constantMenus` + `wholeMenus`（permission store），路由表是另一份数据。菜单过滤（`filterNoPermissionTree` 按角色剔除）只影响显示，路由守卫才管真正的访问控制。只改菜单不过滤角色，用户手敲 URL 照样能进，只是会被守卫拦到 403。

**误解二：动态路由刷新后丢失是 bug。** 路由表存在内存里，刷新即清空，然后守卫检测到菜单为空会重新拉取重建。如果重建失败（接口挂了、token 失效），表现就是刷新后 404 或弹回登录页，这是设计内的行为。

**误解三：新建页面要在某个总路由文件里登记。** 静态路由放进 `src/router/modules/` 自动生效；动态路由由后端下发。不存在需要手动 import 的中央路由文件。
