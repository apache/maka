# 08 - 布局系统与全局配置

本章结论：布局是一个自适应性很强的壳，`src/layout/index.vue` 根据 app store 的 layout 值在三种导航形态间切换，并用 ResizeObserver 实现了窄屏自动折叠；所有默认外观集中在 `public/platform-config.json`，运行时可改；主题与暗色模式由 `useDataThemeChange` 驱动。

## layout 目录地图

| 路径 | 职责 |
| --- | --- |
| `src/layout/index.vue` | 布局主壳，组装下列所有部件 |
| `components/lay-sidebar/` | 侧边栏三种形态：`NavVertical`（左侧）、`NavHorizontal`（顶部）、`NavMix`（混合）；子组件含 Logo、菜单项、折叠按钮 |
| `components/lay-navbar/` | 顶栏：菜单搜索、全屏、用户头像、通知等 |
| `components/lay-tag/` | 标签页栏，样式由 `TagsStyle` 配置（默认 chrome） |
| `components/lay-setting/` | 右侧设置抽屉：布局切换、主题色、界面开关 |
| `components/lay-content/` | 内容区，承载 router-view 与 keep-alive |
| `components/lay-search/` | Ctrl + Shift + K 菜单搜索弹窗，带历史记录 |
| `components/lay-notice/` | 通知中心 |
| `components/lay-frame/`、`layout/frame.vue` | 内嵌 iframe 页面的容器（配合路由 `meta.frameSrc`） |
| `components/lay-footer/`、`lay-panel/` | 页脚与通用面板 |
| `hooks/` | useNav、useLayout、useTag、useDataThemeChange、useBoolean、useMultiFrame |
| `types.js` | 导出 `routerArrays`（标签页初始集合） |

## 三种布局如何切换

布局主壳没有用一堆 v-if 拼接，而是把顶部区域写成了一个渲染函数组件 `LayHeader`（`src/layout/index.vue` 里 `defineComponent` + `h`），按 layout 值决定放 `LayNavbar` 还是 `NavHorizontal`，尾部固定拼上 `LayTag`。侧边栏同理：vertical 和 mix 显示 `NavVertical`，horizontal 隐藏侧边栏只留顶部导航。

布局值的来源链：platform-config 的 `Layout` 字段 → responsive-storage 的 `responsive-layout` → app store 的 `layout`。设置抽屉里切换布局时（`setTheme` 函数），同时更新 DOM 的 `layout` 属性和本地存储，刷新后保持。

## 响应式行为：窄屏三档

`src/layout/index.vue` 用 `useResizeObserver` 监听主容器宽度，注释里写明了三档规则：

| 容器宽度 | 行为 |
| --- | --- |
| 0 - 760px | 切 mobile 设备模式，隐藏侧边栏，显示遮罩抽屉 |
| 760 - 990px | 折叠侧边栏（只收一次，`isAutoCloseSidebar` 防抖） |
| > 990px | 展开侧边栏，除非用户手动点过折叠（`isClickCollapse` 标记） |

这套逻辑和"用户意愿优先于自动行为"的细节（手动折叠后拉宽屏幕不再自动展开）是模板作者打磨过的地方，二开时别轻易删。

## platform-config 全键位速查

全局外观的默认值都在 `public/platform-config.json`，运行时请求加载（第 02 篇讲过链路）。常用键位：

| 键 | 默认值 | 作用 |
| --- | --- | --- |
| `Title` | PureAdmin | 站点名，页面标题后缀、登录页标题 |
| `Layout` | vertical | 默认布局 |
| `Theme` / `ThemeMode` / `DarkMode` | light / light / false | 主题三件套 |
| `FixedHeader` | true | 固定头部 |
| `ShowLogo` / `HideTabs` / `HideFooter` | true / false / false | 界面显隐开关 |
| `TagsStyle` | chrome | 标签页样式 |
| `MultiTagsCache` | false | 标签页持久化 |
| `KeepAlive` | true | 页面缓存总开关 |
| `CachingAsyncRoutes` | false | 动态路由缓存到 localStorage |
| `Watermark` / `WatermarkText` | false / 空 | 水印开关与文案 |
| `ResponsiveStorageNameSpace` | responsive- | 本地存储命名空间 |
| `MenuSearchHistory` | 6 | 菜单搜索历史条数 |

再次强调第 07 篇的结论：改这些默认值只影响清空过存储的新用户。

## 主题与暗色模式

主题切换的入口是 `src/layout/hooks/useDataThemeChange.js` 的 `dataThemeChange()`，布局主壳在 `onBeforeMount` 时就用当前 `themeMode` 初始化一次。它做的事：切换 html 上的暗色类（配合 `src/style/dark.scss` 覆盖变量）、更新 element-plus 主题色（epTheme store）、同步 responsive-storage。登录页左上角那个明暗开关也直接调这个 hook。

灰度模式、弱化模式（`Grey`、`Weak`）同理，是往 html 上挂属性类，配合 `src/style/index.scss` 里的全局滤镜实现。

## 常见误解纠偏

**误解一：侧边栏菜单是 lay-sidebar 自己过滤的。** 菜单数据来自 permission store 的 `wholeMenus`（第 07 篇），lay-sidebar 只负责渲染。想控制菜单显隐，去路由的 `meta.showLink` 或角色配置，别在组件里改。

**误解二：布局切换要写代码。** 全部是配置驱动，`Layout` 字段改 `horizontal` 或 `mix` 重启即可，`NavMix.vue` 会在 mix 模式下被 lay-content 体系自动启用。

**误解三：水印是后端图片或 CSS 背景。** 是 `@pureadmin/utils` 的 `useWatermark()` 用 canvas 画的，`src/App.vue` 里 watch 配置即时重绘，文案来自 `watermarkText`，登录页强制不带。
