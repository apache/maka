# 01 - 初识与快速上手

本章结论：pure-admin-thin-js 是 vue-pure-admin 的付费精简 JS 版，v7.0.0，自带登录鉴权、动态路由、三级权限和 mock 数据，删掉了业务页面留给你填业务。跑通它只需要 node 20+ 和 pnpm 9+，两条命令，默认账号 admin。

## 一句话说清它是什么

把它理解成一栋精装修的毛坯房：承重墙（路由、权限、请求、状态管理）、水电（构建、规范、部署）都装好了，房间（业务页面）只留了四个样板间（首页、登录、权限演示、错误页），其余空间等你按业务装修。

它和官方仓库的关系：

- [vue-pure-admin](https://github.com/pure-admin/vue-pure-admin)：免费完整版，业务页面最全。
- pure-admin-thin：免费精简 TS 版，只剩骨架。
- pure-admin-thin-js：本仓库，精简骨架的 JS 版（无国际化），付费私有。
- pure-admin-thin-max-js：增强付费版，多了字典、定时任务、多租户模块（工作区里的兄弟目录）。

## 版本与分支

当前代码 `package.json` 的 `version` 是 7.0.0，非国际化 JS 版。远程有三个分支，内容差异如下表。

| 分支 | 内容 | 适用场景 |
| --- | --- | --- |
| `main`（当前） | 精简骨架，4 个演示页面 | 从这里开始开发 |
| `origin/full` | 额外带 `system` 模块（部门、菜单、角色、用户管理页面） | 需要参考系统管理页面写法时拉下来对照 |
| `origin/i18n` | 带国际化的 JS 版 | 需要多语言时参考 |

注意 `main` 分支没有系统管理页面。如果你要写用户管理、菜单管理这类页面，`git show origin/full:src/views/system/user/index.vue` 可以直接查看 full 分支的写法作为参考，不需要合并整个分支。

## 跑起来

环境要求：Node `^20.19.0 || >=22.13.0`，pnpm `>=9`。`package.json` 的 `preinstall` 脚本用了 `npx only-allow pnpm`，用 npm 或 yarn 安装会直接报错终止，这是刻意的防护。

```bash
# 安装依赖。用途：按 pnpm-lock.yaml 精确安装。预期：生成 node_modules，无报错
pnpm install

# 启动开发服务器。用途：本地开发。预期：终端打印构建信息后，浏览器打开 http://localhost:8848
pnpm dev
```

登录页默认已经填好账号 `admin`、密码 `admin123`，直接点登录就能进首页。输入其他用户名（比如 `common`）也能进，但拿到的角色和按钮权限不同，第 04 篇会展开。

第一次启动有两个预期现象，别当成 bug：

1. 终端会出现一个带渐变色和 boxen 边框的构建信息面板，来自 `build/info.js` 的 `viteBuildInfo()` 插件。
2. 首页内容只有一行标题 "Pure-Admin-Thin（非国际化版本）"，见 `src/views/welcome/index.vue`，它是空样板。

## 默认页面清单

`src/views/` 下只有这四个目录，每个都能当样板间用：

| 目录 | 路由 | 用途 |
| --- | --- | --- |
| `welcome/` | `/welcome` | 首页占位，替换成你的仪表盘 |
| `login/` | `/login` | 登录页，含表单校验、动画、记住登录 |
| `permission/page/`、`permission/button/` | `/permission/*` | 页面级和按钮级权限的活教材 |
| `error/` | `/error/403`、`/error/404`、`/error/500` | 错误页，配合路由守卫跳转 |

业务代码全部从零写，模板不带任何现成业务模块（没有列表页、表单页的完整示例，第 12 篇会带你手写一个完整的）。

## 开发中最高频的几条命令

| 命令 | 用途 | 预期结果 |
| --- | --- | --- |
| `pnpm dev` | 启动开发服务 | 8848 端口，热更新生效 |
| `pnpm lint` | 依次跑 eslint、prettier、stylelint 并自动修复 | 无输出且退出码 0 表示通过 |
| `pnpm build` | 生产构建 | 生成 `dist/`，产物在 `dist/static/js`、`dist/static/css` 等子目录 |
| `pnpm report` | 构建并打开打包分析 | 自动弹出 `report.html`，看体积大头 |

## 初学者最容易踩的三个误解

**误解一：这是个开源 MIT 项目，可以随便传播。** `package.json` 里写着 MIT，但 `README.md` 明确这是付费私有仓库，合同效力高于开源许可证模板，禁止售卖和公开源码。放进公司内部项目用没问题，推到公网仓库不行。

**误解二：echarts 在依赖里，首页就该有图表。** `echarts ^6.0.0` 确实装了，但 `src/main.js` 里 `useEcharts` 的导入被注释掉了，welcome 页面也没用它。依赖装了和功能启用了是两回事，精简版保留依赖是为了让你少装一步。

**误解三：改了 `public/platform-config.json` 不生效。** 这个文件在启动时通过 axios 请求加载（第 02 篇讲链路），改完需要重启 dev server。它和 `.env` 文件一样都要求重启，Vite 的热更新只覆盖源码目录。
