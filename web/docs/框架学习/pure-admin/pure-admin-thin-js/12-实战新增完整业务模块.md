# 12 - 实战：新增一个完整业务模块

本章结论：新增一个业务模块涉及五类文件：路由模块、页面、接口定义、mock 数据、权限标注。本篇以"知识库"模块为例（列表、搜索、新增），把每一类文件的最小可用写法全部给出，代码可直接复制运行。写完这个模块，前面十一篇的所有机制你都会在真实代码里各见到一次。

## 目标与文件清单

做一个知识库管理页：左侧无目录，侧边栏出现"知识库"菜单，进去是带搜索的列表，管理员可以点"新增"弹窗建条目，普通用户只能看。

| 步骤 | 新建文件 | 对应机制 |
| --- | --- | --- |
| 1 | `src/router/modules/knowledge.js` | 静态路由自动注册（第 03 篇） |
| 2 | `src/api/knowledge.js` | HTTP 层（第 06 篇） |
| 3 | `mock/knowledge.js` | mock 契约（第 10 篇） |
| 4 | `src/views/knowledge/index.vue` | 页面 + keep-alive（第 07 篇）+ 按钮权限（第 04 篇） |

不需要动 `src/router/index.js`（glob 自动收集），不需要动任何菜单组件（菜单由路由数据渲染）。

## 第一步：路由模块

新建 `src/router/modules/knowledge.js`：

```js
// 本地静态路由：不经过 /get-async-routes，适合不依赖后端菜单的模块
const Layout = () => import("@/layout/index.vue");

export default {
  path: "/knowledge",
  name: "Knowledge",
  component: Layout,
  redirect: "/knowledge/index",
  meta: {
    icon: "ep:collection",       // 离线 Iconify 图标（第 09 篇）
    title: "知识库",
    rank: 5                      // 菜单排序，小于权限管理的 10
  },
  children: [
    {
      path: "/knowledge/index",
      name: "KnowledgeIndex",
      component: () => import("@/views/knowledge/index.vue"),
      meta: {
        title: "知识库",
        // roles: ["admin"]      // 页面级权限：需要限制时打开，未配置则人人可访问
        keepAlive: true           // 配合组件同名参与页面缓存
      }
    }
  ]
};
```

要点核对：父级 component 固定用 Layout；子级 name 与页面组件的 `defineOptions` name 保持一致（下一步会写）；`rank` 不写也能用，会自动补序号。重启 dev server（路由模块的 glob 收集发生在启动时），侧边栏立刻多出"知识库"菜单。

## 第二步：接口定义

新建 `src/api/knowledge.js`：

```js
import { http } from "@/utils/http";

/** 知识库列表（按关键字搜索） */
export const getKnowledgeList = params => {
  return http.request("get", "/knowledge-list", { params });
};

/** 新增知识条目 */
export const addKnowledge = data => {
  return http.request("post", "/add-knowledge", { data });
};
```

响应已被拦截器解包一层，页面里拿到的就是 `{code, message, data}`。

## 第三步：mock 数据

新建 `mock/knowledge.js`：

```js
import { defineFakeRoute } from "vite-plugin-fake-server/client";

// 内存态数据，重启 dev server 后重置
const list = [
  { id: 1, title: "pure-admin 路由机制", category: "前端", updatedAt: "2026-09-01" },
  { id: 2, title: "token 无感刷新方案", category: "前端", updatedAt: "2026-09-01" }
];

export default defineFakeRoute([
  {
    url: "/knowledge-list",
    method: "get",
    response: ({ query }) => {
      const keyword = query.keyword ?? "";
      return {
        code: 0,
        message: "操作成功",
        data: list.filter(item => item.title.includes(keyword))
      };
    }
  },
  {
    url: "/add-knowledge",
    method: "post",
    response: ({ body }) => {
      list.unshift({
        id: list.length + 1,
        updatedAt: new Date().toISOString().slice(0, 10),
        ...body
      });
      return { code: 0, message: "操作成功", data: null };
    }
  }
]);
```

mock 支持热更新，保存即生效，不用重启。

## 第四步：页面

新建 `src/views/knowledge/index.vue`：

```vue
<script setup>
import { ref, reactive, onMounted } from "vue";
import { getKnowledgeList, addKnowledge } from "@/api/knowledge";
import { hasPerms } from "@/utils/auth";
import { message } from "@/utils/message";
import PureTableBar from "@/components/RePureTableBar/src/bar";

defineOptions({
  name: "KnowledgeIndex" // 与路由 name 一致，keep-alive 生效的前提
});

const loading = ref(false);
const keyword = ref("");
const tableData = ref([]);
const dialogVisible = ref(false);
const form = reactive({ title: "", category: "" });

async function loadData() {
  loading.value = true;
  try {
    const res = await getKnowledgeList({ keyword: keyword.value });
    if (res.code === 0) tableData.value = res.data;
  } finally {
    loading.value = false;
  }
}

async function onAdd() {
  if (!form.title) return message("标题不能为空", { type: "warning" });
  const res = await addKnowledge({ ...form });
  if (res.code === 0) {
    message("新增成功", { type: "success" });
    dialogVisible.value = false;
    form.title = "";
    form.category = "";
    loadData();
  }
}

onMounted(loadData);
</script>

<template>
  <div>
    <el-card shadow="never">
      <div class="mb-3 flex items-center gap-2">
        <el-input
          v-model="keyword"
          placeholder="搜索标题"
          clearable
          class="max-w-50!"
          @keyup.enter="loadData"
        />
        <el-button type="primary" @click="loadData">搜索</el-button>
        <!-- perms 轨道按钮权限：common 用户拿不到 add code，看不到此按钮 -->
        <Perms value="knowledge:add">
          <el-button type="primary" @click="dialogVisible = true">
            新增
          </el-button>
        </Perms>
      </div>

      <el-table v-loading="loading" :data="tableData">
        <el-table-column prop="title" label="标题" />
        <el-table-column prop="category" label="分类" width="120" />
        <el-table-column prop="updatedAt" label="更新时间" width="140" />
      </el-table>
    </el-card>

    <el-dialog v-model="dialogVisible" title="新增知识条目" width="420px">
      <el-form label-width="60px">
        <el-form-item label="标题">
          <el-input v-model="form.title" />
        </el-form-item>
        <el-form-item label="分类">
          <el-input v-model="form.category" />
        </el-form-item>
      </el-form>
      <template #footer>
        <el-button @click="dialogVisible = false">取消</el-button>
        <el-button type="primary" @click="onAdd">确定</el-button>
      </template>
    </el-dialog>
  </div>
</template>
```

示例有意选了 el-table 起步。生产级列表页换 `@pureadmin/table`（依赖已装，全局注册为 PureTable，`src/main.js` 里 `app.use(Table)`）加 RePureTableBar，能白得刷新、列设置、密度三个工具，写法参考 `origin/full` 分支的 `src/views/system/user/index.vue`。`hasPerms` import 了但模板里主要用组件形态演示，函数形态适合出现在方法逻辑里。

## 验证流程

按顺序执行，每步都有明确的预期：

1. 重启 `pnpm dev`（路由模块需要重新 glob）。
2. `admin/admin123` 登录，侧边栏出现"知识库"菜单，进入后看到两条 mock 数据。
3. 点"新增"，填写并确定，列表刷新出第 0 行新数据，这是 `/add-knowledge` 全链路。
4. 退出登录，用任意非 admin 用户名（如 `common`）登录，同一个页面"新增"按钮消失（permissions 里没有 `knowledge:add`），搜索仍可用。
5. 想验证页面级权限：打开路由里注释的 `roles: ["admin"]`，common 用户再访问会被守卫送进 403。

第 4 步不生效的话，检查 mock/login.js 里给该用户名返回的 `permissions` 数组是否包含 `knowledge:add`。为了让 common 用户看到按钮权限差异，可以在 mock 的 common 分支 permissions 里加上 `knowledge:add` 之外的对照。

## 切到动态路由（可选）

如果菜单由后端管理，删掉 `src/router/modules/knowledge.js`，在后端 `/get-async-routes` 的返回里追加（对照 `mock/asyncRoutes.js` 的结构）：

```js
{
  path: "/knowledge",
  meta: { title: "知识库", icon: "ep:collection", rank: 5 },
  children: [
    {
      path: "/knowledge/index",
      name: "KnowledgeIndex",
      component: "knowledge/index",   // 与 src/views 下的路径对应（第 03 篇解析规则）
      meta: { title: "知识库", roles: ["admin", "common"], keepAlive: true }
    }
  ]
}
```

注意动态路由模式下 `component` 是字符串，`keepAlive` 和 `roles` 的语义与静态路由完全相同。两种方式不要同时用，会出现重复路由被去重逻辑跳过的混乱。
