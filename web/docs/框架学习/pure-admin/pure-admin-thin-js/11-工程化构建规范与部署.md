# 11 - 工程化：构建、规范与部署

本章结论：工程化配置全部集中在 `build/` 目录和根目录的几个配置文件里，提交卡控由 husky + lint-staged + commitlint 组成三道闸，部署提供 Docker 两阶段构建的现成方案。这一篇的定位是速查手册，按需查阅。

## build 目录：Vite 的插件盒子

`vite.config.js` 本身很薄，所有插件和工具都从 `build/` 导入：

| 文件 | 职责 |
| --- | --- |
| `build/plugins.js` | 插件总装：tailwind、vue、jsx、代码定位、构建信息、路由警告抑制、mock、svg、图标按需、CDN、压缩、移除 console、打包分析 |
| `build/cdn.js` | `VITE_CDN=true` 时把大依赖替换为 CDN 引用 |
| `build/compress.js` | 按 `VITE_COMPRESSION` 生成 gzip/brotli 产物，`-clear` 后缀变体同时删除原始文件 |
| `build/info.js` | 启动时终端打印的构建信息面板 |
| `build/optimize.js` | 依赖预构建的 include/exclude 清单 |
| `build/utils.js` | `wrapperEnv`（环境变量类型转换）、`alias`、`pathResolve`、`__APP_INFO__` |

几个值得知道的插件行为：

- **code-inspector-plugin**：开发时按 Alt + Shift（Mac 为 Option + Shift）点击页面元素，自动打开 IDE 定位到对应代码行，找代码利器。
- **vite-plugin-router-warn**：只抑制 vue-router 动态路由在开发环境的 "No match found" 警告（动态路由注册前的那次导航），只在服务启动时运行一次。
- **vite-plugin-remove-console**：生产构建移除 console，调试信息别依赖它在线上保留。
- **rollup-plugin-visualizer**：只在 `pnpm report` 时激活，产出 `report.html`。

构建目标 `es2015`，产物按类型分目录：`static/js/[name]-[hash].js`、`static/[ext]/[name]-[hash].[ext]`，超限告警阈值放宽到 4000KB。

## 脚本速查

`package.json` 的 scripts 与开发流程的对应关系：

| 命令 | 场景 | 说明 |
| --- | --- | --- |
| `pnpm dev` / `pnpm serve` | 日常开发 | 两者等价，dev 显式给了 4GB 内存上限 |
| `pnpm build` | 生产构建 | 先 rimraf dist，8GB 内存上限 |
| `pnpm build:staging` | 预发构建 | 走 `.env.staging`，无压缩等配置差异时与 build 等价 |
| `pnpm report` | 体积分析 | 构建并打开 report.html |
| `pnpm preview` / `preview:build` | 本地验证产物 | preview:build 是先构建再预览 |
| `pnpm svgo` | svg 压缩 | 递归处理当前目录 |
| `pnpm lint` | 提交前自检 | eslint + prettier + stylelint 三连 |
| `pnpm clean:cache` | 环境重置 | 清 eslint 缓存、lockfile、node_modules 后重装 |

## 提交三道闸

git commit 时 husky 依次触发 lint-staged 和 commitlint，任何一关失败提交都会被拒绝。

**第一道，lint-staged**（`.lintstagedrc`）：只检查暂存文件。js/jsx 走 prettier + eslint；vue 额外过 stylelint；css/scss/html、json、md 各有对应的 prettier 处理。

**第二道，commitlint**（`commitlint.config.js`）：message 必须符合 `type: subject` 格式，允许的 type 有十五个：feat、fix、perf、style、docs、test、refactor、build、ci、chore、revert、wip、workflow、types、release；header 上限 108 字符；包含 "init" 的提交跳过检查。

**第三道，pre-push 无**：模板只配置了 pre-commit 阶段（`.husky/`），推送前没有额外卡点。

日常写代码的正确姿势：改完 `pnpm lint` 自检，提交 message 用 `feat: xxx` / `fix: xxx` 格式，中文 subject 完全合法。

## Docker 部署

根目录 `Dockerfile` 是两阶段构建，可以直接用：

```dockerfile
# 阶段一：node:20-alpine 里 corepack 激活 pnpm，npmmirror 源
# pnpm install --frozen-lockfile 严格按 lockfile 安装
# pnpm build 产出 dist
# 阶段二：nginx:stable-alpine，把 dist 拷进 /usr/share/nginx/html，暴露 80
```

构建与运行：

```bash
# 构建镜像。用途：产出可部署的 nginx 静态镜像。预期：本地生成镜像 pure-admin
docker build -t pure-admin .

# 运行。用途：本地验证容器。预期：浏览器访问 http://localhost:8080
docker run -d -p 8080:80 pure-admin
```

Dockerfile 没有拷贝 nginx 配置，用的默认配置。**history 路由模式上线必须配 try_files 回退到 index.html**，模板默认用 hash 模式所以不需要；如果改成 `h5`，记得在 nginx 配置里补：

```nginx
location / {
  try_files $uri $uri/ /index.html;
}
```

## 上线前检查清单

以下每一项都对应本系列前面讲过的坑：

1. mock 开关已处理：`build/plugins.js` 的 `enableProd` 已改为 false 或插件已移除（第 10 篇）。
2. `expires` 时间戳适配：`src/utils/auth.js` 的 setToken 已按后端格式调整（第 05 篇）。
3. 登出补了服务端 token 销毁调用（第 05 篇）。
4. 响应拦截器补了统一错误提示（第 06 篇建议）。
5. `VITE_PUBLIC_PATH` 与部署子路径一致；用子路径时 `VITE_ROUTER_HISTORY` 带 base 参数（第 10 篇变量表）。
6. 内网部署检查过图标方案，无在线 Iconify 依赖（第 09 篇）。
7. 生产产物验证过登录流程走真实接口而非 mock。
