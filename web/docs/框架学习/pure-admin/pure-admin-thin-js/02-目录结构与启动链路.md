# 02 - 目录结构与启动链路

本章结论：这份模板的目录按"配置、骨架、机制、页面"四层组织，启动链路是 index.html → main.js → 拉取全局配置 → 注册插件 → 挂载路由 → 渲染 App.vue。理解这条链路后，任何"启动就报错"的问题你都能定位到具体环节。

## 目录地图

先看整体，再逐层解释。`src` 下的每个目录职责单一，没有交叉污染。

```
src/
├── api/              # 接口定义，按业务拆文件（目前只有 user.js、routes.js）
├── assets/           # 静态资源：iconfont 字体、svg、登录页配图
├── components/       # 通用组件，Re 前缀族（第 09 篇展开）
├── config/           # 全局配置加载器（platform-config.json 的读取入口）
├── directives/       # 自定义指令：auth、perms、copy、longpress、optimize、ripple
├── layout/           # 布局骨架：侧边栏、导航栏、标签页、设置抽屉（第 08 篇展开）
├── plugins/          # element-plus 按需注册
├── router/           # 路由核心：index.js 守卫 + utils.js 动态路由（第 03 篇展开）
├── store/            # Pinia 模块：app、epTheme、multiTags、user、permission（第 07 篇展开）
├── style/            # 样式：reset、tailwind、主题 scss
├── utils/            # 工具箱：http、auth、message、localforage、tree 等（第 09 篇展开）
├── views/            # 页面，与路由一一对应
├── App.vue           # 根组件
└── main.js           # 启动入口
```

仓库根目录还有两块和 `src` 平级的关键内容：`mock/`（假接口，第 10 篇展开）和 `build/`（Vite 插件配置，第 11 篇展开）。

路径别名在 `jsconfig.json` 里定义：`@/*` 指向 `./src/*`，`@build/*` 指向 `./build/*`。源码里所有 `@/xxx` 导入都走这个映射，Vite 侧的解析由 `build/utils.js` 的 `alias` 提供，两处配置必须保持一致。

## 启动链路逐步走

整条链路在 `src/main.js`，一共七步，顺序有讲究。

**第一步，静态导入。** 样式三件套（`reset.scss`、`index.scss`、`tailwind.css`）和 element-plus 全量 CSS 在这里加载。`tailwind.css` 特意在 main.js 引入，注释说明了原因：避免 Vite 每次热更新都重新请求整个 `index.scss` 导致热更新慢。

**第二步，注册自定义指令。** `import * as directives from "@/directives"` 后遍历注册，对应 `src/directives/index.js` 里的六个导出：auth、perms、copy、longpress、optimize、ripple。

**第三步，注册全局组件。** 三个图标组件（`IconifyIconOffline`、`IconifyIconOnline`、`FontIcon`）和两个权限组件（`Auth`、`Perms`）注册为全局，所以模板里直接用，不需要 import。

**第四步，`getPlatformConfig(app)`。** 这是链路的第一道关口，实现在 `src/config/index.js`。它用 axios 请求 `public/platform-config.json`，把返回的对象合并进 `app.config.globalProperties.$config`，并缓存到模块级变量供 `getConfig()` 随时读取。请求失败会抛出明确提示"请在public文件夹下添加platform-config.json配置文件"。

这里有个设计要点值得注意：全局配置走 HTTP 请求加载，不走 import。好处是部署后改一个 JSON 文件就能换标题、换默认布局，不需要重新构建；代价是这条链路天然是异步的，后面所有初始化都包在 `getPlatformConfig().then()` 里。

**第五步，`setupStore(app)` 注册 Pinia。** `src/store/index.js` 只做了 `createPinia` 和 `app.use`，很薄。

**第六步，挂载路由并等待就绪。** `app.use(router)` 后 `await router.isReady()`，确保首次导航（包括路由守卫里的异步逻辑）完成后才挂载应用，避免闪一下空白或权限页。

**第七步，`injectResponsiveStorage` 并注册 UI 插件。** `src/utils/responsive.js` 把 platform-config 里的布局、主题、界面显示配置注入 responsive-storage（一个让 localStorage 拥有响应式能力的库），命名空间前缀取自配置项 `ResponsiveStorageNameSpace`，默认 `responsive-`。最后挂上 MotionPlugin（动画）、element-plus 和 `@pureadmin/table`，`app.mount("#app")`。

一句话记住这条链：**先有配置，再有状态，再有路由，最后才有页面**。配置加载失败会卡在第四步，Pinia 注册失败卡在第五步，依此类推。启动白屏时按这个顺序打断点，比全局搜索报错快得多。

## App.vue 里藏的两个全局行为

`src/App.vue` 看着只有几行，做了两件影响全局的事：

1. **路由切换自动关弹窗。** `router.beforeEach(() => closeAllDialog())`，任何页面跳转都会调用 `src/components/ReDialog` 的 `closeAllDialog()`，防止弹窗跨页面残留。
2. **水印全局响应。** watch 了 `$storage.configure` 的 `watermark`、`watermarkText` 和当前路由名，开关或文案变化时立即重画水印，登录页强制无水印。

另外根组件包了 `el-config-provider` 并固定 `zh-cn` 中文语言包。这份是非国际化版本，想做多语言要用 `origin/i18n` 分支，在这个基础上改工程量会很大。

## 初学者最容易混淆的一点

`platform-config.json`（运行时配置）、`.env` 系列（构建时配置）、`src/config/index.js`（配置加载器）三者经常被混为一谈。区分方法看修改后需不需要重新构建：

| 配置 | 修改后 | 加载时机 | 典型内容 |
| --- | --- | --- | --- |
| `public/platform-config.json` | 重启即可，生产环境替换文件即可 | 浏览器运行时 HTTP 请求 | 标题、布局、主题、缓存开关 |
| `.env` / `.env.development` / `.env.production` | 必须重新构建（开发环境重启 dev server） | Vite 构建时注入 `import.meta.env` | 端口、路由模式、CDN、压缩开关 |
| `src/config/index.js` | 属于源码 | 跟随代码打包 | `getConfig()` 读取逻辑，一般不改 |
