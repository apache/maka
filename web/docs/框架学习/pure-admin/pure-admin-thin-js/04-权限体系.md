# 04 - 权限体系

本章结论：权限分两层。页面级靠路由 `meta.roles`，由路由守卫强制执行；按钮级有两套并行的机制，`auths` 从路由配置来，`perms` 从登录接口来，组件、函数、指令三种用法一一对应。模板用 `/permission` 下的演示页把这两层都演示了一遍，是最值得精读的活代码。

## 类比先行

页面级权限像小区门禁：你有没有资格进这栋楼（这个页面），没有就直接拦下送走。按钮级权限像公司门禁卡的开门权限列表：你能进楼，但这张卡能开哪些房间（新增、编辑、删除按钮）各不相同。模板里小区门禁只有一种刷法（roles），房间钥匙却有两套管理系统，这正是初学者最容易晕的地方。

## 页面级权限：roles

数据来源是路由的 `meta.roles` 数组，用户角色存在 localStorage 的 `user-info` 里（登录时写入）。执行点有两处：

**第一处，路由守卫。** `src/router/index.js` 的 `beforeEach` 里，用 `isOneOfArray(to.meta?.roles, userInfo?.roles)` 判断两个数组有没有交集，没有交集跳 `/error/403`。注意 `isOneOfArray`（`src/router/utils.js`）在任一方不是数组时直接返回 true，也就是**没配 roles 的路由所有人可访问**。

**第二处，菜单过滤。** `src/router/utils.js` 的 `filterNoPermissionTree()` 在组装菜单时递归剔除无权限项，子菜单全部被剔除的空目录也会被 `filterChildrenTree()` 摘掉。这就是上一篇文章说的"菜单隐藏，守卫兜底"：菜单只管不显示，守卫管真进不来。

mock 数据里，`admin` 和 `common` 两个角色都能访问权限演示页（`mock/asyncRoutes.js` 里两个子菜单都配了 `roles: ["admin", "common"]`），想验证 403 效果，可以把某条路由的 roles 改成只留 `admin`，再用 `common` 用户登录访问。

## 按钮级权限：双轨制

两套机制思路相同（对比 code 列表），差别只在 code 从哪来。对照表先放上，后面逐个展开。

| | auths 轨道 | perms 轨道 |
| --- | --- | --- |
| code 来源 | 路由 `meta.auths`（后端下发路由时带上，或静态路由里写死） | 登录接口返回的 `permissions` 字段，存进 user store |
| 判断函数 | `hasAuth()`（`src/router/utils.js`） | `hasPerms()`（`src/utils/auth.js`） |
| 全局组件 | `<Auth value="...">` | `<Perms value="...">` |
| 指令 | `v-auth` | `v-perms` |
| 超管通配 | 无 | `*:*:*` 表示拥有全部权限 |
| 演示页面 | `src/views/permission/button/index.vue` | `src/views/permission/button/perms.vue` |

**auths 轨道**。`getAuths()` 直接读当前路由的 `meta.auths`，`hasAuth(value)` 拿它和传入的 code 对比。传字符串判断"是否包含"，传数组要求**全部满足**（内部用 `isIncludeAllChildren`）。mock 的权限管理菜单里，"路由返回按钮权限"这个页面配了三个 code：`permission:btn:add`、`permission:btn:edit`、`permission:btn:delete`。

**perms 轨道**。登录接口返回什么，用户就有什么。mock 里 `admin` 拿到 `["*:*:*"]`（全权），`common` 拿到 `["permission:btn:add", "permission:btn:edit"]`（没有 delete）。`hasPerms` 检测到 `*:*:*` 直接放行，其余逻辑和 `hasAuth` 一致。

**三种用法**以 perms 轨道为例（auths 轨道把 `Perms`/`hasPerms`/`v-perms` 换成 `Auth`/`hasAuth`/`v-auth` 即可）：

```vue
<!-- 组件式：包住按钮，无权限时不渲染 -->
<Perms value="permission:btn:add">
  <el-button>新增</el-button>
</Perms>

<!-- 函数式：配合 v-if，逻辑更灵活 -->
<el-button v-if="hasPerms('permission:btn:edit')">编辑</el-button>

<!-- 指令式：最简洁 -->
<el-button v-perms="'permission:btn:delete'">删除</el-button>
```

## 常见误解纠偏

**误解一：两套机制随便混用。** code 来源不同，混用会出"明明配了却不生效"的假 bug。排查口诀：先确认这个按钮属于哪条轨道，路由下发的是 auths，登录返回的是 perms。判断函数、组件、指令三件套必须配套使用。

**误解二：指令和组件等价。** 三个演示页面里指令卡片的标题专门标注了"该方式不能动态修改权限"。指令在 mounted 时操作一次 DOM，之后权限变化它不会跟着变；组件和函数走 Vue 渲染机制，是响应式的。权限在页面存活期间会变的场景，用组件或函数。

**误解三：按钮隐藏就安全了。** 权限控制的是显示，真正的防线必须在后端接口。前端任何权限方案都是体验层，绕过浏览器直接调接口的场景只有服务端能拦。
