# 02 · 启动链路

一句话定义：`src/main.js` 按固定顺序做七件事，第一件事就是发一个网络请求拉平台配置，这决定了整个项目的配置体系分成"构建期"和"运行期"两层。

上一篇：[01 项目全景](./01-项目全景与运行指南.md) ｜ 下一篇：[03 静态路由与菜单](./03-静态路由与菜单.md)

## 先打个比方

开店要按顺序来：先拿到经营手册，再装好收银系统，规划完动线，登记老会员的偏好，最后才开门迎客。`main.js` 干的就是这件事，顺序乱一步就开不了门。

## 两个配置层

这是本篇最重要的概念。这个项目有两套配置，很多"改了没生效"的问题都出在分不清它们。

| | `.env` 系列文件 | `public/platform-config.json` |
| --- | --- | --- |
| 加载时机 | 构建期，Vite 启动时注入 `import.meta.env` | 运行期，`main.js` 里用 axios 发请求获取 |
| 生效条件 | 改完必须重启 dev server | 浏览器刷新即生效，不用重启 |
| 能力边界 | 只能存字符串，参与代码替换 | 完整 JSON 对象，支持嵌套读取 |
| 典型内容 | 端口、路由模式、CDN 开关 | 标题、布局模式、主题、存储命名空间 |

`platform-config.json` 当前全部字段值得过一遍，后面每篇都会用到其中几个：

| 字段 | 当前值 | 用在哪 |
| --- | --- | --- |
| `Title` | `"PureAdmin"` | 浏览器标签、登录页标题 |
| `Layout` | `"double"` | 布局模式，第 10 篇的主题 |
| `KeepAlive` | `true` | 页面缓存总开关 |
| `MultiTagsCache` | `false` | 标签页是否持久化到 localStorage |
| `CachingAsyncRoutes` | `false` | 动态路由是否缓存到 localStorage，第 04 篇 |
| `MenuStyle` | `"popular"` | 菜单风格，max 版增强功能 |
| `ResponsiveStorageNameSpace` | `"responsivemaxjs-"` | 本地存储的 key 前缀，第 08 篇 |
| `MenuSearchHistory` | `6` | 菜单搜索保留的历史条数 |

读取工具在 `src/config/index.js`。`getPlatformConfig` 发起请求，失败时抛出一句中文提示"请在public文件夹下添加platform-config.json配置文件"，如果你哪天看到这个报错，说明文件丢了。读取支持点路径，比如 `getConfig().Title`，也可以 `getConfig("a.b")` 深层取值，取不到返回 `null`。

## main.js 的七步

打开 `src/main.js`，对着下面的顺序读，代码就是按这个顺序写的。

1. `createApp` 之后导入三份样式（重置、公共、tailwind）和 iconfont 字体图标。注释里特意说明 tailwind.css 必须在 main.js 引，否则热更新会整体重载样式文件，变慢。
2. 注册 6 个自定义指令，来自 `src/directives`：`auth`、`perms`（权限相关，第 05 篇）、`copy`、`longpress`、`optimize`、`ripple`。
3. 注册全局组件：三个图标组件（`IconifyIconOffline`、`IconifyIconOnline`、`FontIcon`）和权限组件 `Auth`、`Perms`，再装上 vue-tippy 气泡提示。
4. `getPlatformConfig(app)` 发请求拉配置。**注意这一步是 await 的**，请求没回来，后面全部不执行。这就是为什么弱网下首屏前会有一小段空白。
5. 配置到手后装 Pinia（`setupStore`），装路由，然后 `await router.isReady()` 等路由就绪。
6. `injectResponsiveStorage(app, config)` 把用户的界面偏好注入 responsive-storage。第 08 篇细讲。
7. 装 MotionPlugin（登录页的入场动画）、Element Plus、@pureadmin/table，最后 `app.mount("#app")`。

有两处被注释掉的预留能力，读代码时别疑惑：`plugins/echarts.js`（图表）和 `PureDescriptions` 组件，用的时候把注释打开即可。`src/utils/sso.js`（单点登录）在 router 入口也留了同样的注释位。

## 为什么顺序不能乱

顺序即依赖。第 5 步的 Pinia 和路由初始化要读平台配置（比如 `getConfig().Title`），所以配置请求必须最先完成。第 6 步的偏好注入要在 Pinia 之后，因为 multiTags store 初始化时要读 `configure` 里的 `multiTagsCache` 来决定标签页从哪恢复。你以后往启动链路里加自己的初始化逻辑时，先想清楚它依赖谁、谁依赖它，再决定插在哪一步。

## 新手常见误区

**改 `.env` 没生效。** 环境变量在 dev server 启动时注入，改完要重启。改成 `platform-config.json` 里的字段则刷新浏览器就行。

**全局搜不到 `$config` 在哪定义。** 它是运行时挂到 `app.config.globalProperties` 上的，定义在 `src/config/index.js` 的 `getPlatformConfig` 里，静态搜索 `const $config` 之类是找不到完整来源的。

**以为所有配置都能进 `platform-config.json`。** 只有启动早期就要用的配置适合放那（渲染前就得知道标题、布局）。请求类的、构建类的各回各家。

## 动手验证

1. 打开 `public/platform-config.json`，把 `Title` 改成 `我的后台`，保存后只刷新浏览器（不重启终端），标签页标题和登录页标题都变了。再把 `.env` 里的 `VITE_PORT` 改成 9999 并保存，观察终端毫无反应，重启后才生效。这个对比做完，两个配置层的边界就刻在脑子里了。
2. 在 `src/main.js` 第 55 行 `getPlatformConfig(app).then` 处打个断点（或在 console 里把 Network 节流设为 Slow 3G），刷新页面，观察首屏渲染被配置请求阻塞。
3. Network 面板确认 `/login`、`/get-async-routes` 这些请求的 URL 没有域名前缀，它们是相对路径，第 09 篇讲对接后端时这一步很关键。
