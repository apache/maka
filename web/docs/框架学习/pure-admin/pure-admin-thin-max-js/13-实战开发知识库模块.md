# 13 · 实战：开发知识库模块

一句话定义：毕业题。用前十二篇的知识，按平台既有范式新增一个"知识库"模块（文章列表：搜索、分页、标签、状态、弹窗表单），全程只加文件加配置，不改任何骨架代码。

上一篇：[12 工程化与构建](./12-工程化与构建.md)

## 为什么选"知识库"当毕业题

一是它呼应了这个项目的规划方向。二是规模适中：一个列表页加一个表单弹窗，刚好覆盖六个考点——mock 接口（第 09 篇）、api 层（第 09 篇）、动态路由注册（第 04 篇）、页面四件套范式（第 11 篇）、权限控制（第 05 篇）、规范提交（第 12 篇）。

需求描述：管理员维护团队知识库的文章，能按标题关键词、分类、状态搜索，分页展示，能新增和编辑文章（标题、分类、标签、状态、正文摘要）。普通用户不可见。

新建 `mock/knowledge.js`。注意分页做了真实的切片，比现有 mock 只回全量列表更进一步：

    updateTime: 1725033600000

    updateTime: 1727712000000
  }
];

export default defineFakeRoute([
  // 分类下拉
  {
    url: "/kb-category",
    method: "get",

  },
  // 文章分页列表
  {
    url: "/kb-article",
    method: "post",
    response: ({ body }) => {
      let list = articles.filter(v => v.title.includes(body?.title ?? ""));
      if (body?.categoryId) list = list.filter(v => v.categoryId === body.categoryId);
      if (body?.status !== "" && body?.status != null) {
        list = list.filter(v => String(v.status) === String(body.status));
      }
      const pageSize = body?.pageSize ?? 10;
      const currentPage = body?.currentPage ?? 1;
      return {
        code: 0,
        message: "操作成功",
        data: {
          list: list.slice((currentPage - 1) * pageSize, currentPage * pageSize),
          total: list.length,
          pageSize,
          currentPage
        }
      };
    }
  }
]);

## 第二步：api 层

新建 `src/api/knowledge.js`（独立文件，不往 `system.js` 里堆）：

```js
import { http } from "@/utils/http";

/** 知识库-分类下拉 */
export const getKbCategory = () => {
  return http.request("get", "/kb-category");
};

/** 知识库-文章分页列表 */
export const getKbArticle = data => {
  return http.request("post", "/kb-article", { data });
};
```

`src/views/knowledge/utils/hook.jsx`，全部逻辑：

```jsx
import dayjs from "dayjs";
import { h, ref, reactive, onMounted } from "vue";
import editForm from "../form/index.vue";
import { message } from "@/utils/message";
import { addDialog } from "@/components/ReDialog";
import { deviceDetection } from "@pureadmin/utils";
import { getKbCategory, getKbArticle } from "@/api/knowledge";
import { usePublicHooks } from "@/views/dict/hooks";   // 复用状态开关配色

export function useKnowledge() {
  const formRef = ref();
  const dataList = ref([]);
  const loading = ref(true);
  const categoryList = ref([]);
  const { switchStyle } = usePublicHooks();
  const pagination = reactive({
    total: 0, pageSize: 10, currentPage: 1, background: true
  });
  const searchForm = reactive({ title: "", categoryId: "", status: "" });

  const columns = [
    { label: "编号", prop: "id", minWidth: 70 },
    { label: "标题", prop: "title", minWidth: 180 },
    { label: "分类", prop: "categoryName", minWidth: 110 },
    {
      label: "标签", minWidth: 160,
      cellRenderer: ({ row }) => h(
        "div",
        { class: "flex justify-center gap-1" },
        row.tags.map(t => h("el-tag", { key: t, size: "small" }, { default: () => t }))
      )
    },
    {
      label: "状态", prop: "status", minWidth: 100,
      cellRenderer: ({ row }) => (
        <el-switch
          v-model={row.status}
          active-value={1} inactive-value={0}
          active-text="已发布" inactive-text="草稿" inline-prompt
          style={switchStyle.value}
        />
      )
    },
    {
      label: "更新时间", prop: "updateTime", minWidth: 160,
      formatter: ({ updateTime }) => dayjs(updateTime).format("YYYY-MM-DD HH:mm")
    },
    { label: "操作", fixed: "right", width: 120, slot: "operation" }
  ];

  async function onSearch() {
    loading.value = true;
    const { code, data } = await getKbArticle({
      title: searchForm.title,
      categoryId: searchForm.categoryId,
      status: searchForm.status,
      pageSize: pagination.pageSize,
      currentPage: pagination.currentPage
    });
    if (code === 0) {
      dataList.value = data.list;
      pagination.total = data.total;
    }
    setTimeout(() => { loading.value = false; }, 300);
  }

  function handleSizeChange(val) {
    pagination.pageSize = val;
    onSearch();
  }

  function handleCurrentChange(val) {
    pagination.currentPage = val;
    onSearch();
  }

  function openDialog(title = "新增", row) {
    addDialog({
      title: `${title}文章`,
      props: {
        formInline: {
          title: row?.title ?? "",
          categoryId: row?.categoryId ?? "",
          tags: row?.tags?.join(",") ?? "",
          summary: row?.summary ?? ""
        }
      },
      width: "40%",
      draggable: true,
      fullscreen: deviceDetection(),
      closeOnClickModal: false,
      contentRenderer: () => h(editForm, { ref: formRef, formInline: null }),
      beforeSure: (done, { options }) => {
        const FormRef = formRef.value.getRef();
        const curData = options.props.formInline;
        FormRef.validate(valid => {
          if (valid) {
            // 实际开发先调用新增/修改接口，成功后再执行以下动作
            message(`已${title}文章「${curData.title}」`, { type: "success" });
            done();
            onSearch();
          }
        });
      }
    });
  }

  onMounted(async () => {
    const { code, data } = await getKbCategory();
    if (code === 0) categoryList.value = data;
  });

  return {
    loading, columns, dataList, pagination, categoryList, searchForm,
    onSearch, openDialog, handleSizeChange, handleCurrentChange
  };
}
```

`src/views/knowledge/utils/rule.js`：

```js
import { reactive } from "vue";

export const rules = reactive({
  title: [{ required: true, message: "请输入文章标题", trigger: "blur" }],
  categoryId: [{ required: true, message: "请选择分类", trigger: "change" }]
});
```

一个和字典页的细微差异值得注意。字典页把弹窗模式（新增/修改）也塞进了 `formInline.title`，表单组件内部会读它；本模块的表单组件不关心模式，所以 `formInline` 里只放文章字段，模式靠 `beforeSure` 闭包里的 `title` 变量使用。两种都行，但一个模块内要保持一致，混用会在维护时埋雷。

## 第五步（可选）：按钮权限

给"新增文章"加权限，两种方式任选。登录下发式：mock 登录接口的 `permissions` 数组里加 `knowledge:article:add`，模板里 `<el-button v-perms="'knowledge:article:add'">`。路由下发式：路由 meta 加 `auths: ["knowledge:article:add"]`，用 `v-auth`。第 05 篇的选型结论是默认用前者。

## 验证清单

1. 重启 `pnpm dev`（mock 是 node 侧代码，必须重启）。
2. `admin` 登录，左侧菜单出现"知识库"，位于字典管理之后（rank 14）。
3. 列表出数据，三个搜索条件分别测试：标题关键词、分类、状态。
4. 翻页正常，pageSize 改成 20 后 mock 的切片正确。
5. 新增和修改弹窗能打开，空标题提交被规则拦下，合法提交弹成功提示并刷新列表（数据不落库，演示级写操作）。
6. `common` 登录，菜单无"知识库"；地址栏直输 `/#/knowledge/index` 落到 403。
7. 切到移动端宽度，弹窗自动全屏（`fullscreen: deviceDetection()`）。
8. 提交代码，信息用规范格式：`feat: 新增知识库模块`。

## 接真实后端时改什么

只改两处。`src/api/knowledge.js` 的两个 URL 换成真实路径（配合第 09 篇的代理配置），mock 里的 `/kb-article` 删除或保留给开发期兜底。hook、form、rule 一行不动，这就是 api 层单独建文件买来的分层红利。
