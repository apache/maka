## 先打个比方

连锁快餐店不靠厨师发挥，靠标准作业流程。中央厨房（平台组件）备好半成品，门店（业务页面）按同一张流程卡出餐。这个项目的流程卡就是"四件套"。

## 四件套

以字典管理页为例，一个标准管理页由四个文件构成：

| 文件 | 职责 | 字典页对应 |
| --- | --- | --- |
| `index.vue` | 模板与布局，不写业务逻辑 | `src/views/dict/index.vue`，约 120 行，大部分是模板 |
| `utils/hook.jsx` | 全部逻辑：状态、列定义、请求、弹窗 | `useDict()` |
| `form/*.vue` | 弹窗里的表单组件 | `form/index.vue`（字典详情）、`form/dict.vue`（字典树节点） |
| `utils/rule.js` | 表单校验规则 | reactive 规则对象 |

后缀 `.jsx` 不是笔误，列定义里的自定义渲染要用 JSX 写，Vite 的 vueJsx 插件（第 12 篇）提供支持。

## index.vue 的骨架

照抄这段结构，换名字就能用：

```html
<script setup>
import { useDict } from "./utils/hook";

defineOptions({ name: "SystemDict" });   // 必须与路由 name 一致

const { loading, columns, dataList, pagination, onSearch, openDialog } = useDict();
</script>

<template>
  <PureTableBar title="字典管理" :columns="columns" @refresh="onSearch">
    <template #buttons>
      <el-button type="primary" @click="openDialog()">新增</el-button>
    </template>
    <template v-slot="{ size, dynamicColumns }">
      <pure-table :columns="dynamicColumns" :data="dataList"
        :pagination="pagination" :loading="loading" :size="size">
        <template #operation="{ row }"> <!-- 操作列插槽 --> </template>
      </pure-table>
    </template>
  </PureTableBar>
</template>
```

`defineOptions({ name })` 那行单独强调。keep-alive 按组件名缓存，这个名字必须和路由的 `name` 完全一致，大小写也算。忘了写或写错，页面的缓存、标签页刷新等功能静默失效，控制台不报错，属于"最难查的一类问题"。

## hook 里都有什么

打开 `src/views/dict/utils/hook.jsx` 的 `useDict()`，五类东西：

**状态。** `dataList`（表格数据）、`loading`、`pagination`（reactive 的 `{total, pageSize: 10, currentPage: 1, background: true}`）、`dictId`（左树选中项）。

**列定义 columns。** 每列 `label / prop / minWidth`，特殊列加料：

- `cellRenderer`：JSX 渲染。字典标签列渲染成带 `row.color` 颜色的按钮，状态列渲染成 `el-switch` 开关。
- `formatter`：纯文本格式化，创建时间用 dayjs 转字符串。
- `slot: "operation"`：声明该列交给模板的 `#operation` 插槽，操作按钮写在模板里，因为要拿到 `size` 和作用域。

**请求方法。** `onSearch` 是唯一取数入口，调 `getDictDetail({dictId})`，成功后把 `list/total/pageSize/currentPage` 各归各位，finally 里关 loading。

**交互方法。** `onTreeSelect` 响应左树选中并重新 `onSearch`；`onChange` 处理状态开关。

**弹窗方法。** `openDialog` 和 `openDictDialog`，下一节展开。

## addDialog：全项目统一的弹窗

弹窗不写 `.vue` 模板里的 `el-dialog`，统一调 `@/components/ReDialog` 的 `addDialog(options)`。以字典详情为例：

```js
function openDialog(title = "新增", row) {
  addDialog({
    title: `${title}字典详情`,
    props: { formInline: { title, label: row?.label ?? "", ... } },  // 表单初始值
    width: "32%",
    draggable: true,
    fullscreen: deviceDetection(),      // 移动端自动全屏
    closeOnClickModal: false,
    contentRenderer: () => h(editForm, { ref: formRef, formInline: null }),
    beforeSure: (done, { options }) => {
      const FormRef = formRef.value.getRef();
      const curData = options.props.formInline;    // 表单当前值
      FormRef.validate(valid => {
        if (valid) {
          // 实际开发在这里调用新增/修改接口
          message("操作成功", { type: "success" });
          done();        // 关弹窗
          onSearch();    // 刷新列表
        }
      });
    }
  });
}
```

五个关键点。第一，新增和修改共用一个方法，靠 `title` 区分。第二，表单初始值从 `props.formInline` 进，当前值从 `options.props.formInline` 出，表单组件内部对它做双向绑定。第三，`contentRenderer` 用 `h` 挂载表单组件并传 `ref`，表单组件必须暴露 `getRef()` 返回 el-form 实例，这是平台对表单组件的硬约定。第四，`beforeSure(done)` 里 `done()` 负责关弹窗，校验不过不调 done，弹窗就不关。第五，ReDialog 还支持 `beforeCancel`（拦截取消）、`sureBtnLoading`（确定按钮 loading）、`popconfirm`（确定前二次确认）、自定义 `footerButtons`，字典树右键编辑用的就是同一套。

## PureTableBar 与公共小件

`PureTableBar`（`src/components/RePureTableBar`）是表格上方的工具条，内置刷新按钮、列设置（显隐 + 拖拽排序，拖拽用 sortablejs）、紧凑度切换。它的 `columns` 必须由 hook 提供，写死在模板里就享受不到列设置。

三个公共件出场率极高，写页面时直接用：

- `src/views/dict/hooks.js` 的 `usePublicHooks()`：`tagStyle` 和 `switchStyle`，返回适配明暗两套主题的 CSS 变量。状态列的 tag 和 switch 都靠它上色。
- `@/utils/message`：对 ElMessage 的封装，统一样式和用法。
- `deviceDetection()`：移动端判断，控制布局分叉和弹窗全屏。

一个值得学习的细节在 `onChange` 里：开关切换先弹确认框，用户点取消时手动把 `row.status` 翻回去。乐观更新的回滚逻辑就两行，但很多真实项目都忘了写回滚。

## 新增一个 CRUD 页的七步

1. `mock/` 加接口（读接口，写操作先留注释位）。
2. `src/api/` 加请求函数。
3. `src/views/` 下建四件套目录。
4. hook 抄 `useDict` 的骨架，改状态字段和 columns。
5. form 改字段，记得暴露 `getRef()`。
6. rule 改校验规则。
7. `mock/asyncRoutes.js` 注册路由（第 04 篇），`meta.roles` 按需配（第 05 篇）。

第 13 篇会带着你把这七步完整走一遍。

## 新手常见误区

**把列定义写在 index.vue 里。** 列设置功能需要拿到响应式的 columns 引用，hook 里定义是前提。写在模板组件里，列设置面板不显示或改了不生效。

**表单组件不暴露 `getRef()`。** `beforeSure` 里拿到的是 undefined，校验直接报错。每个 form 的最后都要有 `defineExpose({ getRef })`。

**状态开关不做回滚。** 见上文 `onChange` 的示范，取消或失败必须把 row 翻回去，否则界面和数据从此对不上。

## 动手验证

1. 字典管理页点"新增字典详情"，填完提交，看到成功提示但列表里没有新数据。回到 hook 的 `beforeSure` 看注释"实际开发先调用新增接口"，确认这是演示级的写操作（第 09 篇讲过 mock 只实现了读）。
2. 点列设置图标，隐藏"备注"列，再拖拽调整两列顺序。刷新页面后列设置还原（PureTableBar 的列偏好在部分版本有持久化，以实际表现为准），理解哪些状态是临时的。
3. 把 `useDict` 里的 `dictId` 初始值改成 `100`，热更新后列表默认展示"通知类型"的字典详情，左树过滤逻辑被你劫持了。改回来。
