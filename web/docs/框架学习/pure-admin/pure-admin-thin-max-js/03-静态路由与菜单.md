# 03 · 静态路由与菜单

一句话定义：在 `src/router/modules/` 下新建一个 `.js` 文件并导出路由对象，菜单里就会自动多一项，不需要任何手工注册。

上一篇：[02 启动链路](./02-启动链路.md) ｜ 下一篇：[04 动态路由](./04-动态路由.md)

## 自动装配的原理

像超市货架，把货放上去就自动上架。往货架深处放、不贴排位标签的，就按上架顺序往后排。

装配逻辑在 `src/router/index.js` 顶部，三行核心代码：

```js
const modules = import.meta.glob(
  ["./modules/**/*.js", "!./modules/**/remaining.js"],
  { eager: true }
);
```

`import.meta.glob` 是 Vite 的能力，编译期扫描目录并收集所有匹配文件，`eager: true` 表示启动时同步全部加载。排除规则把 `remaining.js` 挡在外面，这个特殊文件后面单独讲。

收集到的路由会经过一条加工流水线，同样在 `src/router/index.js`：

```
routes.flat(Infinity)          拍平（允许一个文件导出多个路由）
  → ascending()                按 meta.rank 升序排，没写 rank 的按数组顺序补 index + 2
  → buildHierarchyTree()       给每个节点标好父子关系（来自 src/utils/tree.js）
  → formatFlatteningRoutes()   多级嵌套压成一维数组
  → formatTwoStageRoutes()     一维数组重新组装成二级：全部挂在 "/" 的 children 下
```

最后一步值得多说一句。所有业务路由都被强行压到二级，菜单可以显示多级，但真实路由结构最多两层。原因是 Vue 的 keep-alive（组件缓存）在多级嵌套下有已知缺陷，`src/router/utils.js` 里挂了官方 issue 链接。你写三级菜单完全没问题，运行时会被拍平。

## modules 目录现状

当前有三个文件，各自角色不同。

| 文件 | 内容 | rank | 参与菜单 |
| --- | --- | --- | --- |
| `home.js` | `/` 重定向到 `/welcome`，子路由 welcome | 0 | 是，`VITE_HIDE_HOME=true` 时隐藏 |
| `error.js` | `/error/403`、`/error/404`、`/error/500` | 9 | 是（可自行加 `showLink: false` 隐藏） |
| `remaining.js` | `/login`、`/access-denied`、`/server-error`、`/redirect/:path(.*)` | 无 | 否 |

`remaining.js` 是"编外人员"。它不参与菜单生成和登出重置，专门放那些不该出现在菜单里的页面：登录页、全屏异常页、`/redirect` 中转页（标签页"刷新"功能靠它实现）。它在 `src/router/index.js` 里单独用 `remainingRouter` 变量承接，和静态路由分开处理。

## meta 字段速查

meta 是路由的"简历"，菜单、权限、缓存全看它。这张表贯穿后面好几篇，建议收藏。

| 字段 | 类型 | 作用 | 消费方 |
| --- | --- | --- | --- |
| `title` | string | 菜单、标签页、浏览器标题 | 全局 |
| `icon` | string | 菜单图标（iconify 名称） | 菜单渲染 |
| `rank` | number | 菜单排序，越小越靠前，首页恒为 0 | `ascending()` |
| `showLink` | boolean | `false` 时不出现在菜单，路由仍可访问 | `filterTree()` |
| `roles` | string[] | 页面级权限角色，第 05 篇 | 守卫 + 菜单过滤 |
| `auths` | string[] | 路由下发的按钮权限码，第 05 篇 | `hasAuth()` |
| `keepAlive` | boolean | 是否缓存页面组件 | `handleAliveRoute()` |
| `frameSrc` | string | 内嵌 iframe 的地址 | `addAsyncRoutes()` |
| `fixedTag` | boolean | 固定标签页，不被关闭 | multiTags 初始化 |
| `dynamicLevel` | number | 同路径路由最多开几个标签 | `handleTags("push")` |
| `hiddenTag` | boolean | 不出现在标签页 | `handleTags("push")` |
| `saveSrollTop` | boolean | 路由切换时记住滚动位置 | `scrollBehavior` |

最后一个字段注意，源码里就拼作 `saveSrollTop`，少了一个 c。写 `saveScrollTop` 不会报错，但也不生效。搜不到效果的时候先检查拼写。

## 路由守卫在静态路由阶段做的事

`src/router/index.js` 的 `router.beforeEach` 是全项目流量的总闸，静态路由阶段它管四件事。

1. 进度条。`loadedPaths` 这个 Set 记录访问过的路径，第一次进某个页面才开 NProgress，重复访问不再显示进度条。
2. keep-alive 登记。`to.meta.keepAlive` 为真时调 `handleAliveRoute` 把组件名加进缓存列表。
3. 浏览器标题。从路由树里找到第一个有 `meta.title` 的节点，拼成 `页面名 | PureAdmin`。
4. 登录态判断。Cookie 里有 `multiple-tabs` 且 localStorage 里有 `user-info` 视为已登录；未登录访问任何页面都会被重定向到 `/login`，同时清掉残留凭证。

已登录时还有两道专项检查：`meta.roles` 不匹配跳 `/error/403`；`VITE_HIDE_HOME=true` 时手输 `/welcome` 跳 404。

## 新手常见误区

**以为静态路由的组件也是按路径字符串匹配的。** 静态路由的 `component` 是显式 `import()`，例如 `home.js` 里 `component: () => import("@/views/welcome/index.vue")`。路径字符串匹配是动态路由的玩法，下一篇讲。

**删掉 `remaining.js`。** 编译直接报错，因为 `src/router/index.js` 显式 import 了它。想隐藏登录页路由不如去看 sso 预留位。

**给 `remaining.js` 里的路由加 `rank`。** 没有意义，它不参与菜单排序逻辑。

## 动手验证

1. 在 `src/router/modules/` 下新建 `test.js`，内容抄 `home.js` 的结构，路由写成 `/test` 指向 welcome 组件，`meta` 里给 `title: "测试"`、`icon: "ep/star"`。保存后浏览器左侧菜单立刻多出"测试"项。没写 rank，它排在最后，这就是 `ascending()` 的默认补位。
2. 给它加上 `rank: 1`，菜单跳到首页后面第二位。
3. 加上 `meta: { showLink: false }`，菜单里消失，但地址栏直接输 `/test` 仍能访问。菜单可见和路由可达是两回事，第 05 篇权限会反复用到这一点。

实验完可以留着这个文件，下一篇我们用另一种方式（后端下发）再实现一遍同样的菜单。
