# 08 · 本地存储双轨制

一句话定义：界面偏好走 responsive-storage（带命名空间的 localStorage），大数据量的离线存储预留了 localforage（IndexedDB 优先），两套机制并存、各司其职。

## 先打个比方

便利贴和仓库。界面偏好这类小纸片（主题色、侧栏开合、标签页）用便利贴，随手贴、随手改、丢了也无妨。未来可能有的大块数据（离线缓存、草稿箱、附件）要进仓库（IndexedDB）。仓库目前建好了但还没人入住。

## 轨道一：responsive-storage

接入点在 `src/utils/responsive.js` 的 `injectResponsiveStorage`，也就是启动链路的第 6 步。它往 app 里装 responsive-storage 插件，同时预置三个键的默认值。默认值的优先级是：storage 里已有的 > `platform-config.json` 里的。所以用户改过的偏好会覆盖平台出厂设置。

三个键长这样（`ns` 即 `platform-config.json` 的 `ResponsiveStorageNameSpace`，当前为 `responsivemaxjs-`）：

| key | 内容 | 备注 |
| --- | --- | --- |
| `responsivemaxjs-layout` | `layout` `theme` `darkMode` `sidebarStatus` `epThemeColor` `themeColor` `themeMode` `menuStyle` | 布局与主题偏好 |
| `responsivemaxjs-configure` | `grey` `weak` `hideTabs` `hideFooter` `showLogo` `watermark` `watermarkText` `tagsStyle` `multiTagsCache` `stretch` | 界面显示开关 |
| `responsivemaxjs-tags` | 标签页数组 | 仅 `MultiTagsCache: true` 时存在 |

读取有两条路。底层读法是 `storageLocal().getItem("responsivemaxjs-layout")`（`storageLocal` 来自 @pureadmin/utils，是 localStorage 的安全封装）。全局读法是组件里 `useGlobal().$storage`，直接拿响应式对象，模板里用得最多。

写入方都是第 07 篇表格里的那几个 action：`toggleSideBar` 写 layout，`setEpThemeColor` 写 layout，`multiTagsCacheChange` 写 tags。永远通过 action 写，不要绕过。

命名空间是给多系统共存准备的。同一域名下部署两套 pure-admin 系统，靠不同的 `ResponsiveStorageNameSpace` 隔离各自的偏好，互不覆盖。

## 轨道二：localforage

`src/utils/localforage/index.js` 封装了一个 `StorageProxy` 类。要点四个：

- 驱动链 `[INDEXEDDB, LOCALSTORAGE]`：IndexedDB 可用就用它，不可用降级 localStorage。IndexedDB 是浏览器提供的数据库型存储，容量以 MB 计，远超 localStorage 的 5MB 上限。
- 存储结构：`setItem(k, v, m)` 把值包成 `{data: v, expires: 时间戳}`，参数 `m` 是过期分钟数，默认 0 表示永久。
- `getItem` 时校验 `expires`，过期返回 `null`，等效于自动清理。
- 实例名 `pure-admin`，全库一个实例，通过 `localForage()` 工厂函数获取。

一个值得知道的现状：**全项目业务代码目前没有一处调用它**。它是 max 版预留的基础设施。当你需要做离线缓存、本地草稿、大文件元数据缓存这类功能时，直接用，不用再引依赖。

## 本地存储全量地图

把前几篇出现过的所有键收拢到一张表，排查问题时按图索骥。

| key | 机制 | 写入方 | 内容 |
| --- | --- | --- | --- |
| `responsivemaxjs-layout` | responsive-storage | app/epTheme store | 布局主题偏好 |
| `responsivemaxjs-configure` | responsive-storage | 设置面板相关 action | 界面开关 |
| `responsivemaxjs-tags` | responsive-storage | multiTags store | 标签页（可选开启） |
| `authorized-token` | js-cookie | `setToken()` | accessToken、expires、refreshToken |
| `multiple-tabs` | js-cookie | `setToken()` | 登录态手环 |
| `user-info` | localStorage（storageLocal） | `setToken()` | 用户资料与角色权限 |
| `async-routes` | localStorage（storageLocal） | `initRouter()`（可选开启） | 动态路由缓存 |
| IndexedDB `pure-admin` | localforage | 目前无人 | 预留 |

注意最后一类和 `user-info`：它们走裸 localStorage，没有命名空间前缀。全库搜"我的数据存哪了"时别忘了这两个例外。

## 新手常见误区

**改了 `platform-config.json` 的默认值，界面没变。** 本地 storage 里已经存了旧偏好，优先级更高。删掉对应的 `responsivemaxjs-*` 键再刷新，就能看到新默认值。给客户演示"改配置"之前记得先清浏览器存储。

**把 localforage 当同步 API 用。** 它全部返回 Promise。`const v = localForage().getItem("k")` 拿到的是 Promise 不是值，必须 `await`。

**把 token 之类的敏感数据塞进 localforage。** 轨道各有分工，凭证属于轨道一的既定方案（`authorized-token` Cookie）。往 IndexedDB 里放敏感数据等于把敏感信息多存了一份，清理路径也变复杂。

## 动手验证

1. Application 面板依次找到 `responsivemaxjs-layout`、`user-info`、Cookie 里的 `authorized-token`，对照全量地图确认每一项。这个动作以后排查"状态诡异"时天天用。
2. 在设置面板切换一次布局模式（比如 double 换 vertical），观察 `responsivemaxjs-layout` 里 `layout` 字段实时变化。
3. 在任意组件的 setup 里跑一段：

```js
import { localForage } from "@/utils/localforage";
localForage().setItem("my-test", { hello: "world" }, 1); // 1 分钟过期
const v = await localForage().getItem("my-test");        // { hello: "world" }
```

Application 面板的 IndexedDB 里出现 `pure-admin` 库。等一分钟再 `getItem`，拿到 `null`，过期机制生效。
