# 06 · 登录态与请求层

一句话定义：登录态由"两个 Cookie 加一份 localStorage"表达，token 过期后由请求层自动换新票，页面上的用户全程无感。

上一篇：[05 权限体系](./05-权限体系.md) ｜ 下一篇：[07 状态管理](./07-状态管理.md)

## 先打个比方

去景区玩。accessToken 是当日的门票，两小时有效；refreshToken 是年卡，凭它能补办新门票；Cookie 里的 `multiple-tabs` 是检票口给你套的手环，证明"你今天进过园"，摘了（浏览器关闭）就得重新检票。

## 登录流程

入口在 `src/views/login/index.vue` 的 `onLogin`，四步：

1. el-form 校验通过后调 `useUserStoreHook().loginByUsername()`，实际请求 `/login`。
2. 成功后 `setToken(data.data)` 落库，下一节细讲。
3. `await initRouter()` 拉动态路由（第 04 篇的五步流水线）。
4. `getTopMenu(true)` 取过滤后的第一个菜单并 push 过去，`tag=true` 参数会顺手把它压进标签页。

体验细节有两个值得注意：回车键登录走了 `debounce(fn, 1000, true)` 的立即防抖，连按不会重复提交；登录表单里的租户输入框由 `.env` 的 `VITE_ENABLE_TENANT === "true"` 控制显示，但当前登录请求只发 `username` 和 `password`，`tenant` 字段没有传出去。接真实后端如果需要租户标识，记得在 `onLogin` 里补上，这是预留的坑位。

## 凭证存在哪

全部在 `src/utils/auth.js`，三个 key 三个位置，职责分明：

| key | 位置 | 内容 | 什么时候消失 |
| --- | --- | --- | --- |
| `authorized-token` | Cookie | `{accessToken, expires, refreshToken}`，Cookie 有效期对齐 `expires` | 过期自动销毁，或登出时移除 |
| `multiple-tabs` | Cookie | 字符串 `"true"`；勾选免登录时有效期 `loginDay`（默认 7 天），否则会话级 | 浏览器完全关闭自动销毁 |
| `user-info` | localStorage | `refreshToken, expires, avatar, username, nickname, roles, permissions` | 登出时 `removeToken` 移除 |

设计意图在 `setToken` 的注释里写得很直白。token 三件套进 Cookie 且随 expires 过期，保证过期后拿不到旧 token；`multiple-tabs` 支撑"多标签页共享登录态"和"关浏览器就要重登"的产品行为；用户资料进 localStorage 是为了刷新页面时 Pinia store 能快速水合（`src/store/modules/user.js` 的 state 初始值直接从 `user-info` 读）。

`getToken()` 做了一层兼容：优先读 Cookie，读不到再回退 localStorage。处理的是"Cookie 已过期但 localStorage 还在"的初始化边界。

## 请求层 PureHttp

`src/utils/http/index.js` 用 class 封装 axios，对外暴露 `http.request/get/post`。默认配置：超时 10 秒，JSON 头，数组参数用 qs 的 `stringify` 序列化（绕开 axios 的方括号格式争议）。

请求拦截器是全篇核心，逻辑分四支：

1. URL 以 `/refresh-token` 或 `/login` 结尾的白名单请求，直接放行，不挂 token。白名单防止"token 过期 → 去刷新 → 刷新接口又要 token → 死循环"。
2. 没有 token，直接放行（登录页的初次探测类请求）。
3. 有 token 且未过期，请求头挂上 `Authorization: Bearer xxx`。
4. token 已过期，进入无感刷新流程。

无感刷新三件套，配合注释读源码更清楚：

- `isRefreshing` 静态标志，保证同一时刻只有一个刷新请求在飞。
- `requests` 静态队列，存放"等新 token"的请求回调。第一个发现过期的请求触发刷新，其余过期请求全部进队列排队。
- 刷新成功，新 token 发给当前请求和队列里所有回调；失败则清空队列、`logOut()`、弹"登录已过期，请重新登录"。

响应拦截器只做一件事，返回 `response.data`。所以业务代码里拿到的直接是 `{code, message, data}`，不用再 `.data.data`。错误统一 reject，并附加 `isCancelRequest` 标记区分主动取消。

## 退出登录

`src/store/modules/user.js` 的 `logOut()` 是纯前端登出：清 store 字段、`removeToken()` 清三个 key、标签页重置、`resetRouter()` 清动态路由、跳 `/login`。没有登出接口调用，需要后端吊销 token 的项目要自己补一行。

## 新手常见误区

**expires 格式。** mock 返回 `"2030/10/30 00:00:00"` 这种日期字符串，`setToken` 里会转时间戳。mock/refreshToken.js 的注释特意提醒：后端若直接给时间戳，把 `src/utils/auth.js` 里 `setToken` 的 `expires = new Date(data.expires).getTime()` 改成 `expires = data.expires`。对接真实后端时这是必查项。

**绕过封装裸用 axios。** 项目里新写请求必须走 `@/utils/http`。自己 `axios.create` 的新实例没有这套拦截器，token 不会挂、过期不会刷，线上表现为"隔两小时莫名掉登录"。

**以为刷新 token 有弹窗提示。** 设计目标就是无感。想观察它，得看 Network 面板里 `/refresh-token` 的调用，或者故意把 expires 改到过去。

## 动手验证

1. 登录后打开 Application 面板，Cookies 里找 `authorized-token` 和 `multiple-tabs`，LocalStorage 里找 `user-info`，对照上表逐字段确认。取消勾选记住我（当前登录页未展示该选项，`isRemembered` 默认 false），`multiple-tabs` 是会话 Cookie，关掉浏览器再开就要重新登录。
2. 把 `mock/login.js` 里 admin 的 `expires` 改成 `"2020/01/01 00:00:00"`，重启 dev server 后重新登录。登录成功，然后随便点一个会发请求的页面（比如进入字典管理），Network 面板里先出现 `/refresh-token`，紧接着原请求重发，页面正常出数据。这就是无感刷新的现场。验证完把时间改回去。
3. 在 Network 里找任意业务请求，看请求头 `Authorization` 的 `Bearer` 前缀，对应 `formatToken()`。
