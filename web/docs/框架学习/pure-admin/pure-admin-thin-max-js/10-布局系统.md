# 10 · 布局系统

一句话定义：layout 是一个"换壳容器"，四种布局壳共用同一套内部零件，壳的选择、主题、各种开关全部由配置和偏好驱动。

上一篇：[09 Mock 接口层](./09-Mock接口层.md) ｜ 下一篇：[11 业务页面开发范式](./11-业务页面开发范式.md)

## 先打个比方

手机桌面。壁纸和图标颜色是主题，桌面布局方式（列表还是分页）是布局模式，通知栏、搜索框、小组件是可开关的零件。`src/layout/` 就是这台手机的桌面系统。

## 骨架总览

`src/layout/index.vue` 是唯一入口，模板结构翻译成文字：

```
app-wrapper
├─ NavVertical      # 布局含 vertical 或 mix 时显示的经典左侧栏
├─ NavDouble        # 布局为 double 时显示的双侧栏（max 版特色）
├─ main-container
│  ├─ LayHeader     # = LayNavbar（顶栏） + NavHorizontal（horizontal 布局的顶菜单） + LayTag（标签栏）
│  └─ LayContent    # 页面主体，keep-alive 在这里面
└─ LaySetting       # 右侧设置面板（齿轮按钮唤出）
```

`LayHeader` 是个渲染函数组件，逻辑是按布局模式决定装什么：`/vertical|mix|double/` 能匹配到就渲染顶栏 navbar，`horizontal` 用 NavHorizontal 承载菜单，标签栏 `LayTag` 永远在。`FixedHeader` 配置为 `true` 时头部固定、内容区独立滚动；为 `false` 时整页滚动，并启用回到顶部按钮。

## 四种布局模式

| 模式 | 长相 | 渲染组件 |
| --- | --- | --- |
| `vertical` | 经典左侧栏 | NavVertical |
| `horizontal` | 菜单全在顶部 | NavHorizontal |
| `mix` | 顶部一级菜单 + 侧边二级菜单 | NavVertical + NavHorizontal 组合 |
| `double` | 双侧栏，max 版新增 | NavDouble |

默认值来自 `platform-config.json` 的 `Layout: "double"`。切换入口在右侧设置面板，切换时 `src/layout/index.vue` 的 `setTheme` 做两件事：给 `body` 设置 `layout` 属性（大量 CSS 靠它做样式分支），把新值写进 `responsivemaxjs-layout`。

## 响应式三档

`src/layout/index.vue` 里有一段 `useResizeObserver` 监听容器宽度，分三档自动调整：

- 宽度大于 990：侧边栏展开。但如果用户是手动点折叠的（`isClickCollapse` 为 true），不强制展开，尊重用户选择。
- 760 到 990：自动折叠一次（`isAutoCloseSidebar` 保证只在"从窄变宽再变窄"的循环里折一次，不来回抖动）。
- 小于等于 760：进入 mobile 模式，侧栏变抽屉，展开时加半透明遮罩，点遮罩关闭。

这套阈值是纯 UI 逻辑，但它演示了一个好的习惯：自动化行为要给用户手动操作让路。

## 零件清单

`src/layout/components/` 下的 `lay-*` 目录，各自职责：

| 零件 | 职责 | 关联配置 |
| --- | --- | --- |
| `lay-navbar` | 顶栏：折叠按钮、菜单搜索入口、全屏、通知铃铛、用户下拉 | FixedHeader |
| `lay-tag` | 多标签页栏，chrome 卡片风格，右键菜单（关闭/固定/刷新等） | TagsStyle、HideTabs |
| `lay-search` | 菜单搜索弹窗，支持拼音匹配（pinyin-pro），历史记录可拖拽排序 | MenuSearchHistory（保留 6 条） |
| `lay-notice` | 通知铃铛的消息列表 | 静态数据在 `data.js` |
| `lay-setting` | 右侧配置面板：布局、主题色、暗黑、灰度、色弱、水印、页宽 | 对应 configure 键 |
| `lay-frame` | iframe 容器 | 路由 `meta.frameSrc` |
| `lay-panel` / `lay-footer` | 通用面板与页脚 | HideFooter |

页面缓存在 `lay-content` 里实现，但名单管理在别处：permission store 的 `cachePageList`，由路由守卫的 `handleAliveRoute` 维护，配置总开关是 `platform-config.json` 的 `KeepAlive`。回忆第 03 篇，路由 `meta.keepAlive: true` 才会进缓存名单。

## 主题体系

`src/layout/hooks/useDataThemeChange.js` 是主题中枢，三个维度：

- `themeMode`：light / dark / system（跟随系统），底层是 VueUse 的 useDark。
- `themeColor`：预设色板（`#409EFF` 蓝、auroraGreen 绿等），写进 CSS 变量。
- `menuStyle`：菜单风格（`popular` 等），max 版的"菜单风格高级功能"，同样落在 CSS 变量上。

登录页右上角那个日/夜切换开关走的也是同一套 hook，所以未登录状态下主题就已经可用了。

## 新手常见误区

**想改布局直接去改 layout/index.vue 的模板。** 布局是配置驱动的，先确认 `platform-config.json` 和设置面板能不能满足，九成需求不用动骨架。改模板之前先想想 `body[layout]` 属性加 CSS 是不是更轻。

**加了 `meta.keepAlive` 但页面不缓存。** 三件事要同时对：路由 `meta.keepAlive: true`、页面组件 `defineOptions({ name })` 与路由 `name` 一致、`platform-config.json` 的 `KeepAlive` 为 true。任何一件缺失都不缓存。页面 name 与路由 name 的一致性是最高频的翻车点。

**找不到水印、灰度这些功能在哪实现的。** 都在 `lay-setting` 与主题 hook 里，且状态存于 `responsivemaxjs-configure`。改配置面板前先读 `configure` 的字段表（第 08 篇）。

## 动手验证

1. 设置面板依次切四种布局，每切一次在 Elements 面板看 `body` 的 `layout` 属性值，同时观察 `responsivemaxjs-layout.layout`。配置驱动的证据链就齐了。
2. 拖拽浏览器窗口宽度跨过 990 和 760 两个阈值，观察侧栏的展开、折叠、抽屉三态切换。
3. 把 `platform-config.json` 的 `Layout` 改成 `"vertical"`，清掉 `responsivemaxjs-layout` 后刷新，默认布局变了。再把 storage 键恢复，偏好又赢回来，第 08 篇的优先级规则再次得到验证。
