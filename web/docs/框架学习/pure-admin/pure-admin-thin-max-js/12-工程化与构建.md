# 12 · 工程化与构建

一句话定义：`vite.config.js` 只做组装，真正的开关都拆在 `build/` 目录和 `.env*` 文件里，改任何构建行为前先去那两处找。

## build 目录六件套

| 文件 | 职责 | 什么时候需要碰 |
| --- | --- | --- |
| `build/utils.js` | 路径别名、环境变量类型转换、构建信息注入 | 加环境变量默认值、改别名时 |
| `build/plugins.js` | Vite 插件清单 | 增删插件 |
| `build/optimize.js` | 依赖预构建的 include / exclude | 开发环境切页卡顿时 |
| `build/cdn.js` | `VITE_CDN=true` 时用 CDN 替换本地库 | 部署带宽敏感时 |
| `build/compress.js` | `VITE_COMPRESSION` 控制 gzip / brotli 压缩 | 配置部署产物时 |
| `build/info.js` | `viteBuildInfo`，启动时打印构建信息横幅 | 基本不用碰 |

`utils.js` 里两个常客。别名配置：`@` 指向 `src`，`@build` 指向 `build`，写 import 时用。`wrapperEnv` 负责把环境变量从字符串转成正确类型并兜底（`VITE_PORT` 缺省 8848、`VITE_CDN` 缺省 false 等），所以 `.env` 里写 `"true"` 到了代码里是真布尔值。

`optimize.js` 的文件头注释值得完整读一遍。预构建（optimizeDeps.include）把列出的依赖提前编译成 ESM 缓存到 `node_modules/.vite`。它的典型使用场景是"调试时禁用了浏览器缓存，切页面就卡"，因为 Vite 会把没缓存的依赖当成新依赖强制刷新页面。装了新的常用依赖后开发体验变卡，加进 include。

## 插件清单

`build/plugins.js` 里的插件，按用途分组：

| 插件 | 作用 | 备注 |
| --- | --- | --- |
| `@tailwindcss/vite` | Tailwind 4 接入 | 无 tailwind.config.js |
| `@vitejs/plugin-vue` + `vueJsx` | SFC 与 JSX 支持 | hook.jsx 的 JSX 靠后者 |
| `code-inspector-plugin` | 按住 Alt+Shift 点击页面元素直达源码 | 开发效率利器 |
| `vite-plugin-router-warn` | 消除动态路由的 No match 警告 | 仅开发环境 |
| `vite-plugin-fake-server` | mock 服务 | `enableProd: true`，第 09 篇 |
| `vite-svg-loader` | svg 以 `?component` 方式作为组件导入 | `import X from "./a.svg?component"` |
| `unplugin-icons` | `~icons/ep/delete` 按需引入图标 | 页面里大量 `import Delete from "~icons/..."` |
| `vite-plugin-remove-console` | 生产构建移除 console | 保留 iconfont 的例外 |
| `rollup-plugin-visualizer` | 打包体积分析 | 仅 `pnpm report` 时启用 |
| `configCompressPlugin` / cdn | 压缩与 CDN 替换 | 由环境变量开关控制 |

## 环境变量总表

| 变量 | 所在文件 | 当前值 | 影响 |
| --- | --- | --- | --- |
| `VITE_PORT` | `.env` | 8848 | dev server 端口 |
| `VITE_HIDE_HOME` | `.env` | false | true 时首页不进菜单、`/welcome` 直达 404 |
| `VITE_ENABLE_TENANT` | `.env` | true | 登录页租户输入框显隐 |
| `VITE_PUBLIC_PATH` | 各环境 | `/` | 部署子路径时改 |
| `VITE_ROUTER_HISTORY` | 各环境 | `"hash"` | `"h5"` 切 history 模式，支持 `",base"` 带基路径 |
| `VITE_CDN` | `.env.production` false / `.env.staging` true | 见左 | 构建时用 CDN 替换本地依赖 |
| `VITE_COMPRESSION` | `.env.production` | `"none"` | `gzip` / `brotli` / `both` 及 `-clear` 变体 |

注意路由历史模式是 hash。部署到 nginx 时 hash 模式不需要服务端兜底配置，切 `h5` 就要配 try_files，这是部署文档里最常见的坑。

## 命令速查

| 命令 | 干什么 |
| --- | --- |
| `pnpm dev` | 启动开发服务器，Node 堆内存给到 4G |
| `pnpm build` | 清 dist 后生产构建，堆内存 8G |
| `pnpm build:staging` | 预发布构建（CDN 开启） |
| `pnpm report` | 构建并生成 `report.html` 体积分析 |
| `pnpm preview` / `preview:build` | 预览构建产物 |
| `pnpm lint` | eslint + prettier + stylelint 三连 |
| `pnpm clean:cache` | 清缓存重装依赖，救急用 |

一个 Windows 用户专属的事实：`dev` 脚本写的是 `NODE_OPTIONS=--max-old-space-size=4096 vite`，这是 Unix 风格的环境变量赋值，cmd 或 PowerShell 原生不认。它能跑，是因为 `pnpm-workspace.yaml` 里开了 `shellEmulator: true`，pnpm 内置了 shell 模拟器。哪天报"NODE_OPTIONS 不是内部或外部命令"，先检查这个开关。

## 规范链

提交和检查是一条自动化链条：

```
git commit → husky 钩子 → lint-staged（.lintstagedrc）只对暂存文件跑 lint --fix
           → commitlint（conventional 规范）校验提交信息
```

提交信息必须是 `feat: xxx` / `fix: xxx` / `chore: xxx` / `docs: xxx` 这类格式，类型用英文冒号加空格。看 git log 全是 `chore: 同步最新代码`，就是这个规范的样子。eslint 用 flat config（`eslint.config.js`），`--max-warnings 0` 意味着连警告都过不了，prettier 和 eslint 有冲突时以 prettier 插件仲裁。stylelint 按 recess-order 排属性序。

一个对本文读者的好消息：`pnpm lint` 系列脚本只扫 `src`、`mock`、`build` 和 `src` 下的 md，`docs/` 目录不在检查范围内，本系列文档的格式不受 lint 约束。

## 新手常见误区

**在 vite.config.js 里找 rollupOptions。** Vite 8 用 Rolldown，键名是 `rolldownOptions`，构建输出规则（`static/js/[name]-[hash].js` 这类）都写在那里。

**新装依赖后开发环境切页卡顿。** 回看 `optimize.js` 头注释，把依赖加进 include，或确认是否被错误地放进了 exclude（当前 exclude 只有 `@iconify/json`，它体积巨大，按需加载才是对的）。

**改了 `.env` 里的 `VITE_HIDE_HOME` 后只在浏览器里刷新。** 环境变量要重启 dev server。顺带回顾第 03 篇，这个开关同时在菜单 showLink、守卫重定向、初始标签页三处生效，改完三处都要验一遍。

## 动手验证

1. `pnpm report`，浏览器自动打开 `report.html`，找到体积最大的几个 chunk。生产构建前过一遍是保留习惯。
2. `pnpm lint`，全绿通过。然后随便在某个文件里把一处缩进改乱或把单引号换成双引号，再跑一次，`prettier/prettier` 规则会以 error 拦下。顺带说一个反直觉的事实：eslint 并没有开 `no-console`，源码里就有裸的 console.log，生产环境的 console 清理靠的是构建期的 `vite-plugin-remove-console`，两道闸互不相干。
3. 随便提交一次不规范的 commit 信息（比如 `更新`），commitlint 会拒绝。这就是链条在工作，提交前手写规范格式：类型（feat/fix/chore/docs 等）加英文冒号加空格再加描述。
