# 04 · 动态路由

一句话定义：菜单长什么样由后端返回的 JSON 决定，前端维护一个"页面池"，靠路径字符串把菜单和页面组件对上号。

上一篇：[03 静态路由与菜单](./03-静态路由与菜单.md) ｜ 下一篇：[05 权限体系](./05-权限体系.md)

## 先打个比方

后端给的是点菜单，上面只有菜名和编号。前端厨房有一整架菜谱（`import.meta.glob` 收集的 `src/views` 下所有组件），来单后按名字找菜谱、按菜谱炒菜。菜单可以天天换，厨房不用动。

这是后台管理系统最主流的权限方案：菜单存在数据库里，不同角色看到不同菜单，前端不需要为每个角色写死路由。

## 数据从哪来

接口定义在 `src/api/routes.js`，只有一个函数，请求 `/get-async-routes`。当前由 `mock/asyncRoutes.js` 提供，返回四个路由：权限管理（rank 10）、日历排班（11）、字典管理（12）、租户管理（13）。

返回结构和静态路由对象同构，但有一个关键差别，`component` 是字符串：

```js
{
  path: "/permission/button",
  children: [
    {
      path: "/permission/button/router",
      component: "permission/button/index",   // 字符串，不是 import
      name: "PermissionButtonRouter",
      meta: { title: "路由返回按钮权限", auths: [...] }
    }
  ]
}
```

甚至可以不传 `component`，这时前端拿 `path` 去页面池里匹配。所以后端返回的 `path` 不能乱写，它必须能命中 `src/views` 下真实存在的文件路径。

## 五步加工流水线

全部逻辑在 `src/router/utils.js`，入口是 `initRouter()`。

**第一步，取数据（可缓存）。** `platform-config.json` 的 `CachingAsyncRoutes` 当前为 `false`，每次刷新都重新请求。设为 `true` 后路由列表会存进 localStorage 的 `async-routes` 键，刷新不再发请求。代价是改了菜单要手动清这个键才生效。

**第二步，规范化（`addAsyncRoutes`）。** 给每个节点做四件事，全是兜底：

- `meta.backstage = true`，打上"我是后端来的"标记，后面多处判断用它。
- 父级没有 `redirect` 就默认指向第一个子级的 `path`。
- 父级没有 `name` 就取第一个子级的 `name` 加后缀 `Parent`。必须错开，父子同名会导致重定向跳 404。
- 处理组件。`meta.frameSrc` 存在则绑定内置的 IFrame 组件（内嵌网页）；否则把 `component` 字符串（或 `path`）与页面池的 key 做 `includes` 匹配，找到对应的动态 `import()`。

**第三步，注册进 router（`handleAsyncRoutes`）。** 逐条判断防重复后 `router.addRoute()`。这里有个容易看漏的细节：代码同时把路由 push 进 `router.options.routes[0].children`，再把两者强制同步。`options.routes` 是菜单和标签页取数据的来源，和 router 内部注册表不一致会出诡异 bug，所以源码特意做了双向对齐。

**第四步，生成菜单（`handleWholeMenus`）。** 静态菜单 + 动态路由合并后过三道过滤：`filterNoPermissionTree` 按当前用户 roles 剔除无权限项，`filterTree` 剔除 `showLink: false`，`filterChildrenTree` 剔除空目录。结果存进 permission store 的 `wholeMenus`，侧边栏读它渲染。

**第五步，补 404 兜底（`addPathMatch`）。** 全匹配路由 `/:pathMatch(.*)*` 放在动态路由注册完之后才添加。顺序反了的话，刷新动态页面时路由还没注册完，就会先被兜底路由截住跳 404。

## 刷新页面为什么不会丢

F5 之后内存里的动态路由全部蒸发，Vue 应用重新启动。恢复流程藏在路由守卫里（`src/router/index.js` 的 `beforeEach`）：守卫发现用户已登录但 `wholeMenus` 是空的，判定为"刷新场景"，重新执行 `initRouter()`，拿到路由后 `router.push(to.fullPath)` 再走一遍。源码注释明确提醒，这个恢复过程会让 `beforeEach` 触发两次，第一次路由还没加全，第二次才加全，所以守卫里自己的业务判断要放在 `to.name` 存在的条件下，保证只执行一次。

## 退出登录时发生什么

`src/store/modules/user.js` 的 `logOut()` 是纯前端登出，不调后端接口：清凭证（第 06 篇），标签页重置为初始的 `routerArrays`，然后 `resetRouter()`。`resetRouter` 在 `src/router/index.js`，做四件事：`clearRoutes()` 清空路由表，重新加入静态路由和 remaining，清空 keep-alive 缓存列表，清空已加载路径记录。动态路由由此全部退场，等下次登录重新拉。

## 新手常见误区

**后端返回的 path 随手起名。** 不传 `component` 时，`path` 就是找组件的唯一线索。`/knowledge/list` 必须对应 `src/views/knowledge/list` 下存在的 `.vue` 或 `.jsx` 文件，匹配方式是字符串 `includes`，写错一个字符匹配到的可能是别的文件或者匹配不到。

**改了 mock 的路由没反应。** mock 是 node 侧代码，先重启 dev server。重启后还不对，检查 `CachingAsyncRoutes` 是否开着，开了的话 localStorage 里的 `async-routes` 会一直挡在新数据前面，删掉这个键再刷新。

**在动态路由上找不到自定义 `meta` 字段。** 检查是不是被第二步的兜底逻辑覆盖。`backstage`、`redirect`、`name` 这三个字段后端不传的话前端会补，后端传了以后端为准。

## 动手验证

1. 打开 `mock/asyncRoutes.js`，仿照 `dictManagementRouter` 加一个：

```js
const aboutRouter = {
  path: "/about",
  meta: { icon: "ri:information-line", title: "关于", rank: 14 },
  children: [
    {
      path: "/about/index",
      name: "About",
      meta: { title: "关于", roles: ["admin", "common"] }
    }
  ]
};
```

把它加进 `defineFakeRoute` 的 `data` 数组，重启 dev server（mock 是 node 侧代码），`admin` 和 `common` 登录都能看到"关于"菜单，页面内容是 welcome 组件，因为 `/about/index` 不存在于页面池，`includes` 匹配会命中 `/welcome`？不会，匹配不到时 component 为 undefined，页面空白。这个"空白"本身就是教学点：动态路由的页面必须真实存在于 `src/views`。把 path 改成 `/welcome` 试一次，再改回来。

2. 把 `public/platform-config.json` 的 `CachingAsyncRoutes` 改成 `true`，刷新后 Network 面板里 `/get-async-routes` 消失了，Application 面板 localStorage 多出 `async-routes` 键。改一下 mock 里的菜单标题，刷新发现没变，删掉 `async-routes` 键后变化出现。
