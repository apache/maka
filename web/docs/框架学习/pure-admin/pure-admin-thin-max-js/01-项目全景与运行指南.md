# 01 · 项目全景与运行指南

一句话定义：pure-admin-thin-max-js 是一套后台管理系统的骨架。权限、路由、布局、请求、存储这些地基全部造好，业务页面只留了 6 个示例模块，所有数据来自本地 mock。

上一篇：[导读](./README.md) ｜ 下一篇：[02 启动链路](./02-启动链路.md)

## 你拿到的到底是什么

先把业务盘点清楚，避免在找不到"功能"上浪费时间。`src/views/` 下只有这些：

| 模块 | 路径 | 功能 | 可见角色 |
| --- | --- | --- | --- |
| 首页 | `src/views/welcome` | 一个静态欢迎页 | 所有角色 |
| 登录 | `src/views/login` | 账号密码登录，可选租户输入框 | 未登录 |
| 权限管理 | `src/views/permission` | 页面权限、按钮权限的演示页 | admin、common |
| 日历排班 | `src/views/schedule` | 基于 el-calendar 的排班日历 | admin |
| 字典管理 | `src/views/dict` | 左树右表的字典维护 | admin |
| 租户管理 | `src/views/tenant` | 租户列表、租户套餐 | admin |
| 异常页 | `src/views/error` | 403、404、500 | 按需 |

把这些页面增删改的接口扒开看，你会发现 mock 里只实现了查询。点"删除"只会弹一条成功提示，数据不会真的变。这符合预期，后面第 11 篇会讲怎么补全。

打个比方，这个项目是精装修样板间。水电、门窗、厨卫（路由、权限、请求、存储、布局）都是真的能用，摆在家里的家具（页面数据）是道具。你要做的是把道具换成自己的家具。

## 技术栈

选型比较新，查资料时注意版本。

| 选型 | 版本 | 在项目里的角色 |
| --- | --- | --- |
| Vue | 3.5 | UI 框架，全项目 `<script setup>` 写法 |
| vue-router | 5.2 | 路由，动态路由是核心玩法 |
| Pinia | 4.0 | 状态管理，6 个 store |
| Element Plus | 2.14 | UI 组件库，全量引入 |
| Tailwind CSS | 4.3 | 原子化样式，模板里大量 `flex`、`w-40!` 这类类名 |
| Vite | 8.1 | 构建，内置 Rolldown 打包器 |
| axios | 1.18 | 请求层，二次封装成 PureHttp |

两个容易踩坑的版本细节。第一，Vite 8 用 Rolldown 替代了 Rollup，所以 `vite.config.js` 里写的是 `rolldownOptions`，网上搜旧教程看到 `rollupOptions` 会以为配置丢了。第二，Tailwind 4 用 `@tailwindcss/vite` 插件接入，没有 `tailwind.config.js`，样式配置在 `src/style/tailwind.css` 里用 CSS 变量声明。

## 目录地图

```
├─ build/                 # vite 配置的拆分件（插件、压缩、CDN、环境变量转换）
├─ mock/                  # 假后端，4 个文件对应 10 个接口
├─ public/
│  └─ platform-config.json # 运行时平台配置（标题、布局、主题、存储命名空间）
├─ src/
│  ├─ api/                # 接口定义，3 个文件，全部只有 URL 没有业务逻辑
│  ├─ assets/             # 图标、登录背景、异常页插画
│  ├─ components/         # 平台级组件，全部 Re 开头（ReDialog、RePureTableBar…）
│  ├─ config/             # getConfig()，读 platform-config.json 的工具
│  ├─ directives/         # 6 个自定义指令（auth、perms、copy、longpress、optimize、ripple）
│  ├─ layout/             # 布局壳：导航、标签页、搜索、通知、设置面板
│  ├─ plugins/            # element-plus 与 echarts 的注册（echarts 目前注释掉）
│  ├─ router/             # 静态路由 + 动态路由加工厂，全项目最核心的目录
│  ├─ store/              # 6 个 Pinia store
│  ├─ style/              # 重置样式、公共样式、tailwind 入口
│  ├─ utils/              # http 封装、auth、存储、事件总线、树处理等工具
│  └─ views/              # 业务页面，上面表格里的 6 个模块
├─ .env / .env.development / .env.production / .env.staging
└─ vite.config.js         # 只做组装，细节都在 build/ 目录
```

## 跑起来

```bash
pnpm install    # preinstall 钩子校验包管理器，npm/yarn 会被 only-allow 拦下
pnpm dev        # 端口 8848，host 0.0.0.0（局域网可访问）
```

预期结果：终端出现构建信息横幅，浏览器访问 `http://localhost:8848` 看到登录页。登录后看到"首页"标签页和左侧菜单。

两个账号的区别值得当场对比一次：

- `admin / admin123`：角色 `admin`，按钮权限 `*:*:*`（通配全部），菜单全量。
- `common / admin123`：角色 `common`，按钮权限只有新增和编辑，菜单只剩首页和权限管理。

密码随便填都能过，因为 `mock/login.js` 只看用户名。真接后端后这条自然就变了。

## 同族仓库

项目所在的父目录下还有几个同门，对照着看对理解很有帮助。

| 仓库 | 关系 |
| --- | --- |
| `pure-admin-thin-js` | 免费开源的精简版，没有租户、排班、字典这些增强模块 |
| `pure-admin-thin-max-ts` | 本仓库的 TypeScript 版，逻辑同构，类型定义可当文档读 |
| `vue-pure-admin-max` | 完整版，业务示例最全，找"某个功能官方怎么做"的参考 |
| `pure-admin-utils` | 同作者的配套工具库仓库 |

本系列只讲当前仓库。需要交叉对照时我会明确指出去哪个仓库看什么。

## 新手常见误区

**thin 等于简陋。** thin 指精简掉了业务示例，max 指保留了付费增强能力（租户、日历排班、菜单风格等）。骨架本身的完成度高于免费版。

**数据是假的，所以随时能上线。** 恰恰相反。`build/plugins.js` 里 mock 服务配置了 `enableProd: true`，生产构建的包里跑的还是假数据。上线前必须按第 09 篇的步骤处理，这是这个项目最容易被忽略的一颗雷。

**文档少所以没法维护。** 官方文档站 pure-admin.cn 覆盖通用问题，本系列覆盖这个仓库的 specifics（具体实现）。源码本身注释密度很高，中文注释，读起来不费劲。

## 动手验证

1. `pnpm dev` 启动后，分别用 `admin` 和 `common` 登录，截图对比两次菜单数量。这个差异在第 05 篇会逐行解释。
2. 打开浏览器开发者工具的 Network 面板，刷新页面，找到对 `platform-config.json` 的请求。它能证明配置是运行时加载的，第 02 篇展开。
3. 在 Network 面板看 `/get-async-routes` 的响应体，这就是动态路由的原始数据，第 04 篇的主角。
