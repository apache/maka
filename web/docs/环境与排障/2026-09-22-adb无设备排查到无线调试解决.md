# HONOR 100 Pro 上 adb "no devices/emulators found"：从环境变量排查到无线调试落地

## 一句话结论

`no devices/emulators found` 与环境变量无关（adb 能运行就证明 Path 已生效）；真正根因是荣耀新机型（VID_339B）走微软 WinUSB 免驱绑定，而 Windows 版 adb 的经典枚举后端只认 Google USB 驱动注册的接口 GUID，USB 通道永远扫不到这台手机。绕开方案：改走无线调试（`adb pair` + `adb connect`），全程不装驱动，最终 `adb install` Success。

## 现场环境

| 项 | 值 |
| --- | --- |
| 电脑 | Windows 10 22H2 (19045.6456)，主机 HeT-HLW0609，有线网 10.6.33.85 |
| platform-tools | 37.0.0-14901028，位于 `D:\DevTools\Languages\Android\platform-tools` |
| 手机 | HONOR 100 Pro（型号 MAA-AN10），USB VID_339B，Wi-Fi 网段 10.6.x.x，带 VPN |
| 待装包 | `C:\Users\802165\Downloads\jev-assistant-v1.3-release.apk` |

## 症状

```
C:\Users\802165\Downloads> adb install -r jev-assistant-v1.3-release.apk
adb.exe: no devices/emulators found

C:\Users\802165\Downloads> adb devices -l
List of devices attached
（空）
```

手机用 USB 线连着电脑，adb 命令本身能执行，但设备列表始终为空。

## 排查过程与证据

按嫌疑度逐层排除，每步都有可复现的命令和实测结果。

| # | 步骤 | 命令 / 位置 | 实测结果 | 结论 |
| --- | --- | --- | --- | --- |
| 1 | 查环境变量 | `where adb` | 解析到 `D:\DevTools\Languages\Android\platform-tools\adb.exe`，与用户变量 `ADB_HOME` 一致 | **排除**。报错是 "no devices" 而不是"不是内部或外部命令"，说明 Path 已生效。另：adb 官方不读 `ADB_HOME` 这个变量，它只是摆设 |
| 2 | 查设备树 | PowerShell `Get-PnpDevice -PresentOnly` | 手机以复合设备挂载（`USB\VID_339B&PID_107D`），4 个功能接口全部到位：MI_00 WPD(MTP) OK、MI_01 大容量存储 OK、MI_02 ADB Interface OK、MI_03 HDB Interface Error | USB 调试已开、线能传数据。MI_03 的 Error 是荣耀自家 HDB 通道没驱动，adb 不用它，**不用管** |
| 3 | 查 ADB 接口驱动 | `Get-PnpDeviceProperty -InstanceId 'USB\VID_339B&PID_107D&MI_02\...'` | Service=WINUSB，Provider=Microsoft，winusb.inf 10.0.19041.1 | 驱动绑定正常（免驱路径），**不是驱动缺失** |
| 4 | 重启 adb 服务 | `adb kill-server` → `adb devices` | 仍为空 | 不是服务端状态陈旧 |
| 5 | 抓服务端 USB 扫描日志 | `ADB_TRACE=usb adb nodaemon server`（后台起服务端，日志落文件再 grep） | 设备线程正常启动（usb_windows.cpp），但日志里 0 条设备记录，无任何 339B | 电脑侧 adb 的枚举根本没扫到这个接口，问题在枚举机制，不在握手 |
| 6 | 查 Google 驱动 GUID 注册 | 注册表 `HKLM\SYSTEM\CurrentControlSet\Control\DeviceClasses\{F72FE0D4-CBCB-407d-8814-9ED673D0DD6B}` | 该键下没有任何设备注册 | **根因坐实**（见下节） |
| 7 | 尝试重启 USB 接口 | `pnputil /restart-device "USB\VID_339B&PID_107D&MI_02\..."` | 拒绝访问（需要管理员） | 即使重启也只是重新枚举，GUID 注册机制不变，治标不治本，放弃 |

## 根因分析

把第 3、5、6 步的证据拼起来：

1. 手机侧正常：USB 调试开着，adbd 在跑，所以 USB 配置描述符里暴露了 ADB 接口（MI_02）。
2. 驱动绑定正常：接口走的是**手机自声明 + 微软 winusb.inf 自动绑定**的免驱路径（荣耀 VID_339B 不在 Google USB 驱动的 INF 硬件 ID 列表里，Windows 10 不会匹配 Google 驱动）。
3. 免驱路径注册的设备接口 GUID 来自手机的 MS OS 描述符；而 Windows 版 adb（目录里有 `AdbWinApi.dll`，trace 显示走 `usb_windows.cpp` 经典后端）按 **Google USB 驱动 INF 声明的那条 adb 接口 GUID** 去枚举设备。
4. 注册表实测该 GUID 下空无一物 → adb 服务端每次扫描都返回 0 台设备。

一句话：**接口在、驱动在，但双方"对暗号"的 GUID 不是同一个**。这不是装个驱动就能自动好的问题——手改 Google INF 加 VID 会破坏 WHQL 签名，Win10 x64 拒装。

## 解决方案：无线调试（零安装）

Android 11+ 的无线调试是纯 TCP 通道，完全绕开 Windows USB 驱动栈。实测 5 分钟落地。

### 第 0 步：手机关 VPN（本次踩的最隐蔽的坑）

手机状态栏挂着 VPN 时，无线调试页面显示的「IP 地址和端口」是 **VPN 虚拟网卡的地址**（本次为 `172.19.0.1:37023`），电脑路由不可达，`adb connect` 报 10060 超时、ping 100% 丢包。先关 VPN，页面才会显示真实局域网地址（本次为 `10.6.24.162`）。

### 第 1 步：配对

手机：设置 → 开发者选项 → 无线调试 → 「使用配对码配对设备」，记下弹窗里的 **IP:配对端口** 和 **6 位配对码**（弹窗保持打开）。

```
adb pair 10.6.24.162:43437
Enter pairing code: 456723
Successfully paired to 10.6.24.162:43437 [guid=adb-...]
```

注意两点：

- 配对端口和连接端口**不是一个**，配对弹窗显示的是配对专用端口，一次性。
- 手机「已配对的设备」列表里的条目是客户端身份（`用户名@主机名`），换一台电脑必须重新配对。本次手机里已有的 `802164@C-03-2004-0150` 是别的电脑留下的，与本机（`802165@HeT-HLW0609`）无关。

### 第 2 步：连接

回到无线调试主页，用**主页面**的「IP 地址和端口」连接：

```
adb connect 10.6.24.162:37023
connected to 10.6.24.162:37023

adb devices -l
10.6.24.162:37023      device product:MAA-AN10 model:MAA_AN10 device:HNMAP transport_id:1
```

状态是 `device` 而不是 `unauthorized`，说明配对授权已生效。`adb mdns services` 在这种场景下发现不了设备（电脑有线、手机 Wi-Fi，跨广播域组播不通），**直连不受影响，不依赖 mDNS**。

### 第 3 步：安装

```
adb -s 10.6.24.162:37023 install -r C:\Users\802165\Downloads\jev-assistant-v1.3-release.apk
Performing Streamed Install
Success
```

手机端确认应用已正常安装。

## 有线方案备选（未执行）

想根治 USB 有线通道，装荣耀官方驱动：下载安装「荣耀手机助手 (HiSuite)」，它自带的 USB 驱动带荣耀 VID 适配，装完重插手机即可。不建议手改 Google USB 驱动的 INF 加硬件 ID——修改后 INF 与 WHQL 签名目录失配，Win10 x64 直接拒装，还得动签名策略，代价远超收益。

## 坑位清单（下次直接抄）

- `no devices/emulators found` 第一直觉别放在环境变量上：adb 能打印版本号就说明 Path 通了，问题一定在"电脑看不见手机"这一层。
- 排查顺序固定化：`adb devices` → 设备树有没有 ADB 接口节点 → 接口驱动是不是 WINUSB → 服务端 trace 扫到了什么 → Google GUID 注册表有没有东西。每步都是二分，5 分钟能定位到哪一侧的锅。
- 手机开 VPN，无线调试就废了：页面显示的是 VPN 虚拟地址，先关 VPN 再看端口。
- **配对成功 ≠ 已连接**：pair 只交换钥匙，connect 才建立会话；两个端口不同，配对码一次有效。
- HONOR/华为机型的 `HDB Interface` 报黄叹号无所谓，adb 不走那条通道。
- 无线调试端口在开关无线调试、重连 Wi-Fi 后会变；配对关系持久，断了只需重跑 `adb connect <新端口>`。
- 装完想恢复 VPN：已建立的 adb 连接可能被 VPN 掐断，关 VPN 重连即可，无需重新配对。

## 本次排查命令速查

```powershell
# adb 解析路径与设备列表
where adb
adb devices -l

# 设备树：找 Android/ADB 节点
Get-PnpDevice -PresentOnly | Format-Table Status,Class,FriendlyName -AutoSize

# 查 ADB 接口绑的驱动
Get-PnpDeviceProperty -InstanceId 'USB\VID_XXXX&PID_XXXX&MI_02\...' `
  -KeyName DEVPKEY_Device_Service,DEVPKEY_Device_DriverProvider

# 抓 adb 服务端 USB 扫描日志（后台起，日志落文件，别接管道吞输出）
adb kill-server
ADB_TRACE=usb adb nodaemon server > adb-trace.log 2>&1
adb devices -l

# Google adb 接口 GUID 注册检查
reg query "HKLM\SYSTEM\CurrentControlSet\Control\DeviceClasses\{F72FE0D4-CBCB-407d-8814-9ED673D0DD6B}" /s
```
