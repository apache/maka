# 02 · 接口契约（WP0，最先合并）

> 本文件是并行开发的"合同"。WP0 合并后，其他工作包只能**实现**这里的接口，不能改。要改契约，先改本文件和 `packages/contracts`，单独一个 PR。
> 对应骨架：`附录/代码骨架/src/{events,routeEvents,routeGroups,health,pipeline}.ts`，契约 zod 版：`附录/console-原型/src/contracts.ts`。

## 1. Canonical 层增量（`apps/gateway/src/core/`）

只做加法，现有 Provider 不用改就能编译。

| 位置 | 变更 | 原因 |
|---|---|---|
| `core/errors.ts` `ProviderError` | 新增可选 `retryAfterMs?: number` | 429 的 `Retry-After` 要传到健康簿和下游响应头 |
| `core/errors.ts` `ERROR_CODES` | 新增 `PROVIDER_REJECTED` | 上游 400 / 内容拒答。属于"问题本身"，**不改道、不歇息** |
| `core/provider.ts` `QoderProvider.id` | `"gateway" \| "cli" \| "cloudAgents"` → `string`；接口改名 `GatewayProvider`，保留 `export type QoderProvider = GatewayProvider` 兼容 | 用户可以加任意多个供应商实例 |
| `core/provider.ts` | 新增 `kind`、`label` | `kind` ∈ `qoder-gateway \| qoder-cli \| qoder-cloudAgents \| openai-compatible \| anthropic-compatible`；`label` 给界面看 |
| `core/provider.ts` `assertProvider` | 只检查 provider 自己返回的能力对象，**不先合并默认值**（修 `:35`） | 现在的校验恒通过 |

**能力映射**：现有 `ProviderCapabilities` 是三态（`tools: native|emulated|none`、`vision: native|attachment|none`、`thinking: native|text|none`），且 `capabilities()` 可能返回 Promise。路由的 `plan()` 只需要布尔值：

```ts
// routing/capabilityView.ts（WP6）
export async function capabilityView(p: GatewayProvider) {
  const c = await p.capabilities();
  return { tools: c.tools !== "none", vision: c.vision !== "none", thinking: c.thinking !== "none" };
}
```

结果按 provider id 缓存，供应商配置变更时随快照一起重建。骨架里的 `Capabilities` 布尔接口就是这个视图。

## 2. 路由事件（`routing/routeEvents.ts`）

### 2.1 Schema

```ts
type MemberRef = { providerId: string; model: string };

type RouteEvent =
  | { type: "request.start";     requestId; at; agent; alias; groupId: string | null; protocol }
  | { type: "route.decision";    requestId; at; strategy: "ordered" | "smart" | "direct";
      candidates: Array<MemberRef & { state: "ready" | "resting" | "skipped"; reason: string; restUntil?: number }> }
  | { type: "upstream.attempt";  requestId; at; member; attempt }          // attempt 从 1 开始
  | { type: "upstream.firstByte"; requestId; at; member; ms }              // 从本次 attempt 开始计
  | { type: "upstream.failed";   requestId; at; member; code; status?; restUntil?; reroutable }
  | { type: "reroute";           requestId; at; from; to; reason }
  | { type: "request.end";       requestId; at; outcome: "ok" | "error" | "cancelled";
      member: MemberRef | null; ms; reroutes; errorCode?; usage?: { inputTokens?; outputTokens? } };
```

总线给每条事件加单调递增的 `seq`（进程内唯一，重启从 1 开始）。`at` 是毫秒时间戳。

### 2.2 序列约束（测试必须断言）

同一个 `requestId`：

1. 第一条是 `request.start`，**恰好一条** `request.end` 且在最后（不变量 I2）。
2. `route.decision` 最多一条，在第一个 `upstream.attempt` 之前。
3. `upstream.firstByte` 最多一条；它之后不再出现 `upstream.attempt` 和 `reroute`（I1：改道只在首个内容事件前）。
4. `reroute` 紧跟在一条 `reroutable: true` 的 `upstream.failed` 之后。
5. 直连（`strategy: "direct"`）不出现 `reroute`（I3）。
6. `request.end.reroutes` 等于该请求 `reroute` 事件的条数。

### 2.3 内容边界

事件里**只放路由元数据**。不放 prompt、回复正文、工具参数、图片、任何 Key、上游原始错误正文（错误只给 `code` + `status`；人看的原因由 `health.classify()` 生成）。e2e 测试会把 prompt 里的标记字符串和 Key 在 `/admin/events` 输出里做反向搜索，必须找不到。

## 3. Admin API（`/admin/*`）

### 3.1 认证与边界

- 网关只绑 `127.0.0.1`（`::1` 可选）。`QPA_HOST` 改成非回环地址时启动打警告，且 `/admin/*` 和 `/ui` 默认拒绝。
- admin token：首次启动生成 32 字节随机值，写 `secrets.json`。请求头 `Authorization: Bearer <token>`。
- 控制台由网关同源托管（`/ui`），页面通过 `GET /ui/` 时注入的 `<meta name="qpa-admin-token">` 拿 token（只有回环来源能拿到 `/ui`）。
- **防 DNS rebinding**：`Host` 必须是 `127.0.0.1:<port>` / `localhost:<port>` / `[::1]:<port>`；有 `Origin` 时必须同上，否则 403。
- `?token=` 只给 dev 模式和无法带头的场景兜底，生产托管下关闭（`QPA_ADMIN_QUERY_TOKEN=1` 才开）。
- dev 跨源：`QPA_DEV_CORS_ORIGIN=http://localhost:5173` 时才回 CORS 头并处理 `OPTIONS`。默认不开。

### 3.2 端点

| 方法 & 路径 | 用途 | 请求 | 响应 |
|---|---|---|---|
| `GET /admin/state` | 控制台首屏一次拿全 | — | `{ version, providers[], groups[], health[], agents[], plans[], lastSeq }` |
| `GET /admin/events` | 路由事件 SSE | `Last-Event-ID` 或 `?since=<seq>` | `id: <seq>`、`event: route`、`data: RouteEvent`；每 15 秒 `: ping`；先回放缓冲区里 `seq > since` 的事件 |
| `GET /admin/providers` | 供应商列表 | — | `Provider[]`，Key 只回 `keyHint`（末 4 位） |
| `POST /admin/providers` | 新增 | `{ id, kind, label, baseUrl?, apiKey?, models?, enabled }` | `201 Provider` |
| `PATCH /admin/providers/:id` | 修改 | 部分字段；`apiKey` 只写不读，传 `null` 表示删除 | `Provider` |
| `DELETE /admin/providers/:id` | 删除 | — | `204`；仍被路由组引用时 `409 { refs: groupId[] }` |
| `POST /admin/providers/:id/test` | 连通性测试 | `{ model? }` | `{ ok, ms, code?, status?, models? }`：先 `listModels`，再发 1 token 请求 |
| `GET/POST/PATCH/DELETE /admin/groups[/:id]` | 路由组 CRUD | `RouteGroup`（§4） | 同上；成员引用不存在的 provider → `422` |
| `POST /admin/health/reset` | 清除歇息 | `{ providerId?, model? }`，空 = 全部 | `{ cleared }` |
| `GET /admin/agents` | 三个 Agent 状态 | — | `AgentIntegration[]`：`{ id, installed, configPath, connected, model, drift }` |
| `POST /admin/agents/:id/connect` | 接入 | `{ model, dryRun? }` | `dryRun: true` → `{ diff, writes[] }`；否则写入并 `{ backupId }` |
| `POST /admin/agents/:id/disconnect` | 断开并恢复 | `{ dryRun? }` | 同上；按 §6 三方比对 |
| `PATCH /admin/agents/:id` | 只换模型 | `{ model }` | `AgentIntegration` |
| `GET/POST/DELETE /admin/plans[/:id]`、`POST /admin/plans/:id/apply` | 方案（Agent→模型的快照） | `{ name, assignments: { [agentId]: alias } }` | 应用后返回每个 Agent 的结果 |
| `GET /admin/usage` | 用量查询 | `?from&to&groupBy=day\|agent\|provider\|model` | `{ rows: [{ key, requests, errors, reroutes, inputTokens, outputTokens, p50Ms, p95Ms }] }` |

正式控制台用 **fetch + ReadableStream** 读 `/admin/events`（能带 `Authorization`），`EventSource` 只在 dev 兜底。断线重连带上最后的 `seq`；如果 `since` 早于缓冲区最旧一条，服务端先发一条 `event: reset`，客户端重新拉 `/admin/state`。

### 3.3 写入语义

- 所有写操作：校验 → 写 `config.json.tmp` → `fsync` → `rename` → 构建新的 `PipelineDeps` 快照 → 替换引用 → 返回。任一步失败，内存状态不变。
- 请求带 `If-Match: <version>`，版本不符 → `409`，防两个标签页互相覆盖。
- 来自环境变量的条目在响应里带 `source: "env"`，对它的写操作返回 `409 { error: "ENV_MANAGED" }`。

### 3.4 Admin 错误格式

```json
{ "error": { "code": "VALIDATION_FAILED", "message": "members[1] 需要 providerId 和 model", "path": "members[1]" } }
```

| HTTP | code |
|---|---|
| 400 | `BAD_JSON` |
| 401 | `ADMIN_AUTH_REQUIRED` |
| 403 | `ORIGIN_REJECTED`（Host / Origin 不符） |
| 404 | `NOT_FOUND` |
| 409 | `VERSION_CONFLICT` / `IN_USE` / `ENV_MANAGED` / `AGENT_CONFIG_DRIFT` |
| 422 | `VALIDATION_FAILED` |
| 500 | `INTERNAL`（不带堆栈） |

## 4. 路由组配置与别名

```json
{
  "id": "daily-coding",
  "name": "日常编码",
  "strategy": "ordered",
  "enabled": true,
  "maxAttempts": 3,
  "members": [
    { "providerId": "kimi", "model": "kimi-k2" },
    { "providerId": "deepseek", "model": "deepseek-chat" },
    { "providerId": "qoder", "model": "auto" }
  ]
}
```

- `id`：`^[a-z0-9][a-z0-9-]{0,39}$`；`members` 非空、去重；`maxAttempts` 1–5，默认 3。
- `strategy`：
  - `ordered`：按配置顺序，跳过 `resting` / `skipped`；
  - `smart`：会话亲和 > 失败次数少 > 在途请求少 > 首字节 EWMA 低 > 配置顺序。
- 下游 `model` 字段的解析顺序（`resolveTarget`）：
  1. `group/<id>` → 路由组；
  2. `QODER_MODEL_ROUTES` / `config.directRoutes` 里的别名 → 直连；
  3. `<providerId>/<model>` 且 providerId 已注册 → 直连；
  4. 其他 → 默认 provider + 原 model（保持 v0.1 行为，`QODER_MODEL_MAP` 照旧生效）。
- Agent 接入时，写进 Agent 配置的 model 就是上面任意一种字符串，通常是 `group/<id>`。
- 直连永不改道。想要改道，必须显式用组。

## 5. 数据面 HTTP 错误映射

协议层先 `peekFirst()`。首事件是 `error` 时按下表回真实状态码；否则写 200 + SSE，之后的错误只能作为流内错误事件。

| ProviderError.code | HTTP | 额外头 | 是否改道（组内、commit 前） | 健康簿 |
|---|---|---|---|---|
| `PROVIDER_RATE_LIMITED` | 429 | `Retry-After`（秒，取最早恢复） | 是 | 歇 `Retry-After`（≤1 小时），否则 60 秒×2^strikes（≤30 分钟） |
| `PROVIDER_AUTH_ERROR` | 502 | — | 是 | 歇 30 分钟 |
| `MODEL_NOT_FOUND` | 400（直连）/ 改道（组） | — | 是 | 歇 10 分钟 |
| `PROVIDER_UNAVAILABLE` / `PROVIDER_PROTOCOL_ERROR` | 502 | — | 是 | 60 秒×2^strikes（≤10 分钟） |
| `PROVIDER_TIMEOUT`（首字节超时） | 504 | — | 是 | 同上 |
| `PROVIDER_REJECTED` / `UNSUPPORTED_CAPABILITY` | 400 | — | 否 | 不歇 |
| `PROVIDER_ABORTED` | 499（只记日志，客户端已走） | — | 否 | 不歇 |
| 组内全部 `resting` | 429 | `Retry-After` = 最早恢复 | — | — |
| 组内全部 `skipped`（能力不符） | 400 `UNSUPPORTED_CAPABILITY` | — | — | — |

错误体按下游协议的格式写（OpenAI `{error:{type,code,message}}`，Anthropic `{type:"error",error:{type,message}}`），`message` 是中文可读原因 + 英文 code，不夹带上游原始正文。

## 6. Agent 配置目标（WP9）

> 字段名基于 2026 年中各 CLI 公开文档整理，**WP9 第一步必须用真实 CLI 逐项核对**（05 R4）。

| Agent | 文件 | 我们写的键 | 下游协议 |
|---|---|---|---|
| Claude Code | `~/.claude/settings.json` | `env.ANTHROPIC_BASE_URL`、`env.ANTHROPIC_AUTH_TOKEN`、`env.ANTHROPIC_MODEL`（可选 `env.ANTHROPIC_SMALL_FAST_MODEL`） | `/v1/messages` |
| Codex | `~/.codex/config.toml` | `model`、`model_provider = "qoder-proxy"`、`[model_providers.qoder-proxy]` 下 `name`、`base_url`、`wire_api = "responses"`、`env_key = "QPA_CODEX_KEY"` | `/v1/responses` |
| OpenCode | `~/.config/opencode/opencode.json` | `provider["qoder-proxy"]`（`npm: "@ai-sdk/openai-compatible"`、`options.baseURL`、`options.apiKey`、`models`）、`model: "qoder-proxy/<alias>"` | `/v1/chat/completions` |

规则：

1. **只改自己的键。** 解析 → 修改指定路径 → 按原格式写回。JSON 保留缩进与键顺序；TOML 用行级编辑，只动我们的表和顶层两个键，保留注释。
2. **备份**：首次接入前把原文件完整复制到 `backups/<agent>/<时间戳>.orig`，记录 `sha256(原文件)` 和 `sha256(写入后)`。文件不存在时记录 `absent`。
3. **断开 = 三方比对**：
   - 当前文件 sha256 == 写入后 sha256 → 用备份逐字节恢复（或删除，若原来不存在）；
   - 不等（用户后来手改过）→ 只删除我们写的键，其余保留，并在 diff 里标出；dry-run 返回 `drift: true`，界面二次确认。
4. **dry-run 先行**：界面的"接入 / 断开"一律先请求 `dryRun: true`，展示 diff，用户确认后再写。
5. Codex 的 Key 走环境变量 `QPA_CODEX_KEY`，不写进 `config.toml`；界面给出 `export` 命令让用户自己加进 shell 配置。Claude Code / OpenCode 的 Key 写进其配置文件（与它们自身的惯例一致），文件权限保持原样。
6. 只支持这三个。其余 Agent 在界面列出为"暂不支持"，不写任何文件（ADR-0009）。

## 7. 存储 schema

### 7.1 `~/.qoder-proxy-api/config.json`

```json
{
  "version": 7,
  "defaultProvider": "qoder",
  "providers": [
    { "id": "qoder", "kind": "qoder-gateway", "label": "Qoder", "enabled": true },
    { "id": "deepseek", "kind": "openai-compatible", "label": "DeepSeek",
      "baseUrl": "https://api.deepseek.com/v1", "models": ["deepseek-chat", "deepseek-reasoner"],
      "capabilities": { "tools": true, "vision": false, "thinking": true },
      "firstByteTimeoutMs": 30000, "enabled": true }
  ],
  "groups": [ /* §4 */ ],
  "directRoutes": { "fast": "deepseek/deepseek-chat" },
  "agents": {
    "codex": { "connected": true, "model": "group/daily-coding", "backupId": "codex/2026-05-12T09-30-00Z",
               "writtenSha256": "…", "originalSha256": "…|absent" }
  },
  "plans": [ { "id": "budget", "name": "Budget", "assignments": { "claude-code": "group/cheap-and-fast" } } ]
}
```

- `version` 每次写入 +1，用作 `If-Match`。
- `openai-compatible` 的能力由用户声明（界面默认 tools ✓ / vision ✗ / thinking ✗），"测试连接"可以辅助勾选。

### 7.2 `~/.qoder-proxy-api/secrets.json`（权限 0600，目录 0700）

```json
{ "adminToken": "…", "providerKeys": { "deepseek": "sk-…" }, "agentKeys": { "qpa-…": "codex" } }
```

启动时权限不是 0600 → 打警告并尝试 `chmod`。任何 API 响应、日志、路由事件都不出现这里的值。

### 7.3 `~/.qoder-proxy-api/usage.sqlite`（`node:sqlite`）

```sql
CREATE TABLE IF NOT EXISTS requests (
  request_id   TEXT PRIMARY KEY,
  started_at   INTEGER NOT NULL,      -- ms
  agent        TEXT NOT NULL,
  alias        TEXT NOT NULL,
  group_id     TEXT,
  provider_id  TEXT,                  -- 最终成员；失败时可为 NULL
  model        TEXT,
  outcome      TEXT NOT NULL CHECK (outcome IN ('ok','error','cancelled')),
  error_code   TEXT,
  reroutes     INTEGER NOT NULL DEFAULT 0,
  first_byte_ms INTEGER,
  total_ms     INTEGER NOT NULL,
  input_tokens INTEGER,
  output_tokens INTEGER
);
CREATE INDEX IF NOT EXISTS idx_requests_started ON requests(started_at);
PRAGMA user_version = 1;
```

- 写入者只订阅 `request.end`（`first_byte_ms` 从同 requestId 的 `upstream.firstByte` 取），批量每秒一次事务。
- 默认保留 90 天，启动时清理。
- `node:sqlite` 不可用（老 Node / 打包问题）时降级为 `usage.jsonl` 追加，查询退化为内存聚合（05 R5）。
