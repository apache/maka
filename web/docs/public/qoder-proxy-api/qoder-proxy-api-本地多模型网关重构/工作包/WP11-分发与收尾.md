# WP11 · 分发（npx / SEA / 可选桌面壳）与收尾文档

- **目标**：干净机器上一条命令跑起来；文档与定位声明收尾。
- **依赖**：WP7–WP9
- **分支**：`feat/wp11-dist`
- **归属文件**：根 `package.json` 发布配置、`scripts/build-sea.ts`、`.github/workflows/release.yml`、`README.md`、`CLAIMS.md`、`docs/**`

## 步骤

1. npm 包：发布 `apps/gateway` + `apps/console/dist`；`npx qoder-proxy-api` 启动并打开 `/ui`（`--no-open` 关闭）。Node 24 直接跑 TS 源（沿用现状）或预编译 JS，二选一并写进 ADR。
2. Node SEA：打包单文件（macOS arm64/x64、Linux x64、Windows x64），控制台静态资源作为 SEA asset。实测 `node:sqlite` 在 SEA 下是否可用（05 R5），不可用则自动降级。
3. 可选桌面壳评估（Tauri 优先）：只负责启动网关子进程、托盘状态、打开 WebView 到 `/ui`。写评估结论，不强求实现。
4. 文档：README（定位声明、三步上手、截图）、CLAIMS.md（每条能力对应测试）、`docs/agents.md`、`docs/middleware.md`、升级说明（v0.2 → v1.0：env 继续有效，`PROXY_API_KEY` deprecated）。
5. CI 版本校验：`CLAIMS.md` 里的版本与 package.json 一致。

## 验收

- 干净 Docker 容器（只有 Node 24）里 `npx qoder-proxy-api` 启动，`curl /v1/chat/completions` 与 `/ui` 均可用。
- SEA 产物在至少两个平台实测启动。
- README 的每条命令可复制执行。

## 不要做

- 不为桌面壳改网关架构。
