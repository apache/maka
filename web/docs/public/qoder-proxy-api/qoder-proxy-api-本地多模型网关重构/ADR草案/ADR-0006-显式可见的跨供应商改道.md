# ADR-0006：从"无自动 fallback"调整为"只允许显式、可见的跨供应商改道"

- 状态：草案（Proposed）
- 取代：现有原则"显式路由、无自动 fallback"中的"无自动 fallback"部分
- 相关：02 §2、§4、§5；WP6

## 背景

v0.x 的原则是一个 model 别名对应一个上游，失败就把错误交给客户端。这让行为可预测，但在接入多个供应商后有两个问题：

1. 某个供应商限流（429）时，Agent 整轮失败，用户只能手动改配置。
2. 用户本来就有多个供应商的 Key，"这个不行换那个"是他们手动在做的事。

magpie 的做法是账号池 + 自动轮换。我们不想要账号池（见下），但"组内换供应商"是合理需求。

## 决定

允许改道，但同时满足下面四个条件：

1. **显式**：只在用户配置的**路由组**内改道。下游用 `group/<id>` 才会改道；直连（`provider/model`、旧别名）永不改道。
2. **时机**：只在**下游还没收到任何内容**之前改道（commit 前）。一旦开始输出，失败就是流内错误。
3. **可见**：每次决策、尝试、失败、改道都发路由事件；控制台路由页实时显示；用量库记录 `reroutes`。
4. **有据**：只有 429、401/403、404 模型、5xx、首字节超时、空回复这类"换个上游可能就好"的错误才改道；400、内容拒答、客户端取消不改道。

## 明确不做

- **不做同一服务的多账号池、额度共享、轮换绕过限流。** 路由组成员应是不同供应商，或同一供应商下用户自己合法持有的不同 Key / 模型。
- 不做 commit 后的"续写拼接"。
- 不做同一成员的立即重试。

README 增加定位声明：

> qoder-proxy-api 是个人本机使用的多模型网关。它帮你在**自己拥有的**多个供应商之间显式切换，不提供账号池、额度共享或任何绕过服务商限制的功能。

## 后果

- 正面：限流时 Agent 不中断；行为仍可解释（每一跳都有事件）。
- 负面：改道后模型不同，thinking 签名、prompt cache 失效（05 R2）；需要会话亲和与中间件剥离缓解。
- 测试：不变量 I1–I3 成为 CI 必测项。
