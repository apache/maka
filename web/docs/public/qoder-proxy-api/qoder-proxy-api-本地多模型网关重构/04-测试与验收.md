# 04 · 测试与验收

## 1. 分层

| 层 | 位置 | 工具 | 跑在哪 | 说明 |
|---|---|---|---|---|
| 单元 | `apps/gateway/test/**` | `node --test`（零依赖） | 每个 PR | 纯函数：`classify`、`plan`、`resolveTarget`、SSE 解析、请求映射 |
| 协议往返 | `test/protocols/**` | `node --test` + fixtures | 每个 PR | 下游 JSON → Canonical → 下游 JSON，工具 / 图片 / thinking 签名不丢（性质测试：随机生成消息序列） |
| 管线 | `test/routing/**` | `node --test` + `fakes.ts` 脚本化 Provider | 每个 PR | 骨架 17 个用例 + 新增；断言事件序列（02 §2.2） |
| 网关 e2e | `test/e2e/**` | `node --test`，起真实 HTTP 服务 + 假上游 HTTP 服务 | 每个 PR | 骨架 `openaiCompatible.test.ts` 那种：真实 fetch、真实 SSE、真实 `/admin/events` |
| 标准契约 | `test/standard/**` | devDep：`@langchain/openai`、`@langchain/anthropic` | 每个 PR（单独 job） | standard-tests 风格约 15 个用例：流式、工具调用、工具结果回填、多轮、图片、stop reason、usage、取消 |
| langchain smoke | `examples/langchain-smoke` | `createAgent` 两轮工具往返 | 每个 PR（单独 job） | 经 `group/<id>` 和直连各一次 |
| 控制台 | `apps/console/test/**` | Vitest（store reducer）、Playwright（页面） | 每个 PR | reducer 吃一串事件后的状态快照；Playwright 对 mock 和 live 两种模式截图比对 |
| 真实供应商 | `test/live/**` | 手动 / nightly，需要 Key | 不在 PR CI | 每个供应商：一次文本、一次工具调用、一次 429 观察（如能触发） |

CI 中 gateway 的数据面测试必须在**没有安装 devDependencies** 的情况下也能跑（`node --test` 直接跑 TS），保证零依赖不被破坏。

## 2. 不变量（每个改道相关测试都要断言）

| 编号 | 不变量 | 怎么测 |
|---|---|---|
| I1 | 改道只在首个内容事件之前 | 假上游先发 1 个 `text.delta` 再抛 429 → 下游收到流内错误，事件里无 `reroute` |
| I2 | 每个请求恰好一条 `request.end`，且在最后 | 所有管线测试结束时调用 `assertSequence(events)` |
| I3 | 直连不改道 | `provider/model` 直连 + 429 → 下游 429，无 `reroute` |
| I4 | 事件不含 prompt / Key | e2e 中在 prompt 放 `CANARY-<uuid>`，在 `/admin/events` 原始输出里搜索，必须 0 命中；Key 同理 |
| I5 | 下游只看到一个上游的内容 | commit 前被扣住的 `message.start`/`usage` 在改道时丢弃，下游的 `message.start` 只有一个 |
| I6 | 客户端中止会传到上游 | 中止后假上游的 `signal.aborted === true`，outcome `cancelled`，不歇息 |
| I7 | Agent 配置断开后逐字节恢复 | 临时 HOME 里放原文件 → 接入 → 断开 → `sha256` 相等 |

## 4. Definition of Done（每个 PR）

- [ ] 只改了归属文件（`git diff --stat` 贴进 PR）
- [ ] 新增 / 修改的行为都有测试，且测试先红后绿（PR 里说明怎么证明）
- [ ] `pnpm -r test`、`pnpm check`、`tsc --noEmit` 全绿
- [ ] gateway 没有新增运行时依赖（`apps/gateway/package.json` 的 `dependencies` 为空）
- [ ] 日志、事件、错误响应里没有 Key 和 prompt
- [ ] 用户可见变化更新了 README / CLAIMS.md
