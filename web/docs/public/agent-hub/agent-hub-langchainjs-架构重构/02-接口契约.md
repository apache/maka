# 02 · 接口契约（WP0 合并，所有工作包共用）

> 原则：**前端可见的协议零破坏**。新增的只有：ChatRequest 进入 zod 单一事实源，以及可选的 `threadId` 字段。

## 1. 契约增量（packages/shared/src/contracts.ts）

```ts
/** 对话请求：原来只在 schemas.py 里有，现在进入单一事实源 */
export const ChatRequest = z.object({
  message: z.string().trim().min(1).max(2000),
  /** 会话标识；不传 = 单轮（与旧行为一致）。前端生成，点"清空"时重置 */
  threadId: z.string().min(8).max(64).optional(),
});
export type ChatRequest = z.infer<typeof ChatRequest>;
```

同步规则（AGENTS.md 现有规则）：

- `apps/api/app/schemas.py` 的 `ChatRequest` 同步加上 `threadId: str | None = None`。迁移期 py 后端会收到这个字段，接收但忽略。
- `fixtures/contract-example.json` **只追加** `chatRequest` 样例：`{"message":"想给妈妈送生日礼物","threadId":"t-0123456789"}`。
- `contracts.test.ts` 与 `test_contracts.py` 各加 1 个用例，对账这个样例。

**事件联合 `AgentStreamEvent` 一个字段都不改。**

## 2. 事件映射表（translate.ts 的规范）

| 来源（agent.stream） | 条件 | 出站事件 | 备注 |
|---|---|---|---|
| `messages` · AIMessageChunk · node=`model_request` | `additional_kwargs.reasoning_content` 非空 | `thought{seq, text, final:false}` | 每次模型调用的首个 reasoning 开新段，后续增量追加到同一 seq |
| 同上 | `tool_call_chunks[i].name` 出现 | `thought` 新段 | 固定文案：`search_evidence`→「检索顾客画像与历史记录…」、`search_catalog`→「查询在售花材与价格…」、`present_recommendation`→「整理推荐方案…」，其他工具→「调用工具 X…」。**不透传参数** |
| 同上 | `content` 文本，且本次调用累计 ≤ 24 字、还没出现工具调用 | （扣留） | 见 01 §4.3 |
| 同上 | 扣留期间出现工具调用 | `thought` 新段（扣留文本） | 开场白进思考区 |
| 同上 | 扣留超过 24 字 / 调用结束且无工具调用 | `token{text}` | 首个 token 前先补 final thought |
| 同上 | 已出现工具调用后同一调用的文本 | 丢弃 | 少数模型会在 tool_call 之后吐空白 |
| `messages` · ToolMessage · node=`tools` | `status === 'error'` | `thought` 新段「校验未通过，重新检索后再推荐…」 | 错误原文只给模型看 |
| `messages` · ToolMessage | `status === 'success'` | 不出站 | |
| `messages` · 其他 node | 例如摘要中间件内部的模型调用 | 不出站 | |
| `custom` | `{type:'card'}` / `{type:'evidence'}` | 原样（再 parse 一次） | 首个 card 前先补 final thought |
| 流正常结束 | | 补 final thought（如有）→ `done{replyId}` | `replyId` = 12 位随机 hex，**不再是模型名** |
| 异常 | | `error{code,message}` | 互斥于 done；见 §5 |

**序列不变式**（04 §3 的断言来源）：

- S1 最后一个事件是 `done` 或 `error`，且两者合计恰好出现一次；
- S2 `thought.seq` 从 1 开始单调不减；`final:true` 之后不再出现 thought；
- S3 若有 thought，首个 `card`/`token` 之前必有 `final:true`；
- S4 card 引用的每个 `evidenceId` 都会随后以 evidence 事件下发；
- S5 每个出站事件都满足 `AgentStreamEvent.parse`。

## 3. 工具 schema（tools.ts）

| 工具 | 入参（zod） | 返回 | 副作用 |
|---|---|---|---|
| `search_evidence` | `{ kinds?: ('purchase_history'\|'preference_survey'\|'care_record')[] }` | `content_and_artifact`：content=`[id] 来源（可信度 n）：原文` 多行；artifact=`Evidence[]` | 无 |
| `search_catalog` | `{ scene?: RecommendScene, maxPriceFen?: int>0 }` | content=`[skuId] 名称 类型 ¥价` 多行；artifact=`FlowerItem[]` | 无 |
| `present_recommendation` | `{ scene, title(1–30), reason(1–80), skuIds: string[1..3], evidenceIds: string[≥1] }` | 字符串（提示模型"卡片已展示，用一两句话说明理由"） | `writer(card)` → `writer(evidence)×n` |

`present_recommendation` 的校验：

```text
本轮 = 最后一条 HumanMessage 之后
evidenceIds ⊆ ⋃ 本轮 search_evidence（status≠error）的 artifact[].id
skuIds      ⊆ ⋃ 本轮 search_catalog（status≠error）的 artifact[].id
不满足 → throw Error("证据 X 不在本轮检索结果中，请先调用 search_evidence；商品 Y …")
满足   → FlowerCardPayload.parse({ scene, title, reason, items: 从 CATALOG 取, evidenceRefs: {evidenceId, label: EVIDENCE[id].source} })
```

> "本轮"而不是"本会话"：上一轮检索过的证据，这一轮可能已经不成立了（例如顾客改口）。要求每轮重新检索，代价是一次很便宜的工具调用。

## 4. HTTP（apps/agent）

| 方法 | 路径 | 请求 | 响应 |
|---|---|---|---|
| POST | `/api/agent/chat` | `ChatRequest` JSON | 200 `text/event-stream`；请求体不合法 → 422 `{detail}` |
| GET | `/api/evidence/:id` | — | 200 `Evidence` / 404 `{detail:"evidence not found"}`（与 FastAPI 一致） |
| GET | `/healthz` | — | `ok` |

响应头：`content-type: text/event-stream; charset=utf-8`、`cache-control: no-cache`、`x-accel-buffering: no`。

- 帧：``event: ${e.type}\ndata: ${JSON.stringify(e)}\n\n``。`JSON.stringify` 不会产生裸换行，天然单行。
- 客户端断开（`res.on('close')` 且未写完）时 `AbortController.abort()`，中止模型调用。
- 不带 `threadId` 时用一次性的 `randomUUID()`，行为等同于旧版单轮。

## 5. 错误码映射

| 触发 | code | message（给用户看） |
|---|---|---|
| `signal.aborted` / `AbortError` | `aborted` | 已停止生成 |
| `ZodError`（出站事件不合契约） | `protocol` | 智能体输出不符合契约 |
| `ModelCallLimitMiddlewareError` / `ToolCallLimitExceededError` / `GraphRecursionError` | `server` | 本轮推理步数超出上限，请换个说法再试 |
| 带 `status` 的上游错误 | `server` | 模型服务暂不可用（{status}） |
| 其他 | `server` | 智能体运行出错 |
