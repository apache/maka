## 3. 合并顺序与 rebase 规则

1. WP0 → main。
2. WP1、WP2、WP6 任意顺序合并，互不冲突。
3. WP3 从合并了 WP1+WP2 的 main 拉分支。
4. WP4 合并前**必须** E2E 3 条在 `AGENT_BACKEND=ts` 下全绿；在 `AGENT_BACKEND=py` 下也要绿（回退可用）。
5. WP5、WP7 可同时开；WP5 先合（它改了前端，WP7 只加测试）。
6. WP9 最后。前置条件：对等测试连续绿 + 至少一次真实模型手测记录（见 04 §6）。

## 4. 分支与 worktree

```bash
# 在仓库根执行；每个代理一个 worktree，互不干扰
git worktree add ../ah-wp0 -b refactor/wp0-contracts-shell main
# WP0 合并后：
git worktree add ../ah-wp1 -b refactor/wp1-tools main
git worktree add ../ah-wp2 -b refactor/wp2-translate main
git worktree add ../ah-wp6 -b fix/wp6-task-restart main
# WP1+WP2 合并后：
git worktree add ../ah-wp3 -b refactor/wp3-agent-assembly main
# 以此类推：wp4-http-cutover / wp5-memory / wp7-real-path / wp8-hitl-order / wp9-cleanup
```

每个 worktree 需要各自 `pnpm install`。WP6 还需要 `pnpm api:setup`。

## 5. 给代理的通用约束（每个提示词都隐含这些）

- 先读 `AGENTS.md`、本包 `02-接口契约.md` 和对应 WP 文档。
- 只改归属文件；需要越界时，停下来说明原因。
- 不加 ADR 之外的依赖；不引测试框架（只用 `node:test` / `pytest`）。
- Node 24 strip-only：不写参数属性（`constructor(private x)`）、`enum`、`namespace`；import 带 `.ts` 后缀。
- 完成后输出：改动文件列表、测试结果、与本文档不一致的地方。
