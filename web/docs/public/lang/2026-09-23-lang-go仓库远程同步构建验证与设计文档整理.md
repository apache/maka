### 3.1 远程同步与"重命名冲突"的解决

**初始状态**：main 落后 origin/main 20 个提交且可快进；工作区有一处未提交修改 `docs/lang-go-v0.4-v1.0-prompts.md`（5 增 5 删，内容是把 `implementations/` 目录设想修订为与根 README 对齐的平级结构）；未跟踪文件 `docs/plans/`。

**症状**：`git pull --ff-only origin main` 被拒：

```
error: Your local changes to the following files would be overwritten by merge:
	docs/lang-go-v0.4-v1.0-prompts.md
```

但该文件并不出现在 `git diff --name-only main origin/main` 里——这是**重命名冲突**的特征。

**根因**：远程提交 `d4e51d1`（"docs(lang-go): 开发文档收拢 docs/lang-go/——日期+中文统一命名"）把该文件移动并重命名为 `docs/lang-go/2026-09-20-分版本执行提示词v0.4到v1.0.md`，内容未变（新旧 blob 同为 `05d8567`）。旧路径要被删除、而旧路径上有本地未提交修改，Git 拒绝合并。`git diff --name-only` 只显示**新路径**，所以先前按路径排查会漏掉它；`git log --follow` 才显示该文件被移动过。

**解决步骤**（有效方案）：

```bash
# 1. 备份本地改动为补丁
git -C "E:\ggbdpq\gh\language" diff -- docs/lang-go-v0.4-v1.0-prompts.md > /tmp/lang-prompts-local.patch
# 2. 还原旧路径为干净状态（改动已在补丁里）
git -C "E:\ggbdpq\gh\language" restore docs/lang-go-v0.4-v1.0-prompts.md
# 3. 快进拉取
git -C "E:\ggbdpq\gh\language" pull --ff-only origin main    # a146f94..cd491a1
# 4. 把补丁里的旧路径替换为新路径后应用
sed 's|docs/lang-go-v0.4-v1.0-prompts\.md|docs/lang-go/2026-09-20-分版本执行提示词v0.4到v1.0.md|g' \
  /tmp/lang-prompts-local.patch > /tmp/lang-prompts-ported.patch
git -C "E:\ggbdpq\gh\language" apply --check /tmp/lang-prompts-ported.patch   # 先干跑
git -C "E:\ggbdpq\gh\language" apply /tmp/lang-prompts-ported.patch
# 5. 核验后清理临时补丁
git -C "E:\ggbdpq\gh\language" diff --stat   # 1 file changed, 5 insertions(+), 5 deletions(-)（新路径上）
```

**为什么有效**：新旧 blob 相同，说明远程只移动未改内容，因此同一 hunk 必然能干净套用到新路径；`git apply --check` 干跑先验证再落地，避免半途失败。改动保持未提交状态，与拉取前一样由用户决定何时提交。

### 3.3 三个环境问题的定位与修复

**a. 在仓库根执行 `go build` 报 "cannot find main module"**

症状：`go: cannot find main module, but found .git/config in E:\ggbdpq\gh\language`。根因：这是多语言仓库（`go/`、`typescript/`、`python/` 各自独立），仓库根没有 `go.mod`，Go 模块在 `go/` 子目录。修复：

```bash
cd go && go build -o lang-go ./cmd/lang-go
# 或免切目录：
go -C go build -o lang-go ./cmd/lang-go
```

**失败尝试**：不要按报错提示执行 `go mod init`——那是给"想在此新建模块"的人用的，会在仓库根多出一个多余 `go.mod`。

**b. 终端用 `cat > file` 交互式建文件，代码行被 bash 执行**

症状：输入 `cat > main.lang-go` 回车后敲代码，出现三条 `bash: syntax error near unexpected token ...`（`(`、`"hello, lang-go"`、`}` 各一条，正好对应三行代码）。根因：`cat` 提前退出（Ctrl+C 或在提示符下直接敲代码）后，代码行落到了 bash 手里，`fn main() {` 被当 shell 命令解析，`(` 是 bash 元字符故报错。修复（自动结束、可覆盖半截文件）：

```bash
cat > main.lang-go <<'EOF'
fn main() {
    println("hello, lang-go")
}
EOF
```

**c. `code` 命令崩溃：PATH 里的坏 shim 遮住了正版 VS Code**

症状：`code main.lang-go` 抛 Node 错误 `Cannot find module 'D:\DevTools\AI\Alibaba\QoderCN\QoderCN\resources\app\out\cli.js'`。定位：`type -a code` 显示 PATH 里三个 `code`，排最前的是 **QoderCN**（VS Code 分叉版）的启动器，其实体文件 `cli.js` 已丢失（安装损坏或被移动），把后面的正版全遮住了：

```
code is /d/DevTools/AI/Alibaba/QoderCN/QoderCN/bin/code   # 坏的，排最前
code is /d/DevTools/AI/Alibaba/Qoder/bin/code
code is /d/DevTools/IDE/Microsoft VS Code/bin/code        # 正版，1.138.0，可用
```

修复（`~/.bashrc` 末尾加函数，不动系统 PATH）：

```bash
code() { "/d/DevTools/IDE/Microsoft VS Code/bin/code" "$@"; }
```

**失败尝试**：先写成 `alias code=""/d/.../Microsoft VS Code/bin/code""`，嵌套引号导致值被空格切成 `/d/DevTools/IDE/Microsoft` 与 `VS Code/bin/code` 两截而失效。教训：**路径含空格时用函数而非 alias**——alias 展开后会重新分词，引号必须写进别名的值里才安全，函数体则原样保留引号。

生效方式：当前终端 `source ~/.bashrc` 或新开终端（已实测 `bash -ic 'code --version'` 返回 1.138.0）。回滚：删掉该行。QoderCN 本身未修复，只被绕过。

### 3.4 语言命名、架构定位与设计沿袭

**命名结论**：lang-go 是**语言名**（根 README 标题「lang-go v1.0」、CLI 报 `lang-go 1.0.0`），`go/` 只是它的 **Go 参考实现**。仓库定位为"一门语言 + 三个实现"：`go/`（参考实现）、`typescript/`（独立第二实现，根 README 口径 151/151）、`python/`（实现本身 README 称 108/108 全绿并"完整能力面已对齐参考实现"）。把实现搬进 `go/` 不改变语言仍是 lang-go 的事实。

**设计沿袭**（出处：`go/docs/decisions.md` 根定位表、`go/examples/tour/main.lang-go`）：刻意混血，台账原话"白拿"——

| 来源 | 沿袭内容 |
|------|----------|
| Go | struct 值语义与方法声明、`go`/`chan` 并发原语、位运算优先级、transpile-first、函数永不染色（无 async）、转译约束反推语法面（struct/enum 必须模块顶层声明） |
| TypeScript | C 家族花括号、无分号、结构化类型 |
| Rust | enum + match 编译期穷尽检查、`Result<T, E>` + `?` 上抛、无 null 无异常 |
| 自有 | `let`/`var` 默认不可重绑、内建 JSON 与 println 等内建函数面 |

**真实差异化优点**：① 一套源码三路执行（解释器 / →Go / →JS）；② Agent 可操作（v0.4–v0.9 五个里程碑主线：稳定诊断码 + ruleId 跨实现契约、全 JSON 输出、重构禁 Regex、`fix --safe` 事务闭环、四路差分 verify、conformance 跨实现套件）；③ 确定性硬保证（同一输入四路输出逐字节一致）；④ 错误处理严于 Go/TS/Python；⑤ 全语言可被作者一人掌控。

**边界**（用户已确认的定位，decisions 根定位 #1）：个人统一工具链、不求社区采纳；性能上限 Go 级（无所有权系统，#2）；v1 明确不做包管理器/LSP/调试器（#8）；生态为零。优点只在自用定位下成立。

## 六、踩坑经验与失败尝试

1. **重命名型拉取冲突**：`pull` 报"local changes would be overwritten"但该文件不在 `git diff --name-only main origin/main` 中，说明远程把它**移动/重命名**了（--name-only 只显示新路径）；用 `git log --follow` 钉死。解法是"补丁备份 → 还原旧路径 → 拉取 → 路径改写后套用"。
2. **`git apply` 前先 `--check`**：干跑验证，避免半途失败留下半截修改。
3. **多模块仓库里 Go 命令必须进模块目录**：`go -C <dir>` 免 cd；不要被 "run: go mod init" 提示带偏。
4. **终端里 `cat > file` 交互式建文件很脆**：必须空行 Ctrl+D 收尾，中途 Ctrl+C 或回到提示符后敲代码，代码会被 bash 当命令执行（`(` 是元字符）。用 heredoc `<<'EOF'`，自动收尾且 `>` 天然覆盖半截文件。
5. **PATH shim 遮挡排查用 `type -a`**：装过编辑器分叉版（如 Qoder）会劫持 `code` 命令名；分叉版安装被移动/损坏后，其启动器在 PATH 里报 `MODULE_NOT_FOUND`。修复优先"绕过 + 别名/函数"，不动系统 PATH。
6. **shell 别名不能直接装含空格路径**：alias 展开会重新分词，`alias code=""/d/.../Microsoft VS Code/bin/code""` 这类嵌套引号会把路径切碎；用函数。

## 十、可迁移的通用经验

1. **拉取被拒先怀疑重命名**：报"本地修改会被覆盖"但该路径不在新旧提交差异里时，用 `--follow` 查移动；解法是补丁跨重命名搬运，而不是丢弃或强推。
2. **任何 patch 应用先 `--check` 干跑**。
3. **README 的构建声明要实测**：本次"三步构建 + 六条命令"逐条跑通并留存输出，才算"可行"；验证放临时目录，不污染仓库。
