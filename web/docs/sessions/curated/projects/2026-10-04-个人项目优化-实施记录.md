## 3. 验证期间揭出的共享根因

除原报告反例，既有门与独立复核揭出了以下缺口，均在原有调用链就地修复：

- **console 取消最新尝试**：同一时间创建多个 execution 时，`created_at` 不能选定最新记录。改用已有 `attempt_number`，公开 API 冻结 Date 的反例先红后绿。
- **console 备份覆盖**：毫秒名称仍可能碰撞。settings/profile 两入口均使用标准库 UUID 与排他写入；临时目录反例验证每次留备份、旧字节可恢复。恢复测试通过审计关联选择原始备份，不猜随机文件名顺序。
- **console 治理漏扫**：迁移后默认根是 console 本身，原 scanner 只读子项目。现同时扫描根和直接子项目，临时工件 Route Handler 反例与自身工件检查通过。
- **cbmini 标签碰撞**：函数前缀仍可能与 `.Lret_` 返回标签重叠。`ret` 与 `then0` 的合法程序实际组装失败，加入保留的控制流前缀后通过。
- **diffmap 快速刷新与子模块**：立即刷新可丢掉尚未防抖写入的通过标记；同 SHA 的脏子模块内容变化不会改变普通 diff 摘要。公开浏览器反例先失败，再删除防抖、对不能证明内容的条目不发可复用指纹。

这些修复没有新增任务队列、事务框架、永久资源缓存或递归子模块扫描。必要保护保留。交付前检查了本次触达的设计；可删除的保存延迟已删除，并沿用相同验收复验。
