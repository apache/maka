## 1. 双层环形饼图（NutritionPieChart.tsx）

### 思路
ECharts 同一个 option 里挂两个 pie series，`series` 数组前面的在底层。底层是 100% 单段渐变背景环，半径外扩；上层是分段数据环，半径略收，扇区之间留白线。weapp 端的 ECharts 已经支持 `echarts.graphic` 渐变（[src/subPackage/beautifulReport/components/SwipeableLineChart/index.tsx](src/subPackage/beautifulReport/components/SwipeableLineChart/index.tsx) 现成在用 `LinearGradient`）。

### 关键 option（写在 `buildOption` 内）
```ts
import * as echarts from '@/subPackage/components/echarts-taro3-react/ec-canvas/echarts';

const bgGradient = new echarts.graphic.RadialGradient(0.5, 0.5, 0.7, [
  { offset: 0, color: '#FDEFE8' },
  { offset: 0.6, color: '#F7E0E6' },
  { offset: 1, color: '#E2EAF5' }
]);

return {
  tooltip: { trigger: 'item', formatter: '{b}: {c}克 ({d}%)' },
  series: [
    {
      type: 'pie',
      radius: ['42%', '77%'],
      center: ['50%', '50%'],
      silent: true,
      label: { show: false }, labelLine: { show: false },
      data: [{ value: 100, itemStyle: { color: bgGradient, borderWidth: 0 } }],
      animation: false
    },
    {
      type: 'pie',
      radius: ['46%', '73%'],
      center: ['50%', '50%'],
      avoidLabelOverlap: false,
      label: { show: false }, labelLine: { show: false },
      data: segments.map(seg => ({
        value: seg.value,
        name: seg.name,
        itemStyle: {
          color: seg.color,
          borderColor: '#ffffff',
          borderWidth: 4
        }
      }))
    }
  ]
};
```

要点：
- 背景层 `silent: true` 不接事件，所有 hover/tooltip 走数据层。
- 背景层 `animation: false` 避免初次渲染两层动画错位。
- 不引入外部引导线标签、不画中心文字（保持现在的右侧 legend 不变，避免改 SCSS 整列）。
- `borderWidth` 调成 4 在小程序高 DPR 下肉眼分隔更明显（HTML 例子 2.5 是桌面 px）。

### 单位强制为「克」
- `pickUnit` 的兜底从 `'g'` 改为 `'克'`，并把 `segments[].unit` 直接写死 `'克'`。
- `NutritionItem` 的 `{current}{unit}` 渲染保持不动，自然就出「22.3克」。
- 类型 `MacroItem.unit` 不删（向后兼容后端口径），只是 UI 不依赖它。

## 4. 顺手复检上一轮业务逻辑

只读复检，发现风险点会同步修；目前看到的：

- AnalyseFood 的 `useEffect(... [routineData.date, customerId])`：如果后端 `parsed` 里带 `date` 字段，`setRoutineData(prev => ({ ...prev, ...parsed }))` 可能覆盖 date 触发二次拉取。打算把 merge 写成 `{ ...prev, ...parsed, date: prev.date }` 加一层保护，避免日期被远端结果改写。这是潜在死循环风险，必修。
- `handleDateChange` 依赖整个 `routineData`，每次都重建。当前不影响功能，**不动**。
- `EvaluateFood` 里 `<ActionSheet>` 包 `<AnalyseFood>`，AnalyseFood 上次已改成 ScrollView + 70vh，本次不再调整。
- `MindFood` 上一轮的 `isMountedRef / createSessionRef` 不动。
