# 预约助手技术分析文档撰写计划

## 目标与产出物

- **会议用途**：向产品、后端、测试说明当前「预约看板」前端的模块划分、数据流、与 PRD 的对应关系、接口占位与风险，便于评审排期与联调边界。
- **产出位置**：建议在 [`docs/预约助手-技术分析与设计.md`](docs/预约助手-技术分析与设计.md) 新建单文件（与现有 [`docs/预约助手PRD.md`](docs/预约助手PRD.md) 并列，便于会议材料打包）。
- **模板对齐**：按截图模板顺序组织章节，并在文首用 1 段话说明「本稿结构与公司模板字段的映射关系」，避免评审时翻页对不上。

## 章节与模板映射（写什么）

| 模板区块 | 本项目的填充策略 |
|----------|------------------|
| 标题与元信息 | 文档名、作者、创建/更新日期、关联 PRD 版本（PRD  frontmatter 中的 `generated_at` / 版本表）。 |
| 模块地图 | 中心节点写「预约助手需求」，一级分支按 PRD 的 P01/D01… 或按用户故事 US01–US06 二选一（**建议用 PRD 4.0 功能覆盖索引表**，与评审表一致）；每个模块下挂四支：**功能**（验收点）、**组件**（对应 `components/*` 路径）、**接口**（当前 Mock 与未来 REST 契约占位）、**前置资源**（设计图路径、门店/用户上下文）。可用 Mermaid `mindmap` 或文字树（Mermaid mindmap 在部分渲染器不稳定时用缩进列表兜底）。 |
| 前置资源汇总 | 从 PRD `Evidence` 与代码事实列出：原型图 [`docs/design-png/`](docs/design-png/)（PRD 已引用）、路由入口 [`src/app.config.ts`](src/app.config.ts) 中 `pages/reservationBoard/index`、技术栈（Taro 页面 [`src/pages/reservationBoard/index.tsx`](src/pages/reservationBoard/index.tsx)）、Mock 适配 [`adapters/mockReservationRepository.ts`](src/pages/reservationBoard/adapters/mockReservationRepository.ts)、模块内说明 [`README.md`](src/pages/reservationBoard/README.md)。 |
| 核心模块设计 | 建议 **2～3 个核心块** 即可，避免会议超时：**(1) 看板布局与筛选链路**（`useReservationBoard` + `useReservationFilters` + 五区展示组件）；**(2) 时间轴排班与布局算法**（[`utils/scheduler.ts`](src/pages/reservationBoard/utils/scheduler.ts) 的输入输出、与 PRD「时间轴 / 重叠展示」的对应）；**(3) 状态与操作闭环**（[`domain/status.ts`](src/pages/reservationBoard/domain/status.ts) + `ConfirmDialog` + 面板/详情弹窗）。配一张 **数据流示意**（Mermaid `flowchart`）：`selectedDate/activeTab/selectedStatuses` → 过滤 → `buildSchedulerLayout` → `Timeline`。 |
| 技术自检清单 | 逐行对照模板 7 项，用「有/无 + 一句话说明」**基于现状诚实填写**，可引用实现细节：例如多终端写「当前为小程序/Taro 页」；操作保护写「二次确认在 `ConfirmDialog`，连续点击是否需防抖可写待办」；浏览器兼容可写「以各端小程序 WebView 为准」或「不适用」并说明。 |
| 风险评估 | 与 PRD「待确认」条目对齐：Mock 与真实接口差异、PRD 中门店切换/状态筛选点击态/详情页形态与当前实现（底部面板 vs 全屏 Modal）的差异、时间轴大量卡片时的滚动与布局性能、敏感字段脱敏策略未在 PRD 定稿等。 |
| 标签 / 附件 / 评论 | 会议稿可简化为「关联文档链接」小节（链 PRD、README、测试文件 [`reservationBoard.test.cjs`](src/pages/reservationBoard/reservationBoard.test.cjs)），不必强行填空。 |

## 推荐撰写顺序（怎么开始写）

1. **只读盘点（30～45 分钟）**：通读 PRD 的 4.0 索引与 4.2 各节；对照 [`README.md`](src/pages/reservationBoard/README.md) 的目录树，标出「PRD 已覆盖 / 实现已覆盖 / 仍有差距」三列表（可直接作为文档一节「需求与实现对照表」）。
2. **画模块地图**：以 PRD 表格行为主键，每行补一列「源码锚点」（文件路径），地图自然成型。
3. **写核心模块设计**：先写文字 + 一张数据流/时序图，再补关键类型 [`types/index.ts`](src/pages/reservationBoard/types/index.ts) 与适配边界一句话。
4. **填自检清单与风险**：从对照表中的「差距」与 PRD `unknown` 行提炼，避免泛泛而谈。
5. **会议版润色**：文首 5 行执行摘要（现状、范围、未接接口、待产品确认项、建议下一步），方便主持人开场。
