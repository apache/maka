# Coding Agent 宪法与个人 Skills 精简、执行边界及跨模型适配

## 背景与目标

本次对话从用户发现个人 `ponytail` Skill 约 1066 词、担心每次加载过长开始，逐步扩展到跨工具宪法、个人 Skill 和自主执行边界的审阅、精简与维护。目标不是让 Agent “永不提问”，而是减少重复规则、过度流程和无效停顿，同时保留授权、安全、验收与真实验证。

## 最终结论

- Ponytail 的可迁移核心：先理解需求和根因，优先复用，以最小必要改动完整满足验收；简化实现，不省略明确需求、必要保护和验证。
- 宪法应写可执行的目标、边界、验收和停止条件，不把“资深专家”“第一性原理”等标签当成行为保证，也不假定某种模型预训练后会稳定执行某个口号。
- 同一套规则可供不同 Coding Agent / 模型参考，但是否加载取决于各工具的实际配置机制，效果也须按代表性任务验证。切换到 GPT-5.5 xhigh 不需要复制一份模型专属宪法；本次没有完成跨模型行为评测。
- 清理冗余不等于扩大权限。破坏性删除、数据迁移、权限变更、凭证披露、生产写入、发布等边界仍需具体授权；部分任务完成和未验证项须如实报告。

## 关键决策与已落地修改

### 宪法范围和自主执行

- 用户主目录宪法不应把一个 Windows 用户名写死；已改为“本文件所在用户主目录”，并说明相对路径以宪法文件所在目录为准。
- Codex、Claude Code、Gemini、ZCode 的个人入口复用精简后的沟通、上下文、执行、实现简化、验证和工具约定；项目内规则在项目范围适用。
- 已明确用户要求实施后，常规本地跨文件修改可在授权范围内推进，不因为复杂度重复索取方案批准；关键歧义、扩大范围及高影响操作仍先确认。
- 提问前先做不依赖答案的工作；用户纠正或中止时及时转向。不得借合理假设扩大写入、外部操作或自动化授权。
- 变更保持可回滚并保护用户已有改动；不由笼统目标推导提交、推送、发布、发送消息或持续定时任务的授权。

### Ponytail 与个人开发工作流

- 在 Codex 宪法中加入并精炼了一句话原则：先理解需求与根因，优先复用，以最小必要改动完整满足验收；只简化实现，不省略明确需求、必要保护和验证。该句可迁移为其他工具的协作原则，不需要把长篇 Skill 原文复制到每份规则。
- `helper-me` 改为按当前问题选择专题，不再将普通 Web 开发串成完整的 PRD→UI→React→API→CSS→Quality 固定流水线。
- Code Review 的五层扫描从“每次必走”改成按本次 diff、调用方和失败路径选择；要求全面审查或发现跨层影响时再完整遍历。
- 方法论名词作为检索提示，而不是模型必然执行的保证；是否保留规则依据代表性任务结果，不依据模型版本、主观印象或低触发次数。
- 消融只针对本次新增或触达的可删复杂度；没有候选就跳过，不为消融另起重构。保留必要安全、权限、兼容、错误处理、可观测性、发布控制、可访问性与明确能力。

### 验收受阻时的完成语义

已授权的小修复遇到真实测试环境阻断时，可交付可回滚补丁并标记“未完成验证”，列出已执行检查、未跑项目与继续条件；这不算验收通过，也不授权合并、发布或跳过审批。没有新证据或环境变化，不重复相同失败路径。

## 有效经验与失败尝试

- 先检查真实生效文件、别名/Junction 与目标文件名，再编辑唯一源文件；共享目录里同一路径的多个入口可能指向同一文件，不应重复编辑。
- 对规则文档做静态核对即可验证编码、读回、旧条款消除、备份和范围；这不能证明不同模型的实际行为相同。
- 一次较大的批量写入调用曾在命令执行前被额度审核拒绝，没有产生文件变化。缩小到已授权的自有文件清单后，修改成功并逐一读回验证。这属于工具执行状态，不是宪法内容的技术结论。
- 曾建议修改第三方 TDD、Grilling 等 Skill 的阻断式规则；最终按用户边界未改动它们。不要把旧的审阅建议误记成已实施修改。
- 曾提议改写自动化、目标、循环等第三方 Skill 或任务流程；这些提案未实施。不要据旧建议推断当前行为、可用工具或已创建自动化。

## 遗留问题与待验证假设

1. 未用代表性任务比较不同模型 / reasoning effort 下的越界、无故暂停、漏验收、验证真实性、耗时和工具调用；“规则能适用”不等于“行为等价”。
2. 第三方 `tdd` 仍有“测试边界必须先与用户确认”的原规则；第三方 `grilling` 仍要求穷举设计树并等待共同理解确认。它们是已知潜在摩擦点，但因不在授权修改范围内保持原样。
3. 自定义 `helper-me` 与 `mentor-me` 曾按允许目录做过澄清和阶段等待的简化；最终七文件变更集中于宪法及 `helper-me`，没有将后续对 `mentor-me` 的早期改动计划混记入本轮完成项。

## 后续建议

- 用一组固定任务做跨模型小型回归：只读分析、小型跨文件修复、会改变目标的歧义、测试环境受阻。记录是否越界、是否无故停顿、验收与验证是否真实、耗时与工具调用；据结果删改规则。
- 规则调整按“实际失败证据→最小改动→同任务复测”迭代，不因模型更新就自动删除低频安全约束。
- 项目入口保持项目专有事实、命令和契约；用户级规则只放跨项目稳定偏好。技能按触发场景加载，避免把同一流程在多份文档重复维护。
