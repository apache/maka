## 三、最终结论（方法论）

**三层性质模型**——库里有三种性质不同的东西，不能同一种方式对待：

| 层 | 内容 | 组织逻辑 | 处置 |
| --- | --- | --- | --- |
| 外部输入（01-04） | 同事交付物，按版本到达，封板后变冷 | 镜像接收方式：谁有迭代历史谁配历史汇总 | 保持不动 |
| 工作现场（05） | 本人开发区 | 产品 → 版本 | 保持不动 |
| 沉淀层（06） | 唯一的知识库原料 | 按**主题**，不按版本 | 唯一大改 |

核心原则：**资料靠归档，知识靠提炼**。原始资料价值随时间衰减，提炼出的主题笔记价值随复用增长。

**版本号=外键**：`VX.Y.Z-功能名` 命名全库统一，找"某版本的全部资料"用文件名前缀搜索（Everything/rg），不靠物理搬家关联。

**版本号重叠≠内容重复**：AxHub 构建产物与 PRD/切图文档按版本号看似双份，内容形态完全不同（互补），动手前必须内容级核实。

## 六、git 操作方案与关键命令

```bash
# 1. 收编用户的手工重组（6 万+文件级，rename detection 使 .git 不膨胀）
git add -A                 # 结果：53909 R + 8686 D + 140 A
# 2. .gitignore 补 .mimosa/（AI 工具状态不入库）
# 3. 批量迁移用 git mv（保留 rename 语义）；空目录 rmdir
git mv "06-经验总结" "06-知识库"
# 4. 删 .gitkeep：git rm 会连带删除空父目录（&& 链在此断过一次）
# 5. 全历史 squash（5→1 根提交）
git branch backup/pre-squash 9bd5b40a      # 退路
git reset --soft f72cf762                  # 回到根提交，索引保持全树
git commit --amend -F msg.txt              # 替换根提交
# 6. 验证历史重写未动内容：树哈希比对
git rev-parse "HEAD^{tree}"                # e212cbd1344ed3b5e52026b3a0406133293f586c 前后一致
```

最终提交历史：`b7710649 feat(web): 初始化个人开发知识库`（唯一根提交）；备份分支 `backup/pre-squash` → `9bd5b40a`。

## 七、踩坑与失败尝试

1. **AI 工具状态入库**：init 提交吞了 8,500+ 个 `.mimosa/` hook-state 文件（与 maka 仓库同款坑）。修复：`.gitignore` 补 `.mimosa/`。
2. **README 失真**：结构改完不改 README，AI agent 和新人都被误导。修复：重写根 README + 06-知识库 README（沉淀流程+上浮索引表）。
3. **版本号重叠误判为重复**：批准的是"删版本迭代侧副本"，核实为互补后改移动。教训：**破坏性操作前必须内容级核实，版本号相同≠内容相同**。
4. **`git rm` 连带删空父目录**导致 `&&` 链中途失败：遇到后先 `git status` 看断点现状再续，不要盲目重跑整条链。
5. **CRLF 警告无害**：`.gitattributes` 设了 `* text=auto eol=lf`，add 时的大量 CRLF→LF 警告是预期行为。
6. **4.2GB 二进制入库是沉没成本**：`.git` 已 2.0GB，不值得重写历史；止血方案是**今后 AxHub 新版本以 zip 归档不入库**。

## 十一、可迁移到其他项目的通用经验

1. **冷热分离**：知识库 99% 体积往往是冷归档（构建产物/设计导出），与热知识（md 笔记）分开机制对待；git 只管热知识和轻量文档，大体积归档走 zip/独立存储。
2. **命名即外键**：统一的 `VX.Y.Z-功能名` 命名让跨目录关联靠搜索完成，避免为"聚合"而物理搬家。
3. **三层模型**：外部输入（镜像接收方式组织）/ 工作现场（按产品→版本）/ 沉淀层（按主题）；沉淀层只进"下个项目还会用"的东西。
4. **沉淀流程**：版本封板 → 上浮可复用件（保留来源前缀做双向溯源）→ 版本私有件留档案区。
5. **结构变更必须同步 README**，否则文档就是谎言。
6. **破坏性操作三步走**：内容级核实（版本号相同≠重复）→ 优先移动而非删除 → git rename 兜底可回滚。
7. **历史重写双保险**：先建备份分支，后用树哈希（`HEAD^{tree}`）证明内容零变动。
8. **AI 工具状态目录（.mimosa 等）必须在项目 init 前写进 .gitignore**。
9. **脚本会复活被废弃的结构**：废弃目录约定时同步处理生成脚本。
10. **Windows Git Bash 大仓库操作**：`git add -A` 6 万文件/4.2GB 设长超时可行；rename detection 使纯移动的 commit 零 blob 增量；`git -C` 或直接 cd 均可（本仓库无 maka 的 fnm 钩子问题）。
