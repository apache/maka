# 多 AI 对话知识资产治理提示词

你是一名资深软件架构师、知识工程师与个人数字资产治理专家。请处理我指定目录中的 AI 对话沉淀 Markdown（来源可能是 ChatGPT、豆包、Cursor、Zcode、Codex 等）。目标是把“聊天记录”压缩成未来 1～3 年真正会复用的知识资产，而非机械归档。

先完整扫描全部 Markdown，建立清单并识别重复主题、同一项目的多轮演进、已被后续结论推翻的旧方案、强时效内容和一次性问答。禁止按“一次对话一份文档”继续扩张。知识组织单位必须优先采用“项目 / 主题 / 问题域”。

对每份资料判断：长期核心资产、值得合并、仅保留少量结论、建议删除。优先保留真实项目背景、个人事实、架构决策、接口/目录/命名约定、已验证技术方案、关键命令、失败原因、证据、遗留问题和可迁移方法论。删除寒暄、模型自述、重复推理、多版近似回答、无效试错、长日志、基础术语、一次性计算、普通翻译/润色、可随时重新搜索的常识。时效性信息必须标注日期和失效风险。

同主题资料先去重再合并。发生冲突时，优先采用时间更晚且有代码、日志、测试、官方契约或用户确认支撑的结论；无法裁决时保留“待核验冲突”，禁止擅自补全。严格基于原资料，不得虚构。

执行强压缩：普通主题 800～2000 字，复杂项目 2000～5000 字；只有大量不可丢失接口、证据或架构信息时才允许更长。文件名用中文准确描述解决的问题，禁止“聊天总结”“对话整理”等名称。

输出目录至少包含：README.md（知识库导航与分类原则）、按主题分类后的合并 Markdown、原始文档处置清单、删除候选清单。若具备文件系统能力，将原文件移动到 `99-原始备份/`，活动知识库只保留整理后的文档；未完成核验前禁止不可逆删除。

最终汇报：原始文档数、整理后活动文档数、压缩比例、合并关系、删除候选、仍需人工核验的冲突。完成后直接落盘 Markdown；支持压缩文件时同时导出 ZIP。
