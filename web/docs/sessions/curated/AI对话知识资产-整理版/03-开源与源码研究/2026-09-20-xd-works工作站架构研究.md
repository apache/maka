### 2. 最终结论（一句话版）

**xd-works = 用确定性状态机（Controller）调度多个 AI 会话（Architect/Implementer/Reviewer），按「设计 → 实现 → Review⇄Repair → 受管交付 → 收尾」推进单个 Issue，全程以结构化报告 + exact-HEAD 证据 + 回执为纪律的本地开发工作站。工程上不能直接接 maka（缺 Gate/交付基础设施且合并权在上游），但方法论可立即搬运。**

### 1. 问题背景与目标

- 用户长期在 apache/maka 做 issue/PR 贡献（手工接单流：`take` 认领 → 分析 → 修复带红测 → 验证矩阵 → 开 PR），群主在群里开源了「最近搞的 issue 开发工作流」——xd-works，用户想快速了解这个项目与自己的工作有何关系。
- 明确要求：调用 `mentor-me` / `helper-me` / `writer-me` 三个 skill，在 `E:\guahub\gh\open\aigc\gaoxiaodiao__xd-works\docs\` 写 7 篇文档，每篇不少于 3000 字。

### 4. 关键决策与执行过程

1. **先收事实再写**（writer-me「写作前先收事实」）：通读 controller.ts 骨架、types.ts、control-state.ts、review-policy.ts、archive.ts、handoff.ts、reporter-tool.ts、agent-runner.ts、control-inbox.ts、issue-stop.ts、talk.ts、escalation.ts、finalization-session.ts、github.ts 及全部配置/合同/监督手册。所有文档规则表从**校验代码**抽取而非抄提示词（提示词与代码双源时以代码为准）。
2. **7 篇选题由浅入深**：01 总览（为什么做）→ 02 概念词典 → 03 生命周期走读 → 04 提示词与结构化报告 → 05 Review 判级与分流 → 06 证据与恢复 → 07 接入成本核算与借鉴清单。
3. **三 skill 分工**：mentor-me 提供讲解骨架（一句话定义、工地/快递类比、误区点破、maka 场景对照）；helper-me 提供方法论钩子（状态机、单一可信来源、契约先行、对抗式审查、清场、最后写入获胜）；writer-me 管文风纪律（无填充语、无「综上所述」、表格优先、路径可核验）。
4. **接 maka 的核算结论**：适配器能写出来但无意义——`deliver/finalizeDelivery` 会退化成「开 PR+记台账」（合并权在 maintainer，流程终点是 PR 等复审而非 merge），状态机后半段架空。**方法论搬走，工程不硬接**。

### 6. 失败尝试与踩坑

- **sed 处理 Windows 反斜杠路径报错**（`unterminated 's' command`）：列文件清单改用 `cd /e/... + find` 相对路径写法。
- **字数口径踩坑**：首写完成后按「去空白总字符」统计（5000-6600/篇）看似达标，但按 Word 口径（中文字符+英文单词）复算发现仅 2600-2950/篇贴线。补救：每篇增补一节有真实依据的内容（01 补首次配置走读与流派对比、02 补配置三件套逐字段、03 补 adoption 岔路、04 补 worker-system 开场纪律与 main-chat 话路、05 补 reviewStartRound 轮次算术、06 补会话快照机制、07 补最小跑通路径），二次校验全部 ≥3000。**教训：中文写作任务的字数验收要先和用户对齐口径，且首轮就按严格口径自检。**
- **本机环境惯例**（沿用既有约定）：`cd` 进仓库触发 fnm 钩子，git 操作用 `git -C`；后台命令输出落文件。

### 7. 可迁移到其他项目的通用经验

1. **原子写状态文件**：任何脚本写 JSON 状态都用「临时文件 + rename」，永不出现半个文件。
2. **证据加 tuple 头**：测试输出/验证记录带上「commit SHA + 分支 + 时间 + 命令原文」，专治「记得跑过但不知是不是这个提交」。
3. **断言分级**：「我修了」（claimed）与「在明确 SHA 上复核通过」（verified）分开表述，防跨会话记忆漂移。
4. **五路自问**：被卡住时归类——自己能干/走流程能解决/在等外部/缺授权/真需他人拍板；多数「等回复」是第一类。
5. **verdict 推导式自查**：结论必须从明细推导（有 P0 级问题就不能写「基本可以」），结论与明细自洽是免费质检。
6. **handoff 五问进 PR/交接文档**：修了什么、证据在哪、现场状态、信息缺口（没验证什么+为什么+怎么补）、下一步。
7. **多轮失败才升级**：给换策略定硬触发（如三轮不收敛），不凭挫败感决策。
8. **事实层/派生层分层**：索引文件自带边界声明（「本索引是派生物，以条目为准」），且随事实重算而非手改。
9. **拒绝消息要教学式**：打回时附「怎么改才对」，一步到改正。
10. **契约先行管 LLM**：提示词每条硬要求配一条代码校验；权限靠配置物理隔离，提示词只负责解释。
