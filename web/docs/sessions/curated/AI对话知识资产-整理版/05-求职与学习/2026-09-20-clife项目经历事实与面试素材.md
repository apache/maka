面试宝典（`E:\guahub\docs\temp\面试宝典\`）中三篇文档——`06-个人材料/14-关天豪-clife-AI项目经验-草稿.md`（简历草稿）、`07-AI智能体学习地图/01-四周精读与vibe计划.md`、`07-AI智能体学习地图/02-同事智能体代码精读素材.md`——含有大量可证伪的硬声明：文件行号/行数、提交数、代码归属（谁写的）、路径、后端契约。其中 2026-09-06 那轮取证的部分结论是错的。本次任务：以 `E:\Projects` 真实代码与 git log 为唯一事实源，逐条取证并修订，修正错误、补缺口，不重写文档结构（writer-me 技术文档模式 + ponytail 最小 diff）。

### 三、关键决策与工作流

1. **按仓库域拆三路并行 Explore agent 取证**（① SC 内核+Sidebar+baseUrl；② advisor+企微+brand；③ workbench+后端+个人资产），每条声明要求"声明→实际（命令+证据）→判定→修正建议"裁定表；主 agent 只做定点补查与最终编辑。
2. **主 agent 对翻案级结论必须亲自复核**：预约看板归属、A 仓 git 可用性、BottomSheet 存在性、relationType 五类、brand 提交触及文件、mock-gateway 定位，均由主 agent 用 rg/git 二次钉死后才写进文档（agent 报告确实有一处错报，见下）。
3. **修订策略**：错误事实段→删除并留一行"勿引用"警示（保留勘误痕迹供溯源）；正确但粗糙的声明→行号精化；归属表→全部改为 git 复核口径；文档头部与 frontmatter `updated` 同步标注复核日期。
4. **归属取证命令包**（可复用）：
   - 作者分布：`git -C <repo> log --format="%an %ae" | sort | uniq -c | sort -rn`
   - 单文件归属：`git -C <repo> log --follow --format="%an %ae" -- <file> | sort | uniq -c | sort -rn`
   - 提交计数双口径：`git -C <repo> log --author=802165 --oneline | wc -l` 与 `--author=关天豪` 各跑一次
   - 路径过滤计数：`git -C <repo> log --author=802165 --oneline -- <path> | wc -l`
   - 提交信息检索：`git -C <repo> log --all --oneline --grep=<关键词>`
   - reflog 写入者（≠commit 作者）：`git log -g --format="%gn %ge" | sort | uniq -c`
   - 用户提交触及面：`git log --author=802165 --name-only --pretty=format: | grep -v '^$' | cut -d/ -f2-3 | sort | uniq -c | sort -rn`
   - Windows 注意：git 一律 `git -C "路径"`，不 cd 进仓库（fnm 钩子截断 && 链）。

### 四、失败尝试与踩坑

- **".git 损坏"是环境故障误报**：上一轮取证据此写下"无法确证归属"+ 一批错误归属。教训：git 报 fatal 先怀疑本机环境，重试后下结论；环境恢复后旧勘误要主动翻案。
- **reflog ≠ 作者**：838 条 reflog 中 835 条写入者是用户，但这只证明"在仓库工作过"；`%an` 统计的是 commit 作者，`%gn/%ge` 才是 reflog 写入者，两套口径不能混。
- **Explore agent 错报一例**：agent 2 报告"brand 无 BottomSheet 组件"，实际 `src/aiAgentPackage/aiAgent/components/BottomSheet/` 存在且是用户提交范围——主 agent 定点抽检拦住了这个错误进文档。
- **单仓零命中 ≠ 不存在**：rg 在 workbench 找不到预约看板组件时，正确动作是换仓搜（最终在 advisor 仓全数命中），而不是直接判"组件不存在"。
- **Edit 工具两坑**：必须先 Read 再 Edit（system-reminder 里出现过的内容不算）；old_string 必须逐字匹配——02 的列表顺序与预期不符导致一次替换失败，重读局部后再改。
- **文档-代码漂移实例**：ai-audio-editing-node-bff README 仍写旧接口名 `/n/jobs`，代码已是 `/internal/audio-edit/jobs`——双源冲突以代码为契约。
