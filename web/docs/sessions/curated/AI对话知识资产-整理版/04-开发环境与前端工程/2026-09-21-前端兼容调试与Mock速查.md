### 来源：CSS属性低版本安卓WebView兼容性复盘.md

### 核心结论

1. `order`：Flex/Grid基础属性，**不属于高级属性**，兼容性最好；Android4.4及以上原生支持，仅古董Android4.3及以下需要旧webkit前缀。
2. `gap`：进阶布局属性，**分场景兼容差异巨大**
    - Grid的gap：Android7.0+支持，低版本可写`grid-gap`兜底
    - Flex的gap：Chrome84才支持，仅Android10+可用，Android9及以下完全失效
3. `inset`：**高级简写属性**，Chrome89才支持，Android11及以上才识别；Android10及以下直接忽略该属性，不能直接使用。

### 背景与问题

项目需要适配低版本安卓手机WebView，需要确认3个CSS属性兼容性：`order`、`gap`、`inset`；并区分它们是否属于高级CSS属性。

### 有效方案

1. **order**：交给Autoprefixer自动补全前缀，无需手动维护。
```css
.item {
  -webkit-box-ordinal-group: 5;
  -webkit-order: 5;
  order: 5;
}
```

1. **gap**
   - Grid布局：同时写`grid-gap`和`gap`兜底
   - Flex布局：放弃gap，用`* + * { margin }` + 容器负margin模拟间距
2. **inset**：不使用简写，降级手动写四条定位属性

```
/* 不兼容低安卓 */
.box { inset: 0 10px; }
/* 兼容兜底写法 */
.box { top:0; right:10px; bottom:0; left:10px; }
```

### 踩坑与错误认知

❌错误认知：`order/gap/inset` 是同一级别的高级CSS属性。 ✅纠正：三者兼容性差距很大，`order`是flex基础属性，兼容性很强；`gap`要看布局类型；`inset`简写兼容性最差。

❌踩坑：直接在Flex布局中使用gap，在Android9及以下机型间距完全不生效。

### 后续建议

1. 项目打包配置autoprefixer，按目标最低安卓版本配置browserslist；
2. 针对老旧安卓机，Flex间距统一用margin方案，不要依赖gap；
3. 定位样式禁止直接写inset简写。

```
> 文件名称：`CSS属性低版本安卓WebView兼容性复盘.md`
> 内容说明：提炼H5移动端适配老旧安卓WebView时order/gap/inset三个css属性的兼容边界、降级方案，可作为前端开发笔记长期检索复用。
```

### 来源：荣耀100 Pro MagicOS升级后APP沉浸式状态栏顶部遮挡问题排查与解决方案.md

### 核心结论

该问题是MagicOS系统更新重置了挖孔屏沉浸式适配规则，`自动匹配`模式在新版本下对部分第三方APP适配逻辑出错，APP页面直接全屏顶到屏幕最顶端，造成APP标题UI与系统状态栏重叠。 **最优修复方案：对出现故障的APP单独设置为【显示顶部区域】，强制预留状态栏高度，APP界面整体下移，避免重叠。**

### 背景与问题

1. 设备：荣耀100 Pro，MagicOS系统版本升级后出现显示异常；同版本安卓其他同事设备无该故障。
2. 故障现象：第三方录音剪辑APP（闪记音频编辑页面）界面顶栏文字直接和系统状态栏（时间、WiFi、电量、信号图标）重叠，状态栏内容完全看不清；手机桌面、系统自带应用显示正常。
3. 系统自带适配选项：屏幕顶部显示，包含3个模式：**自动匹配、显示顶部区域、隐藏顶部区域**，APP默认是自动匹配模式。
4. 用户诉求：解决APP界面覆盖状态栏问题，并提炼方案，生成可投喂给ChatGPT的专业提示词。

### 有效方案（按优先级排序）

1. 【首选方案】单应用适配修改 设置 → 显示和亮度 → 更多显示设置 → 屏幕顶部显示 → 在应用自定义列表找到故障APP → 选择**显示顶部区域**。
2. 【备选方案】修复系统UI缓存（修改适配后无效时使用） 设置 → 应用 → 应用管理 → 搜索`系统界面` → 存储 → **清除缓存（禁止点清除数据，避免重置桌面）**，清理后重启手机。
3. 【分辨率异常修复】全局所有界面状态栏裁切时使用 设置 → 显示和亮度 → 屏幕分辨率 → 关闭智能分辨率，手动切换高分辨率，重启手机。
4. 【冲突排查】悬浮窗叠加遮挡 设置 → 应用 → 权限管理 → 显示在其他应用上层，临时关闭第三方悬浮权限测试。
5. 【终极方案】重置所有设置/更新系统补丁
   - 重置所有设置：设置 → 系统和更新 → 重置 → 重置所有设置（不会删除照片文件，重置壁纸、显示等系统参数）
   - 检查系统软件更新，安装官方MagicOS修复补丁。

### 踩坑与错误认知

1. ❌ 误区：选择「隐藏顶部区域」解决遮挡。 ✅ 说明：该选项只是增加顶部黑边，浪费屏幕空间，不是真正修复UI重叠，不推荐。
2. ❌ 误区：全局把所有APP改成「显示顶部区域」。 ✅ 说明：仅单个APP故障时，只修改目标APP即可，全局修改会让其他支持沉浸式的APP失去全屏效果。
3. ❌ 误区：直接清除系统界面数据。 ✅ 说明：清除数据会重置桌面布局，只需要清除缓存即可。

### 后续建议

1. 修改APP适配选项后，立刻打开APP验证效果。
2. 如果后续多个APP陆续出现同类遮挡，可考虑全局修改屏幕顶部显示默认选项。
3. 持续关注MagicOS官方系统更新，这类沉浸式适配bug一般会在后续小版本补丁修复。
4. 遇到同类安卓挖孔/屏下状态栏适配问题，可直接复用本套排查流程。

### 来源：Whistle拦截HTTPS接口并返回本地自定义JSON配置方案.md

### 核心结论

1. whistle中**Mock返回Values面板内文件，使用`file://{文件名}`语法**，`resWrite://`是保存响应，不能做Mock返回。
2. HTTPS接口拦截必须开启whistle HTTPS捕获、安装信任根证书，否则规则对HTTPS请求不生效。
3. SwitchyOmega负责把浏览器流量代理转发到whistle服务。

### 背景与问题

开发调试场景：使用 whistle（10.6.33.85:8899）+ SwitchyOmega 做前端接口Mock，需要拦截HTTPS接口`[https://itest.clife.net/v1/homing/system/web/employee/page-list](https://itest.clife.net/v1/homing/system/web/employee/page-list)`，返回在Values面板预先建好的`test.json`自定义返回数据。 当前错误配置：使用`resWrite://`，该指令作用是**把原始接口响应保存到本地**，并不是拦截并返回本地JSON；同时页面提示HTTPS隧道流量未开启，HTTPS请求无法正常拦截。

### 有效方案

1. Values面板：新建`test.json`，粘贴接口预期返回的完整JSON。
2. Rules规则编写（Default分组）

```
[https://itest.clife.net/v1/homing/system/web/employee/page-list](https://itest.clife.net/v1/homing/system/web/employee/page-list) file://{test.json}
```

1. HTTPS配置（必做）
   - 点击顶部`HTTPS`按钮，下载并安装whistle根证书，系统信任证书。
   - 勾选`Capture Tunnel Traffic`（捕获隧道流量）。
2. 保存规则：点击顶部`Save`，确认左上角ON开关打开。
3. 代理：SwitchyOmega配置代理指向`10.6.33.85:8899`，浏览器启用该代理。
4. 验证：刷新页面触发接口，在whistle Network面板查看请求响应是否替换为自定义json。

### 踩坑与错误认知

1. ❌ 错误：使用`resWrite://`做mock返回 ✅ 纠正：resWrite是**保存响应**，不是返回本地文件，无法实现接口mock。
2. ❌ 忽略红色HTTPS警告，不安装证书 ✅ 纠正：HTTPS请求不开启Capture Tunnel Traffic、不安装根证书，rules规则不会生效。
3. ❌ 文件名大小写/后缀写错，`file://{}`内文件名必须和Values文件名完全一致。

### 后续建议

1. 可以把该规则导出备份（Export），后续开发同项目接口调试直接Import复用。
2. 多接口Mock时，可以在Values分类存放多个json响应文件，在Rules写多条对应拦截规则。
3. 校验JSON格式，可使用在线JSON校验工具提前检查，避免whistle返回解析异常。

### 来源：VS Code全局搜索正则：精准匹配top，排除padding-topmargin-top.md

### 核心结论

1. `\b`单词边界在连字符场景存在匹配特性：`-`属于非单词边界字符，`padding-top`内`top`两侧是`-`，`\btop\b`本身就不会匹配`padding-top`；如果搜不到结果，代表**当前目录代码里根本不存在独立的`top`单词**，不是正则写错。
2. VS Code支持JS风格的零宽断言`(?<!-)`负向后行、`(?!-)`负向先行。
3. 有两种思路：①直接找独立`top`；②保留所有含`top`结果，在排除框过滤掉`padding-top/margin-top`（更常用）。

### 背景与问题

在VS Code全局搜索SCSS文件，搜索关键词`top`时，会大量命中`padding-top`、`margin-top`这类连字符拼接属性；需要编写正则，**只匹配独立的`top`**，不匹配`xxx-top`/`top-xxx`组合。尝试`(?<!-)\btop\b(?!-)`正则后搜索无结果。

### 有效方案

### 方案1：搜索独立CSS属性 top:

```
(?<!-)top\s*:
```

> 用途：只匹配CSS属性`top`，如`top:10px`，排除`padding-top`/`margin-top`。

### 方案2：全局匹配独立top文本（变量、CSS通用）

```
(?<!-)top(?!-)
```

> 用途：匹配任意独立`top`文字，左右不能带横杠`-`。

### 方案3（推荐，最常用）：保留所有top，过滤padding-top/margin-top

1. 搜索框直接填写：`top`（不开启正则）
2. 下方【排除的文本】框填入正则：

```
(padding|margin)-top
```

> 效果：展示所有包含`top`的代码，自动剔除`padding-top`、`margin-top`，适合批量查看。

### 踩坑与错误认知

1. ❌ 错误认知：正则失效。实际是**项目代码没有独立`top`属性**，过滤后结果为空，不是正则bug。
2. ❌ `\b`单词边界坑：`(?<!-)\btop\b(?!-)` 语法没问题，但`\b`对`-`边界判断容易造成预期之外无结果，优先去掉`\b`使用`(?<!-)top(?!-)`。

### 后续建议

- 优先使用方案3，排查项目中所有`top`相关样式；
- 如果需要专门查找`top:`定位布局属性，使用方案1。
