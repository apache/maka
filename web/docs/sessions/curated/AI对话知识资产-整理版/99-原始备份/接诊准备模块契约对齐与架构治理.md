## 一、背景与目标

- 后端（耿耀）对 BFF 做了破坏性调整：接口路径加前缀 `/v1/beautycamp/workbench`，`cardTypeList` 与卡片 `cardType` 枚举值从大写下划线改为小驼峰；前端需要一次性对齐。

## 四、架构与数据链设计（当前形态）

### 设备条双组件

## 六、排查方法论与踩坑（可迁移经验）

1. **旧 bundle 判定法（字符串标记）**：怀疑页面跑旧代码时，`fetch` 页面实际加载的 chunk 并搜索本次改动独有的字符串字面量（如新路径、新枚举值）。实测曾出现「分包 chunk 是新代码、主包 app.js 是旧编译产物」的混跑态——根因是 dev server 内存供包的部分重编译失效，重启 dev server 解决。判断「页面为什么这样渲染」先证明它跑的是哪版代码。
2. **IDE 与 CLI 的 TS 差异**：IDE 用新版 TS（报 ts2345 strictNullChecks），项目锁 TS 4.2.3 的 CLI 即使开 strictNullChecks 也可能不复现。结论：IDE 标红为准，修复取「删除调用点」这类任何版本都干净的方案。
3. **eslint warning-as-pass 漏洞**：`no-unused-vars` 是 warning 级，退出码 0 的 `&& echo PASS` 会放行带伤文件。统一改用 `--max-warnings 0`，靠它抓到了 `closeEvidence` 未接线（抽屉关闭会 ReferenceError）。
4. **重构旧文件前先确认基线**：temp 里用户昨天的实现是从旧版页面改的（含已废弃的 ARCHIVE_PENDING、已改名常量）——整文件照搬会静默回退已提交的决策。正确做法：只提取有效 delta 打到当前 HEAD 上。
5. **「死代码」判断要复核**：原始组件解构的 `is4GProduct` 在该 JSX 里确实没用，但它是 hook 为同需求预留的 API；后来修 ts2345 时正确解法恰恰是改用它，而不是删掉再从分包引工具函数。
6. **编译期开关是复杂度放大器**：LOCAL_MOCK/API_MOCK 双通道（脚本+注入+常量+baseUrl 分支+专用代理规则）最终全部删除，只留 URL 参数——数据源调试只需要运行时开关。
7. **行为测试跑 node 的关键**：TS 源码用 `--experimental-strip-types` 直跑，但 `@/` 别名与无扩展名相对导入需自写 ESM resolve 钩子（探测 .ts/.tsx/index）；宿主依赖（store/Taro）用「手写桩文件 + resolve 重定向」比万能 Proxy 靠谱（named import 需要静态导出）。源码里值导入类型（`import { GlobalDataType }`）要改 `import type`。
8. **工具细节**：`rg -rn` 的 `-r` 是 replace 会吞匹配文本；CRLF 文件用 python 替换需行尾自适应；prettier --write 后再 Edit 会报 modified-since-read。
