## 核心沉淀

- Windows + 微信 4.1.13 的本地情报库链路已经完成数据库读取、派生校验、索引和群聊精选站生成。

### 三、最终结论

**全链路已打通**：reader doctor `ready`、27 个库全部解密（27/27 HMAC 校验通过）、原生消息 646,599 条、情报库 radar.db 索引 393,205 条（2021-02-24 → 2026-09-07，291 会话、71,399 链接、1,166 商机对象）、旗舰 HTML 日报与群聊精选站均可浏览。剩余缺口：索引 387,840 条 < 原生 646,599 条（去重+噪声过滤+大聊 5 万条/聊上限所致，原生数据仍完整可读）；Profile 个性化材料（个人说明/本月计划）待用户提供。

### 一、问题背景

用户希望把本机微信聊天记录变成可检索、可出日报的"个人情报库"，选用开源项目 `Rion-Wu-tech/wechat-intelligence-hub`（含只读 Reader `rion-wechat-cli` 与情报引擎）。核心障碍：微信 4.1.13.12 的本地数据库是 SQLCipher 加密的，而公开的密钥提取工具生态在 2025-10 后被腾讯法务清扫殆尽（wx_key 被 DMCA、chatlog 作者收函自删、wechat-dump-rs 被 GitHub 451、PyWxDump 删库）。上游项目只测过 macOS，Windows 全链路需要自行适配。中期用户导入 12GB 外部聊天记录，数据规模从 2.9 万条暴涨到 64.6 万条。后期用户要求参照"麦田精选"（群成员李小麦的人工月度精选：成员排行榜+文章分享榜）建立独立的群聊精选系统。

### 四、关键决策（按时间序）

1. **安装布局沿仓库设计**：装到 `~/.codex`（skills + share + bin），Windows 上不重建结构，只打兼容补丁。
2. **密钥路线三选一**：静态内存扫描（四条路线全败）→ 社区 fork 特征码 + Hook 捕获（成功）。放弃不可审计的二进制（WeChat_Key_New 只有 LICENSE、chatlog-plus 核心无源码）。
3. **免编译补丁**：不装 MSVC，对已审计的 wx_key.dll 直接打 **23 字节数据补丁**（特征码 6×imm32 + 掩码 2 字符），PE 结构/导出/导入零变化，SHA256 重新固化进驱动。
4. **主密钥 vs 库密钥的关键区分**：Hook 抓到的 32 字节是**主密钥**，不是任何库的直连密钥。每库密钥 = PBKDF2-HMAC-SHA512(主密钥, 该库文件头 16 字节盐, 256000, dklen=32)。曾因拿主密钥直接开库而全盘误判"密钥不对"。
5. **多账号只接一个**：目标账号 `wxid_lskjg2rhnpw512`（另有 wxid_qqcykmj1p96t12 未接入，不混读）。
6. **精选系统独立成站**：不动旗舰日报，期数化单文件 HTML；计分公式直接采用李小麦群公告版本（综合分 = 0.3×发言分 + 0.7×质量分；发言分 = min(100, 发言数/P75×100)；质量分 = AI 编辑判读）。
7. **语义编辑层不可省**：`render-bundle` 只认语义编辑后的分区文件（final_report.md、group-daily/*、contact-daily/contact_daily_brief.md，规则在 report_bundle_flagship.py 的 SOURCE_RULES），机器初筛直接渲染 = 空白页。编辑由 Agent 按 `skills/wechat-intelligence-hub/references/group-editorial.md` 规范完成。

### 五、架构设计（数据流）

```text
微信 4.1.13.12（登录中）
  └ Documents\xwechat_files\wxid_lskjg2rhnpw512_4fbc\db_storage\  ← 27 个 SQLCipher 库
       │ ①一次性密钥接入（主密钥捕获 → 逐库派生 → keys.json 0600）
       ▼
rion_wechat_reader.py（只读 CLI，30 工具；快照复制→PRAGMA key→query_only）
       │ ②db-index：会话/搜索 → radar.db（SQLite+FTS5）
       │ ③group-daily / contact-daily：机器初筛（读活库快照，不经 radar.db）
       ▼
语义编辑（Agent 按规范产出 final_report.md、group-daily/、contact-daily/ 分区）
       ▼
render-bundle（pandoc）→ wechat_daily_report.html（旗舰日报）
群聊精选站：tools/gen_jingxuan_site.py → 精选\群聊精选.html（单文件，期数导航+群筛选）
```

密钥捕获链（微信重启时才触发）：
`wxkey_driver.py wait` 模式 → 忽略旧进程、等新微信主进程（以加载 Weixin.dll 为特征）→ 调补丁版 DLL `InitializeHook(pid)` → shellcode 在密钥函数（RDX={+8 密钥指针, +0x10 长度=32}）被调用时把 32 字节拷入共享内存 → 驱动轮询取走 → 校验 64hex → 写 keys.json 的 `"*"` → 再由派生脚本重写为逐库条目。

### 九、有效方案及原因

1. **数据补丁替代重编译**：特征码/掩码是编译进 DLL 的数据（6×imm32 + 字面量），补丁 23 字节即可切换版本适配，省掉 MSVC 全套工具链。
2. **离线唯一命中验证**：特征码可信度不靠 fork 声誉，靠"在本机 Weixin.dll 上恰好命中 1 处 + 旧特征码 0 命中"的地面真值。
3. **纯 Python 页级 HMAC 校验**：免去逐候选开库（3ms→10µs 量级），是候选矩阵扫描可行的前提。
4. **wait 模式驱动**：密钥只在登录开库瞬间流过，等待新进程 + 登录窗口的时序设计把"用户配合"降到一次重启。
5. **编辑层独立于机器初筛**：机器初筛管召回，Agent 编辑管可读性与人工判断（含误判点名，如订餐群被标"商单/推广"）。
6. **单文件内嵌数据站**：无服务器、file:// 直接开、期数/群筛选纯客户端。
