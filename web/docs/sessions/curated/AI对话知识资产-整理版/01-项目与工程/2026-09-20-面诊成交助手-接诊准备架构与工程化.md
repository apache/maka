### 有效方案

- **COS 上传**：skill 的 `upload-homing-cos.mjs` 强制 HOMING_TOKEN；本地兜底密钥已失效。可用方案是自写脚本走 STS 临时密钥（`TENCENT_COS_TEMP_KEY_URL` + 员工 token），**签名必须包含 `x-cos-security-token`**（只签 host 会 403 SignatureDoesNotMatch）。HOMING_TOKEN 由用户提供，仅在单命令环境变量中流转，不落盘。
- **Figma API 拉图**：token 在原型项目 `.env.local`；`GET /v1/images/:key?ids=...&scale=2` 导出帧图，`GET /v1/files/:key/nodes?ids=...&depth=N` 拉结构树；帧树对比用"本地已导出帧 id 集合"做基线找新增。
- **Taro button svg**：H5 构建下 `.svg` 被 `@svgr/webpack` 转成 React 组件（icon 模式），必须直接 import 当组件渲染，绝不能当 URL 传给 ImageWebp/Image。
- **ImageWebp 对 svg 的渲染**：跳过 webp 参数后 `ImageWebp` 可正常渲染 svg URL。

### 一、问题背景与目标

`src/subPackage/receptionPrep`(面诊成交助手/接诊准备)是新开发的子包,交付前存在四类问题:

1. 代码格式不统一、导入顺序不合规、存在未使用导入/死代码;
2. 孙级组件平铺在父组件目录根部(如 `CustomerPlan/ProjectMatrix.tsx`),公共/私有边界模糊;
3. 组件函数参数使用内联类型(`function X({ item }: { item: T })`),IDE 插件报 `typing-function-paramaters`,且与模块内 `interface Props` 风格不一致;
4. 真实顾客上下文访问卡片页/详情页时,客户姓名旁不显示编辑图标(用户报障)。

目标:格式全绿、目录层级符合约定、类型声明规范化、编辑图标对真实顾客可见。

### 三、关键决策与理由

| 决策 | 理由 |
| --- | --- |
| 孙级组件包一层,不平铺 | 平铺让父组件目录根部混入私有子件,「哪些可对外复用」变模糊;包一层后 `<子组件>/index.tsx` 是唯一公开面。项目里 `deviceCenter` 已有 `components/components/` 先例 |
| 孙组件 scss 统一重命名 `index.module.scss` | 与全模块组件目录结构一致(CSS Modules 按导入的 styles 对象取类名,改文件名无行为影响) |
| Props 接口按组件命名(`WaveformCardProps`、`CustomerPlanProps` 等),禁用同名 `interface Props` | 同文件多个同名 interface 会声明合并,把所有组件的 props 混进一个类型,且不报错 |
| 编辑图标:去掉 `preview ? ... : undefined` 门控,恒传 `onEdit` | CustomerSummary 仅在 `onEdit` 存在时渲染图标;编辑器只改页面本地状态,mock 阶段与 preview 无关,门控是历史遗留 |
| `imageWebp/index.tsx` 的 CRLF 不处理 | 该文件在 HEAD 中就是 CRLF 存储,强修会变成整文件 diff 的共享组件改动,收益为负 |
| tsc 全量 1462 个报错不修 | 全部位于 node_modules(项目 tsconfig 未开 skipLibCheck 的预存依赖噪音),只以 `grep -v node_modules` 后的 src 结果为验收口径 |
| `typing-function-paramaters` 规则虽不在项目内也照修 | 规则来自用户 IDE 插件(CLI 不可复现),但指出的问题真实存在且与代码库风格冲突 |

### 八、失败尝试与弯路

- `npx eslint` 直接跑崩溃(get-intrinsic 加载链失败),换本地 bin + 环境变量后才稳定;中途又踩 `react-hooks/exhaustive-deps` 崩溃,最终定型为「本地 bin + DISABLE_V8_COMPILE_CACHE + exhaustive-deps:off」三件套。

### 问题背景与目标

- 用户在审查暂存区（git staged）改动时发现遗漏了一处按钮变更：`src/subPackage/selectCustomer/index.tsx` 在接诊准备流程（`type=receptionPrep`）下，底部原先只有单个「开始」按钮；设计稿（Figma）要求改为两个按钮：
  - **接诊准备**（次按钮：白底、紫边、紫字胶囊）→ 带选中顾客进入接诊准备卡片页
  - **开始接诊 →**（主按钮：紫底、白字、右侧箭头胶囊）→ 跳过卡片页直接开始接诊（进 AI 听录制流程）
- 验收口径：其他入口（`type=aiRecorder / guideOrder / binding / aiDesigner / select`）的底部按钮行为与文案完全不变。

### 关键决策与理由

| 决策 | 理由 |
| --- | --- |
| 不复用 `receptionPrep/components/BottomActions` 组件 | 其非 detail 模式带 AI 免责声明（本页设计稿没有）、detail 模式是 20rpx 圆角矩形（设计稿是胶囊），两种形态都不匹配；强行传参改造会污染卡片页/详情页 |
| 样式不 `@import` receptionPrep 的 `rp-pill-button` mixin | 避免跨功能页耦合；在 selectCustomer 自有 scss 内按同一视觉口径（#605ce5、胶囊、2px 边框）落静态值 |
| 箭头图标复用 `RECEPTION_ASSETS.arrow`（COS 资源） | 与卡片页底部主按钮完全同源，视觉一致性零成本 |
| 「开始接诊」用 `useStartReception` 而非在页内重写跳转 | 单一实现源：该 hook 已封装 `isSupportRecord` 校验、mock 直跳分支、`navigateToAiRecorder`；卡片页 TODO 的行业类型弹窗接入后两端自动同步 |
| 页内中文文案直接写 JSX（不引 `ACTION_TEXTS` 常量） | 遵循 selectCustomer 文件既有风格（`'开始'/'确定'/'请选择客户'` 均为内联中文）；「JSX 不出现中文」仅是 receptionPrep 模块内约定 |
| `useDebounceFn` 参数与 `handleConfirm` 对齐（`{ wait: 2000, maxWait: 2000, leading: true, trailing: false }`） | 同页双按钮防抖口径一致，防双击重复跳转 |

### 技术方案

### tsx（src/subPackage/selectCustomer/index.tsx）

1. 新增 import：`ImageWebp`（`@/components/imageWebp`）、`RECEPTION_ASSETS`（`@/subPackage/receptionPrep/constants/images`）、`useStartReception`（`@/subPackage/receptionPrep/hooks`）。
2. 新增 `handleStartReception`（`useDebounceFn`）：
   - 守卫：`isOpen.current` 为 false 时 toast「请选择客户」；
   - 从 `selectedCustomerRef.current` 组装上下文：`customerId / customerName(customerName || nickname) / customerPhone(fullMobile) / orgId / gender / avatar / age`；
   - `setIsLoading(true)` → `await startReception(context)`，catch 后 console.error + toast「开始接诊失败，请重试」，finally 复位 loading。
3. 底部 JSX 改为条件渲染：容器 `classNames(styles.footer, isReceptionPrep && styles.footerPrep)`；
   - isReceptionPrep 分支：`styles.prepButton`（onClick=handleConfirm）+ `styles.startButton`（onClick=handleStartReception，内含 `<Loading>` 与 `<ImageWebp imageUrl={RECEPTION_ASSETS.arrow}>`）；
   - 其余分支还原为原单按钮，文案三元还原为 `isAiRecorder ? '开始' : '确定'`。

### scss（src/subPackage/selectCustomer/index.module.scss）

- `.footer`（紫色胶囊本按钮）保持不动，追加：
  - `.footerPrep { display: flex; background: #fff; }` —— 定义在 `.footer` 之后，同权重靠源顺序覆盖 `background: #605ce5`；容器继承 `.footer` 的 fixed/bottom 24px/宽 calc(100% - 48px)/translateX(-50%) 定位；
  - `.prepButton` / `.startButton`：`flex: 1`、高 86px、胶囊 `border-radius: 50px`、字号 30px（Taro 750 设计稿 px 单位），次按钮 `border: 2px solid #605ce5; margin-right: 24px`；
  - `.startArrow`：34px、`flex-shrink: 0`、`margin-left: 12px`。
