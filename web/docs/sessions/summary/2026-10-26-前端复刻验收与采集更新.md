## 关键结论

- **画布白屏根因是布局高度链断裂，不是初始化时序**：AntD Spin 外层 `ant-spin-nested-loading` 是 block 且有 441px 高，内层 `ant-spin-container` 只剩 2px，画布容器高 0，思维导图库构造时直接抛"容器元素el的宽高不能为0"。500ms 后的 resize 救不回来（构造已抛错）。修法一条 CSS：给该 wrapper 补 `display:flex;flex-direction:column;min-height:0`。定位手法是在生成器里往 constructor 前注入临时探针，沿父链记录 8 层的 `getBoundingClientRect` + computed style，一眼看出断点在哪层。
- **接口测试通过 ≠ UI 验收通过**：用页面真实提交体测接口，接口层绿了页面按钮可能仍没验证过；反过来，菜单项本身是 disabled 时确认弹窗不弹，是正常表现不是宿主 bug。写验收结论时把"接口操作"和"实际 UI 操作"分开记录。
- **新旧采集 ID 交集为 0 就不是同一批数据的增量**：当前 606 条与旧 82 条 Agent ID 零交集（知识库同理），还有旧前端不支持的 runMode=7。处理方式是新包独立存放、独立校验，不混入旧运行基准，避免旧任务/租户配置串数据。
- **大表采集先试接口的 size 上限**：页面默认每次拉 5 条分段，但同一接口透传 `size=1000` 实测有效，5.7 万条分段从约 1.1 万次请求降到几百次；续页游标读原发布代码确认是 `last.segmentOrder+1`，采完校验 segmentOrder 连续无重复防漏段。
- **JSON 里的大整数 ID 保持字符串**：JS `Number` 超过 2^53 会丢精度，知识库/docId 全程按源字符串精确匹配，不要 `String(已失真数字)`。
- **文档嵌套信封结构以现有消费方为准**：knowledge-documents 的 `info/config` 是直接响应信封 `{code,data}`，不是 `info.response`；改 schema 前先读校验函数（validateSnapshot）和现有测试，不要凭提示词里的示例猜。
