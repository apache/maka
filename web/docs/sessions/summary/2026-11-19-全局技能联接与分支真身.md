## 可复用经验与案例

5 个 clife 技能的扁平联接都指向插件工作区里的 `plugins/clife-dev-tools-plugin/skills/<name>`，不是各自一份拷贝。本地仓停在 `master` `71262cc`（2026-10-20）时，前 4 个有正文，`clife-tapd-frontend-task` 没有。该技能只在 `feature/clife-tapd-frontend-task`，远端提交 `74137eb`（2026-11-10）与页面一致，且该分支快进包含当时的 `master`。

换仓时删的是插件目录本身。旁边的联接指向同一绝对路径，所以克隆回原路径后，5 条联接不用重建就又能打开 `SKILL.md`。`node ~/.ai/scripts/sk-sync.js` 随后报 15 个 IDE 目录 27/27，categories 476 个 `SKILL.md`。这是工具输出，不是新会话已能调用的证据。当前对话的清单不会中途补技能。

目录被占用时，`rmdir /s /q` 把内容清掉了，文件夹还在，并报 “The process cannot access the file”。空目录上再 `git clone` 成功。这是失败信号：退出前先看目录是否还在，不要把「删失败」当成仓库还是旧内容。

## 常用命令

前提都是 Windows PowerShell，路径按实际替换。`cmd /c` 的退出码在这台机器上不可靠，以目录和 `Test-Path` 为准。

```powershell
# 看联接的直接目标。成功信号：行内有 <JUNCTION> 和目标路径。
cmd /c "dir /al C:\Users\802165\.cursor\skills"

# 技能是否真能打开。成功信号：True。False 且 dir /al 仍有联接 = 最后一跳断了。
Test-Path -LiteralPath "C:\Users\802165\.cursor\skills\<name>\SKILL.md"

# 把插件仓换成指定分支。目标目录必须是空的；成功信号：rev-parse 分支名与 log 的提交。
git clone --branch feature/clife-tapd-frontend-task --single-branch "https://cnb.cool/clife/fontEndCommonForYangLao/clife-dev-tools-plugin.git" "<空目录>"

# 全局视图对齐。成功信号：各 IDE「经源 27/27 [OK]」，且没有「断链」。
node C:\Users\802165\.ai\scripts\sk-sync.js
```

⚠️ `cmd /c "rmdir /s /q <插件目录>"` 会删掉真身文件。只对确认要换掉的工作区使用。联接本身仍用裸 `rmdir`（不带 `/s`）。
