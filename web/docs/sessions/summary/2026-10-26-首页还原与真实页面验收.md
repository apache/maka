# 首页还原与真实页面验收

**一句话总结**：预览更新不等于真实首页更新；先追完整数据链，再用实际页面和回归测试确认，而不是反复改 mock 数字。

## 背景

首页按设计稿调整后，独立预览已有完整数据，实际开发首页却仍没有邀约进度，复盘区也显示原摘要。排查确认：邀约人数 mock 已更新，缺的是完整展示数据进入实际页面的那段装配链。

## 核心命令

在项目根目录执行。以下为对话中实际有效命令的可复用写法：具体路径已去除，`<占位符>`按注释替换。Node 工具入口以当前项目安装版本为准；环境变量使用 Bash 写法。

```bash
git status --short # 查看暂存与未暂存改动，先保护已有工作
git diff --check # 检查改动中的空白错误、冲突标记等问题
git diff --cached --name-only # 核对当前暂存文件，不把工作区测试等同于暂存快照验证
git check-ignore "<占位符>" # 判断指定文件是否被 Git 忽略，避免误以为预览已随提交保存
rg -n "<占位符>" "<占位符>" # 第一个填关键词，第二个填源码目录；追踪字段、函数及其调用方
node node_modules/prettier/bin-prettier.js --check "<占位符>" # 检查本次改动文件的格式，不全量重排
DISABLE_V8_COMPILE_CACHE=1 node node_modules/eslint/bin/eslint.js "<占位符>" # 检查改动代码；环境变量用于本次高版本 Node 的缓存兼容处理
node node_modules/stylelint/bin/stylelint.js "<占位符>" --customSyntax postcss-scss # 按 SCSS 语法检查目标样式文件
node node_modules/typescript/bin/tsc --noEmit -p "<占位符>" # 指定最小 tsconfig 做语义检查，不生成编译产物
node "<占位符>" # 运行已有 .cjs 回归测试，结合断言和退出码判断结果
```

## 关键结论

1. **实际页面没变化，先追数据和调用链，不先认定缓存或旧包。** 本次人数已是 6，独立预览额外传了进度和成交统计，实际首页却没收到这些展示字段。修复放在现有 mock 分支：接口形状的数据仍经 mapper 转成 View，再补本地设计样例，由页面装配透传给卡片。随后在用户实际编译的首页读到了进度和完整统计。

2. **契约 mock、设计样例、真实接口必须分开。** 设计稿有字段，不代表后端已经提供；不能把“高成交机会”当“成交数”，也不能自行推算转化率。本次完整样例仅在 mock 分支附加，真实请求分支保留原字段；空数据和请求失败也不能用漂亮样例掩盖。

3. **完整状态枚举不等于全部都要展示。** 本次业务有五种活动状态，但首页只展示筹备中和进行中，且两者结构不同。状态字典、展示白名单和具体渲染分支应分别核对，不要把一个状态的展示规则套到所有状态。

4. **验证必须覆盖实际装配，也要看真正生效的样式。** 直接给叶组件传 props 的测试，发现不了页面没有传参。回归应覆盖公开 service 返回值到实际页面装配，并检查正常、空态、真实请求和失败路径。浏览器再核对目标页面的 DOM、computed style 和截图；还要区分设计单位与 CSS 像素，留意 `font: inherit` 对高亮字号的覆盖。转译成功不等于语义类型检查通过，预览通过也不等于宿主或真机验收。

5. **把项目经验写进规范时，要保留适用边界。** 通用前端规则与单个项目的导入、目录、样式、测试留存限制分开；参考骨架不等于可运行工程。`echo` 占位命令返回成功不能算检查通过，检查器也要确认真的扫描到模块。本次规范与模板部分只完成了盘点、范围澄清和交接提示词，没有完成更新实施。
