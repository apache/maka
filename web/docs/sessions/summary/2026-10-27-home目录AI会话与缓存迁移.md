# home 目录 AI Agent 会话与缓存统一迁移

**一句话总结**：30 个 AI 工具的会话记录按 SHA 严格校验归档进 `E:\cc\guahub\sessions\raw`，可再生缓存打包进 `_trash` 待删，共移出 home 约 19GB；顺带解决 home 配置仓库被 `.cursor/plans/projects` 刷屏的 git 忽略问题。

## 背景

home 目录（`C:\Users\802165`）是 git 白名单仓库，只该跟踪配置，但各 Coding Agent（claude/codex/cursor/kimi/trae/qoder 等 30 个）的会话、转录、缓存把它塞满；`.cursor/plans`、`.cursor/projects` 还因被 git 跟踪产生 3000+ 条变更噪音。

## 核心命令

```bash
# 让 git 真正放弃跟踪已跟踪目录（.gitignore 对已跟踪文件无效）
git rm -r --cached ".cursor/plans" ".cursor/projects"

# 验证某路径被哪条忽略规则命中（-v 显示文件:行号，--no-index 不看索引）
git check-ignore -v --no-index ".cursor/plans/probe.md"

# 实测 git 当前还能看见什么（比 check-ignore 更接近真实）
git status --porcelain --untracked-files=all -- ".cursor"
```

```powershell

Get-Process | Where-Object { $_.ProcessName -match 'codex|kimi|trae' } |
  Select-Object -ExpandProperty ProcessName -Unique

# 目录体积盘点（PowerShell 5.1 兼容写法，别用 ?? 和内联 $ 变量）
Get-ChildItem $p -Recurse -Force -File -ErrorAction SilentlyContinue |
```

## 关键结论

1. **git 忽略的优先级是"越深越赢、同文件后写的赢"**：`.cursor/.gitignore`（Cursor 托管块）里的 `!plans/**` 能压过根 `.gitignore` 的 `/.cursor/plans/`；覆盖规则必须追加到更深文件的托管块**之后**。`.git/info/exclude` 也压不过更深的 in-tree `.gitignore`。另外父目录被排除时子文件无法被重新放行，这是探针验证的可靠抓手。
2. **会话数据要分两级处理**：记录档（sessions/转录/附件/日志库）逐文件 SHA-256 严格校验；缓存档（extensions/runtime/updater/Cache 类）只校验体积、zip 用 `ZIP_STORED` 纯复制。这次慢一小时的根因就是把 SHA×4 遍的全套流程套在了 ~20GB 可再生缓存上。
3. **动数据目录前的三道安全闸**：进程守卫（应用在跑就拒动，codex 中途被打开写日志导致两次 archive 失败）；junction/reparse 守卫（PortableGit 内部有 junction，盲删留残骸，`p.is_junction()` 可检）；凭证/登录态白名单（Electron 的 `web`/`Partitions`/`IndexedDB`/`Network`/`Local State` 含登录 cookie，一律保留）。
4. **Windows Python 三个坑**：删只读文件（git 对象）先 `os.chmod(p, stat.S_IWRITE)` 再 unlink；文件 mtime 早于 1980 时 zipfile 报错，要用 `ZipInfo(date_time=(1980,1,1,0,0,0))` + `z.open(info,'w')` 兜底；Git Bash 内联 PowerShell 时 `$` 变量会被吞，写成 .ps1 文件跑，输出用纯 ASCII 防 GBK 乱码。
5. **zip 用 `'x'` 模式互斥创建**，中途失败重跑会撞 `FileExistsError`——archive 前先删残留 zip。

## 下次怎么用

- **配置仓库被 IDE 运行时目录刷屏**：补忽略规则（注意内层 .gitignore 反放行）→ `git rm -r --cached` → 造探针文件跑 `check-ignore -v` + `git status` 双验证 → 提交删除。
- **换机或清理 home 的 AI 工具**：先 `Get-Process` 查目标工具是否在跑 → 跑 `migrate_home_agents.py` 五步（新工具往脚本 `AGENTS` 字典加一组配置即可）→ 记录档进 `raw`，缓存档进 `_trash`，确认无误后删 `_trash`。
- **迁移中途失败**：脚本支持断点续删（重跑 `apply` 会跳过已删文件、只拒绝新增/内容变化的记录档文件），不用从头再来。
