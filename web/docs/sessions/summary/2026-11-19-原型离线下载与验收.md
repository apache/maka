## 可复用经验与案例

### 百分号编码经过 bat 时还会被 cmd 解析

- **触发：** 用户双击 bat 后，正确的 `%E8%B5%84…` 页面路径变为 `B54AEE8B…`，浏览器打不开。
- **根因与修复：** URL 已经做过编码；单个 `%` 在批处理里参与变量展开。bat 源码中把字面 `%` 写成 `%%`，覆盖 `echo` 与 `start` 两处。
- **证据：** 当前课程原型 bat 第 4、6 行均保留 `%%`。历史 `cmd //c ...test.bat` 输出的 `start` 行保留了完整 `%E8%B5%84…`，但同次运行还出现 `'5001'` 和乱码中文“不是内部或外部命令”的错误。
- **验证边界：** 百分号展开结果有证据；完整 bat 未验收通过，修后也没有用户确认。不能把直接 HTTP 打开页面成功写成“双击启动成功”。批处理文件中的 `%%` 规则不要照搬到交互式 cmd 或 PowerShell。

### 单页与整站复用工具，临时资源与脚本平级

用户先限定“只这一页”，后明确要求增加整站模式，并纠正目录为 `prototype/scripts/` 与 `prototype/tmp/` **平级**。这属于原型资料维护约定，保留在项目笔记，不上升为全项目目录标准。

当前脚本第 13–14、39–41、61–63 行静态可见：第 3 个参数起传页面名时限制 HTML 跟随；不传页面参数时从播放器首页、页面清单及样式种子递归抓取。历史单页输出 90 个成功文件，两次整站输出 1139/1599 个成功文件；这些是抓取计数，尚无逐页清单与全依赖完整性对照。

原型的依赖藏在 HTML、JS、CSS 中，只有一个 HTML 不足以离线浏览。历史本地 HTTP 请求返回 200，浏览器能打开播放器并进入目标内容。关于“file:// 必然不可用”的说法，本轮仅见使用说明，未执行对照实验。

### 失败信号要保留，不能在总结中被洗成成功

- **异常标签失真：** 下载器保存异常字符串，却丢弃其类型并统一打印 `404`；历史最终回复把 `403` 解释为“原站缺失”，证据不足。读取失败清单时先查日志生产方式。
- **浏览器 profile 冲突：** 工具只提示 profile 已被占用，不能据此确认相关 Chrome 进程全是“残留”。历史按命令行匹配强制结束了整批进程，未核实全部归属；此操作不收进常用命令。应优先使用工具支持的隔离会话，仅清理已确认由本次任务启动且获准结束的进程。
- **目录被占用：** `mv docs script` 曾返回 busy，切出原 cwd 后成功；后续另一轮改名仍失败，逐个搬移文件和 tmp 才完成。因此“先切出目录”是低成本排查动作，不能保证解决全部句柄问题。

## 常用命令

以下均为本对话实际执行且有可见结果的命令形态，已参数化并隐去内部域名。下载脚本是项目工具，不冒充通用命令。

**单页/整站下载。** 前提：从可信脚本目录运行 Python 3，`<原型目录URL>` 为以 `/` 结尾的目录地址；使用新建空输出目录。脚本应位于下载目录之外，避免执行下载内容。

```bash
python -I download-proto.py "<原型目录URL>" "<新建输出目录>" "<页面名>"
```

```bash
python -I download-proto.py "<原型目录URL>" "<新建输出目录>"
```

前者历史输出 90 个成功文件，后者输出 1139/1599 个成功文件，均伴随失败项。副作用：写入输出目录；当前实现会覆盖同名文件，重复运行前先核对目标，不能当作无损更新。

**检查本地入口 HTTP 响应。** 前提：静态服务已启动且确认服务根目录、端口正确。

```bash
curl -s -o /dev/null -w '%{http_code}' "http://127.0.0.1:<端口>/index.html"
```

Git Bash 历史执行返回 `200`。它只证明该入口有成功响应，不证明页面资源、交互或 bat 启动有效；不修改文件。下载异常抽查曾用同类命令返回 `403`，只能保留该请求被拒这一事实。
