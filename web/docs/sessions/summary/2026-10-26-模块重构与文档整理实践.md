# 模块重构与文档整理实践

**一句话总结**：按能力集中代码、按事实整理文档，用测试与 Git 树比较验证重构，用分类提交压缩反复整理的历史。

## 背景

AI 识别客户服务保留了超出正式职责的转写、客户池、识别和 mock 实现，需要集中管理并保留替换能力。随后整理了文档、提交历史和讲解图，也暴露出“文档目标态冒充代码现状”“图形校验通过冒充业务正确”等问题。

## 核心命令

以下在仓库根目录执行；尖括号内容需替换。

```bash
git status --porcelain # 检查暂存区与工作区；空输出表示干净
git log --oneline -8 # 查看最近提交，确定整理范围
git mv <旧路径> <新路径> # 移动或重命名受控文件
git diff --check # 检查 diff 中的空白错误，不验证业务正确性
npm.cmd run type-check # TypeScript 类型检查
npm.cmd run test:contracts # 接口契约回归
npm.cmd run test:unit # 用例与适配器单元测试
npm.cmd run build # 验证正式构建
npm.cmd run test:recognition:self # 运行固定 mock 基线
npm.cmd run smoke:recognition:audio-ai -- --fake --source-bucket mock-bucket --source-region ap-guangzhou --source-key recognition/smoke/input.mp3 # 不依赖真实云服务的冒烟检查
git diff <整理前提交> HEAD --stat # 比较最终文件树；空输出说明受控内容一致
git log --oneline --all -8 # 查看所有分支，排查旧提交为什么仍在图中
```

合并连续的本地提交时，本次验证有效的方法：

```bash
git branch backup/before-squash # 先保存重写前的历史引用
git reset --soft <合并范围之前的提交> # ⚠️ 改写当前分支位置，保留文件与暂存内容；只用于已确认的范围
git commit -F <提交信息文件> # 重新生成一条描述最终净效果的提交
git diff backup/before-squash HEAD --stat # 应为空，确认最终受控内容没有变化
git branch -D backup/before-squash # ⚠️ 删除备份分支引用；确认内容一致且不再需要备份后才执行
```

## 关键结论

1. Fastify 路由可以用 `app.register(plugin, options)` 分组注册；把文件放进一个目录只是代码归类，不等于已经支持独立启停。
2. 可替换实现按能力集中，依赖由组合根装配；业务用例依赖端口，避免直接创建具体云服务客户端。
3. 能力开关必须同时检查路由注册、依赖创建和调用链。只关路由，不能证明生产流程已与该能力解耦。
4. mock 代码可以集中到一个能力目录；JSON 基线、模拟器和生成音频需区分。被忽略的音频可重新生成，受控基线不能当临时结果随意清空。
5. “以后删一个目录”仍需清理组合根注入、fallback、脚本和测试引用，目录合并不能消灭这些依赖。
6. 只有一个消费方的类型，适合放回对应实现文件；无需为少量类型预留多层目录或全局类型桶。
7. 模块目录更名要同步 import、package scripts、文档与配置；HTTP 前缀、环境变量、COS key 是否改名要单独判断，不能全文替换。
8. 文档合并应先列核心内容，再去重和补缺；不要为了凑字数重复叙述。中文字符数、总字符数和编辑器词数是不同口径。
9. 文档文件名去日期前缀后，以标题下的变更日志记录日期、改动内容和修改人；重命名后同步索引与交叉引用。
10. 必须分开写“目标职责”和“当前实现”。本次 Node 目标为截片、COS 发布和回调，但派发代码仍含转写、识别及客户池依赖。
11. Java 接收 Node 回调、维护主账本幂等和超时兜底，不能因职责表勾选位置含糊就全部画成 Node 所有。
12. 合并提交后 GUI 仍显示旧历史，可能是“显示所有分支”把备份分支也画出来了；先查引用，不需要清理 Git 对象库。
13. 图形结构校验通过，只证明部分几何与格式约束成立。浏览器检查和业务语义核对是另外两道检查，不能混报全通过。
14. 本次图解仍有已知偏移：Java 冻结客户池与“工作流再次拉池”并存、万象识别误连到转写节点、状态机混淆阶段和状态。PRD 按客户聚合多音频的细节也需继续核对，不能当作已修正结论。

## 下次怎么用

目录重构先追调用链，再移动文件和修改引用，最后运行类型、契约、单测、构建及自测。文档合并按“业务目标—职责—现状差距—契约—验收”组织，确认核心内容已覆盖后再删除旧文档。整理本地提交前创建备份，结束后比较两端文件树；对外讲解前，再单独对照 PRD 检查图中的归属、方向、聚合粒度和状态含义。
