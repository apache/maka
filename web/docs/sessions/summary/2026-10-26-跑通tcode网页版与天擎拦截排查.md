# 跑通 tcode 网页版与天擎拦截排查

**一句话总结**：coding-agent 的桌面版被公司杀软拦死编译，改跑 TS 网页版并接入 DeepSeek 真实模型，全程端到端验证通过。

## 背景

想在本地跑 `E:\cc\guahub\interview\code\coding-agent` 项目的桌面版。桌面版是 Tauri 壳（`impls\typescript\desktop`），启动时拉起 `node bin/tcode.js web` 后端再开窗口。Rust 构建反复失败，转跑网页版，并接入了 DeepSeek 模型配置（写在 `~/.tcode/config.json`，字段 `apiKey` / `baseUrl` / `model`）。

## 核心命令

```bash
# 启动 TS 网页版（零依赖，配置读 ~/.tcode/config.json）
cd "E:\cc\guahub\interview\code\coding-agent\impls\typescript" && node bin/tcode.js web

# 跑桌面版（需先解决杀软白名单，见结论 1）
cd "E:\cc\guahub\interview\code\coding-agent\impls\typescript\desktop" && npm install --no-audit --no-fund && npm run dev

# curl 载荷含中文时先落文件再发：Git Bash 内联 -d 直接写中文会损坏成 invalid unicode code point
printf '{"model":"<模型>","messages":[{"role":"user","content":"reply with just: ok"}],"max_tokens":10,"stream":false}' > /tmp/test.json
curl -s -m 15 https://api.deepseek.com/v1/chat/completions -H "content-type: application/json" -H "authorization: Bearer <API_KEY>" -d @/tmp/test.json

# 查本机注册了哪些杀软（企业 EDR 不写 Defender 日志，要查 SecurityCenter2）
cat > /tmp/avcheck.ps1 <<'EOF'
Get-CimInstance -Namespace root/SecurityCenter2 -ClassName AntiVirusProduct | Select-Object displayName, productState | Format-List
EOF
powershell -NoProfile -ExecutionPolicy Bypass -File /tmp/avcheck.ps1

# 报"系统资源不足"先看内存提交配额是否打满（Committed 逼近 Limit 才是资源问题）
powershell -NoProfile -Command "Get-Counter '\Memory\Committed Bytes','\Memory\Commit Limit'"

# 降低 cargo 并行度后台重试构建（排除并行资源竞争；本次证明不是这个原因）
cd "E:\cc\guahub\interview\code\coding-agent\impls\typescript\desktop" && CARGO_BUILD_JOBS=4 npm run dev

# 验证本地服务活着（只看状态码，不刷屏）
curl -s -m 3 -o /dev/null -w "%{http_code}" "http://127.0.0.1:<端口>/t/<token>/"

# SSE 链路冒烟：后台订阅事件流，同时 POST 发消息，抓包验证整条链路
curl -s -N -m 30 "http://127.0.0.1:<端口>/t/<token>/events" > /tmp/sse.txt & sleep 1
curl -s -X POST "http://127.0.0.1:<端口>/t/<token>/send" -H "content-type: application/json" -d '{"text":"reply with just: ok"}'

# 解析 SSE 抓包：Git Bash 控制台直接 cat 中文是乱码（代码页问题，文件本身是 UTF-8），用 node 读文件解析
node -e "const lines=require('fs').readFileSync('C:/Users/<用户>/AppData/Local/Temp/sse.txt','utf8').split('\n').filter(l=>l.startsWith('data: ')); let out=''; for(const l of lines){try{const e=JSON.parse(l.slice(6)); if(e.type==='text')out+=e.delta||'';}catch{}} console.log(out)"
```

## 关键结论

1. **cargo 构建报 `os error 1450`（系统资源不足）的真凶是奇安信天擎 EDR**：它把 cargo 刚编译出的 build-script exe 定点查杀，最硬的证据是 exe 编译完几分钟后自动从 target 目录消失。排查路径：内存提交配额充足排除资源问题 → 手工编译运行小 exe 正常排除无差别拦截 → SecurityCenter2 查到天擎在运行（Defender 无任何检测记录）→ 被拦的 exe 凭空消失坐实查杀。解法只有让 IT 在天擎控制台把 `src-tauri\target` 加白，加白后 `npm run dev` 即可（构建缓存已就位）。
2. **tcode web 壳有个已知脆弱点**：`src/shell/web.ts` 里 `void runTurnAsync(text)` 火后不管，provider 抛网络错误（比如配置了不可达的占位端点）就以未处理 Promise 拒绝把整个服务带崩。本地跑壳不要指向不存在的端点；改代码时这个点五个语言版本要同步修。
3. **Git Bash 两个编码坑**：curl `-d` 内联中文 JSON 会损坏，必须先 `printf` 落文件再 `-d @文件`；控制台显示中文乱码不代表数据坏了，验证内容用 node 按路径读文件（Git Bash 的 `/tmp` 在 node 里要换成 Windows 实际路径）。
4. **网页版接口约定**：每次启动端口和 URL token 都变（`http://127.0.0.1:<端口>/t/<token>/`），旧链接作废；页面 → `POST /send`（体 `{"text":"..."}`）→ `GET /events`（SSE 推流，文本增量在 `delta` 字段）。会话后台任务随会话结束被回收，要常驻就在自己终端跑。
5. **接新模型的固定动作**：先 curl 实测 key 和模型名有效，再写 `~/.tcode/config.json`，重启服务后用 /send + /events 冒烟——不要配完直接信。带思考链的模型（如 deepseek-flash）首字延迟长属正常。
