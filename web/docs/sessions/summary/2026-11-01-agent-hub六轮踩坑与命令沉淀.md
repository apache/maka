# agent-hub 六轮开发踩坑与命令沉淀
**一句话总结**：多智能体项目六轮升级中实测有效的本机测试环境三前提、Playwright/pytest 工具坑、git worktree 并行工作流与 gh 发版命令。

## 背景
在 agent-hub 仓库完成六轮升级（契约冻结 → 三路并行 → 串行集成 → 对抗审查 → 真实模型消融 → 缺陷修复发布）。大部分返工时间花在本机测试环境坑、Playwright 长任务编排、以及 git worktree + gh 发布流程上，以下是可复用部分。

## 核心命令

```bash
# --- 本机 E2E 三前提（macOS + 全局代理环境实测）---
no_proxy=localhost,127.0.0.1 NO_PROXY=localhost,127.0.0.1 pnpm test:e2e
# shell 的 http_proxy=127.0.0.1:7897 会劫持回环探测，本地服务健康检查全 502
OPENAI_API_KEY= OPENAI_PROVIDER= pnpm test:e2e   # 置空 key 强制离线剧本（.env 有真实 key 会让内容断言失败）

# --- 清理残留端口（E2E 前后）--- ⚠️ kill -9 无差别杀进程，确认端口上没有别的服务
lsof -ti :8808 :8809 :8888 | xargs kill -9

# --- macOS 无 timeout 命令，用 perl alarm 给任意命令加超时 ---
perl -e 'alarm 90; exec @ARGV' python -m pytest -q tests/xxx

# --- venv 迁移/重建（目录移动后 shebang 绝对路径断链）---
uv venv .venv --python 3.12
uv pip install -q -e ".[dev]" --python .venv/bin/python

# --- git worktree 并行开发（每目录独立 venv，editable install 指向各自目录）---
git worktree add ../ah-X -b feat/xxx <起始tag或commit>
git worktree remove --force ../ah-X   # ⚠️ 强制丢弃该目录未提交改动
git branch -d feat/xxx                 # 已合并分支用 -d 安全删除

# --- gh：盯 CI / 发版 / 仓库设置 ---
gh run watch $(gh run list --branch main --limit 1 --json databaseId --jq '.[0].databaseId') --exit-status
git tag -a v0.2.1 -m "说明" && git push origin v0.2.1
gh release create v0.2.1 --title "标题" --notes-file notes.md ./asset.webm
gh repo edit --description "新描述" && gh repo edit --add-topic langgraph
git push origin --delete 旧分支名      # ⚠️ 删远端分支，删前确认已合并

# --- sqlite3 命令行快速查运行库，定位测试卡住的原因 ---
sqlite3 /tmp/xx.sqlite "select status, count(*) from runs group by status"

# --- 真实模型 API 调用（OpenAI 兼容，key 从 .env 提取不落盘）---
export OPENAI_API_KEY=$(grep '^OPENAI_API_KEY=' .env | cut -d= -f2-)
unset http_proxy https_proxy all_proxy   # 真实 API 直连，别走本地代理
```

## 关键结论

1. **本机 E2E 三前提**：no_proxy 绕代理、置空 API key、临时 db 用显式路径。macOS 的 `tempfile.gettempdir()` 是 `/var/folders/...` 而不是 `/tmp`——清理脚本删错位置等于没删（遗留数据占消费队列导致整组测试雪崩）。
2. **Playwright 1.63+ 三个坑**：`--video` CLI 参数已移除（须在 config 写 `use.video: "on"`）；块注释里出现 `*/` 会提前终结注释（表象是诡异的 "No tests found"）；`pnpm exec` 会吞 CLI 参数（用 `./node_modules/.bin/playwright` 直跑）。
3. **"通过 ≠ 无竞态"**：SSE 终态竞态（状态可见先于事件批次 → 提前断流）潜伏两周、全量绿多轮，目录迁移拨动时序后才 3/3 确定性红。修复模式：终态判定后补排空一次再退出。另一同类坑：async 生成器/FastAPI 端点里不要直接调带锁的同步 IO（SQLite 等锁可达秒级，冻结整个事件循环）——用 `asyncio.to_thread` 包；`Future.set_result` 必须在事件循环内（端点 async 化）。
4. **langgraph 1.2.x 实测**（版本相关，待验证于其他版本）：`Send` 必须经 `add_conditional_edges` 发出（节点直接返回 Send 列表会抛 InvalidUpdateError）；interrupt 暂停后从结果的 `__interrupt__` 键读取、用 `Command(resume=...)` 恢复；重开 SqliteSaver 连同一 db 文件即模拟进程重启，已完成节点不会重跑。
5. **流程教训**：批量补丁脚本中途断言失败会静默跳过后续步骤（一行依赖因此漏合入，靠对抗式审查抓回）——多步补丁要逐步验证；生产路径与测试路径的恢复语义不一致是高危缺陷（测试用 `Command(resume)` 恢复、生产却带输入重新 invoke 导致整图重跑）——评审时专门核对"同一操作测试和生产各走的是哪条代码路径"。

## 下次怎么用

- 本机跑任何 localhost E2E / 集成测试前，先套"三前提"命令；测试莫名雪崩时先 `lsof -ti` 清端口、再用 sqlite3 直查数据库确认有没有遗留数据。
- 发版流程可直接套：推送 → `gh run watch` 盯 CI → `git tag -a` → `gh release create --notes-file` 附资产（GitHub 原生可播 webm，无需 ffmpeg 转 GIF）。
- 写 LangGraph 多分支 + 人工审批的图时，先抄实测探针骨架（Send 走条件边、interrupt/resume、SqliteSaver 重开模拟重启），不要照旧教程的写法。
