## 可复用经验与案例

触发：适配表第 3 行要求老人列表“加一列”，并警告不加就会“少一列”。

证据分工：

| 来源 | 可见事实 |
| --- | --- |
| 用户职责确认 | 先划清负责项，再判断是否已改 |
| 适配表 | `65984`、`65987` 需要前端适配；`65985`、`65989` 不改；三个 `virtual/dashboard-*` 只是文案建议 |
| 仓库源码 | 页面只消费机构养老 summary、fee-trend、page 等封装；没有三个 virtual dashboard 接口 |
| 2026-11-16 HetAPI 导出 | page 响应有 `valueAddedAmount`，没有 `valueAddedServices` |
| 已登录环境的真实响应 | page 同时返回金额和 `valueAddedServices`；非空值形如“中换药、提供材料，1次；修脚，1次；” |
| 详情实现 | 月度详情把 `valueAddedServices` 当对象数组 |

决策：保留金额列，按列表样本新增文本列；空值继续走现有文本兜底。本地接口 Markdown 和 JSON 已按运行样本补档，但这不是导出文件原有内容，以后端重新导出为准。

本轮页面验证只覆盖重载后的项目列。自定义区间下五张统计卡显示 `¥0.00 / 0 人`，只能证明当时有渲染，不能证明五卡口径重新通过。

## 待验证与不适用边界

- `/v1/institution_import_record/page` 和 `/xiangyang/institution_import_record/page` 返回 404。缩写路径不是可调用 URL。
- `typeof valueAddedServices` 把 null 归成 `object`。它不是对象数组证据，不能进入有效命令。
- 编辑后第一次读取页面没有新表头，整页重载后才出现。这符合既有“确认新产物”规则，不是新的缓存机制结论。
- `npm run tsc` 退出码 2，错误位于 `node_modules` 的 pro-form 与 `@types/node/ffi.d.ts`，不是本次两个业务文件的诊断结果。
- 三个 virtual dashboard 的图例文案不在当前页面消费链，未改。
- 本轮没有提交、推送或调用业务写接口。
