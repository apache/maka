# Go 测试空转双缺陷与流式零拷贝坑

**一句话总结**：修一个开源网关 bug 时，自己的 perf 测试被维护者抓出"恒绿但什么都没测"（尾逗号+替换 no-op 相互抵消），同时流式过滤器踩了零拷贝返回切片被覆写的坑——三个坑都是写 Go 测试和流式代码时的高频雷。

## 背景

在 yetone/magpie 修 #4256（上游把 CR 字节缝进流式 tool-call 参数，客户端按 CR 断行）。第三版按维护者 review 的 spec 重做后收编进主线（dd279e931，v0.1.2257）。过程中：我写的 24MB 性能测试实际在空转（维护者靠 65ms 这个数字不对劲抓出来的），流式 relay 过滤器自己也藏了一个字节覆写 bug，靠字节级黄金流测试才暴露。

## 核心命令

```bash
git fetch upstream main && git fetch origin    # 会话开场同步双远程
git worktree add -b <分支名> /tmp/wt-xxx upstream/main   # 从主线开独立 worktree，不动共享工作树
git worktree remove /tmp/wt-xxx --force        # 用完即清（需在仓库根目录执行）

# 判断某提交是否已被收进主线（核对收编/让位时最直接）
git merge-base --is-ancestor <提交sha> upstream/main && echo "IN main"

git log --oneline upstream/main -- path/to/file.go       # 某文件在主线最近被谁动过
git show upstream/main:path/to/file.go | grep -n "func Test"   # 不切分支读主线文件内容

# ⚠️ 带租约强推：只有远端分支还停在写明的旧 sha 时才成功，防止覆盖别人新推的提交
git push --force-with-lease=<分支名>:<期望旧sha> origin <分支名>
git ls-remote origin refs/heads/<分支名>       # 推送后复核远端 tip == 本地提交

# 定向跑测试族并精确计数（-count=1 绕过缓存）
go test -tags nogui -count=1 -run 'TestA|TestB' ./pkg/ -v 2>&1 | grep -c "^--- PASS"
go test -race -tags nogui -count=1 -run 'TestX' ./pkg/   # 并发改动必跑 race

# 长套件后台跑：输出落文件再查，不接 tail（管道吞摘要）
go test -tags nogui ./pkg/... > /tmp/full.log 2>&1; echo "EXIT=$?" >> /tmp/full.log
```

## 关键结论

1. **测试空转双缺陷会相互抵消**。我拼 JSON fixture 时每项后追加逗号、循环结束直接闭合 `]`——尾逗号使整行非法 JSON，被测过滤器 decode 失败走了透传路径（mending 从未发生）；同时 `strings.Replace` 在错误的转义层找子串（线上字节是 `x\\ry`，我搜的是 `x\ry`），替换没生效，期望值==原始输入。两边都等于输入，断言恒绿，65ms 只是解析失败的耗时。维护者一句"这个数不对劲"就拆穿了。
2. **防法：测试必须校验被测对象真被处理**。"被修复"的场景先断言输出 != 输入再比对内容；JSON 数组拼接用前导逗号（`if i > 0 { b.WriteString(",") }`）；断言用的期望值和输入必须来自不同层的独立构造，不能让一个 no-op 替换悄悄把两者变成同一个字符串。
3. **零拷贝过滤器返回切片不得与内部缓冲同存储**。`lines()` 走快路径时直接返回了缓冲区的切片，外层随即 `append(buf[:0], tail...)` 把尾部数据下移——同一块内存被当场覆写，调用方还没消费的返回值就花了。修法：缓冲区还有尾部数据要保留时，返回拷贝。症状极其隐蔽（个别字节被改，如 `event:` 变 `dvent:`），只有把流按 1/2/3/7/13 字节逐块喂进去、和原始输入做全字节比对的"黄金流测试"才能稳定抓住。
4. **JSON fixture 想清楚转义层级再写断言**。线上字节 `\r`（JSON 转义）解码后是真实 CR 字节；线上字节 `\\r` 解码后是字面的 `\`+`r` 两个字符。同一个 bug 的载体在哪一层，决定了 fixture 怎么写、断言什么——先在纸上把 wire→decode 两层各是什么写清楚。
5. **给厂商加专用规则，先找仓内判例**。这次 scoped 规则（只对 glm-5.3-flash* 生效）整套照抄了仓里 grok_integral.go 的模板：模型名判定函数 + Request 旗标 + 构造点 `if` 包装器 + 整回复钩子，零自研。开源仓里"维护者自己写过的类似代码"就是最好的 API 文档。

## 下次怎么用

写涉及 JSON 拼接、流式过滤、字符串转义的测试前，过三条清单：逗号前导化了吗、"被修复"场景断言 `got != in` 了吗、转义层级想清楚了吗。写流式缓冲代码时加一个黄金流测试（同一输入按多种 chunk 尺寸逐块喂，输出和整体单次喂逐字节比对），别名覆写和状态机残留类 bug 基本都能被它兜住。fork 贡献场景可直接整套搬用：worktree 独占开工 → `--force-with-lease` 带 sha 推送 → `ls-remote` 复核 → `merge-base --is-ancestor` 核对收编。
