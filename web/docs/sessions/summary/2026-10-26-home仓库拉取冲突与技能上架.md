# home 仓库拉取冲突与技能上架

**一句话总结**：主目录 dotfiles 仓库带未提交改动拉远程，用 stash→ff→pop 解决冲突（本地为主），顺带把动态生成文件转忽略根治跨机冲突，再用 manifest+两个同步脚本把新技能挂上全局视图。

## 背景

home 目录本身是 git 仓库（`~/.gitconfig` 等配置即仓库文件，跨多台机器同步），带着一批未提交改动拉取远程时，4 个配置文件冲突且 `.gitconfig` 被写坏导致 git 瘫痪。解决冲突后复盘发现：反复冲突的根源是"每会话都被工具改写的动态文件"被跟踪了，于是做了一次动态/人工文件分类出库；最后把 `improve-codebase-architecture` 技能通过既有的 `.ai` 真身体系挂上全局。

## 核心命令

```bash
# 拉取前先看分叉：本地领先/远程领先各有哪些提交
git fetch origin && git log origin/main..main --oneline && git log main..origin/main --oneline

# 带未提交改动拉远程的固定三步：备份改动 → 快进合并 → 弹回改动
git stash push -m "pull 前本地改动备份"
git merge --ff-only origin/main
git stash pop          # 有冲突时 stash 不会被丢弃，解决完需手动 git stash drop

# stash pop 冲突取边：ours=拉取后的远程状态，theirs=stash 里的本地旧改动（与 merge 直觉相反）
git checkout --theirs -- <文件>   # 保留本地版
git checkout --ours   -- <文件>   # 保留远程版
git reset                          # 全部解除暂存，恢复成"未提交工作区改动"的原状

# ~/.gitconfig 被冲突标记写坏、所有 git 命令报 fatal: bad config 时的旁路开关
GIT_CONFIG_GLOBAL=/dev/null git status    # 让 git 跳过全局配置，先修复文件再摘掉前缀

# 停止跟踪"每会话都被工具改写"的文件（磁盘保留；提交后其他机器 pull 会删掉该文件，应用会自动重建）
git rm --cached <文件>

# 提交信息较长且含中文/特殊字符时，写文件再 -F 提交，避免引号转义事故
git commit -F msg.txt

# 全局技能两步上架：先在 ~/.ai/skills.manifest.json 的 global 列表加技能名，然后
node sk-rebuild.js --dry-run   # 演练：重建 ~/.agents/skills 联接视图
node sk-rebuild.js             # 实际执行
node sk-sync.js --dry-run      # 演练：分发到 .claude/.zcode/.codex 等全部 CLI 的 skills 目录
node sk-sync.js                # 实际执行；阶段3 自带真身完整性验收
```

## 关键结论

1. **home 即仓库的 dotfiles 模式有个特有死穴**：`~/.gitconfig` 既是仓库文件又是活的全局配置。stash pop 把 `<<<<<<<` 冲突标记写进去后，任何 git 命令都会 `fatal: bad config line N`。解法是 `GIT_CONFIG_GLOBAL=/dev/null` 旁路让 git 先跑起来完成修复，修完即自动恢复。
2. **跨机冲突的根治手段是出库，不是每次手工挑边**：每会话被工具改写的文件（recentProjects/窗口尺寸/时间戳类 setting、抓取缓存、shell 快照、statsig 缓存、日志、secrets）跟踪了就永远冲突。`git rm --cached` + .gitignore 一次解决；代价是其他机器 pull 时文件被删，靠应用自动重建。
3. **stash pop 的冲突方向与 merge 相反**：`--ours` 是拉取后的远程内容，`--theirs` 才是 stash 里的本地改动。搞反会把刚拉下来的更新又覆盖回去。
4. **白名单式 .gitignore（默认 `*` 全忽略 + `!` 逐条放行）**：让某文件不再出现，删掉对应放行行即可；但已跟踪文件对 .gitignore 无感，必须 `git rm --cached` 才真正脱离。
5. **技能上架的标准路径是清单驱动，不是手工复制目录**：真身在 `~/.ai/categories`，`.agents/skills` 是按 `skills.manifest.json` 重建的联接视图，sk-sync 再分发到各 CLI。全程 junction 链（CLI→agents→categories）可穿透读取；改完先 `--dry-run` 再执行，脚本自带验收。另注意：Git Bash 里 `[ -e "C:\反斜杠路径" ]` 会因引号内转义误报断链，验证一律用 `/c/Users/...` 正斜杠路径。
