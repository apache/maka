# 设计资产导出与技能治理

**一句话总结**：用可核验的节点、配置和测试完成 Figma 资产交付，并把项目经验沉淀为分工清楚、不过度膨胀的 Skill。

## 背景

这次先审查并调整了 Figma 页面与资产 Skill，随后实际导出设计节点、上传对象存储，并检查批量处理效率；最后开始用最新的接诊准备模块和本人提交记录校对可复用的工程经验。笔记只保留已经跑通、日后能复用的操作。

## 核心命令

以下 Git 命令在目标仓库根目录执行，Node 命令在目标 Skill 根目录执行；尖括号内容按本次任务替换。

```bash
git status --short -- . # 区分已暂存与仅在工作区的改动，避免把两者混为一谈
git diff --check -- . # 检查工作区补丁的空白字符问题
git diff --cached --check -- . # 单独检查暂存区补丁
git log -30 --author="<EMAIL>" --date=short --format='%h %ad %s' -- "<MODULE_DIR>" # 按作者和模块追溯最近提交
rg --files "<MODULE_DIR>" # 先列模块文件，再按入口和调用链缩小阅读范围
node --test scripts/test/asset-pipeline.test.mjs scripts/test/parallel.test.mjs # 运行资产管线与有界并发的离线回归测试
node --check "<SCRIPT.mjs>" # 对改动的 Node 脚本做语法检查
node scripts/export-figma-images.mjs --file "<FIGMA_FILE_KEY>" --ids "<NODE_ID_1>,<NODE_ID_2>" --format png --scale 2 --out "<OUTPUT_DIR>" # 按准确节点 ID 导出本地图像
node scripts/upload-cos.mjs --files "<FILE_1>,<FILE_2>" # ⚠️ 会向对象存储写入文件；先核对目标 Bucket、前缀与凭证
```

## 关键结论

1. **配置只保留一个读取入口**：沿用 `config.mjs`，按“运行环境变量 → 本地 `.env` → 项目默认值”取值，不为同一组常量再建文件。示例配置只放非敏感默认值和空白凭证项；`.gitignore` 不会自动把已经暂存的 `.env` 移出索引，提交前必须检查暂存清单。
2. **Figma 资产要从准确节点导出**：整页画板、播放条、播放/暂停图标与底部按钮是不同节点；先核对节点及格式，再保存本地文件并上传。Figma 返回的下载地址是短时中转地址，不写进源码。实际交付的图像 URL 经 HTTP 200、媒体类型和本地文件 SHA-256 一致性核验；视觉切图不是实际音频文件。
3. **批量任务并行但不失控**：多个独立图像使用最多三路并发，结果仍按输入顺序返回；失败后停止派发新任务、等待已启动任务结束。独立资产组可分给子智能体分析、导出和上传，但应分开输出路径，由主智能体统一验收和写常量；部分上传失败时先核对已成功 URL，再重试缺失项。
4. **通用 Skill 与项目事实分层**：Skill 正文保留触发条件、决策步骤和完成标准，具体画板、模块路径与存储配置放项目引用；不要把某次 UI 样式、模块名或单项目规则升格为所有任务的强制规范。合并零散 Skill 时优先合并重复决策，保留不同用户意图的独立触发入口。
5. **接诊准备的可复用工程原则**：真实接口数据先经 DTO/mapper 转成页面视图，再由 hook 编排加载、刷新和交互；卡片与顾客档案独立请求，慢响应只允许最新一次写入，异常按已确认的空态规则处理。记录这些“数据归属、竞态、清场、验收”方法，比照搬该模块目录或业务字段更有价值。
