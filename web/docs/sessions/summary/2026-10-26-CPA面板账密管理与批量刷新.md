# CPA 面板账密管理与批量刷新

**一句话总结**：把 1592 条 ChatGPT 账密从"注册期旧快照"重建为"OA 授权最新凭证"，并给管理面板补上库存筛选、批量部署、令牌刷新与批量删除能力。

## 背景

本地 CLIProxyAPI 管理面板的「数据管理」模块要支撑卡密库存运维（存量健康度、故障队列、批次账本）。实战中连续踩到三类坑：库存导入了错误的旧数据源导致满屏 401、跨工具 ID 不可比导致合并逻辑选错记录、以及 Windows 上内嵌脚本与批量文件事件的限制。

## 核心命令

```bash
# 编译并跑全部相关包测试（-count=1 禁用缓存，避免假绿）
go build -o custom-addon/exe/cli-proxy-api-datamgmt.exe ./cmd/server
go test ./custom-addon/backend/ ./internal/managementasset/ -count=1

# 只格式化自己改的文件——不要对整目录 gofmt -w（CRLF 仓库会污染上百个文件）
gofmt -l <改动文件>            # 先用 -l 看谁不合规
gofmt -w <改动文件>            # 再定点写回

# 查端口占用并强杀（⚠️ 会立即中断正在运行的服务，先确认 PID 是目标进程）
netstat -ano | grep ":8318" | grep LISTENING
taskkill //F //PID <PID>       # Git Bash 里双斜杠，否则被路径转换吃掉

# 面板管理 API 调用（Bearer 用 <管理密钥> 占位）
curl -s "http://127.0.0.1:8318/v0/management/data-records/stats" -H "Authorization: Bearer <管理密钥>"

# 带去重的批量导入（重复执行安全，新凭证覆盖旧记录）
curl -X POST "http://127.0.0.1:8318/v0/management/data-records/import?dedupe=1" \
  -H "Authorization: Bearer <管理密钥>" -F "file=@<清单>.jsonl"

# 不引依赖直接用 Node 内置 sqlite 查库（需要 Node 22.5+；本机用 v24）
"$NODE" --no-warnings -e "
const { DatabaseSync } = require('node:sqlite');
const db = new DatabaseSync('C:/path/to/data-records.sqlite');
console.log(db.prepare('SELECT COUNT(*) n FROM data_records').get().n);
"
```

## 关键结论

1. **先确认真实数据源，再谈清洗**：库存满屏 401 的根因不是令牌逻辑，而是导入的是注册期快照（8 月 2 日导出），而 8 月 12-13 日的 OA 重授权产物（67 个文件、1630 邮箱、几乎全含 mailapi_url）从未入库。重建后 1592 条里 1258 条是 8 月凭证。
2. **跨工具的 `db_id` 不可比**：注册工具与 OA 重跑工具各自自增，`db_id` 大小与凭证新旧无关。合并键必须换成「凭证新鲜度」——取 JWT 的 `iat`、`last_refresh`、`created_at` 三者最大。
3. **CPA 内核刷新令牌只写 auth 文件与内存**，不会通知外部库存；面板看到的"新过期日"要回写到库存，只能读盘上的 `<email>.json` 再抄回来（挂在已有的额度探测钩子上，零额外请求）。
4. **批量创建凭证后 CPA 内存加载不全**（1592 个文件、内存只认 831）：文件 watcher 丢事件，触发目录事件也无效，**重启服务**才全量加载。
5. **Windows 两个硬限制**：Node 脚本用 `-e` 传参会撞 32K 命令行上限（改成临时文件传递）；Git Bash 的 `/c/...` 路径传进 Node 字符串会被解析成 `C:\c\...`，脚本内一律写 `C:/Users/...`。

## 下次怎么用

- **新数据入库**：`?dedupe=1` 导入 → 查 `stats` 的 `detected`（有额度且有重置时间的条数）→ 五格状态卡点「已检测」按重置时间看可用池。
- **复活过期账号**：勾选 → 「刷新令牌」（走代理，避免 `unsupported_country_region`）→ 失败者自动标 `needs_reauth`（只能重跑 OA 授权）→ 成功者再检测。
- **只改自己动的文件**：补丁面维持 4 个官方文件 + 1 个新增测试文件；每次改完跑 `verify-archive.ps1` 比对归档，`git diff --stat` 核对面没有膨胀。
- **误跑 `gofmt -w` 污染行尾**（⚠️ `git checkout -- <文件>` 会丢弃这些文件的所有未提交修改，确认无自有改动再用）：
  ```bash
  git diff --name-only | grep -v -E "<允许改的文件>" > /tmp/revert.txt
  while read -r f; do git checkout-index -f -- "$f"; done < /tmp/revert.txt
  git add -A && git reset   # 刷新索引状态位，清掉幻影 M
  ```
