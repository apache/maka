# 开源接单狩猎五车道
**一句话总结**:开源仓库的 issue 池被抢空时,按"候选池→增量扫→兄弟面→实证 flake→审计构造"五车道降级找单,今天用第五条车道从"池面零候选"做到发 issue+修+PR 全流程落地。

## 背景
给 apache/maka 提 PR:30 个 open issue 全部有主(assignee/当日被 take/调查意图软占坑),表面看一单都接不了。把 magpie 仓库的狩猎方法论迁移过来后,靠代码审计自己构造出一单确定性缺陷并交付。

## 核心命令
```bash
# 池面全量(REST,不用 search API——本仓 search 假空)
gh api "repos/OWNER/REPO/issues?state=open&per_page=100" --jq '.[] | select(.pull_request == null) | "\(.number)\t\(.comments)c\ta=\([.assignees[].login]|join(","))\t\(.title[0:60])"'

# 占坑三查:assignees 之外还要查评论区 take 和关联 open PR
gh api "search/issues?q=is:pr+is:open+repo:OWNER/REPO+<issue号>&per_page=5"

# 发 issue 后占坑:评论正文恰为一个词 take
gh api -X POST repos/OWNER/REPO/issues/<N>/comments -f body="take"

# 实证 flake 扫描:套件 N 连跑(先跑已知 flake 做阳性对照,复现不了=rig 无效)
for i in $(seq 1 10); do node --test dist/xxx.test.js 2>&1 | rg "^ℹ (pass|fail)"; done

# 并发压测:直接 cmd & + wait PID(注意:(cmd)& 子壳脱管,wait 等不到!)
cmd1 > /tmp/a.log 2>&1 & P1=$!; cmd2 > /tmp/b.log 2>&1 & P2=$!; wait $P1 $P2
```

## 关键结论
1. **五车道降级**:池枯不等于没单。①候选池表(含"让位/不接"否定先例区,勿重复踩)→②REST 增量扫→③新报告缺陷的兄弟面 rg 反模式→④main 上实证跑 flake→⑤**审计构造**:读熟面代码找"函数注释承诺 vs 实现不符"、"共享 id 多条目"、"读取失败被当空"三类锚点。车道⑤今天产出真缺陷:同一条消息投影成两个共享 id 的条目,锚定用 first-match 把重连后的通知插进了错误位置。
2. **take 无排他权**:占坑靠交付速度护城河——认领者一周无 PR 可评估竞争接手;反过来自己 take 后要当天出活。
3. **TS target 是 ES2022 时 `Array.prototype.findLastIndex` 不可用**(tsc TS2550):用 reduce 写 last-match(`arr.reduce((last,c,i)=>pred(c)?i:last,-1)`),或照仓库先例写局部 helper。
4. **阳性对照是实证扫描的前提**:拿一个已知间歇红先验证 rig 能复现(同版本、同命令),否则"跑了 50 轮全绿"证明不了任何事——今天的已知 flake 在新 main 被顺带修掉,对照失败反而提示了"该坑已填"。
5. **发 issue 的诚实披露**:代码审计构造的问题必须写明 "found by code audit (AI-assisted), not from a real failure I hit",并附确定性测试级复现(3 连跑同结果),不带真实故障记录就不包装成真实故障。

## 下次怎么用
给任何开源仓库接单:先花 10 分钟做池面三查;全占满就直跳车道⑤——挑自己修过/读熟的两三个文件,按三类锚点通读,写出确定性红的探针再立项。七问闸(能复现/收益说得清/不碰维护者活跃区/兄弟面查过/三句话讲得清)任一不过就放弃,零新单是正常结果,不为发帖量降标准。
