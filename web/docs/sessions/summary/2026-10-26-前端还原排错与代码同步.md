# 前端还原排错与代码同步

**一句话总结**：UI 尺寸先找语义布局盒，JSX 报错先查类型来源，拉代码前先保存本地改动，验证只认实际覆盖范围。

## 背景

这次处理了页面还原中的小数尺寸、Taro 的 View/Text TS2786 报错，以及带本地改动拉取远程代码。真正可复用的是定位根因和小范围验证的方法，不是具体页面的尺寸、节点号或机器路径。

## 核心命令

以下命令均在本次对话中实际执行过；文件、目录和分支换成 `<占位符>`，在仓库根目录运行。

```bash
git status -sb # 查看分支、同步状态及暂存/未暂存改动
git diff --cached --name-status # 确认本次提交真正包含哪些文件
git diff --check -- src tsconfig.json # 检查改动中的空白和补丁格式问题
npx prettier --write "<占位符>" # 只格式化触达文件，修正缩进和折行
npx prettier --check "<占位符>" # 只检查格式，不修改文件
npx stylelint "<占位符>/**/*.scss" --customSyntax postcss-scss # 按 SCSS 语法检查样式
node "<占位符>/tests/hooks.behavior.test.cjs" # 运行模块已有的行为测试
```

带本地改动同步远程时，依次执行：

```bash
git stash list # 先记住已有 stash，避免混淆恢复对象
git stash push -u -m '<占位符>' # 临时保存已跟踪改动与未跟踪文件；不包含忽略文件
git pull --ff-only origin '<占位符>' # 仅快进拉取；分支已分叉时停下，不自动生成合并提交
git stash pop # 恢复刚保存的改动；出现冲突时检查并解决，stash 会保留
git diff --cached --stat # 恢复后重新核对暂存区，原暂存分组可能变化
```

## 关键结论

1. **小数尺寸先查取值对象，不要直接全量取整。** 本次不少值来自矢量外接框、描边外扩或计算结果，而非布局槽位。先区分 FIXED、HUG、FILL：固定槽位用设计尺寸，HUG 由内容撑开，FILL 用 flex/stretch。真实描边、字距、阴影及百分比派生值另行处理；REST 与 MCP 本身不是尺寸错误的充分原因。
2. **老安卓兼容和视觉验证要分开做。** 该项目用 margin/兄弟选择器表达 Auto Layout 间距，避免核心布局依赖 gap、inset。源码通过 lint 只证明规则检查通过；还要在目标视口读取 computed style、看截图。局部 0 FAIL 不代表整页一致，未比对、未映射及真机未测要明确保留。
3. **View/Text TS2786 的本次根因是 React 类型重复解析。** 两份 @types/react 导致 ReactNode 不兼容；通过 tsconfig 的 `react` 路径映射统一类型来源，并把本地 tests 排除出主工程，避免测试中的简化模块声明污染 Taro 类型。不同 TypeScript 版本也会影响诊断；本次目标模块验证通过，不等于全仓类型检查通过，也不是所有 TS2786 都用同一招。
4. **先删除已失效的实现，再考虑抽象。** 箭头改成 CSS chevron 后，旧隐藏图片 DOM、样式和未使用常量一起移除；已复盘卡片的本地保留记录增加筛选作用域，防止切页签时混入其他筛选。图片溯源集中记录“常量名、节点、中文名”，避免重复行尾注释；同事负责的业务代码撤回，仅保留允许修改的样式。
5. **拉取前保存改动，恢复后重新检查暂存区。** 本次远程更新与本地只重叠路由配置，快进后自动合并成功，保留远程新增路由和本地去重修改。`stash pop` 未加 `--index` 时，原暂存分组可能变化；提交文案应以当前 `git diff --cached` 为准。⚠️ `git checkout HEAD -- <占位符>` 会同时丢弃指定文件未提交及已暂存的改动，只在已确认备份并明确要撤回该文件时使用。

## 下次怎么用

遇到类似问题，先查改动范围和负责人边界，再用节点字段、完整报错链或失败测试定位根因。只改直接相关文件，执行触达文件的格式/样式检查与模块测试；涉及样式再补 computed style 和截图。同步远程按上面的 stash → 快进拉取 → 恢复顺序处理，最后核对暂存文件再写提交文案。
