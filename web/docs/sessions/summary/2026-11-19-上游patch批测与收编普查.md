## Skill 增量建议（待确认，未改动）

**候选：am 批测配方与三陷阱 → gua-pr-patch**

- 位置：`references/workflow.md` §4 维护档「可应用性」行（「严格 `git am`/3way 批测落到当前 base」处展开），或在 `references/pitfalls.md`「常见流程坑」加一条；二选一，不两处重复。
- 现有缺口：workflow §4 只有档位概念无配方。pitfalls 已有两点范围意识但语境是 filter-branch 清史（「用 `<base>..<branch>` 只重放差异提交」），format-patch 批测语境无覆盖；本轮三个陷阱全部实踩，无既有规则可拦。
- 建议文本：
  1. 批测取分支自有提交用两点 `format-patch <tip>..<branch>`；三点 `<tip>...<branch>` 是对称差，会把 main 侧全部提交打进「patch」（实测单支 17459 文件），整轮结果作废。护栏：`grep -c '^diff --git'` 超预期（如 >60）即 RANGE-SUSPECT 停发。
  2. 每支 am 前 `reset --hard <tip>` + `clean -fdq` 隔离 worktree；上一支 CLEAN 的残留让后续支全部假 CONFLICT（第 1 轮从 #3380 起全假）。
  3. 批测 tip 开工即取定存变量；多 remote 时 `FETCH_HEAD` 会被后一次 fetch 覆写（实测 fork fetch 后取 TIP 得到 fork 分支头，第 2 轮整轮作废），或直接用显式 `refs/remotes/upstream/main`。
  4. 两点范围为 EMPTY = 分支已含于 tip；配合紧格式 `(#N)` grep + commit API author 校验，可在维护者发 Landed 帖之前判「已收编」（#1677：分支头与 tip 提交同 SHA 原样落地、author 保留、issue 零帖）。
- 来源证据：本轮批测四轮试错记录（脏树假冲突 → TIP 错基 → 三点范围爆炸 → 两点+复位出权威表）；#1677 EMPTY + tip 同 SHA；批测表与 38 单普查结论见本会话汇报。
- 适用边界：跨仓通用；worktree 只建临时目录，家目录仓禁 `reset --hard`/`clean`（pitfalls 已有铁律，不冲突）。
- 检验场景：拿一支已收编分支跑四步——三点范围应产出超量文件被护栏拦截；两点范围应 EMPTY；`rev-parse <分支头>` 与 tip 中某提交同 SHA。能区分对错即配方有效。

## 常用命令（本会话实际执行、最终有效版）

- **存量 patch 池批测**（第 4 轮权威版，Git Bash）：

  ```bash
  git -C <repo> fetch https://github.com/<owner>/<repo>.git main
  TIP=$(git -C <repo> rev-parse FETCH_HEAD)   # 必须在后续任何其他 fetch 之前取
  WT=<临时目录>/batch-wt
  git -C <repo> worktree add --detach "$WT" "$TIP"
  printf '%s\n' "<tag> <ref>" ... | while read -r tag b; do
    git -C "$WT" reset --hard -q "$TIP"; git -C "$WT" clean -fdq
    git -C <repo> format-patch "$TIP..$b" --stdout > /tmp/pool-$tag.patch
    files=$(grep -c '^diff --git' /tmp/pool-$tag.patch)
    [ ! -s /tmp/pool-$tag.patch ] && { echo "#$tag EMPTY(已收编/无自有提交)"; continue; }
    [ "$files" -gt 60 ] && { echo "#$tag RANGE-SUSPECT(${files}f)"; continue; }
    git -C "$WT" -c user.name=ggbdpq -c user.email=ggbdpq@gmail.com am -3 /tmp/pool-$tag.patch \
      && echo "#$tag CLEAN(${files}f)" || { git -C "$WT" am --abort; echo "#$tag CONFLICT"; }
  done
  git -C <repo> worktree remove --force "$WT"
  ```

  前提：分支 ref 已 fetch 到本地（origin/fork 命名空间均可）；成功信号=逐支 CLEAN/CONFLICT/EMPTY 且文件数相称（1-8f）；副作用=临时 worktree、`refs/remotes/fork/*` 引用、/tmp patch 文件。⚠️ `reset --hard`/`clean -fdq` 只许用于临时 worktree，家目录仓禁用。

- **fork 分支枚举与单号映射**：`git ls-remote https://github.com/<user>/<repo>.git 'refs/heads/*'` 枚举；`git for-each-ref --format='%(refname)'` 全命名空间扫（分支常在 `refs/remotes/origin` 而非 `refs/heads`）+ `git log -1 --format='%s%n%b' <ref> | grep -o '#[0-9]*'` 建映射。
- **批量 fetch fork 分支**：`git fetch <fork-url> "+refs/heads/<名>:refs/remotes/fork/<名>" …`（一条命令多 refspec；refspec 加引号）。
- **收编 commit 的 author 校验**：`gh api repos/<owner>/<repo>/commits/<sha> --jq '.sha[0:9]+" "+.commit.author.name+" <"+.commit.author.email+"> "+((.commit.message|split("\n"))[0])'`。
- **SSH 远程挂起的替代**：`git fetch https://github.com/<owner>/<repo>.git <ref>`（HTTPS URL 直 fetch，不改 remote 配置；本轮 SSH fetch 卡死后 kill 改 HTTPS 成功）。
