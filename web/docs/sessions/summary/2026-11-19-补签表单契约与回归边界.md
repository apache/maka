## 可复用经验与案例

- **按字段拆开需求与契约**。原型要求补签原因可选、限 50 字。会话中浏览器对手动补签接口提交 `reason: ""`，HTTP 200、业务码 `572029`「补签原因不能为空」。前端保留必填，输入和表单校验均收紧到 50 字。活动评价、满意度评价看板也要求回复限 50 字，两页均调用 `components/replyModal`，因此在共享组件改一次。浏览器验证了补签原因留空时前端拦截，以及活动评价的输入截断和看板的 50 字计数。两处回复均未提交保存，程序化注入超限后的 Form 拦截沿用已有验证方法，本轮未重验。
- **按执行位置验时间窗**。用户转述与测试同事确认，以「活动结束后 7 天内可补」替代 XMind 的「只支持补签当日，待确认」。当时浏览器用名单接口的活动起止时间与页面时钟对照，看到进行中行置灰、已结束且在期限内的已报名行可点。此前关于接口也会拒绝超窗的说法超出证据。后续只读核查另有记录，指出所查 admin 实现的手动补签分支跳过时间窗。参见 [活动补签接口不拦窗口](2026-11-19-活动补签接口不拦窗口.md)。

## 常用命令

**读取 XMind 的具体用例**。适用场景是截图只截取某个节点，需要核对工作表中的完整条目。前提为 Python 3 和含 `content.json` 的 XMind 文件。保留实跑命令的 JSON 分支和筛选条件，将文件路径参数化。Windows Git Bash 使用 Python 可识别的文件路径。成功信号是输出带层级缩进的「补签」「回复内容50字」原文。仅读取归档内的 JSON，无解压或写入。

```bash
python -I -c '
import json, sys, zipfile

with zipfile.ZipFile(sys.argv[1]) as archive:
    raw = archive.read("content.json").decode("utf-8", errors="replace")

def walk(node, depth, output):
    title = node.get("title", "")
    if title:
        output.append("  " * depth + title)
    for child in node.get("children", {}).get("attached", []):
        walk(child, depth + 1, output)

sheets = json.loads(raw)
sheet = sheets[0] if isinstance(sheets, list) else sheets
lines = []
walk(sheet.get("rootTopic", {}), 0, lines)
for line in lines:
    if any(word in line for word in ("50", "200", "回复", "补签")):
        print(line)
' '<XMind 文件路径>'
```

会话原命令实际读到补签原因限 50 字、两处回复限 50 字和当日补签待确认项。这里保留首张工作表的读取范围，其他工作表及 XML 格式未验证。
