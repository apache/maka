# git 大迁移与仓库清理实战

**一句话总结**：个人仓目录大重构（业务域拆分、五区上移、白名单切换）+ 单根历史重建演练 + AI 工具目录瘦身，全程命令实测有效。

## 背景

部门从美业调到康养，`guahub/web` 按业务域拆成 `美业(meiye)` 和 `康养(senior)`，随后 web/interview/sessions/reverse/passkeys 五区上移为仓根一级目录；顺带把 `.codex`/`.claude`/`.cursor` 三个 AI 工具目录做了垃圾排查（1.7G→889M）。

## 核心命令

```bash
# ── 目录迁移 ──
mv 旧路径/子目录 新路径/域/            # 整目录被锁时逐层搬子项
rmdir 空壳/深层 空壳/浅层               # ⚠️ 先深后浅，只能删空目录

# ── 白名单 gitignore 验证(改规则后逐项过一遍) ──
git check-ignore -q <真实存在的路径> && echo 被忽略 || echo 已放行
git check-ignore -v <路径>             # 显示命中了哪条规则

# ── 大迁移整批提交(一次一版本) ──
git add -A -- .gitignore 旧路径 新路径  # pathspec 里旧路径必须写,已删除文件靠它才进暂存区
git diff --cached --name-status | awk '{print $1}' | sort | uniq -c   # 预期绝大多数是 R(改名配对)
git diff --cached --name-status | grep -v '^R' | head -20             # 抽查非改名项
git log --follow <新路径>              # 追溯移动过的文件,历史不断

# ── 拉取"冲突"先诊断再动手 ──
git fetch origin
git rev-list --max-parents=0 HEAD; git rev-list --max-parents=0 origin/main  # 两边根提交不同=历史被重建
git rev-list --count origin/main..HEAD; git rev-list --count HEAD..origin/main  # 本地独有/远程独有计数
git merge --ff-only origin/main        # 0 本地独有时直接快进,别 merge

# ── 找出删不掉的目录是谁占的 ──
powershell -NoProfile -Command "Get-CimInstance Win32_Process | Where-Object { $_.ExecutablePath -like '*关键路径片段*' } | Select ProcessId, Name, ExecutablePath"
taskkill //PID <pid> //F               # ⚠️ Git Bash 双斜杠;杀的是插件助手进程,主程序会自动重启它

# ── 目录排查大头与重复文件 ──
du -sh 目录/* | sort -rh | head -8     # 空间大头排序
md5sum 文件* | sort                    # 内容指纹分组,完全相同的归一组
```

## 关键结论

1. **整目录 mv 报 Permission denied ≠ 没救**：是别的进程（其他 AI 会话/资源管理器）持有子树句柄，锁整目录改名但通常不锁子项移动——先建目标目录→逐项 mv→空壳按先深后浅 rmdir 就能完成迁移。
2. **"拉取冲突"多数根本不是冲突**：先查根提交是否一致、两边独有计数，本机常见结论是"本地 0 独有提交，纯落后，ff-only 即可"。ff-only 报 "untracked files would be overwritten" 时，对比本地未跟踪文件与远程版内容，旧版备份到 `/tmp/cc-pull-backup*` 后移除放行。
3. **白名单 gitignore 迁移目录必须同步改规则**：`!/旧路径/`+`!/旧路径/**` 成对换成新路径；`sessions/_tmp` 这类排除规则要跟着目录走，否则下次 add 就是大文件事故。
4. **单根重建五步**：bundle 备份留退路 → `checkout --orphan new-root` + commit → 删旧分支改名 main → 强推 → reflog expire + gc 清底。⚠️ `push -f` 和 `reflog expire --expire=now --all` 不可逆，bundle 是唯一退路；多机仓库强推后其余机器 `git fetch && git reset --hard origin/main` 对齐，别 merge（unrelated histories 会拒）。
5. **删备份文件前先核对"独有内容是否已被现役吸收"**：md5 分组找完全重复 → 提取结构行（段落头/关键配置）对比 → 逐个关键词 grep 现役文件；provider 等定义全被现役包含时，删副本零损失。
6. **提交前必看暂存区**：本机有自动化会乱 add，`git diff --cached --name-status` 核对范围和超大文件后再 commit；pathspec 圈范围比 `git add -A` 全仓收安全。

## 下次怎么用

- **仓库结构重组**（拆域/上移/改名）：按"普通 mv（被锁就逐层搬）→ 改 .gitignore 白名单 → check-ignore 全项验证 → 同步改 README 路径 → pathspec 圈范围整批提交"的顺序走，一天内两次实战均零丢失。
- **AI 工具目录瘦身**：`du -sh | sort -rh` 找大头 → 区分"数据/程序本体/缓存日志"三类，只清第三类；运行中的工具（sqlite-wal 在写、lock 文件存在）先退出再清。
- **拉取出问题**：按"fetch → 根提交对比 → 独有计数 → ff-only"四步走，先诊断再动手，别急着解冲突。
