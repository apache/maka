# 浏览器批量创建每日任务

**一句话总结**：TAPD 每日任务可通过复制已有任务保留固定字段，逐日调整状态与日期，再用保存后的详情和筛选列表核对结果。

## 背景

需要连续创建多天的同类开发任务，除了日期和状态，其余字段保持一致。最终由用户在内置浏览器手动登录，复用已有任务完成了 3 条每日任务的创建与核验。

## 核心命令

本次没有符合筛选标准的通用终端命令。有效操作均在浏览器界面完成，不保留一次性路径、任务编号和浏览器内部控制脚本。

## 关键结论

1. **登录状态按浏览器会话区分。** 外部浏览器已登录，不代表内置浏览器也已登录。使用内置浏览器时，先由用户手动登录，再核对当前项目与任务页面。
2. **固定字段多时，优先复制已有任务。** 在原任务详情的“更多”菜单选择“复制需求”，确认目标项目和任务类别。复用标题、描述、父需求、模板、迭代、分类、工时、优先级、处理人和所属端，不必逐项重填；新任务状态改为“未开始”。
3. **先检查日期联动，再决定是否补填。** 本次表单修改“预计开始”并失焦后，“预计结束”会联动为同一天。读取两个字段的实际值，确认正确后再提交，避免自动更新期间重复输入。其他表单是否联动，以实际界面为准。
4. **独立每日任务保持独立。** 复制时检查“同步更新需求字段与状态”，保持关闭，避免后续修改牵连原任务。本次也未开启复制评论、复制附件或关联源需求。
5. **提交动作不等于创建成功。** 页面横向滚动后，提交按钮可能被固定侧栏遮挡，先恢复视图、确认按钮可见。提交后读取新任务编号，核对状态、起止日期和固定字段，再按标题筛选列表检查条数。本次核实新增了 3 条任务，均为“未开始”，且每条起止日期为对应当天。
