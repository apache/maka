# 开发笔记去重整理方法

**一句话总结**：笔记按主题合并，重复资料按内容判断，明确的清理任务用定向命令完成，验证范围别扩大到整个知识库。

## 背景

项目总结混杂了日期记录、设计方案和重复材料，查找结论需要来回翻文档。这次先按版本和主题归位，再把 16 份开发记录合成两篇文章；确认不再需要原始资料后，直接删除历史目录。

## 核心命令

将 `<占位符>` 替换为自己的路径。前四条 Git 命令在 Bash、PowerShell 中均可运行；最后两条是 PowerShell 原生命令，仅在 PowerShell 中执行。

```bash
git -C "<仓库目录>" rev-parse --show-toplevel # 确认真实 Git 根目录，避免把子目录误当独立仓库
git -C "<仓库目录>" status --short # 查看改动；被忽略且未跟踪的文件不会出现在这里
git -C "<仓库目录>" check-ignore -v "<文件相对路径>" # 找出具体是哪条忽略规则屏蔽了文件
git -c core.autocrlf=false -c core.safecrlf=false diff --no-index --check -- "<原文路径>" "<修改稿路径>" # 比较任意两份文件，检查本次新增的空白问题

# 以下两条仅在 PowerShell 中执行
Remove-Item -LiteralPath '<待删除目录>' -Recurse -Force -ErrorAction Stop # ⚠️递归删除目录及全部子项，不进回收站；先确认绝对路径和删除范围
Test-Path -LiteralPath '<待删除目录>' # 删除后复核；返回 False 表示目录已不存在
```

`--no-index` 适用于未纳入 Git 的文件；两个 `-c` 参数只影响这一次调用，不修改 Git 配置。该比较有差异时可能返回 1，检查空白问题还要看是否输出具体诊断，别仅凭退出码下结论。

## 关键结论

1. **按主题合并，不按日期拼接。** 多份记录反复描述同一条数据链和同一问题，适合合成“结构与契约”“交互与跨端故障”两篇。保留根因、最后采用的方案和未决边界，删掉重复提交过程；审核计划、已实施改动和待验收事项分开写。
2. **同名不等于重复。** 这次发现同名方案内容不同，也发现不同补丁包里有字节相同的源码。先比内容或 SHA256；需要保留的补丁包、规格目录不要拆散去重。用户明确不要的原始资料则直接清理，不再另造项目内归档层级。
3. **Git 状态为空，不代表文档没变化。** 知识库被祖先目录的忽略规则排除，普通 status 没有覆盖这些文件。先用 check-ignore 定位规则；未跟踪文件可用 no-index 比较，不必为一次文档整理修改忽略配置。
4. **验证只围绕本次目标。** 简单删除只需核对明确路径、执行删除、检查是否还存在；父子路径重叠时删除父目录一次即可。全库哈希会受其他目录的并行修改干扰，不适合作为这种定向操作的前置门槛。目录删除和旧引用清理是两个结果，应分别核验，避免只完成其一就统称全部完成。
5. **测试通过有范围，历史结果有时点。** 合成测试通过不等于真机通过，构建启动不等于构建完成，修复留在工作区或 stash 也不等于已经发布。整理笔记时保留这些差别，不把历史记录升级为当前保证。
