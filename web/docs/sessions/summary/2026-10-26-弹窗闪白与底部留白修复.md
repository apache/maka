# 弹窗闪白与底部留白修复

**一句话总结**：弹窗闪白要检查动画过程中的层叠关系，底部留白要检查滚动占位与固定底栏的实际高度，两处都优先用局部 CSS 修复。

## 背景

Taro H5 页面运行在 App WebView 中，重连失败弹窗出现、关闭时，白底吸顶设备条会短暂高亮。另一个问题是卡片页、详情页末卡与底部免责声明之间留白过大，并伴随一处 SCSS 注释格式报红。

## 核心命令

在项目根目录执行，先将 `<文件路径>`、`<脚本文件>`、`<样式文件>` 替换成实际相对路径。下面保留的是对话中实际使用并有效的检查命令，不包含安装、提交或发布操作。

```bash
git status --short # 查看已有改动，避免混入无关文件
git diff -- "<文件路径>" # 检查指定文件的实际修改范围
git diff --check # 检查补丁中的尾随空格等空白问题
node --check "<脚本文件>" # 检查 JavaScript 语法，不执行浏览器回归
node node_modules/prettier/bin-prettier.js --check "<样式文件>" "<脚本文件>" # 使用项目已安装的 Prettier 检查格式，不修改文件
node node_modules/stylelint/bin/stylelint.js "<样式文件>" # 使用项目已安装的 Stylelint 定位具体样式规则报错
```

## 关键结论

1. **遮罩子元素的层级很高，也可能在动画中被页面盖住。** 本次 Taro 弹窗外壳在 `opacity < 1` 时形成层叠上下文，内部 mask 的 `z-index: 1000` 无法越过外壳所在层级，页面中的 sticky 设备条因而短暂露出。页面父级原本已有 `position: relative`，只增加 `z-index: 0`，就把设备条和导航限制在页面上下文内，让挂到 body 末尾的弹窗稳定覆盖页面。这个写法依赖本次 DOM 结构，不能当成所有层级问题的通用补丁；已有的 Loading 到弹窗至少 200ms 的间隔也保留，两者分别处理交叉淡化和层叠问题。

2. **瞬时问题要看中间帧，不能只检查弹窗完全显示后的状态。** 在 Chrome 前台用 `MutationObserver` 配合 `requestAnimationFrame` 逐帧读取 computed style，再用 `document.elementFromPoint()` 检查设备条坐标由谁覆盖。本次设备条自身样式始终未变；修复后淡入 12 帧、淡出 11 帧均被 mask 覆盖，临时撤掉修复又能复现穿透。采样前应确认元素在可见区域，并留意后台标签的 rAF 节流，避免漏掉整个 200ms 动画。

3. **末卡离免责声明太远，先查末尾占位与重复预留。** 卡片页移除了滚动区 `::after` 额外占位；详情页将底部预留调整为固定底栏实际高度 `200rpx` 加安全区，并清零最后一张卡的 `margin-bottom`，保留免责声明已有的上间距。`200rpx` 来自本例底栏各部分高度之和，其他页面要按实际尺寸计算。滚动容器、吸顶和按钮定位没有改，但移除占位会缩短滚动行程，短内容场景仍需确认能否达到预期吸顶位置。

4. **样式报红按具体规则修，不靠猜。** 本次 `comment-empty-line-before` 要求注释前留空行，补一行空白后该文件的规则报错消失。改动后再运行同一条 Stylelint 命令，确认对应错误确实解决。

5. **区分检查通过与实际验收。** 语法、格式和 Git 空白检查各自只覆盖一部分问题，不能代替视觉回归。本次弹窗完成了 Chrome 中的逐帧回归；底部留白修改交由用户实测，App WebView 离线包没有实机验证。修复保持在页面 CSS 范围内，没有修改组件库源码或新增依赖。
