## 可复用经验与案例

### 1. 文档同步任务的可复用流程（本次验证有效）

1. **正本判定**：代码目录先 `find -type f` 无过滤全列（见坑 2），git status/diff 盘点未提交改动——并行会话改动中的文件以工作区最新态为准，不以 HEAD 为准。
2. **文档全景**：按编号目录（01-产品原型/03-接口定义/06-页面开发…）分别 `find -maxdepth`，确认目标版本目录是否存在；不存在则在对应编号下新建（本次 06-页面开发 下无 v4.44.4，新建后放进度文档）。
3. **矛盾调和落点**：两份文档对同一接口判定相反（适配清单称 65990「完全不变」vs 待补清单判缺 settlementAmount；适配清单称 68759-68765「已在平台建好」vs 导出快照未找到）→ 不改任何一份的结论，在新文档 §矛盾记录 里逐条列出并注明「以谁为准 + 联调前重新核验的条件」。
4. **快照类文档保护**：`审查证据.md` 是历史审查快照，覆盖会丢证据 → 保留原样不动；`后端待补字段清单` 是活文档 → 原地旁注修订。

### 2. find 按扩展名过滤会漏文件（本次真实踩坑）

`find -name "*.ts" -o -name "*.tsx"` 只找到 9 个 tsx，误判「文件缺失」；实际该目录 41 个文件是 `.js/.jsx`（React 项目 JSX 系与 TS 系混用）。**陌生目录第一步 `find <dir> -type f` 不带过滤全列或先 `ls -R`**，看真实扩展名分布再过滤。诊断信号：列表里 scss 数量远多于对应 tsx 时，先怀疑漏了扩展名而不是文件损坏。

### 3. 并行会话改动的诊断信号

同一文件两次读取内容不一致（优惠券列从 dataIndex 变占位"—"）= 并行会话正在改。定位动作：`find <dir> -type f -newermt "YYYY-MM-DD HH:MM"` 圈出刚改过的文件 + `git status --short` / `git diff` 盘点改动范围，然后以工作区态为正本继续，不按早前读取覆盖（对应既有记忆 parallel-session-workspace-inventory 的操作化）。

## 常用命令

```bash
# fnm 劫持环境下 git 的稳定调用：/mingw64/bin/git 全路径 + -C 指仓
# 场景：git ls-files 等首次调用报 "We can't find the necessary environment variables to replace the Node version"
/mingw64/bin/git -C /e/Projects/senior/frontend/microweb/microweb-saas-affair diff --stat src/pages/dataAggregation/
/mingw64/bin/git -C <仓库路径> log -1 --format="%h %ad %s" --date=format:"%Y-%m-%d %H:%M"
# 成功信号：正常输出 diff/log；副作用：无（-C 不改变当前 shell cwd）
```

```bash
# 定位并行会话/近期刚改过的文件
find <目录> -type f -newermt "2026-11-10 15:00"
# 成功信号：列出该时刻后修改的文件清单；配合 git status 交叉确认
```

```bash
# Windows GBK 控制台下 Python 输出/写 UTF-8（转换中文 HTML/JSON 文档时必需）
PYTHONIOENCODING=utf-8 python -I -c "import re,html; raw=open('x.html',encoding='utf-8').read(); ..."
# 成功信号：不报 UnicodeEncodeError: 'gbk' codec
# ⚠️ 副作用：脚本内 open('/tmp/x','w') 的 /tmp 由 Python 按当前盘符解析（cwd 在 E: 时写到 /e/tmp/），
#    既不是 Git Bash 的 /tmp 也不是 Windows Temp，Read 工具按 Windows 临时路径找不到——
#    读回时用 cat /e/tmp/x，或一开始就写完整盘符路径
```

```bash
# 快速提取大 HTML 文档的标题骨架（判断文档结构再决定要不要全文转换）
grep -o '<h[1-4][^>]*>[^<]*</h[1-4]>\|<title>[^<]*</title>' x.html | sed 's/<[^>]*>//g'
# 成功信号：输出按文档顺序的标题清单；适用：静态 HTML，无 JS 渲染标题
```
