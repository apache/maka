# Git 分支 stash 操作与前端接口联调沉淀

**一句话总结**：活动管理 7 模块开发全流程沉淀——多分支协作的 stash/快进/凭据命令、按模块拆分提交的挑文件恢复法、测试环境接口连通性探测三法，以及 echarts 图表空白死锁的根因与修复。

## 背景

在 microweb-saas-business（CRA + React17 + antd5，CRLF 仓库）开发活动管理 7 个新模块：个人分支与协作分支并行、7 个模块按人分批提交、后端 BFF 尚未部署需提前确认连通性，期间还排查了统计汇总页图表空白的 bug。

## 核心命令

```bash
# 同步上游最新代码到个人分支(个人分支无自有提交时直接快进,不产生 merge commit)
git fetch origin <协作分支>
git merge --ff-only origin/<协作分支>
# 个人分支已有自有提交后 --ff-only 会拒绝,去掉它改普通 merge

# 删分支前验证无独有提交(输出为空才删)
git log --oneline <协作分支>..<个人分支>
git branch -d <个人分支>          # -d 安全模式,未合并会拒绝

# stash 保存未完成工作:-u 必须加,否则新增文件(未跟踪)不会被收走
git stash push -u -m "说明文字"
git stash list

# 从 stash 挑文件恢复到当前分支(进工作区+暂存区)
git checkout stash@{0}^3 -- src/pages/xxx/     # ^3 是 untracked 文件树,恢复新增文件用
git checkout stash@{0} -- src/components/X.js  # 不带 ^3 是 tracked 改动树,恢复对已有文件的修改

# 平台删旧令牌后更新 git 凭据(Credentials Expired 时),写进 GCM 不用重登录
printf "protocol=https\nhost=<host>\nusername=<user>\npassword=<新token>\n" | git credential reject
printf "protocol=https\nhost=<host>\nusername=<user>\npassword=<新token>\n" | git credential approve

# 对比任两个文件的差异(不看提交历史,忽略 CRLF 差异)
git diff --no-index --ignore-cr-at-eol 文件A 文件B

# 浏览器地址栏直测测试环境 GET 接口:自动带登录 cookie,最省事
# https://<测试环境域名>/v1/saas/<接口路径>?param=1
# 返回 404 JSON(带 timestamp/status)= 接口未部署;code:0 = 通;跳登录页 = 无登录态

# curl 带 token 测接口(token 在 F12 → Application → Local Storage → auth-info-3 的 token 字段)
curl -s -H "authorization: <token>" "https://<测试环境域名>/v1/saas/<接口路径>"

# CRLF 仓库(仓库 lf、工作区 crlf)的 prettier 校验:去掉 \r 后走 stdin 判定
tr -d '\r' < 文件名 | npx prettier --check --stdin-filepath 文件名
```

## 关键结论

1. **echarts 图表空白根因**：echarts-for-react 3.0.6 首次渲染先挂临时实例、等它的 `finished` 事件才 setOption，而 echarts 4.x 空实例不触发 finished → 初始化 Promise 永远挂起。图表挂载后数据还会更新的页面能靠 componentDidUpdate 直接 setOption "自愈"；首次挂载后不再更新的图表（如在 `Card loading` 里每次卸载重挂）永远空白。修复：公共包装组件挂载后探测实例无 option 就主动补一次 setOption（幂等，不影响正常实例）。
2. **git stash 默认不收未跟踪文件**，必须 `-u`；保存后 `git status --short` 确认没有 `??` 残留，否则那批文件只在工作区裸奔。
3. **整合型文件（菜单 menuList、路由注册）不要整文件从 stash 恢复**：里面混着多模块条目，拿到别的分支会引用不存在的页面导致编译报错，应手工按需补条目；只有 stash 版与恢复后页面集合一一对应时才可整文件覆盖。
4. **改动范围要机器比对**：`git status` 结果与预期清单各导出到临时文件后 `comm` 比对，多一个少一个立刻现形，肉眼数行会漏。
5. **接口连通性判定**：404 JSON（带 timestamp/status）= 网关在但服务未部署；200 + code:0 = 可用；同一前缀下部分通部分 404 = 具体服务未上线，网关和认证没问题。
6. **新旧接口是两套路径**：同一业务的新老页面接口路径不同（如 `/senior/admin/cmini/**` 与 `/senior/org-web/aggregate/web/activity/**`），老的通了不代表新的部署了。

## 下次怎么用

- **多人协作分支同步**：`fetch` + `merge --ff-only`；删个人分支前先 `git log 协作..个人` 确认为空。
- **开发到一半要切分支 / 只交部分代码**：`stash push -u` 全量保存 → 切目标分支 → `checkout stash@{0}^3 -- <路径>` 挑文件入暂存区 → 提交后回原分支 ff-only 拉回。
- **平台令牌轮换**：credential reject + approve 两条命令搞定，验证用 `git ls-remote origin HEAD`。
- **后端说"接口部署了"**：先浏览器地址栏开一条 GET 接口看 code:0，再切前端的 mock 开关走真实接口；mock 数据与真实字典编码不互通，混用时列表筛空属预期。
