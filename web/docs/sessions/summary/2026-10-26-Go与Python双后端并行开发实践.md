# Go与Python双后端并行开发实践

**一句话总结**：用多个子智能体并行开发 Go + Python 双版本后端，砍掉 Temporal/gVisor 过度设计，落地自研轻量 DAG 工作流引擎。

## 背景

Agent Studio（智能体云平台）前端已复刻完成，原定的 Go/Python 后端方案不满意：Go 版引入了 Temporal + gVisor（过重），Python 版依赖 Celery + Redis（复杂）。本次重新做架构分析后，按语言拆目录，用 3 个子智能体并行开发，Go 版最终 35 个测试全过、编译出 21MB 单二进制。

## 核心命令

```bash
# Windows Git Bash 下带反斜杠的路径必须加引号，否则报 No such file or directory
cd "E:\cc\guahub\code\agents\agent-studio\backend"

# 双语言后端按目录分离，互不污染
mkdir -p backend/go backend/python

# 把已有 Go 工程整体挪进 go/ 子目录（多个文件一次性 mv）
mv cmd internal go.mod go.sum config.yaml go/

# 列出工程内全部 Go 源文件，核对交付物
find internal cmd -name "*.go" -type f

# 运行全部 Go 测试并看详细输出（验证子智能体交付质量，别只信它自报"全过"）
go test ./... -v

# 编译为单二进制，验证工程完整性
go build -o test-server.exe ./cmd/server

# 运行 Python 项目的功能自检脚本（验证核心算法：拓扑排序/环检测/变量解析）
python verify_minimal.py
```

Docker Desktop 安装失败的修复（管理员 PowerShell 执行）：

```powershell
# 启用"虚拟机平台"功能 —— Docker Desktop 的前置条件，普通用户安装无权限启用
dism.exe /online /enable-feature /featurename:VirtualMachinePlatform /all /norestart

# 启用 WSL（Docker Desktop 用 WSL2 后端时需要）
dism.exe /online /enable-feature /featurename:Microsoft-Windows-Subsystem-Linux /all /norestart

# 重启后重新运行安装程序即可
Restart-Computer
```

图形界面替代方案：`Win+R` 输入 `optionalfeatures`，勾选"虚拟机平台"和"适用于 Linux 的 Windows 子系统"，重启。

## 关键结论

1. **原方案过度设计的根因**：Temporal 是企业级分布式工作流引擎，但这个项目的 DAG 执行本质是单进程有向无环图调度——用 Kahn 拓扑排序自研引擎约 500 行就够，状态持久化用 PostgreSQL JSONB 字段存节点状态即可，砍掉后启动依赖从 postgres+temporal+qdrant 缩到 postgres+qdrant。

2. **双语言后端必须按目录分离**（`backend/go/`、`backend/python/`），共用 `migrations/`。混在一个 Go module 里会导致 go.mod、路径前缀、构建产物互相干扰。

3. **多子智能体并行开发的可行模式**：主会话先定接口契约（如 `ExecutorService.Chat(ctx, req)`），Agent 1 导出接口、Agent 2 注入消费，各自独立开发互不阻塞；交付后主会话亲自跑 `go test ./... -v` 和验证脚本核验，Agent 自报的"31/31 通过"要复跑确认才算数。

4. **Go 循环变量闭包坑**：goroutine 里直接引用循环变量会共享最后一个值，必须传参——`go func(n Node) { process(n) }(node)`。

5. **Docker Desktop 装不上的根因不是安装包问题**，是 Windows 没启用"虚拟机平台"功能且用户级安装无权限启用，必须管理员 PowerShell 跑 dism 或图形界面勾选后重启。

6. **两版本选型结论**：生产高并发选 Go（启动 <100ms、内存 ~50MB、单二进制）；快速原型和 AI 生态选 Python（代码量仅为 Go 的 1/4、自带 Swagger 文档）。开发期用 Python 迭代、生产用 Go 部署是性价比最高的组合。
