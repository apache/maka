# cursor 忽略压制与技能农场同步

**一句话总结**：家目录 `.cursor/projects` 反复冒进 git status 的根因是 Cursor 自管 ignore 块的深层放行压过根规则，用"目录内更深 .gitignore + 提交坐实"根治；顺带把技能农场从 15 个 CLI 目录扩到 21 个并走管线安装了 4 个审美技能。

## 背景

1. `.gitignore` 里明明有 `/.cursor/projects/`，未跟踪文件却反复出现在源代码管理里，修了两次都复发。
2. 全局技能只镜像到 15 个 CLI 目录，workbuddy/crush/goose 等新 IDE 没覆盖。
3. 想装文章里的 4 个前端审美技能（taste/huashu-design/hallmark/impeccable）到全局。

## 核心命令

```bash
# 定位 ignore 判定权归属：-v 直接告诉你哪条规则、哪个文件赢了
git check-ignore -v .cursor/projects/empty-window/mcps/x.json
# 输出 .cursor/.gitignore:11:!projects/*/mcps/**  ← 判定权在深层文件的"放行"规则手里

# 压制：在目标目录放更深的 .gitignore（内容就两行：* 和 !.gitignore）
# 管理块会挡普通 add，必须 -f
git add -f .cursor/projects/.gitignore .cursor/plans/.gitignore

# 暂存 ≠ 锁住；提交才防"放弃更改"连文件一起清掉（本项目翻车两次的教训）
git commit -m "chore(home): projects/plans 深层 gitignore 压制 cursor 管理块放行" -- .cursor/projects/.gitignore .cursor/plans/.gitignore
```

```bash
# 技能农场同步（~/.ai/scripts），先 dry-run 审查将删/将建
cd ~/.ai && node scripts/sk-sync.js --dry-run

# 执行前硬校验：将被删的技能必须真的不在农场里，零违例才放行
node scripts/sk-sync.js --dry-run 2>/dev/null | grep '将删' | awk '{print $2}' | cut -d/ -f2 | sort -u \
  | while read n; do [[ -e ~/.agents/skills/$n ]] && echo "违例: $n"; done

node scripts/sk-sync.js   # 实际执行，看阶段3 每目录"经源 n/n [OK]"

# 全局增删技能走三步，不要手工建链：
# 1) 改 ~/.ai/skills.manifest.json 的 global 数组
node scripts/sk-rebuild.js && node scripts/sk-sync.js
node scripts/sk-index.js --dry-run   # 新技能登记进分类 INDEX，先审再写
```

```bash
# 拉取冲突时按"取较新"裁决：本地 mtime vs 远程最后改动该文件的提交时间
stat -f '%Sm' -t '%Y-%m-%d %H:%M' .codex/config.toml
git log -1 --format='%ad' --date=iso -- .codex/config.toml

# TOML 改完先验语法（python3.11+ 自带 tomllib，零依赖）
python3 -c "import tomllib; tomllib.load(open('config.toml.template','rb'))" && echo OK
```

## 关键结论

1. **ignore 不生效先查"谁在裁决"**：git 规则是目录更深的 ignore 文件赢。`.cursor/.gitignore`（CURSOR MANAGED BLOCK，Cursor 自动生成）里 `!projects/*/mcps/**` 等放行规则压过一切浅层规则，根 `.gitignore`、`~/.config/git/ignore`、`.git/info/exclude` 全都救不了，唯一解是目录内放更深文件（skills/plugins 目录早有同款先例）。
2. **暂存态的新文件经不起一次"放弃更改"**：discard/reset 会把暂存新增连磁盘一起删。修复类改动当天提交坐实，否则等于没修。
3. **装第三方技能前先查本地**：文章里的 taste 就是本地已有的 `design-taste-frontend`（SKILL.md frontmatter `name:` 为证），impeccable 也早已在库，实际只需拉 2 个。
4. **generate-config.cjs 是 Windows 专用**（mappings 全是 AppData/codex.exe），别在 Mac 上跑，会把 computer-use 的机器字段整个换成 Windows 版；Codex 配置里 `windows_wsl_setup_acknowledged` 是 Windows-only 键，macOS 没有对应必填属性，编辑器 schema 红线是校验噪声。
5. 家目录拉取冲突按"每文件比 mtime 取较新"，比"无脑取远程"更保本机状态（config.toml/settings.json 这次都保住了本地较新版本）。

## 下次怎么用

- 任何 ignore 规则不生效：先 `git check-ignore -v <路径>` 找出裁决文件，再决定在哪一层加规则，不要盲改根 `.gitignore`。
- 新装 AI IDE 想挂全局技能：把它的 skills 目录加进 `sk-sync.js` 的 `DIRS` 数组 → dry-run 审查 → 硬校验 → 执行；验收看阶段 3 全 `[OK]`。
- 要装外部 skill：先 `find ~/.ai/categories -iname '*关键字*'` 查重，缺的再 clone 进 03 分类 → manifest.global 登记 → rebuild+sync+index。
