# 照护帮手 H5 本地没有菜单

> 归档日 2026-11-19。会话只做了源码定位，没有改业务代码，也没有在浏览器打开页面。

## 一句话结论

`h5/app-h5-service-task` 是照护帮手原生壳按 hash 直开的页面包。本地打开 dev server 看到的是 `/` 上的设备测量，不是模块目录；活动管理要自己拼 `#/activeManage/...`。

## Skill 增量建议

建议改 gua-dev-tools，不改 gua-writer / gua-pr-patch。2026-11-19 已落盘：只改了 `modules/prd/MODULE.md` 对照表「菜单否、跳转否」那一格。

- **目标位置**：`modules/prd/MODULE.md`「从组件反查页面入口」表格最后一行。修订原规则，不另起一条。
- **现有规则或缺口**：现表是「菜单可见 × 代码有跳转」。两者都否时，结论写「标注可能废弃」。这覆盖不了「菜单在宿主、本仓库没有菜单配置、顶层页之间也没有 `router.push`」的内嵌 H5。`modules/taro` 只覆盖 Taro 内嵌页；本仓是 CRA + `HashRouter`。`modules/senior` 只记机构端 `4002` 与集团端 `8000`，没有这条 H5。
- **建议替换最后一行**：菜单否、页间跳转也否时，先看路由表和页面文件是否还在。本仓库没有菜单、页面由 App/WebView 按 hash 直开 → 顶层路由仍是入口，输出 `#/path`，并写明菜单在宿主；本地 `/` 只表示默认路由挂了哪一页。路由、页面文件、宿主约定都对不上，才标可能废弃。
- **来源证据**：本对话工具结果。`src/App.js` 使用 `HashRouter`；`src/routes/index.js` 里 `/` 挂 `DeviceMeasure`，`/activeManage/list|publish|roomBook` 有独立路由；`list/index.js` 只从列表进详情和签到，发布、预定没有从列表链出去。全仓搜菜单只命中 `MockLogin`。用户两轮都是：服务已在本地启动，但找不到活动管理，并想要一个能切模块的菜单。
- **适用边界**：宿主直开的 H5/WebView。微前端或后台若路由表外还有菜单配置，仍以菜单配置为准。不要把某个 H5 的端口写进 senior 两仓表。
- **检验场景（未执行）**：照护帮手活动发布在路由表和 `pages/activeManage/publish` 里，仓库内无菜单、列表也不跳发布。正确结论是宿主直开入口。按现表标「可能废弃」即错。对照：路由还在、页面文件已删、全仓无引用，才标可能废弃。

## 可复用经验与案例

问题：新人打开照护帮手本地页，想从菜单进「活动管理」。

关键证据（本对话读到的源码，归档时重读 `.env` 与 `App.js` 失败，以下不重复当成本轮复核）：

| 事实 | 位置 |
| --- | --- |
| 端口 `PORT=3201` | 该仓 `.env` |
| 路由是 hash，没有站内菜单 | `src/App.js` 的 `HashRouter`；路由只登记在 `src/routes/index.js` |
| 打开本地根地址看到的是设备测量 | `/` 与 `/deviceMeasure` 都挂 `DeviceMeasure` |
| 活动三页彼此不是一个菜单下的子项 | `/activeManage/list`、`/publish`、`/roomBook` |

本地入口（活动页带 `mock=1` 走页面内假数据，这是源码分支，不是已打开页面的结果）：

- `http://localhost:3201/#/activeManage/list?mock=1`
- `http://localhost:3201/#/activeManage/publish?mock=1`
- `http://localhost:3201/#/activeManage/roomBook?mock=1`

详情要 `sessionId`。列表上的签到进 `/activeManage/signUp`，签到码是详情里的 `/activeManage/signCode`。去掉 `mock=1` 才打真实接口。其余模块看 `src/routes/index.js` 的注释，不要把这份路由注释当成原生菜单原文。

这和机构端 `microweb-saas-business` 的 `src/pages/activeManage` 不是同一套页面。后者的退 mock 已另记在 `2026-11-19-活动管理退mock改造复盘.md`。

## 待验证与不适用边界

- 未在浏览器打开上述 URL，也未核对原生壳实际菜单文案与 hash 是否一一对应。
- `mock=1` 只在本对话读过的活动页（列表、发布、预定、详情、签到码）里看到。不能推广到用药、档案等其它路由。
- 端口以当时 `.env` 为准；换机器或改端口后要重读，不要背 3201。
