# GitHub 贡献统计与主页自动刷新修复

**一句话总结**：用 GitHub API 把"我在上游仓库的真实贡献"（合并 PR、patch 合入、贡献语言占比）统计出来做成个人主页卡片，并修好了定时刷新任务因缺 token 而静默失效的问题。

## 背景

个人主页（ggbdpq/ggbdpq 仓库的 README + SVG 卡片）想展示第三方上游贡献：合并 PR 数、上游 patch 数、贡献语言占比。原有统计只覆盖个人仓库，且日常需要反复核对"今天有多少合入"。过程中还发现每日定时刷新从未真正生效。

## 核心命令

```bash
# 查某作者今天（北京时间）被合并的 PR；北京 0 点 = 前一日 16:00Z，> 要编码成 %3E
gh api "search/issues?q=author:ggbdpq+is:pr+is:merged+merged:%3E=2026-10-23T16:00:00Z&per_page=100" \
  --jq '.total_count, (.items[] | [.repository_url, .number, .title, .pull_request.merged_at] | @tsv)'

# 查上游 main 上"我署名或致谢我"的提交（patch 被采纳的取证）
gh api "repos/OWNER/REPO/commits?since=2026-10-23T16:00:00Z&per_page=100" \
  --jq '.[] | select((.author.login//"")=="ggbdpq" or (.commit.message | test("ggbdpq"))) | [.sha[0:8], .commit.committer.date, (.commit.message|split("\n")[0])] | @tsv'

# 看某笔提交的完整提交信息（核对署名形式：author 保留 / Co-authored-by / 尾注）
gh api repos/OWNER/REPO/commits/SHA --jq '.commit.message'

# GitHub 官方口径的"我在某仓库的贡献行数"（Insights 同源，数字最权威）
curl -s -H "Authorization: Bearer $(gh auth token)" \
  https://api.github.com/repos/OWNER/REPO/stats/contributors
# 返回 202 = GitHub 正在重算，隔几秒重试；每人一行，weeks[].a/.d 是增/删行

# 数我在上游 main 上的 authored 提交（和侧栏 Contributors 头像数一致）
git fetch upstream && git rev-list --count --author=ggbdpq upstream/main

# 带本地 token 跑数据构建（脚本从 GITHUB_TOKEN 取凭证）
GITHUB_TOKEN="$(gh auth token)" python3 scripts/build.py

# 核对线上真实部署的内容（raw 不走 camo 缓存，所见即仓库内容）
curl -s "https://raw.githubusercontent.com/ggbdpq/ggbdpq/main/assets/stats-light.svg" | grep -o "关键词"

# SVG 本地渲染成 PNG 目检布局（缩略图右侧约 1.5% 会被裁掉，属渲染器问题）
qlmanage -t -s 1760 -o /tmp/preview assets/stats-light.svg

# 定时任务排障三板斧：看运行列表 → 看日志 → 看仓库 secret
gh run list --repo OWNER/REPO --workflow=refresh.yml --limit 5
gh run view RUN_ID --repo OWNER/REPO --log | grep -E "using cached|error"
gh secret list --repo OWNER/REPO   # 空输出 = 一个 secret 都没配

# 手动触发 workflow 验证修复
gh workflow run refresh.yml --repo OWNER/REPO --ref main
```

## 关键结论

1. **贡献统计有四个口径，数字各不相同**：GraphQL `pullRequests(MERGED)` 总数、REST search 总数、`/stats/contributors`（Insights 图表）、`/contributors`（侧栏头像）。search 和 GraphQL 会有 ±1 的同步延迟；前两个数"合并的 PR"，后两个数"落地的提交"。
2. **patch 被维护者代提交后能否上贡献榜，取决于署名形式**：`/stats/contributors` 算 author **和** Co-authored-by（实证：3 笔 Co-authored-by 落地后数字恰好 82→85）；侧栏 `/contributors` 只算 author；纯尾注 `(#N, ggbdpq)` 两个榜都不算。所以请维护者"保留 author 或加 Co-authored-by"直接决定上不上榜。
3. **CI 定时任务"成功"≠"生效"**：workflow 引用的 secret 不存在时，脚本静默回退到仓库缓存重新生成相同文件，`git diff` 为零所以永不提交，但 run 状态是 success。排障入口：看 run 日志里的环境变量（`PROFILE_TOKEN:` 后面是空就是没配）和 `gh secret list`。
4. **读公开 API 不需要申请 PAT**：Actions 里用内置 `secrets.GITHUB_TOKEN` 就能查 GraphQL/REST 公开数据，配合 `permissions: contents: write` 还能自己提交推送。
5. **SVG/图片内容变了还要动 URL**：GitHub 用 camo 缓存 README 里的图片，提交新 SVG 后必须更新 `?v=` 参数页面才会变，自动化里要把这一步也写进 workflow。

## 下次怎么用

- 每天想知道"今天合了几个 PR / patch 被采纳没"：直接套上面前两条命令，把时间窗换成当天的 `T16:00:00Z` 前缀。
- 怀疑某个定时 CI 在空转：按"三板斧"顺序查——run 列表看有没有产出提交、日志里 grep 关键行为、`gh secret list` 看 token 是否真的配了。
- 个人主页/统计卡类项目可整体复用本次模式：GraphQL 拉数 → 脚本生成 SVG → Actions 定时刷新 → 提交前自动 bump 缓存参数。待验证：`/stats/contributors` 对 Co-authored-by 的计数在 GitHub 官方文档里没有明说，是实测推断，数字口径以后可能变。
