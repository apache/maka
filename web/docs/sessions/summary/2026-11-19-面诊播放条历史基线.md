# 面诊播放条历史基线

## 一句话结论

AI 面诊默认底栏播放（无音频编辑入口）在开发 audioEdit 之前就是 `.popup { min-height: 300px }` 撑出的白底；audioEdit 没有改这条路径。贴底外观是同一次排查里去掉 `min-height` 的未提交试验，不是旧版正确样式。

## Skill 增量建议

目标：`gua-dev-tools` / `modules/bug/MODULE.md`，接在现有「这是我改坏的还是历史遗留」段落后，不另起规则。

现有规则：用 `git show HEAD:<file>` 和 `git diff HEAD -- <file>` 区分「接手前就有」和「本轮工作区引入」。缺口：问的是「某功能有没有改到默认路径」时，HEAD 已经包含该功能；提交说明里的「安全区」也不等于该提交里每个文件都改了安全区。

建议追加：

> 「功能有没有改到默认路径」不要只看 HEAD，也不要只看提交说明。用引入该功能的提交的父版本 `git show <引入提交>^:<file>` 对照默认分支，再看可疑选择器是否只在条件为真时挂上。文件被该提交改过，不等于默认分支行为变了。同一轮里看起来更贴设计的截图，先确认是不是未提交试验，不能当成历史基线。用户要求保持功能引入前的默认操作时，默认路径整段回退，不顺手改视觉。

来源：本对话。`8b13461c^` 的 `VideoPlayPopup` 已是 `className={styles.popup}` + 裸 `AudioPlayer`，样式只有 `min-height: 300px`（`6eb73d80`，2025-12-01，audioEdit 之前）。HEAD 默认分支仍是 `` `${styles.popup} ${showAudioEditEntry ? styles.audioEditPopup : ''}` ``，`showAudioEditEntry=false` 时渲染裸 `AudioPlayer`。`4e7637ea` 的提交说明写了安全区，但该文件 diff 只有 `.audioEditText` 的 `white-space: nowrap`；`env(safe-area-inset-bottom)` 在 `321abcf6` 的 `.audioEditContent`，以及 `4e7637ea` 的 `audioEdit/index.module.scss`。用户指出不能影响 audioEdit 之前的默认操作后，`VideoPlayPopup` 两个文件已 `git checkout HEAD` 恢复。

适用边界：只用于判断「这是回归还是历史默认」。用户明确要求改掉这段历史视觉时，这条不阻止修改。

## 可复用经验与案例

问题：AI 面诊繁忙页点「查看」，底栏播放条下面有大块白底。另一模型归因到 `.audioEditContent` 的安全区，并称 audioEdit 改动污染了播放器。自测时把贴底截图当成正确旧版。

关键证据（本对话内 `git show`，源码静态可见；真机白底为用户截图）：

| 外观 | 对应代码 | 性质 |
| --- | --- | --- |
| 控件下大块白底 | `.popup { min-height: 300px }`，`6eb73d80` 起，默认路径一直挂着 | 历史默认 |
| 控件贴底 | 同轮去掉该 `min-height` 的未提交改动 | 试验，已回退 |
| 编辑入口弹层底部留白 | 仅 `showAudioEditEntry=true` 时的 `.audioEditContent` | 不作用于默认播放 |

取舍：白底本身是 2025-12 定下的默认高度，不是 audioEdit 回归。用户要求保持开发音频编辑之前的操作，因此不把默认路径改成贴底。编辑入口的安全区留白未动。

下次复用：先问清截图是已提交版本、未提交试验，还是功能引入前的父版本；再按上表对分支，不要用「文件被 audioEdit 提交改过」推出「默认播放被改过」。

旁支（已另改、与播放条无关）：复盘「暂缓」被裁切，是 `nut-radio` 上 `& > *:last-child` 打到每个 radio 内部的 label，行尾 margin 从未清零，再叠加容器 `overflow: hidden`。选择器要改成组件自身的 `&:last-child`。

## 常用命令

适用：判断某功能引入前，目标文件的默认路径长什么样。前提：本地有该提交。成功信号：父版本文件内容与当前默认分支可逐段对照。

```bash
git show <引入提交>^:<file>
git show <引入提交> -- <file>
```

本对话有效实例：`8b13461c^` 看 audioEdit 引入前的 `VideoPlayPopup`；`git show 6eb73d80 -- src/subPackage/aIAnalysising/VideoPlayPopup/` 确认 `min-height: 300px` 的引入提交；`git show 4e7637ea --stat` 之后再看单文件 diff，避免被提交说明带偏。

⚠️ 丢弃该路径未提交改动（本对话用于按用户要求恢复默认播放，执行后 `git status` 不再列出这两个文件）：

```bash
git checkout HEAD -- <file>
```

只在用户明确要求回到已提交版本时用。会丢掉该路径上的未提交修改。
