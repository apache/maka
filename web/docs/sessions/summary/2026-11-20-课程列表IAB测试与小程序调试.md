## Skill 增量建议（均为建议，未执行修改）

### 1. api 反模式：「包装字段拆平」与「改名」同列入补扫清单

- 目标位置：`gua-dev-tools/modules/api/MODULE.md` 反模式节，字段统一改名条目（现第 81 行附近）句末追加。
- 现有规则或缺口：现条目针对**改名**（id→sessionId）给出三类漏点+补扫 `\.<旧字段>\b`。NEW-1 是**拆平**场景：`rowIn` 映射删除后行数据从 `{schedule: {scheduleType, ...}}` 变为平铺 `{scheduleType, ...}`，重构者视角里没有「改名」、不会触发该条检查，但 `rules.js recommendState` 仍读旧包装键 `row.schedule` → assessRecommend 收到 undefined → 全部非推荐课程误判 blocked，运行态「可设置」态消失。`\.schedule\b` 补扫本可抓到，只是「拆平」不落在改名检查的触发条件里。
- 建议追加短文本：`删除包装/映射字段（如把 schedule 对象拆平为 scheduleType 等列）同属此类：包装键名也要列入 \.<旧键>\b 补扫；配套旧单测批量失效（如 16 条按旧字段名编写的用例）是消费面变动的免费信号，先核对失效原因再重写，不搁置。`
- 来源证据：rules.js diff（15+/1-，工作区）；`node --input-type=module` 直载消融（打包=can / undefined=红）；六环证据链见 04-测试用例\v4.44.5-集团端-课程管理\课程列表-测试报告-itest.md §3 NEW-1。
- 检验场景：下次删除映射层重构时，检查清单里是否出现包装键补扫项；若 `row.<包装键>` 读点漏扫，运行态应出现「整列状态误判」类症状（与 NEW-1 同形）。

### 2. quality/test.md：浏览器自动化操作组件的可行手法（五条实测）

- 目标位置：`gua-dev-tools/modules/quality/references/test.md` 「验证设计」节，表单绕过验证段（现第 44 行附近）后追加。
- 现有规则或缺口：已有「原生 value setter + input 事件」绕过校验手法，但 antd 组件交互与文件上传无覆盖。此前多个需求把「文件选择」标为 IAB 人工项；本轮 DataTransfer 注入实测打通，是能力边界更新。
- 建议追加短文本（要点式）：浏览器自动化操作 antd/wangEditor 组件的实测手法——
  1. antd Select 合成鼠标事件（dispatchEvent mousedown/click）打不开下拉：用 `input.focus()` + `keydown Enter` 键盘路径，或 MCP 原生 click/hover（合成 mouseenter 触发不了 React Tooltip）。
  2. antd 分页 item 点击须完整事件序列 `pointerdown→mousedown→pointerup→mouseup→click`（带 clientX/Y），单 click 无效。
  3. wangEditor/slate 编辑器 `document.execCommand('insertText')` 无效：聚焦编辑器、range 收尾后用 MCP `type_text` 真实键盘输入，再读计数器确认。
  4. 文件上传不必转人工：构造 File 加入 `DataTransfer`，赋给弹窗内 `input[type=file].files` 并派发 `change`，可触发 antd Upload customUpload 真实上传（以 COS 返回地址+「移除图片」按钮出现为成功信号）；超限/类型拒绝分支同法可测。
  5. 「字段改动清除错误」类断言等 700ms+ 再读 DOM（antd 动画残留出过两次假阳性）；控制台 uncaught 报错先 rg 源码归因再计入结论（注入脚本的异步回调变量会残留报错，本轮 timeText 实例）。
- 来源证据：本对话 IAB 执行记录（测试报告 §2 各用例证据列）；DataTransfer 注入实测 CL-14（PNG→COS 地址回显）。
- 检验场景：下次 IAB 测表单上传，用手法 4 应能直接走通；若对非 antd Upload 实现（原生 input 无 onChange 包装）失效，按组件实现换等价触发，不硬套。

## 常用命令

```bash
# 纯函数消融验证：直载 ES module 规则文件（package.json 无 type:module 时用 --input-type=module + file:/// URL）
node --input-type=module -e "import { recommendState, hasArrangementThisWeek } from 'file:///<模块路径>/rules.js'; console.log(JSON.stringify(recommendState(契约行, now))); console.log(hasArrangementThisWeek(undefined, now));"
# 适用：字段打包修复的红绿消融；成功信号=两种传参输出不同；注意 rules.js 是 ESM（export），CommonJS 文件换 require。

# 浏览器注入文件触发 antd Upload 真实上传（IAB evaluate_script，替代人工文件选择）
# 前提：弹窗内存在 input[type=file]；成功信号=预览换远程地址+移除按钮出现
# 代码：const bin=atob(b64); const file=new File([new Uint8Array(bin)], 'x.png', {type:'image/png'});
#       const dt=new DataTransfer(); dt.items.add(file); input.files=dt.files; input.dispatchEvent(new Event('change',{bubbles:true}));

# 文档 CRLF 统计与转换（Edit/Write 破坏行尾后的核验/修复）
node -e "const fs=require('fs');const p='<文件>';let t=fs.readFileSync(p,'utf8');console.log('CRLF:'+(t.match(/\r\n/g)||[]).length,'LF:'+(t.match(/(?<!\r)\n/g)||[]).length);"
node -e "const fs=require('fs');const p='<文件>';let t=fs.readFileSync(p,'utf8');fs.writeFileSync(p,t.replace(/(?<!\r)\n/g,'\r\n'));"
# 注意：node 里 replace 用 \n 模式匹配 CRLF 文件会静默失效，必须带 \r\n 核验命中（本对话复现一次）。

# wxa-runner 启动（登录实测）
node E:/cc/github/miniprogram/wxa-runner/packages/cli/bin/wxa-runner.js dev <dist目录> --forward-console --devtools-login
# 前提：fork main=pnpm install（坏模板行 '@parcel/watcher' 本地改 true，勿提交）+ pnpm build；开发者工具安全设置开服务端口+允许获取工具登录票据。
```
