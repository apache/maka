# 技能库缺口补全与候选池扩充

**一句话总结**:按项目规范从 skills.sh 找出技能库真缺口(Taro/Node BFF/契约测试/时区),5 个源仓进候选池,并掌握稀疏克隆和 frontmatter 扫描两个可复用手法。

## 背景

我是前端转全栈,日常项目是 Taro 小程序 + React H5 + Vue3 后台 + Node BFF,但技能库里 Taro 零覆盖、Node 后端和契约测试都是空白。这次对照自己的项目规范文档,去 skills.sh 搜缺的技能,下载进候选池(不直接进分类,真实项目用过一次再晋升)。

## 核心命令

```bash
# skills.sh 命令行搜索技能目录(非交互:重定向 stdin + 去 ANSI 颜色码)
npx -y skills find taro </dev/null 2>&1 | sed 's/\x1b\[[0-9;]*m//g'

# 稀疏克隆:大仓库只要一个子目录(实测 vercel/ai 154MB → 4.4MB)
git clone --depth 1 --filter=blob:none --sparse https://github.com/vercel/ai.git vercel-ai
git -C vercel-ai sparse-checkout set skills   # 只检出 skills/ 子目录

# ⚠️ 重克隆前删旧目录(rm -rf 不可恢复,先确认路径没指错)
rm -rf vercel-ai

# 一行扫描所有 SKILL.md 的多行 description(会把 skill 整个吞掉的病灶)
# 原理:description: 行之后到下一个 --- 之间若还有行,就是多行描述
find <技能根目录> -name "SKILL.md" | while read f; do
  desc_lines=$(awk '/^description:/{c=1;next} /^---$/{if(c)exit} c{c++} END{print c+0}' "$f")
  [ "$desc_lines" -gt 1 ] && echo "多行描述×$desc_lines $f"
done

# 中文提交消息用 heredoc 从 stdin 传给 -F(免临时文件)
# --no-verify 绕过自家的 .ai 删除守卫钩子——仅在确认删除是有意的时候用
git commit --no-verify -F - <<'MSG'
refactor(ai): 技能库按技术栈重组二级分类
MSG

# 工作区状态分布速览(按状态码聚合计数)
git -C "$HOME" status --porcelain | cut -c1-2 | sort | uniq -c
```

## 关键结论

1. **skill 不出现在 `/` 下拉,先查 frontmatter,不是查 router**:多行 `description:` 会被多数 loader 静默丢弃——整个技能等于不存在。单行 description 是 15+ 家 CLI 解析器的最小公倍数;`name:` 必须等于目录名(vercel 的 use-ai-sdk 目录里 name 是 ai-sdk,也得修)。
2. **SkillRouter 类工具药不对症**:router 解决"技能太多怎么选对"(发现层),不解决"技能进注册表前被解析层吞掉"。分层定位问题再选工具,能省一整轮改造。
3. **候选池纪律有效**:下载进 `00-候选池/<来源仓>/`,不直接进分类;真实项目用过一次再 `git mv` 晋升 + rebuild/sync/doctor。池内源文件不改(会被 git pull 冲掉),缺陷在晋升那一刻修。
4. **查重先于下载**:搜到的"好货"一半候选池里早有(wshobson 的 nodejs-backend-patterns、patricio 的 contract-testing-builder 都是老池员)。下载前 `ls` 一遍池子,避免重复 154MB 级的克隆。
5. **awk 扫 frontmatter 有个坑**:判定多行必须在 frontmatter 结束的 `---` 处截断,否则单行长描述(合法)会被误报成多行。

## 下次怎么用

- 新装的 skill 在 `/` 下拉里找不到 → 跑上面的 awk 扫描,九成是 description 多行或 name ≠ 目录名。
- 想补某类技能 → `npx -y skills find <关键词>` 搜,高装机量优先;整仓大但只要一个子目录 → sparse 三连(`--filter=blob:none --sparse` + `sparse-checkout set`)。
- home 仓库提交涉及 .ai 大量删除 → 确认是有意后 `git commit --no-verify` 坐实,防 pull 时被当误删回灌。
