# Figma 画板同步生成 UI 原型

**一句话总结**：把 Figma 画布的画板批量导出成本地 PNG 并配上 React 壳和热区做成高保真原型，过程中沉淀了 Figma REST API 管线、API 不稳的兜底套路和 Windows/Git Bash 环境坑。

## 背景

V1.7.3 迭代负责 App 首页，需要参考上一版本的做法：用 Figma REST API 把画布画板批量导出为本地截图，工程壳（Vite + React）提供页面导航、缩放和交互热区，设计稿更新后重跑同步脚本即可。期间 Figma API 间歇性抽风、本机是 Git Bash + Windows 原生 Python 的混合环境，踩了不少坑。

## 核心命令

```bash
# 从 .env 读 token 到单命令变量（不 echo 不落盘，用完即弃）
FIGMA_TOKEN=$(grep '^FIGMA_TOKEN=' /path/to/.env | cut -d= -f2- | tr -d '\r')

# 列出画布(CANVAS)顶层的全部画板 Frame：id / 名称 / 尺寸
curl -s -H "X-Figma-Token: $FIGMA_TOKEN" \
  "https://api.figma.com/v1/files/<FILE_KEY>/nodes?ids=<CANVAS_ID>&depth=1"

# 导出画板为 PNG（scale=2 即 2x 图）；images.<节点id> 是短期URL，必须立刻下载落盘
curl -s -H "X-Figma-Token: $FIGMA_TOKEN" \
  "https://api.figma.com/v1/images/<FILE_KEY>?ids=<NODE_ID>&format=png&scale=2&use_absolute_bounds=true"

# 同一时效问题：imageRef → 图片URL 映射（节点fills里的imageRef查这里）
curl -s -H "X-Figma-Token: $FIGMA_TOKEN" "https://api.figma.com/v1/files/<FILE_KEY>/images"

# 网络不稳时的幂等重跑：脚本带"已存在跳过+单张失败容错"，外层再兜一圈
for i in 1 2 3 4; do node scripts/sync-figma.mjs && break; sleep 5; done

# 验证 CDN 资产可访问且媒体类型正确
curl -sI "<CDN_URL>" | grep -iE '^(HTTP|content-type|content-length)'

# 长截图缩略成 JPEG 便于目检/送审（Pillow）
python -c "from PIL import Image; im=Image.open('in.png').convert('RGB'); im.thumbnail((450,3200)); im.save('out.jpg','JPEG',quality=80)"

# 后台起 Vite 并验证关键资源 200
(npx vite --port 5199 --strictPort >/dev/null 2>&1 &) && sleep 3 \
  && curl -s -o /dev/null -w "%{http_code}\n" http://localhost:5199/screens/manifest.json
```

## 关键结论

1. **Figma images API 不稳是常态**：同一个节点同一 token，这次请求返回正常 URL，下次就返回 `null`；批量下载中途还会遇 CDN 连接超时（`ConnectTimeoutError`）。解法三层：单张失败 try/catch 不中断整批 → 已存在文件跳过（断点续传）→ 外层重跑循环兜底；API 全挂时手写 `manifest.json` 先用已导出的图顶上。
2. **Git Bash 的 `/tmp` 对 Windows 原生 Python 不可见**：bash 写 `/tmp/x.json`，python 按 Windows 路径找不到。临时产物一律落项目目录（`.gitignore` 管住），用完即删。
3. **openpyxl 读"合并单元格多"的表格别用 `read_only=True`**（会拿到空值），普通模式加 `data_only=True` 即可；按负责人筛任务时直接遍历 `ws.merged_cells.ranges`，比逐行猜合并范围快得多。
4. **Vite + TS 模板 build 报 TS5096**：`tsconfig.node.json` 里 `allowImportingTsExtensions` 必须搭配 `"noEmit": true`（v1.7.2 骨架只跑过 dev 没跑过 build 才没暴露），补一行即修复。
5. **复制项目骨架只拷需要的文件**：`cp -r` 整目录会把 `node_modules` 一起拖进去，慢到像卡死；先停掉，只拷源码/配置/脚本十几个文件，依赖交给 `npm install` 重建。
