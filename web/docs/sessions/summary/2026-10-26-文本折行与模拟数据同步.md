# 文本折行与模拟数据同步

**一句话总结**：两行省略需要配齐截断样式；Mock 要覆盖混合行数和参数场景；同步验收完成前不能删除原始快照。

## 背景

护理报告的多张卡片需要按组对齐标题、描述的行数，超过两行显示省略号。为验证显示效果，补充了多种 Mock 场景，并尝试将 SQLite 数据同步到 Whistle；本地脚本检查通过，真实上传因服务连接失败尚未完成。

## 核心命令

以下命令在本次对话中实际执行且通过，路径已替换为可复用占位符。

```bash
node --check "<脚本路径>.mjs" # 检查 JavaScript 脚本语法，不执行上传逻辑

git -C "<仓库路径>" diff --check # 检查已跟踪文件改动中的空白错误，不代表功能验证通过

git -C "<仓库路径>" status --short # 查看修改和未跟踪文件，避免遗漏本地脚本
```

## 关键结论

1. **两行省略要配齐 CSS。** 本次 Chromium 复现中，单独设置 `line-clamp: 2` 未显示预期省略号；补上 `display: -webkit-box`、`-webkit-box-orient: vertical`、`-webkit-line-clamp: 2` 后成立，保留原有无前缀声明。目标真机效果仍待验证。
2. **截断和整组对齐是两个问题。** 截断限制单项最多两行；整组对齐则分别测量标题组、描述组，只要组内有一项折为两行，整组就使用两行高度。字体加载完成后再测一次，避免使用字体加载前的尺寸。
3. **Mock 要覆盖混合情况。** 除全一行、全两行，还应准备一项两行其余一行、超过两行、描述为空、字段缺失，以及列表成员数量变化。本次阶段卡覆盖了 1～5 项；详情按 `launchId` 区分，生成状态接口也要配合返回可进入详情的状态。
4. **导出活动场景不等于导出全部有效场景。** SQLite 同步还要包含 `queryScenarioMap` 引用的场景；参数规则需精确匹配，默认规则排除已映射参数，防止场景互相覆盖。修订脚本的离线参数检查通过，真实 Whistle 分组与回放效果待验证。
5. **上传成功必须靠目标端核验。** 本次提前删除了原始快照，随后只找到部分去重响应，无法还原完整 Session。⚠️ `rm -rf` 会直接删除目录；必须先核验备份完整性及恢复能力，再清理源文件。Whistle Values 不能替代完整会话备份。

## 下次怎么用

先准备混合行数、空值和数量边界的 Mock，通过真实页面逐条验证。同步前检查脚本语法和 Git 改动，并确认不会覆盖已有手工规则；同步后核对目标分组、场景数量和参数回放。只有这些检查通过且原始会话已有可恢复备份，才清理本地快照。
