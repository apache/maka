# PRD 转需求 Spec 三轮澄清

**一句话总结**：用「清单定范围、PRD 定规则、原型定展示」三材料分工法生成产品需求 Spec，再经结构化澄清 → 对抗审查 → 最终扫描三轮收敛，7 个关键问题全部闭环，遗留歧义清零。

## 背景

拿到 PRD 文档、Excel 迭代清单和原型三份材料，要为其中两个页面产出产品需求 Spec。三份材料口径不一致（12 处冲突）、关键规则缺失（7 处），需要一套可复用的流程把范围锁定、把歧义收敛掉，而不是靠猜。

## 关键结论

- **三材料分工**：Excel 清单定需求范围（哪些项本期做），PRD 定业务规则（字段、状态、文案），原型定展示细节（布局、交互形态）。三者冲突不能含糊带过，逐条编号（冲突 C-xx、缺失 G-xx）写进 Spec 并给出处理结论，需求评审时才可追溯。
- **三轮收敛工作流**：第一轮结构化澄清（一次一问、每问带推荐答案和理由）→ 第二轮对抗审查（只提「会导致理解偏差或返工」的问题，材料能推断的一律不问）→ 第三轮最终扫描（通常已无新问题，把遗留项显式化为合理假设）。每轮结论直接回写 Spec 的 Clarifications 节。
- **提问判据三条**：材料能推断的不问；推荐项预写进 Spec、答复后再逐题核对闭环（一致则不动）；依赖性问题和它的前置问题不放在同一轮问。
- **单文件 HTML 原型模式**：页面内容全部放 JS 数据数组，渲染函数驱动 + 事件委托绑定，零外部依赖保证 file:// 离线可开；交付前必须过「提取 script → node --check → 标签配对计数」三步，语法或配对错了会直接白屏。
- **环境坑**：Windows Git Bash 下路径写 `/e/Projects/...` 形式；python 一行脚本里换行符要用 `chr(10)` 拼接，别直接在字符串里敲回车。

## 下次怎么用

拿到「PRD + 需求清单 + 原型」要做需求分析时，直接套四步：

1. 用 openpyxl 把清单导出读全，按清单锁定本期范围（其余项明确写出归属，不漏不扩）。
2. 按「清单定范围、PRD 定规则、原型定展示」生成 Spec 初稿，冲突和缺失全部编号记录。
3. 跑三轮澄清：带推荐项提问 → 对抗审查 → 最终扫描，每轮结论回写 Clarifications。
4. 交付前自查：引用编号一致（Q1~Q7 统一）、无残留旧路径、口径全文统一。

写单文件 HTML 回顾页/原型页时，套「数据数组 + 渲染函数 + 事件委托」结构，发布前跑上面的三步质量门。
