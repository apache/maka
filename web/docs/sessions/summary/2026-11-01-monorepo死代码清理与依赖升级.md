# console 大仓死代码清理与依赖升级实战

**一句话总结**：pnpm monorepo 全仓死代码清理（净 -5147 行）+ 依赖全量刷新 + 摘除外层仓 11 个裸 gitlink，全程用「可达性分析 + 三重闸门」保证功能零回归。

## 背景

接手一个 7 apps + 10 packages 的 pnpm monorepo（约 11 万行），需要大规模削减代码且不能破坏功能；顺带核实"TS8 出了没"、刷新全部依赖版本，并解决 VS Code 源控里嵌套仓库常年显示 M、容易被误提交的问题。

## 核心命令

```bash
# 核实"某版本到底出没出"：看 dist-tags 的 latest（canary/beta 不算稳定版）
npm view typescript dist-tags --json

# pnpm monorepo 全仓过时依赖盘点
pnpm outdated -r --format list

# 范围内全量刷新到最新（^ 允许的 minor/patch 一次到位）
pnpm update -r

# 0.x 包的 ^ 锁死 minor（如 oxfmt ^0.70 拿不到 0.74），必须手改 package.json 范围
# 全局工具（pnpm）升级后还要同步改项目 package.json 的 packageManager 字段
npm install -g pnpm@12.15.0

# 查外层仓登记的裸 gitlink（嵌套仓指针，mode 160000）
git ls-files -s | awk '$1==160000'

# 摘除指针：只删外层登记，内层仓磁盘与 .git 完全不动（可从 git 历史恢复）
git rm --cached -- <目录>

# 验证 .gitignore 规则是否真的生效（白名单制改完必跑）
git check-ignore -q <path> && echo 已忽略

# 改动后的标准闸门（影响面相称的验证）
pnpm typecheck && pnpm test && pnpm style:check && pnpm --filter <app> run build
```

## 关键结论

1. **核实版本只认 `npm view <pkg> dist-tags`**。TypeScript 8 不存在（`npm view typescript@8` 直接 404），传说的"Go 重构"就是 TS7 本身；next/react/tailwind 当时也全在 latest。canary/beta/dev 标签是预发布通道，不算数。
2. **判死代码靠"可达性"不靠引用计数**。knip 只报零引用的根，整簇传递性死文件（barrel→registry→adapter 链）会漏报；自建 BFS 从路由/instrumentation/CLI 入口遍历 import 图才准。四个解析坑必须修对，否则整包误判：`.jsx` 路由入口、`@` 别名（tsconfig paths）、`.js` 后缀实际指向 `.ts` 文件（NodeNext 风格）、package.json exports 子路径键没去 `./` 前缀。每簇删除前仍要 rg 人工复核——人工核实拦下了两个整包误判。
3. **fetch 只 `.catch()` 不检查 `res.ok` 是一类静默 bug 的根因**（本仓实例：确认流路由打错，404 后干等 120 秒超时）。解法是统一 `apiFetch`：检查 ok + 解析错误封套 + 抛 `ApiRequestError`，全部客户端 fetch 收编到这一个入口。
4. **pnpm 10+ 跟随项目 packageManager 字段自动切换版本**：全局升级后 `pnpm -v` "没变"，是字段还钉着旧版。升级两件套 = `npm i -g pnpm@新` + 改 package.json 的 `packageManager`。另外 pnpm-workspace.yaml 的 `allowBuilds` 值必须是真布尔，写了占位文本任何 install 都报 `ERR_PNPM_IGNORED_BUILDS`。
5. **白名单制 .gitignore 摘 gitlink，摘链后必须在尾部补后置忽略规则**（gitignore 后者优先，压过前面的 `!` 放行），否则整个嵌套仓立刻以未跟踪身份重新刷屏。跨主版本升级（motion 14 / dotenv 18 / googleapis 188）先升后跑全量闸门，红了就回退（react-table v9 因 3 文件 42 处 API 破坏回退 8.x，留待真迁移）。

## 下次怎么用

- pnpm monorepo 依赖升级标准流程：`pnpm outdated -r` 盘点 → 0.x 包手改范围 → `pnpm update -r` → typecheck + 全量测试 + 各 app build 全闸门 → 红了单独回退那个包。
- 大规模删代码前：先跑可达性分析（或至少 knip + 每簇 rg 复核），删完跑全量闸门，按批次留 git 可回滚。
- VS Code 源控里嵌套仓库常年显示 M：`git ls-files -s | awk '$1==160000'` 确认是裸 gitlink → `git rm --cached` 摘指针 → .gitignore 尾部补忽略 → `git check-ignore` 验证。
- 怀疑"某库出新大版本了"：`npm view <pkg> dist-tags --json` 一锤定音，不看博客传闻。
