# Git 同步冲突解决与转义补丁落地

**一句话总结**：本地有未提交改动时安全拉远程的固定套路（摸底→stash→快进→pop→证据定序解冲突），外加中文文件名补丁的字节级解码方法和多会话并行时防裹挟的提交技巧。

## 背景

个人仓在 Mac / Windows 两台机器、多个 AI 会话并行写同一批 Markdown 台账，经常遇到：拉取时本地有未提交改动、同一天同一文件两边各写了一段日记、提交时暂存区里混着别的会话的文件。这次把三类问题都处理顺了。

## 核心命令

```bash
# —— 拉取前摸底：本地改动与远程改动是否重叠 ——
git fetch origin
git diff --name-only                    # 本地未提交的文件
git diff --name-only main origin/main   # 远程新提交动过的文件
# 交集为空可直接快进；有交集则 pop 时大概率要手工解冲突

# —— 本地有未提交改动时的安全拉取三步 ——
git stash push -m '说明'         # 1. 暂存本地改动
git merge --ff-only origin/main  # 2. 只允许快进，不产生合并提交
git stash pop                    # 3. 恢复改动；冲突文件标 UU

# —— 冲突解完的收尾 ——
git add <解决后的文件>
git stash drop                   # pop 成功后清掉暂存记录

# —— 中文路径不转义显示（默认变八进制乱码）——
git -c core.quotePath=false status --short

# —— 多会话并行时只提交自己的文件，不裹挟别人暂存的改动 ——
git -c user.name=<名字> -c user.email=<邮箱> commit -m 'msg' -- <文件1> <文件2>

# —— 补丁先演练、后验证 ——
patch -p1 --dry-run < fix.patch      # 全部干净才真应用
patch -R -p1 --dry-run < fix.patch   # 应用后反向演练，退出 0 = 落盘内容与补丁逐字一致

# —— 中文文件名被八进制转义的补丁，解码出可用副本（必须字节级）——
python3 - <<'EOF'
import re
data = open('fix.patch', 'rb').read()
pat = re.compile(rb'\\(\d{3})')
out = []
for line in data.split(b'\n'):
    if line.startswith((b'diff ', b'--- ', b'+++ ')):
        line = pat.sub(lambda m: bytes([int(m.group(1), 8)]), line)  # 八进制→原始字节
        line = line.replace(b'"', b'')                               # 去 git 引号包裹
    out.append(line)
open('fix-decoded.patch', 'wb').write(b'\n'.join(out))
EOF

# —— 动手前的备份、事后审计 ——
tar -czf backup.tar.gz <目录>                 # 改目录前先打包
git show --name-only --format='' <sha>        # 某次提交到底包含哪些文件
git ls-files -s <路径>                        # mode 160000 = 子模块指针(gitlink)
git check-ignore -v <路径>                    # 文件被哪条 ignore 规则挡的
```

⚠️ `rm -rf <目录>`：只有先证明目录里没有独有数据（对照 `git ls-tree -r <旧提交> -- <路径>` 与 find 全量清单）之后才能删，删除前先列出「除 .DS_Store 外的全部文件」确认为空或已迁移。

## 关键结论

1. **冲突定序靠证据不靠感觉**：GitHub 评论 ID 全局递增，帖号 645xxx 必早于 646xxx；同一文件两段日记谁前谁后，拿行内锚点数字一锤定音，「上轮已定性」这类交叉引用也是时间序证据。
2. **冲突块会吞行尾换行**：解完两行表格粘成一行，肉眼难发现；用「单元格数是否与邻行一致」这类结构校验来抓（本次 13 格 vs 邻行 6 格暴露问题）。
3. **patch 对八进制转义中文文件名无能为力，且失败是交互式跳过、不是报错**；解码必须字节级（rb 读、bytes 写），按 str 解码会产出双重编码乱码。
4. **管道吞退出码**：`python3 x.py | tail; echo $?` 拿到的是 tail 的退出码；要判断脚本成败写 `> log 2>&1; echo $?`。
5. **子模块指针（gitlink）会被别的机器用旧基线悄悄回退**——子仓内容没丢，只是外仓记录旧了，下次提交 `git add <子模块路径>` 即可恢复指针。

## 下次怎么用

- **每次拉取**：摸底三连（fetch → 两个 diff 求交集）→ 交集空直接快进；非空走 stash 三步，pop 后按「帖号 / 交叉引用」定序解冲突，解完 `grep -c '^<<<<<<<' <文件>` 确认无残留。
- **应用外部补丁**：tar 备份 → dry-run →（中文路径先字节级解码）→ 应用 → 反向 dry-run 验证逐字一致。
- **多会话并行**：提交一律带 pathspec（`commit -- <文件>`），提交后 `git show --name-only` 复核没裹挟别人的文件。
