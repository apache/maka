# git 本地文件锁与行尾僵尸坑排查

**一句话总结**：用 `skip-worktree` 把本地专属文件（AGENTS.md/tsconfig/lock）锁在更改列表外，以及 pull 报「local changes」但 diff 为空时的行尾僵尸解法。

## 背景

本地维护着几个不想入库的专属文件（个人版 AGENTS.md、本地 tsconfig、package-lock），它们一直挂在源代码管理的更改列表里，既碍眼又容易被顺手提交；另外拉远程时 package-lock.json 报「local changes would be overwritten」，但 `git diff` 却是空的。

## 核心命令

```bash
# 只 stash 指定文件的本地改动，不碰暂存区里其他文件
git stash push -m "个人本地改动" -- .gitignore AGENTS.md tsconfig.json

# 从 stash 只恢复指定文件（注意：会把内容写进暂存区，之后要 restore --staged 退掉）
git checkout "stash@{0}" -- .gitignore AGENTS.md tsconfig.json

# 给已跟踪文件设本地锁：改动不入库、不出现在更改列表
git update-index --skip-worktree AGENTS.md tsconfig.json package-lock.json

# 查看当前所有锁（skip-worktree 的标记是大写 S）
git ls-files -v | grep "^S"

# 解锁单个文件（远程真改了它、需要合并时用，处理完再锁回）
git update-index --no-skip-worktree AGENTS.md

# pull 报 local changes 但 diff 为空时，先试强制刷新索引
git update-index --really-refresh -- package-lock.json

# 刷新无效就删掉本地文件让 merge 重新 checkout（lock 类文件可随时由 git 生成，低风险）
rm package-lock.json && git pull

# cd 进仓库会触发 fnm 钩子报错并截断 && 链，git 操作一律用 -C 绕过
git -C "E:\仓库路径" stash push -m "说明" -- 文件

# eslint 8 启动即崩（v8-compile-cache 把 ESM 的 .mjs 当 CJS 编译）时的绕过
DISABLE_V8_COMPILE_CACHE=1 npx eslint 改动的文件...

# node_modules 半截安装（包缺 main 文件、.bin 为空）时补装
npm install --ignore-scripts --no-audit --no-fund

# 全量 tsc 输出落文件，只统计 src 下的报错行数（node_modules 的 @types 噪音不算）
npx tsc --noEmit -p tsconfig.json > /tmp/tsc-out.txt 2>&1
grep -cE "^[^ ].*src[\\/]" /tmp/tsc-out.txt

# 按目录统计代码行数（git 跟踪文件，grep 排除他人负责的目录）
git ls-files "src/pages/模块" | grep -E "\.(ts|tsx|scss)$" | grep -vE "排除模式" | xargs wc -l | tail -1
```

## 关键结论

1. **本地专属文件的正解是 `skip-worktree` 锁**，不是 .gitignore（对已跟踪文件不生效）。锁之后：本地内容一直生效、更改列表干净、不会被顺手提交。坑有三个：`git restore --staged` 会清掉锁位，恢复暂存后要重设；`git checkout <tree-ish> -- <file>` 会顺手把内容写进暂存区，之后要退暂存；远程真改了被锁文件时 pull 会报冲突，走「解锁 → 合并 → 锁回」。
2. **pull 报「local changes would be overwritten」但 `git status`/`git diff` 全空 = 行尾僵尸**。根因是 `core.autocrlf=true` 加远程重写过该文件（这次是 lock 全量重建，±1.7 万行），行尾归一化让 git 误判有本地改动。`update-index --refresh` 和 `checkout --` 都无效时，直接删文件再 pull，让 merge 从远程 blob 重新 checkout。
3. **eslint 8 启动即崩的根因链**：node_modules 半截安装（包的 main 文件缺失）→ 补装后仍崩 → 是 v8-compile-cache 在新版 Node 下把 ESM 的 `require.mjs` 当 CJS 编译。不用修依赖，`DISABLE_V8_COMPILE_CACHE=1` 前缀绕过即可，代价只是 eslint 启动慢一点。
4. **`cd` 进仓库触发 fnm 钩子报错会截断 `&&` 命令链**（退出码非零，后半条根本没执行），git 操作改用 `git -C <路径>` 形式最稳。
5. **写提交文案前先 `git log --oneline -20` 看自己既往风格**（如 `type(scope): 动宾短语并列成果`），比现编更统一。
