# 创建表单默认值与验收

## 一句话结论

创建表单默认值应按字段的实际状态来源设置。首次进入、修改后重置、编辑回显各自需要有区分度的样本。单次页面观察能确认现象，根因和请求是否发出还要有各自的证据。

## 可复用经验与案例

### 默认值未选中时，对比首次加载和稳定后的重置

康养活动创建页的「收费」「获取积分」由 Form 字段管理，「是否配置签到设备」由组件 state 控制。对话中的浏览器结果显示，挂载时执行 `setFieldsValue` 后前两项仍未选中，页面稳定后点「重置」执行同类赋值，两项都变成「否」。改用 Form `initialValues` 后，从列表重新进入创建页，三项均选中「否」，依赖这些选项的子字段未显示。依据为 `activeMain/addOrEdit/index.js` 的 Edit 结果，以及浏览器 `evaluate_script` 两组 `before/after`、`加载后/点重置后` 输出。

该页使用随机 key，重挂载可能参与了赋值丢失。对照实验证实绑定可以工作、不同入口的赋值结果有差异，未隔离验证随机 key 是否导致 Form 值丢失。归档采用这组对照作为排查手法。历史回归在默认态直接点了重置，编辑样本也恰好三项均为「否」，因此仍缺少相反值样本及切换后的提交参数验证。

### 口径对照与拦截证据各看一层

列表卡的已报名数读取活动行 `willnum`。浏览器实测某活动的场次人数是 `6 / 6 / 7`，列表行返回 `6`。这足以排除用场次求和直接替代列表字段，也说明用首场样本无法覆盖后场人数较大的情况。活动级字段的通用计算规则未获确认。依据为列表与场次的 `evaluate_script` 结果，以及 `activeMain/content.js` 卡片渲染片段。

前端临时限制曾显示内联错误，随后用户说明后端已修改，并要求将该前端限制 stash。指定文件的 stash 有命令输出佐证。后端校验未做本轮实测，`fetch` 单点打点也不足以独立证明更新接口没有请求。后续如需验收此类限制，可复用隔离响应或写请求拦截。历史回归为验证前端提示给共享测试活动留下了报名数据，这一步无需复用。
