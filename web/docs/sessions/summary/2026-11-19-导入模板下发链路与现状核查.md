## Skill 增量建议

### 候选 1（建议采纳）：需求点名"加交互"时先核实现状

**位置**：gua-dev-tools `SKILL.md` 通用铁律「先读后改」条，追加半句。

**现有缺口**：「先读后改：沿真实入口、调用方和失败路径读完再动手」只约束"读"，没约束"读完发现现状已满足需求怎么办"。本对话反例：读了 BatchDeleteModal 全文、亲眼看到已有 `Modal.confirm` 二次确认，仍字面执行"增加一个二次弹窗"嵌套加层，被用户撤回（"其实我之前是有二次弹窗，请撤回你的修改"）。

**建议文本**：在「先读后改」后追加：「需求点名要加的交互/能力若现状已存在，先摆现状给用户再定加不加层，不字面执行"加"字」。

## 可复用经验与案例

### 模板/文件类"替换"需求的排查三步（本次验证有效）

1. **追前端消费方式**：`rg -n "templateUrl|templateName" src/<模块>`，找到消费组件与取值来源（本次：ImportTableModal props 透传，无列头硬编码）。
2. **追下发接口**：取值函数一路读到 HTTP 层（本次：`utils.js` 的 `getTemplateData` → `public/fileTemplate/getByBizCode?bizCode=`）——下发在后端，文件替换就不是前端改动。
3. **改文档不改码**：把"待后端登记 + 复验条件"落进需求正本文档挂账行（本次改了接口定义.md B-7 段、前端开发进度.md 两处 ⏳ 行），前端 diff 为零是合法交付。

### xlsx 模板缺陷的验证点（B-7 复验用）

拿到新模板先读表头与示例行，核对三症状：表头是否单行、第 2 行是否表头与示例混排、有无合并单元格——B-7（2026-11-12 实测）即"解析器把示例行当数据行导入"（id=714「某某」）。1113 版两文件三症状均消除；**待后端登记 fileTemplate 后才能在 itest 复验下载与真实文件导入**，静态核对不替代联调。

### 群消息拟稿的边界（关联已有记忆）

向产品/后端询问配置入口属合法开放问题，但 MEMORY.md 已有 product-question-single-decision（只问单一裁决点、既成事实不是开放问题）——拟稿前先过一遍：已实现的行为不要再作为问题问出。

## 常用命令

```bash
# 读 xlsx 模板的表头与示例行（验证表头错位类缺陷、比对模板版本）
# 前提：python 装 openpyxl；Git Bash 下路径用原始字符串或正斜杠
python -c "
import openpyxl
for f in [r'C:\path\to\模板A.xlsx', r'C:\path\to\模板B.xlsx']:
    wb = openpyxl.load_workbook(f)
    print('===', f, 'sheets:', wb.sheetnames)
    for ws in wb.worksheets:
        print('--sheet:', ws.title, 'dims:', ws.dimensions)
        for row in ws.iter_rows(min_row=1, max_row=3, values_only=True):
            print(row)
"
# 成功信号：逐 sheet 打印维度与前 3 行元组（None=空单元格）；
# 副作用：只读打开，不修改文件；带 * 前缀的表头=模板必填列
```
