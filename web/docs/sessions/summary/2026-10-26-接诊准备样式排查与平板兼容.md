# 接诊准备样式排查与平板兼容

**一句话总结**：修完接诊准备模块一批走查样式（页签灰色态、吸顶设备条漏出、间距、头像投影），并定位了小米平板 4 上详情页顾客卡被压成一行高的根因（固定高度 flex 滚动容器 + 旧内核 WebView），顺手补了「子页面返回不刷新数据」的交互 bug。

## 背景

Taro 3 + React 的接诊准备模块（H5/小程序双端）走查出一批样式问题；另有一个后端同事在安卓小平板（小米平板 4，Android 8.1 旧内核 WebView）上反馈的「详情页顶部顾客卡塌成一行、年龄段/标签消失」的兼容问题，以及「修改客户档案后返回数据不刷新」的问题。

// 注意：Taro hash 路由若触发整页刷新，钩子会丢、需重装；chrome-devtools 的 initScript 可跨刷新存活
window.__reqLog = [];
const origFetch = window.fetch;
window.fetch = function (input) {
  const url = typeof input === 'string' ? input : input && input.url;
  const p = origFetch.apply(this, arguments);
  if (String(url).includes('<关键字>')) {
    const entry = { url: String(url), body: null };
    window.__reqLog.push(entry);
    p.then(r => r.clone().text().then(t => { entry.body = t.slice(0, 4000); }));
  }
  return p;
};

## 关键结论

1. **Taro 固定高度 flex 滚动容器必须给子项 `flex-shrink: 0`**。详情页根节点是 `flex column + height: 100vh + overflow-y: auto`，子项默认 `flex-shrink: 1`：内容总高一旦超过一屏，flex 先把子项压扁到刚好塞下（连滚动条都不出现），顾客卡塌成一行、内容下溢被下一张卡盖住。手机内容不溢出不触发；旧安卓 WebView（Android 8.1 系统内核，2018 年后不再更新）的 `min-height: auto` 内容兜底不可靠，压得更狠，所以只有平板坏、桌面和手机都复现不了。修法：给顾客卡补 `flex-shrink: 0`（卡片页早有同类免疫 `.content > * { flex-shrink: 0 }`，详情页漏了同款口径）。
2. **Taro H5 的 rpx→rem 根字号有钳制**：`config/index.js` 里 `pxtransform.maxRootSize/minRootSize`（本项目 26/20）。屏宽超过 `maxRootSize/40×750 = 487.5px` 后根字号恒为 26px，rem 内容最大渲染约 487px 逻辑宽——平板上「不满屏、两侧留白大」只是观感问题，与布局 bug 无关，不要混为一谈。
3. **Taro 子页面返回不触发重新挂载**：`navigateTo` 压栈后返回，页面组件不卸载，`useEffect` 不重跑 → 数据不刷新。修法：hook 里补 `useDidShow(() => { if (customerId) reload(); })`（项目内 workBench/deviceCenter 已有同款先例）。TDD 口径：先在桩里收 `useDidShow` 回调断言 reload 被调（红），再补实现（绿）。
4. **设计还原数值不目测**：颜色用截图 GetPixel 采样 + 区域直方图；间距/层级用 Figma REST 拉节点 JSON 读 autolayout `itemSpacing`/`padding`。注意 `homing_token` 只用于 COS 上传凭证，调 Figma API 必须用 `.env` 里的 `FIGMA_TOKEN`。
5. **样式回归锁模式**：模块 `tests/` 下用结构断言锁 SCSS 关键规则（读源码 assert 选择器/属性），改样式前先改测试跑红、再改样式转绿；测试文件只存本机、永不进暂存区。反过来，接手存量测试先跑一遍分清「预存失败」与「本次引入」——本次用 `git stash` 单文件改动后复跑同崩溃，证明失败与改动无关。
