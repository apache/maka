# 孤儿快照仓重构合流经验（cc 私仓 11-08~11-16 三轮同步）

## 一句话结论

远程被重置为孤儿快照后做过一次 ~1.2 万文件的大目录重组（`code/`+`web/` 新布局 + 扩展名禁入政策），本地合流不能信任 worktree 现状与 `-X theirs`：以 `ls-tree -z` 内容哈希为准做双向分类，合并后必须对三方各核验一次文件数，否则会静默丢本地独有文件（本次实测丢了 15448 个，靠备份分支找回）。

**gua-dev-tools `SKILL.md` 通用铁律追加一条**（与既有 wsl.exe UTF-16 陷阱同类，Windows+中文路径环境陷阱）：

> 处理含中文路径的 git 仓时，grep/统计 `ls-tree`、`status`、`diff` 的文本输出会因路径引号化（core.quotepath）整行漏配——含非 ASCII 的行以 `"` 开头。判定"某路径在不在某树"一律用 `git ls-tree -r -z` + 字节级比对（python），或临时 `-c core.quotepath=false`；禁止用 `grep '^前缀/' | wc -l` 下结论。

- 现有规则缺口：通用铁律只有 wsl.exe 一条环境陷阱；本次会话实测 grep 误判（grep 得 web/ = docs 2115+scripts 18+temp 3 ≈ 2136，字节级实际 web/ 共 5576，`web/senior` 等中文路径整类漏配），直接导致一轮错误结论与返工。
- 检验场景：`git ls-tree -r --name-only HEAD | grep -c '^web/'` 与 `git ls-tree -r -z HEAD` 字节统计对比，两者应一致而 grep 法偏小。
- 路由边界：git 仓库手术/多分支同步经验**不进** gua-dev-tools 模块（它是前端交付工具箱，bug 模块管业务缺陷）、不进 gua-pr-patch（cc 是自有私仓非 fork 贡献）、不进 gua-writer——本文即独立归档位置。

## 可复用经验与案例

### 1. 半成品合并的识别签名（另一会话留下的烂摊子）

特征三件套（本次 11-14 会话产物实测）：① HEAD 树文件数远大于远程（29600 vs 13513，胖树=两侧并集，旧路径没删）；② `git status` 数千个**未暂存** `D`（改了磁盘没进提交）；③ 工作树与远程双向不齐（磁盘缺远程新路径 13467 个，又多出旧路径 14168 个）。处理：先 `reset --hard` 回到一致的 HEAD，再按下方分类法重建，绝不基于半成品 worktree 做判断。

### 2. `git merge -X theirs` 大合并会静默丢己方新增（最重要反例）

胖树（含大量旧路径副本）合并进已重组的远程时，重命名探测把"远程删了旧路径+加了新路径"与"本地在旧路径有同内容文件"配对成 rename/modify 冲突，`-X theirs` 一律取远端 → 本地 15448 个独有文件从合并结果中消失（结果树 = 远程 13513 + 仅 39 个幸存；对本地父提交 diff 显示 16082 D + 13428 R100）。机制解释属推断（基于 rename/modify 冲突解析行为，未做最小复现实验）；**防御动作是硬规则**：合并后必查 `git diff --raw <远程> HEAD` 的 A/M/D 计数与 `ls-tree | wc -l`，与预期保留清单对账。

### 3. 内容哈希分类法（孤儿快照/大重构合流的通用流程）

1. `git ls-tree -r -z` 两侧树 → path→blob 映射（字节级，避开引号陷阱）；
2. 己方独有路径分四类：**blob 在对侧存在**=纯改名重复（删）；**同名路径存在但内容不同**=同路径冲突（按政策取远端）；**改造名目标碰撞**=目标被对侧占用的搬迁项（弃用己方，备份保留）；**其余**=真独有（保留/搬迁）；
3. 被对侧"改名+改内容"取代的旧版（R09x 证据）删除；对侧整体弃用但本地仍要的（课程 zip、私有仓、工作目录）保留。
本轮三轮实战：11-08 判 1220 重复/39 独有；11-16 判 14078 重复/15448 独有/21 跳过，全部零内容损失。

### 4. 本仓工作流约定（用户明确决策）

- `main` 以远程为准（`reset --hard origin/main`），日常在 `develop`（跟踪 `origin/develop`）；
- 同步前必建 `backup/<说明>-<日期>` 分支 + 关键未提交改动进 stash，双保险；
- 远程新布局带白名单式 `.gitignore`+扩展名兜底（`*.log/*.zip/*.exe/*.crx/*.mp4` 等禁入，防 GitHub 100MB；develop 对这些扩展零跟踪）——恢复/搬迁文件前先 `git check-ignore -v`，被禁入的文件保持磁盘+备份分支双保险，不强行入库。

## 常用命令

均为本会话实际执行且有可见结果；中文路径场景一律配 `-z`/`--pathspec-file-nul`。

```bash
# 1. 树规模与三方对账（合并后必跑；A/M/D 计数与保留清单对账）
git ls-tree -r HEAD | wc -l
git diff --raw origin/develop HEAD | awk '{print $5}' | sort | uniq -c

# 2. 可靠的树比对原料（字节级，中文路径不引号化）
git ls-tree -r -z origin/develop > /tmp/dev.bin   # python 按 \0 切分，\t 前取 blob

# 3. 大批量恢复：从备份分支按清单恢复（暂存+工作树一步）
git restore --source=<备份分支> --staged --worktree \
  --pathspec-from-file=<清单.bin> --pathspec-file-nul

# 4. 大批量删除/冲突收尾
git rm -q --pathspec-from-file=<清单.bin> --pathspec-file-nul
git diff --name-only -z --diff-filter=U | xargs -0 git checkout --theirs -- && \
git diff --name-only -z --diff-filter=U | xargs -0 git add --

# 5. 判定文件为何加不进暂存（命中哪条 ignore 规则）
git check-ignore -v <路径...>

# 6. 本机代理端口探测（git 全局代理 127.0.0.1:7897；代理未开时 fetch 报错、绕代理直连会挂起）
timeout 10 bash -c "</dev/tcp/127.0.0.1/7897" && echo OPEN || echo CLOSED
```

副作用说明：#3 会同时改暂存区与工作树；#4 第一条对 modify/delete 冲突取远端版本，执行前确认清单；#6 为只读探测。

## 待验证与不适用边界

- **-X theirs 丢文件的机制**（重命名探测配对 → rename/modify 冲突 → theirs 丢弃改名目标）是行为推断，未做最小复现实验；防御性核验（三方对账）不依赖该解释成立。
- **绕代理直连 GitHub 挂起**是单次环境观察（已终止后台任务），非系统性结论。
- 内容哈希分类对**二进制同名不同版**只判"独有/重复"，不判新旧——同名路径冲突一律远端赢，本地版仅在备份分支可回，是否该回是人工决策（如 win/mac 双机同日各自写的 journal 编年条目）。
- 1216/1220 等具体数字是本轮快照事实，不是常量；复用的是分类流程。
