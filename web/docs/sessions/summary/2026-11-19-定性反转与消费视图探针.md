## 可复用经验与案例（执行反例，规则已存在，勿堆同义规则）

### 反例 1：判别器已晋升但定性时未跑——#6266「非回归」定性被反驳

- **经过**：报告者称「v8 迁移丢失全局流式缓冲字段」。我核实字段/消费方/作用域测试都在，发「非回归」定性评论。yueziji（CONTRIBUTOR）反驳：两拼写进共享视图 `cfg.Codex` 都对，但过 `cfg.ForAPIKey()`（API-key 执行器的真实视图）后 v8 拼写丢 buffering/timeout；我引的作用域测试只用 legacy 拼写断言。复现坐实，修复开 PR #6270（TDD 红→绿，+37/-0，上游 CI 三查绿），issue 公开认错。
- **对应规则**：fix-direction.md 被拒型判别器「等价未逐变体实测：声称两种写法、拼写或路径等价，每种各测过吗？按命名空间推断归属，查过真实的消费视图吗？」——两个子问都命中：只测了 legacy 拼写路径 + 按 `oauth.providers.*` 命名空间推断作用域、没查 `ForAPIKey()` 消费视图。
- **可执行教训**：定性评论发出前把被拒型判别器过一遍；「作用域测试证明 X」必须确认测试覆盖了被讨论的拼写路径（测试锁定的是它测的那条变体，不是语义本身）；探针对象=消费方拿到的视图，不是共享数据结构。认错闭环本身做得对：评论→复现→认领→修复一轮完成，未过夜。

## 常用命令（本会话实际执行、有可见结果；Windows Git Bash，gh 完整路径 `"C:\Program Files\GitHub CLI\gh.exe"`）

### 1. 在途 PR 定性审计（区分「等审」与「真红叉」）

```bash
GH="C:/Program Files/GitHub CLI/gh.exe"
"$GH" api "repos/<owner>/<repo>/commits/<head_sha>/check-runs?per_page=100" \
  --jq '[.check_runs[] | select(.conclusion != "success" and .conclusion != "skipped" and .conclusion != null) | "\(.name):\(.conclusion)"] | "bad=\(.)"'
```
- 前提：gh 已认证；`<head_sha>` 用 PR head 完整或前 8 位。
- 成功信号：`bad=[]` = 该 head 无失败 check，blocked 属等审；有输出则逐项看是政策守卫还是测试红。
- 副作用：只读。坑：`--jq` 后只能跟一个参数——`--jq --arg sha "$s" '...'` 会报 `accepts 1 arg(s), received 4`（本会话第一版踩过），把变量拼进查询串或用双引号字符串。

### 2. 逐条 PR 批查（防列表分页漏单）+ 双端点评论扫描

```bash
for n in <PR号列表>; do
  "$GH" api "repos/<owner>/<repo>/pulls/$n" --jq '"PR \(.number) state=\(.state) ms=\(.mergeable_state // "?") head=\(.head.sha[0:8])"'
  "$GH" api "repos/<owner>/<repo>/issues/$n/comments" --jq '[.[] | select(.user.login!="<me>" and .user.type!="Bot")] | length'
  "$GH" api "repos/<owner>/<repo>/pulls/$n/comments" --jq '[.[] | select(.user.login!="<me>" and .user.type!="Bot")] | length'
  "$GH" api "repos/<owner>/<repo>/pulls/$n/reviews"  --jq '[.[] | select(.user.login!="<me>" and .user.type!="Bot" and .state!="PENDING")] | length'
done
```
- 成功信号：评论计数与历史基线一致 = 无新人工反馈；`issues/{n}/comments` **不含**行内 review 评论，必须三端点都扫（journal 维护Ⅵ 定性过此盲区）。
- 副作用：只读，每 PR 4 次调用（认证后限额充足）。

### 3. Go 测试免 cd 直跑指定仓（Go 1.21+）

```bash
go test -C "E:/<某仓路径>" -p 2 -run "TestPattern" -v ./internal/<pkg>/
```
- 前提：Go 1.21+；`-p 2` 防本机全并发编译器崩。
- 成功信号：`ok  <module>/<pkg>`；`--- FAIL` 带行号。
- 副作用：只写测试缓存；配合 `-run` 定向跑，绕开 flaky 大包。
- 说明：本会话在主仓与 cpa-pr1 子仓探针均用此形式成功，替代 `cd` 链（fnm/沙箱语境下 cd 链有截断前科）。

### 4. gofmt 真格式判定（CRLF 法，最终有效版）

```bash
tr -d '\r' < "<file>" > /tmp/fmt_check.go && gofmt -l /tmp/fmt_check.go
```
- 成功信号：无输出 = 格式干净（本机 `core.autocrlf=true` 下对原文件直跑 gofmt 会全文件假阳性）。
- 副作用：只读原文件，写一个临时文件。

### 5. 占坑搜索（某 issue 是否被在途 PR 覆盖）

```bash
"$GH" api "search/issues?q=repo:<owner>/<repo>+is:pr+<issue号>" --jq '.items[] | "\(.number) \(.state) \(.title[0:60])"'
```
- 成功信号：空输出 = 无占坑 PR；有输出逐条核对正文是否 `Closes #<issue号>`。
- 副作用：只读。坑：URL 编码由 gh 处理，`+` 分隔符照写即可。
