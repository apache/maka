## 可复用经验与案例

### 制品库不是 git 仓

`https://cnb.cool/clife/npm` 的 `git ls-remote` 为 Not Found。现有访问令牌打制品库接口返回 errcode 10023（scope 不匹配）。要每个包最新版一个 tgz，不要下历史版本。

已验证的下载路径（已登录浏览器，cookie 不外带）：

1. 列表页 SSR 忽略 `?page=`，永远第一页。改请求 `GET https://cnb.cool/clife/npm/-/web-packages?type=npm&page=N&page_size=100&ordering=-last_push_at`，头 `Accept: application/json`。当时 page1=100、page2=9，共 109。
2. 页面上的 href 是 `https://cnb.cool/110?url=...tgz`，这是外链确认页。`fetch` 得到 HTML，不下文件。程序化 `<a>.click()` 也会进确认页。
3. 真正的文件地址是 `/{slug}/-/packages/{type}/{package}/-/tag/{tag}/-/file/{filename}`。页面内 `fetch`（带 cookie、跟随重定向）落到 `npm.cnb.cool/download/{hash}`，gzip 魔数 `1F 8B`，大小与清单一致。hash 一次性，无 cookie 再请求是 410。直链顶层导航是 401。
4. tgz 文件名丢掉 scope：`@agri-base/utils` 对应 `utils-1.0.33.tgz`。落盘目录 `E:\Projects\clife\npm`，109 个文件，抽查包名与清单一致，无重名。Chrome 批量下载会先写 `uuid.tmp`，曾把一个包存错名，按大小改回。

`cnb/npm.py` 仍按 git 浅克隆写，对制品库无效。用户没有要求改成下载器。

## 常用命令

前提：Windows PowerShell；公司仓；不把令牌写进 remote 或命令行。下面只保留本对话有可见成功结果的最终形式。

直连探测，绕过本机死代理，不改配置：

```powershell
git -c http.proxy= -c https.proxy= ls-remote https://cnb.cool/<group>/<repo> refs/heads/master
```

成功信号：打印 `<sha> refs/heads/master`。副作用：只读，不更新本地。失败信号是 `over proxy` 或 `Failed to connect`，说明代理没清掉。

本地补上单条 fetch refspec（不提交）：

```powershell
git config --add remote.origin.fetch "+refs/heads/<name>:refs/remotes/origin/<name>"
git switch -c <name> --track origin/<name>
```

成功信号：`checkout --track` 不再报 `is not a branch`。副作用：只改该仓本地 config 和检出。工作区脏或用户没点名要切时不要 switch。

判断 shallow 边界是不是误伤（只读）：

```powershell
git rev-list --parents -n 1 <boundary>
git cat-file -t <parent>
```

父对象类型能打出来，该行是误伤；`cat-file` 失败，该行是真浅克隆，保留。⚠️ 删 `.git/shallow` 里父对象缺失的行会让 Git 去要不存在的历史。本轮没有对 admin 做删除。

失败、不要当成有效命令：经 `127.0.0.1` 代理的 `git fetch`；对完整历史再 `git fetch --depth N`；无 cookie 去请求已经用过的 `npm.cnb.cool/download/{hash}`（410）；`fetch` 页面上的 `/110?url=` 链接（HTML）。
