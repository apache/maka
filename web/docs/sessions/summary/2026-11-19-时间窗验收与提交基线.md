# 时间窗验收与提交基线

## 一句话结论

精确到时刻的规则用同一天的截止前后样例验收，补丁去向用开工时的 Git 基线核实。

## Skill 增量建议

### 操作窗口的边界样例

在 `gua-dev-tools/modules/quality/references/test.md` 的「验证设计」第 2 条后补一句。现有规则要求最小输入输出用例和 UI 验收，尚未约定时间窗取点。适用于有明确开放或截止时刻的操作。

> 标明窗口两端是否包含，选当天非零点的截止时刻，用受控 `now` 验证截止前、等于截止和截止后。再用真实行的时间字段和页面时钟核对按钮状态与禁用提示。

证据是 11-03 的 Day.js 输出。截止为 16:00，15:59 放行，16:01 过期。建议检验（未执行）是同一组样例对照旧版按 `day` 比较与新版按时刻比较，并断言 16:00 按当轮规则仍放行。

### Git 归因使用开工基线

修订 `gua-dev-tools/modules/bug/MODULE.md`「平台机制优先于业务代码」中 `git show HEAD:<file>` 的归因条目。它把当前 `HEAD` 当成接手前版本，在共享工作区有人提交时会失准。

> 需要归因时，保留开工 SHA 和目标文件已有的差异。收尾若发现 diff 消失，先查暂存区，再核对开工 SHA 以来的提交及目标文件补丁。操作人以可核验的操作记录为准。

当轮报名页 diff 消失且暂存区为空，`git log` 出现 `724f3d13`，`git show HEAD~1..HEAD --stat` 只列报名配置，盘上仍有新版判断。建议检验（未执行）是用同一份初始补丁分别模拟暂存、提交、撤回，判断三种情况下的补丁去向。

## 可复用经验与案例

- **补签时限**。当轮 68090 实际返回 `activityEndTime`，开始字段缺失时按已确认口径回退到 `activityDate` 零点。浏览器实测未来场次和超期场次均置灰，悬停文案各自匹配。可用行打开弹窗后点取消。临界场次在约 14:58（UTC+8）仍可点，与 16:00 截止的计算一致。截止前后一分钟是独立计算，页面在这两个模拟时刻的渲染未测。依据为 11-03 的 68090 结果、悬停与弹窗工具输出、Day.js 探针输出。
- **范围收窄**。用户随后明确只改报名页。参与统计的 `render` 恢复旧值后，按最新单文件范围收尾即可。工具只证实文件状态，回退操作者未核实。已有规则覆盖按本轮授权执行，ESLint 最小规则集降级也已收录在 `quality/references/test.md`「独立 ESLint 诊断」。

## 常用命令

当历史口径按 `activityEndTime` 加 7 天时，在已安装 `dayjs` 的项目目录用 Git Bash 运行。输入使用接口时间格式，Node 与浏览器采用同一时区。以下保留实跑探针的截止判断，并将样例时间参数化。成功信号为截止前后分别输出 `false true`。命令只在本地计算并输出结果。

```bash
node -e '
const dayjs = require("dayjs");
const deadline = dayjs(process.argv[1]).add(7, "day");
console.log("截止", deadline.format("YYYY-MM-DD HH:mm:ss"));
console.log("截止前后一分钟是否过期",
  deadline.subtract(1, "minute").isAfter(deadline),
  deadline.add(1, "minute").isAfter(deadline));
console.log("距截止的整分钟数", deadline.diff(dayjs(), "minute"));
' "<结束时间 YYYY-MM-DD HH:mm:ss>"
```
