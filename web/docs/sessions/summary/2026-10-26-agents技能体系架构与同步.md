# agents 技能体系架构与同步

**一句话总结**:`~/.agents` 全局 Skills 是「真身 + junction + manifest」三层体系,放全局只改 manifest 再跑两个脚本;zcode 直读 `~/.agents/skills`,不需要镜像。

## 背景

想弄清楚全局通用 Skills 仓库(`C:\Users\802165\.agents`)到底怎么组织、怎么把一个场景 skill(如 `proto-to-prd`)提升为全局,以及 `.zcode` 这类新 CLI 怎么接入这套体系。

## 核心命令

```bash
# 定位某个 skill 在真身层(categories)的唯一物理路径,确认有无重名
find ~/.agents/categories -type d -name "proto-to-prd"

# 查某 skill 在 manifest/overrides 里的引用位置(SSOT 配置)
grep -rn "proto-to-prd" ~/.agents/scripts/config/skills.manifest.json ~/.agents/scripts/config/SKILL_TARGET_OVERRIDES.json

# 改完 skills.manifest.json 后重建 skills/ 和 scenarios/ 的 junction 层
node ~/.agents/scripts/sk-rebuild.js

# 把 ~/.agents/skills 同步成五大 CLI(~/.claude/.codex/.cursor/.gemini/.kimi)的经源 junction 镜像
node ~/.agents/scripts/sk-sync.js

# 只读体检:校验 manifest ↔ overrides ↔ categories ↔ skills ↔ scenarios ↔ 五 CLI 全链一致性,有问题 exit 1
node ~/.agents/scripts/sk-doctor.js

# 把场景视图部署到某个项目的 CLI skills 目录(用完 remove 撤掉),不占全局上下文
node ~/.agents/scripts/sk-scenario.js apply 01-PRD转页面 /e/project/某项目 claude
```

注:`sk-rebuild/sk-sync/sk-doctor/sk-scenario` 的用法本次经脚本源码与 README 核验,会话内未实际运行;侦察命令均为实际执行。

## 关键结论

1. **三层架构,真身唯一**:skill 实体只在 `categories/`(约 120 个),`skills/`(全局 14 个)和 `scenarios/`(7 个场景)全是指向真身的 NTFS junction。改真身内容,所有派生层(含五大 CLI 和 zcode)自动跟随,无需重新同步。
2. **放全局的标准流程 = 改一个文件 + 两个脚本**:把 skill 名加进 `scripts/config/skills.manifest.json` 的 `global` 数组 → `node scripts/sk-rebuild.js` → `node scripts/sk-sync.js` → `node scripts/sk-doctor.js` 验证。真身无重名时不需动 `SKILL_TARGET_OVERRIDES.json`。一个 skill 可同时存在于 global 和 scenario,互不冲突。
3. **Windows junction 两条铁律**(踩坑结晶,写进了所有脚本注释):建链必须用 `fs.symlink(target, link, 'junction')` 或 `mklink /J`,禁用 `ln -s`(会把 junction resolve 成直指 categories 绕过中间层,对实体目录则 fallback 成复制);⚠️ 删链用 `rm` 不带 `-rf`,`rm -rf` / `rd /s` 会穿透 junction 把真身删掉。
4. **zcode 不吃镜像这套**:它直接读 `~/.agents/skills` 本体(会话加载的 skill 带的就是 `.agents\skills\...` 绝对路径),`~/.zcode/skills` 目录根本不被读取。所以别往 `sk-sync.js` 的 `DIRS` 数组里加 zcode——建了也是死目录。
5. **manifest 是唯一机器可读 SSOT**:`scripts/MANIFEST.md` 只是给人看的展示文档。文档里的数字会漂移(如"13/15 个全局 skill"vs 实际 14 个),`sk-doctor` 只校验机器配置不校验文档;统计以 manifest 和 `sk-doctor` 输出为准。
