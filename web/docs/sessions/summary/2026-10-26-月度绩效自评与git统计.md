# 月度绩效自评与 git 提交统计

**一句话总结**：用 git 按作者+月份聚出提交量级与工作流，再按评分档位逐维度补数据写自评，比写"积极认真完成"有效得多。

## 背景

月末要交绩效自评，审核要求"描述当月主要事项、贡献、问题"。手写容易变成态度表态，缺数据支撑。同时想把可复用的自评流程固化成个人 Skill，真身放本地 categories 仓库、运行时用软链挂载。

## 核心命令

```bash
# 按月拉某人提交，并剔除 stash 条目
git log --all --author="<邮箱>" --since="2026-08-01" --until="2026-09-01" \
  --pretty=format:"%h|%ad|%s" --date=short | grep -vE "^(On |index on )"

# 量级：变更文件数 / 增删行
git log --all --author="<邮箱>" --since=... --until=... --pretty=format: --numstat \
  | awk 'NF==3 {add+=$1; del+=$2; files++} END {print "files:"files, "add:"add, "del:"del}'

# 提交类型分布（仓库遵循 type(scope): 约定时）
git log --all --author="<邮箱>" --since=... --until=... --pretty=format:"%s" \
  | sed -E 's/^([a-z]+)\(.*/\1/; s/^([^(:]+).*/\1/' | sort | uniq -c | sort -rn

# 多仓库扫描：哪些项目当月真有提交
for d in <工作区>/*/; do
  [ -d "$d/.git" ] && n=$(git -C "$d" log --all --author="<邮箱>" \
    --since=... --until=... --oneline | wc -l) && [ "$n" -gt 0 ] && echo "$d: $n"
done

# 核实分支归属与包含关系（别在当前目录想当然）
git branch -a | grep -i "<关键字>"
git log --oneline <分支A>..<分支B>   # 反向为空 = A 已完全包含在 B

# Windows 建 junction 必须用同步 API
node -e "require('fs').symlinkSync(target, link, 'junction')"
```

⚠️ `git log --all` 会带上 stash 记录（`On xxx:` / `index on xxx:`），统计前先过滤，否则提交数虚高。

## 关键结论

1. **自评失分不是措辞问题，是缺数据**：每个维度至少一个数字或一件具体事；措辞要复用评分档位的关键词（"按时并高质量""输出了学习产物"），审核人才对得上档。
2. **git 的 fix 提交数不是缺陷数**：某月 fix 77 个，缺陷系统里只有 1 个缺陷。两者混写会让"缺陷需求比"看起来灾难性地差，分子只认缺陷系统。
3. **项目名 ≠ 仓库名**：绩效维度名和本地仓库名经常对不上，用 README 首行反查；查不到就标注"需人工补充"，不要猜。
4. **分支可能不在你以为的仓库**：本次任务实际在另一个子项目仓库，且当前目录的分支名与口述不一致（`env-x` vs `feature/env-x`）。动手前先 `git branch -a` 核实，否则改动会落在错误的地方。
5. `fs.symlink(target, link, 'junction')` 会抛 `ERR_INVALID_ARG_TYPE`，必须用 `symlinkSync`；先 `readlink`/`readdir` 验证链接可读再收工。

## 下次怎么用

- **月末自评**：先跑前三条命令拿量级与工作流聚类，再按表单维度逐条"结论 → 范围 → 数据 → 结果"填；量化指标先核对系统数据再落笔。
- **新建 Skill**：真身放 `categories/一级/二级/<name>/`，manifest 登记后建 junction；改完用 `npx prettier --check <touched files>` 与模块自带 `node *.test.cjs` 验证（部分测试需 token 或 fixture，跑不了就如实标注）。
- **"明明改了却没效果"**：先确认跑的是不是最新构建（对比源码 mtime 与 dist），再改代码——本次多个"缺陷"在当前源码里其实已经修好了。
