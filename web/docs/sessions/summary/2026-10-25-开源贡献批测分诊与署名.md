# 开源贡献工作流：批测分诊与署名管理

**一句话总结**：一次完整的开源 fork 贡献日常——多分支补丁的批量套用性分诊（merge-tree 三分类）、维护者收编盯梢、以及贡献者署名（contributors 图口径）的完整方法论。

## 背景

向 yetone/magpie 上游持续提交 patch（fork+patch 附 issue 形态，不走 PR），在途补丁 60 个左右。每天维护者高频自修上游，需要知道：我的补丁哪些还能干净打上、哪些被覆盖该撤、哪些要 rebase；以及贡献署名到底怎么算。

## 核心命令

```bash
# ── 上游漂移检测：看自上次巡检以来 main 新进了什么 ──
git -C <主clone> fetch upstream main && git -C <主clone> rev-parse upstream/main
git -C <主clone> log --oneline <上次SHA>..upstream/main   # 新提交清单

# ── 收编盯梢：新提交里有没有带上我的补丁 ──
git -C <主clone> log --format='%h %an: %s' upstream/main --grep='ggbdpq' -i

# ── 批测第一步：新提交碰的文件 × 我的分支碰的文件 求交集 ──
git -C <主clone> diff --name-only <上次SHA>..<新SHA> > /tmp/up.txt
mb=$(git -C <主clone> merge-base origin/<分支> <新SHA>)
comm -12 <(git -C <主clone> diff --name-only $mb..origin/<分支> | sort) <(sort /tmp/up.txt)

# ── 批测第二步：文件重叠≠冲突，用 merge-tree 干跑三方合并分诊 ──
# 三分类：clean=不动 / 真冲突=rebase / 已被上游覆盖=撤回
git -C <主clone> merge-tree --write-tree <新SHA> origin/<分支>  # 输出含 CONFLICT 行=真冲突

# ── rebase 后自证代码零漂移 ──
git range-diff <旧基>..<旧head> <新基>..<新head>   # 只看得到注释/上下文差异=安全

# ── 安全强推：锚定旧 SHA，别人动过就拒绝 ──
git push origin <分支> --force-with-lease=refs/heads/<分支>:<旧head完整SHA>  # ⚠️ 会覆盖远端分支；lease 锚定确保只覆盖自己预期的那一版

# ── 提交不落本地身份坑：显式双 flag ──
git -c user.name=<你的名字> -c user.email=<你的邮箱> commit -F <msg文件>

# ── GitHub API 取最新评论（坑：默认升序，per_page=3 拿到的是最旧 3 条！）──
gh api "repos/<owner>/<repo>/issues/<N>/comments?per_page=100" --jq '.[-1] | .body'
```

## 关键结论

1. **文件重叠 ≠ 冲突**：上游动了我 patch 碰过的文件，八成仍能干净合并——先文件交集粗筛、再 merge-tree 干跑精分诊，能省掉大量无谓 rebase（本轮 19 支重叠分支里 15 支干净）。
2. **"真冲突"还要再分两叉**：先逐笔读上游新提交判断语义——正交（各自改各自的层）就 rebase 保双方；覆盖（上游用自家修法修了同一行）就撤回补丁发确认帖留档，硬 rebase 等于拿我的写法换掉人家已合并的写法。
3. **GitHub contributors 图只数 commit author**：`Co-authored-by:` 尾注、提交信息里点名都不进图。想让图面有自己，唯一硬通货是维护者 `git am` 原样合入（author 保留）。
4. **已合并的提交补不了署名**：维护者原话"已推 main 的历史不能改写（会破坏所有人的 checkout 和 tag）"——补救机制是在 issue 评论区贴 commit 清单作署名记录。
5. **merge-tree 比 checkout 试合并快得多**：不污染工作树、不用解了再退，一条命令出冲突清单。

## 下次怎么用

多分支在途、上游高频前进的场景直接套三步：
1. `fetch` 记新 SHA → `log --grep 自己ID` 查收编 → 有就发确认帖促关单
2. `diff --name-only` 交集 + `merge-tree --write-tree` 分诊 → clean 不动 / 冲突再判正交还是覆盖
3. rebase 后用 `range-diff` 自证零漂移，`--force-with-lease` 锚定旧 SHA 强推

注意：`gh api` 查最新评论必须 `per_page=100` + jq 取尾（`.[-1]`）；macOS 上 `python3` 别名可能指向无第三方库的版本，关键脚本用 `/usr/bin/python3` 显式指定（待验证：不同机器别名配置不同）。
