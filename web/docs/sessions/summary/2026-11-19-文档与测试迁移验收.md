# 文档与测试迁移验收

## 一句话结论

把仓库外的测试资料交接给下次开发时，分别验收副本内容、现行引用和恢复运行。仓库状态只能说明工作区的 Git 变化，归档副本需要单独验收。

## Skill 增量建议

**目标** `gua-dev-tools/modules/quality/references/test.md`，测试资产归档条款。现有规则已区分 `archived` 与其他资产类型，`quality/MODULE.md` 已要求把暂存检查与实际跑测分开报告。康养 `senior/MODULE.md` 也已明确测试归档目录、回拷说明、账号隔离及禁暂存纪律。建议只补归档后的验收判据。

**建议追加**「迁出仍需复跑的测试时，记录原相对目录、依赖与运行入口。移除源文件前，逐项校验副本，任何不一致或读取错误都阻断清理。未在原布局恢复并实际执行时，交付写『副本已核对，恢复运行未验证』。」

**证据和边界** 本会话的测试迁移 Bash 调用对 7 个 Jest 文件执行了 `cmp -s`，可见输出无差异提示。但脚本以 `|| echo` 处理不一致，后续仍可能清理源目录。工具结果只确认当次观察到的迁移结果。另有 `replenishGate.test.js` 的源码摘录证明它依赖原目录的相对引用和 Jest 全局。此建议适用于以源码和测试框架为运行前提、移出后仍需要复用的测试。

**检验场景（未执行）** 故意让一个目标文件少一行，清理步骤应被阻断。副本一致但只在归档目录检查文件时，交付仍应标明恢复运行未验证。

## 可复用经验与案例

- **同步文档时逐条确认断言的证据类型。** 接口定义曾把两个旧接口列为「工程未检索到调用」。继续检查后，在 `activityQuery/request.js` 找到列表请求，在 `activityQuery/index.jsx` 找到导出调用和一个「导出」按钮。这些静态证据足以修订当前调用清单和按钮数量。实际导出成功仍需运行态证据。现行 `gua-writer/SKILL.md` 已规定以源码核对现状、同步活引用并保留历史路径，无需新增同义规则。
- **迁移验收按对象核对。** 缺陷记录目录在改写 README 路径前做了递归比对。截图与本地笔记的可见结果只有数量核对，因此不能把缺陷目录的比对结果推广到全部目录。迁移后 `git status --short` 仅显示既有 `.gitignore` 改动。这个结果确认 Git 工作区状态，不能证明仓库外资产可运行。来源为 debug 复制校验及最终检查的两条 Bash 输出。

## 常用命令

**递归对照迁移副本**。本会话在 Git Bash 实际用于比对缺陷记录目录。两端都须可读，并在需要改写目标引用之前执行。路径用引号包住，支持含空格的目录。

```bash
diff -rq "$source_dir" "$destination_dir"
```

退出码 `0` 表示目录树比对一致，`1` 表示有差异，大于 `1` 表示发生错误。历史调用通过 `&&` 打印「缺陷记录：递归一致」。命令只读。它比对目录项和文件内容，可运行性与文件权限需要各自的证据。
