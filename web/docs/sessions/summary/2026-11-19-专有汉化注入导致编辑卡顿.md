# 专有汉化注入导致编辑卡顿

## 1. 一句话结论

`ggbdpq.cursor-language-pack-zh-hans` 不是静态语言包。它把 DOM 翻译脚本注入 Cursor 安装目录的 workbench；`document.body` 上的 `MutationObserver` 加上每 100ms 全树扫描，会在打字和 Markdown 滚动时拖住主线程。清用户数据或重装只是暂时去掉被改过的程序文件，扩展默认还会在下次启动把补丁打回去。

根因来自扩展源码，用户已认可。本对话没有执行撤销，也没有复测滚动，修复仍未闭环。

## 2. Skill 增量建议

不改 `gua-writer`、`gua-pr-patch`。写作模板已覆盖复盘七要素；本轮没有向上游交 patch。2026-10-26 的《Cursor汉化补丁修复与CDP验收》讲的是锚点、校验和与 CDP 验收，不覆盖这次的滚动卡顿。

已写入 `gua-dev-tools` 的 `modules/bug/MODULE.md`「平台机制优先于业务代码」（真身在 `.agents/skills`，`.cursor` / `.claude` 是联接）。不另起规则。Cursor 滚动复测仍未做。

> 重装或清用户数据后症状消失时，先查安装目录是否被扩展或启动逻辑改写，以及该写入会不会在下次启动自动发生。清掉的是被改过的程序或缓存，不证明操作系统有病。用户已改掉一组嫌疑配置后症状仍在，就放弃该假设，不要再在同一组配置上加开关。

适用边界：只用于「重装/清数据就好、用久又回来」或「改了嫌疑配置仍复现」。普通页面 bug 仍走现有四问，不要把 Cursor 注入细节写进美业/康养模块。

检验场景（未执行）：撤销该扩展对安装目录的补丁并禁用扩展、完全退出进程后，Markdown 打字与滚动不再掉帧；只清 `%APPDATA%` 而扩展仍自动打补丁，则启动后复现。

## 3. 可复用经验与案例

**问题。** Windows 10 上 Cursor 打字、Markdown 滚动明显卡顿。扩展列表很短。整机重装并清用户数据后暂时不卡。

**排除。** 用户把 `editor.renderWhitespace`、`editor.wordWrap`、`editor.fontLigatures` 关掉后仍卡。这三项只影响编辑器绘制，解释不了注入脚本。主题、图标、中文界面本身也不是这条链路。

**关键证据（静态读扩展，未改安装目录）。**

- 扩展 ID：`ggbdpq.cursor-language-pack-zh-hans`。`activationEvents` 为 `onStartupFinished`。`cursorZh.autoApplyOnInstall` 默认 `true`。
- 注入脚本在扩展内 `bundled/patch-core/dist/assets/cursor.inject.js`，注释写明写入 workbench 副本头部。
- 脚本劫持 `Element.prototype.attachShadow`，把 closed shadow 改成 open。
- `MutationObserver` 监听 `document.body` 的 `childList`、`subtree`、`characterData`；变更后在 `requestAnimationFrame` 里全量翻译。
- `setTimeout(task, 100)` 每 100ms 再扫一遍。扫描根包含 `.workbench`、Agent/Composer，并始终加上 `document.body`。
- `.view-lines` 在不翻译名单里，所以编辑器正文不一定被改字，但滚动仍会改 DOM，观察者照样全树走。

**和「重装就好」的关系。** 补丁写在 Cursor 安装目录，不在 `settings.json`。重装换回官方 workbench，所以立刻不卡。扩展还在且会自动应用时，补丁会回来。不要把这件事收成「Win10 或 GPU 坏了」。

**次要现象，不当成这次滚动根因。** 同一次启动日志里，Figma 插件市场列表约 10 秒，四个扩展宿主一度 `unresponsive`。这解释启动顿，不解释 100 行级 Markdown 滚动。曾把 `E:\Projects` 整目录当过工作区，会放大文件监视，本轮没有把它证成滚动卡顿的原因。

**下次。** 先读扩展是不是改宿主文件，再看观察者扫的是不是整页、有没有定时全量扫描。撤销用扩展自己的恢复命令，完全退出进程再开。不要用另一套 DOM 注入汉化替换。界面中文若还要，只用静态 NLS 语言包。

## 4. 待验证与不适用边界

- 未闭环：没有在本对话执行「恢复英文界面」、禁用扩展或滚动复测。用户认可的是机制判断，不是修复结果。
- 若撤销后仍卡，才单独查 GPU 缓存；本对话没有测量显卡，不能写成 GPU 根因。
- 不适用于只换 `translations/*.i18n.json`、不注入 workbench、不挂整页观察者的语言包。
- 不把本案例放进 `gua-pr-patch`。要改注入策略时，那是 `cursor-loc` 自己的修复，本轮没有开 PR。
