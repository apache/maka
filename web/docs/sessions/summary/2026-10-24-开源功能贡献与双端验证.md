# 开源功能贡献与双端验证

**一句话总结**：给上游开源项目（magpie）完整走了一遍「提案 → 实现 → 双端验证 → 修异常 → 开 issue」的贡献流程，沉淀下多仓 git 操作、无 package.json 的 Playwright 跑法、守卫消融法和真机验证沙盒套路。

## 背景

要给 magpie 提一个新功能（路由组规则试算）：在 fork 分支实现后，需要跨 macOS/Windows 双端真机验证、把异常修复收口进提交、最后全英文开 issue 到上游。期间踩了 shell 工作目录漂移、Playwright 版本-浏览器不配套、i18n 键名撞守卫等坑。

## 核心命令

```bash
# 多仓操作一律 -C，杜绝 cd 漂移（本次 shell 工作目录漂移过两次）
git -C /path/to/repo <子命令>

# 功能分支改名后推送（commit 被 amend 过必须 force-with-lease，比 -f 安全：远程被别人推过会拒绝）
git push --force-with-lease origin <branch>

# 回读提交正文（核对验证记录是否与最终状态一致）
git show -s --format=%B HEAD

# 提交前核对只带了自己的文件
git show --stat HEAD

# 确认远程分支真实指向（push 后回读验证）
git ls-remote origin refs/heads/<branch>

# 查维护者是否正在改你要动的区域（开工前防撞车）
git log --since=14.days --oneline -- <path>

# 仓库没有 package.json 时跑 Playwright 测试：NODE_PATH 指向 npx 缓存里配套版本
NODE_PATH=~/.npm/_npx/<hash>/node_modules node --test internal/gui/tests/xxx.test.cjs
BROWSER=webkit NODE_PATH=… node --test …   # 切引擎

# 只写 JS 语法自检，不起浏览器
node --check file.js

# 大包测试放后台、日志落文件再 grep（管道 tail 会吞失败摘要）
go test ./internal/xxx/ -count=1 -timeout 45m > /tmp/suite.log 2>&1

# 跨平台验收（CI 只编译 Windows，vet 才编译测试文件）
GOOS=windows go vet ./... && GOOS=windows go build -o /dev/null .

# python 精准补丁：替换前断言唯一性，防止误替换（配反向替换即可做消融验证）
python3 - << 'EOF'
s = open(p).read()
old, new = "…", "…"
assert s.count(old) == 1
open(p, 'w').write(s.replace(old, new))
EOF

# 读别人的配置文件只看结构不看值，避免密钥泄露
jq -r '.providers[] | {id, off, keylen: (.key | length)}' providers.json

# gh 开 issue，正文用文件（tail -n +2 去掉本地稿的首行标题）
gh issue create --repo owner/repo --title "…" --body-file body.md

# 进程占用与端口排查
lsof -nP -iTCP:<port> -sTCP:LISTEN
```

## 关键结论

- **守卫消融法**：新增守卫测试后，用补丁临时破坏守卫 → 测试必须真红 → 反向补丁恢复 → 复绿。这是「测试修前就绿的空测试」的唯一硬证据，上游评审最认这个。
- **预存红要靠干净基线定性**：全量套件红了先别修，在未改动的同基线 clone 上复跑同名用例；两树同红 = 预存环境问题，与本改动无关。
- **键名/文案先查冲突再定**：i18n 键是全仓子串匹配（"Try" 撞了毫不相干的 "Try again"），短泛键必撞；UI 测试要断言每一条可见文案，否则删了翻译键测试照样绿。
- **集成路径由部署拓扑决定**：先 `lsof` 看进程真实监听了什么再设计对接方式——桌面端 API 走内嵌通道、HTTP 根本不可达时，本地直接调库（CLI 自算）比绕认证墙简单得多。
- **Playwright 版本要和浏览器缓存配套**：alpha 版要的浏览器 build 缓存里没有，所有用例假红；换配套版本即愈，且要看每用例耗时判断是否真开了浏览器。
- **Amend 过的提交推送必须 `--force-with-lease`**，推完 `ls-remote` 回读 SHA；提交正文用 `git commit -F 文件` 写验证记录，方便多次 amend。

## 下次怎么用

给上游项目贡献功能时按此流程套用：① fetch 上游 + 查目标区域 14 天提交防撞车；② fork 分支实现，守卫测试带消融证据；③ 全量套件红先在干净基线定性再归因；④ 真机验证用沙盒 HOME + 凭据副本 + 独立端口，结束时 `chmod -R u+w` 后再删 ⚠️（Go 模块缓存文件只读，直接 rm 会 Permission denied）；⑤ 发布前 grep 双查：fork 分支链接 + 署名句（Attribution/Co-authored-by）；⑥ 开 issue 用 `gh issue create --body-file`，标题沿用仓库 commit 的行为式句法。
