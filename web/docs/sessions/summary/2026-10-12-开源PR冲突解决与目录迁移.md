# 开源 PR 冲突解决与目录迁移实操

**一句话总结**：把一个 51 处冲突的 PR rebase 拆成"三方合并 + 分块重组"啃下来，顺手把两个旧目录并入新仓，踩清了 Windows 下 python 路径、robocopy 编码、node_modules 断链三个坑。

## 背景

给 apache/maka 的一个 open PR 按 review 意见做 rebase：上游已合并了从这个 PR 拆出去的另一半功能，两个分支互为"merge base 减去对方一半"，直接 rebase 会静默丢文件。另有一件事是把用了半个月的 E:\ggbdpq、E:\github 两个目录归并进统一的 E:\cc 仓，两边同名目录交错。

## 核心命令

```bash
# 查 PR 的行内评论 / reviews / issue 评论（gh 已登录时免 token）
gh api repos/<owner>/<repo>/pulls/6052/comments --jq '.[] | {user: .user.login, created: .created_at, body}'
# 发 PR 评论：body 从文件读，绕开 shell 转义和编码问题
gh api repos/<owner>/<repo>/issues/6052/comments -F body=@reply.txt --jq '.html_url'
```

```bash
# Git Bash 的 /tmp 是虚拟路径，Windows 原生 python 看不到，用 cygpath 转换后传参
WINTMP=$(cygpath -w /tmp/maka-prs); python - "$WINTMP" <<'EOF'
import sys, os
base = sys.argv[1]
EOF
```

```bash
# 实验性合并：先看冲突规模再决定解法，不产生提交
git merge --no-commit --no-ff origin/feature-branch
grep -c '^<<<<<<<' src/big-file.ts        # 统计冲突块数量
git merge --abort                          # 不想要了就回滚
# 从 index 恢复某个阶段的文件（:0=工作区已暂存版，:1=base，:2=ours，:3=theirs）
git show :0:path/to/file > recovered.ts
# 提取任意提交的文件版本（不用 checkout）
git show d69f4ec1:docs/a.md | sed -n '10p'
```

```bash
# review 修复后，对上一被审 head 做全量 diff：剩余差异 = 有意保留的修正
git diff d69f4ec1 -- docs/ | head -50
```

```bash
# 目录迁移前定性：文件数、最新修改时间、内容差异
find "$src" -type f | wc -l
stat -c '%y' "$f"                          # mtime 对比定谁是新版
diff -rq "$src" "$dst" 2>/dev/null         # 只看 "Only in" 行，子目录级并入
cmp -s "$a" "$b" && echo 相同              # 单文件快速比对
```

```powershell
# 被进程锁住的目录（rename 报 Permission denied）：robocopy 复制+删源绕过
# 在 bash 里直接调 robocopy 传中文路径会乱码（退出码 16），要走 PowerShell
foreach ($d in @('目录A','目录B')) {
  robocopy "E:\src\$d" "E:\dst\$d" /E /MOVE /NFL /NDL /NJH /NP /R:1 /W:1 | Out-Null
  Write-Output ($d + ' code=' + $LASTEXITCODE)   # <8 算成功
}
```

```bash
# 迁移/重装后验证 git 仓健康（不 cd 进仓库，避免钩子干扰）
git -C "E:/path/to/repo" status --short | head -3
git -C "E:/path/to/repo" branch --show-current
```

## 关键结论

1. **目录迁移后 node_modules 全断是 symlink 断链，不是依赖坏了**。症状是一片无关的 `TS2307 Cannot find module`（子路径模块全找不到）；根因是 node_modules/@pkg 的 symlink 指向迁移前的绝对路径。`npm install` 重装即愈。
2. **两分支互为"对方缺失的一半"时，plain rebase 会静默丢文件**（无冲突标记）。改用 `git merge --no-commit --no-ff` 三方合并：新增文件自动进来，真正的逻辑冲突只剩少数几处，逐块手工取舍。
3. **review 修复要 diff 上一被审 head，别只看自己的增量 diff**——回退和修正经常混在同一提交里，对被审版本的全量 diff 才能把"有意修正"和"意外回退"分开。
4. **大冲突用脚本重组比手工稳**：从两个源版本 `git show <sha>:file` 精确提取段落，python 断言+拼接写回。但重组后必须立刻跑编译——本次重组脚本有个边界 bug（成对块的公共段被复制三次），靠 tsc 报错行号定位修复。
5. **同盘 mv 是 rename 秒完成**；整仓迁移后各 git 仓内部引用是相对路径，天然无损，逐仓 `git -C status` 验证即可。嵌套 .git 会顶掉外层仓对该子树的跟踪，需要归档而非移入。

## 下次怎么用

- **处理大型 rebase/合并**：先 `merge --no-commit` 摸清冲突块数 → 冲突少的逐块 Edit，成片的结构冲突（同名类两套定义等）写脚本从两个源版本拼装 → 重组完立刻编译 → 跑目标测试定性。
- **归并两个目录**：先 `diff -rq` 摸清 "Only in" 和 differ 清单 → mtime 定谁是新版 → 独有项移入、同名保留新版、旧版归档到 `_migrated-日期/` 不直接删 → 嵌套 .git 归档 → 全部迁完逐仓验证。
- **Windows + Git Bash 写 python/调用 Windows 原生工具**：路径一律 `cygpath -w` 转换或改走 PowerShell；中文路径的程序调用优先 PowerShell。

## 踩过的坑（引以为戒）

- ⚠️ `rm -rf` 清空壳目录前，必须 `find <dir> -mindepth 1` 验证内容已全部迁走。本次因 `ls | head -5` 截断了输出，漏判一个未迁移的子项目，rm 后无法恢复（cc 仓有 10-12 的收编副本，损失以副本为准兜底）。
- ⚠️ `git push --force-with-lease` 重写公开 PR 分支前，确认所有在途 review 引用的 head SHA 已在提交信息或评论里留档。
- 调试时往 dist 注入探针会让行号位移，stack trace 的行号要按注入量回推；收尾重新 build 清探针。
- Windows 下被进程占用的目录 rename 会报 Device or resource busy，但**清空其内容不受限**：robocopy 复制走人，空壳留到进程退出后再删。
