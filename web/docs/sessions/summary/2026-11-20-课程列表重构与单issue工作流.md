## Skill 增量建议（均为建议，未执行修改）

### 1. feedback-templates.md 增设「新对话开场提示词（一个对话一个 issue）」模板

- 目标位置：`gua-dev-tools/references/feedback-templates.md`，在 §3「给编码 Agent 的提示词」后新增 §4。
- 现有缺口：§3 是**任务执行型**模板（"做本轮最小修改"）；用户 2026-11-13 明确拍板「每次都打算一个对话一个 issues，这样更容易维护」（原话），并实际采用了本次交付的开场提示词。两类提示词用途不同：开场型解决**会话作用域与状态保护**，不解决单步执行。MEMORY.md 已记「用户工作流=一个对话一个 issue」但骨架本体未入 Skill，下次请求只能凭记忆重造。
- 建议追加的短文本（骨架，五段式）：

```text
# <模块名>（<版本-端>）开发对话
## 角色与范围：你是本模块前端负责人。本对话只处理「X」，代码范围 <目录>。
  同事模块 <Y> 只读不改（其接口仅作读取依赖时注明）；公共层（<列出>）不改；
  范围外问题只记录一句，不展开（跨对话防串的关键句）。
## 当前状态（<日期>，接手任何文件前先重读磁盘核验）：
  仓库/分支；接口接入状态与契约文档路径；提交状态（关键：暂存区=旧版、工作区=新版，
  或反之，拟提交文案原文）；测试环境数据现状（账号可见的量级与识别前缀）。
## 硬性约束：不切分支/reset/commit/push（提交由用户手动）；保住暂存区，改动只落工作区；
  不新增依赖、不顺带重构；仓库行尾（CRLF/LF 按磁盘实测）；测试文件禁进仓库。
## 首选动作（先和用户确认再执行）：1. git diff 审查工作区 2. 用户确认后提交
  3. 按 <接口定义/问题文档> 推进剩余项与新提单。
## 验证入口：本地页面 URL；登录入口与账号指向（不回显密码）；测试命令与基线通过数；
  写操作只做测试环境、不删非本次前缀数据。
```

- 来源证据：本对话 11-13 用户消息（"我发现我前2个问题都跨对话了，有点凌乱了…给我新对话的专业提示词，只是涉及src\pages\courseManagement，不超过三千字"）及交付的完整提示词；MEMORY.md `course-list-real-api-integration.md` 末条已记该工作流。
- 适用边界：同一模块会跨多个对话推进、且存在暂存/工作区分离时用；一次性小任务仍用 §3 任务型模板。
- 检验场景：用户说"给我 XX 模块新对话提示词"——套骨架产出应包含范围锁句、暂存/工作区分离说明、拟提交文案原文三项；缺任一项即不合格。

### 2. senior MODULE 的 TAPD 闭环补一条「拒绝单处置」边界（待比对）

- 目标位置：`gua-dev-tools/modules/senior/MODULE.md` TAPD 缺陷闭环节。
- 现有缺口：grep 该文件无「拒绝/撤单/关闭单」相关规则。本次案例（TAPD#1087388）：单的预期与原型现状冲突，讨论后**提单人（测试）自己选择维持现状 A**，后端个人倾向改 B 但明说"以产品结论为准"——前端正确处置是**评论留证（依据+时间+请提单人撤单）+ 等提单人自行撤单**，不单方点「已拒绝」。
- 建议追加的短文本：`缺陷单预期与现状冲突且提单人经讨论认可现状时：TAPD 评论留证（群内结论时间、依据条目、@提单人）后等提单人撤单，不单方流转「已拒绝」；产品改判后要求重新提单，不沿用旧单扩 scope。`
- 来源证据：2026-11-13 群聊截图（张松选 A、王国庆"没找产品确认"）、TAPD 已发评论；结论已存项目记忆 `data-aggregate-settlement-default-1087388.md`，处置模式未入 Skill。
- 适用边界：仅提单人本人认可撤单时；若提单人坚持、或产品已拍板 B，则正常修复流程。
- 检验场景：缺陷单里测试回复"现在的表现是对的，我撤单"——正确动作是评论确认+等撤单，而非开始改码或点拒绝。

## 可复用经验与案例

### 表单草稿直存契约形状（删除整个转换层的根因解法）

课程列表最初为 UI 私有字段建了适配层（rowIn/detailIn/statusLabel/recommendFlag/scheduleIn/scheduleOut/toSchedule 六函数约 120 行）。映射层每次契约变更都要双侧改，且 11-13 运行态测试曾揪出映射层漏改引入的真实缺陷（recommendState 读已删除字段）。最终解法不是优化映射，而是**消除转换需求**：

- 页面/表单/夹具字段名全部与后端一致（courseName/classId/sortNo/status 0-1/recommendStatus 0-1）；
- **表单草稿（上课时间）直接存接口契约形状**：`{scheduleType: 1|2, weekDays, startTime, endTime, startDatetime, endDatetime}` 按模式存字段子集——详情回显即草稿（保留原值含秒），提交即透传（分钟精度补 `:00` 收进 saveBody 一处）。

收益：映射层整体删除，utils.js 收缩为纯传输边界（pageQueryIn/pageOut/courseScheduleDraft/saveBody/shelfBody/recommendBody/分类目录守卫）。适用条件：表单与接口字段一一对应、无派生/聚合时；若 UI 需要多字段合成一个语义值（如活动管理的 frequencyUnit），仍需适配层，此手法不适用。这与团队既有约定「退 mock：页面用后端原始字段名」同源，但把范围从"展示字段"推进到了"表单内部状态"。
