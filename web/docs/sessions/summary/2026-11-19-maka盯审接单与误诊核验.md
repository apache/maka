## 常用命令（本会话实际执行过、有可见结果）

1. **时间线定案**（证明"某加载/调用链自 X 日起覆盖 Y"，#5909 判定的核心证据）：
   `git log -S '<关键串>' --format="%h %ad %s" --date=short -- <path>`
   前提：任意 Git Bash 环境下仓库内。成功信号：列出引入/删除该串的提交对；**无输出 = 该串从未出现，这本身也是裁决性证据**（本轮判 import 行"自 scaffold 就在"即由此定案）。
2. **多 PR 三端点增量扫描**（盯审基准比对）：
   ```bash
   for n in 5265 5274 5709 …; do
     gh api repos/<o>/<r>/issues/$n/comments --jq '.[] | select(.created_at > "<基准ISO>") | "CMT \(.created_at) \(.user.login): \(.body[0:250])"'
     gh api repos/<o>/<r>/pulls/$n/reviews --jq '.[] | select(.submitted_at > "<基准ISO>") | "REV …"'
     gh api repos/<o>/<r>/pulls/$n/comments --jq '.[] | select(.created_at > "<基准ISO>") | "INL …"'
   done
   ```
   前提：gh 已认证。注意 reviews 端点用 `submitted_at`、其余用 `created_at`；404 出现在 issue-only 编号上（pulls 端点对 issue 返回 404），属正常。
3. **带回复目标的评论**（行内 reply）：
   短文本 `gh api repos/<o>/<r>/pulls/<N>/comments -f body="<文本>" -F in_reply_to=<评论id>`；长正文先 Write 落 JSON（`{"body":…,"in_reply_to":N}`）再 `--input 文件`。`-f` 是字符串、`-F` 是类型化数值——in_reply_to 必须走 `-F` 或 JSON。成功信号：返回新 comment id 与 created_at；副作用：对外可见评论，需当轮授权。
4. **workflow 在某分支的运行核查**（解锁条件类验证，本轮查 performance-frontend main 零运行）：
   `gh api repos/<o>/<r>/actions/workflows --jq '.workflows[] | select(.path | test("perf";"i")) | "\(.id) \(.path)"'` → `gh api repos/<o>/<r>/actions/workflows/<id>/runs?per_page=5 --jq '.workflow_runs[] | "\(.run_number) \(.head_branch) \(.status)/\(.conclusion) \(.created_at) \(.head_sha[0:9])"'`
   信号：runs 清单按 head_branch 过滤即"某分支是否跑过"；空 = 该分支零运行。
5. **（maka 项目专用）epoch 消耗判定**：`git log <旧main>..<新main> --oneline -- packages/runtime-host/src/protocol/index.ts`——空输出 = 新 main 提交未消耗 protocol epoch，在途 PR 无需顺延；非空 = 逐提交读 epoch 尾数定顺延。项目专用，不通用。
