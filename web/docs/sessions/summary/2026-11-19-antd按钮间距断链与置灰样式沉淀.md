## 2. Skill 增量建议（已执行，2026-11-19 用户确认后写入）

**目标位置**：`gua-dev-tools/modules/ui/references/style.md`，可挂在「Token 与第三方覆盖」小节之后。

**现有规则缺口**：style.md 已有「第三方覆盖用 `:global` 指向具体类名、内联优先级、`!important` 是最后手段」，但没有「相邻间距依赖容器选择器、包裹元素断链」这一判断层——遇到按钮贴脸时现有规则会把排查引向样式值而非 DOM 结构。

**建议追加文本**：

```markdown
### antd 相邻按钮间距是容器作用域规则（antd 5）

- antd 5 无全局 `.ant-btn + .ant-btn` 间距；间距来自容器自有选择器，且多为直接子节点限定：
  Modal footer 为 `.ant-modal-footer > .ant-btn + .ant-btn { marginInlineStart: 8px }`，
  Button.Group/compact 是负 margin 压缩（button/style/index.js）。
- Tooltip/Badge 等组件包一层 span 后相邻关系断链，间距丢失且无兜底——表现为「两个按钮贴脸」。
  先查包裹结构，不是调 margin 值；确认无兜底后在按钮上手动补 margin，取值对齐容器既有口径
  （Modal footer 补 antd 默认 8px；业务按钮行对齐本行既有间距，如 Query 行 10px）。
- 判定条件：只有与其他按钮同排的包裹按钮需要补；独占一行或 span 已带 margin 的不用。
- disabled 主按钮的置灰态样式来自样式表，内联 style 可直接覆盖（无需 !important/:global/scss），
  可用于「本期不做、置灰保留」的主操作按钮恢复主色底：
  `backgroundColor/borderColor: var(--primary-color, #1677ff) + color:#fff + opacity:0.5`。
```

**来源证据**：
- 本对话 grep `node_modules/antd/es/modal/style/index.js:190-192`（footer 相邻规则，`> ant-btn + ant-btn` 直接子节点限定）与 `es/button/style/index.js:93-102`（仅 compaction 负 margin，无全局规则）——工具结果实查，非推测。
- 修复现场：报名名单弹窗「关闭 / 导出名单」贴脸（applicantModal 补 8px）、参与统计「查询 / 导出报表」贴脸（补 10px），另 2 处 span 包裹按钮（statSummary 自带 margin、activitySignUp 独占一行）确认无问题不动。
- 用户接受度：两处修复按用户指示已暂存并拟提交文案（type=style）。

**检验场景**（能区分对错）：Modal footer 两钮贴脸、其中主按钮被 Tooltip span 包裹——正确动作=给该按钮补 `marginLeft: 8`；错误动作=给 footer 写 `:global` 覆盖、或凭目测补 20px、或把 Tooltip 拆掉（会丢 disabled 按钮的悬浮提示，disabled 按钮不触发鼠标事件必须包 span）。

**适用边界**：antd 5.x（5.24.2 实测）；antd 4 的 less 机制与 3.x 未验证，不外推。

## 4. 常用命令

**场景：确认 antd 5 某组件样式规则的实现与作用域**（判定贴脸/间距/禁用态是否可覆盖前先拿证据）：

```bash
# 相邻按钮间距规则（modal footer 是否限定直接子节点）
grep -n "ant-btn + \|+ ant-btn\|marginInlineStart" node_modules/antd/es/modal/style/index.js
# 按钮自身是否有全局间距规则（预期只有 compaction 负 margin）
grep -n "marginInlineStart" node_modules/antd/es/button/style/index.js
```

前提：node_modules 已安装；antd 5 为 JS-in-CSS（dist 下无 antd.css，查 dist css 会落空）。成功信号：命中 footer 段 `> ant-btn + ant-btn` 与 token.marginXS。副作用：无（只读）。
