## Skill 增量建议（gua-pr-patch / references/pitfalls.md「常见流程坑」追加；未执行，待确认）

1. **带未提交补丁时禁用 `git checkout -- <file>`**
   - 现有缺口：「破坏性操作前先确认回退源」未点明此具体形状。
   - 建议文本：`git checkout --` 恢复的是 HEAD 不是"上一个状态"——带着未提交的补丁做临时实验改动（如消融、fixture 变形）后用它还原，会把补丁一起冲掉；恢复临时改动用成对的完整语义块 Edit，或先把补丁提交/落 patch 再实验。
   - 来源证据：2026-10-01 #6259 有牙检查，sed 行级替换打碎编译 + checkout 还原已重打的补丁，补丁重写一遍（journal PR-016 踩坑段）。
   - 检验场景：工作树有一个未提交的测试补丁，做一次"禁池"实验后想还原实验改动——遵守规则的路径是 Edit 恢复 fixture 块，违反的路径是 checkout 整个文件（补丁消失，git diff --stat 归零）。

2. **merge-tree/含 NUL 输出的管道统计用 `grep -a`**
   - 现有缺口：工具静默误判家族（rg -r 坑、gh -f 坑）未含此成员。
   - 建议文本：`git merge-tree` 旧式三参数输出（老 merge-base 或含 NUL 的内容）会被 grep 静默判成二进制——`grep -c "<<<<<<<"` 返回空而非 0，被误读成命令失败；管道统计一律 `grep -a`，或改用 `--write-tree` 形式。
   - 来源证据：2026-10-01 九 PR 批量探冲突，#5520/#5747/#6170 三个 PR 的冲突统计为空输出，`grep -ac` 修正（journal 维护Ⅹ）。
   - 检验场景：对老 base 的 merge-tree 输出统计冲突块——不 `-a` 得到空，误判为"命令坏了"；`-a` 得到真实计数 0。

3. **历史改写：范围收窄 + 清除类操作的凭据轮换是必须项**
   - 现有缺口：pitfalls 无历史改写条目；"破坏性操作前确认回退源"不覆盖这两点。
   - 建议文本：filter-branch 成本与改写范围线性相关（Windows 全量 4000+ 提交约几十分钟），用 `<base>..<branch>` 只重放差异提交，与全量等价但快百倍；敏感文件清史后**远端悬挂对象仍可按旧 SHA 直达**（fork 网络归 upstream，GC 前不消失）——泄露凭据的清除必须配套轮换，清史不消除泄露。
   - 来源证据：2026-10-01 custom 分支 config.yaml.bak（现役 secret-key 哈希）清除全案（journal 维护Ⅸ；旧 SHA GitHub API 实测仍可达）。
   - 检验场景：清史后用旧 SHA 调 GitHub commits API——分支文件树已净但旧提交仍 200；只看"分支里没了"就宣布泄露解除是错的。

**M3/M4 判据微扩展（弱候选，可并入现有条目）**：M3 补一句"报告者的 N/0 不 trip 是采样结论不是结构结论，换平台/负载即翻转"；M4 补"fixture 用被测层的真实约定，报告者/文档的高层形状先降级验证再采信"。来源：#6259（macOS 0/400 vs Windows 负载第一批即翻）与 #6249（auth-JSON 高层形状 vs `header:*` 单元层契约）。

## 可复用经验与案例

**案例一：custom 分支敏感文件清除（CLIProxyAPI，2026-10-01）**
- 触发：fork 公开仓里 config.yaml.bak 含 secret-key 哈希，比对确认与现役实例**同值**（泄露的是活密钥非废哈希），同提交还带业务 sqlite。
- 决策链：filter-branch 全量跑几十分钟 → 收窄 `2c8c2e89..custom` 秒级；敏感提交只含三个泄露文件，`--prune-empty` 让提交整体消失（连错误作者身份一起）；本地备份 tag（不推送）先打；`.gitignore` 补条目防再犯。
- 边界（本次学到的硬事实）：分支引用层已净 ≠ 远端已净——旧 SHA 在 GitHub 仍可直达，fork 网络归 upstream，彻底清除只有 Support GC 或删仓重建；**轮换凭据不可免**。
- 未闭环：密钥轮换与 Support 请求待用户执行；本地备份 tag 待用户确认后清理。

**案例二：antigravity 连接池测试去 flake（#6259 → PR #6262）**
- 根因：`wg.Wait()` 只覆盖客户端 goroutine，不覆盖 idle-pool 归还——两个测试在异步窗口的刀口上断言。
- 双向刀口：Test 1 上界（归还未完成 → distinct 超界，报告者 macOS 抓到）；Test 2 下界（负载下 wave 内串行化 → 2 连接池服务全部请求 `distinct=8`，是池完美工作不是缺陷，Windows 负载第一批即抓到，报告者 macOS 0/400 没见到）。
- 取舍：上界放宽到 `2*perWave` + 注释记录 slack 语义；下界删除只留 pooling-absent 守卫；否决 sleep（wall-clock 等待是仓规反模式）与 wave 重写（改动大守卫同效）。两断言都做了禁池牙检（24>16、24/24 大声失败）。
- 修前红证据采信链：本机 45 采样未复现原 flake → 如实声明，采信报告者负载数据 + 代码级推演（异步归还在代码里可证）。

## 常用命令

1. **flake 负载复现/修后稳定性采样**（CPU 满载互为负载；结论只说到观测范围）
   ```bash
   for i in 1 2 3; do (go test -count=20 -run "<TestRegex>" ./<pkg>/ > /tmp/run_$i.log 2>&1 &); done
   sleep <估时>; grep -h "FAIL\|<关键断言词>" /tmp/run_*.log
   ```
   前提：测试无共享状态（httptest 本地端口各自独立）；副作用：占满 CPU 数分钟。

2. **测试牙检（守卫力验证）**：临时破坏被测行为（如 fixture 里 `enabledPool=false`），跑测试必须 FAIL 且失败消息点名断言；跑完恢复。前提：用完整语义块 Edit 做成对替换（见 pitfalls 候选 1 的反例）。

3. **gofmt CRLF 判定**（Windows autocrlf 仓）
   ```bash
   tr -d '\r' < file > /tmp/f.go && gofmt -l /tmp/f.go   # 有输出才是真格式问题
   ```

4. **历史改写（⚠️ 改写已推送历史，破坏性）**：先打本地备份 tag；范围收窄到差异提交
   ```bash
   git tag backup/<branch>-before-purge <branch>
   ⚠️ git filter-branch --force --prune-empty --index-filter \
     'git rm -r --cached --ignore-unmatch <fileA> <dirB>' -- <base>..<branch>
   git push --force-with-lease origin <branch>   # 期望值取完整 SHA
   ```
   前提：本地分支与 origin 一致（先 reset --hard origin/<branch>）；副作用：改写后所有协作 clone 必须 re-clone 或显式重对齐，远端悬挂对象不消失。

5. **gh 评论修正**（发外文本先读一遍；PATCH 而非重发）
   ```bash
   CID=$("$GH" api repos/<o>/<r>/issues/<N>/comments --jq '.[-1].id')
   "$GH" api -X PATCH "repos/<o>/<r>/issues/comments/$CID" -F body=@fix.json
   ```

## 待验证与不适用边界

- pitfalls 三条候选均为**建议文本未写入**，待用户确认后落 gua-pr-patch/references/pitfalls.md「常见流程坑」。
- filter-branch 在 darwin（zsh）上未验证——pitfalls 已有 zsh 吞 refspec 的坑，命令里 refspec 参数应加引号。
- `git merge-tree --write-tree` 形式是否同样有二进制 grep 问题未测（workflow §1 已推荐该形式，可能天然规避）。
- custom 分支清史案例的 Support GC 请求与密钥轮换未执行，属于用户侧待办；本记录不含密钥值（哈希比对过程已脱敏）。
- 三端点评论扫描、消融有牙、rebase grep、上游同题等本会话使用过的方法**不归档为增量**——gua-pr-patch workflow/pitfalls 已明确覆盖，本会话是其执行实例。
