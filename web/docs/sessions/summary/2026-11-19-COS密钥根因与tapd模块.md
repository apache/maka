## 可复用经验与案例

- **诊断规则（本次最值钱）**：签名错误按「密钥 → 权限 → 桶/前缀」顺序排查；同一密钥对双桶同错可锁死密钥层，直接跳过桶配置排查。证据：senior 与 meiye 均 403 SignatureDoesNotMatch（会话记录）。
- **反例：不要手写 COS 签名验证密钥**。本轮复刻签名做 HEAD 测试得 400，是签名串构造错误（formatString 用了 POSTRequest 等），不能作为密钥结论；密钥有效性要用已验证的 `cos-put.mjs` 路径或 cos-nodejs-sdk-v5（SDK 桶名必须 `bucket-appid` 格式，否则报 `Bucket should format as "test-1250000000"`）。
- **tapd lib API 形状（实测踩坑）**：`get_git_status()` 返回三元组 `(commits, uncommitted, success)` 不是字典；`save_profile(profile, profile_name)` 顺序不能反（反了 dict 被序列化进文件名）；`read_config(key, fallback)` 是单键读取；本机 `get_python_executable()` 返回 `py`。
- **dry-run 解耦已提交**：两个脚本 dry-run 跳过 tapd-cli 检查，未装 CLI 可走通 git 扫描 → 描述生成 → 表格解析全链路（推送 tip `6395cc4c`，rebase 后等价于 f2e2a937/a0a7f436）。
- **根 profile.json 未建**：`load_profile()` 读 `~/.clife-dev-tools/tapd/profile.json`（不存在），所以每日任务必须传 `--owner` 兜底；已建的是 `profiles/senior-biz.json`、`profiles/senior-aff.json` 两份。

## 常用命令

1. **换取 COS 临时密钥（已验证）**
   - 场景：codesign/康养上传前取临时凭证；SignatureDoesNotMatch 时先验证密钥链。
   - `curl -s "https://homing.clife.cn/v1/homing/component/web/credential/get-cos-temp-key" -H "token: <业务token-uuid>"`
   - 前提：有效业务 token（UUID 形态）。Header 必须是 `token:`，`Authorization: Bearer` 实测不生效。
   - 成功信号：`{"code":0,"msg":"success","data":{"tmpSecretId":"…","tmpSecretKey":"…","sessionToken":"…","expiredTime":…}}`。副作用：签发短时凭证（约 2 小时级，过期重取）。
2. **tapd dry-run 验证（已验证，模块内命令）**
   - `python scripts/create-daily-task.py --project <id> --repo <repo> --owner <名> --dry-run`
   - `python scripts/create-batch-tasks.py --doc <csv> --developer <名> --dry-run`
   - 成功信号：打印任务信息/待创建列表后以「试运行模式，不会实际创建」结束，exit 0。
3. **反记录**：`npm install -g @tapd/cli` → E404，勿重试。
