# 白名单仓搬目录

## 一句话结论

`*` 起手的白名单仓里，目录搬走后必须把 `!` 放行和其后的再排除一起改掉，并用 `git check-ignore -v` 看最后一条规则。文档只改还在被执行的入口；日记、验证日志和 `git show <旧提交>:旧路径` 是记录，不改。

本对话后半段（cc 目录搬迁）有工具输出。前半段 Projects / CNB 同步只剩压缩摘要，不记入下面的命令。

## 可复用经验与案例

触发：把已跟踪目录挪到新父目录，仓根是 `*` 再 `!` 放行。

下次这样判：

1. 先分两类目录。集合级账本（本轮的 `fork/docs`、`repositories/public/docs`、`github/scripts`、`paused/reverse/docs`）可以收进统一的 `web/docs` 或 `web/scripts`。上游克隆和项目自己的 `docs`/`scripts`（maka、magpie、CLIProxyAPI、console、逆向案例）留在原树。拆走后，仓内相对路径和验收脚本的父目录假设会断。
2. 放行规则是活指针。本轮根上的 `!/interview/`、`!/passkeys/`、`!/reverse/` 在目录进入 `code/paused/` 后不再命中，整树被 `*` 吃掉。四个逆向上游克隆的再排除也要从 `reverse/code/<名>/` 改成 `code/paused/reverse/code/<名>/`。只改放行、不改后面的排除，会把不该进仓的嵌套仓放进来。
3. 脚本若用「自己所在目录的上 N 级」当仓库根，搬一层就指错。本轮 `go-skills.mjs` 从 `web/scripts` 必须再上两级才是 `E:\cc`，锁文件是 `web/docs/skills-lock.json`。`check_docs.py` 的验收根改成从脚本位置拼 `code/paused/interview`，不能再假定脚本躺在目标目录里。
4. PowerShell 的 `Move-Item` 在目标不存在时是改名。本轮第一个子目录 `Gemini 4 Argon` 被改名为 `web\temp`，随后的文件掉进这个被改名的目录。正确顺序是先建目标目录，再逐项移入。同卷移动整个已存在的目录则是改名，很快。
5. 文件已经移走，打开它的进程仍可能占着旧目录。本轮 `rmdir E:\cc\temp` 报文件被占用；`Win32_Process` 的命令行仍是 Typora 打开 `E:\cc\temp\临时日志.md`。不要为删空目录结束用户的进程。空目录当时没删成，本次收尾未再查。

检验：搬完一个白名单目录后，旧路径应被 `*` 忽略，新路径的最后一条匹配应以 `!` 开头；故意再排除的嵌套仓最后一条应是不带 `!` 的规则。本轮对 `code/paused/interview/README.md`、`code/paused/reverse/code/ARTIFEX`、`web/docs/fork/README.md` 跑过 `git check-ignore -v`，结果符合这个区分。没有另做一次「只改磁盘、不改 gitignore」的对照实验。

## 常用命令

在仓根执行。`-v` 会把「被 `!` 放行」的路径也打出来，退出码 0 只说明至少一个路径被忽略，不能当成「全部未跟踪」或「全部已跟踪」。

```powershell
git check-ignore -v -- <路径1> <路径2>
```

成功信号：每行是 `规则文件:行号:最后一条匹配规则<TAB>路径`。规则以 `!` 开头表示未忽略；不以 `!` 开头表示忽略。不加 `-v` 时只打印被忽略的路径。副作用：只读。

目录删不掉时，查谁的命令行还指着旧路径：

```powershell
Get-CimInstance Win32_Process | Where-Object { $_.CommandLine -match '<旧路径片段>' } | Select-Object ProcessId, Name, CommandLine
```

成功信号：本轮打出 Typora 与 `E:\cc\temp\临时日志.md`。前提：进程命令行仍保留启动参数；只凭句柄、不在命令行里的占用查不到。不要据此结束进程。
