# 静态整卡图在宽屏要跟容器走

归档判断：Skill 增量 + 独立笔记。不开 PR，不改写作技能。`gua-pr-patch`、`gua-writer` 无需改。

最值得留下的是一条边界：手机稿上的固定宽是稿面盒，不是宽屏内容区的 CSS 宽。图标「写死盒子」和 Figma「FIXED 写整数」都已经有了，但没写通栏静态位图该跟谁对齐。

资料缺口：上一轮完整 jsonl（`b4d878e3-…`）本机已不在。当前 transcript `9c34eca6-…` 不含「动态展开 / 整卡导出」原文。整卡导出的用户原话只来自会话摘要；宽屏不展开的根因，本轮是直接读到改前源码的。宽屏刷新没有在本会话里再看一眼。

## 1. 一句话结论

接诊准备首页 Hero 被锁成设计宽 `686rpx` + `aspectFit`，宽屏 H5 上停在左侧；同列「设备已连接」是 `width: 100%`。通栏静态图应宽跟容器、高跟图片比例（Taro `mode="widthFix"`）。

## 2. Skill 增量建议

### 2.1 通栏图不要套图标固定盒

| 项 | 内容 |
| --- | --- |
| 位置 | `gua-dev-tools` `modules/ui/references/style.md` P1.5，在「固定尺寸图片要写死盒」后面追加一句，不新开节 |
| 现有规则 | P1.5 只覆盖图标：组件默认 `width: 100%` 时，固定尺寸图在 flex 里要写死盒子。Figma 侧 FIXED 写整数、FILL 才 `flex: 1` |
| 缺口 | 没说：稿面 FIXED 整数宽（手机帧内容宽）不能当成宽屏下的渲染宽；同列已有 `width: 100%` 的兄弟时，位图跟容器 |
| 已写入 | 通栏静态位图不要套图标固定盒。同一内容列里兄弟已经 `width: 100%` 时，图宽跟容器，高度由图片比例撑开。设计帧上的手机稿整数宽只用来核对比例，不写死成宽屏 CSS 宽 |
| 证据 | 本轮读到改前 `HomeHero`：`mode="aspectFit"` + `rp-fixed-size(686rpx, 242rpx)`。`ImageWebp` 容器默认 `width: 100%`。用户口述（摘要）：图不动态展开，设备卡是满宽。改后 `tests/home.test.cjs` 输出 `receptionPrep home layout contract ok`。宽屏目视未复验 |
| 边界 | 只适用于要铺满内容列的位图。真图标、角标、固定槽位插画仍写死盒子。节点在稿里明确是 FILL 时，沿用已有 FILL 写法，不必再套这条 |
| 检验 | 宽屏下列里一张图写死设计宽、一张卡片 `width: 100%`：图应和卡片同宽。写死 `686rpx` 且图停在左侧 = 错。未在浏览器执行 |

### 2.2 Taro 通栏用 widthFix，不用 aspect-ratio

| 项 | 内容 |
| --- | --- |
| 位置 | `gua-dev-tools` `modules/taro/MODULE.md`「老安卓和平板兼容」表加一行，或反模式加一条 |
| 现有规则 | 平台机制归 taro；老 WebView 禁用 `gap` / `inset` 等。没有图片 `mode` |
| 缺口 | `aspectFit` + 固定宽高会把通栏图钉在设计宽。CSS `aspect-ratio` 老 WebView 不可靠 |
| 已写入 | 通栏位图用 Taro `Image` / 项目图片组件的 `mode="widthFix"`，样式只写 `width: 100%`，不写死高度。不用 `aspectFit` 配固定盒，也不用 CSS `aspect-ratio` 代替 |
| 证据 | 同 2.1。项目里登录海报等已经用 `widthFix`（`src/pages/login/index.tsx`）。本轮结构测试锁了 `mode="widthFix"`、`width: 100%`，并禁止 `rp-fixed-size(686` |
| 边界 | 仅 Taro 图片 `mode`。小程序里 rpx 随屏宽缩放时，设计宽有时看起来也是满的；以「同列百分比兄弟是否更宽」为准，不用 rpx 公式推断 |
| 检验 | 宽容器里 `widthFix` + `width: 100%` 的图，高度约为宽 × 图比例，且与同列满宽卡片对齐。`aspectFit` + 固定 `686rpx` 在宽屏仍是一条窄图 = 错。结构测试已绿；页面未复验 |

| 项 | 内容 |

## 3. 可复用经验与案例

**问题：** 接诊准备首页 Hero（`commonComponents/HomeHero`）在宽屏 H5 不随内容区变宽。

**关键证据：**

- 摘要：用户指出图没有动态展开；同屏设备卡是满宽。本轮未重开那张截图。
- 源码（改前，本轮读到）：`mode="aspectFit"`，样式 `rp-fixed-size(686rpx, 242rpx)`。
- 同项目图片组件：容器默认 `width: 100%`；通栏先例是 `widthFix`，不是再写一套量宽脚本。

**根因：** 把手机稿内容宽当成了运行时宽度，并把图标固定盒用到了通栏图上。`aspectFit` 在固定盒里不会把盒子拉到父级宽度。

**取舍：** 宽 `100%`，`mode="widthFix"`，去掉固定高。不引入 `aspect-ratio`，不加 JS 量宽。圆角仍在外层容器。

**验证：** `node src/subPackage/receptionPrep/tests/home.test.cjs` → `receptionPrep home layout contract ok`。`stylelint` 该文件退出码 0。宽屏页面未在本会话复验，不能写成视觉已通过。

**下次复用：** 看到「设计宽 rpx + aspectFit」和「兄弟 `width: 100%`」同时出现，先改图的宽高契约，不要先改圆角或重导图。
