# 首页还原与样式治理复盘

**一句话总结**：Taro H5 还原问题先查单位、实际渲染和最终样式，再用有效断言验证；公共样式按模块提取，Git 操作严格限定文件范围。

## 背景

这次处理了首页、工作台和底栏的样式还原，包括顶部留白、文字颜色、重复箭头、吸顶切换和菜单动画。随后整理组件职责与公共样式，并把不准备纳入本次交付的四个文件单独 stash。

## 核心命令

在项目根目录、依赖已安装时执行。以下用 Bash 表达对话中有效的命令，文件路径已泛化；PowerShell 的 ESLint 环境变量写法为 `$env:DISABLE_V8_COMPILE_CACHE='1'`。

```bash
git status --short # 查看工作区、暂存区及未跟踪文件，操作前后各检查一次
git diff --cached --name-status # 核对真正进入暂存区的文件，避免混入其他改动
git stash list --format="%gd %s" # 查看 stash 编号和说明
git stash show --include-untracked --name-status "stash@{0}" # 核对最新 stash 的实际文件，包含未跟踪文件
node node_modules/prettier/bin-prettier.js --write "<改动文件>" # 只格式化本次改动文件
node node_modules/prettier/bin-prettier.js --ignore-path .gitignore --check "<文档.md>" # 项目默认忽略 Markdown 时，显式检查指定文档
DISABLE_V8_COMPILE_CACHE=1 node node_modules/eslint/bin/eslint.js "<模块路径>" # 绕过本项目新版 Node 下的编译缓存冲突，执行 ESLint
node node_modules/stylelint/bin/stylelint.js "<模块路径>/**/*.scss" --customSyntax postcss-scss # 按 SCSS 语法检查样式
node "<模块路径>/tests/<测试文件>.test.cjs" # 直接运行已有模块测试；仍需确认入口实际执行了断言
```

## 关键结论

1. **像素还原先核单位和最终生效值。** 本项目设计宽度为 750，在已验证的 375 宽视口下，设计值通常除以 2；宽屏还要检查根字号限制。Taro H5 的 `Text`、`View` 会渲染为自定义元素，样式应挂显式 class。颜色、字号、行高和按钮默认样式必须用 computed style 核对，不能只看源码写没写。重复箭头要同时查图片与伪元素。

2. **布局问题先找实际平台入口和容器。** H5 可能命中 `index.h5.tsx`，只看 `index.tsx` 会误判包装层。此次包装函数没有透传 props，导致嵌入参数无效；隐藏页面的几何值为零，也会污染吸顶判断。修复思路是保留 props、跳过隐藏测量并在重新显示后重算；嵌入页面使用父容器高度，避免 `100vh` 和底栏预留重复计算。客户页相关修复后来按要求 stash，不能继续将其描述为当前工作区已生效。

3. **公共样式只抽真正重复的部分。** 采用 `styles/index.scss` 统一入口，`ui.scss` 放稳定颜色，`mixins.scss` 放重复结构，组件自己的尺寸、间距和状态仍留在 `index.module.scss`。相近颜色不强行合并，不为一次使用的样式造配方。纯提取应比较前后编译 CSS，确认选择器、声明顺序和值不变；公共入口本身不输出全局 CSS。

4. **测试通过要有实际断言。** 工作台测试曾采集字号却未断言，注入错误的 10px 字号仍然通过；补上字号和行高断言后才能捕获。仅导出函数的测试文件，直接用 node 运行也可能空绿，需要真正执行的入口。测试依赖凭证时，缺失应明确失败；检查工具若被依赖解析错误卡住，也不能据此宣称目标代码通过。

5. **局部 Git 操作要核对内容，不只看成功提示。** 只保存指定文件时，要考虑未跟踪文件，并检查 stash 的实际文件清单、原暂存区和其他业务文件是否保持原样。已有其他暂存内容时，不能把随手执行的整仓 stash 当作局部保存。测试文件和 `.debug/` 按本项目约定只留本地，不暂存或提交。
