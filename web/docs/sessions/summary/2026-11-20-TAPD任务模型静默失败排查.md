# TAPD 任务模型静默失败排查

## 1. 一句话结论

TAPD OpenAPI 大量写操作「返回 status=1 但实际不生效」（改父需求、非法 ID、旧端点碰新任务模型），唯一可靠判据是**写后用能真正读到该实体的端点回读核对**；项目分新旧任务模型，新旧端点不通用，认准 `task add` 启动日志里是否走 `POST /stories`。

## 2. Skill 增量建议（未执行，待确认）

均指向同事插件技能 `clife-tapd-frontend-task`（项目协作技能，不入个人 gua-* 技能）：

| 项 | 内容 |
| --- | --- |
| 目标位置 | SKILL.md 流程第 8 步「核对」下，与已有「改挂父需求」子项并列 |
| 现有缺口 | 第 8 步只写了 `tapd-cli task list` 核对，未区分项目任务模型；新版任务模型项目上该命令静默返回 0 条，核对步骤整体失效 |
| 建议追加 | 新版任务模型项目（`task add` 日志出现「走新任务分支: POST /stories」即新版）核对与状态变更改用 `story list` / `story update`（任务实体即 workitem_type_id 为任务类的 story）；`task list` / `task update` 在这类项目会静默查空/不生效。误建任务无删除 API，置 `status=rejected` 下架 |
| 来源证据 | 本会话柳州项目实测：`task list workspaceid=33278254 id=<新建ID>` 返回 `data:[]`、`task update status=progressing` 后 story 仍 `open`，改 `story update` 后变 `progressing`；襄阳项目 parent_id 假成功同族 |
| 适用边界 | 只针对 TAPD 新版任务模型项目；旧模型项目 `task` 端点仍正常 |
| 检验场景 | 在新版项目建一条任务后按第 8 步核对：用 `task list` 查应得 0 条（误报），用 `story list` 查应得完整字段——能区分两套端点行为即有效 |

另一条候选：流程第 5/6 步创建参数校验处补一句「分类 ID 等长数字字段传错位数会被静默丢弃（category_id 落回 -1）」——本会话少写 3 位实测静默；但其根因（非法值静默丢弃）已被「回读核对」兜住，是否单列由技能作者定。

## 3. 可复用经验与案例

**静默失败家族**（均为实测，非推测）：

| 操作 | 症状 | 有效路径 |
| --- | --- | --- |
| `task update` / `story update` 传 `parent_id` 改挂 | status=1，回读不变 | 专用接口 `POST /stories/update_story_parent`（story_id+parent_id+workspace_id，一次一条） |
| `task add` 传非法 `category_id`（少 3 位） | status=1，回读 category_id=-1 | 用 `story categories` 查全 ID 重传 |
| 新版任务模型项目用 `task list` / `task update` | 查空 / 状态不变 | `story list` / `story update` |
| 误建任务想删除 | CLI 无 delete 命令，API 无删除 | `POST /stories` 传 `status=rejected` 下架 |

排查路径复盘（可复用的判定顺序）：假成功 → 怀疑 CLI 过滤了字段（读 CLI 源码 `story update` 是全字段透传，排除）→ 怀疑 API 层 → 查官方接口索引找到专用端点 → 回读确认。即**先排除本机工具层，再怀疑服务端语义**，不要在工具层反复换姿势重试。

**执行反例**（技能已有规则被我违反）：创建结果不明时重放了一条 `task add` 做「测试」，多建出一条重复任务，只能 rejected 下架、用户手删。技能原文「同一任务的创建结果不明时，先用 task list 只读核对，不要重复创建」就是防这个——写入操作排查一律只读，不重放。

**多项目字段套不跨用**：profile.json 只存一个 workspace 的字段；襄阳（56610111）与柳州（33278254）的项目来源、所属端、分类 ID 全不同。换项目时找**同项目同类任务的现成工单抄字段**（本次抄了同事后端工单的 7 个字段），不猜枚举值。注意所属端是业务语义（他后台/我前端），抄模板时要按自己任务改。

## 4. 常用命令

```bash
# tapd-cli 源码构建（release 拉不动时；bundle 已在仓内则跳过）
npm --prefix <tapd-cli仓> install --no-audit --no-fund
sh <tapd-cli仓>/scripts/build-bundle.sh   # 产出 skills/tapd-cli/scripts/tapd-cli.cjs
# 运行：TAPD_API_ENDPOINT=https://api.tapd.cn TAPD_TOKEN=<令牌> node <仓>/skills/tapd-cli/scripts/tapd-cli.cjs <实体> <子命令> key=value

# 改挂父需求（CLI 未封装；Bearer 认证；一次一条，改完回读 parent_id）
curl -s -X POST https://api.tapd.cn/stories/update_story_parent \
  -H "Authorization: Bearer <TAPD_TOKEN>" \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "story_id=<任务ID>&parent_id=<父需求ID>&workspace_id=<项目ID>"

# 新版任务模型项目的状态变更与核对（task 端点无效）
tapd-cli story update workspaceid=<项目ID> id=<任务ID> status=progressing
tapd-cli story list workspaceid=<项目ID> id=<任务ID> fields=id,name,status,begin,due,effort,parent_id

# 误建任务下架（无删除 API）
curl -s -X POST https://api.tapd.cn/stories -H "Authorization: Bearer <TAPD_TOKEN>" \
  -d "workspace_id=<项目ID>&id=<任务ID>&status=rejected"
```

Git Bash 传含制表符字段（项目来源）：裸写 `key=$'襄阳项目-\t XS24011182.SJ001'`，**不能**套进双引号（`"$'...'"` 会把字面量原样传上去）。

Windows junction（无需管理员）：`cd <父目录> && cmd //c "mklink /J <链接名> <目标全路径>"`；循环里用变量拼目标会被转义成字面量（`skills$n`），逐条显式写全路径最稳；断链用 `cmd //c "rmdir <链接名>"` 摘除（不删目标内容）。

## 5. 待验证与不适用边界

- 「旧任务模型项目 task 端点正常」是从襄阳/柳州均为新版反推的假设，未在真旧版项目实测。
- `status=rejected` 在 TAPD 页面呈现为「已拒绝」而非消失，是否算合格下架未与团队约定核对。
- `update_story_parent` 为官方文档接口（open.tapd.cn → story → 更新父需求），未验证其对非任务类 story 的行为边界。
- 本文所有 token 均为占位符；真实令牌只在单命令变量或机器本地文件（`~/.zcode/tapd-pat.txt`）流转，不入库不入对话。
