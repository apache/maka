# cc 私仓历史重写与 Git 维护

## 一句话结论

cc 私仓在多机同步中经历镜像拉取（3 次）、大文件拒推、收编自带 .git 目录、远端孤儿根提交重建（reset --hard 对齐）与 reflog 瘦身（.git 2.6G→336M）；核心技法是临时索引比对磁盘与远端树，核心坑是 core.quotepath 对中文路径的静默转义。

唯一可选购（已执行，2026-11-19 用户确认；执行时发现通用铁律已有同根因的 grep 误判条目，按「改原规则不另起重复」合并为一条，同时覆盖统计漏配与删除漏删两个症状）：

- 目标：gua-dev-tools `SKILL.md` 通用铁律（与既有 wsl.exe UTF-16/WSL_UTF8 条目同类环境坑）
- 缺口：无 Windows+CJK 下脚本化处理 git 路径输出的规则
- 建议文本：脚本处理 git 输出的路径一律 `-c core.quotepath=false` 加 `-z` NUL 分隔；默认输出把中文路径转义成八进制字节串，sed 去引号与逐行 rm 会静默漏删
- 证据：本对话 sed 方案只删中 61 个文件（预期 1775，漏删 1714 个中文路径文件，`rm -f` 静默无报错）；换 `-z` 后 removed=1714 + not-on-disk=61 全命中
- 边界：仅脚本化处理 git 路径列表时；交互式操作不受影响
- 检验场景：含中文文件名的仓构造 diff 清单删除循环，sed 方案应漏删、`-z` 方案应全删

归属存疑理由：该坑发生在 cc 仓维护脚本里，康养前端日常 git 操作很少脚本化处理路径列表；写入前需确认是否值得为低频场景占铁律位。

## 可复用经验与案例

### 1. 多机镜像同步的判定与收口（本对话命中 3 次）

- 触发：本地未提交的大量改动（数千个 D）与远端新提交疑似同一件事——本机/自动化先动了盘，另一端随后提交了同样内容。
- 判定：临时索引比对（命令见下节 1），空输出 = 盘上内容与远端树逐字节一致。
- 收口：`reset --mixed origin/main` 只对齐分支与索引，盘上文件零重写；本地独有内容（untracked）原样保留。
- 边界：`reset --hard` 会物理删除盘上 tracked 文件，只在用户明确「以远程为主」授权后使用，且先建备份分支。

### 2. 收编自带 .git 的目录（cc 先例：reverse 5480 文件、work/lab 2482 文件）

- 默认 `git add` 嵌套仓 → 记成 160000 gitlink（空指针，克隆拿不到内容）；`git ls-files -s | awk '$1=="160000"'` 可列出。
- 三步法：全量 add → `git rm --cached -f <嵌套仓>`（刚暂存的 gitlink 不加 `-f` 会拒绝）→ 临时挪走 `.git` 再 add 内层文件。
- 坑：挪走后的备份名（如 `.git__ccbak`）失去 `.git` 天然豁免，被白名单规则收进暂存（本轮混入 155 条），需 `git reset -q -- ':(glob)**/.git__ccbak/**'` 清理后再挪回。

### 3. merge 会被「内容相同」的被忽略文件阻断

- 行为证据：`git merge --ff-only` 报 "untracked working tree files would be overwritten"，列出的文件实际被根 `.gitignore` 的 `*` 规则忽略（`git ls-files -o` 返回 0），且内容与远端逐字节一致（临时索引已证明）。merge 不做内容比对，路径存在即拒。
- 机制未查证 git 源码，按「行为确认、机制存疑」记录。
- 处理：删除与远端一致的本地副本后重新 ff；删除清单必须用 `-z` 生成（见坑 6）。

### 4. 历史被重写的识别与对齐

- 信号：`git merge-base` 退出码 1；远端 HEAD 无父提交（孤儿根）；旧提交不在 origin/main 可达集（`merge-base --is-ancestor` 为假）。
- 流程：向用户确认决策（本轮「以远程为主」）→ 建备份分支 → `reset --hard` → 汇报丢失面明细（本轮 3811 D，主要为 guahub/reverse/code 改记 gitlink）。
- 后续：备份分支删除后 reflog 仍保留旧线约 90 天；`reflog expire + gc --prune=now` 提前关闭窗口（用户主动选择执行）。
- 副作用认知：孤儿根重建意味着所有机器首次拉取都会遇非快进错误，属预期。

### 5. GitHub 大文件红线与 LFS 指针空壳

- >100MB 拒收（GH001，实测 134.3MB tar.gz 被拒）；>50MB 仅警告（76/58/44MB JSON 均推送成功）。
- 修法：`git rm --cached <文件>` + .gitignore 加规则 + `commit --amend` 重推；磁盘文件保留。
- LFS 空壳：远端提交可只含指针不传实体，checkout 时才爆 404（本轮 6 个 fixture）；只有存有实体的机器能 `git lfs push origin --all` 补传。

### 6. cc 仓现状事实（项目专属，易变）

- 多机同仓：本机自动化定时提交（「docs: 文档同步更新」/「update: 更新」），另一台机器独立提交；2026-10-25 远端整仓重建为孤儿根提交 22249b41d。
- 现行布局：repositories/{private,public}（public 多仓为 gitlink）、guahub/reverse/code 4 项目为 gitlink；cc 仓 .git 336M（gc 后），跟踪内容 0.25G/14251 文件。
- 子模块指针 M 状态（本地 clone HEAD ≠ 指钉 SHA）是常态非冲突；处理原则：只核验可达性（`cat-file -e`，缺则 `fetch`），不 checkout——本地 clone 带未提交工作。
- 体积参照：39G 总盘大头是邻居（github/ 上游克隆 23G、guahub/fork 5.4G），均独立管理不入 cc 跟踪。

## 常用命令

### 1. 临时索引比对磁盘与远端树（核心技法）

```bash
export GIT_INDEX_FILE=/tmp/idx-check; rm -f "$GIT_INDEX_FILE"
git read-tree origin/main
git diff --no-renames --name-status   # 空=逐字节一致; M=内容不同; D=盘上缺失
unset GIT_INDEX_FILE
```

适用：判断「本地盘 vs 远端最终状态」是否镜像。副作用：仅写临时索引文件，不动工作区与真实索引。注意 diff 输出路径含转义，机器处理需配 `-z`。

### 2. CJK 路径安全循环（Windows，core.quotepath 默认开启时）

```bash
git -c core.quotepath=false diff -z --no-renames --name-only A B > /tmp/paths.bin
while IFS= read -r -d '' f; do [ -f "$f" ] && rm -f -- "$f"; done < /tmp/paths.bin
```

成功信号：处理计数与清单一致；失败信号：不加 `-z` 时中文路径变八进制转义，rm 静默漏删（本轮漏 1714 个）。

### 3. gitlink 指针清点与可达性核验

```bash
git ls-files -s | awk '$1=="160000" {print $4}'
git -C <clone路径> cat-file -e <sha> || git -C <clone路径> fetch origin
```

### 4. 跟踪内容体积（不含子模块指针）

```bash
git ls-files -s | awk -F'\t' '$1 !~ /^160000/ {print $2}' > /tmp/tp.txt
xargs -d '\n' du -cb -- < /tmp/tp.txt | awk '$2=="total"{s+=$1} END{printf "%.2f GB\n", s/1073741824}'
```

本轮实测 0.25 GB / 14251 文件（Git Bash 环境）。

### 5. ⚠️ 历史瘦身（销毁全部不可达对象的恢复窗口）

```bash
git reflog expire --expire-unreachable=now --all && git gc --prune=now
```

前提：所有机器已对齐新历史、明确放弃旧线。本轮实测：.git 2.6G→336M，对象 82795→16273，pack 6→1；执行后 `fsck --connectivity-only` 通过。用户本人执行，本会话未重复执行。
