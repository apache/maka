# Taro 首页 Figma 还原与分支规范踩坑

**一句话总结**：v1.7.3 迭代从零还原首页 H5 与成交复盘新模块，踩遍 Taro H5 渲染坑、Figma 取数坑、stylelint 白名单坑和 git 分支污染坑，全部定位根因修复并沉淀为测试断言。

## 背景

在 homing-miniapp-workbench（Taro 3.6 + React + SCSS，设计稿宽 750）做 v1.7.3 迭代：按 Figma 还原首页 H5 和成交复盘新模块，期间经历分支重建（原分支错误基于 customerprofile，规范要求基于 develop）、模块重命名、两轮代码审核。过程中暴露出一批「代码写了但样式没生效」「设计稿树不可信」「共享分支被污染」的问题。

## 核心命令

```bash
# Figma：拉节点树 JSON（含全部样式元数据）
curl -s -H "X-FIGMA-TOKEN: <FIGMA_TOKEN>" "https://api.figma.com/v1/files/<fileKey>/nodes?ids=9589:4230" -o node.json

# Figma：请求渲染图 URL（scale 控制倍率），再 curl 下载返回的临时 URL
curl -s -H "X-FIGMA-TOKEN: <FIGMA_TOKEN>" "https://api.figma.com/v1/images/<fileKey>?ids=9589:4230&format=png&scale=1"

  node .debug/scripts/figma-to-cos.mjs --file <fileKey> --ids "a:b,c:d" --scale 2 --const-prefix 业务前缀

# stylelint：SCSS 必须带 customSyntax；--fix 自动收敛属性排序；检查数应归零
npx stylelint "src/pages/xx/**/*.scss" --customSyntax postcss-scss --fix
npx stylelint "src/pages/xx/**/*.scss" --customSyntax postcss-scss 2>&1 | grep -c "✖"

# 最小 tsconfig 类型检查（全量 tsc 有存量噪音不可用）：从已验证配置派生，只换 files

node_modules/.bin/tsc -p .debug/tsconfig.xxx.json 2>&1 | grep -v node_modules

# eslint：Node 26 下必须加前缀防 V8 缓存崩溃；--quiet 只看 error；--fix 收敛 import 排序
DISABLE_V8_COMPILE_CACHE=1 npx eslint "src/pages/xx" --fix
DISABLE_V8_COMPILE_CACHE=1 npx eslint "src/pages/xx" --quiet; echo $?

# git 同步完整性三件套：差值归零 + 祖先关系 + 提交计数
git fetch origin
git log <本地分支>..origin/<上游分支> --oneline | wc -l        # 0 = 无遗漏
git merge-base --is-ancestor origin/<上游分支> <本地分支> && echo OK
git rev-list --count origin/<上游分支> ^<本地分支>              # 0 = 全包含

# dev server 锁住目录导致 mv 失败：查端口 PID 后强杀再移动
netstat -ano | grep ":10086"        # 找 LISTENING 的 PID
taskkill //PID <pid> //F            # Git Bash 下 // 转义单横线
cp -r src/pages/a src/pages/b && rm -rf src/pages/a   # 绕过目录句柄锁的重命名

# 恢复 stash 且保留暂存区状态（普通 pop 会把 staged 混回工作区）
git stash push -u -m "WIP 描述"     # -u 含未跟踪文件（新模块目录必须）
git stash pop --index
```

## 关键结论

1. **Taro H5 的 `Text` 渲染为 `taro-text-core` 自定义元素，SCSS 里 `text {}` 标签选择器永远不生效**，颜色静默回退 UA 默认黑。所有文字样式必须给 `Text` 显式 className；用结构测试断言全模块禁止 `text {}` 防回归。
2. **`appearance: none` 不会移除 button 的 UA 默认 border**，「去邀约」按钮黑框事故的根因。按钮公共块必须显式 `border: 0`（需要边框的再单写），配套 `box-sizing: border-box` 和 `font-family: inherit`。
3. **Figma paint 有双层透明度**：实际值 = `color.a × paint.opacity`，dump 脚本漏掉 paint.opacity 会把 10% 浅紫底全判成实色紫；描边的 `strokeOpacity` 又是独立字段。节点树 dump 脚本必须同时算这两层。
4. **设计树不可尽信**：`visible=true` 但包围盒超出父 FRAME 的子节点是设计师废弃稿（渲染图里不存在），照树还原即无中生有；单个 TEXT 节点的段级多色（如「转化 80%」橙色段）树 dump 读不到，按渲染图核对。树推演清单与渲染图逐块比对是交付前的兜底动作。
5. **设计稿自相矛盾时取文案语义**：进度条画 53% 但文案「11/12」按 92% 实现；筛选高亮「优先复盘(2)」但列表画了全部——默认展示信息更全的状态，矛盾点报告人工，不擅自编值。
6. **stylelint 白名单遗漏会让 --fix 毁代码**：standard 预设会把 `rgba(r,g,b,a)` 自动转成 Color4 现代语法 `rgb(a b c / 45%)`，老 WebView 不支持即整条声明失效。新建模块要同步加进 `stylelint.config.js` overrides 的 files 白名单，且结构测试加「禁现代语法」断言。
7. **`checkout -b <分支> origin/develop` 会把 upstream 设为 origin/develop**，之后 IDE 里点推送会把提交直接推上共享 develop 分支。共享分支被污染的处置：`git push origin <污染前提交>:develop --force` 回滚（⚠️ force 重置共享分支，执行前先 fetch 确认无人再推、污染点之后的提交无团队产出），本地提交用 `git branch --unset-upstream` + `git branch -u origin/<自己的分支>` 归位。
8. **跨端组件共用时改高度契约要两端评估**：把 100vh 改 100% 修嵌入态裁切，会破坏独立路由打开和小程序端（custom tabBar 占位依赖 128px padding），改一半被叫停就整文件 `git checkout --` 回滚。
9. **H5NavBar 等 fixed 定位导航层**默认白底，用组件透出的 className 把背景改成页面底色，否则滚动内容从导航后穿出时露白。
10. **接手他人模块先跑审计脚本再动手**：用 node 提取类型文件全部字段名、在 tsx 里反查 `.字段` 消费计数，零消费字段（如孤儿 footerText）直接删，避免为「看起来该有」的字段编造消费点。
