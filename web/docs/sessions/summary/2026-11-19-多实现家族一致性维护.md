## 一句话结论

同一逻辑的多实现家族（或任何"准绳 + 复制品"结构）修 bug 时，先做全实现 diff 再动手；分歧按"本质约束 + 多数派"裁决、准绳自身缺口也要修；错误处理契约由调用语境的失败传播能力决定，不由默认姿态决定。

**建议追加文本**：

> 定错误处理方式（抛/返回错误值/警告/静默）前，先核调用语境的失败传播能力：闭包、回调、循环体内的调用不可上抛，抛异常会在启动或装配期崩溃；此时 loudly 的等价物是 stderr/日志警告后跳过。只对"丢了会出安全或数据问题"的路径坚持 fail-fast 上抛。

**证据**：coding-agent 提交 72833db（`fix: 技能索引错误契约五版同步`），含修订理由与五版验证（ts 54/54、py 58/58、go ok、rust 55/55、cs 63/63）。

**边界**：适用于给工具函数/可选增强定错误契约；不适用于安全边界与数据写入路径（那里仍 fail-fast）。多语言镜像项目里"契约修订要五版同步改+测试翻转"是该项目特例。

**检验场景**：一个 `listDir()` 工具函数在启动装配的回调里被调用，权限不足时——正确动作是 stderr 警告+跳过；若建议的规则缺失，模型会按"Fail fast"直接抛异常导致启动崩溃。

## 可复用经验

### 1. 多实现家族的一致性维护流程

同一逻辑存在 N 个实现（多语言移植、多端复制）时：

1. **动笔前全实现 diff**：逐条提取每个实现的行为规则（数值、顺序、边界条件、失败行为），带 file:line。分歧清单本身就是设计信息。
2. **分歧裁决**：要么改代码要么改规格，不允许规范与现实各说各话。判准是本质约束（这条规则存在的目的）+ 多数派；写成"允许偏差"登记在案的必须是平台能力差异或明确加严，不是偷懒。
3. **准绳自身会烂**：两个真实案例——① 准绳 tcode 的 compact 用了第二份估算函数（不计 tool_call name），与自己的注释"与 trim 同款"矛盾，四兄弟全对，修准绳（删副本复用）；② tcode 注释宣称"流中断不重试"，但流中读错误以 TypeError 冒泡会命中重试白名单，实测断连后真重试 3 次含 3.1s 退避（假 SSE 服务器 + 连接计数取证），其余四版都有防线，修准绳。**"参考实现不是规范"——准绳的注释与实现矛盾时，信本质约束，不信身份。**
4. **每处修复带"修前会挂"的回归锁**：红相要取证（实际跑一次看到失败），锁要落五版镜像。

### 2. 错误契约的自查信号

出现以下信号说明契约定错了，回头查调用链：为"可选增强"定上抛后，测试替身需要特殊处理才能不崩；同一错误在同一函数里既要"不阻断"又要"抛"——说明有两个调用语境，契约应按语境分裂或取最保守公共集。

### 3. 平台坑两则（诊断信号，防再误判）

- **Windows 的 `os.ReadDir`/目录枚举指向一个文件时不报错，返回空列表**（POSIX 会 ENOTDIR）。后果：file-as-dir 构造不可读目录的测试在 Windows 上测不到警告分支。处理：`runtime.GOOS` skip 并注明"红能力在 POSIX runner"；分支本身由源码保证。
- **Rust 的 `env!("CARGO_BIN_EXE_x")` 在编译期把绝对路径烧进测试二进制**。整仓搬迁后 cargo 认为目标仍新鲜不重编，冒烟全场景秒挂（0.00s 全灭）。诊断：失败速度异常快 + 全灭 + 源码没动过。处理：`touch tests/smoke.rs` 强制重编即愈。已记入 ADR-001 后果。

### 4. 大迁移的 git 提交拆分

目录收口要"纯移动"与"内容修改"分开提交时：`git reset` 后 `git checkout HEAD -- 旧路径` 重建原始内容 → `git mv` 出纯 rename 提交（用 `git show --name-status | grep -vc "^R100"` 验证 0 残留）→ 换回真实工作树再提交修改。直接在工作树上 `git mv` 会让 rename 提交吸收未提交的修改。坑：`git mv` 会被"git 跟踪但工作区已删"的文件阻断（bad source），改用文件系统 `mv` + 定向 `git add -A -- 旧路径 新路径`，rename 交给相似度检测。

### 5. 跨目录批量替换的方法论

多目录路径迁移时，**枚举链文本（如 "go/rust/cs"）绝不能作为 sed 模式**——会把并列枚举误改成路径。安全做法：先 `rg -o "形态" | sort | uniq -c` 提取全部真实形态，只对"不会出现在自然语言里"的子串（如 `typescript/src`、`python/pcode`）逐形态替换；验证用负向后顾断言 `rg -Pc "(?<!新前缀/)旧形态"`，注意新形态包含旧形态子串（`impls/typescript/src` 包含 `typescript/src`），普通 grep 会假阴性。

## 常用命令

均为本对话实际执行、有可见结果的最终有效版本（Windows Git Bash）。

```bash
# 为"已改完的代码"补红相取证：stash 掉修复，跑测试看到旧缺陷，再恢复
git stash push -m "provider-fix-tmp" -- <修复文件...>
node --test test/retry.test.ts   # 看到旧行为失败的证据（本次：3 次连接含 3.1s 退避）
git stash pop

# 验证提交是否纯 rename（0 = 纯移动）
git show <commit> --name-status --format= | grep -vc "^R100"

# 批量替换后验证无残留（负向后顾，防"新形态含旧形态"假阴性）
rg -Pc "(?<!impls/)typescript/(src|docs|test)" README.md specs docs --glob "!**/__pycache__/**"
# exit=1 且无输出 = 清零

# 解除跟踪但不删盘上文件（历史误跟踪的产物出库）
git rm -r -q --cached "*.pyc"

# Windows 装 .NET SDK（ccode 验证前置）
winget install Microsoft.DotNet.SDK.8 --accept-package-agreements --silent
```
