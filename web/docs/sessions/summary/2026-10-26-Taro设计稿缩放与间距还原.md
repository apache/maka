# Taro H5 设计稿缩放下的间距还原排查

**一句话总结**：护理报告页底部间距怎么改都"超过 32px"，根因是 Taro H5 按 `designWidth: 2560` 整页缩放（1280 视口下 0.5 倍），且卡片写死 1240px 高度没跟着视口撑满，用 flex 链路改成自适应后底部恒等于设计稿 32px。

## 背景

服务已完成报告页（serviceComplete）做 UI 还原：设计稿标注底部留白 32px、阶段卡与居家选择区间距 42px，但页面上看底部空隙始终超过 32px，窗口越高越大。devTool 检查 `.reportSlide` 显示 computed padding 是 `16px 20px`，和代码里写的 `32px 40px` 对不上，由此入手排查。

## 核心命令

```bash
# 查 Taro 设计稿宽度配置（缩放系数 = 视口宽 / designWidth）
grep -rn "designWidth\|baseFontSize\|deviceRatio" config/*.js

# 改共享 CSS 变量前先摸清全部消费方，评估影响面
grep -rn "accent-surface-color" src --include="*.scss"

# 只对本次 touched 文件跑格式与样式检查（项目约定不跑全量 format）
npx prettier --check src/pages/serviceComplete/components/A/index.module.scss src/pages/serviceComplete/components/B/index.module.scss
npx stylelint "src/pages/serviceComplete/components/A/index.module.scss" "src/pages/serviceComplete/components/B/index.module.scss"

# 复查改动范围与内容
git diff --stat && git diff
```

## 关键结论

1. **设计稿 px ≠ 页面视觉 px**：`config/index.js` 里 `designWidth: 2560`，Taro 把样式按视口比例换算，1280 视口下缩放系数 0.5——代码写 32px 实际渲染 16px。DevTools 里 computed 值与代码值的比值可直接反推缩放系数，不要拿浏览器标尺对着设计稿数字硬量。
2. **底部空隙超标的根因是两层叠加**：页面缩放（32 只渲染 16）+ 卡片写死高度。section 被 `min-height: 100%` 拉满但卡片固定 1240px，空隙 = (视口内容高 − 1240) + padding-bottom，窗口越高多得多。解法是搭 flex 链路：section 改 `flex-direction: column` → 布局层加 `flex: 1` → 栏由 stretch 撑满 → 卡片 `min-height: 1240px` 改 `min-height: 100%`，写死高度全部降级为兜底下限。
3. **改共享 CSS 变量先 grep 消费方**：`--report-module-accent-surface-color` 从 `#f2f5ff` 换成 `rgb(99 129 255 / 10%)`（设计要的"主色减不透明度"）前，确认 3 个使用方全是"品牌色浅底"语义才动手；夜间模式单独的变量值不动。
4. **该项目 stylelint 脚本在 Windows 下不可用**：`npm run lint:style` 因 npm script 单引号 glob 不展开而失败，且 stylelint 14.16+ 已移除 `--syntax` 参数；直接 `npx stylelint "<文件>"` 可用，输出里的 customSyntax 提示是环境警告可忽略，exit code 有效。
5. **两个兼容要点**：百分比 `min-height: 100%` 在 stretch flex item 父级下可正常解析（现代浏览器标准行为）；卡片内 `position: absolute; bottom: 0` 的按钮会跟随卡片新高度继续贴底，卡片改自适应后内部不跑位。
