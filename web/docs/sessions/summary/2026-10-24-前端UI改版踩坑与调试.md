# 前端 UI 改版踩坑与调试（Playwright 驱动真实页面）

**一句话总结**：在冻结测试的约束下对工作台页面做两轮视觉改版，用 Playwright 事件探针定位并修复"自动保存禁用表单吞输入"和"提示条布局抖动吞点击"两个经典前端坑。

## 背景

给本地 coding agent 的单文件工作台页面（HTML 内联 CSS/JS）做改版，验收标准是 73 个 Playwright 用例全部冻结、只许改 HTML 一个文件。引入"修改即保存"和浮动轻提示后，出现输入莫名丢失、按钮点了没反应两类诡异问题，需要在不碰测试的前提下定位。

## 核心命令

```bash
# Playwright 锁定版本的浏览器没下载时，把 CHROME_PATH 指到本机已有的缓存版本，不用重新 install
CHROME_PATH="$HOME/Library/Caches/ms-playwright/chromium_headless_shell-1248/chrome-headless-shell-mac-arm64/chrome-headless-shell" npm run test:ui

# 嵌套/子目录仓库操作一律 git -C，免 cd，避免 shell 钩子截断命令链
git -C <仓库路径> switch develop
git -C <仓库路径> merge feature-branch   # 对方无新提交时自动快进合并，历史线性

# 合并前双向查看分叉情况（能快进 = 反向为空）
git -C <仓库路径> log --oneline develop..feature-branch
git -C <仓库路径> log --oneline feature-branch..develop

# 从 node --test 输出提取汇总（汇总行前缀是 ℹ 不是 #）
grep -E "^ℹ (tests|pass|fail)" /tmp/test.log

# 单文件 HTML 改完先自查内联 JS 语法，别等浏览器运行时才报错
node -e "const s=require('fs').readFileSync('web.html','utf8'); new Function(s.match(/<script>([\s\S]*)<\/script>/)[1]); console.log('JS OK')"
```

## 关键结论

1. **后台自动保存不要禁用表单**：blur 触发上一控件的 change 并发起保存，若保存期间把整个表单 disabled，紧接着的下一处输入就写不进去（值静默丢失）。后台保存用独立标志位、不禁 UI；只有用户点按钮的显式保存才禁用表单。
2. **占文档流的提示条会吞点击**：toast 出现/消失把内容上下推几十像素，鼠标 mousedown 和 mouseup 之间布局一抖，mouseup 落到移进来的相邻元素上，click 事件就不会派发到目标。提示一律用 absolute/fixed 浮动层，不参与布局。
3. **Playwright 定位这类 bug 的套路**：initScript 里在 capture 阶段监听 `mousedown/mouseup/click` 并打印 `e.target`，配合 `document.elementFromPoint(元素中心点)` 对比预期；"click resolved 但 handler 没跑"基本就是布局位移或控件中途 disabled。用 `defineProperty` 陷阱包住 `disabled` 的 setter 还能抓到是谁禁用的。
4. **"视觉隐藏但测试可见"用 sr-only**：clip-path 1px 方案保留无障碍树和 Playwright 可见性（checkbox 的 isVisible、select 的 selectOption 都正常）；`display:none` 会让元素从 a11y 树消失，getByRole 直接找不到。
5. **测试锁定的精确文案不要在页面出现两处**：`getByText(..., { exact: true })` 是严格模式，多一个匹配直接报错——改版时砍重复信息既是为了设计也是为了测试。

## 下次怎么用

- 给有测试护栏的页面做改版：先跑基线确认全绿，改完回归；遇到"点了没反应/输入丢了"，先怀疑布局抖动和保存期间 disable，用上面的事件探针十分钟内可定位，不用靠猜。
- 新增"修改即保存"类交互：保存请求与 UI 禁用状态解耦是第一原则；提示性反馈一律浮动层。
- 本机 Playwright 浏览器版本对不上 CI/项目锁定版本时，指一个已有缓存的可执行文件即可顶替，版本号小幅差异不影响 UI 测试（待验证：大版本差异可能有 API 行为差异）。
