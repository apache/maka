# D 盘工具链统一与多智能体实现复盘

一句话结论：把散落 C 盘的六套语言工具链、四个数据库与开发_opts 全部以**官方安装器**形态统一到 `D:\DevTools` 分类布局（每类 `Install\` 归档官方包），期间沉淀了 Windows 静默安装姿势、四个安装事故的诊断信号，以及双编译器多智能体实现的可复用方法论；三个个人 Skill（dev-tools/writer/pr-patch）职责域均不含本次内容，无 Skill 增量。

## Skill 增量建议

**无**。逐个核对过：gua-dev-tools 是康养/美业前端交付工具箱（路由表无环境管理/编译器/CI 域）；gua-writer 是写作规则；gua-pr-patch 是开源贡献。本次内容按职责归属放独立文档，不硬塞。

唯一够格升级的是一条**全局执行纪律**（属于根 AGENTS.md 的「执行」节，不属于任何 Skill）：

> 委派子智能体的任务书必须包含**完整门禁清单**（fmt/lint/test/build 各项），并要求回报时逐项给出门禁证据；主智能体集成时**亲自复跑**全量门禁，不转述子智能体的"全绿"。

证据：lang-rs 集成轮中子智能体修完 `builtin.rs` 漏跑 `cargo fmt --check`，CI 红了才发现（日志是 fmt diff 而非测试失败，一度误判为测试问题）；此后的任务书把门禁清单加粗为硬要求，后续再未复发。现有 AGENTS.md 已有"主 Agent 验证最终结果"的原则，此条是它的具体化，是否追加由你定。

## 可复用经验与案例

### 1. D:\DevTools 布局惯例（两条用户纠正过的铁律）

- **官方安装器优先，禁止复制/搬移**：曾用 `mv`/`cp -r` 迁移 Python 和 Go，后用户明确要求改为官方 exe/MSI/rustup-init 重装。复制的隐性代价：pip shim 内嵌旧绝对路径、卸载器失联、"添加/删除程序"无记录。
- **Install\ 归档惯例**：每类目录下建 `Install\` 存本次下载的官方安装包（Database\Install、DevOpts\Install、Java\Install、Fnm\Install 四处已入册 10 个包），下次重装不再找包。

布局：`Languages\Backend\{Python,Golang\Go,Rust\.cargo|.rustup,Dotnet,Java}` + `Languages\Frontend\{NodeJS,Fnm}` + `Database\{MongoDB,MySQL,PostgreSQL,mongosh,DB Browser for SQLite}` + `DevOpts\{Git,Nginx,Redis}`。配套 `setup-dev-env.ps1` 幂等脚本：独立环境变量块（JAVA_HOME/GOPATH/CARGO_HOME/RUSTUP_HOME/DOTNET_ROOT/FNM_DIR/SDKMAN_DIR）+ 按优先级前置用户 PATH + 逐工具版本验证，可重复运行。

### 2. Windows 静默安装姿势（全部实测退出码 0）

| 工具 | 关键参数 | 前提 |
| --- | --- | --- |
| Python 官方 exe | `/quiet InstallAllUsers=0 TargetDir="D:\..." Include_launcher=0 PrependPath=0` | per-user 免管理员；py launcher 自动写 HKCU（`py -0p` 能看到 D 盘路径） |
| Go MSI | `msiexec /i x.msi INSTALLDIR="D:\..." /passive /norestart` | 需管理员（UAC） |
| MySQL MSI | 同上 | 同上 |
| Git exe | `/VERYSILENT /NORESTART /DIR="D:\..." /LOG=路径` | Inno Setup 系；带 /LOG 便于排障 |
| rustup-init | 预设 `CARGO_HOME`/`RUSTUP_HOME` 后 `-y --default-toolchain stable --no-modify-path` | 免管理员；--no-modify-path 防它改 PATH |
| .NET | `dotnet-install.ps1 -Channel 10.0 -InstallDir` + 手动设 `DOTNET_ROOT`、`DOTNET_MULTILEVEL_LOOKUP=0` | 免管理员 |
| JDK | Adoptium API 可钉精确版本：`api.adoptium.net/v3/binary/version/jdk8u502-b07/windows/x64/jdk/hotspot/normal/eclipse`；钉不上退 `/binary/latest/21/ga/...` | zip 解压即用 |

### 3. 安装事故手册（诊断信号 → 根因 → 修法）

- **pip shim 内嵌绝对路径**：`mv` 迁 Python 后 `Scripts\pip.exe` 内部仍指旧盘路径（`grep -ao "C:\\\\...python.exe" pip.exe` 可验）；`--quiet` 会掩盖 shim 重装失败。修法：官方安装器重装，或 `python -m pip install --force-reinstall --no-deps pip` 且不用 --quiet。诊断信号：`pip --version` 报旧路径。
- **MSI `/passive` 不等于完整安装**：MongoDB 8.3.8 MSI 静默装完 `bin\` 里只有 mongos 没有 mongod——缺 `ADDLOCAL`。修法：`ADDLOCAL="ServerService"` 重跑，服务+mongod 一次到位。教训：MSI 静默装完必须核对关键 exe 是否存在，exit 0 不代表装全。
- **MSI 无视 INSTALLDIR**：Memurai 4.2.3 传了 INSTALLDIR 仍装进 `C:\Program Files`。修法（一次 UAC）：停服 → 整目录搬移 → `sc.exe config <svc> binPath= "<新路径>"` → conf 里相对路径（`dir ./`、logfile）改绝对路径（否则服务模式会写进 System32）→ 起服 → 服务 PathName 与 `cli ping` 双验证。
- **ZCode 会话 shell 根绑定 Git 安装目录**：连续两个会话瘫痪——shell 根分别是 `Languages\DevOpts\Git` 与 `DevOpts\Git`，前者在被收拢/退役的旧目录，后者在尚未装完的新目录，`spawn bash.exe ENOENT` 导致全部 Bash 工具不可用，但 Read/Write 不依赖 shell 仍可工作。预防：**重装/搬移 Git 前先确认没有会话以它为 shell 根**；瘫了以后用 Read/Write 继续干收尾活。
- **SDKMAN 安装器依赖 zip**：Git Bash 自带 unzip 无 zip，`get.sdkman.io` 脚本会拒跑。绕法（已验证 5.23.1）：下载 sdkman-cli 官方发行 zip 解到 SDKMAN_DIR → 手工补 `var/platform`（内容如 `x64 MINGW64_NT-...`）、`var/candidates`、`var/version`、`etc/config`、`ext/`、`candidates/` → `source sdkman-init.sh` → `sdk update` 拉全量候选目录。注意 source 必须与 `sdk` 调用同一 shell（管道/子 shell 里定义的函数不回传）。

### 4. 多智能体双编译器实现方法论（lang-rs → lang-cs 的复利）

- **任务书四要素**：文件级独占领地（防写冲突）＋必读清单＋有界交付＋**完整门禁清单并要求回报门禁证据**（见上文反例）。
- **接口契约冻结文件**先行（19 crate/20 项目依赖预接线，Agent 零 Cargo.toml/csproj 冲突）＋每 Agent 一个 status 看板文件（防共享台账写冲突）。
- **波次推进 + 集成轮**：协调人在集成轮亲自复跑全量门禁与差分，不采信转述；跨 crate 接口缺口先在 status 登记 BLOCKED，不直接改别人文件。
- **教训内化的复利**（最有价值的一条）：lang-rs 四波 + 集成轮修 33 格红；lang-cs 把全部教训（赋值降形栈序、预载定义按名映射、构造指令 pop_n 不 reverse、slnx/dev-dep 前缀可编译性）写进任务书，**零集成修复轮**直接 151×4 全绿。教训文档化是并发效率的最大杠杆。
- **平台限流重跑策略**：子智能体被限流打断时要求"保持已写文件可编译 + 进度落 status 文件再收工"，重跑零损失（本轮 4 次限流全部无损失重跑成功）。
- **依赖咬合决定提交拓扑**：dev-dependencies（如测试引用断言器）会让"每笔提交可编译"在直观拆分下不成立——用 `git worktree add` 逐前缀验证再定提交序；worktree 路径用正斜杠（反斜杠会被 MSYS 转换毁掉 robocopy/构建器参数）。slnx/工作区清单类文件必须**随提交演化**（每笔只含已入库项目），不能把最终版带进第一笔。

### 5. 跨平台 CI 排错信号

- **`std::path::absolute` POSIX 保留 `..` 组件、Windows 折叠**（Rust std 文档明载差异）：路径随后做组件级比较时 Linux 上组件错位。本轮实证：loader 根包含检查在 Linux CI 误判"逃出模块根目录"，module 分类 5 case × 四路全挂（115p/5f），Windows 全绿完全无感。修法：absolute 后统一过词法清理（折叠 `..`）；并在 Windows 上构造含 `..` 的入参写合成回归用例，让它能在任何平台跑。**诊断信号：Windows 全绿、Linux 挂、且只挂用到该路径的一段逻辑。**
- **私有仓查 CI**：匿名 GitHub API 404；用 `git credential fill` 取 token（仅单命令变量内流转，不落盘不回显），API 查 run/jobs/logs；日志拉下来后注意失败可能不是测试而是 fmt/check 类门禁（看 diff 输出特征）。
- **仓库收拢/加目录层的连锁**：根相对路径 `../../` 全部要 +1 层；grep 排查要覆盖两种写法（`"../.."` 字面量与 `join("..", "..")` 拼接式）——本轮只扫了字面量，拼接式的漏网由 CI 抓出。

## 常用命令

均为本对话实际执行且有可见结果的最终有效版本；路径参数化。

```bash
# Python per-user 静默装（免管理员；官方 exe）
python-3.14.7-amd64.exe /quiet InstallAllUsers=0 TargetDir="D:\\DevTools\\Languages\\Backend\\Python" Include_launcher=0 PrependPath=0

# Go/MySQL MSI 静默装（需 UAC）
powershell -Command "Start-Process -Wait -PassThru msiexec.exe -ArgumentList '/i','<msi路径>','INSTALLDIR=<D盘目标>','/passive','/norestart'"

# MongoDB 补装 server+服务（/passive 缺 ADDLOCAL 时只装路由器）
powershell -Command "Start-Process -Wait -PassThru msiexec.exe -ArgumentList '/i','<msi路径>','INSTALLLOCATION=<D盘目标>','ADDLOCAL=\"ServerService\"','/passive','/norestart'"

# rustup 重装到指定家目录（先 export CARGO_HOME/RUSTUP_HOME）
rustup-init.exe -y --default-toolchain stable --profile default --no-modify-path

# Adoptium 钉版本下载 JDK（404 则退 latest/ga）
curl -fsSL -o jdk.zip "https://api.adoptium.net/v3/binary/version/<版本串>/windows/x64/jdk/hotspot/normal/eclipse?project=jdk"

# MySQL 数据目录初始化 + 临时起停验证（⚠️ --initialize-insecure 生成空密码 root，仅本机测试用）
mysqld.exe --initialize-insecure --datadir="<D盘data>" --console
mysqld.exe --datadir="<D盘data>" --port 3306 --console &
mysql.exe -u root --skip-password -e "SELECT VERSION();"
mysqladmin.exe -u root --skip-password shutdown

# PostgreSQL 免安装包起停（binaries zip）
initdb.exe -D <data> -U postgres -E UTF8 -A trust
pg_ctl.exe -D <data> -l <data>/logfile start   # 注意：会驻留，后台任务化执行
pg_isready.exe                                  # "accepting connections" 即就绪
pg_ctl.exe -D <data> stop

# ⚠️ 服务改路径（管理员；先停服再改，改完核对 PathName）
sc.exe config <服务名> binPath= "<新exe路径> --service-run ... <新conf路径>"

# 私有仓查 CI（token 仅变量流转，不落盘不回显；用后置空）
TOKEN=$(printf "protocol=https\nhost=github.com\n" | git credential fill | grep "^password=" | cut -d= -f2)
curl -s -H "Authorization: Bearer $TOKEN" "https://api.github.com/repos/<owner>/<repo>/actions/runs?per_page=1"

# 逐前缀可编译验证（提交拓扑定序用；路径用正斜杠）
git worktree add /e/<tmp> <sha> && cd /e/<tmp>/<项目> && cargo check --workspace -q
git worktree remove /e/<tmp> --force
```
