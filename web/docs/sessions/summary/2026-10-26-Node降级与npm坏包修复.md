# Node降级与npm坏包修复

**一句话总结**：umi4 项目在 Node 24 下装依赖报 `No such module: http_parser`，降回 Node 18 解决；启动后又报找不到 antd 图标模块，排查发现是本地 `@ant-design/icons` 包残缺，删单个坏包目录重装解决。

## 背景

给 `@umijs/max@4`（antd 4 + webpack 系）前端项目装依赖，`npm install --legacy-peer-deps` 在 postinstall `max setup` 阶段失败；换 Node 18 装好后 `npm run dev`，页面又报 `Cannot find module '@ant-design/icons/es/icons/CheckCircleFilled'`。

## 核心命令

```bash
node -v; fnm list    # 查当前 Node 版本和 fnm 已装版本
```

```bash
# 项目根建 .node-version 文件写入 18.20.8，fnm 的 use-on-cd 钩子会在新终端自动切换
fnm use 18.20.8      # 当前终端手动切换
```

```bash
node -e "console.log(require('./node_modules/@ant-design/icons/package.json').version)"
                     # 不装任何工具，直接查本地包实际安装的版本
```

```bash
npm pack @ant-design/icons@4.7.0 --registry=https://registry.npmmirror.com
tar -tzf ant-design-icons-4.7.0.tgz | grep -c 'package/es/'
                     # 下载公共镜像 tarball 并统计 es/ 目录文件数，对照本地安装是否残缺
```

```bash
curl -sL -H "Authorization: Bearer <token>" -o pkg.tgz "<私服tarball直链>"
tar -tzf pkg.tgz | grep -c 'package/es/'
                     # 带 .npmrc 里的 _authToken 下载私服 tarball 检查；
                     # npm pack --registry=<私服> 不会附加该认证，会报 E401
```

```bash
⚠️ rm -rf node_modules/@ant-design/icons
                     # 只删确认损坏的单个包目录（不可恢复，删前核对包名，勿删整个 node_modules）
npm install --legacy-peer-deps
                     # npm 检测到包目录缺失会重新解压这一个包
ls node_modules/@ant-design/icons/es/icons/CheckCircleFilled.js
                     # 装完验证关键文件存在，再重启 dev server
```

## 关键结论

1. **Node 21+ 移除了内部模块 `http_parser`**：老 webpack 生态（umi4 → spdy → http-deceiver）在模块顶层调用 `process.binding('http_parser')` 直接崩。Node 22/24/26 全都会挂，这类项目用 Node 18/20。看到堆栈里出现 `process.binding` + `No such module: xxx`，第一反应查 Node 版本兼容性。
2. **npm 对已存在的包目录不做逐文件完整性校验**：某次解压被文件占用（EPERM）打断后，残缺目录会一直留在 node_modules 里，之后重装多少次都被当"已安装"跳过。修法是精确定位后删掉那一个坏包目录再 `npm install`，而不是反复全量重装。
3. **判定"私服坏了还是本地装坏了"的方法**：分别下载私服和公共镜像的 tarball，`tar -tzf` 列出内容对比本地目录。本次两边 tarball 都完好（es/ 806 个文件）→ 问题锁定在本地解压环节。
4. **噪音甄别**：npm 的 `deprecated` 警告、安装末尾的 `EPERM cleanup` 都不是失败原因，不用管；判断"包残缺"前先对照官方 tarball 的真实结构——如 `@ant-design/colors@6.0.0` 官方就只发布 `dist/`，本地没有 `es/` 是正常的。
5. 删除 node_modules 时若报 EPERM，先关 VSCode/杀软等占用文件的程序再删；若坏包重装后复发，把项目目录加杀软白名单。
