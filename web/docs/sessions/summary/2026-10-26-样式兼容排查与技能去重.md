# 样式兼容排查与技能去重

**一句话总结**：先用布局测量和 Git 差异确认问题，再做最小改动；类名改写要保留展示条件，Skill 去重要先补遗漏、再清旧版。

## 背景

接诊准备详情页的顾客卡只在一台旧安卓平板上出现高度塌陷，随后又需要把手工类名拼接统一为 classnames，且保持页面行为不变。整理经验时，还发现个人 Skill 的新旧版本并存，需要确认回流来源、补齐有价值的遗漏并清理重复目录。

## 核心命令

以下命令均来自对话中成功执行的检查；路径和提交号已改成占位符。代码块使用 Bash 语法，执行前替换占位符；项目检查在仓库根目录运行。

```bash
git status --short # 查看已修改、已删除和未跟踪文件，先区分本轮与已有改动
git diff -- "<目标路径>" # 逐条核对工作区差异，防止局部修复混入其他改动
git diff --cached --name-status -- "<目标路径>" # 检查暂存范围，确认本机测试和调试文件未被带入
git diff --check -- "<目标路径>" # 检查差异中的行尾空白等问题，不代表业务或视觉验收通过

git -c core.quotepath=false log --all --format='%h %ad %s' --date=iso -- "<目标目录>" # 按目录追踪历史，直接显示中文路径
git -c core.quotepath=false show --format=fuller --name-status "<提交号>" -- "<目标目录>" # 核对某次提交新增、删除或重命名了哪些文件
git -c core.quotepath=false ls-tree --name-only "<提交号>^" "<目标目录>/" # 查看父提交中的目录树，确认旧文件是否在此次重新加入

node node_modules/prettier/bin-prettier.js --check "<改动文件>" # 使用项目已有 Prettier 检查格式；多个文件继续列出
DISABLE_V8_COMPILE_CACHE=1 node node_modules/eslint/bin/eslint.js "<改动文件>" # 本项目在较新 Node 下禁用旧编译缓存，实际绕过 ESLint 启动故障
node "<模块目录>/tests/<测试文件>.test.cjs" # 直接运行已有模块测试，不为小修复新增测试框架

node scripts/check-skills.mjs # 在个人 Skill 库根目录检查入口命名、引用、隐藏入口和旧目录回流；依赖该库已有脚本
```

`--` 用于分隔 Git 参数与路径；`<提交号>^` 表示该提交的第一个父提交。上述检查命令不执行删除、暂存、提交或推送。

## 关键结论

1. **卡片塌陷要沿 flex 高度链排查。** 固定高度的纵向 flex 滚动容器中，内容卡可能参与收缩，盒子变矮后内容溢出，被下一张卡覆盖。本次最终对顾客卡局部设置 `flex-shrink: 0`，保留外层 `overflow-y: auto`，没有写死卡片高度，也没有按设备分支处理；九个隔离布局场景通过。不要未经核对就给所有子项统一禁止收缩，可压缩空白仍应保留收缩策略。

2. **系统版本不是浏览器内核证据。** 先测卡片与兄弟元素边界，检查父链的高度、`flex-shrink`、`min-height`、`overflow`；用 `scrollHeight`、`clientHeight` 和实际 `scrollTop` 判断滚动。MIUI 或 Android 版本不能单独确定 WebView 版本，桌面压力复现和内置浏览器抽查也不等于旧平板真机验收；本次旧平板修复后的真机视觉仍待复测。

3. **统一 classnames 应是等价改写。** 项目已有依赖时，沿用现有导入别名，把多类名组合改成 `classNames(...)`；保留原条件、类名 token 及其顺序，单个类名不必包装。只收敛多余空白，不顺带改 CSS、DOM、事件、状态或接口。本次类名结果对照和业务语法结构检查通过，但这不等于做过前后像素差分。

4. **旧 Skill 回流要靠提交差异确认，不能只看文件时间。** 本次 Git 记录证实，一次恢复提交重新加入了旧目录，父提交里没有这些目录。逐项对照后，把缺失的个人成长规划和审查提示补到新版，再删除 12 个冗余旧目录，保留 14 个新版；过时的测试入库、固定目录等规则没有搬回。删除前保留备份与哈希，并在另一副本验证回滚，避免覆盖新版和用户已有修改。

5. **检查器也要测“应该报错”的情况。** 原脚本只枚举 `gua-*`，部分旧命名目录回流时会漏报。修正后检查全部顶层目录，仅排除明确的资源目录；旧目录、隐藏入口、断链等六个回归场景通过。恢复或合并后再跑检查，同时核对清单与链接；物理目录重复，不等于宿主已同时加载两版技能。
