# 2026-10-27-git改动溯源与文档迁移

**一句话总结**：spec7 接口迁移落地后的收尾实战——用 `git log -S` 查"这段代码谁改的"、用 `git checkout HEAD --` 撤掉已暂存的改动、把模块文档迁到 guahub 并保证链接不断。

## 背景

spec7 接口大迁移提交前后，需要弄清两处可疑改动（首页顶部品牌行、statusBar.ts 里的 console.log）是同事提交的还是本地工作区产物，把误入暂存区的改动撤干净，再把 home/h5、dealReview 的模块文档和调试物料迁出到个人知识库 guahub。

## 核心命令

```bash
eval "$(fnm env)" 2>/dev/null; git -C <仓库路径> status --porcelain
# fnm 钩子会让 Git Bash 里所有命令报 "can't find the necessary environment
# variables" 并 exit 1；先 eval fnm env，或全程用 git -C <路径> 免 cd

git log -S "brandText" --format="%h %ad %an %s" -- <文件路径>
# 追踪某字符串何时被引入/删除，精确到提交人和时间；
# 结果为空 = 这个字符串从未提交过，是本地工作区产物

git log --follow --format="%h %ad %an %s" -- <文件路径>
# 文件完整提交历史，最早一条即创建人

git diff HEAD -- <路径> > backup.patch   # 先备份
git checkout HEAD -- <文件或目录>
# ⚠️ 同时还原暂存区+工作区到 HEAD，会丢弃该路径全部未提交改动（含已暂存的）。
# 已 git add 的内容用普通 git checkout -- 撤不掉（它只是从暂存区恢复工作区）

git -c core.quotepath=off status --porcelain
# 中文文件名不显示成 \xxx 转义

git ls-files -v <文件>
# 首列 S = 该文件带 skip-worktree 锁（本地专属文件）

sed 's/$/\r/' 源.ts > 目标.ts
# LF 转 CRLF：仓库 core.autocrlf=true 时直接复制会整文件行尾不一致、prettier 全红

cp -a 源目录/. 目标目录/ && diff -r 源目录 目标目录
# 复制目录并逐字节校验，无输出 = 完全一致

git rm -r -- <目录>
# 删除已跟踪目录并自动进入暂存区，随下一次提交生效

awk 'NR==FNR{want["p10/"$0]=1;next} /^diff -ruN/{keep=($4 in want)} keep' 清单.txt 全量.patch > manual.patch
# 从整库大补丁里抽出指定文件的段落，再在对应目录 patch -p1 应用

find <目录> -type f -printf "%s\n" | awk '{s+=$1} END{print s}'
# 统计目录总字节数；目录迁移前后各跑一次（配合文件数）验证 mv 无丢失
```

## 关键结论

1. **查"谁改的"用 `git log -S`**：空结果证明字符串从未进过任何提交（本地/AI 会话产物），命中则拿到人、时间、提交信息。本次凭空结果证明首页品牌行是本地未提交产物，凭命中证明 console.log 是同事 6-23 提交的。
2. **"无意提交"的根源在暂存区**：提交的永远是暂存区版本而不是工作区。文件已被 add 后再在工作区修改，不改回来并重新 add，提交进去的还是旧内容；撤销已暂存改动要用 `git checkout HEAD --`。
3. **应用"整文件重写型"补丁**（diff 段全是 -/+ 无上下文行）：直接提取 + 侧内容即可；带上下文行的小改动段单独切出来用 patch -p1。跨环境复制代码文件先统一行尾，否则 diff/prettier 整文件飘红。
4. **文档迁出仓库五步**：cp -a + diff -r 逐字节校验 → 脚本把相对链接改成跨库路径并做存在性检查（本次脚本存在 guahub `00-开发记录/2026-10-26/校验中间产物/fix-doc-links.cjs`，可复用）→ 仓库内 git rm → 修正 README 内引用 → 提交。git rm 本身就是暂存删除。
5. **踩过的坑**：批准过的计划 ≠ 可以顺手改其他模块；还原命令被环境（fnm 钩子）挡住而失败时，误改仍留在工作区，必须用 `git status -- <路径>` 复核，不能想当然认为已还原。
6. **待验证**：zustand@5 peer 依赖 react18 而项目锁 react17，社区惯例 `npm install --legacy-peer-deps`（本次因 fnm 环境问题未跑成）；H5 大屏（安卓平板）内容偏小疑与 Taro `config/index.js` 的 `h5.postcss.pxtransform.maxRootSize`（当前 26）钳制有关，调整效果未验证。

## 下次怎么用

- 怀疑某段代码被人改过、或想确认"这是我写的还是别人提交的"：先 `git log -S "<特征字符串>" -- <文件>`，再 `git show HEAD:<路径>` 与工作区对比。
- 提交前发现暂存区混入不该提交的内容：先备份 patch，再 `git checkout HEAD -- <路径>`，最后 `git status --porcelain` 逐条核对。
- 把仓库内文档归档到知识库：按"复制校验 → 链接修复 → git rm → 修引用"四步走，链接检查脚本可直接复用。
