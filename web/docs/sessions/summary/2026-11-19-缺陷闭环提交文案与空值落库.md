### 2. api 模块 · 反模式追加两条

- **位置**：`gua-dev-tools/modules/api/MODULE.md` §反模式。
- **现有缺口**：已有「空值先判业务语义」「测试样本要含 null/缺失字段」，但没有**前端请求层主动过滤空值导致无法清空**这一具体形态；也没有「兜底展示文案撞字典 label」的查重规则。

  > - 非必填字段清空无效时，先看请求层有没有空值过滤（`filterEmptyParams`/`keepEmptyKeys` 之类）：被过滤掉的 `null`/`""` 不会到达后端，后端保持旧值，页面回读仍是旧值。判定链：抓请求体是否带该字段 → 后端是否对该列显式写 null → 落库策略（如 MyBatis-Plus 默认跳过 null）是否直接忽略。三段任一段断掉，「保存成功」都只是请求被受理。
  > - 新增展示兜底文案（「未分类」「其他」「暂无」类）前，对目标字典全量 label 查重：撞名时颜色和 key 会同时失效——图例/列表 `key` 必须用 `typeCode` 这类稳定业务键，不能用展示名（同名两行会撞 React 重复 key）。

- **来源证据**：①`filterEmptyParams` 丢弃 null → `updateActivity` 的 `keepEmptyKeys` 缺 `applyStartHour/applyEndHour` → 后端 Integer 列 null 不写入，两段均已对上；②68098 抓包 `typeBars` 中 `{"typeCode":null,"typeName":null}`，前端兜底「未分类」改「其他」后与字典 code 11「其他」同名，`key={item.name}` 需改 `item.typeCode ?? item.name`。
- **适用边界**：前端；后端纯接口问题归 api 的契约核对，不适用本条。
- **检验场景**：清空非必填字段保存后，用 `typeName || "其他"` 这类兜底生成图例时，若同屏出现两行相同 label，React 控制台应无 duplicate key 告警；清空场景应能在请求体里看到该字段（空串或 null）。
- **执行状态**：**已执行（2026-11-19）**——两条追加进 `modules/api/MODULE.md` §反模式（原「字段统一改名」条之后）；`node scripts/check-skills.mjs` 复跑通过（18 模块 / 52 markdown / 103 本地链接，issues 仅 6 条 `.env` 私有配置告警，均为预存、与本轮无关）。

## 可复用经验与案例

**清空非必填字段后回显旧值**（历史缺陷，活动 1604）

| 环节 | 事实 | 证据 |
| --- | --- | --- |
| 前端 | 表单空值是 `null`，被 `filterEmptyParams` 丢掉，更新请求不含这两个字段 | 抓包 body 无 `applyEndHour/applyStartHour` |
| 前端修复 | `updateActivity.keepEmptyKeys` 追加两个字段，空值以 `""` 传出 | 本会话改动（`activeMain/request.js` 一行） |
| 后端 | `applyStartHour/applyEndHour` 是 Integer，未开 `FieldStrategy.IGNORED`；MyBatis-Plus 默认跳过 null | 实体与 `ActivityServiceImpl.updateById` 静态可见 |
| 未闭环 | 改发 JSON `null` 同样不落库；需后端在 `updateById` 内对两列显式 set null | itest 回读仍 15/25 |

**取舍**：不能给实体加 `IGNORED` 解这个 bug——取消/删除走另一份只带 id 的 `updateById`，会顺手把报名时间清空。必须收窄到更新实现里显式赋值。
