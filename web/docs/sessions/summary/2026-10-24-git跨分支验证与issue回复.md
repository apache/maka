# git 跨分支验证与 issue 回复

**一句话总结**：参与开源 issue 时，用 `merge-base --is-ancestor` 判断修复进没进某个版本、用独立 worktree 在不切分支的前提下实测别人的代码，核实完事实再按「先做+自测 → 推分支 → 回帖」的顺序回复，只写本轮实测过的话。

## 背景

我此前面交付给 yetone/magpie 的两个 patch 被维护者收编合入（`Co-authored-patch` 收进 `240f3eb4c`），issue 下多了两条新评论：一位 Windows 用户问纯 TUN 场景是否覆盖、并问我为什么不开 PR；维护者留言等真机确认。需要先核实「合入是否保留署名、修复进了哪个版本、新实现是否真的通过测试」，再回复两位作者。

## 核心命令

```bash
# 判断某 commit 是否已包含在某个发布 tag 里（查"修复进没进这个版本"，比按发布时间猜可靠）
git merge-base --is-ancestor 240f3eb4c v0.1.1321 && echo contained || echo NOT-contained

# 不切分支，把任意 commit 检出到独立目录跑测试（当前工作树完全不受影响）
git worktree add --detach /tmp/verify-2593 <commit-sha>
cd /tmp/verify-2593 && go test -tags nogui -run 'TestFakeIP' -v ./internal/gateway/
git worktree remove --force /tmp/verify-2593   # ⚠️ --force 会丢弃该目录未提交改动；确认干净后可去掉 --force

# 不切分支读另一个 ref 上的文件 / 文件清单
git show <ref>:internal/netguard/netguard.go
git ls-tree <ref> --name-only internal/

# 查 commit 尾注，确认 Co-authored-by 署名是否保留
git log -1 <commit> --format='%(trailers)'

# gh 读 issue 全部评论（--jq 控制只看作者和正文前 500 字）
gh issue view 2593 -R <owner>/<repo> --json state,comments --jq '.comments[] | {author: .author.login, body: .body[0:500]}'

# gh 发评论：正文用文件，避免 shell 转义；输出即评论 URL
gh issue comment 2593 -R <owner>/<repo> --body-file draft.md

# 发完 GET 回读校验内容真的落帖了（注意：REST 接口只认数字 ID）
gh api repos/<owner>/<repo>/issues/comments/<数字ID> --jq '.body'

# 看最新 release 有没有包含修复
gh release list -R <owner>/<repo> --limit 5
```

## 关键结论

1. **issue 显示 Open ≠ 没修**。以 GitHub 实查为准：维护者可能已收编你的 patch，署名是否保留看 commit 尾注里的 `Co-authored-by`（`git log --format='%(trailers)'` 一条命令核实）。
2. **判断修复进没进某版本，用祖先判定，别按时间猜**。本例发布 tag 只比修复 commit 早 17 分钟，按发布日期判断必然出错；`merge-base --is-ancestor` 一锤定音。
3. **Clash/Surge TUN 的 fake-ip 模式会把所有域名解析成 `198.18.0.0/15` 假地址**，任何「拒绝私有地址」类的安全检查都会把它当内网地址全部拒绝，表现是开了 TUN 工具就报 private address、关掉就恢复。根治思路是识别「每个解析结果都在假 IP 段的域名」：有本地代理就按域名交给代理，纯 TUN（没设代理）就直拨假地址让 TUN 转发。真实 TUN 环境我未亲自验证（待验证：基于两位报告者实测+维护者实现）。
4. **对外回复的顺序**：已有沟通在先的帖子，先做+本地自测 → 推分支 → 再回帖，回复里只写本轮实测过的事实；首次接的单先发一条 take 评论占坑，防止和别人撞车。
5. **验证别人的代码不要动自己的工作树**：`git worktree add --detach` 开独立目录，用完即清；顺带发现 REST 接口不认 `IC_` 开头的 GraphQL node ID，数字 ID 在评论 URL 末尾。

## 下次怎么用

- 等某个修复发版、或怀疑升级没生效时：先 `gh release list` 看版本，再 `merge-base --is-ancestor` 确认该 commit 在不在 tag 里。
- 要 review 或跑测别人的分支 / 上游最新代码：worktree 独立目录，不碰当前分支，不 stash。
- 维护开源项目的 issue 区：`gh issue view --json` 读评论 → 本地跑通验证 → `--body-file` 发评论 → `gh api` 回读确认；引用任何测试结果前先本地跑一遍。
- 自己或同事用 Clash Verge/TUN 时遇到工具报「private address」，先怀疑 fake-ip 段，而不是真的内网问题。
