## Skill 增量建议（gua-pr-patch，均为建议未执行）

### 建议 1：行内 review 回复用 replies 端点

- **位置**：`references/workflow.md` §4「review 与新评论」节追加一行（或 pitfalls.md 常见流程坑）。
- **现有缺口**：workflow.md §4 讲了三端点扫描、bot 处置、rework 规范，但没有"回复行内意见走哪个 API"——`POST /pulls/{id}/events` 不落库的坑只在项目记忆（maka-dev-memory）里，跨仓不成立地丢失。
- **建议文本**：回复 PR 行内意见用 `gh api --method POST repos/<o>/<r>/pulls/<N>/comments/<comment-id>/replies --input body.json`（body 为 JSON `{"body":"..."}` 文件）；`POST /pulls/{id}/events` 类端点不落库。成功信号=响应含 `html_url`（`...#discussion_r<N>`）。
- **来源证据**：09-29 #5265 首次实证（maka 台账在册）；本对话 #5889（discussion_r4150232949）、#5890 两处（discussion_r4150346415、discussion_r4151031699、discussion_r4154554687）均经 replies 端点落库并回读到 html_url。
- **适用边界**：GitHub PR 行内评论回复；issue 评论不用此端点（`gh issue comment`）。
- **检验场景**：回复后 `GET repos/<o>/<r>/pulls/comments/<reply-id>`，断言 `in_reply_to` 等于原意见 id。

### 建议 2：fork PR 无 rerun 权限 + 本地裁决性文本优先

- **位置**：`references/workflow.md` §3「CI 红的定性」段（"分支基点落后先 rebase，仍红且无写权限才附证据请维护者 rerun"之后）。
- **现有缺口**：该段已有"不推空提交碰运气"，但没写 fork PR 作者**根本没有 rerun 权限**（API 报 `Must have admin rights`，实测），也没写 rerun 之外的替代取证手段——疑似 flake 的 CI 红，裁决性文本可能只在本地能拿到。
- **建议文本**：fork PR 的 CI run 无 rerun 权限（rerun 需 repo admin）；空提交重触发每轮 ~30 分钟排队+执行且拿不到新信息。对"疑似 flake 还是真回归"的 CI 红，先在本地做最便宜的取证：CI 日志只有断言 diff 没有 `failureReason` 时，把对应 dist 编译产物测试临时 patch 一行打印（如 `console.log(JSON.stringify(outcome.result))`）+ `--test-name-pattern "<名>"` 单跑——拿到文本再决定定性或重触发；事后必须还原产物，patch 不进提交。
- **来源证据**：#5890 三轮 CI 定性两次反转——"同内容上轮 CI 绿"不成立（planner 根本没选该测试面，M1），空提交重触发白付一轮；最终一行诊断打印拿到 `missing_attempt_usage` 终结争论（台账 reviews.md「10-01 深夜场」节）。本次 CI 失败日志确实不含 failureReason（node:test 只打印断言 diff）。
- **适用边界**：测试经 dist 等编译产物执行的仓（TS monorepo 常见）；源文件直接跑的仓可直接 patch 源文件。`--test-force-exit` 规避悬挂句柄是本机 Node 26 特性。
- **检验场景**：同一次 CI 红，本地 patch 单跑能产出 CI 日志中没有的失败原因文本。
- **未执行**：本建议未回写 Skill，也未在第二仓复验泛化性。

## 常用命令（本对话实际执行且有效）

**1. 行内回复 reviewer（replies 端点）**

- 场景：对 PR 行内 review 意见做逐条回复且要求落库可引用。
- 命令：
  ```bash
  CID=$(gh api "repos/<o>/<r>/pulls/<N>/comments" --jq 'sort_by(.created_at) | .[-1] | .id')
  gh api --method POST "repos/<o>/<r>/pulls/<N>/comments/$CID/replies" --input body.json --jq '.html_url'
  ```
- 前提：body.json 为 `{"body":"..."}`；取 CID 的 jq 若评论含 null 字段需先过滤。
- 成功信号：返回 `.../pulls/<N>#discussion_r<N>`；副作用：在原线程追加一条回复（不可静默删除，勘误走追加）。

**2. dist 测试产物加临时诊断打印单跑（拿 CI 日志没有的失败文本）**

- 场景：CI 失败日志只有断言 diff，需要 failureReason/中间状态定性"真回归 vs 预存"。
- 命令（⚠️ 编译产物改动不可提交，跑完必须还原）：
  ```bash
  node -e "const fs=require('fs');const p=process.argv[1];let s=fs.readFileSync(p,'utf8');
  const t='<目标断言行原文字节>';
  s=s.replace(t,'console.log(\"[DEBUG]\", JSON.stringify(<对象>));\n'+t);
  fs.writeFileSync(p,s);" <dist测试文件.js>
  node --test --test-force-exit --test-name-pattern "<测试名子串>" <dist测试文件.js>
  ```
- 前提：测试经 dist 产物执行（先 `npm run build` 该包）；`--test-force-exit` 规避 Node 26 悬挂句柄。
- 成功信号：输出里出现 `[DEBUG] {...}`，含 CI 日志没有的字段（本例：`failureReason:"Runtime Host usage did not settle: missing_attempt_usage"`）。
- 副作用：dist 产物被改——还原方式为重跑该包 build，或用 git 确认 dist 未入库（gitignored 时天然安全）。

**3. epoch 守卫双形态（maka 特有，命令已在 maka-dev-memory，此处只留索引）**

- CI 同款（读分支 diff，提交后跑）：`node scripts/protocol-epoch-check.mjs --base <当前 main tip>`；暂存声明：加 `--staged`。豁免 JSON 是纯 JSON，**不能带 ASF 注释头**（JSON.parse 静默失败）。

## 待验证与不适用边界

- **两机 fork docs 对齐**：darwin（handbook 结构）与 Windows（01-04 结构）是否应统一、统一到哪边——待用户决策；在决策前，gua-pr-patch 入口按仓分路径指引是权宜态。
- **"字符串哨兵一律换持久列"不成立**：ownership 列方案在本例胜出是因为 protocol README 禁移 accepted value；若仓无此约束，保留字收紧可能是更小 diff——按仓的约束面选，不背方案。
- **M1-M13 正本归属**：skill pitfalls.md 标注正本为 `docs/handbook/05-失败模式对照.md`（darwin 路径系），Windows 实测是 `docs/03-失败模式对照.md`——与路由差异报告同源，一并待决策。
- **shell 环境两次故障**（0xC0000135 / bash.exe ENOENT）：宿主瞬态，重试恢复，无经验沉淀价值；仅影响节奏，不影响结论。
