# 接诊准备：双入口身份以路由优先

## 一句话结论

面诊成交助手首页同时服务 AI 美管家选客和宏脉 SDK 直达。`customerId` 必须来自路由；`employeeId` 路由里有非空值就用路由，空串或缺失才回落登录态。解析只放在 `resolvePrepIdentity`，卡片请求、档案请求和编辑回填都读它。宏脉真机未验证。

## Skill 增量建议

### 接诊准备身份：路由非空优先，空则回落登录态

- 位置：`gua-dev-tools` `modules/taro/references/project-facts.md`，现行 homing「路由与多端」下追加，不进通用 Taro 正文。
- 现有规则：不同宿主不能互相推断，路由差异要记台账。没有写明同一页的两个入口如何合并 `customerId` / `employeeId`。`arch` 的「单一可信来源」只说明原则，不规定空串算缺失。
- 建议追加：`/subPackage/receptionPrep/index` 有两个入口。AI 美管家选客只带 `customerId`，`employeeId` 取登录态 `employeeInfo.employeeId`。宏脉 SDK 可同时带 `customerId` 与 `employeeId`。只在 `resolvePrepIdentity` 解析：没有 `customerId` 不能进页；`employeeId` 路由非空优先，空串与缺失回落登录态。卡片、档案和编辑回填读这份结果。`fetchReceptionPrep` 仅在 context 未带 `employeeId` 时再读 store。
- 证据：用户要求「路由能收到就优先用，否则走原来的逻辑」。选客页只传 `customerId` 与 `entrySource`。改前 `service.ts` 与编辑弹窗只读 store。`identity.test.cjs` 四例在 Node v24.19.0 下输出 `identity.test PASS 4`，退出码 0。
- 边界：只适用于接诊准备这组身份。不能推广成所有页面都让路由覆盖登录态。
- 检验：路由 `{customerId:'c1'}` 加登录 `loginE` 得 `loginE`；路由同时有 `c1`/`e1` 得 `e1`；只有 `employeeId` 得 `null`；`employeeId:''` 回落 `loginE`。断言已跑过。宏脉容器是否真把这两个 query 传进来，未执行。

## 可复用经验与案例

### 两个入口共用一页

- 触发：同事问宏脉现场设计跳接诊准备要带什么参数。AI 美管家路径已经只带 `customerId`。
- 证据：选客页跳转只有 `customerId`、`entrySource`。接口 `cards` 与 `customer/profile` 都要 `customerId` + `employeeId`。改前员工号只从 `useGlobalDataStore.employeeInfo.employeeId` 取。
- 决策：对外约定两个 query：`customerId`、`employeeId`。对内不拆第二套页面。示例路径 `/subPackage/receptionPrep/index?customerId=<id>&employeeId=<id>`。
- 取舍：空串 `employeeId` 视为没传，避免宏脉传空串把登录态顾问盖掉。没有 `customerId` 直接无法进页，不拿登录态补顾客。
- 副作用：卡片页「查看详情」会把 context 展开进详情路由。context 现在带 `employeeId`，详情 URL 会多这个参数。这是静态可见行为，浏览器未点。
- 验证：仅隔离样例四例通过。未做 H5、小程序或宏脉容器联调。prettier 因沙箱拒绝写盘未跑成。
