# 机构养老交付门禁与假红分诊

## 一句话结论

数据归集-机构养老静态页交付中，三条新经验值得沉淀：存量 scss lint 违规用文件头定向豁免块收口（不全修、不改共享配置）；并行对话同工作区开工前先盘点 diff 只补缺口；联调接力提示词必须携带假设清单与本机验证命令原样。

## Skill 增量建议（均未执行，待确认）

### 1. 存量 lint 违规豁免块 → gua-dev-tools `modules/quality/references/format.md`

- **现有规则或缺口**：format.md 只覆盖 prettier 格式化与属性顺序；style.md 无豁免机制。存量违规挡 pre-commit（stylelint --fix 修不了 selector-class-pattern/`:global` 这类规则）时无规则可用。
- **建议追加文本**（放「SCSS 决策」节后）：
  > 存量文件带历史 lint 违规挡住提交门禁时：在文件头加定向 `/* stylelint-disable <具体规则>, ... */` 豁免块，注释写明原因（如「:global 覆盖第三方组件类名」）与新人指引（新文件遵循规范）；禁止全量修类名（牵连 tsx 引用，纯 churn）、禁止改共享 lint 配置。本次新增行必须自身全绿。
- **来源证据**：本会话 GetInstitutionalEldercare 两个存量 scss 带 HEAD 既有 ~90 处违规，豁免块（+3 行注释+1 行 rgba 现代写法）后 stylelint 0 错，diff 仅 +9/-4；全修需改 ~16 类名同步 index.tsx 十几处引用。
- **适用边界**：任何 lint 门禁仓；豁免必须「定向规则+原因注释」，不许裸 `stylelint-disable-all`。
- **检验场景**：存量 scss 含 camelCase 类名且本次只改 2 行，提交被 stylelint 拦——正确动作是文件头豁免块，错误动作是全量重命名或 --no-verify。

### 2. 并行对话开工盘点 → gua-dev-tools `modules/quality/MODULE.md` L49 规则扩展

- **现有规则或缺口**：已有「跨会话执行**待办**前先核实源码，可能已被并行会话修掉」——触发面只限待办项，未覆盖「用户直接要求实现某需求」的场景。
- **建议替换文本**（扩展同条规则触发面）：
  > ……前，先 grep 当前源码/暂存区核实；用户要求实现某需求时同理，先 `git status` + `git diff HEAD --stat` 盘点未提交改动——并行对话可能已实现同一需求，只补缺口不重做；编辑前重新 Read（另一会话可能已改同文件，Edit 会报 modified since read）。
- **来源证据**：本会话按自己清单准备修 UI，盘点 diff 后发现 6 行需求已被另一对话的模型实现（+384 行）；保留其重构只补一处 `color="processing"`。同日两次 Edit 因文件被外部修改被拒。
- **适用边界**：多会话共用一个工作区的工作流；单会话项目不适用。
- **检验场景**：用户说「接下来开发机构养老」，工作区有大量未提交改动——正确动作是先 diff 盘点对照需求找缺口，错误动作是按自己的实现清单重写。

### 3. 接力提示词带假设清单 → gua-writer `SKILL.md` L21 句尾扩展

- **现有规则或缺口**：已有「给下一轮对话的提示词：用户下一句要接着用的清单（仓库、当前检出、已做/未做）必须带上」。缺两条：「页面先行」模式下未确认的字段假设清单（新会话易把假设当 bug 顺手修）、本机验证命令原样（含环境坑绕法）。
- **建议追加**：
  > ……必须带上，不能只留结论。页面先行/字段待确认的联调接力，假设清单单独成节并标注「联调时先出假设 vs 实际差异表、经确认再改码」；本机验证命令连环境坑绕法（如 node 全路径）原样粘贴，不留「按项目惯例执行」这类引子。
- **来源证据**：本会话产出的机构养老联调提示词含 6 条字段假设 + node 全路径验证命令；其中「删除当月数据区间禁用」若不带，新会话会当缺陷修掉。
- **适用边界**：跨对话/跨人交接提示词；普通终稿文档不适用。
- **检验场景**：新会话拿到接力提示词后第一件事是重写静态页——说明假设清单缺失或未标注「已就位勿重做」。

## 可复用经验与案例

- **存量豁免块完整模式**：文件头 2-3 行注释 = disable 规则清单 + 原因（第三方类名覆盖）+ 新文件指引；顺带把本次触达行里可机器验证的旧写法（rgba→`rgb(a b c / d%)`）修掉。效果：门禁全绿、diff 最小、维护者一眼可见豁免范围。
- **原型证据链核验**：u 编号控件在 data.js 里是位图引用，页面文案全在 u*.png——核对交互语义（删除按钮禁用态、审批标记）必须看图，文本提取脚本走不通；服务器版本对比用 `data/document.js` 字节数 + 单页 `data.js` 的 Last-Modified，一致即免重下。本会话据此定案卡片用词（u102+u106 vs 旧版 u119）并证实两个真歧义（u116 区间+删除可点、u95 ¥800 无审批）。
- **IDE 假红分诊**（已覆盖，复述要点）：连 `antd/es/table` 都划红 = tsserver 缓存坏（文件被外部工具反复改），Restart TS Server 即愈；CLI 实证 = `tsc --noEmit` 后 `grep TS2307 | grep -v node_modules`，空输出即 0 模块错误。

## 常用命令

```bash
# 本机 fnm shim 劫持 node/npx（报 "can't find environment variables"），用 D 盘真身全路径直调 bin
NODE="/d/DevTools/Languages/Frontend/Fnm/node-versions/v22.23.3/installation/node.exe"
"$NODE" node_modules/eslint/bin/eslint.js "<files>"          # 成功=无输出(仅 react 版本 warning)
"$NODE" node_modules/stylelint/bin/stylelint.mjs "<scss>"    # 成功=无输出
"$NODE" node_modules/prettier/bin-prettier.js --end-of-line auto --check "<files>"
#   ^ --end-of-line auto 必带：否则 CRLF 文件整文件判脏（假阳性）
"$NODE" node_modules/typescript/bin/tsc --noEmit 2>&1 | grep "TS2307" | grep -v node_modules
#   空输出=src 模块解析 0 错；node_modules 内 ~70 个存量错（@types/node ffi.d.ts + pro-form）忽略

# Axure 原型是否被产品更新（免全量重下）
curl -s -I "https://<测试域名>/product_prototype/<路径>/files/<页面名>/data.js" | grep -i "last-modified\|content-length"
wc -c "<本地原型>/files/<页面名>/data.js"   # 长度一致且 Last-Modified 早于本地抓取时间=无需重下
```

## 待验证与不适用边界

- 豁免块模式在本仓只验证过 stylelint 两条规则族（selector-class-pattern/`:global`）；eslint 存量豁免未实测，`no-descending-specificity` 等规则是否同样收口待验证。
- 「并行对话盘点」依据是单日两次实证；若用户改为单会话工作流，规则触发面应收回待办核实场景。
- Axure data.js 文本提取是已证伪路径（只能提取图片路径与字体名），不要再尝试；u 编号直接看图。
