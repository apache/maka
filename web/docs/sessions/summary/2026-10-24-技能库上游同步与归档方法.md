# 技能库上游同步与归档方法

**一句话总结**:用 skills-explorer 管线同步锁内技能、用 gh api 诊断上游删除原因、按 mtime 和 diff 核实后归档与清理,全程"先比对再动手"。

## 背景

个人技能库 `~/.ai/categories`(1697 个技能)要做一次全量上游同步:更新有上游的 75 个锁内技能,查明 6 个"上游已删除"技能的真相并归档,顺带清掉两份历史备份。难点是工作区里混着上一轮未提交的改动,得分清哪些是本轮动的。

## 核心命令

```bash
# ===== 技能同步管线(skills-explorer 目录下) =====
cd /Users/ggbdpq/cc/guahub/code/agents/skills-explorer
node scripts/update-skills.js                            # 五步管线:拉上游→同步真身→rebuild→sync→doctor
node scripts/sk-doctor.js --no-fail 2>/dev/null | grep "^problems"   # 体检计数,和基线对比而非强求 0

# ===== 查上游技能是否还存在(核删除三部曲) =====
gh api "repos/OWNER/REPO/git/trees/HEAD?recursive=1" --jq '.tree[] | select(.path | endswith("SKILL.md")) | .path'
# ↑ 列出上游全部技能路径;jq 里 test("...\\.md") 会报 invalid escape,用 endswith 保险

gh api "repos/OWNER/REPO/commits?path=skills/xxx&per_page=3" --jq '.[] | .sha[0:7] + " " + (.commit.author.date) + " " + (.commit.message | split("\n")[0])'
# ↑ 查某个路径的增删历史,最后一条即删除提交

gh api "repos/OWNER/REPO/pulls/39" --jq '.title + " | " + (.body // "" | .[0:600])'
# ↑ 删除往往是 PR 干的,看正文拿原因

# ===== 分清"本轮改动"和"存量未提交" =====
find /Users/ggbdpq/.ai/categories -newermt "2026-10-24 12:40" -type f   # 只列该时刻后改过的文件

# ===== 归档与提交 =====
git -C /Users/ggbdpq mv "<旧路径>" "<新路径>"    # git mv 进归档目录,历史可追溯(中文路径加引号)
git -C /Users/ggbdpq log --diff-filter=D --name-only --format="COMMIT %h %ad %s" --date=short -- ".ai/categories"  # 历史上删过哪些文件
git -C /Users/ggbdpq commit -F /tmp/msg.txt     # 多行中文提交说明落文件再 -F,不跟 -m 转义较劲

# ===== 目录比对与行删除 =====
diff -rq 目录A 目录B                              # 递归比对:输出 Only in(单侧独有)和 differ(内容不同)
sed -i '' '393d;392d;62d' INDEX.md               # macOS 删多行:行号从大到小删,避免删一行后面全漂移
```

⚠️ `rm -rf /Users/ggbdpq/.ai/.removed-20261020153650 /Users/ggbdpq/.ai/.removed-20261024044236`——删备份目录。风险:递归强删不可恢复;删前必须先 `diff -rq` 确认备份里没有真身缺失的内容。

## 关键结论

1. **同步范围 ≠ 目录大小**:`npx skills update` 只更新锁文件(`.agents/.skill-lock.json`)跟踪的技能(75 条,销案 6 条后剩 69),候选池一千多个快照设计上就不跟上游。"全量同步"对候选池要另走 clone 比对路线。
2. **上游删除 ≠ 弃坑**:查明的 6 个全是重组——1 个合并进别的技能、3 个整体迁入 Next.js 主仓、1 个清理 vendored 副本、1 个插件化重构。诊断链:锁文件 `skillPath` → `trees/HEAD` 核存在 → `commits?path=` 找删除提交 → PR 正文拿原因。
3. **doctor 问题数是基线概念**:本机既有异常约 88 项(嵌套 SKILL.md 等),正确的判断方式是前后对比(89→88 = 无新增),`update-skills.js` 因此以 exit 1 结束属于预期,不是失败。
4. **备份在同步成功那一刻就失去使命**:`.removed-*` 是管线"先复制进真身、再搬走备份"的产物,`diff -rq` 核实无独有文件后即可删。
5. **mtime 窗口是混浊工作区的显影液**:接手一堆未知未提交改动时,`find -newermt` 先圈出本次操作实际碰过的文件,git status 就不会骗人。

## 下次怎么用

- **每月技能同步**:跑 `node scripts/update-skills.js`(已设每月 24 日 10:30 定时任务),看 doctor 计数是否仍 ≈88,日志在 `logs/skills-update.log`。
- **怀疑某技能上游没了**:按"核删除三部曲"顺序跑三条 gh api,十分钟拿到删除时间、commit 和原因。
- **清理任何"看起来没用了"的备份/缓存**:`diff -rq` 确认单侧无独有内容再删,拿不准就不删。
- **整理工作区**:先 `find -newermt` 圈范围,再分批 `git add` 指定路径,提交说明一律 `-F` 文件。
