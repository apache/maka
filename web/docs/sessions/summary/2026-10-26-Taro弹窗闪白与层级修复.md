# Taro H5 弹窗闪白与层级问题修复复盘

**一句话总结**：接诊准备页弹窗前后两次白闪，根因是 sticky 设备条穿透弹窗遮罩（页面缺层叠上下文）和 loading/弹窗同位交叉淡化，分别用 `z-index:0` 和错开 200ms 解决；顺带把 revert+reapply 的丑历史用软重置+强推清理干净。

## 背景

Taro 3.6.34 纯 H5 项目（跑在 AI美管家 App WebView 离线包），接诊准备页点击「重新连接」→ 弹「重连失败」弹窗的前后，设备状态条和屏幕中心各有一次闪白；另有一个已剪辑音频的拦截提示层级问题和免责声明置底需求。闪白查了多轮才闭环。

## 核心命令

```bash
# 看某个历史提交的完整改动（排查历史实现时用）
git show <sha>

# 确认某次提交里的某文件是否包含预期改动（比如确认淡入动效有没有被提交进去）
git show <sha>:src/subPackage/receptionPrep/commonComponents/BottomActions/index.module.scss | grep animation

# 验证两个提交的树内容是否一致（清理历史前必做，输出为空才算零差异）
git diff <shaA> <shaB> --stat

# 本地有未提交改动又要 revert 时，先把单个文件暂存起来，revert 完再恢复
git stash push -m "说明" -- <文件路径>
git revert --no-edit <sha>
git stash pop

# ⚠️ 删掉中间的提交但保留工作区全部改动（软重置只动分支指针，不碰文件）
git reset --soft <要保留的最后一个提交>

# ⚠️ 覆盖远程分支（改写历史后同步远程；lease 指定期望的旧位置，若远程已被别人推新提交会自动拒绝）
git push --force-with-lease=refs/heads/<分支>:<期望的旧sha> origin <分支>

# dev server 探活（重启后轮询等它起来）
curl -s -o /dev/null -w "%{http_code}" --max-time 4 <dev-server地址>

# ESLint 跑不了的兜底：用 TypeScript API 对单个文件做语法校验
node -e "const ts=require('typescript'),fs=require('fs');const f='文件.tsx';const sf=ts.createSourceFile(f,fs.readFileSync(f,'utf8'),ts.ScriptTarget.Latest,true,ts.ScriptKind.TSX);const d=sf.parseDiagnostics||[];if(d.length){console.log(ts.flattenDiagnosticMessageText(d[0].messageText,' '));process.exit(1)};console.log('OK')"
```

浏览器闪白定位方法（比截图可靠）：往页面注入 `MutationObserver`（childList+attributes）记录 DOM 增删时序，配合 `elementFromPoint` 在可疑位置反复采样命中元素——弹窗显示时在状态条位置命中的是状态条而不是遮罩，就直接证明状态条画在了遮罩上面。

## 关键结论

1. **弹窗期状态条白闪的主因是层叠穿透**：`.page` 没有自己的层叠上下文时，`position:sticky` 的白色状态条和导航在 body 弹窗的 opacity 动画期间会被画到遮罩上面——整页压暗时它独亮。修复：`.page { z-index: 0 }` 把整页关进自己的层叠上下文。
2. **屏幕中心的白闪是交叉淡化**：Taro H5 的 `hideLoading`（深色 loading 框，0.1s 淡出）和 `showModal`（白面板，0.2s 淡入）都在屏幕正中，同时触发就混出一块高亮灰白。修复：两者之间强制间隔 ≥200ms。Taro H5 弹窗结构是 `.taro__modal` 追加到 body，内含 mask（z-index 1000、rgba(0,0,0,0.6)）+ 白面板（z-index 4999），开关都是 wrapper opacity 0.2s 过渡。
3. **fixed 定位放进带 transform 的弹窗容器会被 iOS WebKit 裁剪**：弹窗内部的提示气泡要用 `position:absolute` 锚定弹窗壳，不要用 `Taro.showToast`（它 fixed 在视口正中，视觉上脱离弹窗层，App 里感知层级比弹窗低）。
4. **清理 revert+reapply 提交对的套路**：这类提交互相抵消、内容零变化，先 `git diff <保留的最后提交> <当前提交> --stat` 确认为空，再 `reset --soft` 回去、`force-with-lease` 覆盖远程，工作区未提交改动全程无损。注意夹在中间的其他提交（如字重修改）要选对重置目标，别连它们一起删。
5. **坑**：本地 dev server 可能跑着旧 bundle——改完代码在浏览器验证前，先 fetch 页面加载的 js chunk、grep 自己改动的特征串确认编译已生效，否则会得出"修复无效"的假结论；本项目 ESLint 在 Node 26 下跑不起来（旧版 ESLint 8.12 兼容问题），改用上面的 TS API 脚本做语法校验。
