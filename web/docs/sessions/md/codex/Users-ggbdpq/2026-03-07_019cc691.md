**结论摘要**

CLIProxyAPI 可以理解成一个“本地代理网关”：

1. 先启动一个本地服务，默认监听 `8317` 端口。
2. 再把你的上游账号接进来，比如 `Codex(OpenAI OAuth)`、`Claude Code(Anthropic OAuth)`。
3. 最后把本地客户端改成连这个代理，而不是直连官方。

按官方文档，最关键的不是“安装”，而是这 3 件事要串起来：

- `config.yaml` 里先配好服务端口、`auth-dir`、`api-keys`
- 跑一次 OAuth 登录命令，把账号令牌写进 `auth-dir`
- 改本地客户端配置，让它请求 `http://127.0.0.1:8317`

如果你现在只是想“先跑起来并在 Codex 里用”，最短路径就是下面这套。

**可执行步骤**

### 1. 先理解它的工作方式

你可以把它看成：

- 上游账号层：你的 `OpenAI/Codex`、`Claude`、`Gemini` 等账号
- CLIProxyAPI 层：本地代理服务
- 客户端层：`Codex`、`Claude Code`、SDK、其他兼容 OpenAI/Gemini/Claude 的工具

也就是说，你不是直接在 CLI 里登录官方，而是先让 CLIProxyAPI 持有 OAuth 令牌，再让客户端通过本地地址访问它。

### 2. 准备最小配置 `config.yaml`

官方基础配置里有几个你必须知道的字段：

- `port: 8317`
- `auth-dir: "~/.cli-proxy-api"`
- `api-keys:` 这里定义客户端访问代理时要带的 Key
- `host` 如果你只打算本机用，建议用 `127.0.0.1`

一个适合新手的最小示例可以写成：

```yaml
host: "127.0.0.1"
port: 8317

auth-dir: "~/.cli-proxy-api"

api-keys:
  - "sk-dummy"

debug: false
```

这里的 `sk-dummy` 不是上游真实密钥，而是“你的本地客户端访问 CLIProxyAPI 时用的令牌”。  
后面 `Codex` 或 `Claude Code` 配置里要用同一个值。

### 3. 启动服务

官方快速开始里，macOS 是：

```bash
brew install cliproxyapi
brew services start cliproxyapi
```

如果你不是通过 Homebrew service 管理，文档也给了可执行方式：

```bash
./cli-proxy-api --config /path/to/your/config.yaml
```

如果你已经安装好了，但不确定服务是否真在跑，先确认它是否监听本地 `8317`。

### 4. 登录你的 Codex / OpenAI OAuth 账号

如果你要给 `Codex` 用，官方文档的命令是：

```bash
./cli-proxy-api --codex-login
```

补充说明：

- 可以加 `--no-browser`，只打印登录地址，不自动打开浏览器
- 本地 OAuth 回调端口是 `1455`

这一步做完后，依据官方“凭证目录”和“热更新”文档，可以判断令牌会写进 `auth-dir`，也就是默认的 `~/.cli-proxy-api`，而且服务会自动热重载这些认证文件，通常不需要重启。

### 5. 把 Codex 客户端改成走 CLIProxyAPI

官方给的 `Codex` 配置非常直接。

`~/.codex/config.toml`：

```toml
model_provider = "cliproxyapi"
model = "gpt-5-codex"
model_reasoning_effort = "high"

[model_providers.cliproxyapi]
name = "cliproxyapi"
base_url = "http://127.0.0.1:8317/v1"
wire_api = "responses"
```
