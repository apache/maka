### A3
**结论摘要**
- 当前这版最小实现里，“多种配置中心”**不是靠库内的配置项切换**，而是靠 **Spring Bean 注入**。
- 也就是说，这个库现在只认一个统一入口：[`KafkaToolConfigSource.java`](/Users/ggbdpq/github/kafka-tool/src/main/java/io/github/hkh/tool/kafka/configcenter/KafkaToolConfigSource.java#L6)。
- 默认行为是：
  - 如果类路径里有 Apollo，且你**没有**自己提供 `KafkaToolConfigSource`，库会自动用 Apollo，入口在 [`AdjustConcurrencyAutoConfiguration.java`](/Users/ggbdpq/github/kafka-tool/src/main/java/io/github/hkh/tool/kafka/concurrency/AdjustConcurrencyAutoConfiguration.java#L76)。
  - 如果你自己在业务项目里声明了 `KafkaToolConfigSource` Bean，库就会直接用你的，不再用 Apollo，条件在 [`AdjustConcurrencyAutoConfiguration.java`](/Users/ggbdpq/github/kafka-tool/src/main/java/io/github/hkh/tool/kafka/concurrency/AdjustConcurrencyAutoConfiguration.java#L31) 和 [`AdjustConcurrencyAutoConfiguration.java`](/Users/ggbdpq/github/kafka-tool/src/main/java/io/github/hkh/tool/kafka/concurrency/AdjustConcurrencyAutoConfiguration.java#L80)。
- 所以答案很直接：**Apollo 走 Apollo 自己的配置；其他配置中心要在你的业务工程里实现并注册 `KafkaToolConfigSource` Bean。**
- 另外要说明清楚：**当前库只支持一个“生效中的配置源”**。如果你想“同时接 Apollo + Nacos + Consul”，要在业务项目里自己做一个组合实现，例如 `CompositeKafkaToolConfigSource`，库本身不会帮你合并多源。
