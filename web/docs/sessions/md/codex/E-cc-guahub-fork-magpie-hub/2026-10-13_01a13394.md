### A1
核查结论：**截图关于“pi 子 Agent 可换模型”的说法成立；“调用其他 coding agent”不是同一能力。**

1. **同一 runtime、多模型子 Agent：现成支持。**  
   OpenCode 的 primary/subagent 都能独立指定 `provider/model-id`，未配置时子 Agent 继承主模型；自定义 provider 可连接网关的兼容端点。[Agents](https://opencode.ai/docs/agents/)、[Providers](https://opencode.ai/docs/providers/#custom-provider)

2. **pi 支持这条路线，但 subagent 属于扩展。**  
   官方核心 README 明确子 Agent 由扩展/包提供；官方 subagent 示例启动独立 `pi` 进程，并支持每个角色指定模型。[Pi README](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/README.md)、[官方 subagent 示例](https://github.com/earendil-works/pi/tree/main/packages/coding-agent/examples/extensions/subagent)

3. **截图若指 badlogic/pi-subagent：可换 provider/model，执行器仍是 pi。**  
   README 有 `--provider`、`--model`；`shared.ts` 的 `launchRun` 固定启动 `pi`。它不是“选择 Codex CLI / Qwen Code / Claude Code”的通用 runtime 调度器。[pi-subagent README](https://github.com/badlogic/pi-subagent)、[启动代码](https://github.com/badlogic/pi-subagent/blob/main/shared.ts)

4. Pi 当前官方 provider 文档列出 DeepSeek、Qwen；兼容网关可由 `models.json` 接入。具体模型 ID 与工具调用能力需按实际端点核验。[Providers](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/providers.md)、[Models](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/models.md)

**最小路线建议（工程推断）：**先做“一个主控角色 + 两个子角色 + 每角色绑定 provider/model + 同一执行器”，网关继续负责协议、路由、凭证与用量；编排层负责任务拆分、状态、取消和结果汇总。跨 coding-agent runtime 先不纳入 MVP，否则额外承担会话、权限、进程、事件和工作区差异。

### A2
**Pi 当前官方代码支持“同一会话按阶段切换模型”，它与“主控派发独立子 Agent”是两套机制。**

- [Virtual Models 官方文档](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/virtual-models.md)：扩展注册虚拟模型；`route()` 在每次模型请求前选择物理模型和思考级别；阶段状态存于会话分支。每条 assistant message 记录实际物理模型，`/session` 按物理模型统计成本。它不自行创建子 Agent。

- [jev-router.ts 官方示例](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/examples/extensions/jev-router.ts)：**当前源码**是 Jev 对首条任务判断复杂度，选择 GPT-5.6 Sol/Terra；规划模型完成第一次成功的 `edit`/`write` 后，同一会话一次性切到 GPT-5.6 Luna。不是 Jev 持续判断“是否该实施”，也不是每次工具返回都随机选便宜模型。示例明确接受一次 prompt-cache miss。

- [plan-mode 官方示例](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/examples/extensions/plan-mode/index.ts)：管理只读工具、计划步骤、用户选择 Execute 后恢复工具和继续会话；该文件没有 `setModel()` 或分类器路由。`/plan` 本身不等于自动换模型。

**对新截图的校准：**仓库证据确认虚拟模型、阶段切换和物理模型计费机制；截图中的“Claude Opus → Jev 判断进入实施 → GPT 6 Luna”具体 demo 组合尚未由这份现行示例验证。把它当机制参考即可，不能据此声称默认开箱自动路由。
