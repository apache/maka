### A2
基于给定流程，可成立的两项发现：

- **[P1] `status` 失败后继续强制删除，可能丢失未提交修改。** 场景：任务 branch 的已提交部分已进入 `HEAD`，但 worktree 还有修改；`status` 超时或异常被吞掉，祖先检查仍通过，普通 `worktree remove` 因 dirty 失败，随后 `--force` 删除文件。这条路径不需要合并判定有错。Git 明确规定 `--force` 可删除 dirty worktree；因此保存失败必须阻止 `merged` 清理继续进入强制删除。[Git worktree](https://git-scm.com/docs/git-worktree#_commands)

- **[P2，触发条件是该 branch 配有不同 upstream] 前置合并检查与 `branch -d` 使用不同目标，导致清理完成一半。** `merge-base … branch HEAD` 检查 branch 是否进入 `HEAD`；`branch -d` 优先检查 upstream，仅无 upstream 时检查 `HEAD`。因此 branch 已进入 `HEAD`、尚未进入 upstream 时，会先删除 worktree，再删除分支失败并返回 `not-merged`，任务还保留失效路径。应统一安全判定目标，并让重试分别识别“worktree 已移除、分支尚存在”。不能认定这些自动生成分支必然配置 upstream。[Git branch](https://git-scm.com/docs/git-branch#_options)、[Git merge-base](https://git-scm.com/docs/git-merge-base#_operation_modes)

其他已核实的边界，暂不独立报发现：

- `HEAD` 属于执行命令所在 worktree；若祖先检查在任务 worktree 内执行且 HEAD 指向任务 branch，检查就是自身对自身。**需确认 `cwd`，未见代码不能断言。**[Git worktree refs](https://git-scm.com/docs/git-worktree#_refs)
- `status --porcelain` 不报告 ignored 文件，普通 `git add` 也不保存 ignored 文件；不能把“已自动提交”理解为所有本地文件已保存。是否构成遗漏取决于产品保存契约。[Git status](https://git-scm.com/docs/git-status#_short_format)、[Git add](https://git-scm.com/docs/git-add#_description)
- `merge-base --is-ancestor` 的退出码 `1` 才代表非祖先，其他非零是错误。若所有异常统一转 `not-merged`，会误报 Git 故障；是否应列 P2 取决于实际 catch 范围。[Git merge-base](https://git-scm.com/docs/git-merge-base#_operation_modes)
- 双重 remove 失败后，是否仍尝试删分支、是否错误报告成功及清空记录，需要实际控制流；目前不能断言。手工删除目录留下的管理元数据需要 `worktree prune`，成功的 `worktree remove` 不应另算“必须 prune”的缺陷。[Git worktree](https://git-scm.com/docs/git-worktree#_description)
