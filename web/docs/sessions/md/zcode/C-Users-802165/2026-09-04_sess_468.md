# zcode怎么在模型设置选第三方模型，我发现都链接失败的，你有对应的新手教程吗

## 助手最终结论

### A1
全部请求连不上（返回 000），连域名解析可能都有问题。我确认一下 DNS 和连通性。

### A2
关键发现：`api.b.ai` 域名能解析，但 **TLS 握手直接失败**——也就是说不限于 ZCode，这台机器上任何程序都连不上它。我再做个对照实验确认是端点的问题，不是本机网络的问题。

### A3
问题定位清楚了，结论先说：**不是你配置姿势的问题，是 `api.b.ai` 这个接口地址本身连不通**。下面先给证据，再给新手教程。

## 诊断结果

我在你这台机器上做了无密钥探测（不会消耗你的 key）：

| 测试 | 结果 |
|---|---|
| `api.b.ai` 域名解析 | 正常（解析到 AWS 服务器） |
| `api.b.ai` TLS 握手 | **失败**，强制 TLS1.2 也失败 |
| 对照组：智谱官方 `open.bigmodel.cn` | 秒连，返回 401（路由存在，只差鉴权） |

也就是说：你的网络没问题、ZCode 没问题，是这个服务商的地址（或它在你网络环境的可达性）挂了。**这种情况下怎么填配置都连不上**，先找服务商核实最新接口地址——低价中转站换域名是常事。

顺带一提，你截图左侧的「智谱 BigModel」是内置供应商，你现在这个会话就是用它跑通的，可以对照它来配。

## 新手教程：第三方模型配置四步法

1. **模型设置 → 添加供应商**，填四样东西：
   - **Base URL**：服务商给的接口地址，注意结尾要不要带 `/v1`（见下面坑 1）
   - **API 格式**：服务商文档说“OpenAI 兼容 / `/v1/chat/completions`”就选 OpenAI 格式；**只有明确写了支持 Anthropic/Claude 格式的**才选 Anthropic Messages。市面上绝大多数中转站只有 OpenAI 格式
   - **API Key**：服务商后台生成的密钥
2. **添加模型**：模型 ID 必须照抄服务商模型列表里的名字，一字不差（你现在填的 `glm-5.3-flash` 要确认中转站真的上架了这个 ID，大小写、点号都不能错）
3. **点「已启用」**保存
4. **回到聊天输入框**，在模型选择器里选中它，发一句话验证

## 三个最常见的坑

**坑 1：`/v1` 重复拼接。** 界面上写的「Anthropic Messages (/v1/messages)」意思是 ZCode 会在你填的 Base URL **后面自动补** `/v1/messages`。你填了 `https://api.b.ai/v1` 再选 Anthropic 格式，实际请求就变成 `https://api.b.ai/v1/v1/messages`——双重 `/v1`，必然 404。选 Anthropic 格式时 Base URL 一般填到 `https://xxx.com` 或服务商指定的 `/api/anthropic` 这类前缀为止。

**坑 2：API 格式选错。** 格式决定请求发到哪个路径、用什么报文结构。服务商只给 OpenAI 格式你却选了 Anthropic，就是 404 或 400。

**坑 3：地址本身不通。** 就是你这次的情况。所以推荐**配置前先测通**，一条命令搞定：

```bash
curl "https://服务商地址/v1/chat/completions" \
  -H "Authorization: Bearer 你的key" \
  -H "content-type: application/json" \
  -d '{"model":"模型ID","messages":[{"role":"user","content":"hi"}]}'
```

- 返回 JSON 且有回复内容 → 地址、key、模型 ID 全对，照抄进 ZCode 即可
- 返回 401 → key 错或没余额
- 返回 404 → 路径不对（对照坑 1、坑 2 调整）
- 命令报连接错误 → 服务商地址问题，别浪费时间调 ZCode

按这个流程，先拿 curl 测服务商给的地址，测通了再回来填 ZCode；如果 curl 也连不通（大概率和你这次的 `api.b.ai` 一样），直接找服务商要新地址。
