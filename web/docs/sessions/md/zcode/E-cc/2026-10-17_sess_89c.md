## 结论

**这条通知说明“1017 版本”确实已经到你的客户端了，我上一条的“无法证实”可以修正为“大概率就是 1017 权重”。** 我当前会话的请求经 Magpie 转发到 `api.deepseek.com`，Magpie 记录的 `served` 模型是 `deepseek-flash`（显示名 DeepSeek V4.1 Flash）；而 DeepSeek 的 API 本身不返回快照号，所以只能靠客户端这条更新通知来判断版本。另外你本机 Magpie 今天 14:22 刚下载了 `.new` 更新包，和截图里“正在校验更新文件”的时间吻合。

**但“1017”和“两周免费”是两件不相干的事，模型推理并没有免费。**

我查了 Magpie 自己的用量账本，当前会话的 DeepSeek 请求都是计费的：

- `/v1/magpie/usage` 近 30 天：2306 次调用，cost 合计 388.24（全供应商总账）；
- 请求明细里，DeepSeek 单次调用 `cost` 为 0.00057、0.00097，`priced: true`，并且明确记了 `host: api.deepseek.com`。

也就是说，1017 只是权重版本更新，token 费用照常产生。公告里那两周免费，免费的是 **Search/Fetch 联网接口**，而且限定在 DeepSeek Harness / Claude Code / Codex 里通过服务端工具调用触发的那部分，11 月 1 日起按 5 元/千次收费。

**你这条 ZCode → Magpie 链路不会碰到那笔 Search/Fetch 费用。** 它走的是 `/v1/messages` 普通推理；Magpie 自己虽然提供 `/mcp/magpie/web-search`，但那是 Magpie 的 MCP 工具，不走 DeepSeek 的 Search/Fetch 计费项。除非你另外在 Harness / Claude Code / Codex 里用 DeepSeek 的服务端搜索，否则 11 月 1 日之后你的账单不会有这项。

## 一个配置上的提醒

Magpie 现在 `/v1/models` 里实际可调用的 ID 是 `deepseek/deepseek-flash`，**没有带 `-1017` 的模型 ID**。你 ZCode 供应商配置里那条 `deepseek/DeepSeek-V4.1-Flash-1017` 在 Magpie 的模型目录里查不到，选模型时用 `deepseek/deepseek-flash` 才是通的；之前那个拼错的 `deepseek-v4.1-falsh-1017` 也仍然建议删掉。
