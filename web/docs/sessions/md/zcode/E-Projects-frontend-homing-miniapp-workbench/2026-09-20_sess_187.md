### A1

### A2
15 个改动文件被两组完整覆盖。现在按顺序 stash：先暂存区那 9 个文件，再工作区剩下的 6 个文件。

### A3

**结果**

| stash | 内容 | 文件数 |
|---|---|---|
| `stash@{1}` | 暂存区那批：`industry-type-modal/*`、receptionPrep 的 `useLoading/usePrepActions/useReceptionPrep`、`search/index.tsx`、`selectCustomer/index.tsx` | 9 |
| `stash@{0}` | 工作区那批：`.gitignore`、`config/dev.js`、`package-lock.json`、`useDevice/services.ts`、`usePrepDevice.ts`、`stylelint.config.js` | 6 |

两组正好覆盖全部 15 个改动文件，`git diff` / `git diff --cached` 现在都是空的，工作树干净；`AGENTS.md`、`src/utils/loadingTrace/`、`.agents/`、`.debug/`、`config/.proxy.js`、`docs/bugs/` 等未跟踪文件全部保持原样，没被扫进来。两条 stash 的 patch 我都跟 stash 前的快照逐一比对过，内容完全一致。

**一个绕不过去的限制**（这也是我第一次尝试失败的原因）：`git stash push --staged` 对 `MM`（同一文件既有暂存又有未暂存改动）会直接报错 `Cannot remove worktree changes`，暂存区不会清空——我在临时仓库复现确认了这是 git 本身的行为，不是路径写法问题。你这 9 个暂存文件里有 6 个是 `MM`，所以「纯按暂存/未暂存切开」做不到，我改成按文件归属分两组：进第一组的文件，当前工作区的完整内容（含其中未暂存的部分）一起进 `stash@{1}`。

**需要立刻知道的一点**：`.gitignore` 的那条改动本身也在 `stash@{0}` 里，而它加的是 `.agents/`、`.debug/`、`config/.proxy.js`、`stylelint.config.property-order.js`、`docs/bugs/`、`temp/`、`.package-lock.json` 这些忽略规则。也就是说**现在这些目录不再被忽略，`git add -A` 会把 `.debug/` 扫进暂存区**（AGENTS.md 里的红线）。两个选择：

```bash
git checkout stash@{0} -- .gitignore        # 只把 .gitignore 拿回来（会同时进暂存区，可用 git restore --staged .gitignore 撤销暂存）
# 或者等恢复整批时：git stash apply stash@{0}
```

另外两点收尾信息：第一条命令失败时留下了一条重复条目 `stash@{2}`（内容 = 上面 `stash@{1}` 里的暂存部分，纯粹是冗余备份），不想要就 `git stash drop stash@{2}`；`git stash@{3}`（你自己那条 receptionPrep 顾客ID 备份）没动。三重保险的补丁备份在 [.debug/stash-backup-20260920/](E:\Projects\frontend\homing-miniapp-workbench\.debug\stash-backup-20260920)（`00-staged.patch` / `01-unstaged.patch`，该目录已被忽略，不会入库）。
