**第一性原理拆解（报错到底违反了什么不变量）**
- 平台约束：`HTMLMediaElement.currentTime`（Taro H5 `seek` 的落点）只接受**有限数字**，拿到字符串/NaN/undefined 一律强转成 NaN 并抛 `non-finite` TypeError。
- 原代码的洞：`const startAt = item.startTime ?? 0` 只兜 null/undefined。`'00:45'` 这种字符串不是 nullish，会原样穿透 `??` 直达 `seek('00:45')` —— 这就是 itest 上那条报错，一字不差。
- 为什么上次没堵住：我们在 mapper 层把 `mm:ss → 秒` 归一了，正常链路已经干净（我核实过：全模块只有 `drawerAudio.ts` 两处 `seek`，入参都来自 `startAt`；条目只有三个 mapper 生产点，全部走了解析）。但 itest 现网是「后端先发字符串 + 前端包还没带上解析」的**契约变更窗口**——改格式和发版不是原子的。对抗式审查还发现 `parseStartTimeSeconds` 有个理论漏洞：超长数字串按位权累加可以溢出成 `Infinity` 原样返回。两类残余都指向同一个结论：**“seek 只吃有限数字”这个不变量，必须在唯一调用它的边界处强制，不能假设上游永远干净**。

**修复**（[drawerAudio.ts](E:/Projects/frontend/homing-miniapp-workbench/src/subPackage/receptionPrep/commonComponents/EvidenceDrawer/drawerAudio.ts)，一行判定）：

```ts
const startAt = typeof rawStart === 'number' && Number.isFinite(rawStart) ? rawStart : 0;
```
