### 为什么不用做

我把加载链路彻底查清了:

```
真身  categories/.../proto-to-prd
        ↑ junction
全局源  ~/.agents/skills/proto-to-prd
        ↑
        ├── 五大CLI(.claude/.codex/.cursor/.gemini/.kimi)→ 经 sk-sync.js 镜像成各目录的 junction
        └── zcode → 直接读 ~/.agents/skills 本体(无需镜像)
```

**关键证据**:本会话开头系统列出的可用 skill 里,`.agents/skills` 下的 14 个全局技能全是带着 `C:\Users\802165\.agents\skills\xxx\SKILL.md` **绝对路径**加载进来的——这就是 zcode 直接读 `.agents/skills` 的铁证。它不需要 `.zcode/skills` 这个中间镜像层。

### 对你的实际含义

1. **改 `.agents/skills`(或里面的真身内容)→ zcode 立刻可见**。改真身 `categories/`,所有派生层(含 zcode 读的那个全局源)自动跟随。
2. **五大 CLI 才需要 `sk-sync.js`**——因为它们各自读自己的镜像目录(`.claude/skills` 等),必须靠同步保持对齐。zcode 不吃这套,它直连源。
3. 所以 `sk-sync.js` 的 `DIRS` 数组**不该**加 zcode——加了反而会在 `.zcode/skills` 建一个 zcode 根本不读的空镜像,徒增混乱。
