## 1. SKILL.md 的通用结构模式

### YAML Frontmatter（统一极简：仅 2 个字段）

6 个样本无一例外，frontmatter 都只有 `name` 和 `description` 两个字段，没有 `version`、`author`、`tags`、`triggers`、`allowed-tools` 之类的扩展字段。格式严格是：

```yaml
---
name: <kebab-case-id>
description: <一段话>
---
```

`name` 全部是 kebab-case 英文 ID（`tech-writer`、`minimal-diff-fix`、`gua-web-best-practices`、`systematic-debugging` 等），即使正文和 description 是中文也保持英文 ID。

### 正文的两种风格（按"出身"清晰分裂）

**风格 A — 中文本地化技能（tech-writer / mentor-me / minimal-diff-fix / gua-web-best-practices）**
- 正文中文，标题用 `#` + 中文技能名开头，正文全是中文 `##` 小节。
- 没有英文社区那种 "When to Use / How it works / Examples" 三段式。取而代之的是一套中文固定章节词汇，高频出现的有：
  - `## 使用定位` / `## 目标`（开场，说明这个 skill 干什么、不干什么）
  - `## 铁律` / `## 反模式`（强约束 / 不做什么）
  - `## 第一性原理…` / `## 对抗性…审查`（方法论，反复出现"第一性原理""对抗性思辨"作为方法论招牌词）
  - `## 输出格式` / `## 输出要求`（结尾固定一个编号清单，规定最终交付物结构，如"结论摘要 / 修改文件清单 / 改动目的 / 可执行步骤 / 验收方式"）
- 大量使用 **Markdown 表格** 作为正文组织主力（决策表、判断表、反方问题表），这是中文派最显著的视觉特征。

**风格 B — 英文上游技能（systematic-debugging / verification-before-completion）**
- 这两个明显是从英文 skill 库（疑似 superpowers 系列，正文多处引用 `superpowers:test-driven-development`、`superpowers:verification-before-completion`）直接搬来的，全文英文，未本地化。
- 有明显的固定章节模板：
  - `## Overview` → `## The Iron Law`（用代码块写一句全大写铁律，如 `NO FIXES WITHOUT ROOT CAUSE INVESTIGATION FIRST`）→ `## When to Use` → 主体方法论 → `## Red Flags` → `## Rationalization Prevention`（用表格列"借口 vs 现实"）→ `## Quick Reference`
- 用 `## The Four Phases` / `## The Gate Function` 这类强结构化的编号阶段组织流程，并用粗体 `**ALWAYS**`/`**DON'T**`/`**STOP**` 做语气强调。

> 结论：仓库里存在两套并行的写作范式。中文派走"定位 + 铁律 + 反模式 + 输出格式 + 表格驱动"，英文派走"Overview + Iron Law + When to Use + Phases + Red Flags + Rationalization 表"。前者更像"经验沉淀手册"，后者更像"行为约束宪法"。
