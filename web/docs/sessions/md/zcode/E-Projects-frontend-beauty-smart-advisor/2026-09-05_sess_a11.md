## 助手最终结论

### A1
我来查一下 `serviceComplete` 模块里护理服务报告详情调用预约详情接口的逻辑，看没有预约 id 时是怎么处理的。

### A2
找到了核心 Hook `useNextVisitReservation.ts`。再看下相关的两个工具函数，确认无预约 id 时的完整链路。

### A3
查清楚了。结论：**没有预约 id 时，预约详情接口根本不会被调用，点击按钮走的是“新增预约”预填路径，而不是编辑路径。**

具体逻辑都在 `useNextVisitReservation.ts` 里，分三层：

**1. 先从报告详情里解析预约关联**（`buildNextVisitReservationPayload.ts:63` 的 `resolveServiceReportReservationRelation`）

遍历报告详情接口返回的 `serviceLaunchRelations`，只认 `relationType === 'serviceReport'` 的关联。第一次预约的客户没有关联单，返回 `{ hasServiceReport: false, reservationId: '' }`。

**2. 预约详情接口被空值短路**（`useNextVisitReservation.ts:129`）

```ts
if (!hasServiceReport || !reservationId || !fallback) return;
```

预取 effect 里 `hasServiceReport && reservationId` 任一为空就直接 return，所以没有预约 id 时 `getReservationDetail` 完全不会发出请求，`nextVisitAppointment` 保持 `null`。按钮文案也因此不走“修改预约信息”，维持基础的“预约下次到店”。

**3. 点击按钮走 `openAdd` 新增分支**（`useNextVisitReservation.ts:186-192`）

`handleReserveNextVisit` 的判断顺序是：

1. 本地有 `nextVisitAppointment` → 编辑；
2. 有 serviceReport 关联和 reservationId → 用兜底快照编辑；
3. **都没有（即首次预约客户）→ `buildNextVisitReservationPayload(serviceData)` 组装预填数据，调 `host.openAdd(payload, lockedOptions)` 打开新增预约**，锁定顾问和客户。

预填数据全部来自报告详情本身的 `launchSnapshot`：顾客/门店取 `customerDetail`，服务取 `serviceDetail`，顾问取 `beautyDetail`，日期取 `summary.continuation.followUpPlan.suggestedVisitDate`，并带上 `launchId` 和 `source: 'serviceComplete'`。

如果连预填都组不出来（比如快照里没有 `followUpPlan`），`buildNextVisitReservationPayload` 返回 `null`，此时只弹 toast **“缺少预约信息，请手动添加预约”**，不打开任何弹窗。

简单说：你当时的处理是“详情接口只在有预约单时才调；没预约单就静默跳过，用报告快照预填一个新增预约表单，数据不够就提示用户手动添加”。
