## 助手最终结论

### A1
**结论：模型名没问题（`glm-5.3` 和 `glm-5.3-flash` 都是智谱真实存在的模型），问题出在你第二张图里的供应商配置——「上游格式」选了 Anthropic Messages（原生），但「请求地址」却填的是智谱的 Chat Completions 端点，两者不匹配，导致所有请求都打到不存在的路径上返回 404，插件就把 404 翻译成了"模型不存在或无权访问"。**

具体原因：

- 智谱有两个不同协议的端点：`https://open.bigmodel.cn/api/paas/v4` 是 OpenAI Chat Completions 协议；Anthropic（Claude）协议的端点是 `https://open.bigmodel.cn/api/anthropic`（官方文档 [Claude API 兼容](https://docs.bigmodel.cn/cn/guide/develop/claude/introduction)、[Claude Code 接入](https://docs.bigmodel.cn/cn/guide/develop/claude) 里给 Claude Code 用的就是这个地址）。
- 你选了「Anthropic Messages（原生）」（直连、不转格式），代理就会按 Anthropic 协议往 `{请求地址}/v1/messages` 发请求。`paas/v4` 下面根本没有这个路径，所以不管你在插件里选 `glm-5.3-flash` 还是 `glm-5.3`，全部失败——这也正好解释了你截图里两个模型先后都报同样的错。

修复方法（二选一，推荐第一种）：

1. **改请求地址**：把「请求地址」从 `https://open.bigmodel.cn/api/paas/v4` 改成 `https://open.bigmodel.cn/api/anthropic`（注意结尾不要带斜杠，你界面上的黄条提示就是这个）。「上游格式」保持 Anthropic Messages（原生）不变，保存后重试。
2. **或者改格式**：地址保留 `paas/v4`，把「上游格式」改成 Chat（Chat Completions），并按界面说明开启路由接管让代理做协议转换。多一层转换，不如方案 1 直接。

改完后验证两步：

- 在配置页点「管理与测速」或「获取模型列表」，能拉到模型列表就说明 key + 端点通了；
- 回到 VSCode 插件重新发一条消息。

另外提醒一点：如果你的 API Key 是 GLM Coding Plan 套餐专用 key，本来就应该走 `/api/anthropic` 这类 Anthropic 端点（参考 [Coding Plan 快速开始](https://docs.bigmodel.cn/cn/coding-plan/quick-start)），改成方案 1 后正好对上。
