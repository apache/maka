## 助手最终结论

### A1
测试已红：当前身份解析还在读全局 store，测不了 URL 入参。接下来改成只认路由上的 `customerId` / `employeeId`，选客跳转也把两个 ID 带上。

### A2
根因就是身份没走 URL：选客页只带了 `customerId`，接诊准备页在非美管家 App 里还去读全局 store，store 里没有当前顾客，于是变成「请先选择顾客」。详情页再把空的 `employeeId=` 带去档案接口，编辑就会报 `employeeId 不能为 null`。

现在两处一起改了：

1. **身份只认路由**：`customerId`、`employeeId` 都从 URL 取；`employeeId` 缺了才回落登录态；两个都没有就不进页。
2. **选客跳转带上两个 ID**：`/receptionPrep/index?customerId=...&employeeId=...&entrySource=现场设计页`。查看详情、详情回卡片页也走同一套 query。

请从「选择客户」再点一次「接诊准备」。地址栏里应能看到 `employeeId` 有值，卡片页出内容，编辑档案不再空参。

若跳转时弹出「顾问信息缺失，请重新登录」，说明登录态里没有 `employeeInfo.employeeId`，告诉我再查顾问 ID 的字段。

### A3
```
fix(receptionPrep): 选客跳转携带顾客与顾问 ID 并按路由解析身份

- 选择客户点「接诊准备」时 URL 同时带上 customerId、employeeId，缺顾问身份则提示重新登录
- 身份解析改为以路由为唯一数据源，employeeId 缺失才回落登录态，避免现场设计页落到「请先选择顾客」
- 查看详情、详情回卡片页复用同一 query，档案接口不再因空 employeeId 报不能为 null
```

提交时只纳入接诊准备相关文件，不要带上 `.gitignore`、`package-lock.json`、`stylelint.config.js`、`AGENTS.md`。
