## 结论摘要

两个问题同根同源，均已修复：

1. **循环加载的根因**：接口入参字段写错——`pageSize` → `pageRows`（后端文档当时写错）。错误参数让后端分页失控，`hasMore` 判断失真。
2. **"下拉刷新滚动加载每次5条"没有被删**：触底加载（`onScrollToLower`，每次 5 条）和下拉刷新（`onRefresh`）**一直绑定着**。被上次 commit `daccb99c` 误删的是两个**加载反馈组件**——`tableLoadSpacer`（72px 底部撑高）和"没有更多了"footer，导致功能看起来"坏了/没了"。

`✶ Insight ─────────────────────────────────────`
- `tableLoadSpacer` 不只是装饰：容器固定 560px、每行 112px，**5 行恰好填满**。删掉 72px spacer 后内容不再超容器，触底判定 `offsetHeight + scrollTop + 40 >= scrollHeight` 在 `scrollTop=0` 时即成立——**任何滚动都误触发加载**。它是物理层的"触底闸门"，删除它直接喂养循环。
- `pageRows` 修正后，hasMore 归一逻辑才生效：`hasNextPage → totalPages → totalRows → receivedRows>=pageRows`，配合 `appendedRowsCount<=0` 不满页守卫，循环在数据层被终结。
`─────────────────────────────────────────────────`

```
无更多+非空  → "没有更多了"
空态        → emptyState（原有，不冲突）
```
