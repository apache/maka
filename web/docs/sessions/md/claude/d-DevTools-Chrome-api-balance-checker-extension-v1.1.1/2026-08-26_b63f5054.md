| 位置 | 改动 |

`✶ Insight ─────────────────────────────────────`
- **删 `100vw` 是本次改动的关键而非附带**：弹窗场景里视口宽度由 body 撑开，`width: 100vw` 等于"body 取视口宽、视口又由 body 决定”的循环引用，浏览器行为不可预测。原来 560 > 559 断点不触发所以没事；改成 320 后断点**永远命中**，不删它你的“统一 320”就时灵时不灵。
- 这套 CSS 本来就是响应式的（`max-width: 459px` 断点里有两列指标、到期折行、隐藏头像、按钮纵排一整套窄屏适配）。320 定宽正好落进这个适配区间，等于免费继承了全部防挤爆处理——比如“424.4574 USD”这种长数值会自动从三列降为两列布局。
`─────────────────────────────────────────────────`

## ⚠️ 关于你量到的 283px

CSS 原文是 **560px**，你实测 283 ≈ 560 ÷ 2——**你的浏览器或该窗口大概率处于 50% 页面缩放**（Ctrl+- 缩小过，或系统 DPI 缩放的组合效果）。如果是这样，改成 320 后你在当前缩放下看到的仍会是约 160 物理像素，会更窄。建议先在扩展弹窗聚焦时按 **Ctrl+0** 重置缩放再看实际效果；如果重置后你仍觉得 560px 太宽想要 320，那这次改动正好；如果你其实想要的是“更宽”，告诉我目标宽度，一行就能改回来。
