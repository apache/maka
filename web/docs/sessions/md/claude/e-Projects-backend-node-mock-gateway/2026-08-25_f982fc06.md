### A3
✶ Insight ─────────────────────────────────────
- 「position = 文件总长度」的 `Expected ',' or '}'` 报错几乎总是「最外层容器未闭合」——解析器读完全文件还在等内容。此时逐字符括号深度追踪(跳过字符串字面量内的字符)能精确数出缺几个闭合、从哪层开始错,比肉眼看缩进可靠得多。
- 本网关 admin 接口的 `responseJson` 契约是**传 JSON 对象**([store.ts:510](src/store.ts#L510) 入库时 `stringifyJson`);传预序列化字符串会被二次编码,响应变成 `"{\"code\"...}` 双重转义——前端 `r.json()` 拿到的是字符串而不是对象,`.data` 直接 undefined。
- 超过 2^53 的 ID(如 `2048961435516395520`)在 JS number 下会丢精度,`recommendedGoodsIds` 以**字符串数组**入库存最稳；前端 `toText()` 对 number/string 统一处理,不影响消费。
