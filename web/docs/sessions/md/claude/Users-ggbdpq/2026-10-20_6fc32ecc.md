`★ Insight ─────────────────────────────────────`
- `rc.status >= 8` 这类静默失败是 spawnSync 的经典坑：命令不存在时 status 是 `null` 而非错误码，与 `>=` 比较恒为 false。跨平台脚本里外部命令调用必须同时检查 `error` 与 `status`,或像这次一样优先用内置 API(`fs.cpSync`)消除外部命令依赖。
- 管线的“步骤 5 失败但 1-4 已完成”体现了它的分层设计：更新是幂等的(重复跑只会重复回写)，doctor 是纯只读闸门——闸门报警不回滚前面的事务，由人工判断。这比“失败自动回滚”更适合 git 管控的 SSOT 场景。
