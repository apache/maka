## 安全审查发现：已核实，属占位符，无实际泄露

后台自动安全审查标记了一个中危项，我已在已提交版本中核实：

```yaml
# @CLIProxyAPI/config.yaml:35-36
# 启用后所有客户端(Claude Code/Codex/Gemini 等)必须在连接配置中填入此 Key，
# 否则请求会被拒绝。若暂不想启用鉴权，删除本块即可回滚到免鉴权模式。
api-keys:
  - "cli-proxy-api-key-please-change-me"
```

**核实结论**：这个值字面意为"请修改我"，是显式占位示例，不是真实凭据，当前无泄露风险（没有任何真实客户端会使用它）。本次提交把它随 `config.yaml` 一并入库，属于把配置示例模式带进了部署配置。

**模式风险（非当前风险）**：占位 API key 入库的反模式在于——如果日后管理员忘记替换，服务会以这个公开的默认 key 上线，鉴权形同虚设。这是"遗忘风险"而非"泄露风险"。

`✶ Insight ─────────────────────────────────────`
- 静态扫描对 `*-key-please-change-me` 这类值**故意**报警（MEDIUM），因为扫描器无法区分"占位符"与"已上线的默认密钥"，宁报不漏。人工核实时看两点：值是否含明确占位语义、是否与任何真实系统关联——两者都为否则判定为占位符。
- 该值在本次 diff 中是 `+api-keys:` 新增行，属新引入配置；但 `config.yaml` 本身是已跟踪文件，真实 `secret-key`（bcrypt 哈希）早在前几版就已入库。
`─────────────────────────────────────────────────`
