## 结论

图片我这边解析失败了（格式报错），看不到你 Todo Tree 面板具体长什么样。但 [.vscode/settings.json](.vscode/settings.json) 里没有 Todo Tree 的 include/exclude 配置，所以不是被规则排除的。结合上一轮搜索结果，25 处标记确实都写进磁盘了，那问题就出在 Todo Tree 扩展的扫描或显示上。

**不用重启项目。** Todo Tree 只读源码文件，和 dev server 跑不跑完全无关，重启项目解决不了。

按这个顺序排查，通常到第二步就好：

1. **点 Todo Tree 面板的刷新按钮**。打开左侧活动栏的 Todo Tree 图标，面板标题栏有个循环箭头（刷新），点一下。我刚一口气加了 25 处注释，文件监听可能没全捕获，手动刷新会触发重扫。

2. **重载 VSCode 窗口**。`Ctrl+Shift+P` 输入 `Developer: Reload Window` 回车。这会让 Todo Tree 重新激活并全量扫描，比重启项目轻得多，几秒钟。

3. **确认标记确实在文件里**。打开 [constants/waveform.ts](src/subPackage/audioEdit/constants/waveform.ts) 第 48 行，应该看到 `// TODO: [ui-fix] T1-4 帧数间隔太密...`。看得到就说明标记没问题，纯粹是 Todo Tree 没扫到。

4. **检查作用域不是"仅当前文件"**。Todo Tree 面板顶部如果过滤条件写成了某个文件，会只显示那个文件的 TODO。清空过滤框，或确认 `todo-tree.general.scopes` 设成了 workspace（工作区）级别。

5. **确认 tags 含 TODO**。设置里搜 `todo-tree.general.tags`，默认列表里有 `TODO`。如果你之前自定义过把它删了，就扫不到。

如果重载窗口后还是空的，大概率是工作区根目录的问题：VSCode 打开的文件夹必须是 `homing-miniapp-workbench`（或它的上级但没跨太远）。你可以在 Todo Tree 面板里看它扫描的是哪个根。

你先试第 1、2 步。方便的话重发一张 Todo Tree 面板的截图（或者直接说面板现在是完全空白、还是有内容但没我们的标记），我好判断卡在哪。
