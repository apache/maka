`✶ Insight ─────────────────────────────────────`
- **`git restore --worktree --source=<commit>` 是“解除跟踪但不删磁盘”的镜像操作**：它只写工作区、不碰索引，恢复的文件天然是 untracked——恰好匹配“主仓库不再管、磁盘继续用”的终态。若用 `git checkout <commit> -- <path>` 会把文件加回索引，制造 5900 个已暂存新增的灾难。
- **ignore 规则的优先级链**：深层目录 `.gitignore` > 根 `.gitignore` > `.git/info/exclude`。根里一句 `!/vibe/**` 放行就能让 `info/exclude` 全部失效——排查 ignore 不生效时先 `check-ignore -v` 找真正的命中规则。
- **junction 穿透删除是 Windows + git 的复发陷阱**：`git checkout/merge` 清理工作区时把 junction 当普通目录操作，删的是链接目标的真身。凡是“两个路径下的文件同时消失”，第一怀疑就是 junction。
