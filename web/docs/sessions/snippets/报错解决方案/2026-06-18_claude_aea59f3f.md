# 补丁机制(理解「为什么必须完整重启」)
插件应用补丁时做三件事(见 plugins/cursor-language-pack-zh-hans/src/patchService.ts 的 runApply,核心在 vendor/patch-core/src/services/WindowsTranslator.js 的 createTranslator().install()):

3. 修改 Cursor 应用自身 resources/app/package.json 的 main 入口,指向拦截器;拦截器先加载翻译逻辑,再 require 原 main

关键点:package.json 的 main 是 Electron 主进程启动时读取的入口。因此:
- reloadWindow(只重启渲染进程)无法让补丁生效
- 必须「完整重启 Electron 主进程」(整个应用退出再启动)才生效

# 核心问题
插件在「应用补丁」后提供一个「重启 Cursor」按钮,期望点击后 Cursor 完整退出并自动重新打开。实际表现:点击后 Cursor 既关不掉也重新打不开。需要从「扩展层」可靠地实现 Cursor 完整退出 + 自动重新打开。

# 已确认的技术事实(作为约束,不要推翻)
1. VS Code 没有把「完整重启」公开成任何扩展可 executeCommand 的命令。公开的只有 workbench.action.reloadWindow(软重启)和 workbench.action.quit(退出,不重启)。
2. 微软官方语言包扩展本身零代码、零重启逻辑,真正的完整重启由 VS Code 内核 hostService.restart()(= Electron app.relaunch() + app.quit())完成,扩展层访问不到该内部 service。
3. Cursor 是 VSCode 的闭源 fork,保留了大部分 workbench 命令,但某些命令行为可能与 VS Code 不同(已观测到 workbench.action.restart 在 Cursor 中疑似 no-op 却 resolve)。
4. Cursor/VSCode 是单实例应用:已有实例运行时,新启动的 Cursor.exe 会把控制权转给已有实例然后自己退出,不弹新窗口(单实例锁)。
