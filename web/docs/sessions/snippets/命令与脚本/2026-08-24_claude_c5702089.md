## 结论

仓库已在 GitHub 上从 `ggbdpq/dev-config` 改名为 `ggbdpq/home`,本地 `origin` 还记着旧地址。用一条 `git remote set-url` 即可更新，**不动任何文件、不影响工作区**。

## 可执行步骤(按原协议给出 SSH 版)

```bash
git remote set-url origin git@github.com:ggbdpq/home.git
```

你原来的 remote 走的是 SSH(`git@github.com:...`),所以保持 SSH、只换仓库名是最小变更，沿用现有 SSH key 认证，无需额外配凭据。

如果你明确想改走 HTTPS(比如 SSH key 不在这台机器上)，则用：

```bash
git remote set-url origin https://github.com/ggbdpq/home.git
```

注意 HTTPS 方式 push 时需要 GitHub 凭据(Windows 上通常由 Git Credential Manager 弹窗处理)。

## 验收方式

```bash
git remote -v        # 应显示新地址
git fetch origin     # 能正常拉取即连通
```

## 回滚方式

```bash
git remote set-url origin git@github.com:ggbdpq/dev-config.git
```

`✶ Insight ─────────────────────────────────────`
- **GitHub 改名后有自动重定向**：仓库改名后，旧 URL 的 fetch/push 会在服务端被重定向到新地址(除非旧名被新仓库占用)，所以你不改 remote 短期也能 `git pull`。但 GitHub 官方建议尽快更新本地 remote——一旦旧名被别人注册，重定向失效，推送会指向陌生仓库。
- **改名不影响分支跟踪**:`origin/main` 等上游跟踪关系存在 `.git/config` 里，引用的是 `origin` 这个别名而非具体 URL,所以只改 URL 后 `git push` / `git pull` 的行为完全不变。
