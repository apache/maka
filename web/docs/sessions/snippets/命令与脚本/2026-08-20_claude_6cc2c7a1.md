**1. `ui\card-admin`、`ui\date-playbook-miniapp` 源码已随重置被删除。**
它们是被旧历史跟踪的文件，而远程新快照（7584 个文件）里没有 `ui/` 路径，`reset --hard` 会删除所有“远程不存在的被跟踪文件”。仓库现在长这样：

**2. `ui\vibe` 的遗留物（card-admin 数据库 8.5MB、`.env` 文件）已物理消失，且与本次操作无关。**
铁证：本轮我执行任何 git 变更**之前**的 `git status` 里 `ui/vibe/` 就已不在未跟踪列表，现在 `Test-Path` 确认整个 `ui/` 目录不存在。`reset --hard` 不会删除未跟踪文件，所以它是在上一轮对话结束后到你这次指令之间被外部删除的（可能是你手动清理）。**这些数据从未被 git 跟踪，无法从 git 恢复**——如果数据库重要且不是你删的，只能指望回收站/其他备份。

`✶ Insight ─────────────────────────────────────`
- `reset --hard <remote>` 的删除语义是“删到与目标提交一致”：被跟踪但不属于目标的文件会被移除，而未跟踪文件一律不动——本次 `ui/` 消失恰好同时踩中这两条规则的边界。
- 远程“全量快照式”单提交（7584 文件一次提交）意味着远程与旧历史**无共同祖先**，任何 `pull` 都不可能 fast-forward，只能 reset 或 rebase——这也是为什么“以远程为主”在这里等价于历史替换。
