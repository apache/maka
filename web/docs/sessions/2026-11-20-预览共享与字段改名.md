# 预览共享与字段改名

## 一句话结论

wxa-runner 默认只听本机，共享要显式加 `--host`；字段表已经删掉的旧键不要再当备用。这两条现有 Skill 没写死。`data` 数组与 `data.list` 双形态、Node 原生跑测试遇无扩展名导入会失败，已在 `modules/api` 与 `modules/quality` 里，本篇不重复立项。

资料缺口：本对话前半段只剩压缩摘要，样式细节不以摘要为验证。局域网只在本机请求过监听地址，别的电脑没试。`userPackageName` 没有新的测试环境抓包。

## Skill 增量建议

均未改技能，未做「改完再跑一遍」的检验。

### 1. wxa：共享与产物

位置：`modules/wxa/MODULE.md`「步骤」第 3 步启动命令之后。

现有规则：只写了 `node …\dev.mjs`，并打开 `http://localhost:3000/…`。`dev.mjs` 第 22 行仍是 `wxa-runner dev dist/ -o`，没有 `--host`。模块没写「改了 `src` 但页面还是旧的」该先查 `dist`。

建议追加：

> `wxa-runner dev` 的 `--host` 默认 `localhost`，只听本机。要给局域网看：`wxa-runner dev dist/ --host`（不带值即 `0.0.0.0`）。`dev.mjs` 不转发这个参数，直接跑它仍是本机。验收看监听地址：`::1` 或 `127.0.0.1` 是没放开；`0.0.0.0` 才是放开。启动横幅里的虚拟网卡（如 Hyper-V Default Switch）不要发给别人。本机防火墙未放行时，本机访问局域网 IP 仍可能 200，不能当成别人打得开。
>
> 预览读的是启动参数里的目录（这里是 `dist/`），不读 `src/`。页面还是旧图标或旧样式时，先在产物里搜新 URL 或新样式；没有就先构建，不要接着改源码。

来源证据：`wxa-runner dev --help` 写明 `--host` 默认 localhost。改前 `Get-NetTCPConnection -LocalPort 3000` 的 `LocalAddress` 为 `::1`；加上 `--host` 后为 `0.0.0.0`，本机请求横幅中的局域网地址得到 HTTP 200。当前 `modules/wxa/MODULE.md` 与 `scripts/dev.mjs` 仍无 `--host`。本对话里源码已换图、刷新仍是旧图，构建后产物才出现新地址。

适用边界：只针对 wxa-runner 的 dev 服务器。微信开发者工具的真机预览不走这条。

检验场景（未执行）：不带 `--host` 时监听应为回环地址；带上之后应为 `0.0.0.0`。只改 `src`、不构建，产物里搜不到新字符串。

### 2. api：字段表改名不再回退

位置：`modules/api/MODULE.md` 反模式「有内容的键优先」那条后面。那条保留，它管的是同一次响应里两个键都在、其中一个是笔误。

现有缺口：字段表已经用新键替换旧键时，没有「禁止再读旧键」的边界。

建议追加：

> 新导出的字段表用新键替换了旧键时，mapper 只读新键。响应示例、历史私聊或旧抓包里仍有旧键，也不要在新键为空时回退。旧键有值、新键为空，按新键处理（空则不展示），并把「示例未改」记成文档差异。字段表把可空字段写成没有子字段的 Object 时，只接受非空字符串，不拆对象里的属性。状态枚举以字段表说明为准；响应示例里的名称与枚举冲突时，不用名称字段。

来源证据：2026-11-19 17:20 导出里，套餐名从 `packageName` 改为 `userPackageName`，类型仍是无子字段 Object、示例为空；`serviceStatus` 为 Number，说明 1 待服务、2 服务中、3 已完成。响应示例仍是 `serviceStatus=2` 配「待服务」。用户要求与字段表一致后，映射改为只读这两个新键。`npx tsx --test test/health-todo.test.mts` 8 条通过，其中「同时有 `taskStatus=2` 与 `serviceStatus=1` 时展示待服务」「只有 `taskStatus` 时状态为空」「`packageName` 不展示、`userPackageName` 才展示」「`userPackageName` 为对象时套餐名为空」。

适用边界：字段表明确替换。两个键都还在字段表里、只是示例笔误时，仍走原来的「有内容的键优先」。没有新抓包，不把文档更新写成测试环境已经返回字符串。

检验场景（未执行）：字段表只有新键、响应里只有旧键且有值，页面应不展示该值。

### 3. codesign：临时密钥读哪一个变量

位置：`modules/codesign/MODULE.md`「鉴权方式」。现在写「`COS_TEMP_KEY_TOKEN` + 默认 homing 生产接口」，和代码不一致。

现有缺口：`scripts/lib/config.mjs` 读的是 `TENCENT_COS_TEMP_KEY_URL`，缺省是 itest 的 `get-cos-temp-key`。`modules/config/.env.example` 同时有 `TENCENT_COS_TEMP_KEY_URL`（itest）和 `COS_TEMP_KEY_URL`（homing）。后者不会被这段代码读到。

建议替换「默认 homing」那句：

> 代码只读 `TENCENT_COS_TEMP_KEY_URL`，未设置时是 itest，不是 homing。`.env` 里的 `COS_TEMP_KEY_URL` 不会自动生效；要走 homing，把它的值当作 `getCosTempKey` 的 baseUrl 传入，或把同一 URL 写进 `TENCENT_COS_TEMP_KEY_URL`。Header 仍是 `token:`。

画板上传脚本 `upload-codesign-images.mjs` 只认带 `share.json` 的画板目录，不传任意切图。本地切图要走同一套 lib：`buildObjectKey('', ext, body)` 得到桶根内容 MD5；`deliverAsset` 的 level 为 verified 才把 URL 写入代码。Windows 上不要用盘符路径做 ESM import，用 `pathToFileURL` 再动态 import。figma 模块那份上传脚本和兜底密钥仍不要用于 senior 桶（已有 SignatureDoesNotMatch 记录，不另立规则）。

来源证据：本轮读到的 `config.mjs` 第 92–95 行与 `.env.example` 第 55、66 行。本对话上传两张箭头切图时，把 `COS_TEMP_KEY_URL` 作为 baseUrl 传入后，读回 level 为 verified。直接 `import 'C:/…'` 报 `ERR_UNSUPPORTED_ESM_URL_SCHEME`。

适用边界：codesign 这套 lib。别的上传器若已经改读 `COS_TEMP_KEY_URL`，以那个文件为准。

检验场景（未执行）：不传 baseUrl、只配 `COS_TEMP_KEY_URL` 时，请求应打到 itest 缺省地址。

### 4. quality：已有相对导入时用 tsx，不为此拆文件

位置：`modules/quality/MODULE.md` 第 51 行「无扩展名相对导入则 node 解析失败、抽到独立文件」之后补一句，不删原句。

建议追加：

适用边界：本机能执行 npx，且允许它取 tsx。没有网络或不许装包时，仍走第 51 行的拆文件路径。

## 可复用经验与案例

预览仍是旧界面时，先分清三层：源码、`dist`、wxa 正在读的那次构建。本对话里测量图标和标题气泡都是源码已改、产物未更新，刷新无效。构建完成后在产物里搜到新地址，预览才变。

17:20 字段表把套餐名改成 `userPackageName`，状态只留 `serviceStatus`。此前私聊让优先读 `taskStatus`，11:23 字段表仍写 `packageName`。以新字段表为准之后，今日服务和预约日历共用这一处映射；认不出的状态留空，不显示成「待服务」。字段表类型仍是空 Object，所以对象不当成套餐名。响应示例和字段表仍冲突，名称字段继续不用。测试环境是否已经返回字符串，这次没抓包，未闭环。

## 常用命令

工作目录均为小程序仓库根。凭证从 `modules/config/wxa.env` 注入，不写进命令。本对话当时读的是旧路径 `modules/wxa/.env`；以现在的 `dev.mjs` 为准。

看监听范围，不启动服务：

```powershell
wxa-runner dev --help
Get-NetTCPConnection -LocalPort 3000 -State Listen | Select-Object LocalAddress, OwningProcess
```

成功信号：帮助里 `--host` 默认 localhost。`LocalAddress` 为 `::1` 或 `127.0.0.1` 表示只本机；`0.0.0.0` 表示已放开。

放开局域网。先停掉占着 3000 的旧进程，再启动。`dev.mjs` 不会加上 `--host`。

```powershell
wxa-runner dev dist/ --host
```

前提：在仓库根，且进程环境里已有 `WXA_*`。成功信号：横幅出现局域网地址，监听为 `0.0.0.0`。副作用：同一网段能打开这个预览，其中包含当前登录态；本机防火墙可能仍挡住别人。

源码改完要进预览：

```powershell
npx taro build --type weapp
```

成功信号：退出码 0，且 `dist` 里能搜到新字符串。副作用：全量构建约一到两分钟；构建过程中 wxa 可能短暂报 `app.json` 缺 pages，写完会再编译。

已有无扩展名导入的适配器测试：

```powershell
npx tsx --test test/health-todo.test.mts
```

成功信号：该文件内测试全部通过。副作用：本机没有 tsx 时 npx 会下载。不要把 `node --experimental-strip-types --test` 记成这条的替代，它在 `./config` 上失败过。
