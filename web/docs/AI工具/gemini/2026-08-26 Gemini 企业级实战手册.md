## 0. 结论摘要

Gemini CLI 是 Google 开源（Apache 2.0）的终端优先代理，核心竞争力是**大上下文（1M token）、Google 生态 grounding、免费额度（个人账号 60 请求/分钟、1000 请求/天）**。2026-08 的关键演化：配置字段全面命名空间化（`tools.` / `security.` / `experimental.`）、审批模式成为主控轴（`--approval-mode default|auto_edit|yolo|plan`）、skills/extensions/subagents 三大扩展体系配套 `gemini skills` / `gemini extensions` 子命令、GEMINI.md 支持三层发现 + `@import` + 自定义文件名。

核心治理面一览：

| 治理面 | 载体 | 一句话定位 |
|---|---|---|
| 上下文 | `GEMINI.md`（三层发现：全局/workspace/JIT） | 分层持久指令，支持 @import 拆分 |
| 用户配置 | `~/.gemini/settings.json` | 命名空间化字段 + mcpServers + 认证 |
| 项目配置 | `<project>/.gemini/settings.json` | 覆盖用户层，只提交团队稳定配置 |
| 审批安全 | `--approval-mode` + sandbox + trustedFolders | default 逐项确认 → yolo 全自动 |
| 能力扩展 | Skills / Extensions / Subagents / MCP | 子命令管理，来源治理 |
| 忽略边界 | `.geminiignore` + respectGitIgnore | 控制搜索范围 |

事实优先级（处理任何冲突时按此排序）：用户当次明确指令 > 当前源码与配置 > 真实接口与命令输出 > 官方文档 > 本手册 > 社区经验。

## 1. 定位与边界

### 1.1 Gemini CLI 是什么

开源终端代理：读写文件、跑 shell、web fetch/search、Google Search grounding、MCP 扩展、GitHub Action 集成。Gemini 3 系列模型 + 1M token 上下文窗口，适合大代码库理解与长链路任务。

### 1.2 入口形态

| 形态 | 主要用途 | 优点 | 限制 |
|---|---|---|---|
| 终端 REPL | 交互式代理会话 | 最直接路径，checkpointing、/memory | 需理解审批与沙盒 |
| 非交互 `-p` | 脚本/CI | `--output-format json/stream-json` | 需配审批模式与工具白名单 |
| GitHub Action | PR 审查、issue 分诊、@gemini-cli 按需协助 | 官方 action（google-github-actions/run-gemini-cli） | 仓库权限治理 |
| Gemini Code Assist / Antigravity | IDE 协作 | 与编辑器集成 | 能力随版本变化，本机 antigravity* 目录为佐证 |

### 1.3 认证三选项（官方核验）

| 方式 | 适用 | 配置 | 要点 |
|---|---|---|---|
| Google 账号 OAuth | 个人开发者（推荐起步） | 启动后浏览器登录 | 免费 60/min、1000/day；企业 Code Assist 许可配 `GOOGLE_CLOUD_PROJECT` |
| Gemini API Key | 需要指定模型/付费档 | `GEMINI_API_KEY` 环境变量 | 1000/day（flash+pro 混合） |
| Vertex AI | 企业生产 | `GOOGLE_API_KEY` + `GOOGLE_GENAI_USE_VERTEXAI=true` | 高配额、Cloud 集成 |

密钥一律走环境变量，绝不写入 settings.json 或提交仓库。

### 1.4 适合与不适合的任务

| 适合 | 原因 | 验收方式 |
|---|---|---|
| 大代码库问答与结构理解 | 1M 上下文 + JIT 分层 GEMINI.md | 输出入口、模块关系、证据路径 |
| CLI 自动化与管道 | `cat x \| gemini`、`-p` + JSON 输出 | 命令可复现、退出码可判 |
| Google 生态任务 | Search grounding、Cloud 集成 | 引用可核验 |
| MCP 接入 | settings.json mcpServers + `gemini mcp` 子命令 | `gemini mcp list` 状态可查 |
| 敏感系统写操作 | 低——shell/MCP 可执行外部动作 | 默认逐项审批，人手执行关键写操作 |

## 2. 核心工作模型

### 2.1 审批模式（主控轴，官方核验）

| `--approval-mode` | 行为 | 对应场景 |
|---|---|---|
| `default` | 逐项确认 | 生产/敏感仓库 |
| `auto_edit` | 自动批准编辑类，其余确认 | 日常开发 |
| `yolo` | 全自动（`--yolo` 已废弃，改用此值） | 隔离环境/沙盒内 |
| `plan` | 规划优先（实验，需 `experimental.plan: true`） | 方案设计 |

配套开关：`--sandbox/-s` 沙盒执行；`security.disableYoloMode: true` 可在 settings 里禁用 yolo（即使命令行传入）；`tools.autoAccept` 控制只读操作自动接受。

### 2.2 三层治理

**上下文（GEMINI.md 决定知道什么）+ 审批与沙盒（决定能做什么）+ checkpointing（决定怎么回退）**。会话可保存与恢复（`--resume`），压缩阈值 `model.compressionThreshold` 默认 0.5（上下文占用过半触发压缩）。

## 3. CLI 命令全景

### 3.1 安装与发布渠道

```powershell
npx @google/gemini-cli          # 免安装试用
npm install -g @google/gemini-cli
brew install gemini-cli         # macOS/Linux
gemini update                   # 更新
```

发布节奏（官方核验）：`preview` 每周二 UTC 23:59（未充分验证）、`stable` 每周二 UTC 20:00、`nightly` 每日 UTC 00:00。生产用 `@latest`，尝鲜用 `@preview`。

### 3.2 核心命令形态

| 命令 | 说明 |
|---|---|
| `gemini` | 交互 REPL |
| `gemini "query"` | 带初始提示进入交互 |
| `gemini -p "query"` | 非交互执行后退出 |
| `gemini -i "query"` | 执行后继续交互 |
| `cat logs.txt \| gemini` | 管道输入处理 |
| `gemini -r "latest"` | 恢复最近会话 |
| `gemini -r "latest" "query"` | 恢复会话并追加新提示 |
| `gemini -r "<session-id>" "query"` | 按 ID 恢复 |
| `gemini --list-sessions` / `--delete-session <n>` | 会话管理（按索引号） |

### 3.3 关键选项（官方核验）

| 选项 | 说明 |
|---|---|
| `-m, --model` | `auto`（默认，preview 开启时解析到 gemini-3-pro-preview，否则 gemini-2.5-pro）/ `pro` / `flash` / `flash-lite` 或完整模型名 |
| `-o, --output-format` | `text`（默认）/ `json` / `stream-json` |
| `--approval-mode` | default / auto_edit / yolo / plan（见 §2.1） |
| `-s, --sandbox` | 沙盒环境执行 |
| `-w, --worktree [name]` | 在新 git worktree 启动（实验，需 `experimental.worktrees: true`） |
| `--include-directories ../lib,../docs` | 扩展 workspace 目录 |
| `-e, --extensions a,b` / `-l, --list-extensions` | 启用指定扩展 / 列出全部 |
| `--allowed-mcp-server-names a,b` | 限定 MCP server |
| `--allowed-tools` | **已废弃**，改用 Policy Engine |
| `--experimental-acp` / `--experimental-zed-integration` | 编辑器桥接（实验） |
| `-d, --debug` / `-v, --version` / `-h, --help` | 常规 |

### 3.4 MCP 子命令

```powershell
gemini mcp add github npx -y @modelcontextprotocol/server-github        # stdio
gemini mcp add api-server http://localhost:3000 --transport http        # HTTP
gemini mcp add slack node server.js --env SLACK_TOKEN=xoxb-xxx          # 带环境变量（示例格式，token 实际应放安全存储）
gemini mcp add db node db-server.js --scope user                        # 用户级
gemini mcp add github npx -y @modelcontextprotocol/server-github --include-tools list_repos,get_pr
gemini mcp remove github
gemini mcp list
```

`--include-tools` 是最小授权利器：只暴露指定工具而非整个 server。

### 3.5 Extensions 与 Skills 子命令

```powershell
gemini extensions install https://github.com/user/my-extension [--ref develop] [--auto-update]
gemini extensions list / update --all / enable <name> / disable <name>
gemini extensions link /path/to/extension     # 本地开发
gemini extensions new ./my-extension / validate ./my-extension

gemini skills list / install https://github.com/u/repo / link /path/to/my-skills
gemini skills enable <name> / disable <name> / enable --all / disable --all
```

注意：skills 默认实验特性（`experimental.skills: false`），启用前评估。

### 3.6 会话内 slash 命令（reload 系为官方核验新增）

| 命令 | 作用 |
|---|---|
| `/memory reload` | 重载 GEMINI.md 等上下文文件 |
| `/mcp reload` | 重启并重载 MCP server |
| `/skills reload` / `/agents reload` / `/commands reload` / `/extensions reload` | 重载对应注册表 |
| `/memory show / add / refresh` | 查看/追加/重扫分层记忆 |
| `/settings` | 可视化设置面板 |
| `/help` / `/quit` | 常规 |

全量 slash 表（/chat、/compress、/ide、/init、/stats、/theme、/tools 等）见 https://geminicli.com/docs/reference/commands （本次未逐条拉取）。

## 4. 目录与 Git 策略

### 4.1 用户级目录（本机 2026-08-26 观察）

```txt
~/.gemini/
  GEMINI.md            # 全局上下文（个人协作偏好）
  settings.json        # 用户配置（+ .bak 备份链）
  hooks/               # hooks 定义（新）
  skills/              # 技能
  trustedFolders.json  # 文件夹信任登记（新）
  antigravity/  antigravity-backup/  antigravity-ide/   # Antigravity 相关
  config/  history/  projects.json  state.json  tmp/    # 运行状态
  installation_id
```

| 类型 | 治理建议 |
|---|---|
| 上下文 `GEMINI.md` | 跨项目个人偏好，勿写密钥与项目私密 |
| 配置 `settings.json` | 改前留 .bak（本机已有 5 个备份），记录变更原因 |
| 信任 `trustedFolders.json` | 文件夹信任即审批策略边界，定期审查 |
| 状态 `history/`、`projects.json`、`state.json` | 本机运行状态，禁止提交 |

### 4.2 项目级推荐结构

```txt
project-root/
  GEMINI.md                 # 或 AGENTS.md（经 context.fileName 映射）
  .gemini/
    settings.json           # workspace 配置，覆盖用户层
    commands/
      review.md             # 自定义 slash 命令
    skills/
      repo-audit/SKILL.md
    styles/                 # 输出样式
  .geminiignore             # 搜索忽略（类 .gitignore 语法）
  docs/ai-development/gemini-workflow.md
```

### 4.3 Git 策略

- 提交：项目 `GEMINI.md`/`AGENTS.md`、`.gemini/settings.json`（脱敏）、`.gemini/commands/`、`.gemini/skills/`、`.geminiignore`。
- 不提交：`~/.gemini` 全部；`settings.json.bak.*`；任何 OAuth/token 文件（若重新出现）。
- checkpointing 是会话级回退，里程碑落 Git。

## 5. 配置治理（settings.json）

### 5.1 分层与优先级

用户 `~/.gemini/settings.json` < 项目 `<project>/.gemini/settings.json`（workspace 覆盖 user）。`/settings` 命令可可视化查看编辑全部设置。

### 5.2 命名空间化字段精选（官方核验，2026-08）

| 命名空间 | 关键字段 | 默认 | 治理要点 |
|---|---|---|---|
| `general.` | `previewFeatures` | false | 开启后 auto 别名解析到 gemini-3-pro-preview |
| `general.` | `enableAutoUpdate` | true | 企业可关 |
| `model.` | `maxSessionTurns` | -1 | 限制会话轮数防失控 |
| `model.` | `compressionThreshold` | 0.5 | 上下文占用过半触发压缩 |
| `context.` | `fileFiltering.respectGitIgnore` / `respectGeminiIgnore` | true/true | 搜索边界 |
| `context.` | `discoveryMaxDirs` | 200 | GEMINI.md 发现目录上限 |
| `tools.` | `autoAccept` | false | 只读操作自动接受 |
| `tools.` | `disableLLMCorrection` | false | true 时编辑工具精确匹配失败立即报错（防自作主张改写） |
| `tools.` | `truncateToolOutputThreshold` | 4000000 | 工具输出截断，防爆上下文 |
| `security.` | `disableYoloMode` | false | true 时禁用 yolo（含命令行传入） |
| `security.` | `enablePermanentToolApproval` | false | "永久允许"选项开关 |
| `security.` | `blockGitExtensions` | false | 禁止从 Git 安装扩展 |
| `security.` | `environmentVariableRedaction.enabled` | false | 敏感环境变量脱敏 |
| `security.` | `folderTrust.enabled` | false | 按文件夹分级信任 |
| `experimental.` | `plan` | false | Plan Mode 与规划工具 |
| `experimental.` | `skills` | false | Agent Skills |
| `hooks.` | `notifications` | true | hooks 执行提示 |

顶层 `mcpServers`、自定义 slash 命令等结构化配置仍在 settings.json / .gemini 目录（逐键参考见官方 configuration 页，本次未拉取，标注待实测）。

### 5.3 GEMINI.md 三层发现（官方核验）

1. **全局** `~/.gemini/GEMINI.md`：所有项目默认指令。
2. **workspace**：当前配置的 workspace 目录及其父目录中的 GEMINI.md。
3. **JIT（即时）**：工具访问某文件/目录时，自动扫描该目录及祖先（到 trusted root 为止）的 GEMINI.md——模块级指令按需注入，不占常驻上下文。

进阶能力：`@./path/file.md` import 拆分大文件；`context.fileName: ["AGENTS.md", "GEMINI.md"]` 自定义文件名实现跨工具统一；footer 显示已加载上下文文件数可做直觉校验。

## 6. 权限与安全

- 审批轴：`--approval-mode` 四档（§2.1），`security.*` 字段兜底（禁 yolo、禁永久批准、禁 Git 扩展）。
- 沙盒轴：`--sandbox` 独立于审批模式，yolo 场景务必叠加沙盒或容器。
- 信任轴：`trustedFolders.json` + `security.folderTrust.enabled` 按目录分级。
- 工具轴：`--allowed-mcp-server-names` 限 server、MCP `--include-tools` 限工具、Policy Engine 替代已废弃的 `--allowed-tools`。
- 环境轴：`environmentVariableRedaction` 脱敏、密钥只走环境变量、`.geminiignore` 排除敏感路径。

## 7. 提示词与上下文技巧

| 技巧 | 适用场景 | 具体做法 |
|---|---|---|
| JIT 分层 | monorepo | 根 GEMINI.md 写通用约束，各模块目录放局部 GEMINI.md 按需加载 |
| @import 拆分 | 全局上下文过长 | `@./components/instructions.md` 引用，主文件只留索引 |
| 文件名统一 | 多 AI 工具共存 | `context.fileName` 配 `["AGENTS.md", "GEMINI.md"]` 复用同一份规则 |
| 管道投喂 | 日志/文本分析 | `Get-Content logs.txt \| gemini` 避免手动粘贴 |
| flash 分层 | 高频轻任务 | `-m flash` 省配额，复杂任务再上 pro |
| 压缩调优 | 长会话 | `model.compressionThreshold` 调低提前压缩 |
| reload 热更 | 改了配置/GEMINI.md | `/memory reload`、`/mcp reload` 免重启 |
| 会话接力 | 跨天任务 | `gemini -r "latest"` 或按 `--list-sessions` 索引恢复 |

### 7.1 Prompt 模板（三则）

只读分析：

```txt
请只读分析当前项目。不要创建、修改、删除文件，不要安装依赖，不要提交代码。
先列出你会读取的文件类型，再输出技术栈、入口、目录职责、风险点和建议验证命令。
涉及配置和凭据时只输出字段类别，禁止输出具体密钥值。
```

最小改动：

```txt
请按 Read、Plan、Execute 三阶段处理。Plan 必须包含文件白名单、测试策略、验收点、回滚点和风险。
在我确认前不要修改文件。确认后只改白名单文件，先补失败测试，再做最小实现。
交付时说明真实执行过的验证命令和未验证事项。
```

规则沉淀：

```txt
请把这次任务中可复用的经验沉淀为项目 GEMINI.md 或 .gemini/commands 下的规则。
只保留高频、明确、可执行的规则。每条规则说明触发场景、禁止事项、验证方式和维护位置。
不要把一次性背景、会话记录、密钥、临时路径写入规则文件。
```

## 10. 企业级工作流

### 10.1 标准闭环

```txt
目标澄清 -> 只读盘点(plan 模式) -> 最小方案 -> 授权执行(auto_edit) -> 测试验证 -> diff 审查 -> 文档沉淀 -> 规则更新(GEMINI.md/commands)
```

| 阶段 | 关键动作 | 交付物 |
|---|---|---|
| Read | `-m pro` 大上下文盘点 README、package、配置、入口 | 项目地图和风险清单 |
| Plan | `--approval-mode plan`（开 experimental.plan）出方案 | 可确认的执行计划 |
| Execute | `auto_edit` + 文件白名单，先测试后实现 | 最小 diff 和验证结果 |
| Review | 按严重度检查行为、安全、性能、测试缺口 | 可追踪 findings |
| Retrospective | 高频纠正点沉淀为 GEMINI.md 条目 / command / skill | 规则更新记录 |

### 10.2 团队治理组合

- 无人值守：`-p` + `--output-format json` + Policy Engine 工具白名单；或 GitHub Action 做 PR 审查与 issue 分诊。
- 配置兜底：`security.disableYoloMode`、`blockGitExtensions`、`enablePermanentToolApproval: false` 写进企业管理模板。
- 跨工具一致性：GEMINI.md 与 CLAUDE.md、AGENTS.md 共用一份中立工程约束再 import，避免口径冲突。

## 11. 失败模式与修复

| 症状 | 根因 | 修复 |
|---|---|---|
| `--yolo` 不生效 | 已废弃或被 `security.disableYoloMode` 拦截 | 改 `--approval-mode yolo`，检查 settings |
| `--allowed-tools` 无效 | 已废弃 | 迁移到 Policy Engine |
| 免费额度耗尽 | 个人账号 1000/day | 换 API key 认证或等额度重置 |
| 命令找不到 `gemini` | 未安装/未入 PATH | `npm install -g @google/gemini-cli` |
| 编辑工具自作主张改内容 | `disableLLMCorrection` 默认 false | 设 true 强制精确匹配失败即报错 |
| 上下文文件未加载 | 改完未 reload | `/memory reload`；查 footer 加载计数 |
| MCP server 老配置不生效 | 配置改了没重启 | `/mcp reload` |
| worktree 启动失败 | 未开实验开关 | settings 加 `experimental.worktrees: true` |
| 沙盒里任务失败 | 沙盒限制网络/写入 | 按任务评估退出沙盒或开白名单，勿默认关沙盒 |
