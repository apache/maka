## 二、第一性原理：模型缺什么，harness 就是什么

剥离一切宣传，LLM 只有两件事可做：按上下文预测下一个 token、按协议发出结构化调用。它没有记忆、没有手、没有时钟、没有感官。所谓 **Harness（挽具）**，就是把这台无状态 token 机变成可持续干活的工作者所需的全部机器。

由此推出四个缺口，harness 的每个部件都在补其中一个：

```text
缺口① 执行：模型说"删除这个文件"，谁真去删，删错了算谁的 → 工具运行时/沙箱/权限
缺口② 状态：这一轮和上一轮之间，什么活下来了           → 上下文/压缩/记忆
缺口③ 感官：代码库有几万个文件，模型一次只能看几万 token   → 检索/repo map/LSP
缺口④ 缰绳：方向错了谁纠，什么时候纠                   → 审批/转向/评测
```

推文里那些名词——runtime host、异步工具、上下文压缩、memory、mid-turn steering、PTC/Code Mode——全部落在这四个缺口上。下面七条本质，是四个缺口加两条元规则的展开。

## 三、七条本质

**每条按"原理 → 判据 → 证据"展开。证据分三档：✅=我自己核验过；⚠️=单源说法，未核验；📚=有公开文档。**

### 1. 执行事实只能有一个权威

原理：会话状态、工具结果、执行记录的权威所有者必须唯一，且生命周期独立于任何进程与界面。这是高内聚低耦合的直接推论——**进程会崩，界面会换，事实不能跟着陪葬**。

判据：问一句"客户端能不能连别人部署的 server？"能，说明事实与进程解耦。

证据：推文指控 CC"一个 session 一个 bun、天天堆代码山"（⚠️ 闭源无法核验）；夸 Codex V2 用 app-server 统一 runtime——这条我核验了：codex-rs 里 `app-server` / `app-server-protocol` / `app-server-transport` / `app-server-daemon` 全家桶 crate 真实存在（✅）。Maka 同方向：Runtime Host 单一执行权威、事件日志为唯一事实、界面全是投影（✅ 本地读过 `docs/architecture/runtime-host-architecture.zh-CN.md`，推文作者推荐的正是这份文档）。opencode 的 client/server 架构同此理（📚）。

### 2. 延迟是 harness 的属性，不是模型的属性

原理：同步锁步的循环（模型想→工具跑→干等）把模型速度锁死在工具速度上。异步工具、非阻塞执行、**mid-turn steering**（任务进行中从 API 层插入新指令，不是 UI 层的"停下重说"）都是把等待时间还给推理。

判据：任务进行中能不能改需求而不废弃已跑的部分？

证据：Codex 的 `responses-api-proxy`、`async-utils` crate 与推文描述互证（✅ crate 存在；体验层的"快了很多"是 ⚠️ 体验报告）。对照：本目录 18 篇里多数工具的交互模型仍是"提交→等待→审"。

### 3. 上下文经济学：更短但更好

原理：上下文窗口是唯一硬稀缺资源。harness 的水平不看塞了多少，看三件事：什么该进来（检索）、什么该压缩（投影）、什么该沉底但**可召回**（回收）。

判据：删掉历史时，它是"被删除"还是"变成可查询的投影"？

证据：Codex 服务端压缩+可搜索历史（⚠️ 体验，但 `context-fragments` / `guardian-context` / `history` crate 佐证机制存在 ✅）；aider 的 repo map 是第③缺口的教科书答案（📚）；Maka 的"裁剪是投影不是删除"（✅）；crush 的 LSP 增强、gemini-cli 的 1M 窗口（模型侧暴力解）各是一条路线（📚）。

### 4. 记忆是写时纪律，不是读时魔法

原理：跨会话记忆的质量在**写入那一刻**决定——当时是否记成了结构化、可追溯、可撤销的事实。事后靠检索翻找堆成一山的聊天记录，检索越聪明幻觉越多。

判据：记忆条目能不能回答"谁在什么时候因为什么写下了这条"？

证据：Codex `memories` crate 存在（✅），"最少幻觉"是 ⚠️ 体验报告；Maka 的事件日志把这条推到极致——工具结果、终止方式全部落为不可变事实（✅）；CLAUDE.md/GEMINI.md 是最低配：人肉写时纪律（📚）。

### 5. 缰绳必须本地持有

原理：（推文未讲，补齐——缺它无法评判编排层。）执行侧的权限、沙箱、审批权必须留在用户机器与用户手里，否则①②做得越好，风险越大。

判据：越权的最后一道闸在谁的进程里？

证据：codex-rs 的 `execpolicy` / `sandboxing` / `linux-sandbox` / `windows-sandbox-rs` / `network-proxy`（✅）；Maka 沙箱+审批+中止（✅）；cline 的逐步审批（📚）。编排层工具只能加 review gate，管不到引擎内部——见第五节。

### 6. Harness 与模型共演化，或死于功能清单

原理：推文最重的一条。最好的 harness 是**照着某个具体模型的弱点设计的**，并与后训练互相校准（Codex 的 PTC/Code Mode 机器 + 后训练 = "真正的 Harness 和模型相互配合的典范"——`code-mode` 全家桶 crate 已核验 ✅）。反例是照竞品功能清单堆功能、协议设计不借鉴协议史——推文对 MCP 和 Plan mode"历史糟粕"的贬斥，方法内核就这一句。

判据：这个功能是模型能力的补集，还是发布会 PPT 的补集？

证据：注意分寸——MCP 已是行业标准（本目录 18 篇里过半工具接它），**取其方法，不取其结论**：协议设计必须随模型迭代重审，这一点对任何协议都成立。

### 7. 消融是唯一裁判

原理：奥卡姆剃刀 + YAGNI + 消融实验合成的裁决程序——一个功能存在，当且仅当**把它删掉、指标可测量地变差**。benchmark（Terminal-Bench、Maka 内建的 eval）替代宣传成为记分板；"A 家 infra 工程师特别多"这类论据在它面前无效。

判据：敢不敢把任何一套设计决策删掉跑分给你看？

证据：Maka 把 eval 做成一等公民（Experiment→Cell→Attempt，最早有效者权威，✅）；gemini-cli/qwen-code/goose/cline 仓库里都有 `evals/` 目录（📚）——这正在成为行业自觉；纯营销向证据（star 增速、大厂背书）在本框架里权重为零。
