## 0. 结论摘要

Cursor 已从"AI 增强编辑器"演化为**编辑器 + 终端代理 + 云端代理**三形态一体的工程平台。2026 年最大的变化是治理体系的补齐：CLI 更名为 `agent` 并获得独立安装、五类权限 token、Plan/Ask 双只读模式、持久化沙盒；编辑器侧则补齐了 skills、subagents、hooks、plugins 四大扩展体系。

核心治理面一览：

| 治理面 | 载体 | 一句话定位 |
|---|---|---|
| 项目规则 | `.cursor/rules/*.mdc` | frontmatter 控制加载时机，短、准、可提交 |
| 简单规则 | `AGENTS.md` | 纯 Markdown，支持嵌套，轻量替代 .mdc |
| 团队规则 | Team Rules（dashboard） | Team/Enterprise 统一下发，可 enforce 强制 |
| CLI 权限 | `~/.cursor/cli-config.json` / `<project>/.cursor/cli.json` | Shell/Read/Write/WebFetch/Mcp 五类 token，deny 优先 |
| 能力扩展 | Skills / Subagents / Hooks / Plugins / MCP | 单一职责、最小授权 |
| 安全底座 | Plan/Ask 只读模式 + sandbox + checkpoints | 见第 6 章 |

事实优先级（处理任何冲突时按此排序）：用户当次明确指令 > 当前源码与配置 > 真实接口与命令输出 > 官方文档 > 本手册 > 社区经验。

## 1. 定位与边界

### 1.1 Cursor 是什么

Cursor 是 AI 编程平台，2026-08 的形态矩阵：**IDE（编辑器内 Agent/Tab/Inline Edit）+ CLI（`agent`，终端代理）+ Cloud Agent（云端执行）+ Bugbot（PR 审查）+ SDK（TypeScript/Python/Bridge 嵌入）**。所有形态共享同一套规则（rules）、模型账户和 MCP 配置体系。

### 1.2 入口形态对比

| 形态 | 主要用途 | 优点 | 限制 |
|---|---|---|---|
| Cursor IDE | 日常编码、diff 审查、UI 迭代 | 编辑器上下文、跳转、checkpoints、浏览器验证 | 重交互，不适合无人值守 |
| CLI `agent` | 终端代理、脚本化、CI | 三模式切换、非交互 JSON 输出、权限 token | 需理解权限配置 |
| Cloud Agent | 消息前缀 `&` 交接，云端执行 | 异步长任务、跨设备接力 | 需要仓库权限边界 |
| Bugbot | GitHub PR 自动审查 | 与 CI 集成 | 以官方当前文档为准 |
| SDK | 把 agent 嵌入自有工具 | 程序化编排 | 待实测 |

### 1.3 适合与不适合的任务

| 适合 | 原因 | 验收方式 |
|---|---|---|
| 日常编码与组件迭代 | 编辑器内联 + 浏览器实时验证 | 截图、单测、E2E |
| 规则驱动的团队协作 | Project/Team Rules 分层命中 | 规则命中稳定、diff 风格一致 |
| 终端批处理任务 | `agent -p` 非交互 + JSON 输出 | 命令可复现、退出码可判 |
| 陌生代码库只读分析 | Plan/Ask 模式物理隔离写操作 | 输出入口、风险、验证命令 |
| 敏感外部系统写操作 | 低——MCP 与 shell 需审批 | 只读优先，人手执行写操作 |

## 2. 核心工作模型

Cursor 的代理有三种模式，构成"执行 — 规划 — 只读"的安全梯度：

| 模式 | 进入方式 | 权限 | 典型用途 |
|---|---|---|---|
| Agent（默认） | 直接启动 | 按权限配置执行 | 写代码、跑测试 |
| Plan | `Shift+Tab` / `/plan` / `--mode=plan` | 只读，先出方案再执行 | 改造方案、任务拆解 |
| Ask | `/ask` / `--mode=ask` | 只读探索 | 代码问答、架构理解 |

治理三支柱：**规则（决定 AI 知道什么）+ 权限（决定 AI 能做什么）+ checkpoints（决定做错了怎么回退）**。checkpoints 是会话级快照，适合临时回退；长期版本管理仍以 Git 为准。

### 3.6 Cloud Agent 交接与脚本化

- 消息前缀 `&`：把当前对话交给 Cloud Agent 云端执行，终端可关闭。
- sudo 提权：需要密码时走独立 IPC 通道，**密码对模型不可见**。
- CI/脚本化：`agent -p "任务" --output-format json`，配合权限配置（§6）约束写行为；GitHub Action 集成见官方 `docs/cli/github-actions.md`（待实测）。

### 4.3 Git 策略

- 提交：`.cursor/rules/`、`.cursor/mcp.json`（脱敏后）、`.cursor/cli.json`、`AGENTS.md`。
- 不提交：`~/.cursor` 下的一切运行状态；`projects/`、`plans/`、`ai-tracking/`。
- checkpoints ≠ Git：checkpoint 是会话快照，用于即时回退；里程碑必须落 Git。
- Worktree：官方提供 `docs/configuration/worktrees.md` 能力（待实测），多任务并行改造时可与 Git worktree 组合。

## 5. 规则与配置治理

### 5.1 四类规则与优先级

| 规则类型 | 位置 | 提交 | 特点 |
|---|---|---|---|
| Project Rules | `.cursor/rules/*.mdc` | 建议 | frontmatter 控制加载，必须 `.mdc` 扩展名 |
| AGENTS.md | 项目根 + 任意子目录 | 建议 | 纯 Markdown 无元数据，嵌套文件自动叠加，更具体的优先 |
| User Rules | Settings → Rules | 不提交 | 个人全局偏好，仅作用于 Agent（Chat），不作用于 Inline Edit（Cmd+K） |
| Team Rules | Cursor dashboard | 管理员管理 | Team/Enterprise 下发，优先级最高，可 Enforce 强制不可关 |

优先级合并顺序：**Team Rules → Project Rules → User Rules**，前者胜出；`.md` 放在 `.cursor/rules/` 会被忽略（无 frontmatter），纯 Markdown 需求请用 AGENTS.md。

### 5.2 .mdc frontmatter 真值表（官方核验）

| alwaysApply | description | globs | 行为 |
|---|---|---|---|
| `true` | — | — | 每次会话都加载（后两者被忽略） |
| `false` | — | 提供 | 文件匹配时自动挂载（auto-attach） |
| `false` | 提供 | 省略 | Agent 依据 description 判断相关性智能加载 |
| `false` | 省略 | 省略 | 仅 @mention 手动加载 |

glob 示例：`src/**/*.tsx`（src 下所有 tsx）、`docs/**/*.md, docs/**/*.mdx`（逗号分隔多模式）、`tailwind.config.*`。

### 5.3 规则生命周期

- 生成：会话内 `/rules` 或 `/create-rule` 让 Agent 生成带 frontmatter 的规则文件；也可 Customize → Rules → Add Rule。
- 导入：Remote Rules 从 GitHub 仓库拉取 `.mdc` 到 `.cursor/rules/imported/<repoName>/`。
- 团队：dashboard 创建 Team Rules，勾选 Enforce 后成员不可关闭；支持 glob 限定作用文件。

### 5.4 官方最佳实践与反模式

- 单条规则 < 500 行；大规则拆分为可组合的小规则。
- 引用文件（`@template.tsx`）而非复制内容，避免规则随代码腐化。
- 反模式：整抄 style guide（用 linter）、枚举所有命令（Agent 已知 npm/git/pytest）、覆盖罕见边界情况。
- 起步策略：只在 Agent 反复犯同一错误时才加规则，先简单后迭代。

## 6. 权限与安全

### 6.1 CLI 权限 token（官方核验）

配置位置：全局 `~/.cursor/cli-config.json`，项目 `<project>/.cursor/cli.json`。结构：

```json
{
  "permissions": {
    "allow": [
      "Shell(git)",
      "Shell(npm)",
      "Read(src/**/*.ts)",
      "Write(src/**)",
      "WebFetch(docs.github.com)",
      "Mcp(datadog:*)"
    ],
    "deny": [
      "Shell(rm)",
      "Read(.env*)",
      "Write(**/*.key)",
      "Write(**/.env*)",
      "WebFetch(malicious-site.com)"
    ]
  }
}
```

五类 token 语法：

| 类型 | 格式 | 示例 |
|---|---|---|
| Shell 命令 | `Shell(commandBase)`，支持 `command:args` | `Shell(git)`、`Shell(curl:*)`、deny `Shell(rm)` |
| 文件读 | `Read(pathOrGlob)` | `Read(src/**/*.ts)`、deny `Read(.env*)` |
| 文件写 | `Write(pathOrGlob)` | `Write(src/**)`、deny `Write(**/*.key)` |
| 网络抓取 | `WebFetch(domainOrPattern)` | `WebFetch(*.github.com)`，`*` 全放行（慎用） |
| MCP 工具 | `Mcp(server:tool)` | `Mcp(datadog:*)`、`Mcp(*:search)` |

规则要点：**deny 恒胜 allow**；glob 支持 `**` `*` `?`；相对路径基于当前 workspace；`-f/--force` 强制放行未被显式 deny 的命令。

### 6.2 沙盒与提权

- `/sandbox` 或 `--sandbox enabled|disabled`：沙盒与网络访问配置，持久化跨会话（官方 run-modes 文档细节待实测，2026-08-26 拉取时 429）。
- sudo 密码经独立 IPC 通道传递，模型不可见。
- `-p` 非交互模式默认拥有写文件与 bash 全工具——CI 中必须用 `cli.json` 的 deny 列表收窄。

### 6.3 编辑器侧安全

- MCP server 安装前审查来源、权限、密钥范围与日志。
- Agent 任务开始前声明允许改动的目录与禁触文件。
- 团队合规：Team Rules 可作为内部合规一环，但官方明确"AI 引导不应是唯一安全控制"。

## 7. 提示词与上下文技巧

| 技巧 | 适用场景 | 具体做法 |
|---|---|---|
| Plan 先行 | 多文件改造 | 先 `/plan` 出方案与人审，批准后再切 Agent 执行 |
| 模式隔离 | 陌生库调研 | `/ask` 只读问答，避免误触写操作 |
| 上下文压缩 | 长会话 | `/compress` 压缩历史释放窗口 |
| max-mode | 高难任务 | `/max-mode on` 用更强推理档 |
| 规则化纠正 | 反复出错 | 第三次纠正同一错误即沉淀为 .mdc 规则 |
| @ 引用 | 精确上下文 | 对话中 @ 文件/目录/规则名精确投喂 |
| Cloud 交接 | 跑长任务 | 前缀 `&` 交给云端，本地继续别的活 |
| 手动规则 | 低频高风险 | 无 description/globs 的规则仅 @mention 加载，避免常驻 |

### 7.1 Prompt 模板（三则）

只读分析：

```txt
请只读分析当前项目。不要创建、修改、删除文件，不要安装依赖，不要提交代码。
先列出你会读取的文件类型，再输出技术栈、入口、目录职责、风险点和建议验证命令。
涉及配置和凭据时只输出字段类别，禁止输出具体密钥值。
```

最小改动（配 Plan 模式）：

```txt
请按 Read、Plan、Execute 三阶段处理。Plan 必须包含文件白名单、测试策略、验收点、回滚点和风险。
在我确认前不要修改文件。确认后只改白名单文件，先补失败测试，再做最小实现。
交付时说明真实执行过的验证命令和未验证事项。
```

规则沉淀：

```txt
请把这次任务中可复用的经验沉淀为 .cursor/rules 下的项目规则（.mdc 格式，含 frontmatter）。
只保留高频、明确、可执行的规则。每条规则说明触发场景、禁止事项、验证方式和维护位置。
不要把一次性背景、会话记录、密钥、临时路径写入规则文件。
```

## 10. 企业级工作流

### 10.1 标准闭环

```txt
目标澄清 -> 只读盘点(/ask) -> 方案(/plan) -> 授权执行(Agent) -> 测试验证 -> diff 审查 -> 文档沉淀 -> 规则更新(.mdc)
```

| 阶段 | 关键动作 | 交付物 |
|---|---|---|
| Read | `/ask` 盘点 README、package、配置、入口、测试 | 项目地图和风险清单 |
| Plan | `/plan` 出最小方案、文件白名单、验收点、回滚点 | 可确认的执行计划 |
| Execute | Agent 只改白名单文件，先测试后实现 | 最小 diff 和验证结果 |
| Review | 按严重度检查行为、安全、性能、测试缺口 | 可追踪 findings |
| Retrospective | 高频纠正点沉淀为 .mdc / skill / Team Rule | 规则更新记录 |

### 10.2 团队治理组合

- 规范统一：Team Rules（可 enforce）+ 项目 `.mdc` + 嵌套 AGENTS.md 三层分工。
- 代码质量：Bugbot 做 PR 自动审查（与 CI 集成）。
- 无人值守：`agent -p` + `cli.json` deny 列表 + `--output-format json` 退出码判定。
- 跨工具一致性：与 CLAUDE.md/GEMINI.md 共用一份中立工程约束文档再各自引用，避免口径冲突。

## 11. 失败模式与修复

| 症状 | 根因 | 修复 |
|---|---|---|
| 规则从不生效 | `.md` 放进 `.cursor/rules/`（被忽略） | 改 `.mdc` + frontmatter，或用 AGENTS.md |
| "智能加载"规则不命中 | description 缺失或过泛 | 写清触发场景关键词 |
| auto-attach 不触发 | globs 与实际路径不匹配 | 校验 glob，多模式逗号分隔 |
| `cursor-agent` 命令找不到 | CLI 已更名 `agent` | 重装：`irm 'https://cursor.com/install?win32=true' \| iex` |
| CI 中 agent 越权写文件 | `-p` 默认全工具且无 deny | 项目 `.cursor/cli.json` 配 deny 列表 |
| MCP server 反复失败 | OAuth 过期或命令路径错 | `agent mcp list` 查状态，`agent mcp login <name>` 重认证 |
| 会话上下文溢出 | 长会话未压缩 | `/compress`，或 `/new-chat` 重建 |
| 误依赖 checkpoint 回退 | checkpoint 是会话快照 | 里程碑必须 Git 提交 |
