# Go 开发最佳实践（对照 magpie 与个人项目审计）

日期：2026-10-10
依据：
- `fork/magpie` @ `e7279e0d`（只读参考）；
- 七个自研 Go module 的审计与修复，提交 `e7149f2`、`5e428d0`、`0fe088f`（liliya），`a9164c5`、`c478138`（coding-agent），`69d958c`（lang-go）；
- Go 官方资料：[Effective Go](https://go.dev/doc/effective_go)、[Code Review Comments](https://go.dev/wiki/CodeReviewComments)、[Race Detector](https://go.dev/doc/articles/race_detector)、[net/http Server.Shutdown](https://pkg.go.dev/net/http#Server.Shutdown)。

适用范围：GuaHub 下的个人 Go 项目。子项目自己的 AGENTS.md 优先。本文只收录有真实证据的规则，每条写明“规则、原因、证据”。

## 0. 总原则（先读这一节）

1. **先跑通再收紧。** 新项目的门禁只要求 `go build ./...`、`go vet ./...`、`go test ./...` 和 `gofmt -l`。lint 采用增量门禁，存量问题不清零。
2. **修 bug 先写失败测试。** 测试只用标准库（`testing`、`httptest`、`t.TempDir`、`t.Chdir`、`t.Context`），把旧代码上的失败输出写进提交说明。
3. **一次提交一个目标。** 提交说明写可观察的行为变化，并附两行交付说明：“已跑 X（结果）；未跑 Y（原因）”。
4. **按顺序考虑：** 正确性和安全 → 资源与并发 → 性能（必须有测量依据）→ 风格（最后处理，可以不做）。
5. **不为统一风格引入东西：** 不加框架，不写只有一个实现的接口，不重组目录，不新增 testify、samber、goleak 这类依赖。

## 1. 路径与边界判断（安全类，最常见的真实缺陷）

| 规则 | 原因 | 证据 |
|---|---|---|
| 判断路径是否在某目录内，用 `filepath.Rel` 后检查 `rel != ".." && !strings.HasPrefix(rel, ".."+sep)`，或者用 `HasPrefix(p, dir+sep)`。**不能裸用 `HasPrefix(p, dir)`** | `filepath.Clean("./upload")` 的结果是 `upload`，裸前缀会放行同级的 `upload.go`、`uploadX/`，以及目录本身 | liliya `upload.go` 下载接口泄露源码，修复见 `e7149f2` |
| 越界判定的两侧都要先 `filepath.EvalSymlinks`。目标文件不存在时，解析最近的已存在祖先目录；悬空链接按越界处理 | `filepath.Abs` 只做字面归一化，白名单目录里一个指向外部的链接，就能让写入免确认落到白名单外 | coding-agent `pathguard.go`，修复见 `c478138` |
| 也不能裸用 `HasPrefix(rel, "..")` | 会把 `..foo/` 这种合法目录名误判为越界 | 同上 |
| 逗号分隔的 ID 列表字段用 `FIND_IN_SET`，不用 `LIKE 'prefix%'` | `0,100,101%` 也会匹配 `0,100,1015`，数据权限范围被扩大 | liliya 的 `ResolveDataScope`，修复见 `0fe088f`，写法与上游 RuoYi `DataScopeAspect` 一致 |

**测试注意：** 断言“被拒绝”时，不要只检查 body 里有没有错误文案。被下载的源码里本身就含有这段文案，测试会假通过。还要同时断言没有 `Content-Disposition` 头。

## 2. 错误处理

- **只用 `%w` 包装错误**，调用方用 `errors.Is` / `errors.As` 判断。magpie 全仓库有 222 处 `%w`、232 处 `errors.Is`。
- **哨兵错误**用包级变量 `var ErrX = errors.New(...)` 定义，例如 magpie 的 `internal/davsync/lock.go:13`。错误消息写一句话，不要像 `internal/mcpauth/mcpauth.go:73` 那样写成整段说明。
- **只在边界上处理一次错误：** 在顶层用 `errors.As` 把错误映射成退出码（magpie `main.go:167`）。中间层只包装、只返回，不要既打日志又返回。
- **服务关闭不算错误：** `errors.Is(err, http.ErrServerClosed)` 应视为正常退出（magpie `internal/gateway/gateway.go:466`）。
- **这些错误不能吞：**
  - 读取请求体失败时，要立即中止，不能拿已读到的部分字节继续处理（liliya LESSONS：`GetRawData`）。
  - `io.ReadAll` 可能同时返回已读数据和错误，要检查错误（coding-agent `webfetch`）。
  - 输出失败（`fmt.Fprint*`）要从 `Run` 返回（lang-go `irinterp`）。
  - 多层的生成或转译代码，要把每一层的错误都传上去（lang-go `genjs`）。
  - GORM 的 `.Scan(...)` / `.Pluck(...)` 要检查 `.Error`。旧代码吞掉这个错误后会静默退化成空结果，见 liliya `auth_guard.go`。
- **可以忽略的错误：** 尽力而为的清理，比如 `_ = os.Remove(tmp)`，可以忽略，但要显式写出 `_ =`。
- **写文件的 `Close` 错误不能吞：** magpie `build/icon/gen.go:70` 的 `defer f.Close()` 就丢了这个错误，不要照抄。

## 3. context、取消与超时

- **起子进程一律用 `exec.CommandContext(ctx, ...)`。** 工具函数的签名里拿到了 ctx，就不能写成 `_` 丢掉。取消后要返回“已中止”，不要返回跑完的结果。证据：coding-agent `rg.go`，修复见 `a9164c5`。
- **超时要从调用方的 ctx 派生**，写成 `context.WithTimeout(parent, d)`。magpie 在 `quota_wait.go:279` 是对的；在 `main.go:284`、`usage_cli.go:33`、`accounts_cli.go:258` 是从 `context.Background()` 起的，Ctrl+C 取消不了，这是反例。
- **HTTP 请求用 `http.NewRequestWithContext`，并且 `defer resp.Body.Close()`。** DNS 查询用 `net.DefaultResolver.LookupIPAddr(ctx, …)`，不要用不带 ctx 的 `net.LookupIP`。
- **CLI 入口用 `signal.NotifyContext`** 把信号转成 ctx（magpie `signals.go:91-95`）。
- **优雅关停的写法**（适合长驻 HTTP 服务；纯教学 lab 可以暂缓）：

```go
srv := &http.Server{Addr: addr, Handler: h, ReadHeaderTimeout: 10 * time.Second}
ctx, stop := signal.NotifyContext(context.Background(), os.Interrupt, syscall.SIGTERM)
defer stop()

go func() {
	<-ctx.Done()
	c, cancel := context.WithTimeout(context.Background(), 5*time.Second)
	defer cancel()
	if err := srv.Shutdown(c); err != nil { // magpie gateway.go:460 忽略了这个返回值，不要照抄
		log.Printf("shutdown: %v", err)
	}
}()

if err := srv.ListenAndServe(); err != nil && !errors.Is(err, http.ErrServerClosed) {
	return err
}
```

这个写法参考 magpie `internal/gateway/gateway.go:450-469` 的关停顺序。gin 项目把 `r.Run(addr)` 换成 `http.Server{Handler: r}`，再按上面的方式关停。

## 4. 并发与 goroutine

- **从 handler 能访问到的跨请求共享 map 或切片，必须加锁。** gin 每个请求一个 goroutine，并发写 map 会触发 `fatal error: concurrent map writes`，而且无法 recover。证据：liliya 调度器的 `ids`，修复见 `5e428d0`。
- **锁要覆盖整个“读改写”操作**，比如“移除旧条目再注册新条目”要在同一段锁内完成。不要只锁其中一步。
- **锁的粒度是一次 Write，而不是整段 Copy。** 锁住整段 Copy 会让轮询方一直等到管道关闭（coding-agent 冒烟测试的采集器）。
- **全量 `go test -race ./...` 通过不代表没有竞态。** 要有测试真正并发地走到共享状态那条路径。上面 `5e428d0` 的问题，此前全量 `-race` 一直是绿的。
- **goroutine 都要有明确的退出路径**（ctx、done channel、`WaitGroup`）。并发分支用 `sync.WaitGroup.Go`（Go 1.25 起可用）。
- **不要学 magpie 的这几处：**
  - `gateway.go:447` 的 `go f(ctx)` 从不 join；
  - `internal/gui/dev_on.go:171-176` 重复调用 Shutdown；
  - `internal/provider/signin.go:584-590` 用 sleep 等对方退出。

## 5. 测试

- **用表驱动测试，子测试名要能读懂。** HTTP 接口用 `httptest.NewRecorder` 加 `router.ServeHTTP`，不要真起服务、抢端口。“先 listen、再 close、再把端口交给 `main()`”的写法存在竞争。
- **测试隔离：**
  - 用 `t.TempDir()`、`t.Setenv()`、`t.Chdir()`（会自动恢复）。
  - 用 `t.Setenv` 或 `t.Chdir` 的测试不能 `t.Parallel()`，要写 `//nolint:paralleltest // 原因`。
  - magpie 有 3171 处 `t.Setenv`，却只有 1 处 `t.Parallel`。更好的做法是把配置以参数形式注入，而不是改环境变量。
- **依赖外部服务**（MySQL、rg、node）时，探测不到就 `t.Skipf("原因")`。跳过要如实报告，不能算作通过。
- **数据库测试只用自己的数据。** 它们只增删自己插入的行（比如用 ≥ 90 的 ID），绝不删除种子数据。liliya 的 `TestResolveDataScope` 清理时会删掉种子部门 100/101，是反例。验证用临时容器：

```sh
docker run -d --rm --name tmp-mysql -p 127.0.0.1:13306:3306 \
  -e MYSQL_ROOT_PASSWORD=password -e MYSQL_DATABASE=ry \
  -v "$PWD/sql/seed.sql:/docker-entrypoint-initdb.d/seed.sql:ro" mysql:8
```

- **期望值要来自独立的事实来源**（种子数据、上游实现、规格），不要从被测代码的输出里复制。
- **多执行路径的项目**（解释器、编译器、IR）要用同一个程序同时验收所有路径。只在“编译”这一路出现的问题（比如 Go 的 `declared and not used`），解释器测不出来。证据：lang-go 修复 `69d958c`。

## 6. lint 与 CI

- **工具版本固定为 golangci-lint v2.14.0**（本机 `~/go/bin/golangci-lint`）。CI 里写 `version: v2.14.0`，不要用 `@latest`。
- **配置用 v2 结构：** `version: "2"`、`linters.settings`、`linters.exclusions`、独立的 `formatters`。修改后先跑 `golangci-lint config verify`。弃用的键要先查对应版本的文档，确认语义等价后再替换。
- **增量门禁：**
  - PR 用 `only-new-issues: true`。
  - 推送或回退时，用 `new-from-rev: <采纳基线 commit>`。
  - `working-directory` 指向 module 目录。
  - Go 专属的步骤要加 `if: matrix.lang == 'go'`，不要拖慢或影响其他语言的 job。
- **注意“改行即新增”：** 你改动了某一行，这一行上原有的存量 lint 问题也会被当作新问题。要么在同一提交里顺手修掉（比如参数改名），要么写一条带原因的 nolint。
- **gosec 要逐条人工判断。** 误报写 `//nolint:gosec // 原因`。已知的技术债（比如为兼容 RuoYi 用的 MD5）也写 nolint 并注明原因，不要假装已修复。
- **不要批量清零的类别：** wsl_v5、revive、asciicheck、paralleltest。它们只在被改动的行上处理。纯空白风格的修改单独成一个提交，最后再做。
- **本地自检顺序：**

```sh
go build ./... && go vet ./... && go test ./... && gofmt -l .
~/go/bin/golangci-lint run --new-from-rev HEAD ./...      # 本次改动是否引入新问题
go test -race ./<含并发的包>/...                           # 只对并发路径跑 race
```

- **magpie 的 CI 值得借鉴的地方：**
  - `go-version-file: go.mod`（`test.yml:29-33`）；
  - 只对并发包定向跑 race（`test.yml:90-97`）；
  - `permissions: contents: read`，以及非 main 分支取消进行中的旧运行（`test.yml:12-16`）。
- **magpie 的 CI 不适合直接照搬：** 它没有 golangci-lint，只跑 gofmt 和 vet。我们现有的增量 lint 门禁比它强。

## 7. 结构与风格

- **单包平铺可以接受**，比如 liliya 的 5.5k 行。只有当两个领域开始互相调用对方的内部实现时，才拆出第一个 `internal/<domain>`。
- **注释只写代码表达不了的约束：** 为什么要加锁、为什么不能并行、兼容的是哪个上游。注释不要提任务或 PR。
- **删除优先：** 遇到死代码就删。例如 `string([]rune)` 的结果一定是合法 UTF-8，之后再做 `utf8.ValidString` 回退就是死代码。
- **不要遮蔽内置标识符：** 参数不要叫 `cap`、`len`、`real` 这类内置名。

## 8. 采纳清单（新项目或接手项目时逐项检查）

- [ ] `go build ./...`、`go vet ./...`、`go test ./...`、`gofmt -l .` 全绿
- [ ] `.golangci.yml` 为 v2 结构且 `config verify` 通过；CI 门禁只拦新增问题
- [ ] 所有路径边界检查都带分隔符，并解析了符号链接
- [ ] 子进程、HTTP 请求、DNS 查询都带 ctx；超时从调用方 ctx 派生
- [ ] handler 能访问到的共享状态都有锁，并有对应的并发 race 测试
- [ ] 长驻服务用 `http.Server` 并设置 `ReadHeaderTimeout`、实现优雅关停（lab 可以暂缓）
- [ ] 数据库测试不删种子数据；外部依赖缺失时 skip 并在交付说明里如实报告
- [ ] LESSONS.md 按“规则＋原因＋证据＋Seen N×”记账；同一条在 3 个不同日期重现，升格为 AGENTS 必查项

## 9. 暂缓或不做

- 优雅关停和服务超时：个人 lab 收益很低，等项目长驻部署时再加。
- lint 存量清零：增量门禁已经挡住新问题，存量清零的成本远大于收益。
- 测试改为并行：先把依赖环境变量的配置改为注入，才谈得上并行。
- errgroup、goleak：现有的 `WaitGroup` 加 ctx 已经够用，不新增依赖。
