## 硬约定

- Multica License（source-available）——代码可读可改，PR 照常。
- SQL 改动要 `make sqlc`——尽量不接 SQL 单。
- **很多集成测试需要 Docker Postgres**：数据库不可达时测试 `t.Skip("database not available")`，本机没起 DB 时这类测试是 skip 不是绿（#8935 教训）。2026-11-07 对 clone 实读：skip 写在各测试的取夹具处（如 `server/internal/testutil/db_test.go:82`，约 171 个测试文件），`testutil/db.go` 本身不含 Skip。
- **DB-backed 单本机可验（2026-10-04 起）**：用本地 `postgres:16` 容器 + `cd server && DATABASE_URL=... go run ./cmd/migrate up` 自建测试库，配方见 [02 文末「本机 DB 验证环境就绪」](02-本机环境坑.md#本机-db-验证环境就绪2026-10-04) 与 [05-维护任务书](05-维护任务书.md) 验证节；验证时确认目标测试真连上 DB、没有被 skip。
- （校注 2026-11-07：本条原文为「很多集成测试需要 Docker Postgres——本机不可验（Windows 时代无 Docker；mac 10-02 起 Docker Desktop 起不来）……只接纯单元可验的单；DB-backed 测试的单接不了」，是 2026-10-02 Docker Desktop 故障期的结论，10-04 起已过时，[04 §2](04-实战经验移植.md#2-交付纪律自-magpie-5-蒸馏tdddiagnosing-bugs-skill-同源) 早有同样说明。原文见 cc 仓提交 dbdf77a4。）

## 接单开场固定流程

通用过程见 Skill `gua-pr-patch`（接手与排雷 `references/workflow.md` §1-§2，交付 `references/delivery.md`）；本仓验证矩阵以本仓任务书为准；本仓 fetch upstream main，先查在途合并、评论、mergeable 与占坑，再开新单。报告者贴 patch 永不开 PR 的单可接（optimi-bot 先例），但 patch 必须逐字核对基线 + 自己跑红绿。
