## Windows + Git Bash（2026-09~10-02 实测；mac 迁移后未再核验）

- `go test -p 2` 防编译器崩；gofmt CRLF 判定用临时文件法（`tr -d '\r' < file > tmp && gofmt -l tmp`，tmp 用仓库外绝对路径）（2026-09-30，MC-4）。
- symlink/junction 测试在 Windows 是优势环境：Hermes home 类单本机可真实复现；junction 误判拷贝的断言缺陷已修过（`linkedTo` 助手先例，MC-1，2026-09-28）。
- 前端依赖已装好（node 22 via fnm）；cd 进仓触发 fnm 钩子截断 `&&` 链，先 eval 或用 git -C（2026-09-29，让坑单实测）。
- 本机 `internal/daemon` 约 63 个 Windows 预存失败（2026-09-30 与 upstream/main 基线逐一对照实测；旧记录 27 已过时）——验证用基线 worktree 一一比对定性，CI Linux 不受影响。
- rg 用 `/e/` 风格路径+glob 偶发返回空结果（Windows 风格路径正常）——下"无匹配"结论前必须换路径形式复测，否则违反 M1（2026-10-01，扫描沉淀）。
- python 写 `/tmp` 与 Git Bash 的 `/tmp` 不同盘，跨工具 JSON 载荷一律用显式 `C:/Users/...` 路径（2026-10-01，扫描沉淀）。

### 本机 DB 验证环境就绪（2026-10-04）

Docker Desktop 恢复后：**compose 的 pgvector 镜像仍拉不动（Docker Hub TLS 超时）**，但 migrations 零 pgvector 依赖——用本地已有 `postgres:16` 手动起容器绕过 ensure-postgres.sh（它 is_local 时无条件 compose up），`cd server && DATABASE_URL=... go run ./cmd/migrate up` 全量 1178 文件成功。红绿实证补齐：#9039 本机绿（3/3）+ worktree 修前红；#9019 本机绿（2/2）+ worktree 修前红 + 修正后 CI 绿。
**M4 假绿大课**：#9019 的守卫测试漏抄先例的"parent 置 failed"步骤——parent 仍占 (issue_id,agent_id) 部分唯一索引，retry 撞 ON CONFLICT DO NOTHING 得 ErrNoRows，**断言在无守卫的 main 上也绿**。worktree 修前红跑（拷主工作树最新测试文件，注意 `git show branch:path` 只给 HEAD 提交版、未提交的修改不在内）暴露假绿，补置 failed 后基线红（got <nil>）守卫绿。教训入 03-失败模式 M4：**守卫类测试必须做"基线必红"实证，只看守卫侧绿不算数**。
