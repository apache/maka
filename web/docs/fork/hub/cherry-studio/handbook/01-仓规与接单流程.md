## 硬约定

- **DCO 强制**：每次 `git commit -s`（身份 ggbdpq <ggbdpq@gmail.com>）。
- **"无测试的功能视为不存在"**：改动必带测试；bot 的 Local validation 会跑 frozen changed-test targets 预检。
- **bot 每次推送复审**（2026-11-07 按 [04-维护任务书](04-维护任务书.md)「审查方与处置口径」校正）：原文写「cherry-ai-bot 每次推送复审」，该 bot 已不活跃（journal 中最后一次活动记录为 2026-10-10，见 [卷01](../journal/卷01.md) #21358 更正节；04 于 2026-10-28 迁入时已注明），现行深审由 `cherry-pr-review` 承担，报告在 `cherry-review` check run 的 output，口径以 04 为准。仍适用：CHANGES_REQUESTED 必须逐条处置（修或给证据回复）；bot 意见先核实再动手（v1 方案被 bot 判 blocking 后迭代 v2 的先例：#21214）。
- preference 类改动：key 定义在 `target-key-definitions.json`，跑 `generate-preferences.js` 生成 `preferenceSchemas.ts`（DB preference 表是通用 key-value，无迁移）。
- 代码注释英文（改到中文注释顺手翻译）。
- `usePreference` hook 不区分「未加载/无存储值」两态（都返回 schema 默认值）——需要区分时直用 PreferenceService 单例有先例（sidebarShortcuts）。
- 与平台无关、但目前只记在 [02 本机环境坑](02-本机环境坑.md) Windows 历史节的两条仍适用（2026-11-07 引用）：验证矩阵（改动文件测试 + 相邻套件 + `pnpm typecheck` + 改动文件 oxlint/eslint）；API 开 PR 的 `head` 字段必须带 `ggbdpq:` 前缀（裸分支名静默 422，#21220）。
