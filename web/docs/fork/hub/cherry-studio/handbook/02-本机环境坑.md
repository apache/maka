## 本机环境坑（Windows + Git Bash，已实测）

> **Windows 已退役（历史）**：本节为 Windows + Git Bash 时代的实测记录，主力环境已转 macOS，未在 macOS 上再核验，仅作历史参考（2026-11-07 标注）。其中与平台无关的验证矩阵、API `head` 前缀两条已在 [01 硬约定](01-仓规与接单流程.md) 引用。

- cd 进仓触发 fnm 钩子截断 `&&` 链：先单独 `eval "$(fnm env)" 2>/dev/null`。
- integration 测试 SIGABRT 偶发预存 flaky（基线 5/5 对照定性过）——失败先基线对照，预存在 PR 声明 CI 为准，别为它改正确语义。
- `general-test` job 的 ci.yml 变更过滤器漏了 packages/ui：纯 UI 包 PR 该 job 恒 skip/偶标 failure（steps=0 无日志）——预存编排边界，PR 正文声明即可，实际质量门是 renderer 5 分片 + package-test。
- 验证矩阵：改动文件测试 + 相邻套件 + `pnpm typecheck`（四项目）+ 改动文件 oxlint/eslint。
- API 开 PR 的 `head` 字段必须带 fork 前缀 `ggbdpq:<branch>`，裸分支名会静默 422 空响应（#21220 实录）——空响应先查这个。
