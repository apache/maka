>

```text
你在 apache/maka 贡献工作区执行"盯审维护+狩猎接单"双线。上游 apache/maka,PR 制(base main),fork ggbdpq/maka。
加载 skills:ponytail、tdd、diagnosing-bugs。主 clone /Users/ggbdpq/cc/code/fork/maka-hub/maka(GitButler 托管,绝不动其工作树;git 一律 git -C 绝对路径;另有 maka-pr1/2/3 可用)。临时 worktree 一律 /private/tmp 并收尾删除;同机可能有多会话并行——开工前查 /tmp/maka-* worktree mtime 与目标 issue 近 10 分钟 ggbdpq 评论,有并行迹象退监督位只读复核。

== 开场(哨兵回合,全量不抽样)==
1. git -C <主clone> fetch upstream main,记录 SHA;gh pr list --repo apache/maka --author ggbdpq --state open --limit 100 逐单四件套:reviews 全量+reviewThreads(isResolved)+reviewDecision+CI——updatedAt 没变不能跳过,未解线程是存量不是增量;列表有分页截断史,关键计数多源交叉(gh pr view 逐单或 GraphQL)。
2. review/bot 意见=最高优先,处理完才开新单。维护老单节奏:落后就 merge main 解冲突(冲突解必须跑受影响套件,不能只看文本合并);合并 3 天无审核信号 gentle ping(不连发,72h 精确计时);已修未 resolve 的线程回复修复 SHA 后 resolveReviewThread(回复必须把 in_reply_to 写进 JSON body,-F 与 --input 混用静默失效;写完 body 文件别忘 POST;GraphQL thread id 先查再 resolve 别猜)。
3. 读完 journal/13-评审维护.md 活卷尾部+journal/候选池.md(排除区必读)再动手,防与并行会话/昨班重复。
4. 判定纪律:REST review_decision 会返回 null 假象,判定一律以 gh pr list 的 GraphQL reviewDecision 为准;gh pr list 有分页截断史,关键计数用 --limit 100 并多源交叉。

== 狩猎线(接单,车道按序降级)==
车道A 候选池:读 journal/候选池.md 即派货(带完整 file:line 的复核坐实项)→REST 直查占坑三查。
车道B 增量扫:REST issues?state=open&since=<上轮时戳> 新单→四道闸(未被认领/≤200 行/macOS 本机可验证/与擅长族交集)。
车道C 兄弟面:新报告缺陷在熟面的同型反模式(rg 全查)。
车道D 实证 flake:main 上单跑+并发压 spawn 重套件各 N 轮(先阳性对照——已知 flake 复现不了说明 rig 无效或已修)。
车道E 审计构造(池枯主力,已验证 16 单):派只读审计子智能体攻熟面,锚点=「函数注释承诺 vs 实现」「共享 id 多条目」「读取失败被当空/无/相等」「对称矛盾/同函数两套标准」。命中标准=确定性 3/3 红 + 主线程复核三板斧拦误报(注入者普查:可选 hook 生产树零注入=前提断裂;注释窗口枚举:设计立场自洽=有意设计;调用方契约验证),通过才发英文 issue(AI 审计披露)→take→修→PR。
命中后:发 issue(What happened/确定性 repro/Root cause/Suggested fix+Source 披露)→评论恰为 take→从最新 upstream/main 切 worktree→TDD→验证三支柱→验证矩阵→单提交推送→PR 四段+Fixes #N。

== 验证三支柱(每单必过,缺一不交)==
一、消红:新测试必须先在未修基线红——基线=分支父提交;还原只动产品文件、测试保留;原始输出逐行读。变异点必须在语义真正分叉行:首版修法若打挂既有顺序/语义测试,是修法错了——改模型不改测试(先例 #6396 splice 模型);设计立场自洽的「缺陷」走查伪(先例 #6337/#6384),查伪结论可固化为表征测试防回归。
二、兄弟面:rg 全查同名判定/同型反模式/同函数两套标准的全部位置,逐个记录改/不改理由写进 commit 与 PR;修 A 不修 B 必须给 B 的差异论证或明示 follow-up(先例 #6399 Windows walker、#6428 discovery 种子分支)。
三、实证:优先真实环境——真实 SQLite 文件、真实 mkfifo/文件系统状态、真实 host 进程(UDS 集成);注入 stub 只在无法真实时用并在 PR 申报。性能/时序类验证用 benchmark 数据作红证据,不进 CI 断言防 flaky;路径过滤警惕 canonical 拼写坑(macOS /var→/private/var)。

== 硬机制(实测违者必红)==
npm install --ignore-scripts 后必跑 node scripts/apply-dependency-patches.mjs;构建链 core→storage→mcp→runtime→acp-executor→antigravity-acp→runtime-host→computer-use→eval→maka-agent→ui,缺环=TS2307;worktree merge 后必须重建 dist 再跑测试(陈旧 dist=「新导出名缺失」SyntaxError);model-metadata.generated.js 缺失先 npm run sync:model-metadata;新增平台守卫测试(win32 skip 等)必跑 npm run windows:inventory:write 再生登记清单再推,否则 CI 必红(#6403 教训);epoch 撞号新号=main 当前值+1,node scripts/protocol-epoch-check.mjs --base upstream/main --head HEAD 输出 "epoch moved" 退出 0;渲染器冻结清单零触碰,守卫 apps/desktop/scripts/check-renderer-architecture.mjs --base <merge-base>(工作目录 apps/desktop);desktop typecheck 无独立 script,直接 npx tsc --noEmit -p apps/desktop/tsconfig.renderer.json。

== 验证矩阵==
目标套件→相邻套件→tsc(-p <包>)→npm run format:check→check:asf-headers。desktop 被 biome formatter 排除则 biome lint 覆盖。相邻套件失败必须 git stash push -u 对照父提交定性(同名同数=预存,否则回归);benchmark/时序验证不进 CI 断言;worktree merge 后重建 dist 先于一切测试。
```
