## gh 安装、登录与授权
## 安装
```cmd
winget install --id GitHub.cli
```
装完新开的终端才有 `gh` 命令；已开着的 shell（包括 ZCode 的 Git Bash）PATH 不会刷新，用完整路径 `"/c/Program Files/GitHub CLI/gh.exe"` 调用。
## 检查登录状态
```bash
gh auth status
```
输出 `Token scopes` 一行就是当前权限清单。没登录会提示 `not logged into any GitHub hosts`。
## 设备码登录（浏览器授权）
```bash
gh auth login --hostname github.com --git-protocol https --web
```
流程：命令输出一个一次性码（形如 `XXXX-XXXX`）→ 浏览器打开 <https://github.com/login/device> → 输码 → 确认授权。命令会一直轮询直到完成。
国内网络下先设代理再跑（见 下方「代理配置」节），否则报 `dial tcp ...connectex: ... failed` 直连超时。
## 补 workflow 权限（本次踩过的坑）
推送到 fork 的提交只要**包含** `.github/workflows/` 下的文件改动（哪怕只是 rebase 带上来的别人提交），token 必须有 `workflow` scope，否则三个地方都会被拒：
1. `git push`：`refusing to allow an OAuth App to create or update workflow ... without workflow scope`
2. `gh repo sync`（fork 同步）
3. `gh api -X PUT repos/.../pulls/N/update-branch`（服务端"Update branch"按钮同样走 token 身份）
补授权（又会走一遍设备码流程）：
```bash
gh auth refresh -h github.com -s workflow
```
完成后 `gh auth status` 里 scopes 应多出 `workflow`。
## 把 gh 配成 git 凭据
```bash
gh auth setup-git
```
之后 `git push`/`pull` 走 https 时自动用 gh 的 token，不用配 SSH。配置写在全局的 `credential.https://github.com.helper`。

## 代理配置
## 症状
`gh`、`git push` 报 `dial tcp 20.205.243.166:443: connectex: ... failed to respond`（直连 github.com 超时），但浏览器能开 GitHub——浏览器走了系统代理，gh/git 不认 Windows 系统代理设置，只认环境变量。
## 解法
Git Bash 里每次执行 gh/git 前导出：
```bash
export HTTPS_PROXY=http://127.0.0.1:7897 HTTP_PROXY=http://127.0.0.1:7897
```
本机代理端口是 7897（Clash Verge）。验证代理通不通：
```bash
curl -s -x http://127.0.0.1:7897 -o /dev/null -w "%{http_code}\n" --connect-timeout 8 https://github.com
```
返回 `200` 就是通的。
## 注意
- 不要 `setx HTTPS_PROXY` 设成全局：所有应用都会被指到 Clash，Clash 一关全网断。按命令临时导出即可。
- `gh auth login --web` 的浏览器授权码流程里，轮询请求也走这个环境变量，所以必须先 export 再跑。
- 后台长跑的命令（比如等设备授权的轮询进程）要在同一条命令里带上 export，另开的 shell 不共享。

## git 身份配置（公司/个人隔离）
## 需求
这台机器全局 git 身份是公司邮箱（`802165@clife.cn`），给 apache/maka 提交要用个人 GitHub 身份（`ggbdpq@gmail.com`），且不能污染公司项目。
## 解法：仓库级 local 配置
在 fork 仓库里：
```bash
git config --local user.email "ggbdpq@gmail.com"
```
- `--local` 只作用于当前仓库，全局配置（公司邮箱）不动。
- GitHub 按**提交邮箱**关联账号，前提是该邮箱已加进 GitHub 账号的 verified emails。
- 验证：`git config user.email`（当前生效值）、`git config --local user.email`（仓库级值）。
- 用户名 `user.name` 保持 `关天豪` 不影响关联，只影响提交里的显示名。
## 已验证的行为
后续在该仓库的所有提交（含 `git commit --amend`）作者都是 `ggbdpq <ggbdpq@gmail.com>`，GitHub 上正确挂到 ggbdpq 头像。
## 提醒
clone 其他公司仓库时不受影响；新 clone 的个人仓库需要各自再设一次 local 邮箱，否则会掉回全局公司邮箱。
