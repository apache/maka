## Windows + Git Bash（2026-09 起实测；mac 迁移后未再核验）

> **Windows 已退役（历史）**：本节为 Windows + Git Bash 时代的实测记录，主力环境已转 macOS，未在 macOS 上再核验，仅作历史参考（2026-11-07 标注）。

- **cargo test 报 STATUS_ENTRYPOINT_NOT_FOUND**：Windows SxS 按（路径+mtime+size）负缓存激活上下文——测试 exe 依赖旁车 `.exe.manifest`（comctl32 v6 TaskDialogIndirect），manifest 缺失状态下启动过一次就负缓存，之后补 manifest 也不生效。修法：`cargo test --no-run` → 给 deps 下测试 exe 复制 manifest → 再跑；或 touch exe / 换文件名（2026-09-29，CT-1；2026-09-30 CT-3 实证不同 target 目录编译的同名测试 exe 同样中招）。
- 全量 `cargo test --lib` 约 37 个预存失败（sqlite repair、grok 同步时序、pelican 流、Linux 路径发现跑在 Windows 等）——验证用 stash/干净基线**逐名对照**，零新增才算过（2026-09-30，CT-2；2026-10-02 CT-4 复验 38 败同类零新增）。
- 验证矩阵：改动模块测试 + `cargo check`/`cargo test --lib` + 存量定价类测试不回归。
- gh pr create 必须 `--head ggbdpq:<branch>`（裸分支名 422）；cd 后 gh 命令会被 fnm 钩子截断，gh 一律不 cd 直接跑（2026-10-02，CT-4）。
