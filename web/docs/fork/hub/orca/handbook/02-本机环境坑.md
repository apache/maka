## macOS 本机坑（2026-10-30 起，r36 实测；r40 续记）

- `gh api graphql` 批量多 alias：生成器必须带 `count('{')==count('}')` 断言再落盘（手工拼 f-string 极易多/少一对闭括号，报 SDL 错且错误行号有误导）；查询顶层必须包 `repository(owner:..., name:...)`，`pullRequest` 不是顶层字段。线程回帖 mutation=`addPullRequestReviewThreadReply`，input 字段是 `pullRequestReviewThreadId`（不是 `threadId`），先回帖再 resolve，发后 GraphQL 回读 isResolved+last comment 核实。
- zsh 多行变量**不做 word splitting**：`git log -- $files` 把整个多行串当一个路径（静默零命中）；要 `${=files}` 或改用 python。
- fresh worktree `pnpm install` 冷装可达 52 分钟（Electron binary ~45KB/s 下载且可能被 SIGKILL 留半截产物，exit 137）。Electron 43.8.4 dist 已预热在主仓 `.git/orca-cache/electron/43.8.4-darwin-arm64`（APFS clone 过去即可）；依赖装好后验证统一 `pnpm --config.verify-deps-before-run=false run/test`（node 面 vitest 不依赖 Electron binary）。
- upstream 前进后 GitHub 会对全部在途 PR 重算 mergeable，出现十几单同时 UNKNOWN 属重算瞬态（数分钟收敛），以本地 `git merge-tree --write-tree --name-only upstream/main <head>` 探针为准。
- **merge-tree 探针的 head 必须用 PR headRefOid（`gh pr list --json headRefOid` 或 ls-remote），不能用本地分支名**：主线程 SHA 直推后本地分支指针不跟随（r37 实录：探针读旧 head 报双 CONFLICT 虚惊，远端实为 CLEAN）。
- **SSH git 传输被沙箱代理挡死**（r40 实录）：`git push git@github.com:ggbdpq/orca.git main:main` 报 `Connection closed by 127.0.0.1 port 7897`——`ssh -T git@github.com` 握手可用但 git 传输被代理关连接，重试 5 次无效。**fork 推送回落配方**（实测可用）：`git -c credential.helper='!f() { echo "username=x-access-token"; echo "password=$(gh auth token)"; }; f' push https://github.com/ggbdpq/orca.git main:main`。两个勿用：①URL 内嵌 token（`https://x-access-token:<token>@...`）在本机报 `does not appear to be a git repository`（代理不吃 userinfo）；②显式 `-c http.proxy=http://127.0.0.1:7897` 指错代理（环境变量 `HTTPS_PROXY` 才是 53160 可用端口）。
- **哨兵三件的位置与易丢性**（r40 实录）：`.pr-watch-prompt.md` / `.sentinel-prompt.md` 模板**是点文件，`ls` 必须加 `-a`**（r40 曾误判「sentinel/ 目录空」并按 README 契约手搓了一个狩猎向脚本，与模板的盯审契约不符，已按 `.pr-watch-prompt.md` 重写 runner）；真正会丢的是 `/tmp` 下的 runner 脚本和 `sentinel/.pr-watch-state.json` 基线（状态文件 schema 以模板为准：`{repo, base_branch, base_tip, in_flight_prs:[{n,head,updated_at}], watched_issues:[{n,last_comment_id}], last_runs:[]}`；重建时 in_flight_prs 取 `gh pr list --author ggbdpq --state open`，watched_issues 取 `gh search issues --commenter ggbdpq --state open` 近 30 天，末位评论 id 逐个 `issues/{n}/comments?per_page=100` 取 last）。模板内路径曾写 orca-hub 旧结构，r40 已改为现路径（`docs/hub/orca/sentinel/` + 主 clone `fork/orca`）。（2026-11-07 校注：`.sentinel-prompt.md` 已退役删除，现行模板只留 `.pr-watch-prompt.md`）
- **jq `reduce` 的输出会替换整个管道上下文**（不是原地改字段）：`... | reduce $u[] as $x (.arr; ...) | .field = ...` 会在 `.field` 处报 `Cannot index array with string`——先用 `as $v` 绑定再赋给目标字段。另：SHA 全值只能用 `git rev-parse`/API 实取，**禁止按短 SHA 脑补尾部**（r40 臆造 base_tip 全 SHA 导致 compare API 404）。

- `pnpm test -- <files>` 的裸 `--` 会让 run-vitest.mjs 放弃过滤启动**全量套件**——传文件用位置参数 `pnpm test <files>`（r45 实录：误用后 10 分钟全量被 kill）。
- oxfmt/oxlint 是依赖 bin 不是 package.json 脚本：`pnpm run oxfmt` 报 ERR_PNPM_NO_SCRIPT，用 `pnpm exec oxfmt`（r52 实录）。个别 worktree 里 `pnpm exec` 相对路径报 "No files found"，改 `./node_modules/.bin/oxfmt` 直接调用。
- 棘轮脚本已迁 `config/scripts/static-analysis/ratchets/source-budget/check-max-lines-ratchet.mjs`（旧 `config/scripts/check-max-lines-ratchet.mjs` 路径失效，r52 实录）。基线文件 `config/max-lines-baseline.txt`（只许缩不许涨；新超限文件拆分而非加豁免）。
- vitest 测试 helper 已迁 `config/scripts/test-runtime/environment/`（旧 `config/scripts/vitest-host-ports-setup` 路径失效，r51 实录，#38130）。
- electron 安装抖动：undici 经 GitHub CDN 下载持续失败时 curl 直连秒下，dist 预置进 pnpm store 的 electron 包目录供 worktree 共享（r52 实录）。

## 本机环境坑（Windows + Git Bash，已实测；历史遗留，macOS 会话仅参考）

- cd 进仓触发 fnm 钩子截断 `&&` 链：先单独 `eval "$(fnm env)" 2>/dev/null`，或全程 `git -C` 正斜杠绝对路径。
- `tests/e2e/` 下的 Playwright spec 在 `vitest run <关键词>` 时会文件级加载失败（无 e2e 环境）——单测验证用 `src/` 内文件名过滤，别被 e2e 失败吓到。
- `orca-runtime-tests/*.spec.ts` 全部 111 个文件不在任何 CI lane——`config/scripts/ci-unit-files.mjs` 的 UNIT_INCLUDE 只 glob `*.test.ts(x)`/`*.test.mjs`。本地跑 spec 用临时 scratch config（extends `config/vitest.config.ts` + `include` 覆盖为目标 spec glob），跑完删。**声称"spec 端到端绿"前先确认它真被跑过**（09-30 发现 orca-3 的"缺席守卫"当时实为基线红未跑过）。spec 若用到 `scanLocalRepoWorktreesForResolutionMock`，出厂无配置会全红，需 beforeEach `mockResolvedValue({ok:true, worktrees:…})` 固化。
- `node:fs` 的 vi.doMock/vi.mock 对新文件绑定不达某些 import pool——文件系统类测试用**真实临时目录 + 依赖注入 seam**（先例：`GlobFsDeps`）。
- `src/main/ssh` 全套里有 75+ 预存平台失败（POSIX ownership / relay / sftp 类，Windows 环境）；只以自己改动文件的测试集为验证面，失败先做干净基线对照定性。
- glob 语义争议用**探针实测**：本机 node 24 直接跑 `require('node:fs').globSync` 钉行为（点文件、`[.]` 段首、非法区间等都实测过，别照抄 bot 的描述）。
- `tsc -p config/tsconfig.tc.web.json` 首跑可能 OOM——`NODE_OPTIONS=--max-old-space-size=12288` 兜底（10-01 实录）。vitest 不做类型检查，红绿两轮都抓不到的类型错靠 tsc（orca-4d 实录：`map.get(k) && Object.fromEntries(...)` 不收敛）。
- rebase 全程不 cd：`cd xxx && git rebase --continue` 会被 fnm 钩子截断，用 `GIT_EDITOR=true git -C ... rebase --continue`（10-01 实录，截断过两次）。
