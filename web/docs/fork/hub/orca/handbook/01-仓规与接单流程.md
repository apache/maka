# orca 仓规与接单流程

> 2026-10-21 自项目 README 迁入（正文未改）。

## 硬约定

- **max-lines 300 棘轮**（oxlint，禁 disable 注释）：文件超行数就拆新模块（先例：`ssh-config-include-glob-segment-matcher.ts` 142 行）。分档补全（2026-11-07 读 clone `.oxlintrc.json` 核实，clone HEAD `d6f32093e16`）：均按 `skipBlankLines`+`skipComments` 计数；`**/*.ts`/`*.mts`/`*.cts` 300、`**/*.tsx` 400、`**/*.mjs` 600、测试文件（`*.test.*`/`*.spec.*` 的 ts/tsx/mts/cts 八种）800；另有若干生成文件在 `ignorePatterns` 中豁免。
- UI 改动走 STYLEGUIDE；Windows 子进程只准走 `src/shared/child-process/`；禁 helpers/utils 命名。
- **三个 review bot 每次推送必审**（greptile-apps / pullfrog / coderabbitai）：greptile 出 P1/P2 线评论、pullfrog 有时贴可复现细节、coderabbit 有 seam/风格意见。bot 意见也要逐条核实后处置——四轮 review 实测三轮有真 bug。
- 代码注释英文；测试文件与源码同目录同名。

## 接单开场固定流程

1. `git -C ... fetch upstream main`，查在途 PR 是否合并。
2. 扫各 PR 新评论/线评论（三个 bot + 维护者）。
3. 查 mergeable（unstable 多为 bot check 显示态，看 check-runs 实际红绿）。
4. 查候选 issue 是否被占（评论区 "looking into it"/PR 搜索）。
5. 认领评论有效（无 take bot）；评论一律走 `gh`（`--body-file` 发送，payload 先写文件），POST 报错不等于没发，先 GET 回读核实，见 [04-维护任务书](04-维护任务书.md) 审查面一节；git 推送需要 token 时用 `gh auth token` 注入 credential helper，见 [02 坑册](02-本机环境坑.md) SSH 回落配方。（校注 2026-11-07：原文为「token 走 `git credential fill` 单命令变量，payload 先写文件再 curl」，与 02/04 现行 gh 做法不符，已按现行改写。）
6. **派单开场三件套**：先 `git -C ... branch --show-current` + `status --short` 查主工作树残留（10-01 限流中断的代理实例留过半成品）——逐项核对依赖才可续用，否则 reset。**全局单号只由主会话分配**，代理报告里的编号以 02 台账为准（10-01 两代理自编号撞号实录）。
