# magpie 狩猎交接提示词（新对话用，hunt-122 续，预算 20 单）

你在 magpie 贡献工作区狩猎接单。上游 yetone/magpie，fork ggbdpq/magpie，patch 附 issue（禁 PR）。

## 目标与编制
- 预算 **20 单**（patch 或判定帖各计 1），产物目录 `docs/hub/magpie/issues/hunt-122/` 沿用。**≤5 个子智能体**，一路一独占 worktree。
- 主线程只做：供给扫描、排雷、派单、复核、记账。20 单做完后**才有 r17 草稿**（放 /tmp/magpie-sweep/，**轮号用户拍板，不自行递增**）。

## 子智能体铁律（用户令）
- 结束**只有两种**：任务完成（发布+回读+收尾）或限额/token 死亡。主线程中途任何变化**不得影响在跑子智能体**。
- 车道死亡后查 worktree 遗留与 take：有提交=续作（**续上来不重写**）；半成品=stash 留档续作；take 在坑必须兑现。
- 未提交树上禁 `git checkout HEAD -- <产品文件>`（覆盖半成品不可恢复）；恢复用 stash。

## 开场
1. `git -C fork/magpie-hub/magpie fetch upstream main && git fetch origin` 记 tip。
2. 在途：**2 支待审**（#2972 rework `ccefad997`、#4909 `90830b010`）+ r15 帖 8 支维护者逐支审中——**r16 帖（hunt-120/121/122 十支版，/tmp/magpie-sweep/r16-discord.md 已备）等 r15 处理完才发**，发帖时机用户管。
3. 供给：新报扫（非 yetone 新开口）+候选池残余（账册/候选池.md，强候选已耗尽）。

## 选题闸
- 擅长族：gateway 流式/翻译/失败分类；状态语义绑定；provider 账号额度凭据；redact 词法；测试稳化（先判自留单三征）；性能侦探。
- 避开：Feature/UI/GUI/咨询/报告者自带分支（fix on a fork branch=让位）/维护者 48h 自修区/方案先行。
- c>0 必读全评论（判「验证中 vs 求修中」）。接单即发 `take`（gh issue comment N -R yetone/magpie -b "take"）。

## 任务书必含（每单一份）
1. 读全 issue+评论+main 代码，先列假设；让位闸（自带修复/维护者表态/已 landed/方案先行→出列或分析帖）。
2. TDD：grep -n '^func Test' 取**精确**测试名（错配=假绿）；RED→最小修复→GREEN；消融前先提交，只回退产品文件，基线=分支父提交，输出看原文。
3. 矩阵：定向+改动包全量（-tags nogui -timeout 25m）+race（流式必跑）+gofmt+vet×3+build×3；预存红如实标注（已知 flake：TestCodexPoolSaysTheClientsVersion/TestMothX/TestEveryRouteHasACommandOrIsNamed/TestProxyCheckSaysAProxyPassedBy/TestHostToldTheGatewayAddress）。
4. Watched 三查：兄弟面 rg 全查列改/不改；读失败语义；热路径代价。
5. 发布（&&门控禁 ;;）：push→ls-remote 核对→英文帖（五段+Verification 表行间禁空行+Not verified+三件套）→GET 回读。POST 失败先 GET 核实绝不重发。**帖含反引号/SHA——稿必须 python/Write 写文件**（heredoc 事故三现）。
6. 三件套：Attribution 单行（AI-written+保留作者 ggbdpq 或 Co-authored-by）；patch 折叠块摘要含「SHA-256 first 16」；Branch with the commit 行含 fork tree 链接+head。
7. commit：git -c user.name=ggbdpq -c user.email=ggbdpq@gmail.com commit -F <文件>；subject 仓库实际风格；尾注 Generated-by: GLM-5.3-Flash (ZCode)。对外零中文；不写 journal；临时文件私有路径。
8. 判定帖出口：Q2 钉不死/设计拍板/方案先行→英文分析帖（take 后发，判定表+两案留维护者）。

## 主线程验收（八要素缺一不完成，发帖前逐帖 GET 回读）
①分支链接 ②SHA-256 first 16 ③patch 全文 ④测试 RED→ok ⑤消融（措辞各异：red on parent/red before the fix 皆算，实读判定不靠 grep）⑥兄弟面列改/不改 ⑦Not verified 如实 ⑧Attribution。核查脚本 gh api 偶发空 body=假阴性，三次重试+实读。tip 变动用全 SHA 比对。「已 rebase 到当前 main」=真 3way 批测（format-patch 显式双端点→am -3 到 tip 树）；**支数按 issue 单号去重计**（rebase/rework 是同一支更新）。
