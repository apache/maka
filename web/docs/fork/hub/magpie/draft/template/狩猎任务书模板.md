## 铁律
- 让位闸：报告者自带 fork fix/维护者表态/已 landed/方案先行→出列（验证背书/判定帖出口）。
- TDD：`grep -n '^func Test'` 精确测试名；RED→最小修复→GREEN；**消融前先提交**（只回退产品文件，基线=分支父提交）；变异点放语义分叉行。
- 兄弟面 rg 全查（改/不改都写理由）；读失败语义；热路径代价。
- 矩阵（按上游 code-standards Acceptance criteria 第 3 条全列，没跑的列 not run，不省略）：定向测试 + 改动包 `go test ./internal/<pkg>/ -tags nogui -timeout 25m -count=1` + 全量 `go test -tags nogui ./...`（沙盒 HOME、Go 缓存固定，跑 `./...` 不挑包）+ 相称 -race（全包超时改改动包定向+同机并发互证）+ 改动文件 `gofmt -l` 无输出 + `go vet ./...`、`GOOS=linux go vet -tags nogui ./...`、`GOOS=windows go vet ./...` + `go build`、`GOOS=linux go build -tags nogui`、`GOOS=windows go build`；命令链 `set -o pipefail`。在 origin/main 上同样失败的项不构成基线（code-standards：“Fails the same on origin/main” is not a baseline）：照实列为失败、不算通过，附点名根因的 issue 或说明。预存红仅作排查参考，不构成基线：TestMothX/TestLaneLimitRoutes/TestProxyCheckSaysAProxyPassedBy/TestBrowserKeyOffClosesItsBrowser；linux wails `undefined: pointer`。
- 六要素发布门：实际 rebase 到当前 main+git am 即进+分支+sha256+测试实名绿+消融回红+兄弟面+实证，全落 issue。
- 发布：push 显式 refspec→ls-remote→PATCH 帖（draft/template/PATCH帖模板.md；--body-file；REST 404 走 GraphQL）→GET 回读。判定/背书帖用对应模板。
- 基线漂移纪律：fetch 后以当时 upstream/main 锁定基线写进任务书；中途漂移不追，收口对最新 tip 补 merge-tree 快扫。
- **消融变异写入后 `git diff --stat` 复证**（bash 引号吃转义→变异静默失效两跑皆绿判例）；字段型改动摘逻辑 hunk 保留字段；行为变更撞既有测试期望→语义裁决+测试参数化分叉，不硬改断言。
- 两面单先核半面覆盖：同域我方已交付 patch 覆盖的面帖内如实说明（引 head），只修余面。
- **发布前实时 gh 复核 issue 评论态防撞车**；挑单派单时非零评论必须先读内容（他人 patch/交付帖=让位）；发布前 force-with-lease 钉旧值。
- 并行会话协调：接单前读 /tmp/magpie-sweep/active-claims.json，占坑写入自己会话键。
- GUI 测试基建：NODE_PATH=/Users/ggbdpq/cc/code/fork/maka-hub/maka-pr2/node_modules。
- provider 死亡等 2 分钟×3 落盘停止；worktree dirty 即停；不动 journal/；docs 不提交。
