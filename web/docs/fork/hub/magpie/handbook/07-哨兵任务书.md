## 每轮只做有增量的事

1. 核验实际路径、HEAD、最新main SHA与工具链；只更新tracking，不切换、合并或stash共享工作树。Windows操作读 [08](08-Windows工作区与沙盒规范.md)。
2. 对照[台账索引](../journal/README.md)读在途issue正文/最新评论与main实现，区分已合入未关闭、插件已修、他人patch在案、暂不合待样本及真正待审。无新事实不重复发确认或提醒。
3. 同账号跨机claim、patch与分支清单传给每一路；既有交付、维护者认领或产品裁决命中即让位。分析不超出现有内容时零评论。
4. 优先完善现有交付：真实执行路径、收益边界、公开测试与mutation、兄弟路径、失败读取语义、当前main套用与完整质量门。缺真实失败且维护者已给反证的单等待样本，不用构造样本强推。
5. 仅在用户本轮明确要求继续寻找新问题时扫描新候选；没有有价值候选就结束，不以“池枯”为理由转向人工凑单。
6. 任何候选在写成待发布稿前先过 [05 §3.1 七问](05-缺陷狩猎经验.md#31-发帖前七问任一不过就不发)，任一不过即放弃并在报告中一句话说明原因。

## 并行与验证

仅把明确独立的问题交给独立复制品或已确认可用的工作树；不覆盖分支、不清理无关文件。各路遵05的测试接缝确认、逐条红绿、全部相关产品文件消融、关键守护mutation与相称质量门；共用重资源环境时协调整包/全仓检查，保留每路命令和退出状态。主线程统一复核并维护台账，不依赖子线程一句“全绿”。

## 交付与通知

默认只读巡查和本地待发布稿；提交、推送、公开评论/正文更新、关单与定时ping须本轮明确授权。已有授权仍需发布前重读，按05使用正确文件上传参数并GET回读。magpie 上的一切公开内容（issue、评论、回复、commit message、交付尾部）一律用英文，报告者用中文也用英文回复，逐字引用原文除外；本地文档与给用户的报告用中文。待发布稿直接写英文，未发的中文旧稿发布前先改写，规则见 [05 文首语言规则](05-缺陷狩猎经验.md)。实际交付尾部使用 [05 §3.2 证据尾部（版本 C）](05-缺陷狩猎经验.md#32-交付证据尾部版本-c)，署名/AI披露只写一次；普通确认不加尾部、不重复索取署名。不写“契约自检通过”式自我声明。每条公开交付发布前须用户本人读完 diff 并确认。

> 校注（2026-11-07）：本段「提交、推送、公开评论/正文更新、关单与定时ping须本轮明确授权」与「每条公开交付发布前须用户本人读完 diff 并确认」两句，2026-10-24 起以 [fork/AGENTS.md](../../../../AGENTS.md) §3「发布权按形态分」定版为准（子智能体自检→推 fork→发帖→GET 回读，主线程事后复核）；本句保留为无自动化授权会话的默认。

仅有值得用户行动的新事实、完成、失败或需决策时报告；状态不变不制造提醒。报告不含任何计数；被维护者以低价值关闭的单须单列并登记台账。报告区分本轮实测、历史声明、第三方复验和未验证项，包含实际base/head或产物hash及“本轮不自信的点”。必要门禁未通过的patch继续标为未完成验证，不催合入、不称Ready。
