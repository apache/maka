# 修法方向最佳实践

> 分析阶段**定修法**时的方向判断器。分工：[10 避坑清单](10-避坑清单与模式家族.md)管流程坑，[05 狩猎经验](05-缺陷狩猎经验.md)管接单战术，本篇只管修法本身的方向——每次写第一个测试之前过一遍五问；任一问答不上来 = 方向存疑，先升层/找瓶颈口/换替身，再动手。
>
> 锚点案例 **#4502**：v1 被维护者真机驳回 → 按其 spec 拟的 rework 方向 → 维护者数小时内自修落地（`73a12e8bf`，v0.1.2403），落地版在五个维度上全面超越 rework 方向。差距五条是本篇的实证底座；大模型能力有差距，但**修法方向可以用对的方法补**——这是本篇存在的理由。

## 一、修法方向五问

| # | 问 | 判别器（答不上来 = 方向存疑） | 反例（#4502 我方） | 正例（#4502 落地 `73a12e8bf`） |
| --- | --- | --- | --- | --- |
| 1 | **层次：修在认知层还是动作层？** | 修法要不要面对「下一个动作」？写时猜拓扑 → 每个后续动作都要重新猜。能修在 probe/缓存/元数据的**认知层**，就不修在 write/mkdir 的**动作层** | v1 `ensureDir` 放行 EEXIST（写入点，错误挪到写步）；rework 方向=写时 lstat/stat 检测+现场 `readlink -f`（每个写入点各猜一次） | WSL probe 一次问清 `readlink -f` 拓扑（`wslLinkPaths`→`distro.Links`），写入只消费探测结果（`distro.open` 路由） |
| 2 | **收口：共享瓶颈 or 散点调用方？** | rg 出全部 writer/调用方——修一处盖几处？>1 处就找瓶颈口收口，不是逐点列「不改的理由」 | 只换 `copyIn`+`rtkInstall` 两点；Sessions 读、Copilot sign-in、agents 自身文件的兄弟面全没盖 | `distro.open` 单瓶颈收**全部** writer：agents 文件（`place.join/open`）、library（`wslOpen`）、RTK（`rtkAt`/`agent.WSLOpen`）、Sessions（`sessions.WSLHome.Open`）、Copilot sign-in（`provider.CopilotWSLDirs`） |
| 3 | **失败语义：fail-closed 带名状态 or fail-open 吞错？** | 修法里有没有「吞掉一个错误继续走」？有→先想这个错误揭示的状态该怎么**命名**、该停在哪。停、降级还是旁路按后果定：涉及用户配置归属、删除、覆盖、鉴权、敏感信息时，不确定就不做破坏性动作；可选的非关键能力隔离、独立超时、显式降级，不拖垮核心路径（#3682） | EEXIST 当「已存在」放行（假设后续写入顺利——恰恰是 9P 下唯一不成立的事） | 解析失败→`Agent.Unreached`：notice 带原因、拒一切变更与同步；「a link readlink couldn't resolve is **never guessed at**」 |
| 4 | **事实来源：运行时实问 or 惯例硬推？** | 修法里有没有按惯例写死的外部对应关系（`/mnt/x↔X:`、路径模板、厂商命名表）？外部系统能问就别推 | rework 方向按 `/mnt/<d>/→D:` 惯例转换（自定义挂载点即破） | probe 追问 `win:/mnt/c C:` 得 `distro.Drives`——盘符映射是问出来的，不是推出来的 |
| 5 | **可测性：修法落在现有 seam 上吗？替身与失败签名对齐吗？** | ①实现要**新开 seam** 才能测→警报：先查层次是否选错；真实边界确实缺测试入口时可加最小注入点，并说明它不是为迎合测试扩张产品 API；②替身能否逐行复现真机失败签名？本地「能跟随」的替身测不出「不跟随」的拒绝 | v1 测试全绿但真机挂（FakeWSL 与本地 symlink 都**跟随**链接，9P **不**跟随）；rework 写时方案需给 library 新开 wsl.exe exec seam | probe 层修法天然落在 FakeWSL 现有 probes map（`link:.codex /mnt/c/...`、`win:/mnt/c C:` 直接进替身）；替身设计（拒绝链接下全路径）由维护者 review 亲手给出 |

五问的优先级：**Q1 决定 Q2-Q4 的答案**。层次选对（认知层）后，收口、实问、fail-closed 往往自然成立；层次选错（动作层），后面三问怎么补都是在错误的层上打补丁。

## 二、落地修法的形状（`73a12e8bf` 拆解）

一次高质量落地的完整形状，作为修法质量的对照清单：

1. **探测与动作分离**——probe 负责认知（链接拓扑+盘符映射），动作只做路由（`distro.open`）。
2. **一个瓶颈口收全部 writer**——不是「改两个站点+列出其余不改的理由」，而是让其余调用方自然走过同一个口。
3. **未知态显式化**——解析不了不猜，给状态命名（`Unreached`）、给原因、给行为（拒绝变更/同步）。
4. **外部对应关系实问**——`distro.Drives` 是 probe 出来的。
5. **边界如实划**——「Links deeper than the probed paths aren't resolved」写进提交说明与 docs；同族先例：#3260 收编帖注明 Not covered `VSCODE_PORTABLE` 与 macOS `code-portable-data`。
6. **docs 同步**——`docs/subsystems/agent-wiring.md`、`library.md` 各一行更新；文档是契约，落地修法不含 docs 更新=没写完。
7. **测试组随层次走**——`TestWSLProbeLinks`（probe 层）、`TestWSLFolderIsALinkToC`/`TestRTKWSLFolderIsALink`（落盘符路径）、`TestWSLAgentFolderLinkUnresolved`/`TestRTKWSLFolderLinkUnresolved`（fail-closed 分支）、`TestWSLOpenThroughLinks`（路由），每个语义分支一个测试，不是只测 happy path。
8. **验证含跨平台**——`go test -timeout 45m ./internal/agent ./internal/library` + GOOS windows/linux build + gofmt。

## 三、执行门禁（把五问变成流程）

1. **任务书模板加一节「五问自检」**：车道子智能体的任务书在「步骤」前列出五问与答案；主线程派单前先自己答一遍，答不上来的先补事实再派。
2. **RED 替身先过签名对齐**：把真机/报告者失败追踪的每一行签名列出来（#4502：`lstat ok` / `stat 挂` / 链接下 mkdir+write+readdir 全挂），替身逐行对得上才算 RED；对不上的替身给出的绿是假绿（v1 教训）。
3. **review 驳回后的动作顺序**：①读全文提取 spec；②`git log upstream/main --grep=#N --since=<驳回帖时间>` 查是否已被自修（防白做——本轮 rework 差点撞上数小时自修窗口）；③先实证再照办（对方对就照做并承认，实测推翻的部分给证据，见 [10 #19](10-避坑清单与模式家族.md)），按 spec rework，同分支 squash；④`--since` 之后每轮动手前重查。
4. **兄弟面 rg 全查升级为瓶颈口之问**（Q2）：共享规范的「兄弟面 rg 全查」原输出是「这些调用方为什么不改」的清单；五问 Q2 要求再进一步问「**它们该不该走同一个口**」——能收口就收口，收不了才落「不改理由」。
5. **与既有规则的关系**：本篇不重复——真机 RED 天花板与 Not verified 如实标注在 [10 §22](10-避坑清单与模式家族.md)；真资源验收在 [10 §15](10-避坑清单与模式家族.md)；热路径代价、失败读取语义在共享规范与 10。冲突时以更严格者为准。

## 六、被拒三型（r6 三拒实证，2026-11-01）

维护者 r6 三拒各给明确理由——三种「修法方向错误」的通用形态，定修法前对照（共同点：**patch 把「不确定」当成了「可以动手」**）：

| 型 | 单 | 被拒理由 | 通用判别器 |
| --- | --- | --- | --- |
| **设计红线型** | #4063 | `.example` stand-in 被否：打码按**值在协议里的位置**判断，不按键名/主机名——`79b4be466` 真模型实测 4/5 模型把 example 名当占位符答用户（Discord 补充理由定为设计红线） | 修法方向与产品判定原则冲突时，测试全绿也是零分。红线藏在同域近期提交与维护者裁决里——rebase/refresh 车道除漂移外必须查**方向鲜度**（[10 §24](10-避坑清单与模式家族.md)） |
| **覆盖面越权型** | #4436 | 把 host 默认 fallback（`was?.capabilities ?? {…}`）当成插件自述，`InputModalities` 放行过宽 | 「没说」≠「说了」。宿主/上游的**默认值不是声明**；区分声明面与默认面要独立证据字段（维护者 spec：`InputsSaid` 仿 `outputsSaid`）——本篇 Q4「实问 vs 硬推」的单点变体 |
| **用户数据越权型** | #4574 | minted id 下无 mark 的 `modelSettings` 行可能是用户自写 `/autocompact` 值；模式匹配（`mythos-magpie-*`）不构成所有权 | 归属判定必须有 mark/证据，命名模式只是线索；heal/清理的门槛=「**值==我方应写值**」（「magpie 默认不覆盖用户自设值」同源，[10 §11](10-避坑清单与模式家族.md)） |

与五问的关系：三型都发生在五问**之前**——方向前提本身错了（红线未读/默认当声明/模式当所有权），五问答得再好也是在错前提上打转。顺序=先核方向前提（读同域裁决与近期提交），再答五问。
