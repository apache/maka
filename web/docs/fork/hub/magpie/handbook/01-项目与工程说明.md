## 2. hub 目录

```text
magpie-hub/
├── magpie/                  主 clone
├── magpie-pr1/              固定并行 clone，独占复用
├── magpie-pr2/
└── magpie-pr3/

patch 与 issue 草稿（狩猎原件）在 fork 层 `docs/hub/magpie/issues/`（2026-10-24 随文档上收迁入；2026-11-01 定名：第一层只允许 `hunt-<轮次>/`，同轮多车道产物全部收入该轮目录内），本项目文档在 `docs/hub/magpie/`。
```

> 校注（2026-11-07）：产物目录 2026-11-06 起为 `hunt-YYYYMMDD/`（日期式，见 [11](11-狩猎轮机制.md)），旧 `hunt-<轮次>/` 目录保留不改名。

Windows 当前是主仓加三个独立 clone，不是四个共享 Git common-dir 的 worktree。目录分工、复用/新建命令及沙盒规范以 [Windows 工作区与沙盒规范](08-Windows工作区与沙盒规范.md) 为准；旧迁移记录见 [缺陷狩猎经验](05-缺陷狩猎经验.md)。这里的文档与上游主仓的 `magpie/docs/` 分开维护，避免把个人台账带入上游补丁。

新运行沙盒统一在 `E:\magpie-sandboxes\<任务>-<UUID>`，证据留在 hub 内。`E:\cc\.git` 会污染“无 Git 祖先”的测试，不能将这种运行沙盒改到 hub 内；截图中的旧 E 盘沙盒本次不移动。

> 校注（2026-11-07）：以上两段是 Windows 工作区历史（已于 10 月撤除）；当前为 macOS /tmp worktree 制与进程级 `HOME=/tmp/<dir>` 沙盒，见 [05](05-缺陷狩猎经验.md) 文首「Mac 侧」段与 §5.3 与 [08 文首](08-Windows工作区与沙盒规范.md)。

原项目索引记录的验证矩阵包括 `go vet`、darwin/linux/windows 三平台构建（按仓规使用 `nogui`）、沙盒 HOME 下的 `go test -tags nogui -count=1 ./...`，以及 WebKit UI `.test.cjs`。这只是既有工程要求摘要，不代表本次迁移执行了这些检查，也不代表全部 checkout 均可构建。

并行任务默认复用分配到的 `magpie-prN` 独立 clone，每个 clone 单独 fetch。工作树有修改或未跟踪文件时停止并报告，不覆盖、清理或自动 stash。只有用户明确要求新增 linked worktree 时，才按 Windows 规范在 hub 内不存在的目标目录创建；不在 E 盘根目录创建代码工作树。fetch 只更新 remote-tracking，避免对被检出的 `main` 执行 `fetch upstream main:main`。Git 身份使用环境已有配置，不按历史提示词中的姓名或邮箱强行覆盖。
