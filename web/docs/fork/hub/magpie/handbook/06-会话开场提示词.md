# magpie 贡献会话开场提示词

2026-10-17 更新（含对外英文规则）；2026-10-23 并行狩猎模板并入 hunt57-61 沉淀（回合扫描/任务书 v3/消融三坑/老单开场）。本文用于新会话注入，不代表已注册/修改自动化，也不继承历史发帖授权。质量规则唯一入口是 [05 §2–§6](05-缺陷狩猎经验.md#2-开工先判断问题执行路径与贡献状态)，哨兵运行边界见 [07](07-哨兵任务书.md)。

会话入口（2026-10-28 起）：先读 [docs/README.md](../../../README.md)（按项目路由）→ 共享纪律与政策总表 [docs/handbook/12](../../../handbook/12-通用纪律与执行声明.md) → 本文件与 magpie 专属（hub/magpie/{handbook,issues,journal,账册}）。

```text
你在magpie贡献工作区处理用户本轮明确要求。
1. 先读05现行质量规则、项目AGENTS和相关子系统；状态只信本轮GitHub/上游main，台账作历史索引。
2. 实查工作区、checkout HEAD、tracking SHA与工具链。不要切换或stash共享工作树；不移动/清理已有clone、worktree和未跟踪文件。
3. 列出现有issue的真实状态：合入/重写采纳/插件部分修复/分析/暂不合/待审/待确认。Open不是未合入，不追求author计数或发帖量。
4. 每项写清真实使用、他人报告或构造来源；先核对真实执行路径、协作者patch、维护者取舍。缺真实失败且已有反证时暂停，不用fake证明上游一定失败。
5. 新测试先列公开接缝并请用户确认。随后按05完成断言RED、最小修复、GREEN、关键守护mutation和恢复；检查兄弟路径与失败读取的语义。保护性测试本来就绿时如实标注。
6. 验收遵当前main code-standards；失败、超时、跳过和未跑分别列出。既有main同红不等于可以忽略。使用固定Go缓存与当前testenv，不碰真实账号/agent配置。
7. magpie上的issue、评论、回复、commit message与交付尾部一律用英文（逐字引用原文除外）；本地docs记录、分析与给用户的报告用中文。产物收进 docs/hub/magpie/issues/hunt-<轮次>/，台账索引用于定位，编年只追加。先留本地待发布稿；提交、推送、更新issue及自动化只按本轮明确授权执行。
8. 报告实际完成、未完成与继续条件，必附本轮不自信的点。不要把历史测试、第三方声称或文本套用通过写成本轮运行通过。
```

Windows 工作区、clone与沙盒命令仍见 [08](08-Windows工作区与沙盒规范.md)；Mac路径和协作方式执行前实查，不从历史快照猜测。提交与AI署名规则见05，不复制旧工具/模型尾注。

## 单 issue 修复会话模板（2026-10-17）

一个对话只做一单的开场模板（实测于 #2682/#2727 review-fix）；路径为 Mac 侧，Windows 按 08 换算。使用时替换 `<N>`/`<slug>`，连同 ponytail、tdd、diagnosing-bugs 一起贴进新对话。

```text
你在 magpie 贡献工作区修复一个 issue：#<N> https://github.com/yetone/magpie/issues/<N>。一个对话只做这一单。

加载 skills：ponytail、tdd、diagnosing-bugs；Go 侧按需读 fork/magpie-hub/.agents/skills/ 的
golang-testing、golang-code-style、golang-error-handling、golang-concurrency、golang-context、
golang-lint——改到哪项读哪项，不全文加载。质量规则唯一入口 docs/handbook/05 §2–§6；
接单先查 docs/journal/README.md 索引（做过没有、同构先例、避坑）。

开场（只读）：
1. cd fork/magpie-hub/magpie && git fetch upstream main && git fetch origin；
   记下 upstream/main SHA 与各 clone HEAD，全程以此为基线。
2. gh 读 issue 正文与全部评论（含维护者修复意见）；按索引查重：已交付/同构/他人认领/并行会话在途，撞车即让位。
3. 接单顺序（2026-10-22 用户定版）：首接的单先发一条 `take` 评论占坑（#2593 先例），让别人知道这单有人接了，再动手做；
   已有我方沟通在先的单不重复占坑，按「先做+自测 → 推 fork 分支 → 发评论」回帖，回复只写本轮实测过的事实。
4. git -C magpie worktree add -b fix/<N>-<slug> /tmp/magpie-<N> upstream/main——一路一 issue 独占 worktree（2026-11-01 定版分支名；老分支不改名）；
   不动共享工作树、不切主仓分支、不 stash。

诊断（diagnosing-bugs）：
先建反馈回路——在 worktree 写会失败的测试（RED）：一条命令、确定性、秒级、断言用户症状。
先复现，后假设。测试用 testenv 同款隔离：HOME+XDG_* 全套重定向，GOPATH/GOMODCACHE/GOCACHE
固定取 go env；不触网、不碰真实账号与 ~/.config/magpie。

修复（tdd + ponytail）：
一条公开接缝一个测试，RED→最小修复→GREEN；关键守护分别 mutation 证敏感；
显式摘全部产品文件做消融（基线→红，恢复→绿）。最少代码：先 rg 复用仓内既有函数与判定，
不加依赖、不顺带重构、不改无关文件；错误处理与并发改动分别按 golang-error-handling、
golang-concurrency，并发必跑 -race。

验证（05 §5）：
定向家族 + 改动包全量 + gofmt -l + go vet ./... + GOOS=linux/windows vet + 三平台 build；
命令、输出、退出码留档 docs/hub/magpie/issues/hunt-<轮次>/。已知预存红如实标注，不冒充新引入。

交付：
单提交，英文 message，subject=`fix(<scope>): <summary> (#N)`（2026-11-01 定版），正文 What changed / Run + Generated-by: GLM-5.3-Flash (ZCode)；
format-patch 存 docs/hub/magpie/issues/hunt-<轮次>/，fork 推分支。对外一律英文：patch 帖五段 +
Verification 表 + 没跑什么 + 版本 C 尾部。AI 披露帖内可见一次（05 §3.2）：帖内嵌
patch 时模型名只在 commit 尾注、尾部只写承诺句；帖内只有分支链接时，尾部 AI 项
写 written with <model> (<tool>) 再接承诺句。
默认本地待发布稿；推送、发帖、关单须用户当轮授权；发帖用 --body-file，发后 GET 回读。

收尾：编年当日分册（journal/编年/）追加轮次、索引更新行；报告写实际完成、未跑项、本轮不自信的点。
```

> 校注（2026-11-07）：上方「验证」「交付」两段的 `hunt-<轮次>/` 2026-11-06 起为 `hunt-YYYYMMDD/`（见 [11](11-狩猎轮机制.md)），旧目录保留；「推送、发帖、关单须用户当轮授权」，2026-10-24 起以 [fork/AGENTS.md](../../../../AGENTS.md) §3「发布权按形态分」定版为准（子智能体自检→推 fork→发帖→GET 回读，主线程事后复核）；本句保留为无自动化授权会话的默认。

## 并行狩猎循环提示词（2026-10-23，hunt57-61 后迭代；4 子智能体·即完即发·持续接单）

多波次持续接单的开场模板：贴进新对话即可复用。与「单 issue 模板」的区别是编制——主线程只当指挥与复核，4 个子智能体各占一个 worktree，**修完一单立即独立走完复核→推送→发帖→回读，不等队友**；发完的子智能体自行领下一单或休息。维护者回合（review/合入/关单）出现时，处理意见优先于开新单。本版并入 hunt57-61 沉淀：回合全量扫描、任务书 v3（精确 Attribution+自检+禁 AI use 段）、消融三坑（-run 错配/目录级回退/基线错配）、老单专属开场、碰撞检查前置、供给端重派流程。

> 校注（2026-11-07）：下方模板中的编制（「最多 4 个子智能体并行」「主线不接单」）以 [11 狩猎轮机制](11-狩猎轮机制.md)为准（2026-11-06：2 子智能体 + 主线程亲自下场），原数字保留为当时版本；选题「测试稳化（维护者亲单最稳）」2026-10-25 起不适用，维护者亲单不接，见 11 选单正典；第 7 条 `hunt-<NN>/` 2026-11-06 起为 `hunt-YYYYMMDD/`，旧目录保留。

```text
你在 magpie 贡献工作区持续狩猎接单。基线：cd fork/magpie-hub/magpie && git fetch upstream main，记录 SHA。
先读 docs/README.md 分工表、handbook/05 §2–§6 与 §4.10 命中族、handbook/10 避坑清单；状态只信本轮 GitHub。

开场（主线，三步）：
1. 哨兵回合扫描：台账索引在途单逐个查最新评论——维护者/审计者意见=P0，处理优先于开新单
   （全量扫防漏网，#2813/#2814 教训）。禁 PR 政策（b91569d3 只收 collaborator PR）：被要求
   开 PR 时回帖说明 fork+git am 形态、authorship 不变。
2. 在途分支套用性批测：git apply --3way --check 批测——干净=不动；3way 可合=观察；真冲突
   =rebase 车道（语义复验优先于机械 cherry-pick：逐族判定上游新提交是收窄还是覆盖，覆盖则删族收窄）。
3. 选题输入：候选池表（docs/journal/账册/候选池.md，排除区必读）+哨兵扫新报窗口；老存量用词边界
   grep -E "#N([^0-9]|$)" 逐号排查上游已修。
4. 参考规范：接单/PR 形态遇本提示词未覆盖的问题，参考成熟开源规范结合实际适配——cc-switch CONTRIBUTING 贡献指南与 magpie docs/contributors.md（Acceptance criteria/Watched 标准）。执行声明：本工作全靠大模型接单与修复，不脱离 AI；但每一单必走完整测试与验证程序，自测确认后才提交推送——质量由流程保证。
子智能体供给端 token 错误重派前先查 worktree 遗留：死于读题期=恢复干净直接重派；留半成品=先还原。

编制：最多 4 个子智能体并行，每路独占 worktree（git worktree add -b fix/<N>-<slug> /tmp/… <记录的SHA>；2026-11-01 定版，老分支不改名）。
一路修完立即**自行**走完「自检→推 fork→发帖→GET 回读」（2026-10-24 定版：先做完先发布——不等队友、
不等主线程门卫；A 早完成 20 分钟就早发 20 分钟，绝不凑批）；发完的子智能体自行领下一单或休息。
主线只当调度/排雷/派单/事后复核/记账，**不接单、不维护老单、不亲自处理在途回合**——这些一律开子智能体（2026-10-24 定版）。

选题（七问闸，任一不过即弃；目标远、质量闸不松，零新帖也是正常结果）：
- 优先命中族（handbook/05 §4.10）：gateway 流式/翻译/失败分类边界；状态绑定语义（compaction/affinity/rest 作用域）；
  provider 账号额度凭据；测试稳化（维护者亲单最稳）；审计构造+根因实验；Windows/词法。
- 避开：报告者未复现无日志（Q2 必挂）；需真实账号/专属环境；GUI 视觉（例外：app.js 数据绑定类
  逻辑缺陷可用 internal/gui/tests/*.test.cjs 基建测试）；功能请求/设计拍板；大架构改动；
  方案先行单（语义拍板权在维护者的先评论不接）。
- 让位：维护者 48h 自修区、报告者自带分支/patch、他人已认领、上游已自修（必查）、
  我方自占坑/在途同区域（候选池排除区必读）；观察单=维护者背书根因者有自修竞争风险。
- 只接 0 评论、可本地确定性复现、维护者未占坑/回应 的单；c>0 必读评论。
  接下即发 `take` 评论占坑再动手（防抢单，#2593 先例）；已有我方沟通的单不重复占坑，
  按「先做+自测 → 推 fork 分支 → 发评论」回帖（2026-10-22 用户定版）。

子智能体任务书必含（缺一不发）：
1. 读全 issue+全部评论+当前 main 代码；先列假设再动手；同区域在途单先读对方全帖+分支 diff
   判互补/同面（碰撞检查前置，#3197/#2873 先例）。
2. 老单（创建超一周）专属：行号必重核、同域提交逐读、修法对照现行架构不照单硬落、开场说明
   老报告已复核仍成立；报告者事实可纠错（如实标注）。
3. TDD：RED→最小修复→GREEN；消融前必须先提交（未提交先消融=checkout 覆盖工作树修复）；
   消融只回退产品文件（测试必须保留，目录级回退=假绿）；消融基线=分支父提交（非旧上游 SHA）；
   消融输出必须看原文——grep 计数会掩盖 build failed；双保险修法须组合消融（两路同禁）。
4. 复跑/消融前先 grep -n '^func Test' 取精确测试名（-run 模式错配=假绿，复核侧也中过）。
5. Watched 三查：手动打破看新测试回红；rg 兄弟面列改/不改理由；失败读取变成什么；热路径回答代价。
6. 矩阵：定向+改动包全量（-tags nogui）+race（相称时）+gofmt+vet×3+build×3；预存红如实标注。
7. 英文稿五段+Verification 表（行间禁空行）+format-patch 内嵌；零中文；产物落 docs/hub/magpie/issues/hunt-<NN>/（第一层只允许 hunt-<NN>，同轮多车道全收入该轮目录）；
   **禁设 AI use 段**——帖内嵌 patch 时模型名只在 commit 尾注出现一次。
8. 尾部三件套用精确文本+稿成自检 grep 三项各≥1：
   `**Attribution**: AI-written; I've read the whole diff and the tests pass. Please keep the author (`ggbdpq`) or add `Co-authored-by: ggbdpq <ggbdpq@gmail.com>`.`；
   `<details><summary>patch: … (#N) — git am applies it as is; SHA-256 first 16: <哈希前16></summary>`；
   `Branch with the commit: [<分支>](https://github.com/ggbdpq/magpie/tree/<分支>) (head `<sha>`).`
9. 提交一律 git -c user.name=ggbdpq -c user.email=ggbdpq@gmail.com commit -F <file>（主 clone
   user.name 已损坏）；主 clone 只读，编辑一律绝对路径。
10. 报告格式：SHA+身份行/patch sha256 前 16/RED GREEN 原文/消融变异/矩阵/兄弟面清单/三件套自检输出/不确定项。
11. 发布权归子智能体本人（2026-10-24 定版）：自检→推 fork→发帖→GET 回读全部自己做，不写 journal
    （主线程收口统一记，防并发写文件）；报告主线程只交回帖 ID/SHA/验证证据/不自信的点。

子智能体发帖前自检（不照单全收自己）：定向重跑+消融回红（只回退产品文件、保留测试、基线=分支父提交，原输出逐行看）；
草稿八项 grep：分支链接/Attribution 精确行/GLM 计数须=patch 块内计数/零中文/围栏配对/无裸尾注/
format-patch 嵌入/无 AI use 段。套件抓回归→尊重既定契约收窄，不软化既有钉死测试。
主线程事后复核（发布权下放后）：GET 回读已发帖+抽验消融/矩阵关键项+统一记账（索引/编年/候选池唯一写者）；
发现发布质量问题走帖内勘误回帖处置（不删帖不编辑历史）。任务书里的背景事实子智能体必须实测复核，
与实测冲突以实测为准修正交付（#3380 R1 先例：主线程给的"已合入 main"被 compare API 证伪，回帖改为只写可证实部分）。
子智能体超时≠没做完：先查 worktree 再定重派或自做；/tmp 会被周期清理——worktree 用完即推即清。
紧急沟通（2026-10-24 定版）：占坑冲突/收编悬置/等拍板拖进度→Discord/Twitter 直接找原作者 yetone；
GitHub 帖内点名维护者必须写 @yetone，否则通知不到。

即时发布：推分支 ls-remote 终验→发帖前 fetch 查重（上游新提交零触及目标文件+评论数不变）→
--body-file 发帖→GET 回读校验（POST 响应解析失败≠没发，先 GET 核实再决定，绝不直接重发）。
cause 不收敛的侦察单如实放弃不凑 patch（#2984 先例）；诊断有价值的发诊断帖；正文点名的 Left 项
要主动查证闭环（#3165 Kimi 先例）。

书记即时记账：每单发布后立即更新 journal（索引结局、编年当日分册、成本与采纳统计），不攒批；
**文件追加后必须回读**（heredoc 挂错命令=条目静默丢失）。
维护者回合出现时：处理 review 意见优先于开新单，改完 force-push 回帖。
