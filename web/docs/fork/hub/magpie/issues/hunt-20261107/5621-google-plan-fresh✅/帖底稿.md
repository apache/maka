**Root cause** (the reporter's analysis, confirmed): `googleAccount.quota` (internal/provider/google.go:1332) took Code Assist's project plan only when the quota carried no plan at all (`q.Plan == ""`), so the non-empty plan saved at sign-in kept overwriting the fresh one forever — `loadCodeAssistReply.plan()` had already picked the paid tier correctly, and the stale name still won.

**The fix** (theirs, applied as posted): the project's non-empty plan takes precedence (`p.plan != ""`), the saved plan only falls back when a reading can't name one. No extra request, no change to the hourly tier refresh; a failed refresh keeps the last known value.
