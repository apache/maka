## 根因
startRun（internal/gateway/claude_subscription.go）对每个并发调用立即启动 claude-tui-helper → 完整 Claude Code；启动数无界。并发冷启动互相拖慢（单启动 <45s，6 个 >45s）→ 全部 tuiNoStart → 502 → gateway rounds + 调用方重试再入同一无界启动堆 → 正反馈。claudeRoom(#2956) 限"活进程数"不限"启动中数"，64GB 机器 room 不构成瓶颈。

## 修复
interactive 启动闸 tuiStarts（chan 信号量容量 1）+ tuiStartTurn(ctx, what)：tui run 在 helper 启动前取 turn，initialize 应答（=prompt 显示）后经 defer 归还（成功/失败都归还）；失败的启动结束后才放行下一个，重试落在"只剩一个启动要做"的机器上。-p run 不取 turn；已运行的 run 不占 turn；排队等待打日志（对齐 room.take 风格）；等待受请求 ctx 控制（调用方断开即出队）。报告者 Ask 1/2 由闸直接实现；Ask 3（45s 加长）不做——闸消除竞争后单启动窗口足够。
