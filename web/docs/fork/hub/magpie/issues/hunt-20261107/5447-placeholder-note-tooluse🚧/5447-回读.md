@yetone Masking's placeholder note was appended at the end of the earliest message holding a placeholder, whatever that message ends with. When that message is an assistant turn ending in a `tool_use` — its `tool_result` riding in the next user message — the note landed between the two, and Anthropic-protocol upstreams that keep the tool exchange strict turn the request away. @aabbccgg hit this on DeepSeek after upgrading: 30 of 30 masked requests got `messages.N.K: `tool_use` ids were found without `tool_result` blocks immediately after`, none of 13 unmasked ones did, and their report pins the cause exactly.

**Root cause**: `internal/gateway/placeholder_note.go`, `withNoteAnthropic` — the earliest message holding a placeholder gets the note via `appended(body, c, textPart("text"))` when its content is an array (line 128 on `710f0290c`), without regard to the message's role or trailing blocks. A text block appended after a trailing `tool_use` breaks the `tool_use` → `tool_result` adjacency the next message has to complete. In since e8d42c02 (v0.1.2154).

**The fix**: following the reporter's own analysis (they offered before-the-first-`tool_use` or in-the-next-user-message after its `tool_result`s; the in-message placement is the steadier one, since it reads only the message's own blocks — no guessing at the next message's shape — and keeps the note on the earliest placeholder message, so it stays put on later turns and the cached prefix holds), the note now goes before the message's first `tool_use` when the message ends with one: a small `beforeToolUse` check and an `inserted` helper beside `appended`/`prepended`; a message that doesn't end with a `tool_use` is told exactly as before. Sibling faces checked: the Chat (OpenAI) form can't hit this — an assistant turn's tool calls ride in a `tool_calls` field beside `content`, so text appended to `content` can't come between a call and its result; the Responses form already steps past a call's run of outputs for this same adjacency; Gemini's `parts` has no evidenced adjacency rule, left as it is.
