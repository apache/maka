# #5618 Usage/Sessions 慢加载调查（2026-11-07 晚，Discord GrayRabbit 报告+用户本地同感）

- 形态：调查单（机理实测+开 issue 要报告者环境）——反馈环无法复刻其量级，按 diagnosing 纪律停在要数据，不盲修。
- Issue：https://github.com/yetone/magpie/issues/5618（英文机理+实测+要三条）

## 实测（本机 darwin/arm64，294 sources/250MiB，codex 249MB×14）

- walk（CallSourcesAndCodexIdentities）：**444ms**（线性于文件数，每次 rebuild 都跑）
- LedgerPage 进程内首查 **390-420ms** → 后续 **2-3ms**（pages 缓存）
- **touch 一个 rollout 后重查仅 6.6ms**——增量 shard 只重读被改文件，**H1（version bump 全失效）证伪**：缓存链（callCache 增量 shard+requestCache pages/heat/single-flight）健康
- 前端 Requests rows 有 cap（100/500）

## 放大因子（解释"很慢很慢"的环境变量，均无法本机复刻）

1. 文件数线性：代码注释口径 12k rollouts≈150ms/rebuild；数万文件或冷盘倍乘
2. Windows per-open Defender 扫描：增量 reader 仍要 Open+hash 每个源
3. web 模式进程模型：新会话每页付冷读；Usage 页多端点（page+heatmap+sessions）冷读重叠

## 要报告者三条（写在 issue）

OS+版本；会话文件数与字节；最慢页面+DevTools 时序+二次打开是否变快（warm 判据）。
