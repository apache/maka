# #5590 根因与修复（车道 D，2026-11-07）

## 单况

- 报告者 cgsme（老报告者 #5556/#5555），0 评论，OPEN。Windows 双 Codex 账号（Plus、Prolite），版本 0.1.3079 与 main 30ae0e3f9 双确认。
- 现象：同一账号同一额度条，收起显示 7 天剩余 100%，展开显示 57%；展开态在曲线上选了「历史周期」（11/3 09:24 – 11/5 20:23，最后采样 11/5 20:20）。

## 根因（口径源头=前端 renderQuotas 一行）

#2009 历史周期功能（56fcd1dc2）引入的周期源判定写作：

```js
const brief = several && !usageAcctOpen(sub, subs);
const history = !brief && quotaHistoryView(sub);   // ← 门控
const shownSub = history ? quotaHistoryCard(sub, history) : sub;
const [meters, every] = history ? [quotaWindows(shownSub), null] : familyQuota(sub);
```

- `!brief` 把折叠态强制回当前周期 `familyQuota(sub)`；展开态用 `quotaHistoryCard`（所选周期最后采样，`used = 100 - last.left`）。
- 选择存 `quotaCyclePicks`（Map，account key → cycle id），折叠/展开（`usageAcctFold`/`usageMore` → `setUsageAccts` → renderQuotas）只改 `magpie.usageAccounts` 展开态，不清 pick。
- 于是同一额度条在收起（当前 100%）/展开（历史 57%）间隐式切换，无任何提示。正文三个 app.js 锚点（旧树 blob 30ae0e3f9）与当前 tip 同形，仅行号平移（tip 784113472 上=L15992-15995，修复后 15996）。

## 口径判定（以报告者描述为准绳）

展开的 57% 是用户在曲线菜单上**显式选择**的周期（#2009 交互），收起后无提示地变回当前 100%——报告者期望原文：「同一账号的额度条继续使用已选择的周期，并在简略视图保留可辨认的“历史”及周期提示」。统一方向=折叠态继续沿用所选周期；不采用反向方案（折叠清 pick/强制当前），那会丢用户选择且与「收起/展开只改显示细节」相悖。

## 修复（a78082c61，1 行 + 注释）

```js
const history = quotaHistoryView(sub);   // 删除 !brief 门控（口径源头单点统一）
```

- 两视图共用同一 `quotaHistoryView` 判定：quotaRange === "cycle"、无 error、有 readings、有 pick 才走历史；其余两视图同样回当前周期。
- brief 视图自身设计不变（名字+数字+条，时间信息在 tooltip——CSS `.quota-windows.brief .quota-reset { display:none }` 隐藏「Cycle ended」行，tooltip `quota.title` 仍是「Last reading {when}」，可辨认历史读数）。
- brief+history 下 `every`（Every model 按钮）、keyLine、own、checkin、daily、balanceRow、spend、read、resets、policy、credits 各行按既有 `!brief`/`!history` 门自然隐藏，与展开+历史的呈现一致。
- 不在渲染层各补各的：唯一的周期源判定点就是这一行，兄弟面全查见 兄弟面.md。
