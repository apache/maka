@yetone Phoenix0531-sudo reported (#5631) that giving a local stdio MCP server from the Library to Codex wrote a self-contradictory entry into `~/.codex/config.toml`:

```toml
[mcp_servers.ms]
url = "http://127.0.0.1:3425/mcp/run/ms"
type = "stdio"
```

The entry loads, but the server is unusable in Codex (their `codex mcp get ms` even reads it back as `transport: stdio` while the address is HTTP), and the same stale key survives any later sync. The `url` form itself is what a shared server is given to Codex on magpie as (#3885: magpie runs the command itself while a session uses it, so the reporter's second expectation is the landed on-demand behavior — their `os error 10061` is Codex connecting while nothing was listening on the gateway), and keeping the raw stdio trio stays available as the server being kept direct (#4382). What should never survive the rewrite is the `type` of the entry's former shape.

**Root cause**: when Codex on magpie takes a command's server over, `runVia` (`internal/library/mcp_run.go:132`) rewrites the entry as the gateway's url and `merged` (`internal/library/mcp.go:1417`) keeps every old key magpie doesn't own. `type` is neither among `owned[fmtCodex]` (`internal/library/mcp.go:1332`) nor among `codexRefused` (`internal/library/mcp.go:1470`), so the user's hand-written stdio entry's `type = "stdio"` outlived the entry's becoming a URL. Codex reads no `type` at all — `RawMcpServerConfig` has no such field (codex-rs/config/src/mcp_types.rs), the config docs take none, and codex-cli 0.167.0 here ignores the key when loading and drops it when Codex itself rewrites config.toml — but the entry contradicts itself all the same, and the reporter's codex displayed it as stdio.

**The fix**: `codexRefused` now names `type` from either transport, so `merged` drops it when magpie writes the entry, and `behind` (`internal/library/mcp.go:528`) reports an entry still holding one so the next sync — and a project's `.codex/config.toml` — rewrites it, following the reporter's own analysis that the contradiction is the bug. The reporter's third suggestion, writing `type = "streamable_http"` for gateway entries, would only move the foreign key: Codex's config language has no `type` for `mcp_servers` at all, so the clean shape is the url with nothing beside it that Codex doesn't read.
