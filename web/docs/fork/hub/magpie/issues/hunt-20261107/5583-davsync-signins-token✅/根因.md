# 5583 根因

单况：skalitz-wolf 报「Sign-ins sync（WithSignIns / signIns:true）把单次旋转型 refresh token 复制到第二台机器，两机竞速刷新，输家永久掉线」。其更正评论（2026-11-07T08:13Z）撤回「sync 整体镜像旧 generation」说法，确认上游已按 account 合并（provider.MergeSignIns → ApplySignIns，later renewed stays；RestoreSignIns 不写回旧值）；真正的问题=复制本身 + 无更新 generation 可自愈。本单以其更正评论为前提。

## 机理

- `provider.CollectSignIns`（internal/provider/signins_carry.go:212）把 plugin-auth.json 的全部条目收进 sealed backup（`WithSignIns` / davsync collect，`signIns:true` 时）。
- MiniMax Code / Qoder 的 refresh token 一次一用：每次 refresh 返回新 refresh token、旧 token 作废（invalid_grant）。
- 两台机器各持一份副本后，各自在 `expires - refreshLead` 到期时刷新（gateway keepalive internal/provider/plugin_keepalive.go；单机内多进程有锁 internal/plugin/host.js `lockRenew`，plugins #331——**跨机器无锁**）。
- 竞速：一台刷新成功拿到新 generation，另一台 invalid_grant → host `renewLocked` 失败路径 `unrenewed.set(key, {gone:true})` → `notePluginLapse`（internal/provider/plugin_accounts.go:474）标 Lapsed（logins.json）→ keepalive 永久跳过（plugin_keepalive.go:89 `l.Lapsed != ""`）。
- 自愈不可达：sync 虽会随后把赢家的新 generation 合入输家的 plugin-auth.json（MergeSignIns newer wins），但「无人在用的机器」不再发起刷新（keepalive 跳过 Lapsed），Lapsed 标记无清除路径（只有请求 2xx / OnSignIn "renewed" / 重登能清）；且报告者实测终态=两份同代已过期、sync 路径上不存在任何更新 generation（第二台机器停用后无人持活 token）→ 只能设备重登。循环：A 登 → sync 复制到 B → 竞速 → 输家掉 → A 重登 → 下一 token 生命周期重复（「约一天一次」）。

## 修法（报告者 fix 1，following the reporter's own analysis）

- auth hook 声明 `rotating`（与 keepAlive/refreshLead 并列）：host.js `rowOf` 透传 `rotating: a.auth.rotating === true` → `plugin.Provider.Rotating`。
- 发送面过滤：`CollectSignIns` 对 `s.Plugins` 按 `rotatingPlugins()`（plugin.Cached 中 Rotating 的 provider id 集，`plugin.ProviderOf(key)` 对齐）剔除。
- 接收面过滤：`SignIns.records()` 同一过滤 → MergeSignIns（lr/rr 双侧）、Hashes（sync-state prev 记账）、RestoreSignIns 全部一致；旧备份/旧 sync 里已带的 rotating 条目不再被 put 进本机。
- 收敛语义：本机 sign-in 不动（signed in 的机器保持）；已上服务器的副本经既有 removed 语义在每台机器下一次 sync 时退出携带集；跨机不再复制。旋转型 credential 回归「一台机器一个」。

## 语义边界（兄弟面对照后定）

- records() 过滤同时作用于 Hashes：prev 不再记账 rotating id → 旧 state（升级前 sync 留下 prev）+ 旧服务器文件双在时走 `was && p == r.hash → skip`，不误 put 不误删本机。
- `plan.remove` 仅出自 lr 循环；rotating id 不在 lr → 本机 plugin-auth.json 永不被 sync 删除。
- AuthEntries/EditAuth 不过滤（读改写路径，过滤会误删本机 sign-in）。
- keepalive 不受影响：单机刷新仍进行（keepalive 文档既有的 keepAlive:false 语义不变）。
- 插件未声明 rotating 前行为完全不变（minimax-auth 0.2.3 需插件包配套跟进声明）。
