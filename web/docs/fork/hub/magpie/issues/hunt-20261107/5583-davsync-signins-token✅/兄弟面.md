# 5583 兄弟面 rg 全查

同族点逐个列出（rg 全查：AuthEntries/records/Hashes/WithSignIns/CollectSignIns/RestoreSignIns/MergeSignIns/ApplySignIns/applyPlugins/applyLogins/keepAlive/Renews/RenewLead/rotating），改/不改均给理由。

## 改

| 点 | 理由 |
| --- | --- |
| `plugin.Provider`（internal/plugin/providers.go） | 旗标声明落点，与 Renews/RenewLead（auth.keepAlive/auth.refreshLead）并列——报告者明示 "alongside refreshLead" |
| host.js `rowOf`（internal/plugin/host.js:2484 区） | auth hook 的声明透传面，与 renews/renewLead/single 同排 |
| `CollectSignIns` 发送面（signins_carry.go） | 所有携带（backup.WithSignIns → davsync collect / CLI backup_cmd / GUI backup / auto 备份）的唯一生产口，一_filter 全覆盖发送 |
| `SignIns.records()` 接收面（signins_carry.go) | MergeSignIns 的 lr/rr、Hashes（davsync st.SignIns prev 记账）、RestoreSignIns 全部经 records() 派生——单点过滤保证四处一致（含旧 prev/旧服务器文件的收敛路径，见根因.md 语义边界） |

## 不改（逐个理由）

| 点 | 理由 |
| --- | --- |
| `plugin.AuthEntries()` / `EditAuth`（carry.go） | AuthEntries 同时服务 EditAuth 的读改写；在此过滤会在每次 auth 编辑时误删本机 rotating sign-in。过滤必须在 carry 语义层（provider 包），不在文件读取层 |
| `plugin.readAuth()`（providers.go） | providers 列表/账号展示路径，与携带无关 |
| `applyPlugins` / `applyLogins`（signins_carry.go） | 只写 plan.put；plan 已在上游过滤。applyLogins 对 logins 的 Lapsed 覆写是内建账号既有语义，不在本单范围 |
| keepalive（plugin_keepalive.go）`l.Lapsed != ""` 跳过 | 单机刷新语义正确且必需（本机 sign-in 保持活性）；跨机竞速根因在复制，不在刷新。keepAlive:false 的既有逃生口保持 |
| host.js `renewal`/`renewLocked`/`lockRenew` | 单机内跨进程锁+重读自愈（plugins #331）既有且正确；跨机锁不存在也不该在 host 层造（无共享存储）；本单修复制面 |
| davsync.go hashes/bothSides/merge 主循环 | 经 `SignIns.Hashes()` 间接过滤，无需改；`Config.SignIns` 开关语义不变 |
| GUI syncfiles.js / autobackup.js / app.js | UI 只传 signIns 总开关，无 per-provider 面；"warn in UI" 是报告者的退让选项，非最小根因修法，不做 |
| `provider.NotSignedIn` / plugin_accounts.go Lapsed 标记/清除 | 掉线标记与清除路径，不属携带面；其「无更新 generation 不可自愈」的终态由本单从根上（不复制）消除 |
| 内建订阅账号（logins.json，codex/claude 等） | 非 plugin auth hook，无声明面；其合并已按 later-renewed（报告者确认上游已实现），且报告者观察的分界线是「refresh token 是否轮换」在插件族；不扩面 |
