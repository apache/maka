# #5593 根因：Codex 账号 Free→Plus 后 token 刷新不更新存储的 plan

## 报单形状（OutmanSay，magpie 0.1.3225 macOS）

- logins.json 里该账号 `plan: "free"`，`auth.last_refresh: 2026-11-06T12:15Z`（刷新已发生）。
- 同一条记录当前 access_token 的 JWT claim `https://api.openai.com/auth.chatgpt_plan_type = "plus"`。
- `magpie quota` 实时显示 plus；但 routing jsonl 里 278 次 Codex 请求全按 `plan":"free"`、rank 空，排在另一个 Plus 号后面。
- 退出重登后 plan 变 plus —— 症状钉死在刷新路径，不在登录路径。

## 根因

saved Codex 账号的刷新写回点 `internal/provider/logins_on.go` `renewSaved`（写回循环）只更新三样：

```go
ls[i].Auth = auth
ls[i].Renewed = time.Now().UTC().Truncate(time.Second)
ls[i].Lapsed = ""
```

`Plan` 不在其中。`savedLogin.Plan` 只在登录构造点从 ID token claim 取一次（`codexLoginIn` logins.go:815、magpie 自己的 signin signin.go:880、import 的 `codexLogin`），之后 plan 升降级只能经刷新到达 magpie，而刷新写回不带它。

路由读的正是这份存值：`internal/gateway/routing.go:2419` `seats[i].FreePlan = c.p.Account != nil && provider.FreePlan(c.p.Account.Plan)`（另有 `gateway/cap_near.go:101`、`gateway/fallback.go:918` 的 `freeOnChatGPT(model, a.Plan)`、`gateway/middleware.go:124`、`logins.go:776/792` `CodexSignInPlan/Who`、`login_usage.go:379` 卡片）。写点修对后读点全部自然正确，读点零改动。

## 同族先例（修法依据）

- **SiWC（chatgpt-api）刷新**：`chatgpt_api.go:447-452` `siwcFresh` 写回时 `if p := siwcPlan(c); p != "" { ls[i].Plan = p }` —— 同一 savedLogin 写回形状，plan 一直同步。本修法与它完全同构。
- **Copilot entitlement 刷新**：`copilot_entitlement.go:58-63` 也同步 plan。

## 修复（commit b6e48befe，3 文件 +112）

1. `internal/provider/account.go`：新增 `codexPlan(a codexAuth) string` —— 先 ID token 后 access token 读 `chatgpt_plan_type`，读不到返回 ""（与 `siwcPlan` 同序同容错）。
2. `internal/provider/logins_on.go` `renewSaved` 写回循环：`json.Unmarshal(auth, &a)` 成功且 `codexPlan(a) != ""` 时更新 `ls[i].Plan`；新 token 不带 claim 时存值原样保留（同 siwc 先例语义）。
3. `internal/provider/codex_plan_refresh_test.go`：`TestSavedRefreshUpdatesPlan`，fake 层复现报单原始形状。

## 不修的相邻路径（兄弟面.md 详列理由）

- `account.go` `codexTokenRenewing`（Codex 自己 auth.json 的刷新）：写的是 live sign-in 非 savedLogin；held copy 的 plan 在 switch away 时由 `codexLoginIn` 全量重建（从刷新后 token 取，正确）。
- `keepalive.go:264` `renewClaude`：Claude 的 plan 同步在 `claude_dirs.go:452-453` `takeClaudeDir`（`l.Plan = c.OAuth.SubscriptionType`）已存在；#2838（Claude 升 Max 仍显 Pro）是另一单，根因在 Claude 侧同步链条，不在本单形状。
