## 结论

- **commandcode 是唯一「agent 格式带字段（contextWindow/maxOutput）而 magpie 不写」的 writer**，与报告者引 PR #347 的官方 survey（output limit 维度 commandcode 唯一缺）相符；窗口维度本次全扫亦无第二例。
- 车道 C 的 #5573（alma writer 同型缺档）**互查结论**：本车道改动前查了 `/private/tmp` 无 `mg-5573` worktree、`git log --all --grep=5573` 无相关提交、worktree 列表无 5573 分支——车道 C 开工时无留痕；且 #5573 改 alma.go，本单改 commandcode.go，**文件不相交**，无同文件竞写。alma 自身（alma.go:336-340）窗口/输出已写，#5573 的具体缺档面在 alma 的其它键，与本单修复无语义重叠。**终态补充（本单发布时）**：车道 C 对 #5573 最终让位（修复已 landed in upstream/main `140efc8f7`，见 `../5573-alma-functioncalling-让位/判定.md`），未出任何 alma writer 产品补丁——与本单零交集，互查结论不变。
- 调用面：`ccProviderJSONAt` 仅 2 个调用点（commandcode.go:30 闭包 → Sync 与 Field.Set），WSL 侧经 `commandCodeIn(at place)` 共用同一函数，无第二实现；`theirsKept(..., "models")` 整 map 重写保证存量文件下次 sync 自动补齐新字段。
