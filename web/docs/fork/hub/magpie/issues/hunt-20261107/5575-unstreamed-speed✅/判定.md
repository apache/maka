## 假设清单（动手前列）
- H1 非流式无 TTFT → usage.DecodeOf ttft<=0 返回 (0,0) → Requests 页速度列为空。✓ 证实（usage.go:711+）
- H2 noteTrySpeed 拿 (0,0) → noteSpeed ttft<=0 直接 return → speeds 无记录。✓ 证实（speed.go:59-62）
- H3 routes.Fastest 以 TTFT>0 判 measured → 非流式 key 永远 unmeasured；全池 unmeasured 时 ProbeEvery 不生效（需同时有 measured 与 unmeasured）→ 排序退化为列出顺序第一个。✓ 证实（fastest.go:68-71,112）
- H4 报告者场景=全非流式流量 → 所有 key"最近没回答过"→ 总选第一个。✓ 与报告一致
- H5 用量页（DecodeOf/前端 decodeOf/ledDecode 同款）不改。✓ 理由见兄弟面

## 根因
Speed first 的测量链对非流式回答整体失灵：无首字 → DecodeOf 无解 → noteSpeed 不记 → Fastest 视为 unmeasured。调用方全部非流式时全池永远 unmeasured，probe 也不触发（需要 measured 存在），路由意图退化为顺序第一个——报告者所见。

## 修复（speed.go + routes/fastest.go）
1. noteTrySpeed：DecodeOf 无解且 TTFT<=0 且 out>0 且 Millis>0 → fallback tokens,w = out,Millis（报告者口径：输出/总耗时；比流式口径粗——流式只数首字之后的 token，够排序用）。
2. noteSpeed：允许无 ttft 的 tps-only 样本；新增 speedRec.fresh()（两样本较新者）用于 speedMost 清理与 speedOf stale 判定；ttft/tps 各自按各自样本时间判 stale。
3. Fastest：measured 判据 TTFT>0 || TPS>0（Estimate 对 ttft=0 自然落入纯 tps 权重 200*1000/tps）；顶部 doc 更新。
