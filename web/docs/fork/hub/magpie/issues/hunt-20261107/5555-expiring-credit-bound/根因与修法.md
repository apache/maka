# #5555 根因与修法：临期自动用卡未绑定已检查的 credit_id

单况：OPEN，报告者 cgsme（2026-11-06），零评论，无 open PR，无交叉引用；同域扫描（`-S stillExpiring`、codex_expiring.go 历史：da46cd21f #718、04ec2d710 donutsone、62fc1b4b5 #2226、995f84a0f、d4a221f79）无收编。

## 根因

临期自动用卡链路（internal/provider/codex_expiring.go @ 665b9aff1）对同一账号的卡列表读三次，但只有前两次参与判定：

1. `expiring.check` 的 `look()`（:279-284，经 `codexUserWindows`→`codexResets`）读到 `resets.Until`（soonest 卡的到期时间），据此判临期；
2. `spend()` 闭包锁内 `stillExpiring`（:292）重读一次，`spendExpiringNow` 复判——**只返回 bool**，不返回通过的卡；
3. `useCodexReset(ctx, who, ResetUsedExpiring)`（:295）传空 credit → `spendCodexReset`（codex_resets.go:293）第三次 GET 卡列表 `credit, _ = w.first()` → 直接 POST consume。

第 2、3 次读取之间卡 A 过期消失时，`first()` 落到卡 B（30 天后到期），B 从未参与任何临期判定，consume 照发。进程内 `autoReset` 锁挡不住服务端卡片自然过期。

## 实证（报告者注入序列真跑通，原始形状）

`TestExpiringSpendKeptToTheCreditChecked`（internal/provider/codex_expiring_test.go）：signIn + `SetCodexAutoReset`，httptest 假服务器——`/wham/usage` 恒 43% 用量（windowsUsed，不构成"耗尽提前用"）；`/wham/rate-limit-reset-credits` 用 `expireSoon` 开关控制：开时前两次读取返回 A(soon)+B(later)、第三次起只返回 B（A 过期消失）；`/consume` 捕获 credit_id。

**RED 原始形状（修复前实测）**：`spent 1 ("later")`——consume 请求携带 B 的 credit_id，且测试日志同刻打出 "codex reset about to run out: me@example.com used it: 2 windows started again"（用户视角"用了临期卡"，实际花的是从未通过检查的 B）。报告者"可触发的请求序列"逐项复现。

## 修法（following the reporter's own analysis：绑定+终止，复用现成 held 校验）

1. `spendExpiringNow` 返回 `(credit string, ok bool)`：ok 语义不变；credit=通过临期检查的 soonest 卡 ID（`resets.Each[0]`，Each 与 Until 同源同读、each() 排序 soonest first）；**Each 缺失（列表计数不一致）时 credit=""**。
2. `stillExpiring` 返回 `(credit, ok)`，读失败 `("", false)`（与旧行为一致）。
3. spend 闭包：`credit, ok := stillExpiring(...)`；`spendCodexReset(ctx, who, credit, ResetUsedExpiring)`——**复用指定卡路径的现成校验** `!w.held(credit)`（codex_resets.go:297，有名错误 "that reset is no longer on the account, so none was used"）：所查卡在消费读取时已消失 → 终止本次消费 → `check` 走 `retryResetLook` 5 分钟后重评（下轮若只剩 B，B 的 Until 不满足临期 → 不花）。credit=""（Each 缺失罕见态）时传空 → `first()` 旧行为，保底不回退（该态下 Until 仍来自同一次响应，风险窗口与修复前相当，不扩大）。

三子场景断言：A 消失 → consume 0 次；下一 pass 只剩 B → 仍 0 次（B 不临期）；A 回归（expireSoon=false）→ 恰好 1 次且 spentID=="soon"（检查与消费同卡）。
