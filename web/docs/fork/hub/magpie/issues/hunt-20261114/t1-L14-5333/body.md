Following up on my [earlier comment](https://github.com/yetone/magpie/issues/5333#issuecomment-6825154963) — thanks for naming your clients ("我用的 codebuddy code 和 Opencode" — you use CodeBuddy Code and OpenCode). Both are in the joined family I described there: neither has a "magpie's models only" position today. What magpie does to each, read at tip `a82bae2bd`:

**CodeBuddy Code** keeps its models in the `models` array of `~/.codebuddy/models.json` (`$CODEBUDDY_CONFIG_DIR`), which the CLI reads itself (internal/agent/codebuddy.go:6). magpie writes and removes only its own entries in that file, through the shared `buddyWriteAt` (internal/agent/workbuddy.go:228-234): connecting puts magpie's models into the array — and into `availableModels`, the same add-only way (workbuddy.go:385-391) — leaving every other entry and key as the CLI wrote it (workbuddy.go:216-217); disconnecting takes just the vendor-magpie entries out ("CodeBuddy's own: magpie's models come out of its list", internal/agent/codebuddy.go:93-94). CodeBuddy's own models always stay. The entries magpie writes are `sharedModels("codebuddy")` (workbuddy.go:256) — the models its providers' model lists in the editor pick for that agent (internal/agent/route.go:364,369) — so the editor's Select all / none / filter trims magpie's half of the join, but never CodeBuddy's own half.

**OpenCode** gets one provider block from magpie: `provider.magpie` in OpenCode 1's words, `providers.magpie` in OpenCode 2's (internal/agent/opencode_providers.go:18), written by `openCodeLike` (internal/agent/agents.go:1180). That block's models are `magpieModels("opencode")` (agents.go:626-627) — again the editor's selection for that agent. Nothing else in the config is touched: disconnecting removes only those two magpie keys (agents.go:1224), and OpenCode's own providers and their models are never edited, hidden or filtered by magpie. So what you see there is OpenCode's own list plus magpie's block, each side intact.

**Codex is still the only agent with the "magpie's models only" position**: set as provider (`model_provider = "magpie"`, internal/agent/codex.go:370), Codex's list becomes magpie's alone (codex.go:533); its beside and joined positions (codex.go:385,378) are the join forms. Extending that position to CodeBuddy Code or OpenCode would mean hiding the agent's own models — a feature for the maintainer to decide on, as I noted before; no provider-side setting changes it today.

Not verified: I don't run CodeBuddy Code or OpenCode, so this is from reading the source at `a82bae2bd`, not from driving either client.
