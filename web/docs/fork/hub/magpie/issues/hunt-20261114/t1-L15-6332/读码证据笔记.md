## 问题①：账号失败切换语义（SUB1 账号 A 失败 → 先试 SUB1 账号 B 还是直接切 SUB2）

**结论：先试 SUB1 内的账号 B，SUB1 可用账号试尽后才轮到下一块（下一组/下一成员）。账号失败切换的目标是平坦 try list 的相邻下一项，不感知组边界；组块相邻 ⇒ 同组内先切换。**

证据链：

1. **组展开为平坦候选列表**
   - `planLevel` `internal/gateway/fallback.go:764`（ordered 分支）：嵌套子组的成员在其父组列表的位置**整块展开**——fallback.go:930-944，`out = append(out, cs...)` @ 942；子组按自己的路由展开成多个 candidate（每账号/每 key 一个，`keys(m)` → `perKeyBarred` fallback.go:305）。
   - 每项 Via 记归属组路径：`w.Via = m.Groups()` @ fallback.go:950。
2. **主循环严格按列表序串行**
   - `for i := 0; i < len(cands); i++` `internal/gateway/gateway.go:3602`，`c := cands[i]` @ 3611。
   - 失败即 `continue` 到下一个 i（gateway.go:4502、4522、4705、4749 等多处失败出口）——没有「跳到下一组」的独立语义，切换=列表下一项。
3. **规则命中时 SUB2 排最前（turn 开始）**
   - 调用点 gateway.go:3289-3292：`if hit != nil && hit.Use != "" { cands, pl = ruleOver(hit, ms, cands, pl, aff) }`，注释 "the rule's member first, over whoever answered last, as a turn begins; within it, whoever answered last stays while it is of the rule's member, the member's others behind it (#1946)"。
   - `ruleOver` `internal/gateway/rules.go:758`：规则成员提到列表最前；SUB2 内账号失败先试 SUB2 其余账号，SUB2 试尽 fall back 父组自己的顺序（SUB1...）。unready 语义同判定帖所引 rules.go:49。
4. **重叠账号不重复展开（与 #5959 同源语义，也影响 try list 形状）**
   - `membersFound` `internal/provider/group.go:1330`；去重键 `key := WithMemberAccount(WithMemberEffort(p.ID+"/"+m, effort), acct)` @ group.go:1367（含账号维度，1363-1366 取 `MemberAccount(id)`）。
   - 第二次出现的成员进首次出现处的 `Also` @ group.go:1375-1379，注释 "asked once, where it was met first; a rule naming this group still finds it here (#2361)"。
   - ⇒ SUB1=[A,B,C]、SUB2=[B,C,P] 时 try list = [A,B,C,P]（B、C 只在 SUB1 块出现一次；SUB2 块只剩 P）。账号 A 失败 → B → C → P。
5. **两个补充语义（精确性）**
   - 被排除账号（已用 100%、429 休息、超上下文）是计划期排序（restLast `fallback.go:1336`、roomy/behindOverflow 等），不是失败切换的一部分；判定帖已覆盖。
   - 持有厂商缓存的原账号失败于 busy 类错误（overloaded/5xx/timeout，非 429）时原地稍等重试一次再移动：`keptAgain` `internal/gateway/affinity.go:1539-1558`（调用 gateway.go:5166）；429 照旧 rest+move。

## 问题②：路由图渲染——SUB1/SUB2 重叠账号只显示在一个 SUB 下

**结论：与 #5959 同根因（同一渲染语义），帖内归并指路。成员去重后只记录首次归属路径（数据层），trace 与前端都按该路径渲染（显示层），不展开 Also。**

证据链：

1. **数据层：成员只有一份，归属首次出现的组**
   - `membersFound` `internal/provider/group.go:1330`：去重键含 account（1367）；重复成员进 `Also`（1375-1379），注释同上（#2361）。
   - `Member.Groups()` `group.go:477-483` 只读主路径 `m.Via`，**不含 Also**；`Member.Also` 语义注释 @ group.go:426-430。
2. **trace 组快照：每成员一条首次归属路径**
   - `groupRef` `internal/gateway/trace.go:283-305`：`ref.Via = append(ref.Via, strings.Join(m.Groups(), ">"))` @ trace.go:291；Subs 收集自 `m.Via` 主路径（293-299，seen 去重）。不遍历 Also ⇒ 共享成员的 trace 行只带 SUB1 路径。
3. **前端 Routing 页按 via 挂载**
   - 数据来源：`/api/gateway/trace`（client.js:5791）、`/api/gateway/route?id=`（client.js:3676）——trace 驱动渲染。
   - `row.path = ways ? [wayAt.get(id), ...(row.w.via || [])] : row.w.via || []` @ client.js:2750；`wiresTo` 按 via 逐级找子组 wire @ client.js:2552-2564（2555-2560）。via 只有 SUB1 路径 ⇒ 重叠账号只画在 SUB1 下。
4. **#5959 对比（同根因判定）**
   - #5959（fengzhangxian，2026-11-10，open，维护者未回应）：模型级共享成员「只显示在前一个组，后组成员静默缺失」。其自带静态分析（commit c2c2c82）三处：fallback.go 候选构建时把首次归属写进 Via、trace.go 组快照只遍历主成员路径不遍历 Also、client.js 按 via 建立子组与动画路径。
   - 本单读码（tip 65f745dd4）与其一致；差异仅在成员类型：#5959=模型成员（不含账号维度），#6332=账号成员（去重键含 account）——同一 membersFound/Groups/Via 管线的两个表现。
   - 定性口径：路由行为是 #2361 声明的设计（asked once, where it was met first；规则命名后组仍能找到共享成员，测试 rule_shared_test.go 守护）；**图上只画首次归属是同一数据语义的直接结果，是否有意改图属 #5959 在途讨论，维护者未表态——不重复定性**。
5. #2361/#2407 修复语义（判定帖已引）：规则命名后组时共享成员仍按该组顺序参与（`membersNamed` rules.go:586 读 Also；`homed` rules.go:652；`Member.In` group.go:437）——显示与路由脱钩，路由正确、显示单归属。
