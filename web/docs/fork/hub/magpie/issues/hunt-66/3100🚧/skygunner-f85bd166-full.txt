    test(provider): drain plugin callbacks before swapping sign-in observers
    
    The fakeco sign-in test can replace catalog.Changed while its own plugin
    refresh is still about to call it. Wait for Refreshed then Told before
    installing and restoring that global observer. Seed the fake's catalog
    locally so setup never needs a models.dev fetch.
    
    Adapt ggbdpq/magpie 47f78b9900c96d0282683600882b7f6001d4595a.
    The isolated fakeco test reports the named catalog.Changed write/read
    race over 200 repetitions, including with the local catalog seeded.
    With the waits, -race -count=200 passes. All three sign-in paths pass
    -race -count=20. The original behavioral assertions remain intact;
    production sign-in code is unchanged.
    
    Fixes yetone/magpie#3100
    Co-authored-by: ggbdpq <ggbdpq@gmail.com>
