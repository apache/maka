## 根因

- `Install()` 把 `http.DefaultTransport.Proxy = Func`（每次拨号实时读 settings），外面包 `Dispatch`。
- Test 的 through 请求 ctx 不带 `With` → `Dispatch.RoundTrip` 走 `route{}` 分支 → 直接用 `d.base`。
- `Func` 只在**拨新连接**时被问；Go transport 的 HTTP/1.1 池 key 含 proxy 地址（换代理自然重拨），但 **HTTP/2 客户端连接池按 authority 复用、查找先于拨号、不考虑 proxy**——切全局代理后经 A 建立的 h2 连接继续被复用。
- 与 issue 症状逐条吻合：`Describe()` 实时读所以显示 B；`throughLeg` 实测对端不匹配 → `Proxied=false` → `omitempty` 不输出；报告者对照实验（h2 共用 Transport 复用 A、h1 正确换 B）成立。

## 修法（最小，单口）

`Dispatch.RoundTrip` 每请求比对 settings proxy 签名（`globalMoved()`，`d.mu` 下记忆），变化则 `d.CloseIdleConnections()`（现成 seam，关 base + 全部 own 的闲置连接，含 h2 idle）。一次修好全部 8 处 Dispatch 消费方（DefaultClient/Test、gateway 上游 draws/uploads/sockets、workbuddy、MCP、mcpauth、update、pii 下载、library mcp_check）。in-flight 连接不动（Go API 边界，帖中如实说明）。热路径代价：每请求一次 `settings.Load()`（RLock + filememo 缓存读）+ 字符串比较。

## 不确定项 / 边界

- in-flight 边缘：旧连接仍有活跃流时新请求可能复用至其结束（Go `CloseIdleConnections` 语义）。
- 系统代理（macOS/Windows System()）变化不触发失效——issue 只报 settings 切换，Linux 无系统代理路径；同族但另案。
- 全 `GOOS=linux` build 的 wails 失败为环境预存（父提交树同样 10 处 `undefined: pointer`），已在帖中标注。
