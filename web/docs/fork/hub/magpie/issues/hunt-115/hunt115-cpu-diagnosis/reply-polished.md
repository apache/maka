# Discord 回复（润色版，可直接粘贴）

你好！41% 这个数还没法定案——magpie 空闲时实测基本是 0%（刚在干净环境采样验证过），所以应该是某条路径被你的使用状态触发了。花一分钟帮我确认几件事：

**1. 先跑这个，最能定位问题**（magpie 内置的性能采样，跑完把生成的文件发我）：

```
magpie cpu --seconds 60
```

**2. 顺便告诉我：**

- 版本号（设置 → 关于）和系统（Windows / macOS / Linux？）
- 任务管理器里 41% 的是哪个进程：`magpie.exe`、`magpie-bun.exe`（插件宿主）还是 WebView2？
- 是**一直稳定 41%**，还是**一阵一阵**？试试最小化窗口 1 分钟，看会不会回落

**3. 两个高频原因可以先自查：**

- **版本 < v0.1.2622 且开了 Privacy 脱敏**：旧版本对长会话每个请求都全量重扫，555KB 的请求能吃近 2 分钟 CPU，新版已修到 0.2 秒——先升级试试，大概率直接解决
- **每 10 分钟一阵的高峰**：magpie 会定期整理 Codex 的会话文件，`~/.codex` 目录很大时每次整理都会高 CPU 一阵（最小化也不停）——看下曲线是不是这个形状

有采样文件 + 上面几条信息，基本就能定位到具体原因了，谢谢！
