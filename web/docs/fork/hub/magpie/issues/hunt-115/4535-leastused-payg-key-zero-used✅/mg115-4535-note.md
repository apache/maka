## 根因
`weighRouted` 对无 allowance 记录（PAYG key）或记录无百分比窗口（钱包）的候选把 `l.used` 留在 Go 零值 0.0；`LeastUsed` 的 `sa.Used != sb.Used` 直接把这个 0 当「用了 0%」，排到一切已用>0% 的订阅前。Smart（`not known: after those known`）与 Pace（Pace=0 落最低 band）都有护栏，LeastUsed 没有。前端 client.js:535 文案本就承诺 "a key by the tokens magpie sent it lately"——实现背叛了文案。

## 修法（单点，internal/routes/strategies.go）
place 分层比较：Learns=0（探针一次，同 Smart/Pace）→ tier0 且有份额（Known 且 (Used>0 或 Soon 有非零续期)）=1 按 Used 升序 → 无份额=2（PAYG key/钱包/未读账号）→ tier1=3 → tier2=4（Credits 优先不变）。已知 seat 间 place 单调于 Used → 全已知或全无份额的池行为零变化；既有测试（钱包 #3950 三件、credits-first、Smart/Pace）全绿不用改。

## 产品取舍（帖内已声明，待维护者拍板）
无份额 key 落 tier0 之后、tier1(>=90%)/tier2(>=98%) 之前（Smart/Pace 一致）。issue 第一读法「known 一律在前」被否：Spent(100%) 订阅会排到 key 前，而 Resting 只有 Weighted 消费 → 每请求先撞一次已耗尽订阅。
