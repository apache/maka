## What changes

`stickKey` (internal/gateway/affinity.go) is the key every affinity stick is read and written by. It already kept a Claude Code subagent apart by its `x-claude-code-agent-id`. A Codex request names its subagent thread in its turn metadata (`thread_id`, what `codexSubagentThread` reads — codex_resume.go), and `session_id` stays the root thread's for every request of the chat, the lead's and its subagents' alike. So the stick key now ends `|thread:<thread id>` for a Codex request whose thread is not the session's own. The lead's key is the session's, as before — its stick, and `leadFirst`'s read of it by the parent thread id, are untouched; a request whose metadata names no other thread keeps the key it had. The metadata is parsed only behind the `fromCodex` header gate, so no other agent's request pays the read.

Two faces the suffix choice is deliberate about:

- **Why not Claude's `|agent:`**: withSession's Smart face (`withLead`, 06d36d414) keeps a key holding `|agent:` with the account its session is on — right for a Claude Code subagent, whose prompt forks its lead's context. A Codex V1 subagent's first turn is a session of its own to spread (the report's first round spread two to an account over WorkBuddy's three), so a `|thread:` key deliberately does not match `withLead`, and the first round still spreads by what the accounts already hold — now counting each subagent's conversation as the hold it is. What changes is only what the report asks for: from the second round on, each subagent stays with the account whose cache holds its thread, instead of all of them reading the parent session's stick.
- **What a subagent stick holds**: its own cache worth, judged cold, spent and moved on its own — the lead's stick no longer has a subagent's answer written over it (the shape 3b717d5e0 fixed for Claude Code, on the Codex face).
