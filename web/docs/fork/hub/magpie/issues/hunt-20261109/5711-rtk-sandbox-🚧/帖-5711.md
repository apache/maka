**Half 2 first, since it hides half 1's fix**: the RTK page read Codex's hook from `hooks.json` alone, and Codex reads `hooks.json` and the `[hooks]` tables of its `config.toml` alike — so your `[[hooks.PreToolUse]]` with `rtk hook codex` was one the page showed `off` while Codex ran it, and switching RTK on would have run `rtk init -g --codex` to write a second hook of the same command into `hooks.json`, with `RTK.md` and the `@RTK.md` line in `AGENTS.md` to match. `has` reads both sources now, so the row says on and switching it on is nothing; switching it off says `config.toml`'s hook is the user's to take out, instead of pretending done or leaving a hook behind:

```toml
[[hooks.PreToolUse]]
type = "command"
matcher = "Bash"
command = "rtk hook codex"
```

Only `PreToolUse` counts: the event whose commands rtk rewrites (a `SessionStart` hook rewriting nothing isn't an "on").

The old note (from #3320) said the elevated sandbox's account keeps rtk's history "in that account's AppData" — your measurement (the folder is yours, `(RX)` inherited, the write silently lost) is the truth, and the note now says the way out. [sandbox_workspace_write]
