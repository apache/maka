## 根因与修法

- `Allowance.renewing`（父提交 internal/provider/routing.go:584）把 `Limit.RunsOut` 无条件当窗口 renewal（「what is left is lost then all the same」——WorkBuddy 无 reset 包语义）。vendor 同时告诉 `RunsOutLeft`/`Of` 时该假设可证伪：#5791 的 A（500 积分剩 495、28 天重置、1 积分 14h 过期）renewal 被提前到 14h，Smart（renews soonest first）把请求全押 A。
- 修：新增 `Limit.lapsingAll`——有真实 Resets 且 vendor 告诉的丢失量 < 剩余（Of*(100-Used)/100）→ 不提前；无 reset（WorkBuddy）、量未告诉、丢失量覆盖全部剩余 → 保持提前。
