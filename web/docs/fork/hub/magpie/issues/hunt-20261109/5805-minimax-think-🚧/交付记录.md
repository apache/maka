## 根因

Chat 客户端 × MiniMax Chat 端点 → `relayable=true` → `passthrough` 字节级直传，绕过 `chatDecoder.text` 的 leading `<think>/<thinking>/<thought>` lift（只活在 translate 路径）；`chatEncoder`/`renderChat` 的 `reasoning_content` 输出从未被到达。usage 的 reasoning tokens 由 sniff 透传，故计数在而字段无。#1267 的 decoder lift 与 buildChat 写回是配套设计，直传破坏了接收端。

## 修法（共享根因，不写死模型名）

1. `internal/gateway/chat.go`：buildChat 的 inlineThink host 判定提取为共享 `inlineThinkHost(host)`（行为不变）。
2. `internal/gateway/gateway.go`：新增 `inlineThinkChat(p)`（preset `minimax`/`minimax-cn` 或 `inlineThinkHost(p.Host())`）；relay 链加一条 `if relay && from == Chat && inlineThinkChat(p) { relay, ownAPI = false, true }`（与 DashScope 非流式、Claude-on-Messages 同形），走 translate Chat→Chat：decoder 剥块→`reasoning_content`，buildChat 保持按 host 写回。
