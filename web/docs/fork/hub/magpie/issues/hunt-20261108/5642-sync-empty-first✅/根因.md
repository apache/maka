# 5642 根因：只勾 Library 的多机 sync，主机的 Providers/Routing Group 被清空

- 报告者 tan-yong-sheng（0.1.3266，Linux Mint，S3，3 台机只勾 "Library instructions, MCP servers, skills, hooks and subagents"）
- 现象：设置 sync 几分钟后，主机（有 providers + routing groups）的这两类数据变空。

## 语义前提

- `Parts = ["providers","settings","profiles","agents","library"]`（davsync.go:59）；GUI 勾选项 keys/agents/library/usage/sign-ins 是**附加项**，providers/settings/profiles 没有开关、**无条件参与双向三路合并**（报告者以为勾选是白名单，实际是附加项）。
- 合并循环（davsync.go syncOnce）：`lc && !rc`→take（本地上推）；`rc && !lc`→bringIn（远端落地）；`lc && rc`→按 `changed()` mtime 与 `remote.Created` 比新旧。
- `bring("providers")` → `provider.Mirror(b.Providers, b.Groups)`（provider/backup.go:103）= 整面镜像：远端为权威，本地多余条目删除。**空面镜像 = 全清**。

## 触发路径（报告者场景）

1. 空机（全新安装、providers 为空）先设置 sync → `data == nil` → `push(local)` 全 bundle 首推 → **空 providers/settings/profiles 成为文件夹初始状态**。
2. 满数据主机之后同步 → `first=true`（st.Local==nil）→ providers 面 `rc=true, lc=false` → bringIn → `provider.Mirror(空)` → **主机 Providers + Routing Groups 全清**。
3. settings/profiles 面同理（settings 有 KeepOwn 保护部分本机字段；profiles 删除传播）。

时序反例（满机先首推则无清空）——3 台机几分钟内设置，顺序不定，空机先推即触发，与报告者"wait a few minutes"吻合。

## 同族先例

- #1714 `keepUnseenGatewayKeys`：settings 面 first 同步的同类保护（"a computer joining a folder whose store has none of its keys would have them replaced"）——形状相同，只保 gateway keys。
- backup.Collect 注释（backup.go:173-175）：providers.json 读失败禁止携带空面（"carried as no providers, it would take them all away where sync mirrors it"）——**读失败空面已防，"真的没有"空面未防**，本单补的正是后者。
- TestSync "b removes one: each reaches the other"：非 first 的删除传播是**已测既定语义**，本修不触碰（保护只在 first 分支）。

## 修法

`rc && !lc` 分支加 first 保护：`first && L[p] != emptyHashes[p] && R[p] == emptyHashes[p]` → `take(&merged, local, p)` + `there`（本地面胜、上推），否则走原 bringIn。`emptyHashes = hashes(backup.Bundle{})` 包级一次计算，与变更判定同一哈希函数（判定同源）。

- providers 面（含 Groups/Order/GroupOrder/Searches/Plugins，hash 覆盖全体）生效；profiles 面生效。
- settings 面：真实机器 collect 后 Settings=文件加载默认值（≠零值 hash），不触发保护——不扩面，KeepOwn 已有保护。
- 非 first 空面传播（真删光）= 合法删除语义，保持不动。
