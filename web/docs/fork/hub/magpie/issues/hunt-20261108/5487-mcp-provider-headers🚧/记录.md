## 根因（报告者定位 hubServerFor 已过时）
Remote Magpie 的 MCP router 自 cd9c52c16 起由 `adoptBridge`（internal/library/bridge_mcp.go）生成 server，`bridgeHeaders(key)` 只返回 `{"Authorization": "Bearer "+key}`；`provider.RemoteHub` 不携带 Headers（`RemoteHubs()` 构造时丢弃 `p.Headers`）。且 `adoptBridges` 每次同步把 server headers 重写为该单对——用户手加的 headers 也会被收走。报告者 JSON（name=remote-magpie、bridge 字段、URL=root+HubMCPAll）与 adoptBridge 产物形状完全吻合。

## 修法
- `provider.RemoteHub` 增 `Headers map[string]string`，`RemoteHubs()` 填 `maps.Clone(p.Headers)`。
- `bridgeHeaders(h RemoteHub)`：先克隆 provider headers，再无 case-insensitive `Authorization`（EqualFold）时加生成的 Bearer key——显式配置赢，与 `signRemote` 请求面的既有覆盖顺序同语义。
- 既有 server 下次 Sync 自动补齐（adoptBridges 的 sameHeaders 对账路径顺带成为迁移路径）。
