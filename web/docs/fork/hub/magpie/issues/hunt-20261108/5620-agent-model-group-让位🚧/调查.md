## 让位理由

1. 功能面（存储→路由决策）证据链闭合无断点：切换后新请求即按新值路由；唯一"不生效"处是**正在跑的 agent 进程不重读自己的配置文件**——agent 引擎自身行为，非 magpie 代码可修（magpie 无法让一个已运行的第三方进程重读文件）。
2. magpie 既有应对完备：Notice 提示机制（codex 有 `codexRestartAll`）+ Restart 按钮（`agents/restart`）。
3. 报告者正文无 agent 名/步骤/日志，无法复现；按 #5583 判例"报告者描述与代码冲突时以代码+复现为准"，不制造猜测性 UX 补丁（同题 patch 风险>价值）。
4. 可复核线索留此：若报告者补充 agent 名与具体现象（如"重启 agent 后仍走旧组"），首选查该 agent 的 `Field.Set` 写入格式与该引擎实际发送的 model 参数拼写（`group/<id>` vs 引擎拼写），届时走 Spell/split 面（agent.go）。
