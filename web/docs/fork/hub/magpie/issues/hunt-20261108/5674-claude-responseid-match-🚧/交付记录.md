## 修法（共享根因=匹配键缺失；不动 ±2s 窗本身）

- `matchedBlocks`（request_page.go）：网关行的 calls 组现挂两个名字——RequestID（槽 11，原逻辑原样）与 ResponseID（槽 25，别名键挂同组，已存在则复用）；本地行先查 RequestID（命中即原语义），未命中且 rowMsg（槽 35）非空再查其消息 id。withID 容量预估同步覆盖双键行。
- `hintsOf`（match_chunks.go）：本地 chunk 的 ids 哈希补 rowMsg——否则 #2278「只解码被命名的文件」捷径会让页面路跳过 Claude 文件（TestClaudeMessageIDMatchOpensNamedChunk 的「matching never read the file」断言实证此依赖）。
- 三条路自动共享：ledger（gatewayMatchesDetails）、页面（pairRowsIn）、direct（directRows）都走 matchedBlocks，一处修复全覆盖。
- 不改项：logRecord 的 Codex 专属 ResponseID（负例+锁定测试）；±2s 回退窗与唯一性判定；codexResponseMatches 的 codex 双侧校验；任何行的字段值（修复只改匹配器的读取，不写任何字段）。
