## 单情

- **issue**: yetone/magpie#5699 「plugin host: gatewayBegin 把整个请求体放在一行里回传，超过 maxWireLine（32 MB）就杀掉共享宿主」（报告者 1007cordon-ux，v0.1.3327 macOS；`plugin: host starts` 268 次/2.5h 重启循环，多插件 provider 一起 "connection lost mid-reply (the plugin host sent a line longer than 33554432 bytes)"）
- **根因（报告者代码级定位）**: ①任何插件声明 `magpie.hooks` → `HasGateway()` true → 每请求走 `GatewayBegin`（internal/plugin/gateway.go:206）发完整 body ②宿主 `gatewayBegin` 钩子没改 body 甚至超时（"keeping request"）也把原 body 整个 `JSON.stringify` 一行写回（host.js:1631→send），此回包不像 fetch 的 chunk 帧分片 ③Go 侧 stdout 单行上限 `maxWireLine = 32 << 20`（host.go:182）超限 → `errLineTooLong` → `h.fail+h.kill`（host.go:1283-1287）杀整个共享宿主 ④所有插件 provider 共用宿主 → 全灭+重发再杀=重启循环。`maxWireLine` 注释前提「RPC result 远小于它」对 gatewayBegin 不成立。
- **报告者修法建议**: ①钩子未改 body（undefined）或超时 → 只回 `{id, token, unchanged: true}`，Go 侧用原 body（顺带解决 #5168 拷贝/序列化开销）②改了 body 的：fetch 同款分片帧，或 Go 侧超限只放弃该次钩子（等同 keeping request）不杀宿主 ③可选：body 超阈值直接跳过 gateway 钩子+日志。
- **关联**: #5168（同链路性能——unchanged:true 方案顺带改善，帖内说明）/​#3074/#4004（fetch 路径 body 编码开销）/​#3073 系插宿主协议。报告者自注：未抓到实际 >32MB 请求体，结论来自错误类型+时间+源码，未用已知大小请求复现——**实证缺口由我们的测试补**。
