# #5627 根因与修复（车道 D，2026-11-08）

## 单况

- 报告者 jackyfan01，0 评论（开工时），OPEN。Windows 11 + Qoder CN（qoder-cn），0.1.2382，报告者自查到 internal/gui/tune.go 白名单并引用 main 行号。
- 现象：「用量 › 上下文 › 为你调优」对 Qoder 永远空白，提示语一律「这段时间的调用太少，还算不出建议」，而 Qoder 7 天 1.30B tokens、缓存命中 47% 的数据齐全。

## 根因（双层，报告者指出了第一层，实测挖出第二层）

**第一层：gui 三处写死 claude/codex 白名单**（报告者已定位 tuneOf，实测共三处）
- `internal/gui/tune.go` tuneOf（旧 L105）`c.Agent == "claude" || c.Agent == "codex"`
- 同文件 tuneCallsSince（旧 L454）同样的条件（生产路径的源头过滤）
- 同文件 adviseOf（旧 L116）`for _, name := range []string{"claude", "codex"}`

后果：qoder-cn 的调用进得了 sessions 层，但在调优管线里三层全被挡掉 → 无卡片 → 前端 `renderTune` 的 `shown.length==0` 一律落到 "Not enough calls in this range to tune on"——对 Qoder 是谎言（报告者主诉：空白就是空白，提示语得说实话）。

**第二层（本车道实测新发现）：tune 的调用清单管线根本不含 Qoder**
- `tuneFor → tuneCallsSince → sessions.CallSources → callSourcesInto`（internal/sessions/calls.go:346）的清单里**没有** qoder/qoder-cn 的 ccFiles——Qoder 文件只在会话/统计层（`allFilesWith`，sessions.go:742）被列举。
- 即：只修白名单、others 仍从 CallSources 取，生产路径永远看不到 qoder——本车道第一次实现后 HTTP 生产探针（/api/tune 断言 Others 含 qoder-cn）抓出该缺口，随后改从 sessions 列举层取。

## 修复（commit 1da52fff5，rebase 后；基线 d32a7a70c）

1. **单一事实来源**：`agent.TuneAgents()`/`agent.Tunable()`（internal/agent/tune.go，紧贴 tuneWhere）——三处白名单全部改走它；`TestTuneAgentsHavePlaces` 锁住清单与 tuneWhere 不漂移。
2. **诚实空态的状态面**：tuneState 增 `Others []string`（范围内有会话文件被触碰、但无可调设置的代理）与 `Unread []string`（有可调设置、但本机未允许读其会话文件的代理）。
3. **Others 的生产来源**：`sessions.TouchedSince(since)`（internal/sessions/sessions.go，走 allFiles 列举层、零解析）+ gui 侧 `othersOf` 过滤 Tunable；tuneOf（测试缝）从入参 calls 派生。
4. **Unread**：adviseOf 内 `!sessions.Reads(name) && Found() 包含 name` 且无 calls 无 kept 时记录。
5. **前端**（context.js renderTune）：空白时依次报 Unread、Others，两者皆空才落「调用太少」；有卡片时其余代理的原因仍附注在网格后。i18n 五语种（en key + zh/zh-TW/ja/de）。
6. 与 upstream f78d6b0d9（gateway mode 隐藏调优面板）正交：gateway mode 下 /api/tune 提前返回 `gateway:true`，本机制不触达。

## 与报告者三条诉求的对应

1. 「不要硬编码 agent 白名单」→ TuneAgents 单一来源（下一个获得可调项的 agent 只需改 tuneWhere + TuneAgents 两处，测试锁同步）。
2. 「空白时把原因说准」→ 三因分述：无设置（Others）/未允许读取（Unread）/真·调用太少（原话保留）；未实现 #1860 式调用数展示（Others 走列举层不解析，无次数可报；真·调用太少的卡片上有 calls 数）。
3. 「给 Qoder 一条可调路径」→ 不在本单（Qoder 无可写设置，报告者自己也不主张）。
