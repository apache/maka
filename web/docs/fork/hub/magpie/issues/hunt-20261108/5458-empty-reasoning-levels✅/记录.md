## 根因（帖内同口径）

`keptEfforts`（internal/provider/modelprefs.go）把"用户命名的 set == 模型全部 levels"折叠为 nil（"offered all again"），`setModelEfforts` 判"无变化"不落盘。无 override 时发布面只发 catalog 借用词（effortsOf），借用词落空（vendor 沉默+借用链短）的模型发布空，且用户唯一受支持通道（显式 override）被 no-op 挡死——报告者双缺口同根因。

**修法**: 用户命名的 set 即使==native 也落盘；--reset（不命名）仍清。发布面 `entryFor` 的 `effortsKept` 已忠实应用记录（借用得到照旧，借不到发用户命名的 set）。
