# #5622 判定：DeepSeek 4.1 flash 无价格（车道 D，2026-11-08）

## 结论：不上鱼（magpie 侧无可安全修的根因），转判定帖

报告者 Magixyne，0 评论（开工时）。WorkBuddy 的 DeepSeek 4.1 flash 与 Tencent Cloud 的 DeepSeek 4.1 flash 被列入未计价。

## 数据源核验（models.dev api.json，2026-11-08 实抓）

1. **母厂条目无此 id**：`deepseek` provider 只列 `deepseek-flash` / `deepseek-v4-flash` / `deepseek-v4-flash-vision-exp`（均 $0.15/$0.6，cache_read $0.003），`canonical_model_id` 全部指向 `deepseek/deepseek-v4.1-flash-1017`（带 -1017 修订号）。无裸 `deepseek-v4.1-flash`。
2. **无 workbuddy provider**；`tencent-token-plan` / `tencent-coding-plan` / `tencent-tokenhub` 三个条目均无 deepseek 模型。
3. **裸拼写只有 relay 在定价，且互相打架**：openrouter 两拼写 $0.051/$0.567 vs $0.15/$0.6（同源 3 倍差）、llmgateway $0.135/$0.54、kilo/novita/opencode $0.3/$1.2、deepinfra $0.2/$0.6。

## magpie 侧机理（现状代码实测）

- 取价链：provider 自身列表 → 母厂（`makerListPrice` → `catalog.MakerPriced`）→ vendor catalogs → SamePriceIn（ModelSameAs）。
- `MakerPriced`/`PricedBy` 对 `deepseek-v4.1-flash`（带或不带 `deepseek/` 前缀）在**真实 catalog 数据下实测不命中**（探针 ok=false）；#1520 的 canonical 机制按精确 id（含 dashed）匹配 `canonical_model_id`，母厂的 canonical 目标是 `-1017`，裸拼写差一个修订号 → miss。
- 等同两种拼写 = 违反 catalog 既有边界（"an id listed is never taken for another"），且 relay 价差 3 倍，错价比无价更糟 → 不做 suffix-blind 匹配（超出行车安全边界，属维护者政策决定）。

## 可用的现成出路（已实测验证）

Provider 编辑器 Names & levels 的 **Same as**（settings `ModelSameAs`，#2344）：把 WorkBuddy/Tencent Cloud 的该模型 Same as 设为 `deepseek/deepseek-v4.1-flash-1017`（带或不带前缀均可）→ 按母厂价 $0.15/$0.6（cache_read $0.003）计价。探针实测两拼写均命中。
