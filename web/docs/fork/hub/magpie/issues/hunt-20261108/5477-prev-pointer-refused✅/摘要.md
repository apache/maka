- 报告者：路由组把会话从 provider A（agentrouter-linuxdo 族）移到 provider B（agentrouter-github 族）后，出站体携带指向上轮存储响应（A 账户名下）的 conversation/previous_response_id 指针，B 以 400 拒绝；回到 A 又正常。自述 onProvider 处 body 仍 chat 形、转换后出现指针；建议记录指针归属、跨户时内联历史或拒绝切换。
- 排雷五查全净：①take 前实时复核仅报告者 1 评 ②无收编（末评=报告者非 yetone）③open/closed PR 引 5477 均 0 ④log grep 5477 两命中均数字子串误报（whimsical_wolf_15477、磁盘计数文本）⑤log -S previous_response_id 系既有机制提交（ba3a7384f 支持起点、delta/refused 机制已在），#4525/#5266 提交族为 input id 前缀/长度形态（报告者自述本单非该形态）。
- 根因（实证后修正报告者框架）：翻译路径出站组装 buildResponses 从不写指针，且不持有的 id 在翻译路径先行 writePrevNotFound 拒绝；指针只在"组内 Responses 成员按原样中继"（#1594：Pi/omp/droid/dsh）路径出现，且是客户端自己的（上轮成员回复的 id 链）。magpie 持有该轮（store:true）时 previousResponse 给全会话并删指针、自有 delta 附加有 prevRoute 守卫——均不会跨户。缺口：store:false（Pi 即发 store:false）/重启/TTL/换 key 使 magpie 无从持有 ⇒ id 按原样中继给从未见过它的成员 B ⇒ 400。报告者"onProvider 处 chat 形"观察与中继路径吻合不符翻译路径（帖 Not verified 照实说明）。
- 修复（gateway.go passthrough，与既有 prevDelta 兜底同形）：中继体被 prevRefused 形态（previous_response_not_found 族）拒绝且 prevLost 时，去 previous_response_id 重发一次——Responses 客户端 input 自带全会话（Pi 族），B 即有历史可答；纯指针客户端无可失之物（magpie 无历史可内联）。其它原因的 400 不重试（vendor 原样到客户端）；发给持有方的正常中继照旧。翻译路径拒绝行为不变。文档 docs/subsystems/gateway-routing.md prev 小节补一句。
- 报告者方案对照：归属记录在 store:false 下无从建立（无可归因的留存）⇒ 先按原样（持有方照常答）+ 拒绝时去指针重试即其建议的诚实等价；方案 (b) 保持会话在属主成员=组 affinity 已有行为。
