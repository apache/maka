## 机理（与报告者分析逐项核实，全部成立）

1. `\\wsl.localhost` 下 Windows 无法跟随 distro 内 Linux symlink（wsl_links.go 文档化）：Lstat=irregular、Readlink 失败、open=not-exist。
2. probe 只探 agent **文件夹**（#4502 形态）+ `wslLinkPaths()` 静态列表；`~/.pi/agent/settings.json` 等文件级 link 不在列表 → `parseProbe` 过滤丢弃 → `d.Links` 无记录。
3. `piDir`/`omoDir`/`primeAgentDir` 已走 `at.join`（dir 级映射），但 `piLikeKeyed` 三个文件路径裸 `filepath.Join` → 不经 `at.open` → UNC 拼写原样。
4. 下游链：`edit.Read` ErrNotExist→(nil,nil)→`SetJSON` 从 {} 拼（wipe packages/其它 provider）；`beforeMagpie.take` 记 `pi@wsl:<distro>.before.absent`；`WriteAtomic→Target`（UNC 下 Readlink 失败→rename 常规文件盖 link）；`Wired()` 读空→行显示未接入；`Drift` Kind=replaced→Reconnect 再盖。

## 工作记忆反馈（可复用教训）

1. darwin 上 FakeWSL 复现"link 不可跟随"的关键：**link 的字面目标必须本机不存在**（/mnt/c 形配 FakeWSLDrives，或 /data 形靠字面缺失），否则本机 symlink 可跟随→测试假绿。
2. `Wired()` 断言需 applied 记录（connect 写）——用户动作路径用 `a.Pick`（未 wired 时自动 connect），直接 `Field.Set` 不写 applied → Wired 恒 false。
3. 本机 git http.proxy=7897；SSH push 被代理掐断时改走 gh keyring 的 https。
