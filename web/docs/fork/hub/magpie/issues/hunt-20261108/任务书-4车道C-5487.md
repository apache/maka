## 1. 单情（报告者给了实现定位+修法建议，0 评论；v0.1.3127 复现/3134 仍在）

- 现象：Remote Magpie provider 暴露为 Library 的 MCP server 时，生成配置只带 `Authorization`，provider 的 custom headers（CF-Access-Client-Id/Secret）不复制——Cloudflare Access 等代理后端 MCP server 不可用（302 重定向）。
- 报告者定位：`internal/library.(*Library).hubServerFor` 构造 URL+Authorization，未读 `Provider.Headers`。
- 报告者修法建议：先克隆 provider custom headers，再加生成的 Authorization（显式配置的不被覆盖）；header 名比较 case-insensitive。
- 修法注意：Authorization 冲突优先级（provider 显式配了 Authorization 时谁赢——建议=显式配置赢）；敏感性（CF-Access secret 进 MCP 配置文件=与 provider Headers 同级敏感，落盘路径已有先例）。
