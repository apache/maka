## 2. 提案卡 A：规则试算（Try a rule）

**用户故事**：用 Clef 当判断模型、写了两条英文意图规则的用户，粘贴「把 README 的错别字改掉」，2 秒内看到：判为 easy task → 命中规则 3 → DeepSeek-V4.1-Flash。省掉「保存 → 跑 agent → 翻 Routing 页」。

**现状与缺口**：`Classified`（含 `Fallback`/`Error`）和 `RuleHit` 已写进 trace，`classWhy` 会显示「沿用上一轮」。缺：保存前、对草稿规则、拿任意文本试。

**最小设计**

- 接口：`POST /api/routing/try`，请求 `{group: <与保存同结构的草稿 Group>, text, agent?}`；返回 `{classified, rule: RuleHit, effort, order: []memberRef, notes}`，复用 trace 类型与 Routing 页渲染。
- Go：把 `ruleFor` 拆成「无状态判定」+「整轮保持」（`rules.go`，结构待核对）。试算只调判定，**不写** `turnRules`、affinity、`classifyRest`；判断请求照常标 `routing`/magpie's own。key 被厂商拒后照常休息（真实状态），列为待维护者决定。
- 入口：编辑器规则区下「试一试」输入框 + 可选 agent 下拉；TUI 不加界面，CLI `magpie group try <group> "<text>"`（子命令名待核对）。
- 文案只讲规则层：「命中规则 2 → GPT-6-Astra。真实请求还受会话保持、成员休息和上下文窗口影响。」
- 触面：`internal/gateway/rules.go`、新 handler（位置待核对）、编辑器 JS（`plugins/routing/` 或主前端，待核对）、四语言约 6 键、CLI、`docs/subsystems/gateway-routing.md`、测试。

**故障家族自检**

- ① 竞态：用请求内草稿配置，不读正在保存的配置；不写会话状态。
- ② 漂移：**绝不在 JS 重写匹配**，只调 Go 同一判定函数；加真实路径与试算一致性测试。
- ③ 读失败：判断失败显示「判断失败：<error>。真实流量沿用上一轮意图；新会话不命中任何意图规则」，不显示「未命中」。
- ④ 覆盖自设值：无新配置键，接口无状态。
- ⑤ 兄弟路径：嵌套组（`nestedRules`）、共享模型（`Member.Also`）同函数；暂停规则单独说明；文件夹规则在无文件夹时 `folders=` 不命中、`except-folders=` 命中，界面写明；压缩规则显示「仅压缩请求命中，试算不适用」。
- ⑥ 字段丢失：直接返回 trace 原结构。
- ⑦ 声明设计：判断模型只看最后一条用户话（`userText`），试算照办。

**验证**

- `TestTryLeavesNoTurnState`（关键消融：去掉保护应变红）
- `TestTryUsesTheDraftRules`
- `TestTryClassifierFailsSaysSo`
- `TestTryMatchesTheLiveDecision`（保护性，修前即绿，照实写）
- 嵌套组、文件夹规则无文件夹两例；前端 `routing-try.test.cjs`；四语言键齐全；Windows 本地跑（CI 只编译）。

**不做**：历史会话回放、预测休息/会话保持/窗口裁剪、缓存判断结果、批量 prompt、TUI 界面。

## 3. 提案卡 B：规则命中账（Rule hit ledger）

**用户故事**：编辑器规则 2 旁「近 7 天 41 轮」、规则 3 旁「212 轮」，底部「判断失败沿用上轮 9 轮、未命中 30 轮」。一眼看出难题规则不触发或判断模型频繁超时。

**最小设计**

- `GET /api/routing/rulestats?group=`，只扫最近 7 天历史（`history.go`，30 天/200 MB），按文件修改时间缓存；热路径零埋点。
- 按轮计不按请求计（工具来回会放大），用会话+轮次去重（字段待核对）。
- 规则身份按规范文本（与分享文本同序列化），**不按序号**。若 `RuleHit` 只记序号（待核对）则加 `Rule` 字符串字段；旧记录不计入，显示「自 <日期> 起」；帖里写明每请求代价（一个字符串的复制与落盘）。

**故障家族自检**：③ 历史不可读显示「统计不完整」，绝不显示 0；① 对快照计数；⑤ 嵌套组归内层、暂停规则单列、远端 magpie 判定不计入并写明；② 只读 trace 记录不重新匹配；⑥ 旧格式兼容 `TestOldRouteWithoutRuleText`。

**验证**：`TestRuleStatsKeyedByText`（改按序号应变红）、`TestRuleStatsUnreadableHistory`、`TestRuleStatsCountsTurnsNotRequests`、200 MB 合成历史扫描耗时上界。

**不做**：成员 429/延迟分位、图表、告警、自动调规则。

## 4. 现有功能简化（对照截图）

1. **会话保持五档单调排序 + 改名**：现序「自动/整个会话/一轮之内/关闭/严格」非单调；「严格」实为失败也不换号、错误直给 agent（`strictAlone`），新用户必猜错。改为「关闭/一轮之内/自动（推荐）/整个会话/绝不换号（失败直接报错）」。激进版只显示三档，`turn`/`off` 仅当前组在用时显示，不静默转换。先核对 `turn` 与「自动」在有规则组里确有差异。
2. **推理强度与推理档位合并为「推理」区**：「提供给 agent 的档位：成员共有/自定」+「每轮由谁选：agent/判断模型」并排；选判断模型时注明它盖过 agent 选择。
3. **意图判断模型**：仅在有意图规则或「每轮判断」时显示，紧挨规则区；隐藏不清值。
4. **规则区**：末尾加只读「其余 → <默认去向>」；两种「+」只留一种含义；意图文本旁注「这段文字会原样发给判断模型」。
5. **上下文**：去掉「自定义」按钮，改数字即自定义（已有值保留并标注）；「最大模型的」补后果：超过成员窗口的对话会绕过它，含规则指定成员（`roomy`）。只改说明文字（Routing 页以「不在顺序里」表示是声明设计）。
6. **组列表**：「智能」药丸仅非默认策略显示（待核对其含义）；模板卡在有自建组后收进「新建」；顶部全局后缀设置改为跳转「设置」（待核对）。
7. **模板与手动规则**：先查清模板组是一次性复制还是随供应商重解析（`templateModels`，待核对），后者须界面写明。

## 5. 如果只做一个：规则试算

1. 编辑器里唯一不确定的配置是自然语言意图规则，读不出来只能试。
2. 反馈从「保存 → 跑 agent → 翻页」缩短到几秒，且只试草稿不污染真实路由。
3. 不改数据格式、不加配置键、热路径不多一次检查。

**前置条件**：核对 `ruleFor` 能否干净拆出无状态判定。若只能往热路径传 dry-run 标志，改为先做规则命中账。（已核实：能拆，见第 8 节。）

## 6. 用 GLM-5.3-Flash / DeepSeek-Flash 跑是否可行

**两层含义要分开：**

- **运行时**：规则试算**不需要强模型**。它调用的是用户已配置的意图判断模型（截图里就是 Cloudflare Workers AI 上的 Clef 小模型），与真实流量同一个；功能本身只是复用既有判定代码，没有新增推理需求。
- **开发时（让 agent 写这个功能）**：难点不是算力，而是**读懂 `rules.go` 的状态边界**——哪里写了 `turnRules`、affinity、`classifyRest`，`askClassifier` 是否走候选循环并顺带休息 key，嵌套组/共享模型路径。这是「长上下文 + 不臆造 + 严格自查」的活，Flash 级模型的典型失败是：编造 file:line、在 JS 里重写一遍匹配、漏掉藏在调用链深处的状态写入、写出修前就绿的空测试。

**建议分工：**

| 阶段                     | 内容                                             | Flash 可行性                     |
| ---------------------- | ---------------------------------------------- | ----------------------------- |
| P0 只读勘察                | 回答「`ruleFor` 能否拆」、列出所有状态写入点与调用链（带真实 file:line） | **可行**，但结论必须由你或强模型复核          |
| P1 Go 拆分 + 接口 + 测试     | 无状态判定、`/api/routing/try`、四个核心测试与消融             | **勉强**，建议强模型或你逐行审；这是维护者最挑剔的部分 |
| P2 前端 + 四语言 + CLI + 文档 | 输入框、渲染复用、i18n、CLI 子命令                          | **可行**，机械活                    |

结论：**能跑，但不要让 Flash 一口气做完**。按阶段给提示词、每阶段设停止闸门，P0 结论和 P1 diff 必须人工核验。Watched 名单的三查（手拆回红、兄弟路径、读失败）由你自己把关。

## 8. P0 预勘与实施快照（2026-10-18，AI 勘察+实施，待人工复核）

**结论先行：前置问题答案为「能干净拆」，功能已实现**（分支 `try-rule` @ magpie-pr1，基线 d783df46 = 当时 upstream/main 最新）。以下 file:line 由子智能体实读核对，主要结论经主会话抽查，仍属 AI 产出，合并前请人工复核。

**预勘回答（提案写作时的「待核对」项）**

- **拆分**：`ruleFor`（rules.go:172）的新回合判定尾部不含 `turnRules` 写入——状态写全在尾部之外。唯一共享状态是 `classify()` 的缓存/失败休息簿记（classify.go:106-163）。因此无需 dry-run 标志：拆出纯判定 `turnDecide`，试算经 `directAnswer` 直连 `ask`（绕开缓存/休息），live 路径经 `liveAnswer` 走原 `classify()`，热路径仅多一次函数边界。
- **RuleHit 标识**：用序号 `N`（1-based，0=未命中），非规范文本；`When []string` 携带 `provider.Rule.Conditions()` 的规范条件文本（rules.go:27-78）。**提案卡 B 若做，需加文本字段**，原判断成立。
- **维护者活跃度**：证实。rules.go 近 14 天 14 提交（全历史仅 28），48h 内有改动；前端 app.js 近 14 天 512 提交。开工前对齐最新 upstream 是硬要求。
- **符号核对**：全部证实，两处措辞需修正——`roomy`（fallback.go:1417）不是「绕过限制」，而是「请求超过成员窗口时跳过该成员、流向有余量者，被跳过者仍兜底（small/smallW）」；`strictAlone`（gateway.go:2094/3383）是「严格档剪枝到只剩一个后，失败时让它也休息、把错误交给 agent」（#1797），不只是「失败也不换号」。
