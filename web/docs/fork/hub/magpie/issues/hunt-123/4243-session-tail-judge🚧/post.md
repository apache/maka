The whole file replayed says the turn is open; the tail says it isn't.

**Residual face**

The tail indecision the reporter described is still live at tip: `sessionTurnOpen` still reports a long turn closed when `task_started` lies beyond the 512 KiB tail. Its blast radius shrank — the reporter's own trigger chain (third-party catalog rewrite → route change → restart) no longer exists on main — but any genuine route or account-change restart that passes the `codexTurnRunning` gate can still cut a turn whose rollout grew past the tail. The reporter's suggestion 1 (read further back, keep a lifecycle offset, or count an undecidable file as open) is implemented by neither side; suggestion 2 is resolved by 70d50254c; suggestion 3 (a setting to disable auto-restart) is only addressed in the draft, as a side effect of removing the authority entirely.

**Two directions for the maintainer**

- **Option A — stay on upstream's small-step path (70d50254c).** Route = where requests go; the app reads a new list at its next launch, and the Agents row's Restart (StaleCopies) covers list changes on demand. What's still missing on this path: a fix for the tail indecision (the reporter's suggestion 1 — an undecidable tail counting as open, matching the existing unreadable-file rule), and optionally a narrower answer to suggestion 3 if auto-restart ever needs an off switch.
- **Option B — the draft's larger change: remove Magpie's restart authority over Codex.** Catalog, endpoint, connection and account changes stay pending refresh; nothing magpie-side ever ends a Codex app-server. The author's own stated tradeoff: after an account/quota switch, Send may stay unavailable until the user finishes all tasks and refreshes Codex. Honest state: the full Go suite is RED (five gateway failures reproduce on the archived base, #4362; TestPluginSOCKSProxy also red on base, #2207; one timeout on both base and patch; one test unresolved), and the author labels it a draft, not merge-ready. Practical note: its base predates 70d50254c, so a rebase would carry the now-dead catalog-hash churn into the pending-refresh marker (bounded, but real). Its lifecycle tests failing on the unmodified base is exactly the right red for this kind of change.

Choosing between "restart only on real route changes, fix the tail guess" and "never restart, let Codex own its lifecycle" is a product call, not a code call — both are internally coherent. Thanks @aresxu8866-hue for the report and @zhangjian94cn for the draft.
