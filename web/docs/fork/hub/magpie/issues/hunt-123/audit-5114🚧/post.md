I took this and read the install path — your instinct (a whole-repo pull) isn't what happens, and the three answers below narrow where the EOF comes from. Credit @willow-god for the reproduction detail (same skill, search works, install fails "basically every time").

**Answer 2 first — what install actually fetches.** The installer never clones or downloads the repository: it reads GitHub's **file list** (`GET /repos/<repo>/git/trees/HEAD?recursive=1`, a JSON answer — for even a big repo this is kilobytes to a few MB), picks the folders with a `SKILL.md`, and downloads **only the skill folder's files** from `raw.githubusercontent.com` (`skillnew.go`'s `repoTree`/`skillDirsIn`; a tree list over 64 MB or truncated by GitHub is refused with its own message, not read in part). Install and update share this path. So the hindsight repo being large doesn't matter — unless its tree list itself is big, which is a 2-minute read at worst, not the ~seconds your failures take.

**Answer 1 — likely your line, not the repo.** "unexpected EOF" is Go's wrapper for a response body that ended mid-read (`apiGet` → `couldn't reach GitHub: …EOF`), and the two requests in play are exactly the ones a flaky proxy breaks on: a single HTTPS connection held open while **kilobytes-to-MB of JSON streams** (the tree list), repeated for each skill file. Downloading a 1 GB file successfully is a different traffic shape — one long bulk transfer over one connection — while this is many short API calls, each a fresh TLS handshake through your proxy. Proxies that survive bulk transfers still drop the short ones. The GitHub-side alternatives (rate limit, 404, truncation) all have their own distinct messages magpie would show instead.

**Answer 3 — nothing to fetch less of.** Since only the skill folder is downloaded, there's no "part of the repo" left to trim; the list request is already the smallest thing GitHub's API offers for discovery.

**What would settle it** — run the install once with `magpie`'s proxy off (direct), and once with `GIT_CURL_VERBOSE=1`-style tracing if you can; if direct succeeds, the proxy's the line and your provider's settings page can carry the no-proxy note for GitHub API hosts.
