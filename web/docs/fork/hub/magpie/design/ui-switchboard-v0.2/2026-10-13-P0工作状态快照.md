## 已知陷阱（务必遵守）

1. **PowerShell 5.1 重定向会害死长跑任务**
   - `> file` 缓冲原生命令输出
   - `2>` 或 `-RedirectStandardError` 会在浏览器子进程继承句柄时卡死等待
   - **解决方案**: runner 用 `--test-reporter-destination=<file>` 让 node 自己写 TAP
2. **会话结束会杀进程树**
   - Start-Process 拉起的进程树会随会话结束被杀
   - **解决方案**: 长任务用计划任务 (`schtasks`)
3. **Edit 工具的 NUL 字符**
   - `"\u0000"` 会被转义成真实 NUL 或双反斜杠
   - `routing.js` 用 `k.charCodeAt(id.length) === 0` 写法，勿动
4. **PowerShell Set-Content 毁文件**
   - 会把 UTF-8 无 BOM 文件写成 ANSI 并毁掉非 ASCII 字符
   - **解决方案**: 改 JS 文件只用 Edit/Write 工具，绝不用 Set-Content/Out-File
5. **测试有已知 flaky**
   - 如 `routing-keys-fold` 的 ja/de、`settings-search` 的 5 个子测试
   - **判定方法**: ui 出现 base 没有的新失败时，先单文件重跑确认是真回归还是 flaky
