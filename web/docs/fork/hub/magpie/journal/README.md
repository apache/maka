# magpie 逐单台账 · 索引（唯一入口）

接单前先到这里：**查这单做过没有、做过同构的没有、有什么坑**。逐单结局按子系统分表；逐单全过程按日记在[编年](编年/README.md)（只追加，永不回写）。两者冲突以编年更晚轮次为准。

快速上手四步：

1. 在下方子系统分表里查 issue 号（全文搜 `#编号` 最快），看同类单的根因、修法与结局；
2. 对照 [模式家族](../handbook/10-避坑清单与模式家族.md#模式家族避坑核心)，本单若落在已知家族，家族规则就是修法起点；
3. 定修法时过一遍 [修法方向五问](../handbook/04-修法方向最佳实践.md)（层次/收口/失败语义/实问/替身），答不上来先补事实再动手；
4. 过一遍 [避坑清单](../handbook/10-避坑清单与模式家族.md#避坑清单接单前过一遍)，交付时用下方[新单模板](#新单模板)。

狩猎方法论在 [05-缺陷狩猎经验](../handbook/05-缺陷狩猎经验.md)；哨兵任务书在 [07-哨兵任务书](../handbook/07-哨兵任务书.md)。

## 状态口径

| 标记 | 含义 |
| --- | --- |
| ✅ 署名合入 | patch 被 `git am`/cherry-pick 合入，author 或 Co-authored-by 保留 |
| ✅ 采纳自实现 | 维护者致谢 patch 后按其改良实现（多数保留署名） |
| ✅ 方向吸收 | 分析评论的边界/方向被维护者实现 |
| ↺ 同构取代 | 我方交付前后，维护者/竞品独立修了同一根因；登记保留，分支作废 |
| ↺ 让位 | 占坑复查发现报告者/并行会话已在做，不重复触达 |
| ✗ 被拒 | 维护者明示不采纳（附理由，是流程教训的来源） |
| ⏳ 等确认 | 已合入/已发版，等报告者或版本发布后确认关单 |
| 🗂 分析在案 | 分析/考证评论交付，无 patch，后续看维护者回合 |

## 新单模板

```markdown
## YYYY-MM-DD <轮次名>：<一句话>

- **接单**：issue 号 + 报告者 + 四道闸（未被认领/范围小/本机可验/知识交集）+ 排雷结果。
- **根因**：文件 + 函数 + 关键判断；比报告者更深一层更好。
- **修法**：最小 diff；裁掉的方向和理由。
- **TDD**：红（修前会挂，报错与 issue 逐字对照）→ 绿；既有断言改动点名。
- **验证矩阵**：目标包 / -race / gofmt / vet / 三平台 / 全量（预存红注明）；**没跑什么如实列**。
- **交付**：commit SHA + fork 分支 + issue 评论链接（对外内容一律英文，本条记录仍用中文）。
- **结局**：（事后追加）合入 SHA / 版本 / 确认评论 / 关单。
```

## 维护

- 语言：台账与编年用中文；在 magpie 上发布的一切内容自 2026-10-17 起一律用英文（见 [05 文首语言规则](../handbook/05-缺陷狩猎经验.md)）。
- 新单先在[编年](编年/README.md)的当日分册追加轮次记录，再回本索引加行或更新结局列。
- 索引只改自己的行；编年的历史内容永不回写。
- 子系统分表只改自己的行；单张分表超过约 45 KB 时按行序逐字分卷（阈值见 [handbook/10 §1](../../../handbook/10-文档维护与结构.md#1-三条原则)），卷 → 单号范围见[索引/README · 分卷](索引/README.md#分卷)，新行只追加到最新卷。
- 避坑清单、模式家族、交付形态属于规则，归 [handbook/10](../handbook/10-避坑清单与模式家族.md)，由复盘角色维护。
