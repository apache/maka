## MG-1（全局 96，2026-10-08 晚）：sessions List limit 把空会话计入——#1320 → PR #1335

- **根因**：`List`（internal/sessions/sessions.go:872）按 mtime 排序 keys 后先截断到 limit，再 assemble 过滤空会话——最新 mtime 的空会话吃光 limit 名额，`List(1)` 返回空而 `List(0)` 有货；粗粒度 mtime 下空会话与真会话同刻还能靠 key 字典序赢平手裁决。
- **修法**：截断移到 assemble 之后——按序遍历 keys，assemble 成功才计数，够 limit 即停；空会话只花一次循环步，不占页面名额；排序契约（most recently active first）与 `All`/`List(0)` 调用方（CLI/TUI/context 页）零变化；`usage_scale_test` 的 `List(2000)==2000` 断言与新契约天然一致。
- **TDD 闭环**：报告者的复现测试收编为 `TestListLimitSkipsNewerEmptySession`，修前红 `limit=1 returned 0 nonempty sessions, want 1`（与 issue 报告逐字一致），修后绿。

## MG-2（全局 97，2026-10-08 晚）：dsh key store 持本网关 caller key 被误判 drift——#1332 → PR #1339

- **根因**：drift 检查（internal/agent/dsh.go:736）只比 `refs.MAGPIE_GATEWAY_KEY` 与 `.env` 里 magpie 写的 key（keyAt(gw)）是否相等，而 dsh 读 store 优先于 .env（#969）、网关对自签 caller key 照常 Authenticate——dsh 明明在走 magpie，却被报 "holds another MAGPIE_GATEWAY_KEY" 并叫用户去删；删→断→重接写回同一磁盘状态（报告者 0.5s 采样轨迹实证空转）。
- **修法**：条件串上加 `!gatewayTakes(v)`——复用 `access.Authenticate`（网关运行时接受谓词，覆盖 store 内自签 key + 用户自带 own-value key + 迁移期 legacy LAN 回退），本网关认的 key 即安静；外来 key（另一台 magpie 签发的、本网关会拒的）与 off 态 key 仍报。**范围裁决**：`.env` 侧（wiringOff 731 行）不同修——serving 轮会按期望内容重写 .env 自愈，属瞬态；`access.Named` 不用——只验前缀形状，会把另一台 magpie 的 key 也放行，真 401 场景会被消音。
- **TDD 闭环**：新测试 `TestDshStoreHoldingAGatewayCallerKey`（access.Update("add-key") 签发真钥匙放 refs），修前红 = 报告者的原句 drift，修后绿；既有 `TestDshStoreOfTheUsersOwn`（外来 key 必报 holds another）不受扰——外来 key 语义边界被测试钉住。
- **验证矩阵**：agent 包 `-count=1` 绿（17.7s）；dsh 三 store 测试 `-race -count=10` 绿；gofmt 净；vet 包级净；三平台 build 过；全量 nogui 套件 43 包绿 + testenv TestOffline 同一预存环境红（本机回环代理逃逸，已在 MG-1 轮基线定性）。
