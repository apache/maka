## 状态口径

✅ 署名合入 / ✅ 采纳自实现 / ✅ 方向吸收 / ↺ 同构取代·让位 / ✗ 被拒 / ⏳ 等确认·待审 / 🗂 分析在案——全表定义见[../README.md](../README.md)。

> **"在途"实数口径（2026-10-29 定，勿再拿痕迹数当实数）**：行是只增不改，⏳ 会留在已结单行的历史段里——**含 ⏳ 痕迹的行数 ≠ 未合并/未关闭数**。真在途 = **行尾最新状态标记为 ⏳ 且 GitHub 上 issue 仍 open**。10-31 深夜实测（hunt113 大摸底后）：痕迹候选 128；**净可用在途 patch ≈95–99**（死支 ~15 出列：收编 9+驳回 1+被取代 7+分支已删 2，全部经批测验证）；分层=新交付 22/中期 ~48/老存量 ~32；分析在案 3 另计。对时脚本一律按"行尾最新标记 + GitHub state"过滤。

## 记账规则

- 一单一行、只增不改：新事实追加在行尾（日期+事件+链接），不改旧文字。
- 行内禁裸 `||`（Markdown 表格会吃成单元格分隔符）；链接用 issue 评论 permalink。
- 唯一写者=当轮收口的主线程；子智能体只报告不写。
