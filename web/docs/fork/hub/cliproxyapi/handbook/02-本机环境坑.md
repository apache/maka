# CLIProxyAPI 本机环境坑

> 整理说明：命令、认证、版本与结果按原文核验时点保留；本轮仅整理文档，未刷新远端、认证或重跑测试。

> 两节按平台适用（各自实测）；平台无关的纪律在两节里共用的照旧生效。
> 2026-10-02 起主力环境为 macOS；Windows 节在 Windows 侧会话仍适用。

## Windows + Git Bash（2026-09 起实测）

- `core.autocrlf=true` → checkout 后全是 CRLF，`gofmt -l` 会把**所有文件**报成未格式化。判定真实格式问题：`tr -d '\r' < file | gofmt -l /dev/stdin`，有输出才是真问题。
- `go test ./...` 全量并发编译会把 Go 编译器本身搞崩（`compile.exe exit status 0x80000003`、`fatal error: fault in ssa/debug.go`），纯 main 也崩。用 `go test -p 2 ./...` 降并发可过编译。
- executor 包的 xai/antigravity WebSocket 测试在本机合跑下随机 flaky（两次全量失败集合不同：Images/Videos/Websockets/AuthBalance 轮着挂），单跑即绿。定性手法见 03-逐单台账 PR-001。**注意（2026-10-02）**：该预存病在 mac 侧 dev 基线不复现（v8 迁移重构过测试布局），此条仅 Windows 侧适用。
- 验证矩阵（AGENTS.md 要求）：改动的包测试 + `gofmt` + `go build -o test-output ./cmd/server && rm test-output`。
- `gh` CLI 已认证（`"C:\Program Files\GitHub CLI\gh.exe"`，旧 Git Bash 会话 PATH 不刷新用完整路径）。
- 后台跑测试别接 `| tail`（吞摘要），输出落文件再 grep。

## macOS（2026-10-02 起实测）

- 主仓 `/Users/ggbdpq/cc/code/fork/CLIProxyAPI`（2026-11-07 ls 核实；原记 `fork/cliproxyapi-hub/CLIProxyAPI`，2026-10-14 起住 hub 内，hub 现已撤为 fork 平铺）。需要多线并做时在 hub 内按需建 `cpa-pr1` 起的独立克隆（非 worktree，各带 .git，用完即删）——此为 hub 时代做法；现行并行改用 `/tmp` worktree，见 [11-维护任务书](11-维护任务书.md) 第 2 步与 [handbook/07 §5](../../../handbook/07-分工与并行.md#5-worktree-规范)。
- gh：`/opt/homebrew/bin/gh`（已在 PATH，直接用 `gh`）；已认证（ggbdpq，keyring）。旧版不认 `gh pr close --reason`；REST `PATCH /issues` 的 `state_reason` 对 **PR 无效**（响应落 null）——关单理由标记缺失可接受，评论带说明即可。
- 宿主 go 1.25.5，go.mod 要 1.26.0：`GOTOOLCHAIN=auto` + `GOPROXY=https://goproxy.cn,direct` 会自动拉 go1.26.0（实测 13.8s，2026-10-02），无需手动装。
- Bash 工具的 cwd 会在调用间重置（zsh 配置噪音 `_encode/_decode` 报错无害）——git 一律 `git -C <绝对路径>`（家目录本身是个 git 仓库，裸 git 命令会落到错误的仓）。
- mac 无 CRLF 坑（gofmt 直接跑）；`go test -p 2` 防编译器崩的纪律照旧。
- **代理进程没开时（2026-10-02 实测）**：本机配置了本地代理（git 全局 `http.proxy=127.0.0.1:7897` + env `all_proxy=socks5://127.0.0.1:10808`），代理死了会表现为 gh/git 全部 `connection refused`。两条网络路径命运不同：github.com 主站直连**不通**（git fetch 卡 75s 超时），api.github.com 直连**可达**——降级姿势：gh 用 `env -u http_proxy -u https_proxy -u all_proxy gh ...`，git 用 `git -c http.proxy= -c https.proxy= ...`（fetch 仍失败，dev 对象级工作受阻时等代理恢复，开场用 `gh api repos/.../branches/dev` 查 dev head 代替）。
