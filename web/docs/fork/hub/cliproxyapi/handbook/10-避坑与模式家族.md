## 避坑清单（接单前过一遍）

1. 动手前 `git log upstream/dev --grep <关键词>` 最新 20 条——当日消化模式（#6414 教训）。
2. PR/issue 两类评论通道：`issues/comments` 不含行内 review——扫反馈用 `pulls/comments`+`pulls/reviews` 三端点（维护Ⅵ）。
3. push 触发 bot 复审落在收尾窗口后——**下轮开场对上轮 push 过的 PR 强制重查线程**（批2/批3 两次漏盘）。
4. `gh api` 发长文用 jq 构建 JSON 走 `--input`，永不 `-F body=@file`（r16 五条垃圾回复事故）。
5. 等表态类对象每轮查 `state`+`state_reason`，不能只增量扫评论（#6362 漏看四轮）。
6. 内联 `-d` JSON 遇长破折号静默失败——payload 先写 body.json 再 `-d @file`。
7. mergeable clean ≠ 语义无冲突：模块路径迁移后对分支新增文件 grep 旧 import；rebase 撞同域重构先懂对方骨架再落自己语义。
8. PR 编号等创建响应拿到再写进引用评论（预写错两次）；发外文本先读一遍再发。
9. `git log -S "<串>" -- <path>` 钉出身是裁决性文本（"最便宜实验拿裁决文本"）。
10. 台账的状态断言也要对抗复核（#5520"无生产端"误记）；错误不回写旧条目，新条目显式更正。
