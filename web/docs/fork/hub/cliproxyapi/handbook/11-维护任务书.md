逐 PR 四步（10-25/26 四轮实战定型）：

1. **定 rebase 面**：`git log --oneline <旧dev>..upstream/dev` 扫新提交，同域候选逐个 `git show --name-only` 列文件，与各单 `gh pr diff <n> --name-only` 对齐——**文件级交集实锤才 rebase**，零交集且 MERGEABLE 的单不动（纯刷 base 收益不抵 force-push+CI 重跑的风险面）。取代判定看语义不看文件：同文件不同 hunk/不同特性=未取代（先例：#5511 `LevelsAssumed` 与上游 thinking 改动三次同文件共存）。mergeable UNKNOWN 是 dev 推进后的重算瞬态，数分钟收敛后复查。
2. **rebase**：worktree `git worktree add /tmp/cpi-rb-<n> <分支>`；本地分支可能停在旧 head（别名分支推送遗留），先 `git merge-base --is-ancestor <旧head> <origin现值>` 核实再 `reset --hard` 快进。冲突按语义解，已知四型先例：`Result{}` 字面量多字段并存（上游 ExecutionSeq/AccessToken vs 我方 UpstreamModel，字段级双保留）；函数签名双方各加参数的合并（签名+调用点成对改）；记录值演进链（execModel→execReq.Model→executedUpstreamModel，按提交顺序逐级换值、保留上游新字段）；`reporter.SetTranslated*` 与 `helps.RecordWireModelMetadata` 并存。**批量脚本解完必须 grep 抽查字段值完整性**——编译通过≠字段没丢（截断值 `ExecutionSeq}` 实锤一次）。
3. **验证**：改动包 `go test -count=1` + `go build ./...` + 改动文件 gofmt；零文本冲突≠零语义，语义以包测试背书。
4. **推送与复核**：`--force-with-lease` 的 expect 现值一律 `git ls-remote origin <分支>` 取完整 SHA（凭短 SHA 拼长必错，stale info 实锤）；push 后等 5–12 分钟复核 threads/CI——零语义 diff 的 rebase 不触发 bot 复审（五次先例），线程零新增+CI 三查绿即收口。
