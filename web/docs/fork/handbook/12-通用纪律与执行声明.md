## 通用纪律

- **开场先同步再动手**：`git fetch upstream` 后 base 快进（普通仓 `git merge --ff-only`；GitButler 托管仓 `git fetch upstream <base>:<base>` 不动工作区）。
- `gh pr list --author ggbdpq --state open`（或 issue 扫描）逐单核对评论/review/CI/mergeable；数量以开场实测为准。
- 新评论与审查意见逐条处置——采纳修复带验证、反驳留证回复；老单动手前重核行号与状态。
- commit 双 flag `-c user.name=ggbdpq -c user.email=ggbdpq@gmail.com`（`/tmp` 下的 worktree 吃不到 includeIf，出过字面量事故）；force-push 一律 `--force-with-lease`（expect 现值用 `git ls-remote` 取完整 SHA）。
- zsh 显式 refspec 陷阱：双引号内 `"$var:refs/..."` 的 `:r` 被吞，写 `"${var}:refs/heads/<分支>"`。
- 测试输出不接管道（`| tail` 吞退出码出假绿），落文件再 grep；CI 判绿前核对 run 的 headSha 精确等于本方推送 SHA。
- 验证不谎报、没跑的列 not run；动作记账到本仓 journal 与总台账行。
- 台账/表格行内禁裸 `||`（Markdown 吃成单元格分隔符）；文件追加后必须回读。
- 改动 docs 后在 docs 根跑 `python3 scripts/docs_lint.py`：ERROR（断链、表格列数不符、台账生成块缺失或失配）清零才算收口；迁移/改名文件必须同轮改完引用（规则见 [10 §9](10-文档维护与结构.md#9-可信度与验收)）。

## 命名规范（2026-11-01 全仓定版）

分支、提交与产物命名全仓统一（magpie 先行定版后上收；正典条文见 [hub/magpie/issues/README.md 命名节](../hub/magpie/issues/README.md)）：

- **分支**：新建分支 `<type>/<单号>-<slug>`——type 按改动性质取 `fix|feat|test|docs`；单号=上游 issue 号；slug 用 2–4 个 kebab 词说明改的是哪块（如 `fix/4530-leastused-paygo-zero`、`feat/2031-key-pool`）。**老分支一律不改名**。分支 base 仍按各仓规则（CLIProxyAPI=`upstream/dev`、maka=`upstream/main`、其余见各自仓规），与命名正交。
- **提交 subject**：`<type>(<scope>): <summary> (#N)`，scope=子系统/模块名；正文写 What changed / Run；尾注 `Generated-by: <模型> (<工具>)` 照旧。magpie 现行用 `fix(<scope>): …`，其余仓按改动性质选 type。
- **本地产物目录**：magpie 的产物落位与目录命名见 [hub/magpie/handbook/11 狩猎轮机制](../hub/magpie/handbook/11-狩猎轮机制.md) 与 [hub/magpie/issues/README](../hub/magpie/issues/README.md)，本页不复述；其余 PR 仓已有 `issues/` 目录的（multica/orca）用 `<单号>-<slug>/`，没有的不新建结构，产物链接挂台账行。
- **同一单重发/重做**：目录加 `-v2`；PR 场景优先复用原分支 `--force-with-lease` 强推（review 上下文不丢），不另开新分支。

## 台账生成统计

改动 `handbook/02-接单总台账/` 的台账行后（新增、状态更新或迁归档），必须在 docs 根执行 `python3 scripts/ledger_stats.py --apply`，再跑 `python3 scripts/ledger_stats.py --check` 与 `python3 scripts/docs_lint.py`，两项退出码都为 0 才算收口。`--apply` 会将活账中的终态行迁入归档并刷新生成块；执行后回读 diff，确认台账行原文未被脚本改写。**禁止手改计数**：行数与全局号范围只保留在各仓文件自己的生成块；旧头部计数句冻结保留，禁止随新增行或迁归档同步修改；待确认各会话均采用生成块后，再单独移除。README 只作索引，不维护汇总计数。
