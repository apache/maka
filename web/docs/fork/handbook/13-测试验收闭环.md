## 原始思维骨架（2026-11-01，历史记录，不作现行规则）

**第一性原理**（状态只信本轮实测，台账/记忆=线索——判定回到「这个 bug 现在还在吗」）、**消融实验**（消红：摘掉修复测试必须回红，证明改动是成因而非巧合共存）、**对抗式审查**（收编双层查+POST 前 grep 重查+GET 回读：假设自己会错，每步留机械复核点）、**奥卡姆剃刀**（「上游已修」是比「我需要 rework」更简单的解释，让位优先）、**YAGNI**（字节不变不做多余动作：不例行 force-push、不发无变更 refresh）、**高内聚低耦合**（环节跟着变更走，验证域与变更域耦合，变更没发生验证不空转）、**批判性思维/独立思考**（对账报「零收编」也要复核扫法本身——--since 漏检、宽模式假阳性判例）、**蒸馏**（实例判例蒸馏成规则条目，规则被下一轮实测校验后修订）。

## r9-r11 实战校准（2026-11-02，magpie 六轮 73 推 62+ 收之后）
- **判定闸双向作用实证**：r9 的 11 支用户报老支出列 7（报废/冲突）；同轮 #3478/#2547 两支被判定闸从纸面「自留族/打折」判定里**救回**（实证 RED 仍在、上游 prod 零提交）——闸既拦死单也救活单，**纸面三征不算数，摘 patch 跑 RED 才算数**。
- **「am 即进」的严格口径**：严格 `git am` 失败但 `am -3` 自动合+测试全绿 = 纯上下文漂移无语义冲突——**仍不进帖**（维护者流程是普通 am，r10 四支因此出列转 rebase）。`-3` 干净只说明 rebase 会顺利，不等于发布承诺成立。
- **无声收编第三形态**：#1677 维护者把我方分支头**原样 fast-forward** 进 main、未发帖——对账除单号 grep 外，**分支 head == main 内提交**也是收编判据。
- **一 patch 盖双单**（#4525+#4527）：帖内合并一行、批测一次覆盖两 issue，台账两行各自记。
- **跨仓出口**（#4657 范本）：patch 修在哪一层要让位给正确的层——网关面让位，修复落 Zed 插件+provider 双侧，署名以 Co-authored-by 保留；**让位≠丢署名**。
