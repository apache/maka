## 2. 半月巡检的固定动作

逐个 open PR 过一遍：

1. **状态**：merged / closed / mergeable / CI 实际红绿（看 check-runs，不看汇总显示）。
2. **未处置意见**：全量拉取 reviews 与 review threads，统计未解决线程。updatedAt 没变也要看，未解决的线程属于存量问题。
3. **冲突**：和最新 base 做 merge-tree，有冲突就派一路维护子智能体去解。
4. **超过 14 天无信号**：三选一并记录理由——gentle ping / 主动关闭 / 继续等。
5. 结果写进该项目 `journal/在途快照.md` 的文首新节，并在 [巡检日历](#3-巡检日历) 打勾。

## 4. 升降级

- **半月 → 主力**：维护者 @ 了我、提出 review 要求，或 PR 进入可合并状态。当轮按主力节奏处理，处理完再回半月节奏。
- **主力 → 半月**：连续 2 周既没有在途 PR 也没有合格候选。
- 升降级都由你拍板；改梯队表时直接更新本章 §1 表，并在 [02-接单总台账](02-接单总台账/README.md) 对应预算行注明一句。

## 5. 人的固定时间

yetone 每晚抽一点时间"铲屎"。这里对应的是：每天收工前看一遍各项目报告里的「需要人拍板」和「本轮不自信的点」，只处理 AI 判断不了的事，包括方向分歧、对外口径、UI / UX 取舍，以及是否放弃一单。
