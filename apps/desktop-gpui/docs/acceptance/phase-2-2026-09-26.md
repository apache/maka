## Defects and deviations

- **D1 (docs).** `packaging/README.md` says an app opened with `open` does not inherit the
  shell's environment. It does.
  - Repro: in a shell with `DEEPSEEK_API_KEY` set, run `open -n "Maka GPUI.app" --args --root
    <fresh root>`.
  - Expected: no key in the app.
  - Actual: `ps eww` shows `DEEPSEEK_API_KEY`, `OPENAI_API_KEY` and the shell's PATH in the app
    (pid 49772) and in its Host (pid 49785). The Host then imported the key:
    `connection-catalog.json` revision 2 holds `env-deepseek` as the default, with model
    `deepseek-v4-flash`.
  - A launch from Finder was not tested.
- **D2 (product, W1).** The Add connection form checks every discovered model, and "Use as the
  default model" takes the first enabled one, in Ollama's listing order. Here that was
  `qwen3:0.6b`, so every ⌘N task started on it, and it answered without a tool. Set as default
  in the connection detail also takes the first enabled model. So the order of the enabled
  models is the only way to choose the default. A re-checked model moves to the end of that
  order (`ConnectionsPane::set_model_enabled`), which is not a choice a user would find.
  - Expected (plan): `qwen2.5:7b` as the default.
  - Actual: `qwen3:0.6b`.
- **D3 (tooling).** `live_sidebar` returns "the task list or the project list was not read"
  unless the catalog already lists a task: its first wait requires `!catalog.rows().is_empty()`.
  On a fresh root, which is exactly the first-user case, it cannot register a project. This is
  from reading the code; I did not run it on the empty root. Worked around by running step 6
  first.
- **D4 (tooling).** `live_turn` never activates its window. Behind the bundle's window it was
  not redrawn, and its screenshot still showed "No session selected" after the turn. The
  screenshot was dropped.
- **D5 (tooling, from reading the code; not run).** After saving, `live_add_connection` opens
  the model menu with `tab, enter`. `main.rs` uses `tab, tab, enter`, because "+" now sits
  between the draft and the picker. With a real `--session`, the example would press "+".

Other observations:
- The model writes task titles in Chinese even in the English UI.
- New tasks start in `bypass` (Full access), the Host's default.
- Each cold start logs `WARN project.catalog.query failed: not connected to the Runtime Host`.
  The projects load after the connection comes up.
- Maka Desktop is installed and running on this Mac, so "without the Electron Desktop
  installed" was not reproduced literally. The spawn line shows that the Host came from the
  checkout.

Not exercised:
- The dialog's Continue and the native folder pickers.
- Typing in the form: the example calls the form's methods instead.
- ⌘N, the model menu and the queue plate by real keyboard or mouse in the bundle.
- A mid-session model switch on the ⌘N task.
- Permission prompts: none were raised in `bypass` mode.
- Launching from Finder.
- Windows.
