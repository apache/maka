# Design review, 2026-09-26

The Design review checklist and the Accessibility checklist of the gpui-kit Design Guides
(`.agents/skills/gpui-kit-design-guides/references/design-guides.md`), run against five
surfaces after W5 (localization, command palette, keyboard help): the main window, the
Settings dialog, the footer menu, the task menu, and the command palette.

Method: the app at 1512x885 against the dev Host on `.dev-root`, on a task with two tool
calls (`--session 5b3ba118…`), each surface opened with its `--open-*` flag through the
keyboard path, captured in the light and the dark system appearance. Keyboard and focus
claims rest on the `#[gpui_kit::test]`s named below, not on the pictures.

## Fixed in this pass

1. **Dark dialog backdrop did not dim.** gpui-kit's themes set the `overlay` token to 5%
   black (light) and 20% black (dark); over the dark theme's near-black background 20% is
   invisible, so dialogs seemed to float on a live window. `settings::apply_appearance`
   and the system-appearance observer now set it to 20% (light) and 50% (dark, Shadcn's
   value) after every theme change. Test: `a_change_applies_at_once_and_is_saved` asserts
   the alpha in both modes. Compare `review-settings-dark` with `settings-connections-dark`.
2. **Sidebar toggle icon.** It switched between PanelLeftClose and PanelLeftOpen; it is now
   the plain PanelLeft in both states, as AllSum draws it. The accessible name and tooltip
   still say Hide sidebar / Show sidebar with ⌘B.
3. **Provider monograms.** A grey square with a letter, the same for every connection. Now
   gpui-kit's `Avatar` name fallback: a 40-point disc tinted from the letter on a ring of
   OkLCH hues that gpui-kit pins to WCAG AA contrast in light and dark, so a connection
   keeps its color in both themes (the D and O discs in `review-settings-*`).
4. **Commands that open a dialog lacked the ellipsis** in the palette and the shortcuts
   sheet ("Keyboard shortcuts", "Command palette"), unlike the menus. They now read
   "Keyboard shortcuts…" and "Command palette…"; the sheet's title keeps no ellipsis.
5. **Settings search promised more than it did.** The field says Search but matched only
   section names, so "appearance" or "API key" found nothing. It now also matches the
   settings each section holds (Language and Appearance under General; Models, Provider,
   API key, Service URL under Connections; …), in the current language and in English.
   Test: `the_section_list_switches_sections_by_click_and_keys_and_filters` searches "appearance" and
   "api key".

## Design review checklist

1. **Is the task clear?** Pass on all five. The main window opens on the task's
   transcript with the composer ready; an empty task shows the suggestions. The palette's
   placeholder names what it searches (commands, settings, tasks); the task menu is titled
   by the row it opened from.
2. **Does every action keep its promise?** Failed twice, fixed (items 4 and 5 above).
   Palette commands act on what their label names: Archive task and Flag task on the
   selected task, and they read Unarchive task / Unflag task when that is what they do.
3. **Is hierarchy decisive and restrained?** Pass. One primary button per surface (Add
   connection in Settings; Send in the composer, only when there is something to send).
   The Default badge is the only colored text in the Connections list; the monogram tints
   are pale in light and deep in dark, below the text in weight.
4. **Could the interface do less, better?** Pass. The palette hides commands that cannot
   run (Stop without a running turn, Back without history, model choices while a turn
   runs) instead of listing them disabled; the footer menu has four items.
5. **Is the structure exact?** Pass, one note. In the sidebar the search button, the ⌘N
   hint, and the age column end on one right edge; palette rows, headings, and the query
   field share one inset. Note: in dark, the dialog surface and the dimmed window are both
   near black, so a dialog's edge is carried by its 1 px border alone (see Remaining).
6. **Does it follow the component system?** Pass with one documented exception: the
   palette is gpui-kit's `Command` in a `Dialog`, menus are `PopupMenu`, the monogram is
   `Avatar`, hints are `Kbd`. The palette draws its own row content (icon, label, `Kbd`) so
   that the Workbench, not the palette, dispatches the Action after the dialog has closed
   and focus has returned; `Command`'s default row would dispatch first.
7. **Does it remain usable in every state and constraint?** Partial. Keyboard, focus,
   empty (palette "No matching commands"), and loading states are covered by tests;
   Simplified Chinese was checked in the real window (commit 2518610). Not re-verified in
   this pass: the 960x600 minimum window, a larger base font, reduced motion, and a
   language longer than English.
8. **Has it been tested in a real window?** Pass: every screenshot above is the app
   against the dev Host, opened through its keyboard path.

## Accessibility checklist

1. **Every action is reachable and operable by keyboard.** Pass. Tests:
   `tab_walks_the_sidebar_then_the_composer` (now through the new search button),
   `the_command_palette_filters_runs_a_command_and_returns_focus`,
   `escape_clears_the_query_then_closes_the_palette`, the task menu's Shift-F10 and the
   footer menu's Tab-Enter paths in `chrome_tests`, the Settings list's arrows, Home, End.
2. **Focus order follows visual and task order.** Pass: the Tab walk goes window
   controls, search, New task, folder, grouping, list, footer, then the main pane and the
   composer, as drawn.
3. **Focus remains visible and is restored after overlays.** Pass: palette, shortcuts
   sheet, Settings, and footer menu tests assert focus returns to the draft or the row
   that opened them. The palette runs its command after the return, so Focus composer and
   opening a task keep the focus they move.
4. **Controls have accessible names; icon-only controls have tooltips where needed.**
   Pass with a limit: the toggle, Back, Forward, search, "+", Send, and Close are named, and
   the chrome buttons carry tooltips with their shortcut. The palette's query field has
   only its placeholder (gpui-kit's `CommandState` draws the field and offers no label).
5. **Text and meaningful boundaries have sufficient contrast.** Pass by construction
   (gpui-kit's neutral tokens; the monogram colors are pinned to AA by gpui-kit's tests);
   the dark backdrop now separates the dialog layer. Not measured with a contrast tool.
6. **Status is not communicated by color alone.** Pass: the connection state is a dot, a
   spinner, or a warning sign, with words whenever it is not connected; tool cards pair an
   icon with Done / Failed / Stopped; the checked palette choice has a check mark.
7. **Disabled and read-only states are distinguishable.** Pass: Back and Forward dim when
   there is no history; Send dims with an empty draft.
8. **Labels, errors, and descriptions remain near their controls.** Pass: each setting's
   help sits under its title; failures show in the pane or card they concern.
9. **Content remains usable with longer translations and larger text.** Partial: rows and
   titles truncate with an ellipsis; menus have a minimum width; Chinese fits. A longer
   language and a larger base font were not tried in this pass.
10. **Pointer targets are comfortably sized.** Pass: controls use gpui-kit component sizes;
    the smallest are the chrome's small ghost buttons (24 points), as in AllSum.

## Remaining

- Dark dialogs have no elevation: gpui-kit's `Dialog` paints the `background` token, the
  same near black as the window, so only the border marks the edge over the 50% backdrop.
  A raised surface would need a theme token gpui-kit's dialog does not read.
- The palette's query field has no accessible name, and Home and End move its caret rather
  than the list (gpui-kit's `Command` binds Up, Down, Enter, Escape only). The field owning
  Home and End is also what editors do.
- Menus opened from the keyboard (task menu, footer menu) open without a highlighted item;
  Down highlights the first (gpui-kit `PopupMenu`).
- GPUI exposes no screen-reader tree: the accessible names above reach tests, not
  VoiceOver.
- A failure message already on screen keeps the language it was written in until it is
  replaced; reasons from the Runtime Host are English in every language.
- The monogram is sized in points (as `Avatar` sizes itself), so it does not follow the
  base font.
- `--open-footer-menu` now stops with Settings… highlighted instead of opening the
  Language submenu, since Down highlights the first item; the launch helper, not the menu.
- Not re-verified in this pass: minimum window size, larger text, reduced motion.
