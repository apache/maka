# 前端开发全生命周期规则

> 覆盖从需求到上线的完整开发流程，确保 AI 协作的规范性和可追溯性

---

## 📋 阶段一：需求分析

### PRD 理解

- 阅读 PRD 时，提取：功能点、验收标准、边界条件、异常场景
- 不清楚的需求点，列出问题清单，一次性确认
- 将理解的需求转化为可执行的任务拆解

### 设计稿对接

- 确认设计稿交付物：Figma/Sketch 链接、标注文件、切图资源
- 检查响应式断点、交互状态（hover/active/disabled/loading）
- 确认设计规范：色值、字体、间距、圆角等 Design Token

### 输出物

- 需求理解文档（可选）
- 技术方案评审要点
- 工时评估（按功能模块拆分）

---

## 📐 阶段二：技术方案

### 系统设计

- 前端架构：路由设计、状态管理方案、组件拆分
- 接口设计：与后端对齐 API 契约（OpenAPI/GraphQL Schema）
- 数据流设计：请求时机、缓存策略、乐观更新

### 技术选型原则

- 优先使用项目已有技术栈
- 新引入依赖需评估：包体积、维护状态、社区活跃度
- 避免过度设计，YAGNI 原则

### 输出物

- 技术方案文档（复杂功能必须）
- 接口契约文档
- 组件树/数据流图（可选）

---

## 💻 阶段三：编码开发

### 代码规范

- 遵循项目 ESLint/Prettier 配置
- 组件命名：PascalCase，文件名与组件名一致
- 函数命名：camelCase，动词开头（get/set/handle/fetch）
- 常量命名：UPPER_SNAKE_CASE

### 目录结构

```
src/
├── components/     # 通用组件
├── pages/          # 页面组件
├── hooks/          # 自定义 Hooks
├── utils/          # 工具函数
├── services/       # API 请求
├── stores/         # 状态管理
├── types/          # TypeScript 类型
└── styles/         # 全局样式
```

### Git 工作流

- 分支命名：`feature/xxx`、`fix/xxx`、`hotfix/xxx`
- Commit 规范：Conventional Commits
- PR 描述：包含改动说明、影响范围、测试要点

### Mock 开发

- 使用 MSW 模拟后端接口
- Mock 数据贴近真实场景
- 覆盖正常流程和异常流程

---

## 🧪 阶段四：测试验证

### 测试金字塔

```
        /  E2E 测试  \        ← 少量关键流程
       / 组件集成测试 \       ← 核心组件
      /   单元测试     \      ← 工具函数、Hooks
```

### 单元测试

- 工具函数：输入输出验证
- Hooks：状态变化验证
- 覆盖率目标：核心逻辑 > 80%

### 组件测试

- 渲染测试：关键元素存在性
- 交互测试：点击、输入、表单提交
- 状态测试：loading/error/empty/success

### UI 测试

- 视觉回归测试（可选）
- 响应式布局验证
- 无障碍检查（a11y）

### 自测清单

- [ ] 功能完整性：所有需求点已实现
- [ ] 边界条件：空数据、超长文本、特殊字符
- [ ] 异常处理：网络错误、接口超时、权限不足
- [ ] 兼容性：目标浏览器、移动端适配

---

## 🔗 阶段五：联调部署

### 前后端联调

- 切换 Mock 到真实接口
- 验证接口契约一致性
- 处理真实数据的边界情况

### 环境部署

```
开发环境 (dev) → 测试环境 (test) → 预发环境 (staging) → 生产环境 (prod)
```

- 每个环境独立配置
- 部署前检查：环境变量、API 地址、Feature Flag

### 部署检查清单

- [ ] 构建无报错
- [ ] 环境变量正确
- [ ] 静态资源 CDN 配置
- [ ] 错误监控接入（Sentry 等）

---

## 🐛 阶段六：Bug 修复

### Bug 定位流程

```
1. 复现问题 → 确认复现步骤
2. 定位范围 → 确定是前端/后端/数据问题
3. 分析原因 → 查看日志、断点调试
4. 定位文件 → 找到需要修改的代码位置
5. 修复验证 → 修改代码并验证
6. 回归测试 → 确保不引入新问题
```

### Bug 记录模板

```markdown
## Bug 描述

[问题现象]

## 复现步骤

1. ...
2. ...

## 根因分析

[产生原因]

## 解决方案

[修复方法]

## 影响范围

[涉及文件/功能]

## 经验总结

[如何避免类似问题]
```

### Bug 分类

| 类型     | 示例                 | 预防措施     |
| -------- | -------------------- | ------------ |
| 逻辑错误 | 条件判断遗漏         | 单元测试覆盖 |
| 状态问题 | 竞态条件、内存泄漏   | 代码审查     |
| 样式问题 | 布局错乱、响应式失效 | 视觉回归测试 |
| 兼容问题 | 浏览器差异           | 兼容性测试   |
| 接口问题 | 数据格式不一致       | 契约测试     |

## 📚 阶段七：知识沉淀

### 沉淀时机

- 解决复杂 Bug 后
- 实现创新方案后
- 踩坑后的经验总结

### 沉淀内容

- 问题背景和上下文
- 解决方案和代码示例
- 适用场景和注意事项
- 相关资源链接

### 存放位置

| 内容类型   | 存放目录                    |
| ---------- | --------------------------- |
| 技术知识点 | `02-专业技能/`              |
| 可复用代码 | `04-项目资产/可复用资产/`   |
| Bug 经验   | `05-面试与复盘/` 或项目文档 |

- 每个迭代结束后回顾
- 记录做得好的和待改进的
- 更新规则和流程

### 规则演进

- 规则不是一成不变的
- 根据实践反馈持续优化
- 保持规则的简洁和可执行性
