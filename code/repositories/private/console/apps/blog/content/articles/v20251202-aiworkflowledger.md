# AI Coding的瓶颈不是模型，而是缺少“项目演化系统”

- **视频 ID**：`V20251202-AIWorkflowLedger`
- **日期**：2025-12-02

> **一句话**：AI Coding 的瓶颈不是模型，而是你的信息工程能力：结构化输入 + 可复用的 Lessons 池。

## 精华总结
- 结构化输入比事后补救重要：不给足上下文，AI 只能瞎猜。
- Ledger 六点结构：Context / Options / Decision / Design / Result / Lessons，用来把项目历史变成 AI 的“历史书”。
- 高效做法是：找开源代码 → 让 AI 在此基础上修改；不要让 AI 从零写复杂专业代码。
- 长期护城河不是模型，而是你自己的 Lessons 与项目级 benchmark（用自己的项目测新模型）。

## 行动清单
1. 把 Ledger 六点写进你的项目模板（每次决策都落地）。
1. 每次翻车写一条可迁移 Lessons（不要只记录 error 细节）。
1. 新模型出来别看外部 benchmark，跑你的项目级 benchmark 看能过几关。

## Highlights（原文摘录）
- “结构化的输入，比你事后怎么去提取、怎么去折腾，要重要一百倍。”
- “你不给它足够的上下文，AI再聪明它也只能瞎猜，只能用通用答案糊你。”
- “Context / Options / Decision / Design / Result / Lessons，是我给项目加的六点结构。”
- Lessons 的作用，是把工程师的隐性直觉，压成可复用的显性知识。”
- “在专业领域做研究型任务，让 AI 从零写代码，效率极差。”
- “真正高效的做法是：找开源代码 → 让 AI 在此基础上做修改，One-shot 达成目标。”
- “AI 总结出来的是一堆细节 error，我总结的是一行可迁移的决策规律。”
- “Codex 成功次数太多，让我严重高估了它的稳定性，忽视了它必翻车的场景。”
- “未来最强的武器不是模型本身，而是你手里那一整套 Lessons 池。”
- “新模型出来不要看外面的 benchmark，直接跑自己的项目级本质Mark，看它能过几关就够了。”

## Insights（原文摘录）
1. 本视频在你的内容体系里，更偏 L3（实践与实例），但已经开始向 L4（系统与未来）过渡：
   - 用一个真实翻车案例，说明「结构化输入」的重要性
   - 把 Ledger 的六点结构和 Lessons / Benchmark 的长期价值串起来

2. 关键认知升级不是“再吹一次 Codex”，而是承认一个残酷事实：
   - 模型已经够聪明了
   - 限制它的，是你喂给它的上下文结构和你有没有把经验压成 Lessons
   换句话说，你目前的生产力上限，主要卡在**信息工程能力**，不是“提示词技巧”。

3. 这期其实干了两件事：
   - 给 Ledger 补了一块「可复用经验层」（Lessons）
   - 给未来的「模型选型系统」打了地基（项目级本质Mark）
   你从“用 AI 写代码”彻底走向了“用项目历史去驯化和评估 AI”。

4. 你现在还在靠自己写 Lessons，这很原始：
   - 优点：视角清晰、抓本质
   - 缺点：完全靠你的自觉和时间，不可扩展
   下一步如果你不把「生成 / 审核 / 去重 / 归档 Lessons」变成强制工作流节点，这套系统最后很容易退化成「你一个人的高档笔记本」，而不是流水线的一部分。

5. 你对外说的是“Lessons 是未来最强武器”，对内其实是在做两件更深的事：
   - 给自己建一个「不会被新模型绑架的决策层」——不看厂商 benchmark，只跑自己的benchmark
   - 给未来的“自动模型路由 / Auto-ML for LLMs”打基础——一旦你真的把模型切换逻辑自动化，你就离「把自己从链路中剔除」更近一步。
