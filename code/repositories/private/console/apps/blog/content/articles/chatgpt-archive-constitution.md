# ChatGPT 项目归档宪法 v1.1

文件名建议：ChatGPT 项目归档宪法\_v1.1.md  
描述：定义 ChatGPT 对话与资料的统一目录结构、子类、命名规范与裁决规则，解决分类混乱、重复归档、难检索问题。本文不包含公众号文章 11 类归档体系。

## 0. 范围与边界

范围

1. 仅管理 ChatGPT 内的项目文件夹结构
2. 仅管理每条对话的归档位置、子类、标题命名与沉淀产物
3. 允许为面试复用做结构优化

边界

1. 不讨论微信公众号文章分类
2. 不引入 01 到 11 的文章主题体系
3. 文章库管理请使用另一份文档：公众号文章归档宪法

---

## 1. 顶层目录标准（定型为 8 个）

原则  
顶层只承接目标域与产物形态，避免主题穿透顶层，主题放到子类与标题里。

1️⃣ Mac 开发环境  
放系统配置、终端、网络、效率工具、排障

2️⃣ 前端核心  
放 React 基础、TypeScript、工程化、组件模式、常用实践

3️⃣ 前端进阶与项目  
放大型项目实践、性能、工程架构、项目复盘与案例

4️⃣ AGI 核心  
放 Agent 基础概念、提示词方法、评估范式、读书与论文笔记

5️⃣ AGI 工具链与工程实践  
放 Claude Code、Codex、Gemini CLI、Cursor、技能系统、工作流、脚手架、工具开发与排障

6️⃣ 架构思维与方法论  
放工程治理、宪法体系、执行法典、流水线契约、组织化方法与协作机制

7️⃣ 每日复盘与周报  
放 Day 日志、周复盘、月度总结、年度复盘

inbox 收件箱  
放未决策内容，要求可清空

约束

1. 每条对话必须选 1 个子类
2. 子类允许新增，但必须可复用且高频
3. 子类优先使用词表中的既有项

## 3. 标题命名规范（强约束）

统一模板  
【子类】对象或系统｜要解决的问题或产出

示例  
【排障】Claude Code CLI｜切换渠道后 resume 失败与 400 的根因与规避  
【项目开发】claude-profile｜仓库改名与路径重构的步骤清单与验收项  
【方法论】知识库归档｜项目归档宪法 v1.1

约束

1. 标题必须可检索，包含对象名与关键问题
2. 标题不写空泛词，例如 随便聊聊 学习记录
3. 需要版本信息时写在标题尾部，例如 v0.0.1 v1.1

## 5. 归档裁决规则 v1.1（核心）

### 5.1 三段式裁决

第一段：目标域  
工具链工程实践进 5️⃣  
工程治理与方法论进 6️⃣  
前端技能点进 2️⃣  
前端项目与实践进 3️⃣  
系统环境进 1️⃣  
理论与读书进 4️⃣  
复盘总结进 7️⃣  
拿不准先进 inbox

第二段：产物形态  
产物偏可执行流程、规范、清单，优先落 5️⃣ 或 6️⃣  
产物偏代码与工程落地，优先落 5️⃣ 或 3️⃣  
产物偏知识点，优先落 2️⃣ 或 4️⃣

第三段：最终落位  
用冲突优先级做最终裁决，保证只落一个目录

### 5.2 冲突优先级

当同时命中多个目录时，按下列优先级落位

1. 5️⃣ AGI 工具链与工程实践
2. 6️⃣ 架构思维与方法论
3. 3️⃣ 前端进阶与项目
4. 2️⃣ 前端核心
5. 1️⃣ Mac 开发环境
6. 4️⃣ AGI 核心
7. 7️⃣ 每日复盘与周报
8. inbox

## 6. inbox 清空规则（必须可控）

inbox 仅允许两类

1. 未读完资料
2. 未决定归属的对话

清空节奏  
每天至少清一次  
迁移时必须补齐 子类 与 标题模板

---

## 7. 项目型对话收尾三件套（强制沉淀）

每个项目型对话结束前必须产出

1. 结论摘要：10 行以内
2. 步骤清单：可复制执行
3. 坑位与规避：判定信号与解决路径

落位建议  
工具与流程沉到 5️⃣  
制度与治理沉到 6️⃣  
项目复盘沉到 3️⃣

---

## 8. 可直接复用的归档口令

口令模板  
我将给你一段对话内容，请按本宪法进行归档裁决。  
先输出：目标域判定，产物形态判定，最终落位目录。  
再给出：建议标题，子类，关键词标签。  
最后给出：未来可复用的 2 个场景。
