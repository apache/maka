## 如何选择模型？

- 预算充足的情况下，优先开通ChatGPT Pro
  - 原因：
    - 1、Pro用户可以（几乎）无限量使用GPT 5.2 Pro模型，我个人认为是最强模型。
    - 2、Pro套餐所带来的codex额度量巨大，单纯依靠人肉对线codex的话，（几乎）用不完。
    - 3、ChatGPT封号风险比Claude要低很多。
    - 4、ChatGPT所提供的Project功能比Claude能力强，模型自身会优先加载Project里的文件以及记忆

- 能不用中转的情况下，尽可能不要用中转，如果要用，可以作为subagent去用，主控最好选最强模型
  - 原因：
    - 1、你无法确保中转站不会偷偷摸摸换便宜垃圾模型
    - 2、中转站跑路风险
    - 3、中转站（大概率）能看到你的请求的原始信息，并进行落盘（参考《网络安全法》第21条）
    - 4、低智能模型使用久后，你会对AI的信心指数暴跌，觉得AI是垃圾
    - 5、一旦对AI是垃圾的偏见形成，很难逆转，你可能会由于偏见而错过AI时代下个人发展的黄金时刻

- Claude Opus与gpt-5.2-codex模型对比，与UI无关的，无脑选gpt-5.2-codex，让opus和sonnet去做UI
  - 原因：gpt-5.2-codex模型幻觉率极低，指哪打哪，上下文充足的情况下，几乎可以实现one-shot。

## 为什么尽可能使用最强模型？

在这里我并不是指日常工作中，不管什么活都用最强模型来干，而是尽可能多的使用最强模型，探索它的能力边界，而减少很便宜、低智能模型的使用。

在完全没有尝试过最强模型的情况下，低智能模型很多的不足的地方会给人一种工程上可以补足的幻觉（比如没有严格遵守prompt、输出的json格式有误），但实际上这些东西并不值得我们花费精力去解决它，因为最强模型已经解决了这些问题。

- 虚假的努力：花费大量时间精力用工程化尝试补足智能上的不足；
- 真正的努力：直接躺平，使用最强模型，扩展自身领域层面的技术深度、架构层面的能力（目前最强模型做不到这些）

## 如何选择CLI Agent

- 优先使用开源cli，比如codex
  - 原因：
    - 1，一切公开透明，你想了解的所有功能，都可以让codex自己阅读代码，解答你的疑惑
    - 2，未来如果你要定制化工作流、命令，开源绝对是最优方案
    - 3，我视频里提到的协作模式，codex表现是最好的（claude code第一次运行时会不断向你索要权限）
