## 三、明确不做（YAGNI 落盘）

| # | 排除项 | 原因 |
|---|--------|------|
| 1 | 验证码（Kaptcha） | 垂直切片不承担登录加固；API 是新契约，无历史行为包袱。后续加固期再加 |
| 2 | Excel 导入导出（POI→excelize） | P1 范围，切片不需要 |
| 3 | 代码生成器 / 表单构建 / demo 页 | 生成目标栈已换，旧模板零复用价值；demo 是官方教学页 |
| 4 | Quartz 定时任务、在线用户、缓存/服务监控 | P2 范围；token 存储设计已为在线用户留了状态入口 |
| 5 | Redis | 存量 classic 本身无 Redis（ehcache 内存），内存 token 存储即同构复刻 |
| 6 | JWT | 与登出/在线用户语义冲突（无状态），且比随机 token 复杂；见已定口径 #6 |
| 7 | 数据权限 dataScope（按部门过滤） | P1+ 范围；RBAC 功能权限（perms 字符串）首期保留 |
| 8 | 存量 resetPwd 不加盐怪癖的复刻 | 源码 `SysUserServiceImpl:534` 重置密码时 `md5(loginName+password)` 不带 salt，属历史怪癖；Go 版统一走带 salt 的 EncryptPassword（声明差异，不背兼容包袱——API 是新契约） |
| 9 | 登录失败锁定（5 次/5 分钟） | 加固期做；切片不做 |
| 10 | Thymeleaf 页面视觉复刻 | 新 UI 用 shadcn 风格重做，功能对齐不像素对齐 |

## 四、开发影响面

**新增仓库结构**：`server/`（Go 单包扁平结构：main/config/db/models/auth/rbac/users/password/response + password_test）、`web/`（Vite 模板 + src/{lib,stores,layout,pages}）、`docs/`。

**新契约 API（12 个端点）**：
```
POST /api/auth/login            {loginName,password} → {data:{token,…}}
GET  /api/auth/me               → user + perms
POST /api/auth/logout
GET  /api/system/user/list      pageNum/pageSize/loginName?/status? → {rows,total}
GET  /api/system/user/:id       → {user,roleIds,postIds}
POST /api/system/user           新增（密码服务端加盐加密）
PUT  /api/system/user           编辑（不改密码）
PUT  /api/system/user/resetPwd  {userId,password}
DELETE /api/system/user/:ids    逗号分隔批量，软删 del_flag='2'，禁止删 admin/自删
GET  /api/system/dept/options   部门下拉
GET  /api/system/role/options   角色下拉（角色对话框多选）
GET  /api/system/post/options   岗位下拉
```
RBAC：权限串复用 sys_menu.perms（如 `system:user:list`）；user_id=1 全通过（存量 isAdmin 语义）。

**验证等级**：
1. `go vet` + `go test`（密码黄金断言，已实测前提成立）+ `go build`
2. 真实端到端冒烟：连本机 ry 库，老 admin 账号经 Go 后端登录 → 携 token 调 user/list → 增删改查全链路 curl 断言
3. `pnpm build`（tsc 类型检查 + vite 构建）全绿
