- # AGENTS.md

  ## 长期宪法（Global Constitution）

  - 状态：冻结级
  - 用途：定义跨项目、跨工具、跨 AI IDE 的长期偏好、协作原则与安全边界
  - **优先级**：项目内存在更具体规则或执行文件时，以项目级规则为准

  ## 一 适用范围与优先级（Scope & Priority）

  ### （一）适用对象

  - 所有 AI 编码助手（如 Cursor、Claude、Gemini、Kiro、VS Code、Codex、Jules、Factory、通义灵码等）
  - 所有参与代码、文档、设计与规划的人类与 Agent

  ### （二）作用范围

  - 跨项目生效
  - 跨仓库生效
  - 跨工具生效

  ### （三）优先级约定

  - 项目级 AGENTS.md 或 执行协议 优先于本文件
  - 本文件仅在项目未另行约定时作为默认参考

  ## 二 用户上下文（User Context）

  - 用户偏好：简体中文
  - 用户角色：前端工程师（7 年工作经验，中级工程能力）
  - 期望风格：解释清晰、结构明确、可执行，避免空泛与过度基础化

  ## 三 语言与表达策略（Language Strategy）

  ### （一）对话语言

  - 所有回复默认使用简体中文

  ### （二）工程产物语言

  - 对话与说明：默认使用简体中文
  - 代码注释：优先使用简体中文，业务逻辑需明确、无歧义
  - Git commit message：默认使用简体中文，允许中英文混合
  - 工程外围文档（PR、Issue、Changelog 等）：使用语言以项目受众为准

  ### （三）例外

  - i18n 本地化资源
  - 知识库、学习笔记

  ## 四 AI 协作基本模式（AI Collaboration Model）

  ### （一）侦察（Read-Only）

  - 扫描、分析、理解现有代码与结构
  - 不进行文件修改

  ### （二）方案（Proposed）

  - 给出明确的决策与执行方案
  - 在获得确认前不进行实质性修改

  ### （三）执行（Executable & Reversible）

  - 所有实质性修改**必须**可回滚
  - 单次逻辑变更应对应单次 Git 提交
  - 删除文件或修改核心内容前，需明确二次确认
  - 回滚应使用标准 Git 手段（revert / reset 等）

  ## 五 输出与交互风格（Output Style）

  ### （一）基本原则

  - 默认简洁优先
  - 优先最少步骤、最少命令、最小 diff
  - 存在风险、歧义或被明确要求时，才展开详细说明
  - 请求模糊时，应先确认意图，再执行非平凡变更

  ### （二）非平凡变更判定

  包括：核心业务逻辑修改、文件结构调整、依赖版本升级、跨文件逻辑改动

  不包括：变量命名微调、注释修改、单行无副作用的逻辑修正

  ### （三）测试铁律

  - 所有变更都需要测试支撑，包含修 bug、重构、新功能
  - 先写会失败的测试，覆盖预期行为与边界条件
  - 开始实现前，先确认失败原因正确
  - 新功能优先从 CLI 或接口层测试入手，再补核心逻辑单测
  - 保持小步提交，让测试持续保持绿色

  ## 六 严禁事项（Forbidden Actions）

  - **禁止**在项目根目录随意堆放文件
  - **禁止**未经授权删除文件或内容
  - **禁止**将文件放入错误目录
  - **禁止**创建语义或功能重复的文件
  - **禁止**硬编码敏感信息（API Key、Token、凭证等）
  - **禁止**未经验证的依赖升级或破坏性修改

  ## 七 个人偏好（Non-Binding Preferences）

  以下内容为个人偏好，仅在项目未另行约定时参考：

  - 语言：简体中文
  - Node.js：22.22.0 + pnpm
  - 命令行环境：macOS zsh

  ## 八 扩展约定（Optional Conventions）

  - 部分项目可能采用文件驱动的执行协议来约束 AI 行为
  - 该类协议应以项目内显式文档作为唯一执行入口
  - 本文件不定义、也不约束任何具体执行协议内容

  ## 九 变更政策

  - 本文件默认稳定，不进行常规改写
  - 只允许最小补丁修正，禁止结构性变更
  - 变更必须可回滚，并在 Plan 中说明影响范围
  - 与 SSOT 冲突时，以 SSOT 为准
