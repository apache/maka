# 05 场景：质量与交付

> 内容版本：v2.0
> 校准日期：2026-09-13
> 定位：场景路由层。**全局**=直呼名字；**待命**=按真身路径显式调用（路径见 02 章）。

## 结论摘要

| 主线         | 主选                                          | 配合                                                                 |
| ------------ | --------------------------------------------- | -------------------------------------------------------------------- |
| 调试         | `helper-me` bug-me 节（全局，已知根因最小修） | `systematic-debugging`（待命，根因未知先方法论）                     |
| 测试         | `tdd`（全局）                                 | `webapp-testing`、`vitest`（待命）                                   |
| 验收         | `helper-me` quality-me 节（全局）             | `verification-before-completion`（待命）                             |
| 文档交接     | `writer-me`（全局）                           | `handoff`（待命）、`show-me`（全局，配图）                           |
| 数据与浏览器 | 待命组                                        | `agent-browser`、`chrome-devtools`、`firecrawl-search`、`screenshot` |

## 一、调试

| 场景                                           | 路由                                                         | 状态 |
| ---------------------------------------------- | ------------------------------------------------------------ | ---- |
| 报错但根因未知                                 | `systematic-debugging`：先复现、收集证据、假设验证，不改代码 | 待命 |
| 根因已确认，要最小修复                         | `helper-me` bug-me：最小复现 → 共享根因修 → 只改必要文件     | 全局 |
| 接口返回异常导致页面错乱                       | `helper-me` api-me 节查字段映射 + bug-me 收敛                | 全局 |
| 移动端兼容（H5/小程序/老 WebView/键盘/安全区） | `taro-me` + `css-me`                                         | 全局 |

## 二、测试与验收

| 场景                                 | 路由                                                                                    | 状态        |
| ------------------------------------ | --------------------------------------------------------------------------------------- | ----------- |
| 新逻辑先写失败测试 / 修 bug 前补回归 | `tdd`（红绿重构）                                                                       | 全局        |
| 浏览器级 E2E                         | `webapp-testing`                                                                        | 待命        |
| 单测框架                             | `vitest`                                                                                | 待命        |
| 改完不知道验收够不够                 | `helper-me` quality-me 节（质量门）；`verification-before-completion`（逐条证据化验收） | 全局 / 待命 |

## 三、文档、交接与复盘

| 场景                                                   | 路由                                        | 状态        |
| ------------------------------------------------------ | ------------------------------------------- | ----------- |
| README / 开发文档 / 翻译 / 去 AI 味                    | `writer-me`（先读源码再写，事实不全就标注） | 全局        |
| bug 复盘（七要素：表现/触发/排查/根因/修复/验证/预防） | `writer-me` 总结沉淀模式                    | 全局        |
| 交接给下一个 Agent 或同事                              | `handoff`（待命）+ `writer-me`              | 全局 + 待命 |
| 给解释配图                                             | `show-me`                                   | 全局        |

提示词样例（复盘，七要素结构最有代表性）：

```md
使用 $writer-me 写这个 bug 的复盘，凑齐表现、触发、排查、根因、修复、验证、预防七要素；验证只写实际跑过的命令和输出。
```
