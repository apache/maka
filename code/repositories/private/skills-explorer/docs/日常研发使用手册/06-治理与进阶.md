## 一、收录、启用、维护、淘汰

四个动作的严格度不同：收录可以宽，归档必须准，启用必须严，淘汰要留痕。

**收录可以宽**：新 skill 直接进明确分类的候选位（v1 的 `00` 候选池已移除）。收录前检查：有 SKILL.md、触发条件明确、步骤可执行、能对齐分类体系、无安全风险。

**归档必须准**：每个 skill 只有一个主归属。判断顺序见 [02](02-分类与能力链.md) 第一段。进 `99-归档与淘汰` 时记五项：淘汰原因、替代 skill、最后有效版本、可迁移经验、是否需从 global manifest 和农场移除。

**启用必须严**：进 global manifest 前检查当前任务是否常用、是否与已有全局技能触发冲突、是否需要外部凭据。全局 24 是当前结论，不是上限——但每加一个都吃所有会话的上下文。

**维护有节奏**：

| 周期   | 动作                                                       |
| ------ | ---------------------------------------------------------- |
| 每月   | 跑 `sk-doctor.js` 体检，看断链与清单漂移                   |
| 每月   | 检查 global 24 是否仍是"当前主线常用"，低频的收回          |
| 每季度 | 对照 `~/.agents/.skill-lock.json` 更新第三方来源 skill     |
| 每半年 | 复查七大分类是否仍支撑能力链；复查归档区有无该复活或该删的 |

**identity 硬规则**（来自 ~/.ai/README.md，违反会破坏脚本链）：

1. 一等 skill 路径固定为 `categories/一级/二级/skill名/SKILL.md`，目录 basename 必须等于 frontmatter name。
2. 99 区默认不进 active scanner；例外（如 mentor-me / writer-me 真身在 99 但接全局）是所有者决策，doctor 报 missing target 属预期。
3. 归档复活：从 99 移回活跃分类 → `sk-sync.js` → `sk-doctor.js` 验证。

## 二、常用组合（现行名）

```text
从 0 到 1 做业务模块:  grilling → helper-me(prd-me) → ui-me → css-me/taro-me → tdd → writer-me
修一个线上 bug:       systematic-debugging(待命) → helper-me(bug-me) → tdd 补回归 → writer-me 复盘
老项目小步维护:       helper-me 判栈 → ui-me 查契约 → code-simplifier 收敛 → 最小 diff 交付
接口联调:             helper-me(api-me) 契约表 → tdd/契约测试 → writer-me 接口交接
项目交接:             writer-me 交接文档 → show-me 配图 → verification-before-completion(待命) 验收
```

## 三、常见误用

| 误用                                          | 更好的做法                               |
| --------------------------------------------- | ---------------------------------------- |
| 需求不清就写代码                              | 先 `grilling` 或 helper-me 判边界        |
| bug 一出现就改                                | 先复现定位根因，再最小修复               |
| 修 bug 不补测试                               | `tdd` 先写会失败的回归测试               |
| 把待命技能当全局（凭空喊名）                  | 待命技能给真身路径显式调用               |
| 推荐技能不给路径                              | 全局用 `$name`，待命用完整 SKILL.md 路径 |
| 交付前只说"完成"                              | 列实际跑过的验证命令和输出               |
| 直接编辑 `.agents/skills` 或 CLI 前台下的正文 | 只改 `.ai/categories` 真身               |

## 五、三阶段学习（分类名为现行 v2）

**第一阶段：巩固直接优势**——03-设计体验与前端应用 + 04-软件工程与全栈交付 + 个人 \*-me 家族。目标：前端经验变 AI-first 工作流，PRD→初版代码→验收闭环。

**第二阶段：建立 Agent 杠杆**——01-Agent系统与Skills工程 + 05-工具数据与自动化。目标：重复任务变 skill，复杂任务变 workflow，抓取监控变自动化。

**第三阶段：补齐商业闭环**——02-研究产品与决策 + 07-内容增长与一人公司。目标：判断什么值得做，内容获客，反馈回流 skill 系统。

## 六、验收方式

```bash
node .ai/scripts/sk-doctor.js            # 体检：数字、断链、清单
node .ai/scripts/sk-sync.js --dry-run    # 前台对齐预演
node -e "console.log(require('./.ai/skills.manifest.json').global.length)"  # 全局数
find .ai/categories -name SKILL.md | grep -v 99-归档 | wc -l               # active 数
```

验收标准：文档数字与命令输出一致；引用路径可达；治理动作都有对应脚本或 manifest 操作可执行。
