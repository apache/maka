# 01 架构与视图

> 内容版本：v2.0
> 校准日期：2026-09-13
> 事实来源：`~/.ai/README.md`、`skills.manifest.json`、`sk-doctor.js` 输出、`.agents/` 与 `.zcode/skills` 实测

## 一、核心结论

v2 体系只有一个物理真身：`~/.ai/`。其余全是视图。

```text
~/.ai/categories/            真身层（唯一物理源，正文只在这里改）
    ↓ junction（经源，不 resolve）
~/.agents/skills/            全局农场（manifest.global 的 24 项 junction）
    ↓ junction 镜像（sk-sync 同步）
~/.zcode / .codex / .claude / …  九端 CLI 前台
    ↓
会话内 Agent 实际触发
```

四个必须记住的事实：

1. skill 正文只改 `~/.ai/categories/` 下的真身；junction 直连使内容改动即时生效，`sk-sync.js` 管的是各端条目增删。
2. 全局清单的唯一机器源是 `~/.ai/skills.manifest.json` 的 `global` 键（当前 24 项）；`sk-rebuild.js` 按它重建 `.agents/skills` 农场。
3. `.agents/` 只剩两样东西：`skills/`（junction 农场）和 `.skill-lock.json`（第三方 GitHub 来源锁，63 条）。v1 时代的 `.agents/categories、docs、scripts、scenarios` 已全部迁走或退役。
4. 不在 global 清单的 300+ 技能是**待命态**：真身在 categories，用完整路径显式调用，不占每次会话的上下文。这是体系控制上下文膨胀的核心机制。

## 四、管理脚本（~/.ai/scripts/）

```bash
node .ai/scripts/sk-sync.js --dry-run    # 预演九端同步
node .ai/scripts/sk-sync.js              # 实际同步（幂等）
node .ai/scripts/sk-rebuild.js --dry-run # 按 manifest 重建全局农场
node .ai/scripts/sk-doctor.js            # 只读体检（结构/清单/断链）
```

已知体检噪声：sk-doctor 对 06 安全分类报 49 项"非预期嵌套 SKILL.md"，属 vibe-engineer 迁入技能的固有结构，不是断链；mentor-me / writer-me 真身在归档区但接入全局，报 missing target 属预期例外（见 ~/.ai/README.md）。

## 五、验收方式

1. 文档数字与 `sk-doctor.js` 输出一致。
2. 文中引用的路径 `ls` 可达。
3. 结构改动后 `sk-sync.js --dry-run` 无意外差异。
