# 项目开发 Skill Builder

将真实项目的实现模式和业务约束转成可调用的开发 Skill，供后续新功能、存量迭代与缺陷修复复用。默认保持当前产品语言、技术栈和契约，不借生成技能重设计项目。

## 快速开始

显式调用：
`使用 $project-workflow-skill-builder，基于当前项目生成用于后续开发迭代的 Skill，结合指定需求、提交和旧 Skills，实际落盘并验证。`

平台无关调用：
`读取本文件及任务所需引用，为指定项目创建可复用的开发 Skill，保持实现与当前源码和业务契约一致。`

核心是 SKILL.md 和 references；agents/openai.yaml 仅为 Codex 展示与显式调用策略适配。没有专属技能机制时可直接读取文件执行；生成文件与宿主安装/发现分别验证，不强行复制某个平台的目录或字段。

## 输入与交付边界

从请求和已有上下文确定目标仓库、工作流、输出类型、验收、作者/时间范围及输出目录；明确部分不重复访谈。

- 仓库路径必须真实存在。Git、旧 Skill、截图是可选增强：没有历史仍可依据当前源码创建；没有截图仍可从需求和现有组件创建。
- 显式目录优先；未指定时核对项目规则与宿主，Codex 项目级默认 .agents/skills/<product>-<workflow>-developer/。产品名取当前 package、workspace 或主应用；不确定时用工作流名，不凭空补品牌。
- 部署进本机全局 skill 视图时遵循建链约束（junction 经源、禁止 `ln -s`、删链用裸 `rmdir` 不带 `/s`），细节见 [references/skills-link-architecture.md](references/skills-link-architecture.md)。
- 用户要求创建时交付真实目录及 SKILL.md，业务参考不能代替入口；仅要求候选时保持只读。
- 同用途目标已存在时先读、备份并最小更新，保留名称和用户内容，不默认新建 -v2。复用通用方法不取消明确要求的 Skill 交付。
- 生成技能不授权修改业务代码、全局配置、提交推送或真实业务写入；未知关键契约写明缺口。

## 工作流

### 1. 识别形态和本次生成范围

读取项目规则、package/构建配置、路由或服务入口及目标技能现状。
按 [项目形态与证据框架](references/project-shape-framework.md) 识别终端、交互范式、结构和运行特征；只读相关形态段落。
区分前端原型/页面、API 联调、异步任务或其它有证据的工作流；多端分别记录边界。

完成条件：能列出已确认形态、待确认项、技能负责的工作，以及明确不处理的邻近任务。

### 2. 收集稳定证据

遵循同一框架中的领域证据顺序和强规则门槛。先选约 8–12 个代表文件；小链路可以更少，多端有缺口再扩展，不为凑数扫描。
沿目标入口追到数据来源、状态、副作用及失败/验证路径；前端还检查主题、布局、公共组件及真实控件状态。
需要历史经验时才筛 Git 作者与日期，读取实际 diff 并与当前源码比较。区分作者与提交者、不同分支和当前快照；排除 stash/合并噪声，不把提交数当需求数。
旧 Skill 提供候选方法，历史注释与补丁不是当前业务真相；截图只提供视觉事实，不决定接口和权限。

完成条件：每条关键候选规则都有当前来源和适用边界，证据不足明确标记，产品事实与交付质量要求分开。

### 3. 转成下游开发工作流

让目标 Skill 按 [输出契约](references/output-contract.md) 实际写出适用分支：

- **存量迭代**：源码必读；有截图保留信息架构和交互，无截图按当前实现与明确改动点推进。
- **新功能**：需求与验收驱动，复用邻近稳定模式；不存在的接口/组件标待定义，不用 mock 或想象补成已存在能力。
- **缺陷修复**：症状与复现入口驱动，查调用方和共享根因，修改后复验。
  不是只列三个标题：每个保留分支写明输入、读取入口、决策、动作、交付与停止条件；不适用分支说明原因而不凑模板。

完成条件：后续 Agent 能按场景执行，而不仅是阅读项目介绍。

### 4. 写完整技能并继承产物质量要求

按输出契约创建 SKILL.md、必要的项目规则参考和具体测试用例，保持中文优先及一个事实一个维护位置。
阅读 [交付质量约束](references/delivery-guardrails.md) 的通用段和本次产物对应段，将适用要求明确写入目标技能及其验收；不要让目标依赖本 Builder 的绝对安装路径。
UI 输出继承视觉/状态与条件式渲染验证；API/异步输出继承契约和生命周期检查；其余类型依据项目工具定义可执行检查。
代码骨架或典型调用仅在源码有稳定范例时给出，并说明边界；不为结构统一创造新层。
不默认生成 README、CHANGELOG、脚本或多 Agent 引擎；确需确定性脚本时复用工具并保留最小测试。

完成条件：真实 SKILL.md 与所引用文件全部存在、内容可执行且无未替换模板；下游质量要求已落入产物，而非只在 Builder 中提醒。

### 5. 验证、精简与交付

分开报告三类证据：

1. **文件与发现**：回读文件、名称/frontmatter、引用和迁移链接；宿主支持时查技能列表。
2. **行为**：按输出契约的正向、失败、状态切换和近邻排除用例验证；区分设计、已运行、受阻。
3. **收益**：如获准，独立上下文以相同模型/任务/源码/工具比较旧版与新版，保留陌生任务；静态校验不能冒充收益。

只删除不改变验收的重复设计；无合适候选则跳过。真实业务测试仅在授权环境执行。
交付实际路径、调用提示词、产品形态、来源摘要、已执行检查和缺口。没有实测时仍完成已授权技能创建，但不宣称下游开发效果已验证。

## 示例：从项目生成而非复制领域答案

输入：“为护理报告到预约的链路生成开发 Skill，参考我的相关提交。”
输出：该项目的开发入口、字段/状态来源、条件式确认与更新规则、具体行为用例。是否自动确认由该仓库代码决定，不预设。

输入：“为音频剪辑与任务恢复生成开发 Skill，没有截图和 Git 历史。”
输出：从当前源码提炼资源/任务身份、状态映射、恢复与结果确认工作流；有 UI 时补相关控件验证，不带入预约字段，不因缺历史终止。

这两个例子不是固定仓库、作者或技术栈；每次重新确认本次输入。
