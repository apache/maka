## 历史数字怎么使用

- 原始JSON只有评论/评审明细，不含完整PR状态字段；不由84条评论推导合并数。
- 27=21+4+2；“未被拒绝”是旧报告解释，不是GitHub状态。新话术直接讲合并、开放与关闭，不用“零拒绝”。
- brand 27/67、myCustomers 78/69等差异，可能涉及日期/路径/作者过滤；保留不同快照，不靠大小判断真假。
- 新量化条目必须写：指标定义、统计范围、起止日期、分子分母、原始记录、复核命令、审核人。没有对照实验就写交付内容，不写收益比例。

`INTERROGATION.md` Q59—Q61 与旧自评中的三个联调故障作为 R 级经验保留：SSE 帧漏 JSON 解析、Python `None` 与 Zod `.optional()` 不匹配、store 初始化器误用 `useRef`。2026-10-02 核读当前代码（V，源码范围）确认：`services/agent.ts` 先解析 `frame.data`，`stores/chat.ts` 再做 schema 校验并用普通闭包变量保存 AbortController；`contracts.ts` 的 `result/failReason/paidAt` 使用 `.nullish()` 对应 Python 可空字段。本轮没有重新复现历史白屏，也不以笔记证明故障修复作者。

同次核读 `apps/api/app/llm.py`：闭合的 card 围栏经 JSON/schema 校验后才成为卡片，非法或未闭合内容降级为文本，依据 ID 由服务端按场景注入。`apps/api/tests/test_llm.py` 有对应测试源码；本次资料整合未运行 API 套件，测试结果范围仍按 E10。
