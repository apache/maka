# 临场兜底与转场

被问住时先说明确定的范围，再回到机制或证据；句式只作提醒，不另维护一套逐字稿。

## 六种场景与句式

| 场景 | 句式骨架 | 紧接的动作 |
|---|---|---|
| 完全不会 | "这个我没有实际用过，我理解它解决的是……问题，如果让我设计，我会先……" | 转到相邻的已验证经验，说明差异 |
| 部分会 | "我确定的部分是……，……这一段我没有亲手验证过" | 只展开确定部分，主动划边界 |
| 需要思考 | "这个问题我想十秒钟，从输入和数据流开始理" | 现场画状态或数据流，边画边说 |
| 被指出错误 | "对，这里我记岔了。正确的应该是……我回到源码/文档确认过再补" | 当场修正，不狡辩；修正后补一句怎么防止再错 |
| 追问转到陌生方向 | “这个方向我能确认的是……，更深一层我还没有验证” | 先回应当前问题，再用与问题相关的案例补充 |
| 追问超过证据 | "再往下是团队/后端的职责边界，我能证明到……这一层" | 指出自己负责的部分与证据入口 |

## 澄清策略

题目缺失条件或歧义时，先澄清再回答："这道题没有给出 X 条件，我按两种情况分别说。" 若采用假设，标明它影响哪个结论以及怎样验证。

## 转场到证据

先回应当前追问；不知道或缺证据时直接说明。需要案例时只引用与当前问题相关的物证，不用转场回避原问题。

- AI 岗 → P04 接诊准备 / P02 音频任务 / P05 协议网关。
- Web 岗 → SSAP 动态表单 / DOMP 图表分层 / BCP 复杂状态（见[深挖弹药](../02-传统前端基本盘/06-SSAP-BCP-DOMP深挖弹药.md)）。
- 机制与失败路径 → [AI 产品题](../03-题库与系统设计/02-AI-Agent高频追问.md)或[系统设计题](../03-题库与系统设计/03-系统设计题.md)，说明这是知识/设计回答还是本人实绩。

## 短板与架构追问

被问短板时只选与当前追问有关的一项：区分“没有做过”和“尚未验证”，回对应项目卡给出范围与待核验项。生产 RAG、模型训练、完整工具闭环等不能用个人演示替代经历；不临时编造补齐计划或进度。

深挖时按输入与状态拥有者 → 失败路径 → 取舍 → 验证回答；未知项指出影响与查证方式。AI 辅助开发把关回[P07](../01-AI项目与Agent工程/07-Agentic与Context-Engineering.md)，贡献归属与测试分母回[证据登记](../00-事实与简历/05-项目归属与量化证据.md)，不把历史报告或所有 PASS 当全行为证明。

## 红线

不用"背过的百分比"救场；不把设计说成上线；不把同事模块说成自己实现。兜底失败也要守住事实一致——一次"不知道"不致命，一次事实矛盾才致命。

## 依据与延伸

- [自我介绍](../00-事实与简历/03-自我介绍-60秒与120秒.md)：唯一开场稿。

## 先判断卡住的是哪一层

| 卡点 | 当场做什么 | 不能拿什么替代 |
|---|---|---|
| 题意不完整 | 问规模、目标与失败成本；给两个条件下的选择 | 未说明的假设或万能架构图 |
| 名词忘了 | 用输入、状态变化和输出解释，再补术语 | 连续报框架名称 |
| 机制不会 | 明确不会的部分，展开相邻已理解机制 | 猜一个确定答案或编经历 |
| 经历证据不足 | 限定个人模块，区分历史记录与当前验证 | 同事职责、默认mock或未来计划 |
| 例子说不顺 | 画正常链路，再插入一条失败箭头 | 在项目列表间不停切换 |
| 被反例推翻 | 承认原假设失效，修正条件与结论 | 辩解“线上一般不会发生” |

### 练习案例：幂等与取消

学习推演：“如果一个任务重复提交，前端禁用按钮只是交互保护，不能阻止网络重试或多端请求。服务端需要定义请求身份和重复处理规则；实际项目是否实现这一层，我要回原始契约核对。”接着说明取消也有两层：页面停止轮询与后台停止执行并不等价；不能用关闭页面证明任务已取消。这个例子训练语义边界，不是补写P02已实现的幂等能力。

## 如何列出不自信的点

用“已确认—不确定—影响—查证”四句表达：“我确认页面按taskId查详情；没有证明服务重启会恢复执行；它影响在途任务是否能完成；需要核对启动恢复逻辑并设计中断重启探针。”说清未知项比泛泛说“可能有风险”更可检查。

另一种是语义不确定：“HTTP请求是否成功和业务动作是否完成不是同一件事；我能解释传输错误处理，但没有确认重复请求的服务端契约。”先指出可能改变结论的部分，再给合理的验证办法，不把待核验列表全读出来。

## 把长答案缩短而不丢因果

被打断时用一句话收束当前段：“因此我的决策是X，代价是Y，验证覆盖到Z。”若只剩30秒，保留输入条件、本人动作与证据边界；去掉库版本、文件罗列与背景细节。面试官要继续时，再从对应项目的5—8分钟底稿取一个段落，不重新从头背。

答错后的复盘要保存原回答，而不只留下漂亮终稿。下一次闭卷换条件重答；如果换一个条件就无法解释，说明上次修正只记住了句子，仍需回机制题或原始证据。

## 两种被追问时的完整重答

**“Promise.all失败后其他请求就停了吗？”** 学习推演：两项独立请求并行，一项拒绝会让聚合Promise拒绝，另一项仍可能继续。若两块可以分别呈现，就分别保留结果和错误；若必须形成完整汇总，则说明缺项不能当完整结果。取消要另接AbortSignal，而且仍不证明服务端停止工作。把结论、失败显示与取消语义分开，避免只报一个API名。

**“前端类型完整，为什么还有空值错误？”** 学习推演：编译期类型断言不改变响应；先区分缺字段、null、0，再决定合法零值、未知或结构错误。接口入口负责契约校验，mapper负责合法值到展示语义的转换，组件消费ViewModel。若没有确认原项目的校验测试，就说明这是设计检查点，不补称全接口已严格校验。

这两段先回应反例，再回项目证据，不能用转场逃掉原问题。试讲可以在结论后停下，让面试官选择深入失败处理、数据边界或验证。
