# 知识库维护规则

容量目标为全仓 50—60 份 Markdown，当前 54 份（含原始证据）。日课只用[训练入口](../04-表达与模拟/00-每日口述训练.md)，全仓目录不构成阅读清单。原始证据按需查，不重写成教材。

## 唯一维护位置

| 内容 | 唯一维护位置 | 更新触发 |
|---|---|---|
| 身份、任职、归属、技能声明边界 | `00/00-个人事实基线` | 本人确认或原始证明变化 |
| 数字与验证范围 | `00/05-项目归属与量化证据` | 新证据，注明范围与时点 |
| 未核验项 | `00/06-待核验清单` | 核验完成，不按学习计划销项 |
| 公司项目回答 | `01/` 对应项目卡 | 真实闭卷缺口或职责证据变化 |
| P05/P11/P12 公开项目回答 | `06/01—03` | 当前源码或验证证据变化 |
| F01—F08／A01—A10 答案 | `03/00`、`03/02` | 真实练习或面试反馈 |
| 按需机制／系统设计 | `03/01`、`03/03` | JD 或实际追问命中 |
| 开场、转场、HR | 自我介绍 `00/03`、`04/01/04/06` | 口述或 HR 反馈 |
| 本人闭卷结果 | `04/05-模拟面试记录` | 实际回答发生 |
| JD、投递、面试复盘 | `05/01—03` | 真实投递／面试发生 |

项目地图和讲述索引只做选材与转场，不复制长稿。两版简历是投递输出，事实基线、证据和治理是查证材料。P04/P02 主讲、P05 公开备，其余按需。

## 改动原则

1. 先更新唯一事实源，再同步受影响的正文与展示副本；不为一次改动全库重写。
2. 新题先尝试归入18个核心问题；确属专项且JD命中，再补专项速查。新增 Markdown 前先考虑替换或合并已有文档，保持50—60份。
3. 参考答案不等于本人经历；缺失的测试、真机或生产证据继续标待核验。练习记录不由 Agent 代填成绩。
4. 保留 schema 校验、错误处理、权限边界和数据安全；压缩表达不扩大能力保证。
5. 本月只做复习、投递和真实缺口补充，新增实验及三源码项目改造暂缓。原改造计划仍待实施授权。

本次用户明确要求深化现有复习正文，增加案例、参考与5—8分钟稿；这项授权允许一次整体扩写，容量和日课预算保持原样。新增机制作为知识回答，构造案例标为学习推演，历史项目继续带职责与验证时点。后续维护仍按上表触发，不持续按字数扩张；简历、事实台账、原件与真实记录不为长度凑量。
