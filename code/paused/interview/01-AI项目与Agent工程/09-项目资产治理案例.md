# 项目资产治理方法案例

用途：迁移、可回滚治理或方法追问的历史案例；按需回查，不作为 AI 产品前端日练项目。

## 30秒版

历史材料记录了对个人项目资产的盘点、分类和迁移。我能提炼的方法是先冻结清单、明确保留与归档策略，再迁移、修复引用和核验，而不是先移动目录再补解释。该案例是个人资产管理，不是生产用户增长项目。

## 2分钟版

旧治理记录围绕资产清单、维护状态、候选验证、可复用基础和迁移审计展开。可迁移到团队的经验是：分类维度只保留能支持决策的部分，事实字段与对外展示分层，迁移前保留快照，迁移后检查路径和内容。收益应通过可查找性、维护成本等后续测量证明，不把文档中候选产品的假设营收当成结果。本次面试宝典治理是同一方法的文档实例，具体执行证据见[合并与删除日志](../90-知识治理与审计/02-迁移与删除日志.md)。

## 三个难点与取舍

1. 多版本冲突：先选事实源并注明来源，不选“写得最漂亮”的版本。
2. 分类过细：顶层按使用任务划分，标签负责细节。
3. 历史引用：移动时维护映射，原始证据保留哈希，断链要显式处理。

## 三个追问

如何回滚？保留原始字节快照及路径映射，先在副本验证恢复。如何避免丢失？核对迁移前清单与迁移后目标。如何避免再次漂移？身份日期只在事实基线维护，派生材料做一致性检查。

## 递进深挖：先定义信息所有权，再定义目录

本案例最适合回答“历史材料多、版本冲突、如何迁移”的问题。它的产出是可以找到、核对和恢复的资料结构，不是证明公司生产系统可靠。当前文档治理的实际记录由[迁移与删除日志](../90-知识治理与审计/02-迁移与删除日志.md)维护，本卡只解释方法，不再复制文档总数和验收计数。

| 层次 | 维护什么 | 为什么不能互相替代 |
|---|---|---|
| 唯一事实源 | 身份、职责与经过确认的口径 | 话术更顺口不能覆盖原事实 |
| 证据登记 | 来源、时点、级别和可支持范围 | 一张历史截图不自动证明当前状态 |
| 派生材料 | 项目卡、题库、简历、公开展示 | 按读者用途表达，不能新增未经证实的事实 |
| 原件与快照 | 原始字节、路径与恢复入口 | 摘要没有保存全部细节，不能代替可恢复原件 |

高内聚低耦合在这里表现为：同一事实只在指定入口维护，多种表达按需引用。不会为了文件变少就把简历、项目长稿和原始 JSON 拼成一个超长文档；物理文件数与读者需要掌握的核心问题不是同一指标。

## 可核验案例：附件去重和历史文件删除

本轮既有治理把重复 archive 附件收口到 assets。判断不是“文件名相同所以删除”，而是检查原件位置、字节哈希和快照可恢复性；有价值的说明先融入现有项目卡与证据登记，再删除重复稿。历史文件中的过时数字、夸大归属或执行命令，不因为被保存就成为当前事实或授权。这些动作及范围以治理日志为准。

**反例推演**：两个同名 XLSX 内容不同，按名字去重会丢掉其中一个版本；哈希相同也只证明字节相同，不证明内容正确。另一种情况是快照 ZIP 能打开，但目标成员不存在，仍然无法恢复被删除文件。因此验收要分别检查内容保护和恢复路径，不能只检查“ZIP 文件还在”。

## 失败路径与最小保护

| 风险，学习推演 | 最小保护 | 不能夸大的结果 |
|---|---|---|
| 移动后本地链接失效 | 路径映射和链接存在性检查 | 文件存在不证明内容仍与链接标题匹配 |
| 误改原始材料 | 对原件检查字节哈希，解释另写 | 哈希不替代事实审核 |
| 新项目卡与简历口径冲突 | 从事实源及 E 编号检查职责与日期 | 文本相似度不证明真实性 |
| 删除后不能恢复 | 确认 Git 版本或 ZIP 成员，并抽样恢复到副本 | 未实际恢复就不说已做灾难恢复演练 |

这里优先复用 Git、标准库和现有校验脚本；没有必要为个人复习库增加数据库、自动分类 Agent 或全量同步平台。只有维护者数量、更新频率或断链规模出现明确压力，再讨论新工具。

## 对抗式追问与阅读落点

“减少文件是不是一定更高效？”——不一定，合并后可能更难检索。应看是否更快定位当前问题和证据，不能从删除数量推出学习收益。“能否保证以后不漂移？”——只能通过明确入口和一致性检查降低风险；人工新增未经验证的事实仍需要审查。

闭卷用 2 分钟说明一个文件怎样从原件变成项目卡，再说删除原件前应满足什么条件；接着选一个坏链接或同名不同内容反例，解释哪个检查能识别它。没有计时和对照记录时，不宣称查找时间缩短了多少。

一手参考：[Python zipfile](https://docs.python.org/3/library/zipfile.html) 的 `read` 与 `testzip` 分别用于取成员内容和检查 ZIP 的 CRC／文件头；完整性检查不证明语义正确，也不替代与原始清单比对。当前治理检查只是本库的文档验收，不证明生产迁移能力。
