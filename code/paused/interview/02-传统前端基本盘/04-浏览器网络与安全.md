# 浏览器、网络与安全

## 必答边界

- HTTPS保护传输，不替代业务鉴权；CORS是浏览器跨源读取策略，不是通用访问控制。
- HTTP缓存区分新鲜度与重新验证；no-cache不等于禁止存储，no-store表达不存储。
- XSS关注不可信内容执行；CSRF关注浏览器自动携带凭据下的伪造动作；按服务实际认证方式选择防护。
- 前端隐藏按钮只改善交互，后端仍需按资源和动作授权。
- 文件/音频URL进入服务端需验证协议、来源和访问边界；内部token需隔离并避免进入日志。

## 流式协议

SSE是事件流格式。传输chunk可切断UTF-8字符、行或事件；保留解码状态和残片，完整事件后再解析JSON。心跳、错误、完成与业务文本分开。原生EventSource与Fetch读流不是同一个客户端接口，POST请求的流式响应可通过Fetch消费。重连时还需考虑事件游标和重复处理。[MDN SSE](https://developer.mozilla.org/en-US/docs/Web/API/Server-sent_events/Using_server-sent_events)

## 项目落点

P05讲本地Key与上游令牌隔离；P08讲请求层登录态与权限；跨端对话内核作为团队能力而非本人原创。安全机制是否到位以测试和代码为准，不把有token等同于完整安全体系。

## 先画凭据和数据经过哪些边界

**学习推演**：恶意站点诱导浏览器向业务站点发动作请求。若认证依赖自动携带的 Cookie，要考虑 CSRF；CORS 即使禁止攻击页面读取响应，也未必阻止请求造成副作用。后端按认证方式结合 CSRF token、来源检查及 Cookie 策略；不能把任何单项当全防护。[MDN CSRF](https://developer.mozilla.org/en-US/docs/Web/Security/Attacks/CSRF)

AI 文本进入 Markdown 时也不可信：文本节点、HTML、链接 URL 是不同输出上下文，不能用同一个替换函数“全部过滤”。禁用不需要的原始 HTML，校验链接协议；确需 HTML 时用合适的净化器，CSP 作为额外约束。React 的普通文本转义不覆盖主动注入 HTML 的入口。[MDN XSS](https://developer.mozilla.org/en-US/docs/Web/Security/Attacks/XSS)

## 缓存与流的失败演算

学习例：顾客 A 的缓存响应没有重新验证，不等于后端未修改；no-cache 允许存储但使用前验证，no-store 表达不存储。业务内存缓存另外按身份、顾客和版本失效，不能只改 HTTP 头。缓存定义与键设计对照[前端核心题](../03-题库与系统设计/00-P0-必背.md)中的缓存条目

SSE 收到 `data: {"text":"你` 与剩余字节时，不能对每个 chunk 单独 JSON.parse。先保持 UTF-8 解码状态，再积累到完整事件；传输结束也需按协议处理残片。追问重连时，说游标与去重前先确认服务端是否支持重放；前端自动重试不能凭空恢复已丢事件。P05 当前文本子集与 P11 本地验证范围分别查证据。
