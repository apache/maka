# 希音与德奥项目总览

任职日期取自[事实基线](../00-事实与简历/00-个人事实基线.md)，项目记录中的开发日期仅描述提交覆盖区间。

- **SCWF / SSAP**：历史报告记录从0到1前端建设。讲清骨架、页面、数据类型、筛选与请求层，不以提交数替代质量。
- **DOMP**：运营指标与图表。重点讲容器、数据到配置映射和配置工厂的分层。
- **BCP**：预算、审批、树形数据。重点讲遍历、不可变更新和状态一致性。
- **SOP**：登录相关接入、环境配置与代码质量治理，具体能力按模块职责展开。
- **德奥业务系统**：Vue业务交付、财物类型表单、出入库、按钮权限与表格封装。

最强的五个落点：React/TS复杂业务、图表治理、SSO/权限/请求层、Vue业务组件、工程规范与长期维护。ECharts“30+”、TS“92%”等原数字保留在历史证据，不直接放进新简历。

## 选哪个案例，先看问题的约束

| 面试问题 | 优先案例 | 要证明的能力 |
|---|---|---|
| 页面交互复杂，状态容易串 | SSAP 级联筛选／德奥业务表单 | 找到状态拥有者，解释上级变化为何使下级失效 |
| 多张图表重复代码如何治理 | DOMP | 把生命周期与业务映射分开，说明抽象边界 |
| 复杂表格或树形数据 | BCP | 说明金额不变量、变更传播和失败后状态 |
| 多仓如何统一行为 | 请求层与权限接入 | 明确公共错误语义，同时保留业务差异 |

不要连续介绍五个系统。先选一个本人能解释实现的模块，讲输入、约束和取舍；其余只在追问跨场景复用时引出。这里的项目记录是历史 R 级证据，当前源码、性能对照和具体故障修复作者仍按台账核验。

**学习推演**：省份从甲改成乙，旧城市值仍留在表单中。错误不只在展示，而在“城市属于当前省份”的不变量被破坏。先清城市，再用新省份查询城市；旧请求晚到也不能恢复旧城市。这个推导可迁移到 P04 切顾客，但不表示旧项目都实现了相同 guard。

深挖顺序：为什么放 Hook → 多个页面能否共享 → 查询失败保留什么 → 如何复现晚到响应。若只有一个页面且规则很短，先用局部状态，出现共同生命周期再抽 Hook；这是高内聚低耦合的适用条件。状态归属的机制可对照 [React 共享状态](https://react.dev/learn/sharing-state-between-components)，本人案例仍以历史证据为准。
