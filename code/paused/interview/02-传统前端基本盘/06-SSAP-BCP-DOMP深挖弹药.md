# SSAP-BCP-DOMP深挖弹药

Web 岗深挖希音老项目时的讲述素材，从历史逐字稿与项目总结蒸馏。归属与数字服从[证据登记](../00-事实与简历/05-项目归属与量化证据.md)：实现结构可展开，无测量记录的收益比例（44%、70%、95%等）一律不讲；被问到效果时讲"问题、动作、验收"，不报比例。

## SSAP 业务监控预警平台

- **元数据驱动动态表单**：配置字段元数据（`paramsLimit` 取值范围、`preparedStatement` 预置语义），由 componentMap 渲染对应控件；联动用 visible/disabled 表达式而非散落 if。追问"表单引擎怎么设计"时的主答案。
- **采集来源约束**：来源"角色"只能单选模板，其余条件多选 OR；这类业务约束写在规则层，不进组件。
- **级联筛选 Hook**：多级筛选状态收拢为一个 Hook，上级变化清空失效下级；查询键与缓存一致。
- **数据看板**：多接口并行取数用 Promise.all；图表多时用采样与懒加载，实例卸载时 dispose。
- **动态表单三类坑**：字段名冲突、校验联动漏触发、新增/编辑/查看三态默认值差异。
- 审批类场景可延伸讲：状态机配置表 + 乐观锁 version 冲突提示 + 乐观更新失败回滚（按实际项目情况取舍，不夸大）。

## BCP 预算管控平台

- **预算金额编辑组件**：年度/月度/周度横向累加 + 竖向按层级递归累加；按 Enter/Tab 切换输入框，脏值标红。真实业务细节，适合作为"复杂表格交互"案例。
- **公式编辑器**（历史记录，P08 引用前先回忆演示口径）：CodeMirror 6 + Lezer 自定义语法，变量形如 `$类型:数据id[维度id=维度值id]$`，编辑器内高亮与校验。
- **跨端复用**：PC 与移动端共享 hooks 与业务模型（审批流 `useBudgetApproval` 一类），UI 分端实现。
- **树形数据**：先明确节点规模与变更频率再选递归或显式栈；不可变更新避免共享引用误改（immer 的 produce 误用坑：回调里返回新对象导致丢分支）。
- **大文件导入**（历史逐字稿素材）：分片上传 + 断点续传 + Web Worker 算 hash + 并发池限流；讲清"为什么要分片"比背参数分高。

## DOMP 研发运营平台

- **图表三层**：容器（实例生命周期、ResizeObserver、dispose）→ 数据映射 → 配置工厂；与[可视化与复杂业务](05-可视化与复杂业务.md)一致。
- **BBL 国际化**：configure → fetchVersion → fetchDictionary → t()；词条缺失防抖批量上报；规范要点（模板变量占位、禁止中文做逻辑判断）。本人角色是接入与推广，BBL 本身是公司方案，不声称自研。
- **模块化加载与首屏**：讲"拆分策略 + 加载时机 + 失败降级"的思路；历史记录中的首屏秒数无测量底稿，只讲动作不讲数字。

## 权限与请求层（跨项目）

- **权限树扁平化**：后端返回树，前端拍平成 permissionMap；路由守卫用 RegExp 匹配动态路由；按钮级用指令（v-action 一类）。坦承阶段性取舍：移除 DOM 而非注释，防样式残留。
- **统一请求层**：API 权限校验、under2Camel 字段转换、401 → AuthError → SSO 静默续登 → 回跳当前页；错误码集中处理。此层在多仓推广（历史总结记为 5 仓），是"跨项目复用"的主案例。
- **React/Vue 双栈对照**（德奥 Vue + 希音 React）：目录与命名、状态管理（Vuex/Pinia vs Redux/Zustand）、请求层封装、组件设计四张对照卡，可在"两栈都熟"追问时展开。

## 前端负责人视角追问

- **TS 渐进迁移**：allowJs 起步 → 新文件强制 TS → 公共类型先迁移 → 旧文件按改动顺带迁；阻力对照（排查成本上升 vs 类型缺陷前移）。
- **代码规范落地**：ESLint 管规则、Prettier 管格式、CI 兜底；规范讲"为什么"而不是贴配置。
- **组件封装五原则**：单一职责、Props 最小完备、受控/非受控明确、样式的定制边界、文档与示例。
- **了解层**（不声称主导）：希音内部构建系统 Lego 的 tapable 插件化与 Service 分层、Webpack5 懒编译——被问到"了解公司内部工具吗"时作认知层回答。

## 5—8 分钟展开：BCP 金额编辑与状态一致性

这是历史经历的讲述组织，不是要求不停讲满八分钟。开场保留 30 秒结论；面试官确认需要深挖时再展开。**已登记经历**是预算金额编辑、层级累加和键盘交互；下列数字、并发冲突与验收步骤属于学习推演，不能当历史生产改动。

| 展开阶段 | 要解释的内容 | 面试官继续追问的入口 |
|---|---|---|
| 第 1 分钟 | 用户编辑哪一级金额，合计用于什么决策；本人负责编辑交互与数据处理，后端承担持久化约束 | 金额来源、父子约束是否一致 |
| 第 2—3 分钟 | 区分接口 DTO、输入草稿和派生合计；为什么不让每个输入框独立维护整个树 | 数据所有权与无效状态 |
| 第 4—5 分钟 | 演算一次变更，说明空值、取消、失败、晚到响应 | 失败路径与可复现输入 |
| 第 6—8 分钟 | 比较遍历与索引、保存策略与冲突策略；说明当前可证实部分及待核验部分 | 权衡、验证、责任范围 |

可用的长答核心：“我先区分用户正在输入的草稿与已经确认的金额。输入框临时出现空字符串，并不意味着预算等于零；校验通过后才转换成业务金额。父项若由子项推导，就由同一规则层计算，组件只发出编辑事件，避免每个组件各算一遍。历史实现可以讲层级累加、键盘导航和脏值提示；金额精度、后端版本冲突和具体测试结果，缺源码或记录时不会补造。”

**演算一**：假设年度金额要求等于 12 个月合计，当前月值 10、20，其余为 0，年度合计是 30。修改第一月为 15，合计是 35；若用户取消编辑，应回到已确认快照，而不是把已经改过的共享对象再当原值。钱用什么单位存储、何处舍入，必须与后端契约一致；整数最小单位适合约定的小数位，并不能替代任意精度和税费规则讨论。

**演算二**：保存发出后立即改第二个字段，旧保存成功响应晚到。若用旧响应整体覆盖，会抹掉新草稿。学习设计可给草稿代次与提交快照，成功只确认对应代次；若服务端支持 version，则另用它发现并发写入。请求代次解决本页异步先后，version 解决服务端写冲突，两者不同。历史稿提到乐观锁不等于已经在每个模块落地；回答必须先标“若重做，我会……”。

**失败检查**：输入空、负数、超过范围、小数边界；父子合计不符；连续 Enter/Tab 越界；保存失败后草稿保留；关闭重开不残留；晚到响应不覆盖新编辑。练习时从这些条件挑一个给确定输入和预期，不背“覆盖所有边界”。缺原始收益记录时，验收只陈述可观察行为，不报提升比例。

## SSAP 与 DOMP 的递进追问

SSAP 动态表单先说明“元数据负责可配置差异，规则层负责业务约束”。若每个配置都嵌任意执行脚本，会引入权限、调试与兼容成本；只有有限控件和联动需求时，componentMap 加受限条件已够用。追问新增字段时讲字段名、默认值、校验、联动和提交映射，不承诺一份配置适配任意业务。**学习推演**：角色来源只允许一个模板，切换来源后旧多选值失效；必须在状态转换处清理，不能仅隐藏控件。查看态是否参与校验要按业务规则，而非靠 disabled 自动推定。

看板的多个独立接口适合同时发起，但 Promise.all 某项失败不会自动取消其他请求。若每块图表允许独立成功，学习设计可用 allSettled 保留各块错误；若金额汇总必须同一版本齐备，部分成功就不能伪装成完整总数。选择由业务完整性决定，不由“并行更快”决定。[MDN allSettled](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Promise/allSettled)

DOMP 图表分层的关键收益是变更范围可控：指标字段变化主要进入映射层，展示样式变化进入有限配置，页面尺寸变化进入容器。它不保证代码行数最少，也不自动改善性能。删除一层工厂后若仍能清楚表达一张图，先保留直接配置；多个真实场景共享结构后再提炼。容器变为零尺寸、Tab 隐藏后显示和节点移除必须实际检查，依据 [ECharts 容器生命周期](https://echarts.apache.org/handbook/en/concepts/chart-size/)。

## 从负责人视角解释渐进改造

TS 迁移先选变更频繁、调用方多且契约稳定的边界，避免一次改完整仓。allowJs 是允许 JS 共存，checkJs 才对纳入项目的 JS 启用类型检查；不等于旧代码天然获得严格类型。迁移 API 类型时仍需检查真实响应，不能用 any 把新错误消音。[TypeScript checkJs](https://www.typescriptlang.org/tsconfig/checkJs.html)

请求层推广先统一鉴权与错误语义，不把所有业务返回强行揉成同一对象。学习推演里，多个请求同时 401 可共用一次续登过程，但重放非幂等动作要防重复执行；这不是历史系统已实现 single-flight 或自动重试的证明。遇到“你独立做了什么”时按模块、规则、验证分别回答，认证基础与内部构建平台仍保持团队归属。

**待核验与不自信处**：BCP 公式编辑器与大文件上传的实际模块、具体作者和上线状态，目前只有历史素材；先作为按需回忆入口，不抢主故事。组件图表数量、TS 覆盖率、首屏秒数和收益比例缺原测量底稿。旧仓是否具备版本冲突、请求去重与金额精度测试，也不能从本页学习方案反推。
