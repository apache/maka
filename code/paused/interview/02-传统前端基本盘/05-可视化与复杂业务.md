# 可视化与复杂业务

## 图表三层

容器负责实例生命周期和尺寸；映射层负责数据到配置；工厂负责场景配置。检查卸载清理、resize和空数据，不把每张图都抽成大型通用配置平台。

## 复杂状态

级联筛选：上级改变清理失效下级，查询键与缓存一致。树形数据：先明确节点规模与变更频率，再选递归或显式栈；不可变更新避免共享引用误改。预约：资源和时间约束放规则层，拖拽只是输入方式。

## 面试故事

DOMP讲图表分层，SSAP讲级联Hook与请求层，BCP讲树遍历和状态更新，预约讲规则与平板交互。每段按“输入/状态→不变量→实现→失败路径→证据”讲述，不借用旧素材中未核验的PLM成果。

## 学习案例：从数据和状态推导结构

图表收到空数据与 0 值有不同含义：空数据需要空态，0 应按业务含义呈现。先在映射层确定单位、排序、空值；工厂只处理有限场景配置，容器保证初始化时有尺寸，隐藏 Tab 打开后重新量尺寸，卸载 dispose。[ECharts 容器与销毁](https://echarts.apache.org/handbook/en/concepts/chart-size/)

**预算演算**：父项合计 150，两个子项为 100、50；把第一个改为 120，父项应变为 170，不能沿用旧合计再反复累加。先确认父项是可编辑事实还是派生值，再决定更新规则；更新沿路径复制节点，避免一处引用修改污染另一视图。已登记 BCP 经验是金额编辑与树更新，具体此组数是学习输入。

复杂度追问：一次完整遍历通常是 O(n)，但每次键入都扫全树会累计成本；节点少时保留简单遍历，测出瓶颈后再考虑索引与增量计算。ResizeObserver 能发现容器变化，回调又改尺寸可能引发循环，应避免尺寸互相驱动。[MDN ResizeObserver](https://developer.mozilla.org/en-US/docs/Web/API/ResizeObserver)
