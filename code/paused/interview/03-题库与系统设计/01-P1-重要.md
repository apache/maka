## 三组常见追问怎样从提纲展开

**SSR／RSC 学习推演**：商品详情需要首屏内容，购买按钮需要交互。先区分“何时产出 HTML”与“哪段组件代码运行在哪里”，再谈 Server Component、Client Component 与 hydration；RSC 不是 SSR 的同义词。Next 的客户端边界应尽量靠近交互区，Server 侧保留不能暴露给客户端的逻辑。Client Component 也可能参与首屏预渲染，不能概括为“只在浏览器渲染”。客户端会收到的 Props 和返回数据仍需审核，服务端文件不等于所有数据天然保密。[Next Server/Client Components](https://nextjs.org/docs/app/getting-started/server-and-client-components)

追问缓存时先报目标版本、路由和数据获取方式，再解释每层缓存的键与失效；不同 Next 版本的默认行为会变化，本库不固定背一句“fetch 默认缓存”。没有对应项目经历就给学习方案：公开详情可考虑缓存，身份相关价格和权限信息另行处理，不称已经做过线上 SSR 改造。

**并发与 Suspense 学习推演**：输入框要立即响应，结果区可稍后更新。Transition 让相关渲染更新可被更紧急工作打断，不使回调里的巨型排序自动变成可抢占任务。Suspense 需要兼容的资源或框架支持；普通 Effect 发起 fetch 并不会因为外面包一个 Suspense 就自动显示其 fallback。先说明数据入口与等待边界，再讨论并发体验。[React Suspense](https://react.dev/reference/react/Suspense)

**布局学习推演**：弹窗 z-index 很大仍被遮挡，先找祖先的层叠上下文；局部层叠值不能直接越过祖先所在层。布局先检查 Flex 子项的收缩与长文本、Grid 轨道尺寸，再检查 overflow 和定位，不用不停加更大的 z-index 修症状。是否使用 Portal 则看弹窗要跨过哪层容器及焦点管理。[MDN 层叠上下文](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Positioned_layout/Stacking_context)

## 手写轮用最小反例检验解释

| 题型 | 先说不变量 | 最小输入与验收 |
|---|---|---|
| 请求竞态 | 只有当前身份与代次可写当前视图 | A 慢、B 快，再 A→B→A；晚到旧响应不覆盖新值 |
| 超时取消 | 结束后只结算一次并清理计时器 | 请求恰好在超时前后完成；取消、超时与业务失败分别呈现 |
| SSE 解码 | 字节边界不是字符或事件边界 | 中文字符跨 chunk、事件跨 chunk、非法 JSON；不能白屏或把半帧当全文 |
| 树遍历 | 每个有效节点按预期访问，更新不污染原引用 | 空树、深树、单分支；明确是树还是可有环图，不无条件递归 |

不需要从头手写全部浏览器或 Promise 标准。先确认题目要求与运行环境，画失败时间线，写最小实现，再用能使错误实现失败的输入验证。面试中的代码练习与源项目改造是两件事，本轮仍不启动三源码仓的未批准改造。

被问到 Node 背压、RAG 召回或工具续轮时，可先给职责分解，再回到 P02/P05 的真实边界。不会的细节明确列成待核验项，例如版本默认缓存、流源是否支持暂停、服务端是否保存事件游标；不能用术语数量遮盖缺口。每次只因真实题目触发一条深入阅读，否则继续主线与投递。
