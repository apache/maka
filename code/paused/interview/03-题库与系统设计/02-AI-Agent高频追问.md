# AI产品工程核心10题

与[前端核心8题](00-P0-必背.md)共18题。公司实绩、个人演示与设计理解分别回答；这不是本人掌握度排名。先答问题，再查骨架；[实际记录](../04-表达与模拟/05-模拟面试记录.md)仍只填写真实发生的回答。

## A01 一个 SSE chunk 为什么不等于一个事件？

**骨架**：字节块可能切断 UTF-8、行或事件；保留解码状态和残片，完整事件后再解析 JSON。心跳、业务内容、错误与结束分别处理；POST 流可由 Fetch 消费。

**失败追问**：中文被切开、一次收到多个事件、末尾残片或断流，分别怎样识别？

**本人证据／边界**：[P11 演示](../06-三旗舰作品集加固/02-agent-hub-叙事与十问.md)的跨 chunk 解码、[P05 文本协议](../06-三旗舰作品集加固/01-qoder-proxy-api-叙事与十问.md)。公司对话内核是团队能力；CLI 输出 SSE 不等于实时增量。

**推导与案例**：传输只负责按字节交付，业务事件边界由协议定义，两者没有一一关系。白板上把“花”的 UTF-8 三个字节拆成两次输入，再把 `data:` 与空行拆开：先恢复字符，再恢复行／帧，最后处理完整 payload。一次输入也可能含两帧，必须继续消费剩余缓冲。WHATWG 规定空行触发事件，未由空行结束的尾事件不会因 EOF 自动成为完整事件；项目对残片的处理仍需对照解码器，不凭规范假定实现全部覆盖。

**进阶追问**：基础层画四层边界；第二层说明注释心跳为什么不进入业务 store；深挖层问服务端持续发送却 UI 不更新时，怎样分别观察网络到达、帧完成和 UI 提交时点。能给每层观察点，比只说“用了流式”更有辨别力。

## A02 生成中、部分内容与流中错误怎样呈现在 UI？

**骨架**：区分等待、进行中、完成、取消与失败；保留什么内容由产品规则决定。错误不能伪装成完整结果；重新执行前确认旧任务是否仍在运行，避免混用两次输出。

**失败追问**：已经展示部分内容后断流，是继续、重试还是重新开始？旧流晚到事件怎么办？

**本人证据／边界**：[P11](../06-三旗舰作品集加固/02-agent-hub-叙事与十问.md)提供事件与任务页面演示，[P02](../01-AI项目与Agent工程/02-AI音频编辑-Node-BFF.md)提供长任务交互。演示不证明所有客户端断流恢复或生产重试语义。

**推导与案例**：内容和执行状态是两条维度；有文本既可能正在生成，也可能已经失败。学习推演：第一次请求已显示半段，用户取消后发起第二次，第一条流又晚到一个 delta。仅改 loading 会把旧内容接到新回答；应按请求身份归属事件，并明确终态后的处理规则。取消网络读取能结束前端等待，却不能据此宣布远端工作撤销。是否保留半段、是否允许使用，应由业务风险决定，失败提示也要跟随对应回答。

**进阶追问**：先说状态与内容分别谁持有；再画取消后晚到事件的时间线；深挖时比较“保留草稿供查看”和“禁止据此执行动作”。不默认所有场景都能断点接着生成，也不把 UI 重试按钮当服务端恢复保证。

## A03 结构化卡片怎样校验？合法 JSON 是否就能展示？

**骨架**：JSON 解析、schema 与业务规则是不同关口；检查类型、必要字段与枚举。未知类型、非法值和额外字段分别定策略，失败时给明确反馈，不靠字符串猜出业务数据。

**失败追问**：合法 JSON 含未知卡片类型、错误金额或 extra，三者是否应同样处理？

**本人证据／边界**：[P11 当前 schema](../06-三旗舰作品集加固/02-agent-hub-叙事与十问.md)会拒绝未知 type／非法值，extra 默认剥离或忽略；固定卡片演示不证明任意模型输出都可可靠处理。

**推导与案例**：解析成功只说明语法成立，schema 约束数据形状，业务检查才判断能否执行。可检查样例分别是未知 `type`、已知类型却缺必填字段、合法对象附加 `extra`；前三种策略必须先读当前 schema。P11 的固定卡片可以映射到已知组件，但不能让模型输出直接选择任意代码或动作。金额、库存、权限等也不能因字段类型正确就信任。新增可选字段的兼容性与非法核心字段的拒绝是不同决策，不能统一称“严格校验”。

**进阶追问**：基础层区分三关；第二层比较缺省与显式 null；深挖层设计同一输入在两端的期望表，包括 coercion、extra 和错误定位。官方最新版文档用于理解行为，具体结论仍以仓库安装版本和实际 schema 为准。

## A04 来源、引用与可信度字段分别能证明什么？

**骨架**：界面展示结论、来源与原文，便于人核对；引用存在不等于结论正确，分值也不自动等于概率。缺依据、低分或数据不完整时按契约提示，展示与生成／检索链路分开。

**失败追问**：88 分怎样得到？引用指错顾客或原文不支持结论，前端怎样呈现与排查？

**本人证据／边界**：[P04 依据 UI](../01-AI项目与Agent工程/04-面诊成交助手-证据溯源.md)消费后端字段；[P11](../06-三旗舰作品集加固/02-agent-hub-叙事与十问.md)分数来自 fixture。两者都不证明本人实现生产 RAG 或可信度算法。

**推导与案例**：来源 ID 只建立关联，引用片段让人检查支持关系；可靠结论还需要相关性、时效和正确的对象归属。把“顾客 A 的原文”放到顾客 B 的结论旁，结构可能全合法，语义却已经错误。学习验收应同时核对请求对象、结论、引用 ID 与原文，而不只测抽屉能打开。一个 88 分若没有评分定义、标注数据与校准，不能解释成 88% 正确率；P11 固定值只能用于演示高低分 UI 分支。

**进阶追问**：先问分值生产者和含义；再问引用不支持结论时谁负责修正；深挖时提出有依据／缺依据／错误归属三类样例。这里可讲依据展示的责任，检索排序、置信度计算与生产评估若无证据就列为待核验。

## A05 哪些操作需要预览和人工确认？

**骨架**：对外发送、不可逆动作和重要业务决策明确确认点；展示目标、依据与影响，检查权限并保留结果。按钮禁用只防交互重复，服务端重复执行仍需单独处理。

**失败追问**：双击确认、请求超时后再点或权限中途改变，如何避免错误执行？

**本人证据／边界**：[P04](../01-AI项目与Agent工程/04-面诊成交助手-证据溯源.md)依据呈现与人工业务判断、[P11](../06-三旗舰作品集加固/02-agent-hub-叙事与十问.md)确认流程演示。幂等细节按 T06 核实，不包装为生产交易保证。

**推导与案例**：人工确认要绑定具体提案，不能只表示用户曾经点过一次“同意”。学习推演：预览时目标是 A，等待期间切到 B，确认请求仍应携带被审核的对象和内容版本；服务端在执行点重新校验权限。按钮锁定处理当前页面重复点击，幂等键或已执行结果查询处理跨页面、跨网络尝试；这两层不互相替代。确认后权限失效或提案变更，需要拒绝或重新预览，而不是沿用旧同意。

**进阶追问**：基础层列出目标、内容、影响；第二层说明确认请求超时后的未知结果；深挖层讨论确认与写入之间的竞态及可观察结果。具体幂等键、事务和审计方案仅为设计推演，不追加到 P04／P11 既有生产实绩。

## A06 页面刷新续追与后端重启续跑为什么不同？

**骨架**：前端保存任务标识后重新查状态，解决页面恢复；服务端回读快照只证明状态可读。继续执行还需要工作重新调度和资源恢复；查询与执行不是同一能力。

**失败追问**：页面看到 running，但 worker 已退出，谁让任务继续？从处理中间点恢复需要什么证据？

**本人证据／边界**：[P02 audioId 恢复详情](../01-AI项目与Agent工程/02-AI音频编辑-Node-BFF.md)是历史材料；[P11](../06-三旗舰作品集加固/02-agent-hub-叙事与十问.md)页面刷新续追不等于后端重启续跑。当前不补“完全断点续跑”。

**推导与案例**：页面生命周期、服务进程生命周期和业务任务生命周期彼此独立。可检查的时间线有两条：只刷新浏览器，原工作继续，客户端凭 taskId 取快照；再停止服务并重启，若只是读出 running，不能推出有人继续执行。要讲续跑，至少说明谁扫描未终结任务、在哪一步恢复、重复执行是否安全、输入与产物是否仍存在。P11 没有重启后重调度这一层；轮询能重新观察，却不能制造一个不存在的 worker。

**进阶追问**：先指出 taskId 的作用；再说状态快照和执行检查点的差别；深挖时比较整任务重做与中间点恢复的复杂度。没有恢复成本或故障证据时，优先明确失败／人工重试规则，不为演示补分布式调度体系。

## A07 超时、取消、失败与结果未知怎样区别？

**骨架**：超时表示等待预算耗尽，不保证执行未成功；取消也需说明取消的是等待还是工作。先查任务结果，再决定是否重试；业务动作、处理尝试和状态约束分别定义。

**失败追问**：确认请求超时而服务端已执行，直接重试会怎样？晚到回调能把终态改回 running 吗？

**本人证据／边界**：[P02 状态链路](../01-AI项目与Agent工程/02-AI音频编辑-Node-BFF.md)；幂等、尝试号和重复／乱序回调具体实现仍见[待核验 T06](../00-事实与简历/06-待核验清单.md)。设计方案不写成旧项目实绩。

**推导与案例**：超时是观察者结论，失败是执行结论，“未知”是证据不足。学习推演：提交后连接断开，但服务端已经写入成功，此时直接再提交可能重复产生业务效果。先查询原任务或操作标识，比把所有网络错误都当失败更稳妥。任务可有多次 attempt，回调应能辨别归属并检查合法状态迁移；仅凭收到时间排序，旧尝试可能覆盖新结果。取消也需分别定义请求已接收、工作已停和资源已清理。

**进阶追问**：画一次提交两次尝试的乱序回调；问终态允许哪些后续事件；再问查询也不可用时怎样告诉用户。RFC 9110 的幂等原则支持谨慎重试，但 HTTP 方法本身不能证明业务动作已经去重。上述 attempt 与状态守卫仍是 T06 设计讨论。

## A08 AI 生成的代码和测试怎样验收？

**骨架**：先确定输入、契约与验收；检查范围、数据流、失败路径和断言。测试要能发现错误实现，AI 预审不能替代人的提交与上线判断；记录实际结果而非提效口号。

**失败追问**：测试全绿却没有观察真正边界，怎样用一个反例说明它漏测？

**本人证据／边界**：[P06 具体贡献](../01-AI项目与Agent工程/06-Apache-Maka-开源贡献.md)、[P07 约定维护](../01-AI项目与Agent工程/07-Agentic与Context-Engineering.md)；P12 的已登记漏测可作反例。源码改造暂停，不说已经修复或得到全行为证明。

**推导与案例**：验收必须对外部可观察行为下断言，否则代码与测试可能共同照抄错误假设。P12 的反例是工具参数不匹配，工具本来没有写文件，检查文件不变仍会绿；另一例仅看最终文件，无法证明审批前没写入。TDD 的学习顺序是先写能因目标缺口而失败的检查，确认失败原因，再做最小实现，最后在保持行为下整理。先因拼写、环境或依赖失败不等于锁定需求；通过数量也不等于辨别力。

**进阶追问**：先给一个会被测试抓住的错误实现；再说明安排前后快照的位置；深挖时问如何用一次定向反例检验断言。本文补知识与已有漏测分析，不代表已在 P12 修复盲点，也不新增测试框架或本月实践任务。

## A09 项目规则和历史摘要怎样避免失效？

**骨架**：确认工具加载路径、适用范围与当前版本；普通文档不天然拥有系统指令优先级。只提供当前任务所需上下文，恢复前对账；摘要保留目标、状态、证据与未决项，不代替现状。

**失败追问**：摘要说已通过，源码却已变化，哪份信息决定下一步？多人维护规则怎样辨别归属？

**本人证据／边界**：[P07](../01-AI项目与Agent工程/07-Agentic与Context-Engineering.md)为约定、Mock、验收与上下文维护经验；基础 ADR 与规范是多人协作，不称本人独立设计团队全部体系。

**推导与案例**：上下文需要同时说明权威、相关性和新鲜度。当前用户需求决定授权范围，适用规则提供约束，源码与探针提供现状，历史摘要只是线索。学习案例：摘要写“测试通过”，但提交已经变化；应定位当时提交与检查范围，再判断是否需要重验，不能直接复用通过结论。文件出现于附件或工具输出，也不自动获得执行授权。任务状态宜保留最后完成点、阻断与证据指针，避免把大段历史日志复制成当前指令。

**进阶追问**：基础层说明规则怎样加载；第二层解释多份记录冲突如何定位权威；深挖层设计一次新会话恢复对账。多人协作要保留归属与变更来源；摘要不能替代源码核验，版本管理也不能阻止错误内容被提交。

## A10 Mock、契约检查与上线验证怎样分工？

**骨架**：Mock 帮助按约定联调，契约检查发现字段和状态冲突，页面验证检查业务反馈；真实环境还要验证权限、故障和依赖。安装／类型／规范／测试分别提供证据，不互相代替。

**失败追问**：Mock 页面正常而线上失败，怎样区分环境、接口、映射和交互问题？

**本人证据／边界**：[P04 共用 mapper](../01-AI项目与Agent工程/04-面诊成交助手-证据溯源.md)、[P02 Java Mock BFF](../01-AI项目与Agent工程/02-AI音频编辑-Node-BFF.md)、[工程化要点](../02-传统前端基本盘/03-前端工程化.md)。无测量不报提效比例，Mock 通过不算生产通过。

**推导与案例**：不同检查覆盖不同失败集合。学习案例：Mock 返回数字，真实接口返回可空字符串；类型检查可能只认识本地声明，页面又默认有值，直到真实请求才暴露错配。沿原始 payload→schema→mapper→页面观察逐层定位，比同时改 UI 和服务更清楚。契约样例需要覆盖缺省、null、枚举与异常状态；页面还要看错误是否可理解、旧数据是否清理。真实权限、限流、第三方失败及部署配置不能由本地 fixture 替代。

**进阶追问**：先说每层输入和输出；再说当前失败由哪层首先拒绝；深挖时挑一条真实边界对应一项检查。完成报告应列命令、提交与范围，不把“装得上”“类型通过”或“Mock 能跑”汇总为上线验证通过。
