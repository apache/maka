# 系统设计：两道主练与两道按需

每次只选一题，依次讲需求与权限→状态／数据→最小结构→失败路径→取舍→验收。这些是设计练习；实际职责按[事实基线](../00-事实与简历/00-个人事实基线.md)，不把方案写成已上线能力。

## S01 主练：多顾客 AI 工作台

- **澄清**：顾客／门店／身份维度；谁查看结论、谁执行操作，哪些动作必须确认？
- **最小结构**：请求层→顾客查询键与缓存→DTO/mapper→页面状态→来源／原文／人工操作。
- **失败追问**：快速切顾客、旧请求晚到、部分数据、权限变化、生成失败与重复确认。
- **验收**：A 的晚到响应不能进入 B 页面；空／部分／错误有明确反馈，权限和依据归属可核对。
- **本人边界**：[P04](../01-AI项目与Agent工程/04-面诊成交助手-证据溯源.md)为主讲，P01 为协作背景；具体并发 guard 按源码证据，后端可信度／模型能力不归本人。

### 从归属推导最小设计

先把“当前正在看谁”与“服务端数据属于谁”分开。设计推演：查询键至少包含会影响结果与权限的业务维度，mapper 只做字段与展示模型转换，不能补造缺失的证据。A 切到 B 后，A 响应可以存入 A 对应缓存，但不能覆盖当前 B 的展示；取消旧请求是减少浪费，响应归属检查才处理取消来不及的竞态。具体是否已有这些守卫仍按 P04 源码证据回答。

可检查案例：连续切 A→B，让 A 最晚返回；检查标题、结论、来源抽屉与操作目标始终对应 B。再给 B 部分结果与权限失效，确认 UI 不把旧的完整结果当当前成功。取舍是先用查询键、状态和现有请求能力解决，未经规模证据不引入复杂全局总线。深挖追问：缓存还能否跨身份复用？确认期间数据变化时，展示版本与执行对象如何对齐？

## S02 主练：异步音频任务

- **澄清**：任务与一次处理尝试、取消、超时、重试、页面恢复分别怎样定义？
- **最小结构**：小程序→业务任务接口→处理服务→对象存储；详情查询与状态回调各有职责。
- **失败追问**：重复提交／回调、下载失败、晚到结果、进程退出、子进程与临时文件残留。
- **验收**：按定义检查终态与资源；结果未知先查询，界面恢复和工作续跑分别验证。
- **本人边界**：[P02](../01-AI项目与Agent工程/02-AI音频编辑-Node-BFF.md)有历史任务工程证据；尝试号／幂等细节见 T06，分布式队列与完全断点续跑不是既有证明。

### 用时间线解释恢复与重试

设计推演先画业务任务，再画一次 attempt：任务标识追踪用户目标，attempt 标识某次执行；二者不必立即都做成新实体，但语义不能混淆。进度回调、终态与产物地址由服务端负责，页面持有当前观察任务与展示状态。若提交超时，先查询是否已经创建；若执行失败，说明哪些步骤可安全重做、旧产物如何处理，再决定重试。

可检查案例：新尝试已经完成，旧尝试的失败回调最后到达，不能把有效结果覆盖为失败；处理进程退出后，检查业务终态、子进程和临时文件，而不只观察页面 loading 消失。页面刷新测试与服务重启测试分开：前者查看 taskId 能否续追，后者需要证明谁重新调度。尝试号、幂等与自动恢复是学习方案／T06，不能写成历史 P02 已有完整实现。没有任务量数据时，先讲现有接口与资源收尾，不先上队列。

## S03 按需：文本协议网关

**触发**：JD 或面试追问协议接入。沿请求→Canonical→Provider→事件→下游文本走读，说明显式模型路由、鉴权隔离、取消与错误。[P05](../06-三旗舰作品集加固/01-qoder-proxy-api-叙事与十问.md)是公开备用案例；CLI 缓冲 stdout、Gateway experimental、离线测试与当前真机区别必须说清。完整工具翻译、多租户与容量仅作设计。

### 明确“兼容”的对象

设计推演从一个文本请求开始，逐字段核对下游输入、Canonical 与 Provider 的信息损失，再观察文本、结束与错误。若上游能发工具事件而下游丢弃，内部类型再丰富也不能证明工具兼容。可检查案例是给同一 fake 文本事件流，分别观察三种 wire 输出与非流聚合；CLI 的首个下游内容是否在子进程退出前，需要时序观测，SSE 外形不足以回答。取舍：先守住声明的文本子集；当前不以学习讨论扩大到多模态或自动故障切链。

## S04 按需：带权限与引用的文档问答

**触发**：JD 明确要求 RAG。先明确范围、更新频率、权限和不可回答；再画解析切分→索引→权限过滤检索→生成引用→评估。追问越权文档、过期索引、错误引用与提示注入。属于学习设计；[P04](../01-AI项目与Agent工程/04-面诊成交助手-证据溯源.md)只有依据展示可迁移，不证明生产检索。暂停新实践，本月不要求造 Demo。

### 检索与引用分别验收

学习推演：先按用户权限限定可检索集合，再谈相关性；答案引用要能定位版本和原文，并允许“不足以回答”。可检查案例包含无权限但高度相关的文档、旧版本与新版本冲突、检索正文夹带“忽略规则”指令。前两项检查召回集合与引用版本，后一项把检索内容作为不可信资料处理，并继续限制工具权限；过滤词本身不能证明注入防护完成。取舍：检索质量、引用支持关系、权限与动作风险分开评估，现有依据 UI 只覆盖呈现一段。

## 通用验收

每题至少解释一个状态所有者、一个故障、一个能发现错误的检查；没有规模数据时说测量方法，不报虚构吞吐。原回答与重答写[模拟记录](../04-表达与模拟/05-模拟面试记录.md)，不预填通过。

## 原理参考

[HTTP 幂等与重试](https://www.rfc-editor.org/rfc/rfc9110.html#section-9.2.2)支持区分请求重复与业务效果；[WHATWG SSE](https://html.spec.whatwg.org/multipage/server-sent-events.html)用于核对事件边界；[OWASP Prompt Injection](https://owasp.org/www-community/attacks/PromptInjection)用于理解检索资料与指令混用风险。2026-10-02核验原始来源，本文方案仍为学习推演，未新增生产能力或测试成绩。
