# 证据映射：简历句到仓库物证

每条公开声明须能指向源码或公开记录。身份/归属来自[事实基线](../00-事实与简历/00-个人事实基线.md)，数字/提交/测试范围来自[证据登记](../00-事实与简历/05-项目归属与量化证据.md)；本页只维护“声明→物证”，不另维护测试或贡献数字。

| 项目 | 可使用的声明 | 物证与限制 |
|---|---|---|
| P05 | 三 Provider 经 Canonical 请求/事件适配文本接口 | `src/core/`、`src/providers/`、`src/protocols/`；当前下游主要文本，内部 tool/thinking 不等于完整 wire 输出 |
| P05 | 无凭证离线测试与验证矩阵 | `test/`、`docs/06-测试与验证矩阵.md`、E03；当前真机冲突保留 T04，不写本轮线上 CI 全绿 |
| P05 | 静态依赖检查步骤 | `scripts/architectureCheck.ts`；违规只打印，不能称强制 CI 闸门 |
| P11 | 跨 chunk 解码、固定 schema 卡片 | `packages/shared/src/{sse-decoder,contracts}.ts`；未知 type/非法值拒绝，extra 默认剥离；非官方 A2UI 完整协议 |
| P11 | 演示证据来源展示 | `apps/api/app/evidence.py`、`features/evidence/`；分数是 fixture、阈值固定，没有检索/评分算法 |
| P11 | 页面刷新后按 taskId 续追 | `apps/web/src/features/tasks/tasks-page.tsx`、`e2e/agent-hub.spec.ts`；服务重启仅回读快照，不续跑执行 |
| P11 | 历史公开三层 CI | E10 对应公开 run/Release；本轮仅重跑局部测试，不能冒充全套验收 |
| P12 | 七主题规范、五实现、有限场景一致性 | `specs/`、`impls/`、`conformance/{run.mjs,lib/}`；逐实现对 expect，不是全行为等价 |
| P12 | 补丁预验失败零写入 | `impls/typescript/src/plugins/tools/apply_patch.ts`；I/O 失败不回滚，同文件多编辑有覆盖边界 |
| P12 | 产物新鲜度检查与 CI 配置 | `conformance/adapters/`、`.github/workflows/ci.yml`；SC-004-A draft，本轮未重跑五语言全套 |

## 同步影响面

事实/证据源 → 项目长稿 → 正式题库的对应追问 → 简历与介绍 → 个人主页。公司素材、待核验能力及演示分数不直接复制到公开主页。每次只同步受影响的声明，保留可审查 diff。

## 从一句话走到可检查的案例

| 声明 | 现场走读的输入与边界 | 可以给的证据 | 仍然不能推出 |
|---|---|---|---|
| P05协议适配 | 一条文本请求经过路由、Provider事件与输出聚合 | 指定源码、离线fake/抓包回放、E03时点 | 全工具兼容、真实IDE循环或维护收益 |
| P11跨chunk解码 | 多字节字符与SSE帧被切开；坏JSON与坏schema分别处理 | 解码器测试源码、service/store边界、E10指定范围 | 当前端到端线上稳定或模型语义正确 |
| P11任务续追 | 页面刷新读取taskId并查询快照 | tasks-page与detail路径，历史E2E范围 | 服务重启重新执行在途任务 |
| P12补丁预验 | 无效补丁在写入前被拒绝；I/O失败另处理 | apply_patch源码及E11探针 | 事务回滚、系统沙箱或全场景原子性 |

走读先说观察点，再说明断言为何能否定错误实现。例如“返回400”不能证明零写入，还要检查目标内容；“输出SSE”不能证明首token实时，还要观察输出时序。这里是验证方法说明，不表示本轮执行了新项目探针。

## 引用如何选择与更新

职责用事实基线，项目实现用固定提交源码，测试结果用有时点的运行记录，通用机制用官方文档或原论文。一个结论需要多种证据时分别说明：测试通过但没有真实上游，只能支持离线断言；历史公司材料加公开演示，也不能自动支持公司完整原创归属。

新增案例先检查它改变了什么事实。若只是解释更清楚，就更新项目正文与对应题目，不改简历和主页；若新增已核验证据，再先写入事实/证据源，按影响同步展示。这样扩写不会产生第二份动态贡献计数或把学习方案升级成经历。
