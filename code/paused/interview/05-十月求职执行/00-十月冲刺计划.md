# 四周复习与投递计划

本月优先 **AI产品前端（Web + Node）**，Web保底；先复习与投递，暂停源码改造、新工具闭环、RAG Demo 等实践。P04接诊准备与P02音频任务为两项主讲，P05为公开备用；P11/P12只在相关追问时查。原AI/Web练习配比70/30用于控制方向，不把所有材料列为每日必读。

## 每日只走一个闭环

训练顺序与时间分配只维护在[每日口述训练](../04-表达与模拟/00-每日口述训练.md)：普通日最多60分钟，忙日15分钟，模拟日60分钟替代普通课。每周最多一场模拟，题型见[模拟入口](../03-题库与系统设计/04-综合模拟面试/README.md)。

到时停止，不靠夜间补课凑完成；当天没有实际JD／投递任务可提前结束，不代填记录。没有旧卡点的首日做小规模闭卷基线；未答题保持未测，不填已掌握。普通日从[AI产品10题](../03-题库与系统设计/02-AI-Agent高频追问.md)与前端8题选当前最相关的两题，而非再做5基础+3AI+系统设计的全套配额。

## 四周安排

| 周次 | 只做什么 | 可检查的结果 |
|---|---|---|
| 第1周 | 用18核心题分批建立本人闭卷基线；准备P04/P02的30秒与2分钟表达；开始收录真实JD | 有原回答、真实卡点与证据入口；未测项明确留空 |
| 第2周 | 只补实际卡点、复测；按JD微调简历与两主一备组合，沿既定10月中旬节奏开始投递 | JD、简历版本和真实投递记录；不等整库读完 |
| 第3周 | 根据实际追问与回复调整；每周最多一场模拟替代日课 | 当场原回答、反馈与重答，证据缺口回流待核验 |
| 第4周 | 重答仍需查稿的关键问题，跟进投递与面试；按JD触发少量按需题 | 能脱稿解释机制、决策、失败和边界；没有结果时不虚构转化率 |

四周是执行框架，不是已完成记录。时间变化按真实安排调整；周末无需把原3小时预算填满，不额外叠加实践。

## 本月停止扩张

不以读完35基础题、30AI题、十份候选池或五套模拟作为完成条件。岗位未要求的Next/RAG/工具/Node深挖仅[按需查阅](../03-题库与系统设计/01-P1-重要.md)。新实验与三项目源码改造保持暂停；已有问题按当前边界回答，不能写成已修复。GitHub主页只同步可公开核验事实，不把本地计划写成已发布能力。

## 深化后的渐进顺序

资料更完整后，仍分三次接近同一问题。首次只读短答与正常链路，能说清输入、拥有者和输出；第二次在真实卡点上读失败与权衡，能说明一个反例；第三次进入长稿和官方参考，解释条件变化时为何要改设计。这个顺序适用于React状态、顾客切换、音频任务与协议适配，不要求首次就背完整5—8分钟。

| 阶段 | 当前最小任务 | 进入下一阶段的证据 |
|---|---|---|
| 第1周的主链路 | F/A各选一题、P04/P02只练一个正常流程 | 本人闭卷能从输入说到结果，明确职责 |
| 第2周的失败链路 | 对已暴露卡点追加乱序/空值/超时之一 | 能解释原方案何时失效，而非只补术语 |
| 第3周的方案比较 | 给实际JD选中的案例准备替代方案 | 能说明约束、代价和需要的测量 |
| 第4周的迁移表达 | 换题意或输入，复测并练被打断后的长答 | 不看稿仍保持事实一致，未知项可查证 |

上表是新增阅读深度的安排，不代表此前阶段已经完成。晚开始或时间不足时，用剩余时间覆盖真实JD的关键项，不补齐形式上的全部阶段。投递与复习并行：有合适JD就准备该岗位的最小材料，不等待全库达到“满分”。

## 每周如何做独立判断

只看三个真实输入：到期复测的原回答、实际JD的要求、面试官真实追问。若两次回答都卡在状态边界，就暂缓新增Agent框架资料，回F题与P04/P02；若机制已经清楚但职责证据混乱，就回事实台账，而不是继续学新技术。没有反馈时维持当前优先级，不用假设市场偏好制造焦虑。

一周结束时可以减少一项负担：去掉没有命中真实缺口的阅读任务，观察核心回答是否仍能完成。这是复习安排的消融检查；如尚未实际执行，只记录要比较的结果，不宣称节省了多少时间。

## 资料更新的停止条件

一处缺口已经有结论、原理、例子、失败和来源时，先安排重答，不继续堆相似文章。只有重答仍暴露缺口或新JD明确要求时继续扩展。长口述的目标是可选片段充足，验收仍是能独立回答和对证据负责，资料完成不自动表示本人准备完成。
