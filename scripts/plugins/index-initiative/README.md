# 个人助手：一个聊天入口 + 主机心跳

侧栏「个人助手」打开固定的原生聊天，保留 Maka 的模型选择、工具展示、权限交互和上下文管理。首次打开只绑定会话，不启动模型、不导入历史、不建索引，也不开启心跳。已有绑定会继续使用原会话；不通过切换聊天偷偷创建新的助手。

「个人助手」是独立侧栏入口，选中后仍使用原生聊天与 WorkHub。入口创建的会话使用持久化 `personal-assistant` 标签；插件通过通用 `sidebar.navigation.sessionLabels` 声明归属，普通会话列表和切换菜单不再重复列出这些会话。已有同标签会话无需重建。只过滤导航展示，不删除会话，也不影响 Recall 或记忆读取；卸载插件后会话重新出现在普通列表。

右上角「助手动态」只展示状态：主动发现是否运行、下次检查时间、任务摘要与详情、需要处理的异常。切换到其他会话或 WorkHub 时收起。心跳周期与启停、来源同步、索引维护、任务恢复和历史任务接管，统一放在 Maka 设置的独立「个人助手」栏目中。悬浮窗不再放这些操作。日常输入、任务补充与取消仍在主聊天完成。

历史导入是可选项。没有索引时仍可正常聊天和委派任务；有需要时在聊天中说明整理标准与允许使用的来源。索引默认后台创建，先返回进度。已注册来源不等于授权有效；面板显示上次检查和整理状态，不会在每次轮询时重扫来源。

安装 `index-initiative` 获得入口；配套安装 `proactive-matters` 获得持续执行、`memory-network` 获得记忆。未安装的能力会在面板明确提示，不阻止普通聊天。飞书为可选插件，CLI 授权和来源范围仍在飞书插件配置中设置，不会自动授权或导入。

需要包含通用 `sidebar.navigation.openSession`、`activeSessionId`、`sessionLabels` 及 Settings 插槽接口的 Maka 客户端。旧客户端会显示升级提示。Host 需在线；会话删除或 Host 不可达时明确报错，不另建一个空会话掩盖问题。

InitiativeEnable 仍可在普通聊天中显式绑定和启用心跳。用户消息、心跳调查和助手回复使用该 Session 原本的历史与上下文管理。

- InitiativeEnable：保存探索指示及用户要求的检查周期，默认 30 分钟。首次检查在一个周期后；需要立即检查可由用户调用 InitiativeControl check。
- InitiativeStatus：读取主机调度状态。
- InitiativeControl：用户请求 pause / resume / check。暂停只停止后续心跳，不中止聊天；check 是一次检查，不会把已暂停的周期重新开启。

模型不选择下次心跳时间。没有 InitiativeRead、InitiativeCheckpoint、独立记事本或退出 hook；一次调查可以正常结束，不必制造任务或消息。心跳遇到忙碌会话时推迟；每次结束后等待配置周期再检查，不补发积压心跳。已识别的临时服务错误最多自动重试三次并退避；权限、用户中止、超时或不确定执行停止自动重放，保留错误供检查。

开启会话获得一条简短角色指示：正常与用户交流，具体执行任务委派给独立 Matter，按需查询进展并传达用户对事项的修改。具体任务不与主聊天共享工作状态。

## 配套插件

安装当前 memory-network 以检索索引和原文，安装 proactive-matters 以使用：

- MatterDelegate：按稳定 taskKey 转交具体授权任务，重试复用同一事项和子 Session。
- MatterTasks：查询本会话委派的事项及最近报告。读取不等于已通知用户。
- MatterTaskMessage：把明确的新用户要求写入对应事项。
- MatterTaskControl：按用户要求暂停、继续、检查或取消事项。

任务进展通过持续跟进插件的持久化通知记录主动送入发起聊天，在主聊天忙碌或等待用户时延后。Host 接收不等于用户已读；主助手结合历史避免重复通知。升级不会重发全部旧进展，提交结果不确定时显示错误供检查，不盲目重放。旧窗口创建的无归属任务可在「设置 → 个人助手」中明确交给此助手，其他会话已有归属的任务不能接管。实际回复直接出现在原聊天 Session，是否安静由普通 Agent 决定，没有新增空消息渲染协议。授权边界仍由 Maka runtime 执行，提示中的只读要求不是额外工具沙箱。

## 升级与验证

旧版 SQLite 的 worker / notebook / decisions 原样保留在历史归档，升级后默认暂停，需在原发起对话明确启用。旧后台 Session 历史不自动复制到聊天 Session。不会恢复旧的模型自选唤醒时间。

npm run verify 完成构建、打包、平台受控测试和类型检查。产物为 release/index-initiative.maka-extension。Host 需保持运行；tickMs 默认 5 秒，runTimeoutMs 默认 10 分钟。超时停止后续心跳，面板显示原因，设置页提供重新开启入口，不会强制取消共享聊天中的用户请求。

## 两天日常试用

1. 打开侧栏「个人助手」，在原生聊天的模型选择器确认连接和模型。个人助手设置页显示 Host 会话保存的模型/连接，不会为检查连接自动调用付费模型。没有索引也能聊天和委派任务。
2. 如需飞书，在该插件配置中完成 CLI 身份、账号/应用及来源范围设置。在「设置 → 个人助手」查看「信息与记忆」，点击「开启定期同步」；默认每 30 分钟检查最近 24 小时，关闭期间的缺口会在恢复后补查。同步默认关闭，首次打开助手不会下载历史。
3. 需要记忆时，在聊天中说明整理标准和允许使用的来源。既有索引保留，默认每 12 小时维护。设置页可暂停/恢复维护或手动整理；手动整理会运行模型，达到并发上限时明确返回，需稍后重试，不隐式排队。
4. 开启主动发现后，助手按 Host 心跳探索；具体委托交给独立任务。任务结果独立送回主聊天，不依赖心跳开启。遇到后台权限/问题，打开任务会话处理；不会让执行超时替用户取消授权请求。
5. 主会话收到任务进展但没有形成可见回复时，面板保留反馈异常，可在个人助手设置中「核对并重试反馈」。这不会重跑任务。会话创建中断时用「核对并恢复」寻找唯一对应工作会话；无法确认时保留待处理记录，不盲目再创建一个。

三个时间分开显示：来源同步、来源范围观察、索引整理。索引读取观察的是已发布的来源；飞书缓存没有同步时，不能把零增量解释为服务器没有新消息。索引落后时，Agent 可根据返回的覆盖范围读取新原文，无需先整理。同步、读取和观察都不移动索引覆盖游标。

面板每 5 秒读取任务与助手状态，每 30 秒刷新来源/记忆状态（会核对来源授权，但不触发整理或下载）。它不另建聊天页或第二个输入框。Host 必须运行；休眠期间不保证准点执行，恢复后检查到期工作，不补发每一个错过的心跳。来源窗口外的旧消息修改/删除仍需显式刷新相应范围；日历仍按配置窗口读取。
