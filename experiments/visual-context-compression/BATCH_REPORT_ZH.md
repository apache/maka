> 归档说明（2026-09-10）：原实验目录已不存在，本文件按已交付报告重新归档。原脚本、运行明细与图片未恢复；以下验证结论和文件状态均为实验完成时的记录，详见[归档说明](README.md)。

**像素尺寸先明确：除 0.5px 单图方案为 512×512 外，其余实际提交给模型的图片均为 1536×1536。** 1px、4px、8px、12px 指最终图片的字体参数；画布尺寸相同时，字号越大，通常需要更多张图片。

以下是本批完整报告，包含像素、渲染方式、文件大小、token 口径、答题结果和实验限制。

**实验范围。** 日期为 2026-09-09，使用两段真实长会话 B/C，没有混入此前的短材料结果。20 种配置中，19 种完成双材料测试；共完成 39 个“配置×材料”组合、78 次有效答题，另有一次首答因耗时异常被停止。

本批最明确的观察是：**极小整图虽然节省输入，但首答没有比“仅最近原文”保留更多可用历史信息；文本摘要在较低输入量下保留了更多信息。** 每个配置在每段材料上只运行一次，以下是本批观测，不是稳定排名。

**一、数据与测试方法。** 两段材料分别保留约 12.4 万、15.2 万原文代理 token，每个压缩方案都保留同样的最近原文。

| 项目 | B | C |
|---|---:|---:|
| 全部原文代理 token | 123,542 | 151,998 |
| 被压缩的旧前缀 token | 114,645 | 142,903 |
| 共同保留的最近原文 token | 8,896 | 9,095 |
| 可见消息数 | 87 | 137 |
| 分片数 | 590 | 561 |
| 旧前缀／最近分片数 | 543／47 | 529／32 |
| 题目：早期／中期／晚期／最近 | 8／8／8／8 | 8／6／10／8 |
| 全文首答实际输入 token | 135,067 | 163,447 |

两份材料均截取真实会话首次压缩之前的可见历史，保持消息边界，不拼接多个压缩时代。剔除了分析、系统／开发者消息、私有记忆工具输出和环境信封。原日志本来就存在截断的工具输出，实验保留其可见部分，没有恢复缺失内容。

每段独立生成并盲审 32 题，答题前冻结题目和标准答案：

- 合计 **48 道旧历史题、16 道最近历史题**。
- 类型包括：精确事实 26、更正 13、推理 14、续接状态 7、角色判断 4。
- 概念题包含选择题，精确事实按 JSON 类型和冻结答案匹配。
- 最近历史可能重述早期事实，选择题也可能凭题干推断，因此必须保留“仅最近原文”基线。

所有答题统一使用 **`gpt-5.6-luna / xhigh`**，文字经 CLI stdin 提交，图片经原生 `--image` 提交，禁止自行调用工具、联网或读取本地原文。

“首答→回读”分为两阶段：

1. 首次根据压缩表示和最近原文答题，并申请需要回读的分片或关键词。
2. 控制器最多提供 **12 个有效分片、4,000 个带标签原文代理 token**，最多接受 4 个关键词，不反馈答案正确性，再次答题。

第二阶段输入包含原表示、首次答案和返回原文。回读后也可能改错答案。

**二、各方案保留的内容。** 所有压缩方案都另外保留同一段最近原文。

| 方案类型 | 旧历史保留方式 |
|---|---|
| 完整原文 | 全部旧历史原文 |
| 仅最近原文 | 不保留旧前缀 |
| 仅对话正文 | 旧前缀中的用户和助手可见消息正文 |
| 原排版图 | 保留旧前缀原文换行，分页渲染 |
| 紧凑 JSON 图 | 将分片文本编码为 JSON 字符串，显式显示换行等转义，保留分片 ID、角色标签并按列折行 |
| 文本摘要 | 保留旧前缀的模型生成摘要 |
| 摘要转图 | 将同一份摘要渲染成图片 |
| 混合方案 | 追加指定文字，同时提供对应的旧历史图片 |

**通用文本摘要**使用本实验自定义提示词，要求保留用户更正、约束、准确标识符、关键机制与验证、完成状态、待办和分片 ID。生成时不知道后续题目；“最多 8,000 token”是提示词要求。

**Maka 文本摘要**调用当前仓库文本摘要器，代码版本为 `4e139315`，使用生产模板、格式验证和 **8,000 输出 token 的 SDK 上限**。

Maka 的输入由可见消息适配为 RuntimeEvents，再经过当前重放逻辑。B 有 5 个没有对应结果的工具调用被排除，C 没有。这是当前文本摘要器在适配历史上的实验，不等同于完整生产压缩流程重放。

通用摘要经 CLI 生成，Maka 摘要经 OpenRouter 同型号模型生成。两者的提示词、输入组织和生成 provider 有差异，因此不能把得分差异归因于单一因素。

**四、token 的计算口径。** “首答输入”直接读取每个首答运行上报的：

```text
turn.completed.usage.input_tokens
```

计算公式为：

```text
合并首答输入 = B 首答输入 + C 首答输入

全文基准 = 135,067 + 163,447
         = 298,514

输入节省率 = 1 − 配置合并首答输入 / 298,514
```

这个数包含压缩表示、最近原文、题目、协议和 CLI 附加上下文，**缓存命中的输入 token 也包含在内**。不包含摘要生成、答题输出或第二阶段回读输入。

图片方案同样读取这个字段，没有用 PNG 字节数或本地文字 token 估算替代。**本批没有取得单独的“纯视觉 token”字段。**

Maka 对照的输入拆分如下：

| Maka 首答输入构成 | B | C |
|---|---:|---:|
| 摘要正文代理 token | 2,793 | 3,100 |
| 最近原文代理 token | 8,896 | 9,095 |
| 题目／协议／包装代理 token | 2,812 | 2,736 |
| CLI 附加上下文与计数差额 | 8,507 | 8,507 |
| **完整首答实际输入** | **23,008** | **23,438** |

前三项用本地 `o200k_base` 代理计数。第四项是实际总输入减去代理计数的差额，不能全部精确归因于系统提示词。

因此：

- Maka 摘要正文合计：**5,893 token**。
- 完整首答输入合计：**46,446 token**。
- 只看旧前缀：**257,548 → 5,893**，约节省 **97.7%**。
- 以完整首答请求计算：约节省 **84.4%**。

**摘要生成本身的用量另列。**

| 摘要生成 | 正文代理 token | 生成输入 token | 生成输出 token | 其中推理 token | 8k 的含义 |
|---|---:|---:|---:|---:|---|
| 通用 B | 3,271 | 123,569 | 6,755 | 3,478 | 提示词上限要求 |
| 通用 C | 4,036 | 151,827 | 7,818 | 3,775 | 提示词上限要求 |
| Maka B | 2,793 | 118,819 | 2,797 | 0 | SDK 输出上限 |
| Maka C | 3,100 | 148,627 | 3,622 | 516 | SDK 输出上限 |

Maka 两次均正常结束。8k 是包含推理输出的上限，不是目标摘要长度。已核对 SDK 到请求字段的映射，未单独捕获实际网络请求体。

生成输出包含推理，不能等同于摘要正文长度；推理 token 是输出的子集，不能重复相加。

**八、能够支持的判断及适用边界。**

- **极小整图：** 1px 首答与仅最近原文持平，0.5px 略低。不能把尾部信息和题干推断带来的正确数算成图片贡献。
- **字号与分页：** 紧凑 4px 增至 12px，每段从 4 张增至 29 张，输入明显增加，得分改善幅度较小。
- **文本摘要：** 本批通用摘要以接近 Maka 摘要的输入量保留了更多答案；生成提示词、输入结构和 provider 都不同，结论只适用于这两个具体实验实现。
- **摘要转图：** 通用摘要转图没有提高首答得分，合并输入增加；Maka 转图得分略高，输入也增加。样本不足以证明转图稳定有效。
- **配色：** 四种 8px 配色首答为 47～50/64，输入几乎相同，不能据此给出稳定排名。
- **后续工作能力：** 本实验测试历史问答保留，没有测量连续多轮新增工作的吞吐，不能直接推算压缩后能多完成多少真实任务。

同一材料的 32 道题彼此相关，且包含选择题和精确匹配题。**64 道题不是 64 份独立长会话样本。** 本批只有两段历史，每种配置每段一次；CLI 开销和网络状态也可能变化，因此没有给出货币成本或统计显著性结论。
